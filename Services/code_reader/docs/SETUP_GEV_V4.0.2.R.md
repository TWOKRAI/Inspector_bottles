## 1. Сеть [железо]

- Заводской адрес — LLA `169.254.x.x`, **меняется при каждом включении** (был `169.254.75.129`). Advanced IP Scanner показал ложный
  `169.254.13.255`; настоящий адрес — `arp -a` по MAC или вывод `mvcr_probe.py`.
- Общий MVS-SDK (`tools/id3000_discover.py`, `MV_CC_EnumDevices`) на этом приборе даёт **0 устройств** — это норма.
  Перечисляет и открывает его **MvCodeReader SDK** (`Services/code_reader/sdk`, `mvcr_probe.py`).
- Смена IP: `MV_CODEREADER_GIGE_ForceIp(handle, ip, mask, gw)` (адреса числом, `192.168.1.10` → `0xC0A8010A`).
  Вызов возвращает `0x80020204`, но IP в обнаружении меняется. **Сразу выключить и включить питание камеры:** до этого она не отвечает
  ни по ARP, ни по пингу, `OpenDevice` даёт `0x80020206`. После перезагрузки адрес держится.
- Карту ПК менять нужно в той же подсети (`192.168.1.x`); подсеть Wi-Fi `192.168.11.x` не занимать;
  вторая камера (SENSOTEC) по умолчанию `192.168.1.1`, так что `.10` и `.100` с ней не конфликтуют.

## 2. IDMVS не показывает камеру — `encryption.key` [железо]

**Симптом:** список `GigE` пуст, хотя камера пингуется и `mvcr_probe.py` её находит.
**Причина:** для устройств с `Manufacturer = GEV` IDMVS 5.1.0 сверяет серийник с ключом
`C:\Program Files (x86)\IDMVSSTD\Applications\common\vplicense\encryption.key`; файл был **0 байт**.
В `C:\Users\<user>\IDMVSSTD\Log\Client.log`: `CheckEnabledSerial: Check NG: <serial>`, затем `CheckDeviceRegion ... filtered 2`.
У приборов `Hikrobot` этих строк нет.

**Лечение (процедура производителя для прошивки V4.0.2.R):**
1. IDMVS 5.1.0 уже стоит (для V3.2.2.R советуют IDMVS 4.2, ставить его поверх **нельзя**: он перепишет `MvCodeReaderCtrl.dll`, который грузит сервис).
2. Скачать рабочий `encryption.key` по ссылке от поставщика: `https://disk.yandex.ru/d/36iguMoHW5F9hg`.
3. Сохранить прежний: `copy encryption.key encryption.key.bak`, положить новый на его место, перезапустить IDMVS.
   Хеш проверяется `sha256sum` (у нашего файла начинается с `720323025b54…`).

## 4. TCP-вывод результата [железо]

В IDMVS (`Communication Protocols`): включены `TCP Client Protocol`, `Smart SDK Protocol`, `Modbus Protocol`.

| Параметр | Значение | Зачем |
|---|---|---|
| TCP Dest. Address / Port | `192.168.1.100` / `5000` | наша нода `reader_tcp` слушает `0.0.0.0:5000` |
| **Heartbeat Protection** | **выключен** | иначе камера шлёт пакет-пустышку `;` каждые 5 с, приёмник считает его `no_code` [?] |
| **TCP Client Output Barcode Newline Character Enable** (`TcpBarcodeNewlineCharacterEnable`) | **включён** | после каждого результата идёт `\n`. **`;` после кода на V4.0.2.R не приходит**, строка `<code_content>;` не применяется (сырой поток 2026-10-15) |
| TCP Client Output NoRead Enable | включён | при неудаче приходит текст |
| TCP Client Output NoRead Text (`TcpstrNoReadText`) | `NoRead` | без `;`: терминатор теперь `\n` |
| Format Output Content / Format String | `Code Content` / `<code_content>;` | `;` на этой прошивке не работает; оставлено как есть |

Что приходит (сырой поток, камера `192.168.1.10`):
`https://clck.ru/3Vj3AM\n`, `QR-50MM\n`, `NoRead\n` — **каждый результат отдельной посылкой**, терминатор `\n`.
Без `Newline` приёмник склеивает коды в одну запись (виден только `NoRead;`): так вышли 11 записей против 32 срабатываний.

**Рецепты** (`qr_reader_demo.yaml`, `qr_reader_sdk_demo.yaml`): `terminator: "\n"`, `no_code_text: NoRead`.
Для V4.0.2.C был `terminator: ";"` — вернуть, если вернётся та камера.

TCP и SDK работают **одновременно**: при открытом SDK нода `reader_tcp` получает коды (проверено прогоном 11:49).

## 5. Настройка параметров камеры из кода (пока без слоя `sdk`) [железо]

В `MvCodeReaderCtrl.dll` есть `MV_CODEREADER_Get/Set{Bool,Int,Float,Enum,String}Value` и `SetCommandValue` — по имени узла GenICam
(`C:\ProgramData\IDMVSSTD\Local\Features.xml`). Камера должна быть открыта (`api.open`), IDMVS закрыт.
Проверено: `TcpBarcodeNewlineCharacterEnable` (Bool) и `TcpstrNoReadText` (String; для чтения нужен буфер ≥ 256 Б, строка в начале).

```python
import ctypes as C
from Services.code_reader.sdk import MvCodeReaderApi
api = MvCodeReaderApi(); h = api.open(api.enum_devices()[0]); hv = C.c_void_p(int(h))
try:
    api._call("SetStringValue", hv, C.c_char_p(b"TcpstrNoReadText"), C.c_char_p(b"NoRead"))
finally:
    api.close(h)
```

Настройки живут в камере; **сохранить в `User Set` (`UserSetSave`) после всех правок**, иначе после выключения питания могут вернуться заводские
(на первой камере `TCP Client` слетал). Сохранялось ли здесь — [?].

## 6. Дискретные выходы [железо + ?]

Сейчас на камере: **LineOut 3 = `ReadSuccess`, LineOut 4 = `NoCodeRead`**, `Polarity Reversal` включён, `Delay = 0`,
`Duration` владелец увеличил с 1000 µs (1 мс слишком мало для светодиода и ПЛК).

Что хочет владелец (2026-10-15): `1 1` — код есть и хороший, `1 0` — код есть, но плохой/нечитаемый, `0 0` — кода нет
(датчик даёт триггер, ПЛК считает по нему).

Ограничения [мануал + Features.xml]:
- события на линии — **импульсы**, у каждой линии одно событие, «ИЛИ» из событий нет;
- события «код есть, но не читается» **нет**: `NoCodeRead` = «не декодировался»; отличает ли он плохой код от пустого кадра — **не проверено**;
- узла для чтения состояния линий через SDK нет (в списке IDMVS только `LineSelector`): проверка **только светодиодом/мультиметром** (до 200 мА).

**Не закрыто:** таблица «какая линия моргнула» для трёх случаев (код хороший / испорченный или частично закрытый / пусто).
Результат решает, собирается ли схема на самой камере или нужна логика в прототипе.

## 7. Текстовые состояния Good / Bad / NoRead [железо + Features.xml]

Есть только **Good** (текст кода) и **NoRead** (`TcpstrNoReadText`). Отдельного текста «код есть, не читается» (`Bad`) в камере нет;
`TcpClientAddNoReadType` (`Off / AddNoRead / JustNoRead`) — про несколько кодов в кадре. На TCP «плохой код» и «нет кода» неразличимы.
В SDK-канале различие есть в данных (`nBarType 1001`, углы на месте), но в живых прогонах испорченный код давал `ok` или `no_code`,
**`bad_code` ни разу не наблюдался**.

## 9. Стенд: как гонять рецепт `qr_reader_sdk_demo`

1. IDMVS закрыт, VPN выключен, камера на `192.168.1.10`.
2. Любая стенд-команда идёт через `scripts/machine_gate.sh heavy <имя-сессии> …`. Окно (`stand`) выдаёт **координатор** (смотреть `D:\PROJECT_INNOTECH\Inspector_vision\machine.lock`,
   `ListAgents`); имя сессии — **своё** (то, под которым окно выдано), не любое. Закрывает окно координатор; ему шлют
   `window <сессия> closed (<время>): <числа>` и статус портов **8765/8766/5000**.
3. Запуск: `BACKEND_CTL=1 … python multiprocess_prototype/run.py qr_reader_sdk_demo`; состояние: `processes.reader_sdk.state.code_reader_sdk`
   (`device_state=running`), TCP — `reader_tcp`. Остановка — по PID (`TaskStop` не убивает python).
4. Триггер нажимает владелец: сказать время окна, группы по 5 нажатий с паузой ~2 с.

Результат 2026-10-15 (прогон 2, 32 срабатывания): SDK `ok 22 / no_code 10 / bad_code 0`, `dropped 0`, `errors 0`; кадр в `gui` доходит очередью
(процесс безголовый). TCP до исправления терминатора — 11 записей (склейка).
