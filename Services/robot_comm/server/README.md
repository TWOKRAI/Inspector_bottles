# TCP-симулятор робота Delta (universal3)

Modbus-TCP slave с поведением `cvt_universal_full.lua` — для разработки и
тестирования рецептов **без физического робота**.

## Быстрый старт

```bash
# Терминал 1: поднять симулятор (127.0.0.1:5021, unit 2)
python -m Services.robot_comm.server

# То же + окно-монитор обмена (две колонки, счётчик дублей)
python -m Services.robot_comm.server --gui

# Терминал 2: запустить рецепт (после правки host/port в YAML, см. ниже)
python multiprocess_prototype/run.py hikvision_letter_robot
```

## Окно-монитор (`--gui`)

Отвечает на вопрос «сколько заданий инспектор шлёт на ОДНУ деталь».

| Колонка | Что показывает |
|---------|----------------|
| ◀ Принято от инспектора | записи Modbus, подписанные именами из карты регистров (чтения не сорят — только счётчик) |
| ▶ Отдал робот | события ядра: приём задания, завершение, стоп, серво |

Шапка: `заданий · ДУБЛЕЙ · выполнено · чтений`. У каждой строки — время и Δt
внутри своей колонки (три задания за 100 мс видно сразу).

**Детектор дублей** не сравнивает «те же X/Y» — лента едет, и та же деталь на
следующем кадре снята уже в другой точке. Проверяется инвариант трекинга
прошивки: два задания указывают на одну деталь, если разница координат
объясняется проездом ленты за разницу энкодеров

```
невязка = |(Δx, Δy) − (UX, UY)·Δenc·FACTOR_MM| < 5 мм
```

Строка `ДУБЛЬ #3: та же деталь, что #1 (невязка 0.4 мм, Δenc=+1000, Δt=0.07 с)` —
прямая улика пропавшего дедупа в тракте `line_filter → pixel_to_robot →
robot_io → robot_driver` (очередь драйвера — обычная FIFO, дедупа в ней нет).

## Как направить рецепт на симулятор

В файле рецепта (например `multiprocess_prototype/recipes/hikvision_letter_robot.yaml`)
секция `devices:` содержит транспорт робота. Для работы с симулятором замените
`host` и `port`:

```yaml
devices:
  robot_main:
    driver: robot
    transport:
      type: tcp
      host: 127.0.0.1       # было 192.168.1.7
      port: 5021             # было 502
      unit_id: 2
```

## Параметры CLI

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `--host` | `127.0.0.1` | Адрес слушателя |
| `--port` | `5021` | Порт Modbus-TCP |
| `--unit` | `2` | Modbus unit_id робота |
| `--gui` | выкл. | Окно-монитор обмена (нужен PySide6) |
| `--job-ms` | `2500` | Длительность pick-place, мс |
| `--accept-ms` | `20` | Приём задания (`job_flag` 1→0), мс |
| `--belt-mm-s` | `100` | Скорость ленты (пересчитывается в счёты энкодера за тик) |

### ⚠️ Тайминг — не косметика

Дефолт `--job-ms 2500` взят с железа. Раньше ядро отрабатывало задание за
**2 тика = 20 мс**, и на таком «мгновенном» роботе очередь заданий в драйвере
рассасывается быстрее, чем успевает накопиться: дефект «одна деталь → три
задания подряд с задержкой» на симуляторе **не воспроизводится**. Ускорять
осознанно — например `--job-ms 20` для быстрых e2e-прогонов.

Замерено на стенде: `--job-ms 300` → цикл 344 мс, `--job-ms 1500` → 1610 мс;
`--belt-mm-s 100/200` → 97 и 191 мм/с по приросту энкодера.

Для доступа с другой машины (например телефон-пульт через Wi-Fi):
```bash
python -m Services.robot_comm.server --host 0.0.0.0 --port 502
```

## Эмулируемые режимы

| Режим | MODE | Статус | Описание |
|-------|------|--------|----------|
| CVT (pick-place) | 0 | Полностью | Задание + трекинг ленты по энкодеру + поза укладки |
| DRAW (рисование) | 1 | Полностью | Полилиния + окружность, батчи, abort |
| MANUAL (jog) | 2 | Только регистры | Клиент пишет, sim не двигает (ручной jog для калибровки) |
| RETURN (возврат) | 3 | Полностью | Забор из слота + handshake |
| TOOLCHANGE (смена) | 4 | Полностью | target + handshake + обновление tool_cur |

Дополнительно: зеркало ПЧ (VFD bridge 0x1200/0x1210), энкодер (растущий),
телеметрия с heartbeat.

## Зависимости

Требуется `pymodbus` (extra `[modbus]`):
```bash
pip install '.[modbus]'
```

Без pymodbus пакет `robot_comm` работает (FakeRobotTransport для тестов),
но TCP-сервер не поднимется.

## Архитектура

```
SimRobotServer
  +-- pymodbus StartTcpServer  (Modbus-TCP slave, поток server)
  |     +-- action-хук         -> SimJournal.on_write  (сырой обмен с провода)
  +-- RobotSimCore             (конечный автомат, чистая логика)
  |     +-- on_event           -> SimJournal.on_event  (события прошивки)
  +-- ticker-поток             (tick() каждые 10мс = Motion-цикл)

SimJournal (потокобезопасное кольцо) <- drain() <- SimMonitorWindow (QTimer)
```

`RobotSimCore.attach()` привязывает ядро к живому списку регистров сервера
(GIL-безопасная мутация); клиент видит изменения немедленно.
