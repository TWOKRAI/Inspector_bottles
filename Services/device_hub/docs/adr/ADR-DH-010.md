# ADR-DH-010 — полный текст

> Вынесено из [DECISIONS.md](../../DECISIONS.md) по размеру (лимит 32 КБ). Текст ADR перенесён дословно; в `DECISIONS.md` остались заголовок, статус и краткая суть.

## ADR-DH-010: Одно явное состояние RobotDriverV2 под одним замком; драйвер — пакет

**Дата:** 2026-10-20
**Статус:** accepted (T5.3f; решения teamlead стадии 0 Q1–Q10 и владельца 2026-10-20)
**Контекст задачи:** `plans/robot-protocol-v2/tasks/T5.3f.md`; ADR-DH-009 не меняется.

### Контекст

Драйвер робота v2 держал состояние в 30 полях (26 драйвера + 4 `_JogRun`, из них 14 флагов) и в 53 секциях
`with self._flags_lock` в 31 функции; всего 4 замка `threading.Lock()`. Каждый новый флаг проверялся в N воротах
(класс дефектов G2/G4/H* ревью T5.3c/d), `_busy` и `_prog_alive` писались парой в одних местах, файл вырос до
2037 строк, тесты читали и писали 138 приватных имён драйвера (31 из них — поля состояния). Решаем сейчас, пока
SPI хаба и T5.3e стоят на этом драйвере.

### Альтернативы

Q1 — граница замка состояния:

**A. Секции без ввода-вывода под одним листовым замком; I/O под `_jog_tx_lock` и `_param_lock`.**
- Плюсы: порядок замков и записей `STOP_REQ` прежний; поведение не меняется.
- Минусы: остаются 4 замка (3 + замок счётчика потоков модуля).

**B. Ожидание `connect()` под замком параметров переделано (:558).**
- Плюсы: меньше замков.
- Минусы: правка поведения, не рефакторинг.

**C. Один замок и для ввода-вывода.**
- Плюсы: «один замок» буквально.
- Минусы: секция стопа окажется за `JOG_CONT` / `PARAM_SET` — регресс В1 (стоп ждёт медленную запись).

Q7 — как делить файл:

**(i) Миксины по областям + ядро.** Плюсы: код переносится дословно, 75 швов тестов живы. Минусы: связь через атрибуты `self`.

**(ii) Компоненты-объекты.** Плюсы: чистые границы. Минусы: ломает 75 швов (по объёму это задача SPI).

**(iii) Переписать модули.** Плюсы: свободная форма. Минусы: переписывается каждая строка пути стопа.

### Решение

Выбрано A + (i).

- **Состояние.** `RobotState` (`drivers/robot_driver_v2/state.py`): 27 полей (23 + 4 `_JogRun`), 48 переходов + `view()`
  = 49 секций под одним листовым замком `self._lock`; `clock` внедрён. Правило 1:1: секция старого замка → один
  вызов перехода, порядок проверок побуквенно, `connected()` / `budget()` / `ev.is_set()` зовутся под замком в той же
  ветке, где звались (вынос до замка открывает окна W1/W4). Переход решает, драйвер действует вне замка.
- `_busy` + `_prog_alive` слиты в `program_active` (записи парные в одной секции, чтения под замком). `_values`,
  `_epoch` остаются в драйвере под `_param_lock`; `_ready`, `run.handle` — вне состояния.
- Чтение — `drv.state.view()` (замороженный `RobotStateView`, 23 поля; `JogView`). Сеттеров и методов «для тестов» нет.
- **Пакет.** `robot_driver_v2.py` → `drivers/robot_driver_v2/`, путь импорта прежний, `manager.py` не тронут. Модули:
  `state`, `texts`, `args`, `tlm`, `jobs`, `programs`, `params`, `jog`, `ops`, `stop`, `driver`; перенос — по коммиту на
  модуль, код дословно. `__init__` реэкспортирует шесть имён (`RobotDriverV2`, `RobotState`, `RobotStateView`,
  `JogView`, `_JogRun`, `_parse_tlm`); `_PROGRAM_JOIN_S` и `save_params` подменяются в модуле, где имя читается.
- **Отступление (c): сборка в `__init__`.** `driver.py` держит ядро `_RobotDriverCore(BaseDeviceDriver)`, а
  `RobotDriverV2(StopMixin, JogMixin, ProgramMixin, JobMixin, ParamMixin, OpsMixin, _RobotDriverCore)` и
  `RobotDriverV2._OPS = OPS` собираются в `__init__.py`. Причина: при сборке в `driver.py` fan-out файла 17 > 15 и
  `sentrux` `no_god_files` краснеет.
- **Переходы — внутренние, не SPI хаба.** Код вне пакета и вне тестов их не зовёт; сторожит
  `Services/device_hub/tests/test_no_private_driver_state.py` (AST). Тесты не трогают поля состояния (31 → 0); швы
  (`_client`, `_param_lock`, `_epoch`, …) — литеральный белый список `_SEAMS`, сумма 112 (регэксп стадии 0 дал 107, AST
  на HEAD `dbb62fb36` — 112: −1 `_lease_loop` был docstring, +6 `_reconnect_attempts` — имя базы). Сторож сканирует все тесты
  двух каталогов, кроме 7 тестов других драйверов (40 файлов). Снятие швов — задача SPI хаба.

Окна гонок (решение владельца 2026-10-20: T5.3f их не закрывает, не открывает и не пробует):

| окно | суть | статус |
|---|---|---|
| W1 | `request_stop` посреди `connect`: `shutdown` уже True, `_ready` ещё False — простой робот «не подключён», SOFT не записан, затем `connect()` → True | закрыто T5.3g (ADR-DH-011) |
| W1′ | `connect` выходит между секциями `request_stop` (`request_stop_begin` → `process_stop_plan`): план видит «не подключён», 0 SOFT | закрыто T5.3g (ADR-DH-011, снимок `_stop_linked`) |
| W2 | 6 записей `_ready` без замка | закрыто T5.3g (ADR-DH-011, `_ready` в `RobotState`) |
| W3 | `run.handle` под `_jog_tx_lock`, чтение без него | по замыслу К4, не дефект |
| W4 | `connect_reset` после `request_stop`: `shutdown` True при `stopping` False, «стоп не подтверждён» теряется | закрыто T5.3g (ADR-DH-011, `connect_begin`) |

### Последствия

- **Числа до → после** (команды — `plans/robot-protocol-v2/tasks/T5.3f.counts.md`):

- **Архитектура:** новое поле или флаг — один класс и один замок вместо N ворот; порядок ADR-DH-009 (записи стопа,
  таймаут `_jog_tx_lock`, повтор, эхо) не менялся. Миграции нет: путь импорта и публичные имена прежние.
- **Ограничения:** новый переход — только внутри `RobotState`, в одной секции, без ввода-вывода; ввод-вывод — под
  `_jog_tx_lock` / `_param_lock`; новый тест другого драйвера вносится в
  `_OTHER_DRIVER_TESTS` сторожа, иначе его швы войдут в счёт (литерал файлов `_SCANNED_FILES` = 40).
- **Риски:** (1) W1 и W4 найдены чтением кода, не воспроизведены — проба с барьером в T5.3g. (2) Сторож (б) не видит
  пять общих имён переходов (`view`, `enqueue_job`, `enqueue_return`, `stop_unconfirmed`, `stop_unconfirmed_text`) через
  псевдоним (`st = drv.state; st.view()`) и `getattr(drv.state, …)`; уникальные имена ловятся при любом получателе.
  (3) Любая правка пути стопа требует повтора матрицы инъекций (M1–M10, H1–H4, L-I1..L-I5, `T5.3f.injections.md`): прежние красные обязаны остаться красными.
