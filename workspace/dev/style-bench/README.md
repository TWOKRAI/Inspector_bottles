# style-bench — проверка идеи плагина Terse на нашем проекте

Вопрос: даёт ли хук-напоминание о стиле (идея [lowenbjer/claude-terse](https://github.com/lowenbjer/claude-terse))
короче и дешевле ответы поверх наших STE-80 и `CLAUDE.md`.

- **A** — проект как есть.
- **B** — то же плюс `UserPromptSubmit`-хук (`inject.py`), который на каждом ходу добавляет `reminder.md` (около 100 токенов).

Хук подключается только флагом `--settings` в вызове `claude -p`. `.claude/settings.json` стенд не меняет.
Каждый вызов идёт отдельной сессией: только чтение (`Read,Grep,Glob`), без MCP, лимит $1 на вызов.

## Запуск (из корня репозитория)

```bash
python workspace/dev/style-bench/run.py --dry-run              # план вызовов, без затрат
python workspace/dev/style-bench/run.py --mode single --reps 3 # 8 промптов × 2 варианта × 3 = 48 вызовов, ≈ $23
python workspace/dev/style-bench/run.py --mode chain --reps 2  # 8 ходов × 2 × 2 = 32 вызова — дрейф в длинной сессии
python workspace/dev/style-bench/run.py --report-only          # пересобрать report.md и answers.md
```

Прогон можно прервать: повторный запуск пропускает готовые строки из `results.jsonl`.

## Что смотреть

- `report.md` — слова, output-токены, стоимость (среднее ± sd), первое лицо, тире, закрывающие фразы; в режиме chain — слова по номеру хода.
- Строка «Нарушений проверки хука» должна быть 0. Иначе B не отличался от A, и сравнение пустое.
- `answers.md` — ответы рядом, для ручной оценки точности. Стенд меряет длину, а не правильность.

## Итог 2026-10-11 (Opus 5.5)

Токены: single, 24+24 ответа — output 3 271 → 1 881 на ответ (−42%).
Chain, ходы 1–7, 2+2 цепочки (`chain_tokens.py`) — вход 8,27 млн → 5,04 млн (−39%), output 43 749 → 23 518 (−46%).
Вход на ~95% — `cache_read`, и он зависит от числа вызовов инструментов (93 → 64), а не от длины ответа.

Качество: слепая оценка 4 оценщиками Opus по коду, 48 ответов single (`make_judge_packets.py`, `unblind.py`, `judge_scores.tsv`):

| Вариант | верность | полнота | польза | сумма из 15 |
|---|---|---|---|---|
| A | 4.15 | 4.48 | 4.52 | 13.15 |
| B | 3.85 | 3.46 | 3.71 | 11.02 |

B выиграл 1 вопрос из 8 (q2, подсчёт) и сравнялся на 1 (q6, записка). Проиграл на объяснениях и разборах (q3, q5, q7): не хватало частей ответа.
Вывод: напоминание с лимитом 150 слов экономит около 40% токенов ценой −16% качества. В таком виде не внедрять.
Полезная часть без потерь: закрывающие фразы 33% → 0%. Непроверенный вариант C — напоминание без лимита слов.

Ограничения: n = 3 на вариант на вопрос; оценщики видели длину ответа; режим chain по качеству не оценивался.
