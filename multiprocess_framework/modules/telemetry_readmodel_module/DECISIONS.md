# telemetry_readmodel_module — решения

Модуль появился при извлечении Qt-free ядра read-model телеметрии из GUI
`TelemetryViewModel` (план `backend-ctl-framework-module`, Task 2.3).

## Почему модуль существует (reuse-vs-own)

Полное решение и отвергнутые альтернативы — **FE-005** в
[`frontend_module/DECISIONS.md`](../frontend_module/DECISIONS.md). Кратко:
одно generic Qt-free ядро (снимок + история + тонкие инварианты) переиспользуют
и GUI (`TelemetryViewModel`, Qt-обёртка), и headless-драйвер диагностики
backend_ctl — чтобы не дублировать инварианты `snapshot`-boundary /
number-coercion / ring-window (дрейф двух копий).

## Границы модуля

- **Транспорт-агностично:** ядро принимает уже разобранную дельту
  (`ingest(path, value, deleted)`); разбор конверта (`state_delta` /
  `state.changed`) — у потребителя.
- **Без Qt и без IPC:** не импортирует PySide6, не создаёт подписок, не ходит на
  сервер (`get`/`snapshot`/`history` локальны — принцип ADR-136 «чтение локально»).
- **Живая история — в памяти; глубокая — вне модуля:** БД-сток телеметрии
  (час/день) читает `frontend_module.state.TelemetryHistorySource`.

## Порядок записи — второй инвариант ядра (S-1, нога B, 2026-08-17)

**Что было неправдой.** У read-model **два входа** — push (`ingest`) и ответ
опроса, — и до S-1 они были равноправны: побеждал тот, кто записал последним по
факту прибытия. Оборот запроса опроса меряли 7.5–10 с, поэтому ответ, отправленный
ДО остановки плагина, приходил ПОСЛЕ снятия уровня и перетирал `None` старым
числом:

```
t1  poll: запрос ушёл (в дереве probe_level = 12.5)
t2  push: probe_level -> None   (плагин остановлен, снятие доехало)
t3  poll: ответ пришёл -> 12.5  <- воскрешение, сторожа порядка нет
```

Расхождение необратимо и **в противоположные стороны**: push говорит «показания
нет», опрос — «12.5».

**Решение: номер записи, а не часы.** Ядро ведёт `write_seq` — число ПРИНЯТЫХ
записей push-дороги — и помнит номер последней push-записи по каждому пути.
Опрашивающий снимает `write_seq` в момент ОТПРАВКИ и возвращает его во влив
(`requested_at_seq`); путь отбрасывается при `push_seq[path] > requested_at_seq`.

| Вариант | Почему не он |
|---|---|
| Часы (`monotonic`/`time` на записи) | на Windows разрешение `monotonic` — **15.6 мс**, и две записи одного оборота цикла получают ОДНУ метку: «кто раньше» по ней не восстановить. Ровно тот класс, на котором уже обжигался троттл (ADR-PM-017) |
| `snapshot_ts` из ответа опроса | это возраст ОТВЕТА, а не чисел (ADR-PM-035): у остановленного воркера он идёт, а `fps` стоит |
| Сторож в поллере, а не в ядре | номера записей живут в ядре; вторая копия правила в поллере разошлась бы с ним молча, а у headless-драйвера сторожа не было бы вовсе |
| Отбрасывать ОТВЕТ целиком | один ответ несёт несколько путей и терять может часть — целиком потеряли бы и свежие листья |
| Номер в замыкании callback'а поллера | запись о полёте (`_in_flight`) уже привязана к цели и уже переживает оборот; второе место хранения разошлось бы с первым при выселении по TTL |

**Граница `==` принимается, и это доказуемо.** `write_seq` увеличивается ПОСЛЕ
применения записи, поэтому равенство означает «эта push-запись уже была учтена в
снимке, против которого снимали номер» → ответ опроса свежее. Строгое `>`.
Отличить `>` от `>=` может только прямой удар по границе — он есть отдельным
тестом (`==` вливается, `+1` отбрасывается), иначе правка на `>=` прошла бы молча.

**Названные цены, а не умолчания.**

* `path → номер` — вторая копия множества путей. Чистится в `_purge_subtree`, там
  же, где путь уходит из снимка; иначе словарь рос бы по числу когда-либо
  виденных путей — утечка медленная и без симптома. Обмен: удалённый узел теряет
  и защиту сторожа, поэтому ответ, улетевший до удаления, путь восстановит (окно
  — оборот запроса, только для явного `deleted=True`, не для снятия уровня).
* Стоимость на push-дороге измерена: `+70 нс` на вызов `ingest` без истории
  (353 → 422 нс, +19.7%) и `+101 нс` с историей (935 → 1035 нс, +10.8%). На
  боевой раскладке (6 процессов, 96 листьев, тик 1 Гц) это **96 записей в
  секунду × 70 нс ≈ 6.7 мкс/с**. Память: `_push_seq` = 96 строк / 3328 байт —
  зеркало `_state` по ключам.
* Пересоздание ядра обнуляет счётчик. Номер с прежнего экземпляра — из чужой
  шкалы; у свежего `push_seq` пуст, поэтому сторож **вырождается** в прежнее
  поведение (применяет всё), а не отбраковывает ложно. Живой дороги к этому нет
  (поллер держит ссылку на конкретный экземпляр), но свойство названо и
  проверено тестом, чтобы «сторож защищает всегда» не стало посылкой разбора.

**Лока нет, и это проверяемая посылка, а не декларация.** `write_seq` читает
поллер в `_tick` (QTimer владельца), пишет ядро в `on_state_delta` (слот моста) —
обе дороги идут потоком владельца; headless-драйвер работает своим единственным
потоком приёма. Посылку держит тест
`frontend_module/tests/state/test_telemetry_poll_ordering_hazards.py::test_both_sides_of_the_guard_run_in_the_owner_thread`:
переедет влив или тик в исполнителя — красным станет он, а не гонка в проде.
