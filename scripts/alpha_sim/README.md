# scripts/alpha_sim — прогон сценария α на симе (P4)

Скрипт через `backend_ctl` ставит случаи B, D, C на сим, затем «домой» и чистый стоп,
и печатает по каждому диску «вход → наблюдение» с PASS/FAIL по литералам.

## Назначение

- Случаи: **B** «ПЕРЕМИРИЕ» (12 дисков), **D** смена слова на «МИР» без перезапуска (5 дисков),
  **C** одинаковые диски подряд (4 диска Е), **ДОМОЙ** (`robot_park_all`), **СТОП** (SOFT `STOP_REQ`
  и disconnect по файлу журнала обмена).
- Скрипт **не выносит вердикт «α пройдена»**: это Task 1.2 приёмки. Он даёт журнал, PASS/FAIL и код выхода.
- Спека: `plans/word-layout/tasks/P4.md`. Литералы случаев: `scripts/alpha_sim/logic.py` (`CASES`).
- Состояние и числа последнего стенда: `scripts/alpha_sim/STATUS.md`.

Файлы: `logic.py` — чистая логика (литералы, разбор, судьи, углы, печать); `run_alpha.py` — CLI и шаги P0–P6;
`tests/` — тесты на фейках драйвера, без стенда.

## Предусловия

- Окно стенда `stand`; порты 8765, 8766, 8091, 8092, 5021 свободны до старта.
- Прототип **свежий перед каждым прогоном**: пустое слово в регистр не пишется. На уже использованном
  прототипе скрипт выходит с `предусловие: нужен свежий прототип` (rc 3).
- Сим с буквенными ассетами (33 буквы в `<tree>/data/line_sim/letters_ink`; сборка —
  `python -m Services.line_sim.tools.build_stand_assets`). Веса сети — в `<tree>/data/models`.

## Как запустить

Команды из корня дерева стенда `<tree>` (для worktree — корень worktree). Порядок: сим, прототип, скрипт.

```bash
# 1. сим, порт 8766
BACKEND_CTL=1 BACKEND_CTL_PORT=8766 PYTHONUTF8=1 python apps/line_sim/run.py

# 2. прототип, порт 8765, свежий; логи в тот же каталог, что читает скрипт
BACKEND_CTL=1 PYTHONUTF8=1 INSPECTOR_LOG_DIR=<tree>/data/logs/prototype \
  INSPECTOR_MANIFEST=<копия multiprocess_prototype/app.yaml> \
  python multiprocess_prototype/run.py letter_robot_sim --headless

# 3. скрипт
PYTHONUTF8=1 PYTHONPATH=<tree> python -m scripts.alpha_sim.run_alpha --tree <tree> [--dump <файл.json>]
```

Опции `run_alpha`:

- `--tree` — корень дерева стенда (обязательно);
- `--log-dir` — каталог логов прототипа, умолчание `<tree>/data/logs/prototype`; тот же путь, что `INSPECTOR_LOG_DIR`;
- `--proto-port` (8765), `--sim-port` (8766);
- `--dump` — JSON со всеми собранными записями (доказательство для Task 1.2).

Без `INSPECTOR_LOG_DIR` файл журнала обмена ляжет в `<cwd>/logs/prototype_2`, и шаг СТОП выдаст FAIL с названной причиной
(нет файла по `--log-dir`). Файл, который в `--log-dir` есть, но записан не этим запуском (`mtime` раньше отправки
`system_shutdown` минус 2 с, например остался от прошлого прогона), тоже даёт FAIL СТОП: «файл журнала не от этого запуска».
В файле дописываются все запуски прототипа подряд; судится только последняя инкарнация (номер `seq` начинается с `#1` заново).

## Шаги P0–P6

| Шаг | Что делает | Срок | Выход при сбое |
|---|---|---|---|
| P0 | Сторож слушателей: кто слушает 8766 (`apps/line_sim/run.py`) и 8765 (`multiprocess_prototype/run.py` с `letter_robot_sim`), cwd под `--tree`. Чужой или никого — печать PID, команды, cwd; драйвер не вызывается | до connect | rc 3 |
| P1 | Connect. Сим: `scene.status`, очередь не в режиме списка с остатком. Прототип: регистр `layout` пуст, `jobs_emitted` 0 | — | rc 3 |
| P2 | S0: `robot_main` connected. S1: `P_PICK_RZ.raw == -1000`. S2: `log_tail layout INFO`. Журнал обмена включён | 60 с | rc 3 |
| P3 | Сим: `scene.sequence {"random": true}`. Прототип: `vfd_run` 10 Гц. Ждём строку диска в журнале `layout` | 120 с | rc 3, диагностика `recog` |
| P4 B, D, C | Пауза сима, сцена пуста, хвост прошлого случая, 3,0 с тишины в журнале, сброс журнала обмена и база, слово в регистр, список дисков, снять паузу, сбор, судья. Перед B — `defect_rate 0.0` | 60 / 60 / 3 / 180 с | слово не записано — rc 1; прочие сбои — rc 3; далее уборка |
| P5 ДОМОЙ | `robot_park_all` (`timeout_s` 30, ответ ждём до 40 с); статус `park` догнал ответ `seq` и `done` | 5 с на статус | FAIL ДОМОЙ |
| P6 СТОП | `system_shutdown(wait, 60 с)`; порт 8765 освободился; файл `<log-dir>/devices/robot_exchange.log`: один SOFT и disconnect | 10 с на порт | FAIL СТОП |

Сбой в P4 запускает уборку: ДОМОЙ → СТОП → снять паузу сима → режим подачи `random`.
Каждый шаг уборки в своём `try`. При сбое в P1–P3 уборки нет: `robot_park_all` и `system_shutdown` не зовутся.

## Коды выхода

| rc | Значение |
|---|---|
| 0 | все проверки PASS |
| 1 | хотя бы одна FAIL (диск, проверка, ДОМОЙ, СТОП, слово не записано) |
| 2 | ошибка аргументов (`argparse`) |
| 3 | предусловие не выполнено (стенд не тот или не готов, сим занят, нет буквы в каталоге, исключение) |

## Что скрипт меняет на симе и стенде

- Сим: `defect_rate` = 0.0 перед B, назад не возвращается.
- Сим: режим подачи → `random` (в P3, в уборке и в конце прогона). Если сбой после P3, режим остаётся `random`.
- Сим: пауза ставится и снимается; при сбое снимается уборкой.
- Стенд: лента 10 Гц (`vfd_run` прототипа). Скрипт её **не останавливает**.
- Прототип: ДОМОЙ и `system_shutdown` (СТОП) — только после P4 или при сбое в P4.
- Сим и прототип скрипт **не запускает и не останавливает** (прототип останавливает шагом P6).

## Что скрипт НЕ делает

- Не выносит вердикт α. Итог `итог: …` — только PASS/FAIL по случаям, код выхода.
- Не доказывает, что окна съёма §2.8 верны: это литералы; сужать или расширять окно — решение владельца.
- Не меняет рецепт, геометрию, `angle_invert`, `angle_zero_deg`; не шлёт `belt.run`/`belt.stop`.
- Не видит итог медленного процесса при `system_shutdown`: при `unconfirmed` и `pm_gone True` — PASS с пометкой
  «итог детей не виден (предел драйвера)».

## Как читать вывод

Строка диска (сокращена):

```
B #5 вход Е 90.0° → наблюдение: диск 'Е' 91.9° → ячейка 3: взять(460.2,-341.3) → положить x320.0 y-110.0 z-132.0 r-91.9° [4/9] | Δугла +1.9° | CVT_JOB ARGS[7]=64436 ARGS[9]=63617 RES=1 → FAIL: pick (460.2, -341.3) вне окна …; ARGS[3] 62123 ≠ 62096…62116
```

- `вход` — что подано: буква и угол подачи из списка случая.
- `наблюдение` — строка журнала `layout` без префикса `WordLayoutPlugin: ` (диск, угол сети, решение, взятие, положение, `[k/n]`). Для взятого диска — аргументы задания `CVT_JOB`: `ARGS[7]` — ячейка, `ARGS[9]` — окно угла, `RES` — ответ робота.
- `Δугла` — угол сети минус угол подачи. Судится только буква; угол проверяют окна `r` и `ARGS[9]`.
- `→ PASS` или `→ FAIL: причина; причина`. Причины начинаются с ключа поля: `letter`, `decision`, `cell`, `progress`, `pick`, `place`, `r`, `feed`, `argc`, `ARGS[i]`, `res_status`, `res_errno`, `нет задания`.
- Строки проверок случая: `B word_line`, `B lines.count`, `B jobs.count`, `B regs.<поле>`.
- `углы: …` — блок углов «сеть против подачи» (Δ и Δинв). На код выхода не влияет.
- `предусловие:`, `cleanup:`, `ошибка:` — что остановило прогон. `изменено в симе/на стенде:` — что скрипт поменял.
- `INFO поздняя строка диска после случая X: …` — строка диска пришла после точки судейства случая (её проглотила бы тишина перед следующим); пишется и в `--dump` (`late_disk_lines`), на код выхода не влияет. Ctrl-C во время случаев: уборка (ДОМОЙ → СТОП → пауза снята → random), затем прерывание поднимается снова.
- `итог: B=… D=… C=… ДОМОЙ=… СТОП=… → код N (вердикт α — Task 1.2, не этот скрипт)`.

