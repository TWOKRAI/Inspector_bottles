# graph_slice — срез графа graphify по границе модуля

Режет единый граф проекта (`graphify-out/graph.json`, ~30k узлов) до одного модуля
и показывает главное перед рефакторингом: **кто зависит от модуля** и **от чего
зависит он сам**. Внутренности — по флагу.

Запуск (из корня проекта):

```bash
python scripts/graph_slice/graph_slice.py channel_routing_module
```

Slash-команда: `/graph-slice`.

---

## 1. Зачем, если есть graphify-MCP

MCP-инструменты graphify отвечают на «что связано с этим узлом». Они не умеют
резать граф по пути, и поиск по ключевому слову утаскивает выдачу в чужие модули
через одноимённые символы: запрос `logger_module reconfigure rollback` вернул
7 узлов `VersionManager` из `data_schema_module` (там свой `.rollback()`) плюс
12 заголовков README — а 11 узлов из 39 при этом срезал лимит бюджета.

`graph_slice` даёт границу модуля явно, детерминированно и без бюджета на выдачу.

Разделение труда:

| Вопрос | Инструмент |
|--------|-----------|
| «Кого заденет правка модуля?» | `graph_slice` |
| «Что связано вот с этим символом?» | `mcp__graphify__get_neighbors` |
| «Где используется X» по смыслу | `mcp__qex__search_code` |
| «Есть ли циклы, насколько связаны модули» | `mcp__sentrux__dsm` |

## 2. Свежесть — читать первой строкой

Граф это снимок. Скрипт **всегда** сверяет `built_at_commit` графа с `HEAD` и с
рабочим деревом именно по файлам модуля, и печатает предупреждение:

```
ГРАФ: собран на 473fc220 | HEAD 9d978d98
  ВНИМАНИЕ: срез может врать — 9 файлов изменено после сборки. Обнови: graphify update .
```

Правки тестов свежесть не ломают: `tests/` и `test_*.py` исключены из графа
через `.graphifyignore`, поэтому в подсчёт не идут.

## 3. Основные режимы

| Команда | Что даёт |
|---------|----------|
| `graph_slice.py <модуль>` | границы модуля: входящие и исходящие, сгруппированы по соседям |
| `graph_slice.py <модуль> --inner` | плюс внутренние связи |
| `graph_slice.py <модуль> --inbound-only` | только «кого заденет» — самое частое перед правкой |
| `graph_slice.py <модуль> --symbol ChannelRoutingManager` | границы одного символа |
| `graph_slice.py <модуль> --format json` | машинный вывод для агентов |
| `graph_slice.py --list` | доступные цели с числом узлов |
| `graph_slice.py <модуль> --list-symbols` | символы модуля в графе |

Цель — имя модуля (`logger_module`), путь модуля вне `modules/` (`Services/sql`,
`Plugins/processing`) или произвольный префикс пути
(`multiprocess_prototype/frontend/widgets/tabs/pipeline`).

Прочие флаги: `--docs` (вернуть `.md`-узлы и рёбра `rationale_for`),
`--relations calls,imports_from`, `--top N`, `--examples N`, `--all`,
`--graph <путь>`.

## 4. Как читать вывод

```
СРЕЗ channel_routing_module  —  multiprocess_framework/modules/channel_routing_module
  узлов 312 | внутри 334 | входящих 61 | наружу 26

КТО ЗАВИСИТ ОТ МОДУЛЯ (входящие): 61
  statistics_module  [21]  imports 7, inherits 6, imports_from 5, calls 3
      StatsManager → ChannelRoutingManager  [inherits]  .../stats_manager.py:L43
```

Стрелка всегда по направлению ребра (`источник → цель`), независимо от секции.
Группа — внешний модуль, в скобках число рёбер, дальше разбивка по типам связи.

По умолчанию считаются только связи кода: `calls`, `indirect_call`, `imports`,
`imports_from`, `inherits`, `uses`, `re_exports`, `method`, `contains`, `defines`.
Рёбра `rationale_for` и `references` — документальные, включаются флагом `--docs`.

## 5. Важная оговорка про `--symbol`

Граф вешает внешние вызовы на **класс или файл**, а не на метод. У `.flush()`
поэтому будет ноль входящих рёбер, хотя снаружи её зовут. Прочитать этот ноль как
«никто не зависит, можно менять» — прямой путь к сломанному потребителю, поэтому
скрипт печатает владельца и его входящие:

```
КТО ЗАВИСИТ ОТ МОДУЛЯ (входящие): 0
  — нет
  ВАЖНО: это НЕ значит «никто не зависит». Граф вешает внешние вызовы
  на класс/файл, а не на метод. Смотри владельца символа:
      --symbol ChannelRoutingManager   (входящих у владельца: 7)
```

## 6. Тесты

```bash
python -m pytest scripts/graph_slice/tests/ -q
```

15 тестов на синтетическом мини-графе (реальный `graph.json` не нужен, результат
не зависит от даты сборки). Каталог включён в `testpaths`, поэтому идёт в общем
гейте. Четыре теста — регрессы на дефекты, найденные при первом прогоне:
перевёрнутая стрелка в секции «наружу», ложный ноль у `--symbol`, срезанный
первый символ пути из `git status --porcelain`, и `strip()` в `_git`, который этот
срез и провоцировал.

Все шесть защит проверены break-injection: каждая ломается отдельно, падает ровно
ожидаемый тест.
