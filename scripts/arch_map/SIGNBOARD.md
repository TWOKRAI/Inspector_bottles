# signboard — вывески кода на каждом уровне зума

Что это: скрипт `scripts/arch_map/signboard.py` считает из кода (стандартная библиотека, `ast`; помощники берёт
импортом из `build.py`) карточку для каждого уровня карты: слой → юнит → пакет → файл (район) → класс/функция (дом).
Дома — не узлы графа `model.json`; их карточки считаются обходом `ast` по репозиторию.

## Команды (из корня репозитория, `PYTHONUTF8=1`)

| Команда | Что делает |
|---|---|
| `python scripts/arch_map/signboard.py show <путь>[::<имя>] [--format json\|text]` | карточка: `файл.py::Класс`, `файл.py::Класс.метод`, `файл.py`, каталог юнита или пакета, имя слоя |
| `python scripts/arch_map/signboard.py bench --targets docs/arch-map/_bench/k0_targets.json --out docs/arch-map/_bench/k0_reference.json` | эталон по списку целей `[{id, path, qualname?}]`; руками не правится |
| `python scripts/arch_map/signboard.py cards --out docs/arch-map/cards.html` | статическая страница (без CDN, открывается с диска); `#card=<ключ>` в адресе закрепляет карточку |

`--root` задаёт корень (по умолчанию текущий каталог). Проектные умолчания — один блок в начале файла.
Индекс репозитория строится за ~8 с; каталоги `data` и `plans`, точечные каталоги и `docs` пропускаются.

## Правило карточки

Строка 1 — что это. Строка 2 — «использует меня N / использую M». Красным — только нарушенное правило
(«нарушений направления: N» показывается и при 0, но не красным). Остальное — под сгибом.

## Что считается и чем это ненадёжно

- **Вид дома.** Protocol и ABC — по базам (`class_style`); иначе `plugin`/`manager`, если имя класса или листовое
  имя базы кончается на `Plugin`/`Manager`; иначе `class`.
- **Наследники** — по листовому имени базы, прямые. При совпадении имён у нескольких классов остаются те, чей файл
  импортирует базу из её модуля или пакета над ним.
- **Структурные двойники** (не наследуют, но имеют все абстрактные имена ABC или все члены Protocol) — только по
  именам в теле класса, унаследованное не видно. Протокол из одного `__call__` даёт много случайных совпадений.
- **Вызовы по имени** — вызов импортированного имени (`from M import N [as L]`, `mod.N(...)`), импорт из модуля
  определения или пакета над ним. Динамические вызовы, `getattr`, повторный экспорт из пакета не по цепочке
  предков — невидимы. **0 не значит «не используется».** Для метода — любой `.имя(` в файле, импортирующем класс.
- **Тесты** — nodeid test-функций, упоминающих имя; если файл импортирует имя, но ни одна test-функция его не
  упоминает (фикстуры, параметризация) — путь файла без `::`.
- **Ввод-вывод** — `open`, `.open`, `read_text`/`write_text` (+`_bytes`), `json.dump`/`yaml.safe_dump`/`yaml.dump` с
  потоком, `.schedule(`; `open` и `json.dump` в одном `with` — одна запись; путь — текст выражения, не значение.
- **Слой, юнит, пакет** читают `docs/arch-map/model.json`; fan-in/out слоя и пакета — число импортов hard+lazy
  через границу, юнита — число юнитов из `spec`. «Нарушений направления» — находки `layer-reverse` с источником внутри.
  Запись «можно → …; нельзя ← …»: что узел может импортировать и откуда импортировать не может.

Тесты: `scripts/arch_map/tests/test_signboard.py`.
