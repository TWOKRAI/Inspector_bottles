# atlas — архитектурные решения (ADR)

Реестр доказанности и знаний (`scripts/atlas/`): собирается из git, планов, `modules.yaml`, документов, тестов и итогов
задач; показывается карточкой агенту и страницей владельцу. План — `plans/2026-10-04_atlas/plan.md`; рамка — вердикт
CTO `plans/2026-10-04_atlas/research/CTO_VERDICT.md`. Серия ATL — пакет вне `multiprocess_framework` (как `backend_ctl`).

## ADR-ATL-001: схема реестра и контракт `--json` (Task 1.1)

**Дата:** 2026-10-06 (ред. 3 — после двух раундов ревью стадии 0)
**Статус:** Accepted — CTO ACCEPT WITH CONDITIONS 2026-10-06, условия внесены (ред. 4); reviewer `MODE: plan` — 2 раунда

### Контекст

Цепь `commit → Task → plan → module → doc` и цепь доказанности (диаграмма 3б страницы Атласа, коммит `38462b530^`:
модуль → интерфейс → гарантия ← тест ← инъекция; балл из CI) нужно держать в одном реестре. Реестр — производная: его
не коммитит никто, он строится от дерева сборки (принципы 1, 2, 4 плана). Ядро ≤ ~600 строк до второго адаптера,
хранилище `data/atlas.sqlite` (`sqlite3` stdlib, ≤ 6 таблиц), graphify — необязательный вход. Потребители схемы:
адаптеры 1.3a–1.5b, виды 1.6, гейты 1.7, HTML 3.1. Схема, изменённая после 1.2, переделывает всех — поэтому она
фиксируется до первой строки ядра.

### Решение

#### 1. Узел

`Node{kind, id, path, status, edges, findings}` (+ `time`, см. последний пункт списка):
- `kind` — один из видов таблицы ниже; `id` уникален внутри `kind`; ключ узла — `kind:id`;
- `path` — файл-источник от корня репозитория, или `null`, если узел выведен только из git;
- `status` — строка источника без перевода (у задачи — словарь парсера планов; у документа — `fresh`/`stale`), иначе
  `null`;
- `edges` и `findings` в `--json` лежат отдельными списками со ссылкой `kind:id`; в узел не вкладываются (одна запись
  на факт). В модели Python это представления, собираемые запросом.
- `time` (добавлено при брифе 1.2, в конец записи по §5) — время коммита в секундах Unix у узла `commit`, иначе `null`;
  на нём стоят запросы «тронуто за N дней». Запись узла в `--json`: `kind`, `id`, `path`, `status`, `time`.

| `kind` | `id` | источник | строит |
|---|---|---|---|
| `module` | `id` из `modules.yaml` (`router_module`, `process_module/generic`) | `modules.yaml` | 1.3a |
| `plan` | slug: имя каталога плана без префикса `YYYY-MM-DD_` (правило `validate_commit`; коллизий 0 из 148) | `plans_progress --json` | 1.3a |
| `task` | `<slug>#<id>` (`atlas#1.2`) | строка задачи, тот же парсер | 1.3a |

Урок только с `mechanism:` (без `module:`) — узел без рёбер: в карточку модуля не попадает, виден поиском по механизму
(1.6) — принятый предел. Правило «нет `__all__`»: так у 14 нетестовых `interfaces.py`, в том числе у всех 11 `Services/*` (ревью стадии 0).
Мутационный балл — не узел, а снимок метрики модуля (`data/quality/<module>.json`, 1.8). Ветки, трогающие модуль, —
не узлы: вид 1.6 считает их при показе.

#### 2. Рёбра

`Edge{kind, src, dst, via}`; `via` — откуда ребро выведено (`trailer:Refs`, `path`, `ast-import`, `plan-line`,
`marker`, `table`), чтобы находка назвала источник.

| `kind` | `src → dst` | вывод | звено |
|---|---|---|---|
| `refs` | commit → plan | трейлер `Refs:` **всех предков сборки без слияний** (`git log --no-merges <sha>`; трейлеры коммитов-слияний не читаются): по ребру на каждую пару (коммит, slug) из токенов `(?:^|(?<=[\s,;(]))plans/[^\s,;)]+` значения (левая граница — начало значения или пробел `,` `;` `(`; после `rstrip(".")`); значения вне `plans/` и `plans/` внутри чужого пути (`docs/plans/x.md`) рёбер не дают | цепь |
| `implements` | commit → task | трейлер `Task:` всех предков сборки без слияний (как у `refs`) | цепь |

Причина «все предки без слияний» (2026-10-07): fast-forward `main` на коммит «merge main в ветку» (`a5ae9657a`, lifecycle T1) перевернул first-parent историю — слияния PR #5–#14 оказались на втором родителе, на пине `a5ae9657a` в first-parent 0 строк `Task:` и 9 рёбер `implements` вместо 176. Историю не переписывают. Источник ребра `refs`/`implements` и узел находки `REF_*` всегда имеет узел `commit` (п. 1 таблицы узлов); рёбра `touches` строятся как прежде — только для коммитов прежнего набора (first-parent, PR, цели DONE). Принятый предел: опечатка только в `Refs:` коммита-слияния в гейт не попадает.

виды 1.6 и 1.7, не рёбра.

#### 3. Находки

`Finding{code, severity, node, detail, message, source}`; `severity` ∈ `blocking | warning | info`; `node` — `kind:id`;
`detail` — то, что различает две находки одного кода на одном узле (цель ссылки, имя метода, путь `Refs:`), иначе `""`;
`source` — файл и строка или SHA. Уровни и гейт — ADR-ATL-002. Код — стабильная строка; переименование = новая находка.

| `code` | на чём | смысл |
|---|---|---|
| `PRE_POST_MISSING` | interface | у публичного метода, изменённого в диффе, нет `Pre:`/`Post:` (парсер `scripts/s2_gate.py`; `detail` — `Class.method`) |
| `BROKEN_LINK` | doc, test | относительная ссылка `.md` или `guards` ведёт в несуществующее |
| `REF_TO_MISSING` | commit | цели `Refs:` (токен пути `plans/…`; `detail` — токен как найден, `source` — полный SHA коммита) или `Task:` (план по slug; `detail` — значение `<slug>#<id>` как написано) нет ни в дереве сборки, ни в дереве самого коммита; путь проверяется одним `git cat-file --batch-check` по парам `<sha>:<путь>` (сборка и коммит), план по slug — `git ls-tree -z --name-only <sha> plans/ plans/_archive/` только для коммитов, чьего slug нет среди планов сборки; служебные имена (`queue`, `_archive`, `QUEUE.md`, `README.md`, имена на точку, `*.result-*.md` — константа `_SERVICE_NAMES` и правила в адаптере, зеркало `plans_progress.is_service_name`; `plans_progress` — источник данных через `--json`, не донор кода, синхронность держит тест-сверка) в дереве коммита не считаются планами (`Task: README#1.1` — `REF_TO_MISSING`, не `REF_MOVED`); id задачи из `Task:` ищется только в дереве сборки тем же парсером `plans_progress`, второго парсера нет (план есть, id нет — `REF_TO_MISSING` без проверки дерева коммита) |
| `REF_MOVED` | commit | цель `Refs:`/план из `Task:` была в дереве коммита, в дереве сборки её нет (архив, перенос); поля — как у `REF_TO_MISSING` |
| `DONE_HASH_NOT_IN_MAIN` | task | хеш в строке DONE не предок `HEAD` сборки (в PR — вершины PR, после слияния — `main`) |
| `PLAN_SLUG_COLLISION` | plan | два плана с одним slug: сохраняется живой раньше архивного, затем по `path`; отброшенный план уходит целиком вместе с задачами; `detail` и `source` — путь отброшенного (Task 1.3b; прежний `exit 2` ронял `check` всех PR после слияния такого плана) |
| `DONE_WITHOUT_COMMIT` | task | DONE без хеша и без коммита с `Task:` |
| `COMMIT_WITHOUT_DONE` | task | есть коммит с `Task:`, задача не DONE |
| `SURFACE_CHANGED_WITHOUT_TEST` | commit | дифф события меняет `interfaces.py` или `__all__` в `modules/*/__init__.py` и не трогает ни одного файла `tests/`/`test_*.py` — вариант A `research/baseline.md` §2 (1 из 33 за 60 дней). Событие — слияние на first-parent `main` (`git diff <m>^1 <m>`), в PR — весь диапазон `<ref>..HEAD` одним событием, не каждый коммит: коммит интерфейса без тестов — штатный шаг цепи `developer(INTERFACE) → tester(RED)` |
| `INTERFACE_WITHOUT_TEST` | interface | у имени нет теста: слово `\bИмя\b` не встречается в тексте ни одного тестового файла (с узлами `test`), связанного с модулем ребром `tests` — по расположению или по импорту (1.5a; слово в комментарии тоже засчитывается) |
| `GUARANTEE_WITHOUT_INJECTION` | guarantee | ни один тест с `guards` на гарантию не сломан инъекцией |
| `TEST_NEVER_RED` | test | тест назван в таблице, но ни одна его строка не дала «наблюдалось > 0» |
| `MUTATION_BELOW` | module | балл ниже порога — выключена до калибровки |
| `DOC_STALE` | doc | долг свежести выше порога (порог — 1.4 по замеру) |

«Дифф» для `PRE_POST_MISSING` — `git diff <merge-base(main_ref, head)> <head>`; на самом `main` (head == merge-base)
множество пусто по построению. Считает его адаптер интерфейсов: ядро передаёт адаптеру `BuildContext{tree, base}`,
где `base` — дерево merge-base (при явном `--base` — дерево `<ref>`, ADR-ATL-002 «Последствия») или `None` при обычной сборке (тогда находка не вычисляется). Ключ кэша сборки включает SHA **дерева** `base` (не коммита): адаптер читает `base` по содержимому, поэтому два коммита с одним деревом дают одну сборку; адаптер, которому важен сам коммит `base` (`git log <base>..HEAD`), этим ключом получил бы сборку другого коммита — такой адаптер правит ключ (1.5a, О13). Отсутствие `Pre:/Post:`
у неизменённых методов — не находка, а метрика модуля в `snapshots` (`prepost_covered`, `prepost_total`; **не строится в 1.5a** — писатель метрики решает лид, О12):
сегодня маркеров нет у 746 из 756 публичных методов (ревью стадии 0, `s2_gate` по 65 файлам), находка на каждый — шум.

#### 4. Гарантия и маркер `guards`

- Идентификатор `G-<MOD>-NNN`: `MOD` — `id` модуля из `modules.yaml`, `/` заменён на `.` (`G-router_module-001`,
  `G-process_module.generic-003`); `NNN` — три цифры, номер не переиспользуется. Коды ADR есть у 23 из 87 модулей
  `modules.yaml` — второго дома для кода не заводим; дублей после замены `/` → `.` нет (ревью стадии 0).
- Дом гарантии — docstring имени в `interfaces.py`: строка `Post: <текст> (G-…)` или `Гарантия G-…: <текст>`.
  `Post:` без id учитывается в `PRE_POST_MISSING`, узлом-гарантией не становится.
- Маркер `@pytest.mark.guards("G-…", …)`, аргументы — только строковые литералы (Атлас читает AST, pytest не
  импортирует). Регистрация — в обоих конфигах: `multiprocess_framework/modules/pytest.ini` (`markers =`) и
  `pyproject.toml` (`[tool.pytest.ini_options].markers`). `--strict-markers` не включён ни в одном — **1.5b** (не 1.5a, `amendments.md` п. 10) добавляет
  регистрацию и контракт-тест «`guards` зарегистрирован в обоих».
- 1.5a выносит из `scripts/s2_gate.py` публичную функцию `contract_gaps(text) -> list[(qualname, первая строка с декораторами, последняя строка, отсутствующие маркеры)]` (сегодня только приватные
  `_collect_public_functions`/`_missing_markers`); единица проверки — `Class.method`, узел — имя верхнего уровня.

#### 5. Контракт `--json`

- Верхний уровень — объект с ключами в порядке: `schema_version`, `head`, `main_ref`, `legacy_before`, `nodes`,
  `edges`, `findings`, `plans`. Новые ключи — **только в конец** (и в записях); удаление или переименование —
  `schema_version` +1 и правка контракт-теста видов. Новые значения `kind` и `code` аддитивны, без `schema_version` +1:
  потребитель пропускает неизвестный вид или код (контракт-тест видов 1.6).
- `schema_version` — целое, от `1`. `head` — SHA сборки. `main_ref` — ref, по которому считались `main`-правила
  (ADR-ATL-002 п. 3). `legacy_before` — SHA или `null`.
- Детерминизм: при том же `head` и `main_ref` ключи `nodes`, `edges`, `findings` байт-в-байт те же — списки
  отсортированы: узлы — (`kind`, `id`), рёбра — (`kind`, `src`, `dst`, `via`), находки — (`code`, `node`, `detail`);
  `ensure_ascii=False`, без времени сборки; время снимка метрик — время
  коммита `head`.
- `plans` — в 1.2 `null` (адаптера планов ещё нет); с 1.3a — значение `plans_progress --json` без изменений (приёмка
  1.3a); живой вызов или снимок при сборке — решает 1.3a. Значение **вне** гарантии детерминизма: оно зависит
  от текущего времени, живых worktree и веток (`plans_progress.py:2898-2903`). Узлы `plan`/`task` строятся только из
  статичных полей (slug, id, статус, хеш) — их детерминизм сохраняется.
- SQLite — внутреннее хранилище, не контракт: таблицы меняются без `schema_version`, пока `--json` прежний. Виды `card`/`pack`/`log` (1.6) читают SQLite напрямую (`--json` на тёплой базе — 17,8 МБ и 1,5–2 с против предела вида 1 с); контракт видов — их вывод, а не схема таблиц; SQLite по-прежнему не контракт.

### Последствия

- 1.2: пустые адаптеры дают пустые списки, а не отсутствие ключа; `plans: null`; `BuildContext{tree, base}`; параметр
  `--main-ref` (п. 3 ADR-ATL-002).
- 1.5a: узлы `interface`/`test`, рёбра `exposes`/`tests`, находки `PRE_POST_MISSING`/`INTERFACE_WITHOUT_TEST`; ключ кэша с деревом `base`, версия схемы базы (`PRAGMA user_version`: не совпала — таблицы пересоздаются внутри файла, не удалением файла); публичная `contract_gaps` в `s2_gate.py`. `guards` в двух конфигах + контракт-тест — 1.5b.
- 1.6: виды `card`/`pack` читают SQLite реестра, `log` реестра не строит (git и `modules.yaml` ревизии `main-ref`); `pack` берёт коммиты задачи из git (`git log --no-merges --grep '^Task: <slug>#'`), а не из рёбер `implements`: рёбра идут только по first-parent и целям DONE, а first-parent `main` после слияния ветки lifecycle идёт не по слияниям PR (замер 1.6: 9 рёбер против 142 коммитов с `Task: atlas#…`). Порядок разбора импорта: `<путь>/__init__.py` проверяется раньше `<путь>.py`, берётся первый кандидат, присутствующий в дереве (так ищет Python); `CodeAdapter._BASE` 1 → 2.
- 1.6b: виды `ref`/`index` читают SQLite реестра (узлы `interface`, рёбра `tests`) и файлы той же ревизии из git (корневой `interfaces.py`, тестовые файлы); схема SQLite и адаптеры не меняются, узлов нового вида нет. Назначение модуля — поле `purpose` в `modules.yaml` (загрузчик `load_modules` требует, `parse_modules` ревизий — нет); `index --write` пишет `docs/atlas/INDEX.md`, `index --check` сверяет его с регенерацией (код 1 — отстал); проверка свежести на `main` — задача 1.7.
- 1.7: job CI с `fetch-depth: 0`; облако — `setup.sh` уже делает `--unshallow` (P1.1).

### Отклонённые альтернативы

## ADR-ATL-002: отсечка legacy — гейт по новому, старое видно и не мешает (Task 0.5)

**Дата:** 2026-10-06 (ред. 3 — после двух раундов ревью стадии 0)
**Статус:** Accepted — CTO ACCEPT WITH CONDITIONS 2026-10-06 (D1 — гейт по диффу через merge-base; D2 — `legacy_before`
из коммита базы), условия внесены (ред. 4); reviewer `MODE: plan` — 2 раунда

### Контекст

Засыпки старого нет (решение владельца 2026-10-04): 300 DONE без хеша, старые коммиты без `Task:`, 746 методов без
`Pre:/Post:` останутся. Гейт, который краснеет на старом или на чужом, блокирует каждый PR и будет выключен. Ревью
стадии 0 показало, что гейт «по всему реестру против базы» ломается трижды: в CI нет локального `main` (отсечка молча
`null`), коммит с битым `Refs:`, слитый лидом локально без CI, делает красными все следующие PR, а `PRE_POST_MISSING`
в базе выключает себя на старых именах.

### Решение

#### 1. Гейт — только то, что принёс этот дифф

`atlas check` строит реестр дважды — на `<ref>` и на ревизии checkout (`HEAD`) — и блокирует, только если находка
уровня `blocking` есть на `HEAD` и её нет на `<ref>`.
- `<ref>` = `git merge-base <main-ref> HEAD`; в CI на синтетическом слиянии PR это `HEAD^1`. Не `main` и не
  `base.sha`: ветка, ответвлённая до того, как `main` починил или сломал ссылку, иначе получает чужую находку как
  «новую» (ревью стадии 0, раунд 2, репозитории T1/T2: `--base main` → `new=[BROKEN_LINK …]`, merge-base → `new=[]`).
- Ключ сравнения — (`code`, `node`, `detail`). Перед сравнением id узлов `doc`/`test` на `<ref>` переводятся в имена
  на `HEAD` по `git diff -M --name-status <ref> HEAD`: перенос файла (`git mv`, архив) не делает старую находку новой
  (T3). `detail` — текст как написан в источнике (ссылка в `.md`, путь в `Refs:`), не разрешённый путь. Предел: перевод
  покрывает только строки `R`; перенос с переписыванием (< 50 % схожести) git показывает как `A` + `D`, и старая
  находка в таком файле становится `blocking` (CTO, S3b) — принято, такой PR правит находку заодно.
- Дыра: дефект взаимодействия ветки с ушедшим вперёд `main` (ветка ссылается на то, что `main` удалил) виден только
  на синтетическом слиянии. В CI — сам; у лида — чек-листом слияния 1.7: после локального merge и до push
  `atlas check --base origin/main` (HEAD = результат слияния — то же сравнение, что CI).
- Предупреждение: на самом `main` с `--main-ref main` merge-base = HEAD, дифф пуст — `check` никогда не блокирует.
  Это не проверка `main`, а отсутствие диффа; проверка слитого — строкой выше.
- С 1.7a (2026-10-09) — job `atlas` в `ci.yml`: на `pull_request`, расписании и кнопке — `check` без `--base`
  (merge-base выше); на push в `main` — `check --base <github.event.before>`, вершина `main` до push. С 1.6e в `main`
  попадают локальные слияния лида push'ем, а без `--base` на `main` merge-base = HEAD — пустое сравнение. Без force
  push `before` — предок HEAD, то есть та же база, что у чек-листа слияния выше. Прогоны push в `main` друг друга не
  отменяют (своя группа `concurrency`), иначе коммиты отменённого push остались бы без проверки. Force push или
  `before` из нулей → `atlas: ref not found`, exit 2 — громко.
- В CI — job 1.7; лид перед локальным слиянием — `atlas check` в `pre_report_gate.py` (1.7). Цена — две сборки;
  время — оценка: нижняя граница ~1,1 с на сборку (`plans_progress --json`, вердикт CTO), число даёт REDS 1.2;
  приёмка 1.7 «≤ 5 с на горячем модуле» его включает.

#### 2. Уровни

| `code` | новое в диффе | уже было на `<ref>` |
|---|---|---|
| `PRE_POST_MISSING` (только изменённые методы) | **blocking** | — (по определению только дифф) |
| `BROKEN_LINK`, `REF_TO_MISSING`, `DONE_HASH_NOT_IN_MAIN`, `PLAN_SLUG_COLLISION` | **blocking** | info |
| `SURFACE_CHANGED_WITHOUT_TEST` | **warning** 2 недели после отсечки, затем — решение K1.1 | — (событие диффа) |
| `REF_MOVED`, `DONE_WITHOUT_COMMIT`, `COMMIT_WITHOUT_DONE`, `INTERFACE_WITHOUT_TEST`, `GUARANTEE_WITHOUT_INJECTION`, `TEST_NEVER_RED`, `DOC_STALE` | info | info |
| `MUTATION_BELOW` | выключена до калибровки | — |

`GUARANTEE_WITHOUT_INJECTION` и `TEST_NEVER_RED` на старом не срабатывают сами: в репозитории 0 идентификаторов
`G-…` и 0 итогов с таблицей инъекций из 37 (ревью стадии 0) — исключать нечего.

Строки задач в плане не удаляют и не перенумеровывают, а ставят `[SUPERSEDED]` (формат планов, `plans/README.md`): PR, который удаляет или перенумеровывает строку задачи, делает каждый старый коммит с `Task: <slug>#<старый id>` новой находкой `REF_TO_MISSING` `blocking` (ключ `check` — (`code`, `node`, `detail`)). Для удалённого файла плана находка — `REF_MOVED` (`info`). Повышение `info` → `warning`/`blocking`
— только решением K1.1 или владельца, строкой в этом ADR.

#### 3. `main`-правила и ref

Ref задаётся параметром `--main-ref` (по умолчанию `main`, если есть, иначе `origin/main`): в checkout CI локального
`main` нет (ревью стадии 0, S5), а у лида до push `origin/main` отстаёт от только что слитого. `DONE_HASH_NOT_IN_MAIN`
проверяет предка от ревизии checkout (в CI — синтетическое слияние), не от `main-ref`: строку DONE пишут в той же
ветке, что и код, и до слияния хеш не предок `main` (так было у `a4ef89961`, `986448682`). DONE на коммит другой
невлитой ветки — `blocking` намеренно: после слияния утверждение «сделано в `main`» было бы ложным.

#### 4. База-храповик и `legacy_before` — долг, а не гейт

- `scripts/atlas/baseline.txt` пишет лид **один раз** (`atlas check --baseline-init`) отдельным коммитом сразу после
  слияния 1.7. Строка на находку: `<CODE>\t<kind:id>\t<detail>`; шапка — строки `#` в начале файла. Формат свой
  (у `plans/queue/progress-baseline.txt` другой — `<план>:<КОД>[:<id>]`).
- Назначение базы — метка и счётчик долга: находка из базы показывается как `LEGACY_<CODE>`; число строк базы может
  только убывать — рост числа находок уровня `info` сверх базы карточка показывает как тренд. Строку, которую `check`
  больше не воспроизводит, лид снимает `atlas check --baseline-prune` (только удаляет). На блокировку база не влияет —
  её делает п. 1.
- `legacy_before` — SHA коммита, который **добавил** `baseline.txt` в first-parent историю `<main-ref>`:
  `git log --first-parent --diff-filter=A --format=%H <main-ref> -- scripts/atlas/baseline.txt | tail -1`
  (проверено ревью стадии 0 на одноразовых репозиториях: прямой коммит, `--no-ff`, fast-forward, `git mv` — OK).
  Руками не пишется. Сначала `git rev-parse --is-shallow-repository`: `true` — **ошибка** (exit 2): в неглубоком клоне
  команда отвечает не пусто, а молча чужим SHA (CTO: `--depth 1` → вершина вместо коммита базы). Файл базы есть в
  дереве `head`, а git ответил пусто (нет ref) — тоже exit 2, не `null`. Файла нет в дереве `head` —
  `legacy_before = null` (на гейт п. 1 не влияет; в CI-слиянии файл может быть на `head` и не быть на `<ref>`).
- «До отсечки» для потребителей (1.5b `TEST_NEVER_RED`, 2.3 `result.md`): коммит — `git merge-base --is-ancestor
  <sha> <legacy_before>`; задача — по предку хеша из строки DONE; задача без хеша — legacy по определению.
- Смысл принципа 6 уточняется: отсечка — коммит базы сразу после слияния 1.7, а не сам SHA слияния (его нельзя
  записать в коммит, который он порождает). Принято CTO 2026-10-06; поправка плана — `amendments.md`.

#### 5. Пример (приёмка 0.5)

- Коммит `X` в `main`, слитый до PR, с `Refs: plans/old_typo.md` (файла не было никогда): находка `REF_TO_MISSING`
  есть на `base.sha` → в PR она `info`, CI зелёный. После `--baseline-init` она же показывается как
  `LEGACY_REF_TO_MISSING`.
- Коммит `Y` в PR с той же ошибкой → `REF_TO_MISSING` есть на `HEAD`, нет на `base.sha` → `blocking`, CI красный с
  кодом находки.
- PR удаляет `plans/foo.md`, на который ссылается старый коммит `X`: цель была в дереве `X` → `REF_MOVED` (`info`),
  CI зелёный — архивирование плана гейт не ломает.

### Последствия

- 1.2: `check` (по умолчанию `<ref>` = merge-base, `--base` — явная замена; сборка `HEAD` получает `base` = дерево
  `<ref>`, сборка `<ref>` — `None`), перевод `Finding.node` у `doc:`/`test:` по `git diff -M --name-status -z`,
  `--main-ref`, вывод `legacy_before`; две сборки в одном вызове.
- 1.7: `--baseline-init`, `--baseline-prune` (перенесены из 1.2 при брифе: нужны только 1.7, бюджет ядра 600 строк).
- 1.7: приёмка «PR с нарушением → красный» выполнима до коммита базы (гейт не зависит от базы); порядок 1.7 —
  гейт в CI → PR-инъекция → слияние → коммит базы.
- `--baseline-init` и `--baseline-prune` вызывает только лид (принцип 4).

### Отклонённые альтернативы

- **Гейт по всему реестру против базы** (ред. 1) — коммит с битым `Refs:`, слитый без CI, красит все следующие PR;
  `PRE_POST_MISSING` в базе выключает гейт на старых именах; без `main` в CI отсечка молча `null`.
- **`legacy_before: <SHA>` строкой в конфиге** — SHA слияния неизвестен до слияния; выводимое руками не пишется.
- **Исключать правила по возрасту объекта** (ред. 1) — исключать нечего (0 старых `G-…` и таблиц инъекций), а скан
  дерева `legacy_before` по AST стоил бы строк ядра.
- **Дата вместо SHA** — время коммита не упорядочено относительно слияний; предок по графу — упорядочен.

## ADR-ATL-003: виды `ref`/`card` на griffe + grimp, реализации интерфейсов и правила ADR-175 (Task 1.6c)

**Дата:** 2026-10-08
**Статус:** Accepted — ревью стадии 0 (2 раунда), ревью стадии 5 (2 раунда, APPROVED); основание — решение владельца 2026-10-08 и ADR-175 (`multiprocess_framework/DECISIONS.md`)

### Решение

- **Два вида на статике.** `ref` и `card` читают не рабочее дерево, а выгрузку ревизии (`codemap.checkout`: `.py` корней `modules.yaml` через `git archive`, при наличии — в `/dev/shm`). Классы интерфейсов, базы и абстрактные члены — griffe (`griffe.visit` по файлу; базы разрешаются по импортам AST файла, относительные уровни — своим кодом), «Кто использует» — grimp (граф) плюс AST (строки импортов и вызовов). Вывод детерминирован: полные сортировки, без итерации по `set`, один `PYTHONHASHSEED`-независимый порядок.
- **Реализации интерфейсов** — одна чистая AST-функция (`rules.Scan.implementations`) для адаптера и видов: явные, структурные (все абстрактные члены, ≥ 2, тот же модуль по строке `modules.yaml`), структурные Qt. Предки из других модулей разбираются лениво по всему слою framework (`Scan.of_module`).
- **Правила ADR-175 П1–П4 — адаптер `rules`** (`_BASE = 1`, узел `module:<id>`): `P1_IMPL_NOT_INHERITING`, `P2_DOCSTRING`, `P3_NO_ALL`, `P4_DIRECT_WRITE`. Охват — слой `framework` (находки и доля), `services`/`plugins` — только доля в `card`, остальное «вне охвата». `detail` без номеров строк (ключ находки `(code, node, detail)` переживает сдвиг кода).
- **Дополнение к §2 ADR-ATL-002 (О10):** все четыре кода — `warning`; повышение уровня — решение K1.1 или владельца. `check` печатает новые П-находки, блокирует только blocking (О5).
- **`INTERFACE_WITHOUT_TEST` не меняется** (О3): снимается упоминанием слова; честный счёт «тестов N» (по использованию в тест-функции) — только в `ref`/`card`.
- `pack` для задачи без коммитов берёт модули из текста строки `- Task {id}:` плана (источник `(из текста задачи)`).
- Зависимость: `griffe>=2.3` (2.3.2, ISC) в dev-группу; `reportIncompatibleMethodOverride = "warning"` в `[tool.pyright]` (О1).

### Решения лида О1–О10 (2026-10-08)

О1 — включено как `warning` (предупреждений pyright 327 → 380, +53); О2 — `jedi` не берётся; О3, О4, О5, О7, О8, О9, О10 — умолчания брифа; О6 — снято правилом 9 `CLOUD.md`. **Открыто:** ruff `D` (О4), гейт по П-находкам для изменённых файлов (О5), единая функция атомарной записи фреймворка (О8/П4), правка `INTERFACE_WITHOUT_TEST` (О3), кап 8 реализаций в `ref` под `--symbol`.

### Отклонения от брифа (приняты ревью)

Выгрузка без `Tree.materialize` (tmpfs + системный `tar`: создание ~3800 файлов на диске 1,8 с против 0,3 с); `griffe.visit` вместо `GriffeLoader`; лимиты строк `codemap.py`/`rules.py`/`views.py` превышены (377/437/485 против 260/320/470).
