# atlas — архитектурные решения (ADR)

Реестр доказанности и знаний (`scripts/atlas/`): собирается из git, планов, `modules.yaml`, документов, тестов и итогов
задач; показывается карточкой агенту и страницей владельцу. План — `plans/2026-10-04_atlas/plan.md`; рамка — вердикт
CTO `plans/2026-10-04_atlas/research/CTO_VERDICT.md`. Серия ATL — пакет вне `multiprocess_framework` (как `backend_ctl`).

## ADR-ATL-001: схема реестра и контракт `--json` (Task 1.1)

**Дата:** 2026-10-06 (ред. 3 — после двух раундов ревью стадии 0)
**Статус:** Accepted — CTO ACCEPT WITH CONDITIONS 2026-10-06, условия внесены (ред. 4); reviewer `MODE: plan` — 2 раунда

### Контекст

Цепь `commit → Task → plan → module → doc` и цепь доказанности (диаграмма 3б страницы Атласа, коммит `38462b530^`:
модуль → интерфейс → гарантия ← тест ← инъекция; балл из CI) нужно держать в одном реестре. Реестр — производная: его
не коммитит никто, он строится от дерева сборки (принципы 1, 2, 4 плана). Ядро ≤ ~600 строк до второго адаптера,
хранилище `data/atlas.sqlite` (`sqlite3` stdlib, ≤ 6 таблиц), graphify — необязательный вход. Потребители схемы:
адаптеры 1.3a–1.5b, виды 1.6, гейты 1.7, HTML 3.1. Схема, изменённая после 1.2, переделывает всех — поэтому она
фиксируется до первой строки ядра.

### Решение

#### 1. Узел

`Node{kind, id, path, status, edges, findings}` (+ `time`, см. последний пункт списка):
- `kind` — один из видов таблицы ниже; `id` уникален внутри `kind`; ключ узла — `kind:id`;
- `path` — файл-источник от корня репозитория, или `null`, если узел выведен только из git;
- `status` — строка источника без перевода (у задачи — словарь парсера планов; у документа — `fresh`/`stale`), иначе
  `null`;
- `edges` и `findings` в `--json` лежат отдельными списками со ссылкой `kind:id`; в узел не вкладываются (одна запись
  на факт). В модели Python это представления, собираемые запросом.
- `time` (добавлено при брифе 1.2, в конец записи по §5) — время коммита в секундах Unix у узла `commit`, иначе `null`;
  на нём стоят запросы «тронуто за N дней». Запись узла в `--json`: `kind`, `id`, `path`, `status`, `time`.

| `kind` | `id` | источник | строит |
|---|---|---|---|
| `module` | `id` из `modules.yaml` (`router_module`, `process_module/generic`) | `modules.yaml` | 1.3a |
| `plan` | slug: имя каталога плана без префикса `YYYY-MM-DD_` (правило `validate_commit`; коллизий 0 из 148) | `plans_progress --json` | 1.3a |
| `task` | `<slug>#<id>` (`atlas#1.2`) | строка задачи, тот же парсер | 1.3a |
| `commit` | полный SHA | `git log --first-parent <sha сборки>` + коммиты `<sha сборки> --not <вершина main-ref>` + коммиты, названные хешем в строках DONE (154 из 266 хешей лежат вне first-parent; без их узлов `done_by` ведёт в пустоту) + каждый коммит `git log --no-merges <sha сборки>`, у которого в сообщении есть строка `Refs:` или `Task:` (любое значение; Task 1.3c, р.2: у каждого ребра `refs`/`implements` и каждой находки `REF_*` есть узел-источник; на пине `712ce64a1` +2368 узлов, из них у 54 нет ни ребра, ни находки — значение `Refs:` вне `plans/`). | `result` | `<slug>#<id>` | `tasks/<id>.result.md` | 1.5b |

Урок только с `mechanism:` (без `module:`) — узел без рёбер: в карточку модуля не попадает, виден поиском по механизму
(1.6) — принятый предел. Правило «нет `__all__`»: так у 14 нетестовых `interfaces.py`, в том числе у всех 11 `Services/*` (ревью стадии 0).
Мутационный балл — не узел, а снимок метрики модуля (`data/quality/<module>.json`, 1.8). Ветки, трогающие модуль, —
не узлы: вид 1.6 считает их при показе.

#### 2. Рёбра

`Edge{kind, src, dst, via}`; `via` — откуда ребро выведено (`trailer:Refs`, `path`, `ast-import`, `plan-line`,
`marker`, `table`), чтобы находка назвала источник.

| `kind` | `src → dst` | вывод | звено |
|---|---|---|---|
| `refs` | commit → plan | трейлер `Refs:` **всех предков сборки без слияний** (`git log --no-merges <sha>`; трейлеры коммитов-слияний не читаются): по ребру на каждую пару (коммит, slug) из токенов `(?:^|(?<=[\s,;(]))plans/[^\s,;)]+` значения (левая граница — начало значения или пробел `,` `;` `(`; после `rstrip(".")`); значения вне `plans/` и `plans/` внутри чужого пути (`docs/plans/x.md`) рёбер не дают | цепь |
| `implements` | commit → task | трейлер `Task:` всех предков сборки без слияний (как у `refs`) | цепь |

Причина «все предки без слияний» (2026-10-07): fast-forward `main` на коммит «merge main в ветку» (`a5ae9657a`, lifecycle T1) перевернул first-parent историю — слияния PR #5–#14 оказались на втором родителе, на пине `a5ae9657a` в first-parent 0 строк `Task:` и 9 рёбер `implements` вместо 176. Историю не переписывают. Источник ребра `refs`/`implements` и узел находки `REF_*` всегда имеет узел `commit` (п. 1 таблицы узлов); рёбра `touches` строятся как прежде — только для коммитов прежнего набора (first-parent, PR, цели DONE). Принятый предел: опечатка только в `Refs:` коммита-слияния в гейт не попадает.

виды 1.6 и 1.7, не рёбра.

#### 3. Находки

`Finding{code, severity, node, detail, message, source}`; `severity` ∈ `blocking | warning | info`; `node` — `kind:id`;
`detail` — то, что различает две находки одного кода на одном узле (цель ссылки, имя метода, путь `Refs:`), иначе `""`;
`source` — файл и строка или SHA. Уровни и гейт — ADR-ATL-002. Код — стабильная строка; переименование = новая находка.

| `code` | на чём | смысл |
|---|---|---|
| `PRE_POST_MISSING` | interface | у публичного метода, изменённого в диффе, нет `Pre:`/`Post:` (парсер `scripts/s2_gate.py`; `detail` — `Class.method`) |
| `BROKEN_LINK` | doc, test | относительная ссылка `.md` или `guards` ведёт в несуществующее |
| `REF_TO_MISSING` | commit | цели `Refs:` (токен пути `plans/…`; `detail` — токен как найден, `source` — полный SHA коммита) или `Task:` (план по slug; `detail` — значение `<slug>#<id>` как написано) нет ни в дереве сборки, ни в дереве самого коммита; путь проверяется одним `git cat-file --batch-check` по парам `<sha>:<путь>` (сборка и коммит), план по slug — `git ls-tree -z --name-only <sha> plans/ plans/_archive/` только для коммитов, чьего slug нет среди планов сборки; служебные имена (`queue`, `_archive`, `QUEUE.md`, `README.md`, имена на точку, `*.result-*.md` — константа `_SERVICE_NAMES` и правила в адаптере, зеркало `plans_progress.is_service_name`; `plans_progress` — источник данных через `--json`, не донор кода, синхронность держит тест-сверка) в дереве коммита не считаются планами (`Task: README#1.1` — `REF_TO_MISSING`, не `REF_MOVED`); id задачи из `Task:` ищется только в дереве сборки тем же парсером `plans_progress`, второго парсера нет (план есть, id нет — `REF_TO_MISSING` без проверки дерева коммита) |
| `REF_MOVED` | commit | цель `Refs:`/план из `Task:` была в дереве коммита, в дереве сборки её нет (архив, перенос); поля — как у `REF_TO_MISSING` |
| `DONE_HASH_NOT_IN_MAIN` | task | хеш в строке DONE не предок `HEAD` сборки (в PR — вершины PR, после слияния — `main`) |
| `PLAN_SLUG_COLLISION` | plan | два плана с одним slug: сохраняется живой раньше архивного, затем по `path`; отброшенный план уходит целиком вместе с задачами; `detail` и `source` — путь отброшенного (Task 1.3b; прежний `exit 2` ронял `check` всех PR после слияния такого плана) |
| `DONE_WITHOUT_COMMIT` | task | DONE без хеша и без коммита с `Task:` |
| `COMMIT_WITHOUT_DONE` | task | есть коммит с `Task:`, задача не DONE |
| `SURFACE_CHANGED_WITHOUT_TEST` | commit | дифф события меняет `interfaces.py` или `__all__` в `modules/*/__init__.py` и не трогает ни одного файла `tests/`/`test_*.py` — вариант A `research/baseline.md` §2 (1 из 33 за 60 дней). Событие — слияние на first-parent `main` (`git diff <m>^1 <m>`), в PR — весь диапазон `<ref>..HEAD` одним событием, не каждый коммит: коммит интерфейса без тестов — штатный шаг цепи `developer(INTERFACE) → tester(RED)` |
| `INTERFACE_WITHOUT_TEST` | interface | у имени нет теста: слово `\bИмя\b` не встречается в тексте ни одного тестового файла (с узлами `test`), связанного с модулем ребром `tests` — по расположению или по импорту (1.5a; слово в комментарии тоже засчитывается) |
| `GUARANTEE_WITHOUT_INJECTION` | guarantee | ни один тест с `guards` на гарантию не сломан инъекцией |
| `TEST_NEVER_RED` | test | тест назван в таблице, но ни одна его строка не дала «наблюдалось > 0» |
| `MUTATION_BELOW` | module | балл ниже порога — выключена до калибровки |
| `DOC_STALE` | doc | долг свежести выше порога (порог — 1.4 по замеру) |
| `RESULT_FORM` | result | итог `tasks/<id>.result.md` не по форме 0.7: нет раздела `## T` из семи обязательных, раздел абзацем `**T:**` / `**T.**`, пустой раздел или `## Не проверено` со словом «нет» (`scripts/atlas/result_form.py`); **warning**; узел `result:<slug>#<id>`, `detail` — имена нарушенных разделов через `,`, `source` — путь итога (Task 1.9a) |

«Дифф» для `PRE_POST_MISSING` — `git diff <merge-base(main_ref, head)> <head>`; на самом `main` (head == merge-base)
множество пусто по построению. Считает его адаптер интерфейсов: ядро передаёт адаптеру `BuildContext{tree, base}`,
где `base` — дерево merge-base (при явном `--base` — дерево `<ref>`, ADR-ATL-002 «Последствия») или `None` при обычной сборке (тогда находка не вычисляется). Ключ кэша сборки включает SHA **дерева** `base` (не коммита): адаптер читает `base` по содержимому, поэтому два коммита с одним деревом дают одну сборку; адаптер, которому важен сам коммит `base` (`git log <base>..HEAD`), этим ключом получил бы сборку другого коммита — такой адаптер правит ключ (1.5a, О13). Отсутствие `Pre:/Post:`
у неизменённых методов — не находка, а метрика модуля в `snapshots` (`prepost_covered`, `prepost_total`; **не строится в 1.5a** — писатель метрики решает лид, О12):
сегодня маркеров нет у 746 из 756 публичных методов (ревью стадии 0, `s2_gate` по 65 файлам), находка на каждый — шум.

#### 4. Гарантия и маркер `guards`

- Идентификатор `G-<MOD>-NNN`: `MOD` — `id` модуля из `modules.yaml`, `/` заменён на `.` (`G-router_module-001`,
  `G-process_module.generic-003`); `NNN` — три цифры, номер не переиспользуется. Коды ADR есть у 23 из 87 модулей
  `modules.yaml` — второго дома для кода не заводим; дублей после замены `/` → `.` нет (ревью стадии 0).
- Дом гарантии — docstring имени в `interfaces.py`: строка `Post: <текст> (G-…)` или `Гарантия G-…: <текст>`.
  `Post:` без id учитывается в `PRE_POST_MISSING`, узлом-гарантией не становится.
- Маркер `@pytest.mark.guards("G-…", …)`, аргументы — только строковые литералы (Атлас читает AST, pytest не
  импортирует). Регистрация — в обоих конфигах: `multiprocess_framework/modules/pytest.ini` (`markers =`) и
  `pyproject.toml` (`[tool.pytest.ini_options].markers`). `--strict-markers` не включён ни в одном — **1.5b** (не 1.5a, `amendments.md` п. 10) добавляет
  регистрацию и контракт-тест «`guards` зарегистрирован в обоих».
- 1.5a выносит из `scripts/s2_gate.py` публичную функцию `contract_gaps(text) -> list[(qualname, первая строка с декораторами, последняя строка, отсутствующие маркеры)]` (сегодня только приватные
  `_collect_public_functions`/`_missing_markers`); единица проверки — `Class.method`, узел — имя верхнего уровня.

#### 5. Контракт `--json`

- Верхний уровень — объект с ключами в порядке: `schema_version`, `head`, `main_ref`, `legacy_before`, `nodes`,
  `edges`, `findings`, `plans`. Новые ключи — **только в конец** (и в записях); удаление или переименование —
  `schema_version` +1 и правка контракт-теста видов. Новые значения `kind` и `code` аддитивны, без `schema_version` +1:
  потребитель пропускает неизвестный вид или код (контракт-тест видов 1.6).
- `schema_version` — целое, от `1`. `head` — SHA сборки. `main_ref` — ref, по которому считались `main`-правила
  (ADR-ATL-002 п. 3). `legacy_before` — SHA или `null`.
- Детерминизм: при том же `head` и `main_ref` ключи `nodes`, `edges`, `findings` байт-в-байт те же — списки
  отсортированы: узлы — (`kind`, `id`), рёбра — (`kind`, `src`, `dst`, `via`), находки — (`code`, `node`, `detail`);
  `ensure_ascii=False`, без времени сборки; время снимка метрик — время
  коммита `head`.
- `plans` — в 1.2 `null` (адаптера планов ещё нет); с 1.3a — значение `plans_progress --json` без изменений (приёмка
  1.3a); живой вызов или снимок при сборке — решает 1.3a. Значение **вне** гарантии детерминизма: оно зависит
  от текущего времени, живых worktree и веток (`plans_progress.py:2898-2903`). Узлы `plan`/`task` строятся только из
  статичных полей (slug, id, статус, хеш) — их детерминизм сохраняется.
- SQLite — внутреннее хранилище, не контракт: таблицы меняются без `schema_version`, пока `--json` прежний. Виды `card`/`pack`/`log` (1.6) читают SQLite напрямую (`--json` на тёплой базе — 17,8 МБ и 1,5–2 с против предела вида 1 с); контракт видов — их вывод, а не схема таблиц; SQLite по-прежнему не контракт.

### Последствия

- 1.2: пустые адаптеры дают пустые списки, а не отсутствие ключа; `plans: null`; `BuildContext{tree, base}`; параметр
  `--main-ref` (п. 3 ADR-ATL-002).
- 1.5a: узлы `interface`/`test`, рёбра `exposes`/`tests`, находки `PRE_POST_MISSING`/`INTERFACE_WITHOUT_TEST`; ключ кэша с деревом `base`, версия схемы базы (`PRAGMA user_version`: не совпала — таблицы пересоздаются внутри файла, не удалением файла); публичная `contract_gaps` в `s2_gate.py`. `guards` в двух конфигах + контракт-тест — 1.5b.
- 1.6: виды `card`/`pack` читают SQLite реестра, `log` реестра не строит (git и `modules.yaml` ревизии `main-ref`); `pack` берёт коммиты задачи из git (`git log --no-merges --grep '^Task: <slug>#'`), а не из рёбер `implements`: рёбра идут только по first-parent и целям DONE, а first-parent `main` после слияния ветки lifecycle идёт не по слияниям PR (замер 1.6: 9 рёбер против 142 коммитов с `Task: atlas#…`). Порядок разбора импорта: `<путь>/__init__.py` проверяется раньше `<путь>.py`, берётся первый кандидат, присутствующий в дереве (так ищет Python); `CodeAdapter._BASE` 1 → 2.
- 1.6b: виды `ref`/`index` читают SQLite реестра (узлы `interface`, рёбра `tests`) и файлы той же ревизии из git (корневой `interfaces.py`, тестовые файлы); схема SQLite и адаптеры не меняются, узлов нового вида нет. Назначение модуля — поле `purpose` в `modules.yaml` (загрузчик `load_modules` требует, `parse_modules` ревизий — нет); `index --write` пишет `docs/atlas/INDEX.md`, `index --check` сверяет его с регенерацией (код 1 — отстал); проверка свежести на `main` — задача 1.7.
- 1.7: job CI с `fetch-depth: 0`; облако — `setup.sh` уже делает `--unshallow` (P1.1).

### Отклонённые альтернативы

- **Рёбра, вложенные в узел** — одно ребро записано дважды, дрейф между копиями.
- **Код ADR (`RTR`) в `G-…`** — есть у 23 из 87 модулей; второй дом кода в `modules.yaml` нарушает принцип 2.
- **Узел `file`** — 6,8 тыс. файлов; путь → модуль решается `modules.yaml` при построении `touches`.
- **Ветка как узел** — состояние живое и чужое для `main`; вид 1.6 считает его на лету.
- **`PRE_POST_MISSING` на каждом методе без маркеров** — 746 находок или 746 строк базы; жёсткий гейт работал бы

## ADR-ATL-002: отсечка legacy — гейт по новому, старое видно и не мешает (Task 0.5)

**Дата:** 2026-10-06 (ред. 3 — после двух раундов ревью стадии 0)
**Статус:** Accepted — CTO ACCEPT WITH CONDITIONS 2026-10-06 (D1 — гейт по диффу через merge-base; D2 — `legacy_before`
из коммита базы), условия внесены (ред. 4); reviewer `MODE: plan` — 2 раунда

### Контекст

Засыпки старого нет (решение владельца 2026-10-04): 300 DONE без хеша, старые коммиты без `Task:`, 746 методов без
`Pre:/Post:` останутся. Гейт, который краснеет на старом или на чужом, блокирует каждый PR и будет выключен. Ревью
стадии 0 показало, что гейт «по всему реестру против базы» ломается трижды: в CI нет локального `main` (отсечка молча
`null`), коммит с битым `Refs:`, слитый лидом локально без CI, делает красными все следующие PR, а `PRE_POST_MISSING`
в базе выключает себя на старых именах.

### Решение

#### 1. Гейт — только то, что принёс этот дифф

`atlas check` строит реестр дважды — на `<ref>` и на ревизии checkout (`HEAD`) — и блокирует, только если находка
уровня `blocking` есть на `HEAD` и её нет на `<ref>`.
- `<ref>` = `git merge-base <main-ref> HEAD`; в CI на синтетическом слиянии PR это `HEAD^1`. Не `main` и не
  `base.sha`: ветка, ответвлённая до того, как `main` починил или сломал ссылку, иначе получает чужую находку как
  «новую» (ревью стадии 0, раунд 2, репозитории T1/T2: `--base main` → `new=[BROKEN_LINK …]`, merge-base → `new=[]`).
- Ключ сравнения — (`code`, `node`, `detail`). Перед сравнением id узлов `doc`/`test` на `<ref>` переводятся в имена
  на `HEAD` по `git diff -M --name-status <ref> HEAD`: перенос файла (`git mv`, архив) не делает старую находку новой
  (T3). `detail` — текст как написан в источнике (ссылка в `.md`, путь в `Refs:`), не разрешённый путь. Предел: перевод
  покрывает только строки `R`; перенос с переписыванием (< 50 % схожести) git показывает как `A` + `D`, и старая
  находка в таком файле становится `blocking` (CTO, S3b) — принято, такой PR правит находку заодно.
- Дыра: дефект взаимодействия ветки с ушедшим вперёд `main` (ветка ссылается на то, что `main` удалил) виден только
  на синтетическом слиянии. В CI — сам; у лида — чек-листом слияния 1.7: после локального merge и до push
  `atlas check --base origin/main` (HEAD = результат слияния — то же сравнение, что CI).
- Предупреждение: на самом `main` с `--main-ref main` merge-base = HEAD, дифф пуст — `check` никогда не блокирует.
  Это не проверка `main`, а отсутствие диффа; проверка слитого — строкой выше.
- С 1.7a (2026-10-09) — job `atlas` в `ci.yml`: на `pull_request`, расписании и кнопке — `check` без `--base`
  (merge-base выше); на push в `main` — `check --base <github.event.before>`, вершина `main` до push. С 1.6e в `main`
  попадают локальные слияния лида push'ем, а без `--base` на `main` merge-base = HEAD — пустое сравнение. Без force
  push `before` — предок HEAD, то есть та же база, что у чек-листа слияния выше. Прогоны push в `main` друг друга не
  отменяют (своя группа `concurrency`), иначе коммиты отменённого push остались бы без проверки. Force push или
  `before` из нулей → `atlas: ref not found`, exit 2 — громко.
- В CI — job 1.7; лид перед локальным слиянием — `atlas check` в `pre_report_gate.py` (1.7). Цена — две сборки;
  время — оценка: нижняя граница ~1,1 с на сборку (`plans_progress --json`, вердикт CTO), число даёт REDS 1.2;
  приёмка 1.7 «≤ 5 с на горячем модуле» его включает.

#### 2. Уровни

| `code` | новое в диффе | уже было на `<ref>` |
|---|---|---|
| `PRE_POST_MISSING` (только изменённые методы) | **blocking** | — (по определению только дифф) |
| `BROKEN_LINK`, `REF_TO_MISSING`, `DONE_HASH_NOT_IN_MAIN`, `PLAN_SLUG_COLLISION` | **blocking** | info |
| `SURFACE_CHANGED_WITHOUT_TEST` | **warning** 2 недели после отсечки, затем — решение K1.1 | — (событие диффа) |
| `REF_MOVED`, `DONE_WITHOUT_COMMIT`, `COMMIT_WITHOUT_DONE`, `INTERFACE_WITHOUT_TEST`, `GUARANTEE_WITHOUT_INJECTION`, `TEST_NEVER_RED`, `DOC_STALE` | info | info |
| `MUTATION_BELOW` | выключена до калибровки | — |

`GUARANTEE_WITHOUT_INJECTION` и `TEST_NEVER_RED` на старом не срабатывают сами: в репозитории 0 идентификаторов
`G-…` и 0 итогов с таблицей инъекций из 37 (ревью стадии 0) — исключать нечего.

Строки задач в плане не удаляют и не перенумеровывают, а ставят `[SUPERSEDED]` (формат планов, `plans/README.md`): PR, который удаляет или перенумеровывает строку задачи, делает каждый старый коммит с `Task: <slug>#<старый id>` новой находкой `REF_TO_MISSING` `blocking` (ключ `check` — (`code`, `node`, `detail`)). Для удалённого файла плана находка — `REF_MOVED` (`info`). Повышение `info` → `warning`/`blocking`
— только решением K1.1 или владельца, строкой в этом ADR.

#### 3. `main`-правила и ref

Ref задаётся параметром `--main-ref` (по умолчанию `main`, если есть, иначе `origin/main`): в checkout CI локального
`main` нет (ревью стадии 0, S5), а у лида до push `origin/main` отстаёт от только что слитого. `DONE_HASH_NOT_IN_MAIN`
проверяет предка от ревизии checkout (в CI — синтетическое слияние), не от `main-ref`: строку DONE пишут в той же
ветке, что и код, и до слияния хеш не предок `main` (так было у `a4ef89961`, `986448682`). DONE на коммит другой
невлитой ветки — `blocking` намеренно: после слияния утверждение «сделано в `main`» было бы ложным.

#### 4. База-храповик и `legacy_before` — долг, а не гейт

- `scripts/atlas/baseline.txt` пишет лид **один раз** (`atlas check --baseline-init`) отдельным коммитом сразу после
  слияния 1.7. Строка на находку: `<CODE>\t<kind:id>\t<detail>`; шапка — строки `#` в начале файла. Формат свой
  (у `plans/queue/progress-baseline.txt` другой — `<план>:<КОД>[:<id>]`).
- Назначение базы — метка и счётчик долга: находка из базы показывается как `LEGACY_<CODE>`; число строк базы может
  только убывать — рост числа находок уровня `info` сверх базы карточка показывает как тренд. Строку, которую `check`
  больше не воспроизводит, лид снимает `atlas check --baseline-prune` (только удаляет). На блокировку база не влияет —
  её делает п. 1.
- `legacy_before` — SHA коммита, который **добавил** `baseline.txt` в first-parent историю `<main-ref>`:
  `git log --first-parent --diff-filter=A --format=%H <main-ref> -- scripts/atlas/baseline.txt | tail -1`
  (проверено ревью стадии 0 на одноразовых репозиториях: прямой коммит, `--no-ff`, fast-forward, `git mv` — OK).
  Руками не пишется. Сначала `git rev-parse --is-shallow-repository`: `true` — **ошибка** (exit 2): в неглубоком клоне
  команда отвечает не пусто, а молча чужим SHA (CTO: `--depth 1` → вершина вместо коммита базы). Файл базы есть в
  дереве `head`, а git ответил пусто (нет ref) — тоже exit 2, не `null`. Файла нет в дереве `head` —
  `legacy_before = null` (на гейт п. 1 не влияет; в CI-слиянии файл может быть на `head` и не быть на `<ref>`).
- «До отсечки» для потребителей (1.5b `TEST_NEVER_RED`, 2.3 `result.md`): коммит — `git merge-base --is-ancestor
  <sha> <legacy_before>`; задача — по предку хеша из строки DONE; задача без хеша — legacy по определению.
- Смысл принципа 6 уточняется: отсечка — коммит базы сразу после слияния 1.7, а не сам SHA слияния (его нельзя
  записать в коммит, который он порождает). Принято CTO 2026-10-06; поправка плана — `amendments.md`.

#### 5. Пример (приёмка 0.5)

- Коммит `X` в `main`, слитый до PR, с `Refs: plans/old_typo.md` (файла не было никогда): находка `REF_TO_MISSING`
  есть на `base.sha` → в PR она `info`, CI зелёный. После `--baseline-init` она же показывается как
  `LEGACY_REF_TO_MISSING`.
- Коммит `Y` в PR с той же ошибкой → `REF_TO_MISSING` есть на `HEAD`, нет на `base.sha` → `blocking`, CI красный с
  кодом находки.
- PR удаляет `plans/foo.md`, на который ссылается старый коммит `X`: цель была в дереве `X` → `REF_MOVED` (`info`),
  CI зелёный — архивирование плана гейт не ломает.

### Последствия

- 1.2: `check` (по умолчанию `<ref>` = merge-base, `--base` — явная замена; сборка `HEAD` получает `base` = дерево
  `<ref>`, сборка `<ref>` — `None`), перевод `Finding.node` у `doc:`/`test:` по `git diff -M --name-status -z`,
  `--main-ref`, вывод `legacy_before`; две сборки в одном вызове.
- 1.7: `--baseline-init`, `--baseline-prune` (перенесены из 1.2 при брифе: нужны только 1.7, бюджет ядра 600 строк).
- 1.7: приёмка «PR с нарушением → красный» выполнима до коммита базы (гейт не зависит от базы); порядок 1.7 —
  гейт в CI → PR-инъекция → слияние → коммит базы.
- `--baseline-init` и `--baseline-prune` вызывает только лид (принцип 4).

### Отклонённые альтернативы

- **Гейт по всему реестру против базы** (ред. 1) — коммит с битым `Refs:`, слитый без CI, красит все следующие PR;
  `PRE_POST_MISSING` в базе выключает гейт на старых именах; без `main` в CI отсечка молча `null`.
- **`legacy_before: <SHA>` строкой в конфиге** — SHA слияния неизвестен до слияния; выводимое руками не пишется.
- **Исключать правила по возрасту объекта** (ред. 1) — исключать нечего (0 старых `G-…` и таблиц инъекций), а скан
  дерева `legacy_before` по AST стоил бы строк ядра.
- **Дата вместо SHA** — время коммита не упорядочено относительно слияний; предок по графу — упорядочен.

## ADR-ATL-003: виды `ref`/`card` на griffe + grimp, реализации интерфейсов и правила ADR-175 (Task 1.6c)

**Дата:** 2026-10-08
**Статус:** Accepted — ревью стадии 0 (2 раунда), ревью стадии 5 (2 раунда, APPROVED); основание — решение владельца 2026-10-08 и ADR-175 (`multiprocess_framework/DECISIONS.md`)

### Решение

- **Два вида на статике.** `ref` и `card` читают не рабочее дерево, а выгрузку ревизии (`codemap.checkout`: `.py` корней `modules.yaml` через `git archive`, при наличии — в `/dev/shm`). Классы интерфейсов, базы и абстрактные члены — griffe (`griffe.visit` по файлу; базы разрешаются по импортам AST файла, относительные уровни — своим кодом), «Кто использует» — grimp (граф) плюс AST (строки импортов и вызовов). Вывод детерминирован: полные сортировки, без итерации по `set`, один `PYTHONHASHSEED`-независимый порядок.
- **Реализации интерфейсов** — одна чистая AST-функция (`rules.Scan.implementations`) для адаптера и видов: явные, структурные (все абстрактные члены, ≥ 2, тот же модуль по строке `modules.yaml`), структурные Qt. Предки из других модулей разбираются лениво по всему слою framework (`Scan.of_module`).
- **Правила ADR-175 П1–П4 — адаптер `rules`** (`_BASE = 1`, узел `module:<id>`): `P1_IMPL_NOT_INHERITING`, `P2_DOCSTRING`, `P3_NO_ALL`, `P4_DIRECT_WRITE`. Охват — слой `framework` (находки и доля), `services`/`plugins` — только доля в `card`, остальное «вне охвата». `detail` без номеров строк (ключ находки `(code, node, detail)` переживает сдвиг кода).
- **Дополнение к §2 ADR-ATL-002 (О10):** все четыре кода — `warning`; повышение уровня — решение K1.1 или владельца. `check` печатает новые П-находки, блокирует только blocking (О5).
- **`INTERFACE_WITHOUT_TEST` не меняется** (О3): снимается упоминанием слова; честный счёт «тестов N» (по использованию в тест-функции) — только в `ref`/`card`.
- `pack` для задачи без коммитов берёт модули из текста строки `- Task {id}:` плана (источник `(из текста задачи)`).
- Зависимость: `griffe>=2.3` (2.3.2, ISC) в dev-группу; `reportIncompatibleMethodOverride = "warning"` в `[tool.pyright]` (О1).

### Решения лида О1–О10 (2026-10-08)

О1 — включено как `warning` (предупреждений pyright 327 → 380, +53); О2 — `jedi` не берётся; О3, О4, О5, О7, О8, О9, О10 — умолчания брифа; О6 — снято правилом 9 `CLOUD.md`. **Открыто:** ruff `D` (О4), гейт по П-находкам для изменённых файлов (О5), единая функция атомарной записи фреймворка (О8/П4), правка `INTERFACE_WITHOUT_TEST` (О3), кап 8 реализаций в `ref` под `--symbol`.

### Отклонения от брифа (приняты ревью)

Выгрузка без `Tree.materialize` (tmpfs + системный `tar`: создание ~3800 файлов на диске 1,8 с против 0,3 с); `griffe.visit` вместо `GriffeLoader`; лимиты строк `codemap.py`/`rules.py`/`views.py` превышены (377/437/485 против 260/320/470).

### Дополнение Task 1.6g (2026-10-11): выгрузка ревизии переживает процесс

- **Выгрузка на диске, не в tmpfs.** `checkout` кладёт `.py` ревизии в `<корень>/data/atlas/checkout/<sha[:12]>-<хэш корней>` и не удаляет её: следующий процесс на той же ревизии берёт каталог без `git archive`. Распаковка — во временный `.tmp-*` и одним `rename` под итоговое имя (недораспакованное дерево под итоговым именем не видно); проигравший гонку берёт выгрузку победителя. Хранятся 3 новейшие по mtime (попадание обновляет mtime); лишняя сперва переименовывается в `.del-*`, потом удаляется — каталог с открытым файлом (Windows) остаётся целым. `/dev/shm` снят: выигрыш tmpfs (1,8 с против 0,3 с) платился на каждый вызов, теперь — один раз на ревизию.
- **`tar -x -f -` в `cwd`.** Прежняя форма `tar -x -C <каталог>` на Windows падала всегда (bsdtar System32 открывал `\\.\tape0`, GNU tar из Git не принимал `C:\…` в `-C`), и откат на `tarfile` молчал: распаковка 4,0 с вместо ~1 с. Откат теперь печатает строку `atlas: tar … fallback to tarfile` в stderr. `tar` берётся по полному пути из `shutil.which`.
- **Кэш grimp** — `<выгрузка>/.grimp_cache` (файлы выгрузки неизменны).
- **`Code` ревизии в процессе** — `code_of` (до 3 записей, ключ — путь выгрузки и строки `modules.yaml`); `Code` со сбоем разбора не переиспользуется; `forget()` сбрасывает память. Непустые корни при пустой выгрузке — `AtlasError`, не вид.
- **Последствие для тестов 1.6e:** и «холодный», и «тёплый» контроль кэша видов верны только без выгрузки на диске и `Code` в памяти — перед каждым `_cold(repo)` (`forget()` + удаление `data/atlas/checkout`); иначе тёплые нули дают диск и память, а не кэш видов (ревью кода р.1: с `get_view` → `None` стражи 1.6e были зелёными).
- **Пустая выгрузка не залипает:** непустые корни и ни одного `.py` после распаковки → `AtlasError` до `rename`; пустой каталог под итоговым именем — промах (уходит в `.del-*`).
- **Предел пути Windows.** Без `LongPathsEnabled` путь `<каталог кэша>\<ключ>\<самый длинный .py>` не должен превышать 259 знаков: за пределом GNU tar распаковывает, но чтение даёт `FileNotFoundError` (зонд ревью 2026-10-11). Каталог кэша — `<корень>\data\atlas\checkout`; если путь под ним не помещается (worktree агента `.claude\worktrees\agent-…`: 256 знаков с длинным именем временного каталога — 270), выгрузка уходит в короткий постоянный корень `%TEMP%\atlas-checkout\<sha256 корня[:8]>` с теми же правилами; не помещается и там — `AtlasError("atlas: checkout path too long …")` до распаковки. Временный каталог — `.tmp-<8>`, короче ключа: меряется итоговый путь. До 1.6g выгрузка жила в `%TEMP%\atlas-*` (169 знаков) — отказа в глубоком worktree быть не должно.

## ADR-ATL-004: форматы без потерь — бриф, инъекции, итог, отчёт ревью (Task 1.9d)

**Дата:** 2026-10-09
**Статус:** Proposed — ревью стадии 0 р.1 (17 замечаний, внесены); основание — ревизия CTO 2026-10-08 §1 (`plans/2026-10-04_atlas/research/CTO_PLAN_REVISION_2026-10-08.md`), `amendments.md` п. 16–18

### Контекст

Писатель и читатель одного формата расходились, и гейта на это не было:

- **итог** — K0 писал `**Не проверено:**`, `_section` ждал `**Не проверено.**`: `pack k0-framework-quality#1.2` давал 0 хвостов (закрыто 1.9a);
- **бриф** — `plans_ledger.py brief` отвергает брифы Атласа целиком: у 1.9a меток нет совсем (поля — заголовки `## DESIGN`), у 1.7a и 1.6c метки внутри fence (блоки ролей A/B), `build_brief` fence пропускает;
- **инъекции** — четыре формы: таблица в итоге (читает `views._result_parts`), проза `tasks/<id>.injections.md` (1.6c, 1.6e, 1.7a, K0 1.1, 1.2), JSON 1.6c (id `A01…`, без `observed` и `test`, forecast — имена функций), JSON 1.9a (первый объект `legend`, forecast — алиасы `T2`, у одного объекта ключ `note`). Итог 1.9a — 2002 Б в blob и 2045 Б в рабочей копии Windows (CRLF; `RESULT_TOO_BIG` меряет файл на диске) при `RESULT_MAX_BYTES` = 2048, поэтому вместо таблицы сводка; `pack` уже не видит его 4 расхождения прогноза (inj-1, 2, 6, 15);
- **отчёт ревью** — K0 `1.2.review-r1.md`: `Вердикт: **CHANGES REQUESTED** (раунд 1 из 2)`, нумерованные списки по степени, классов нет; брифы 1.7a/1.9a — строка «Классы:» с разным словарём (`scope` у 1.7a, `nit` классом у 1.9a); `reviewer.md` знает только категории `spec…tests`, степень выводит из категории, `nit` нет.

Принцип: у формата один шаблон-писатель и перечисленные читатели-код; на каждого читателя — тест-контракт «пример шаблона → читатель → те же поля». Писатель строг; читатель терпит только перечисленные здесь старые формы.

### Решение

#### 1. Карта форматов

| формат | файл | шаблон (`.claude/plugins/dev/templates/`) | писатели | читатели | тест-контракт | с какой задачи |
|---|---|---|---|---|---|---|
| бриф | `tasks/<id>.md`, `tasks/<id>.<role>.md` | `task-brief.md` | лид; блок FACTS — `atlas brief` (1.9b) | `plans_ledger.build_brief`; хук `lint-brief.sh`; гейт плана `TASK_INCOMPLETE` и `TASK_TOO_BIG` (8 КБ на файл `tasks/*.md`, не блокирует); `views._lead_parts`; `atlas brief --check` (1.9b); `atlas lint-brief` (1.9c) | `scripts/atlas/tests/test_formats_1_9d.py` (бриф, файл роли, грамматика строк, `_lead_parts`, хук) | 1.9d; 1.9b и 1.9c добавляют свой читатель в тот же тест |
| инъекции | `tasks/<id>.injections.json` | `injections.md` | лид (до прогона); `atlas inject run` — `observed` (1.9e) | `atlas lint-brief` (1.9c: `old` в `file`); `atlas inject` (1.9e); `pack` — «предсказано ≠ наблюдалось» (читатель JSON — 1.9e, см. §4); узлы и рёбра ADR-ATL-001 (1.5b, DEFERRED) | `test_formats_1_9d.py::test_injections_example_schema` — пример против литералов §3; 1.9e: `inject summary` на тот же пример | грамматика 1.9d; читатель 1.9e |

Пока у формата нет читателя-кода (инъекции, отчёт ревью), тест-контракт сверяет пример шаблона с литералами этого ADR; задача-читатель заменяет литералы импортом своего парсера, тест остаётся. Пример шаблона извлекается так: `task-brief.md` — 1-й и 2-й блоки в четырёх обратных кавычках с меткой `markdown` (главный бриф, файл роли); `review-report.md` — 1-й такой блок; `injections.md` — 1-й блок в трёх обратных кавычках с меткой `json`. Разбор строк — по `splitlines()` (рабочее дерево Windows — CRLF).

#### 2. Бриф

**2.1. Файлы и роли.** `tasks/<id>.md` — главный бриф, H1 `# Task <id> — <суть>`; роль — писатель (`developer`, `teamlead`, `junior`, `debugger`) или `lead` (соло). Вторая роль — файл `tasks/<id>.<role>.md`, `<role>` ∈ {`tester`, `developer`, `teamlead`, `junior`, `debugger`}, H1 `# <id> — бриф <role>` без слова `Task`: `extract_task_ids(…, in_task_file=True)` его не видит, задача в счётчиках плана не двоится. Спавн — `python scripts/plans_ledger.py brief <id>.<role> --plan <план>`. Суффиксы `.result` и `.injections` зарезервированы. Один файл — одна роль — один спавн; бриф роли внутри fence не пишется.

**2.2. Шапка лида** — всё до первой метки; `build_brief` берёт текст с первой метки, в спавн шапка не уходит. Порядок: H1; абзац «Основание: …»; `## Открыто для лида` — таблица `| № | вопрос | замер | умолчание брифа |` со строками `| О<n> | …` (читатель `views._lead_parts`, `pack` печатает `О<n>: <вопрос>`); `## Ревью стадии 0` — по строке на раунд `- р.<N> → reports/<id>.review-r<N>.md: <вердикт>, Классы: …`; `## Инъекции (план)` — свойство и прогноз, пока `injections.json` не написан.

**2.3. Метка** — строка вне fence, которую ловит `_BRIEF_LABEL_RE` (`scripts/plans_ledger.py:429`; байт в байт `LABEL_RE` хука `lint-brief.sh:75` и зеркала `.claude/plugins/core/scripts/plans_ledger.py`):

```
^[ \t]*([A-Z][A-Z \-/]{2,})(?:[ \t]*\(.*)?:
```

| метка | главный бриф | файл роли | кто требует |
|---|---|---|---|
| `TASK` | да | да | `build_brief` |
| `ROLE` | да | да | `build_brief`; хук линтует по `subagent_type` спавна, не по этой строке |
| `CHAIN` | да | да | гейт плана `TASK_INCOMPLETE` — главный бриф: `CHAIN` или `HANDOFF IN`; файлы роли гейт плана не читает |
| `FACTS` | да | нет | `atlas lint-brief` (1.9c) |
| `DESIGN` | да | да | `build_brief`; хук — ≥ 3 непустых строк |
| `FILES` | да | да | `build_brief`; хук — ≤ `brief_max_files` (6) пунктов; гейт плана (Files) — главный бриф |
| `REDS` | да | да | `build_brief`; хук — ≤ 10 пунктов или первая строка `n/a` |
| `ACCEPTANCE` | да | нет | гейт плана (Acceptance) — главный бриф; `atlas lint-brief` (1.9c) |
| `TESTS` | да | да | `build_brief` |
| `OUT OF SCOPE` | да | да | `build_brief` |
| `TRAPS`, `HANDOFF IN` | рекомендуется | рекомендуется | — |

Размер: шапка лида и FACTS растят файл, `TASK_TOO_BIG` (8 КБ, `plans_ledger`) — предупреждение, превышение брифом принято (1.9a — 20 КБ, 1.9d — 11 КБ); долгое — в `reports/<id>.*.md`. Допустимые сверх таблицы: `FORBIDDEN PATHS`, `GUARDS`, `PROBE`, `COMMIT` и `REPORT` (перекрывают постоянные блоки `executor-brief.md`), `BRIEF-OVERRIDE`. Иная метка — предупреждение `lint-brief`, не ошибка.

**2.4. Тело метки** — строки до следующей метки. Строка тела — пункт списка (`- `, `N. `, с отступом или без), продолжение с отступом ≥ 2 пробела или строка fenced-блока. Запрещены строки, которые откроют чужую метку:
- ловит `_BRIEF_LABEL_RE` (только латиница, с отступом тоже): `  API: x` → метка `API`, `  NOTE (see: y) z` → `NOTE`;
- ловит гейт плана `_ANY_FIELD_LABEL_RE` (`plans_ledger.py:413`) — он обрывает блок Files и на пункте списка:

```
^\s*(?:[-*+]\s+)?(?:\*\*[^*\n]+:\*\*|\*\*[^*\n]+\*\*\s*:|[A-ZА-ЯЁ][A-ZА-ЯЁ \-/]{2,}(?:[ \t]*\(.*)?:)
```

  примеры: `ВАЖНО: z`, `  - API: x`, `- **Итог:** x`. Правило писателю: после маркера пункта — не слово ЗАГЛАВНЫМИ и не `**…:**`.

**2.5. Строки FACTS и ACCEPTANCE.** Блок FACTS начинается строкой `<!-- atlas:facts <sha7> -->` и кончается строкой `<!-- /atlas:facts -->`; `<sha7>` — 7 hex коммита, на котором получены литералы (правило свежести — 1.9b). Строка, литерал которой на этом коммите не получить (файл ещё не закоммичен), идёт в ACCEPTANCE. Пункт FACTS и ACCEPTANCE — только `- ` (не `N. `); каждая строка FACTS между маркерами и каждый пункт ACCEPTANCE (строка `^[ \t]*(?:- |\d+\. )`):

```
^[ \t]*- (?P<what>.+?) — `(?P<cmd>[^`]+)` → (?:`(?P<lit>[^`]+)`|exit (?P<code>\d+))$
```

Тире — U+2014, стрелка — U+2192, обе с пробелами. В команде и литерале нет обратных кавычек (нужна — команда уходит в скрипт `reports/<id>.probe.md`). Сверка (1.9c): `` `lit` `` — точная подстрока объединённого stdout+stderr команды из корня репозитория; `exit N` — код возврата. Два куска вывода — две строки, пересказ (`:429, :429, :75`) — не литерал. Литерал не зависит от платформы: байты — `git cat-file -s <sha>:<путь>`, не `wc -c` (рабочая копия Windows — CRLF: у `1.9a.result.md` 2045 против 2002 в blob). Команды вне allow-list 1.9c не повторяются, а печатаются «сверка лидом».

**2.5а. Генератор и свежесть FACTS (1.9b).** Блок пишет `python -m scripts.atlas brief <slug>#<id>` (`scripts/atlas/brief.py`): строка метки `FACTS (generated by python -m scripts.atlas brief <slug>#<id>; edit DESIGN, not this block):`, маркеры §2.5. Каждая строка — вывод `pack`/`card`/`ref`, вызванного в процессе теми же аргументами, что в её команде (`--ref <sha7>`, `--main-ref` — только если дан явно), поэтому литерал — подстрока вывода по построению; строка с обратной кавычкой даёт литерал — самый длинный элемент `split` по ней (≥ 8 знаков). «Что» — из закрытого словаря (`задача`, `объект задачи <S>`, `потребитель через <S>`, `хвост <id>, <раздел>` …), словарь — в брифе `tasks/1.9b.md` DESIGN 4 и в тесте `test_brief_1_9b.py`. Живые строки (ветки модуля, `pytest --collect-only`) — только когда `--ref` = HEAD. **Свежесть** (`brief --check`, без сборки): входы — пути модулей из команд блока (позиционный модуль `ref`/`card`, `--module` у `pack`) и файлы, названные в литералах (у любой команды, не только `scripts.atlas`; хвост `:` у `путь:N:` снимается — так читает `check` с 1.9c, раньше — только у atlas-команд); всё под `plans/` — не вход; рабочее дерево против коммита маркера (`git diff --name-only <sha7>`): изменилось — код 1. `--check` ловит дрейф кода, не неверный литерал: повтор команд — `lint-brief` (1.9c). `--write` сохраняет концы строк файла: есть хоть один CRLF — весь файл пишется с CRLF (смешанные концы становятся CRLF). Объект задачи без `--symbol` — символ в обратных кавычках строки плана, иначе публичные символы файлов из текста задачи (`views._text_sources`, и при `--module`, и у задачи с коммитами); кандидаты «из прошлой задачи» — только из `pack --module`, без строк самой задачи. Пин приёмки 1.9b — `24a229e66` (бриф K0 1.2 ред. 1), не `2d7e9d8f6` ревизии CTO: на нём задача 1.2 уже сделана, и `pack` берёт FILES из её же коммитов.

**2.5б. `atlas lint-brief` и повтор команд (1.9c).** `python -m scripts.atlas lint-brief <tasks/<id>[.<роль>].md> [--no-replay] [--no-fresh]` (`lint_brief.py`, `replay.py`): код 0 — ошибок нет (предупреждения не меняют код), 1 — есть ошибка, 2 — нет файла, имя не по форме, файл вне корня. Вывод: `<путь>[:<N>]: error|warning <КОД> <текст>`, строки `  не сверено (вне allow-list): <команда>` и итог `lint-brief: ошибок E, предупреждений W, сверено V, вне allow-list O` (строка с `FACT_FORM`/`LITERAL_TIMING` не повторяется и в V, O не входит; `--no-replay` — V = 0 и O = 0: allow-list — часть повтора, строки «не сверено» не печатаются). Коды: форма — `H1`, `LABEL_MISSING`, `LABEL_UNKNOWN` и `LABEL_DUPLICATE` (предупреждения), `BODY_LABEL` (§2.4), `DESIGN_SHORT`, `FILES_TOO_MANY` (> 6), `REDS_TOO_MANY` (> 10, кроме `n/a`); факты — `FACTS_MARKER`, `FACT_FORM`, `LITERAL_TIMING` (время в литерале не воспроизводится: целые секунды тоже), `FACT_MISMATCH` (текст — первая строка `литерал не найден в выводе: <литерал>`, вторая — `  вывод: <первая строка вывода>`; `код возврата N, ожидался M`), `FACT_TIMEOUT`, `FACTS_STALE` (в том числе неизвестный sha маркера — не молчание); REDS — `REDS_NO_FILE`, `REDS_NOT_COLLECTED`, `REDS_COLLECT_FAILED` («файлы FILES» — FILES брифа и файлов роли рядом: тесты пишет tester); `<id>.injections.json` — `INJ_FORM`, `INJ_FILE_MISSING`, `INJ_OLD_MISSING`, `INJ_OLD_AMBIGUOUS` (`old` — в рабочем дереве корня, CRLF→LF с обеих сторон), `INJ_FORECAST_UNKNOWN`; `PROBE_MISSING` и `RACE_WITHOUT_PROBE` (предупреждение; слова гонки — основы `гонк`, `race`, `lost-wakeup`, `реентер`, `reentran`, `одновременн`, граница слева, без фрагментов в обратных кавычках). Allow-list повтора: `python -m scripts.atlas {pack,card,ref,log,brief,index}` (без `--write`), `python -m pytest … --collect-only …` (аргументы только `-q`, `-p no:<имя>`, `-k`, `-m`, пути, nodeid), `git {grep,log,diff,cat-file,rev-parse,ls-files,ls-tree,show}` (без `--output*`, `-O*`, `--exec*`, `--batch*`, `--ext-diff`, `--textconv`, `--follow-symlinks` и глобальных опций), `wc -l`; запуск без shell, `stdin` закрыт, таймаут 300 с (`ATLAS_REPLAY_TIMEOUT`), дерево процессов убивается. Всё остальное печатается `не сверено (вне allow-list)` (в §2.5 — «сверка лидом»; слова заменены этим абзацем). Фильтр опций — по имени до `=`: запрещённой длинной опции git отказ и её сокращению (`--op=…` — это `--open-files-in-pager`), и букве `O` в склейке коротких (`-nO<команда>`); `@файл` у pytest — отказ (проносит любые опции); `ATLAS_REPLAY_TIMEOUT` — только конечное число > 0, иначе 300 с; `LITERAL_TIMING` не считает временем русский предлог («2 с ошибкой»). Отклонения от брифа 1.9c: `git grep -c` разрешён (запрет `-c` — только глобальная опция `git -c`); `lint-result` вне allow-list (файл итога появляется после брифа). Правило литерала приёмки 1.2: четыре из шести неверных чисел отчёта `1.2.review-r1.md` линт называет — nit 1 и nit 2 повтором команды, nit 4 («37 строк» — пересказ) и nit 9 (время) формой; nit 3 и nit 8 механике недоступны (нет команды).

**Хук `lint-brief.sh` (1.9c).** Лимиты DESIGN/FILES/REDS и тексты отказов — `scripts.atlas.lint_brief.spawn_violations`, та же функция, что у файл-режима. Проект набора без `scripts/atlas` (`ModuleNotFoundError` с `e.name` из `scripts`, `scripts.atlas`, `scripts.atlas.lint_brief`) проверяется прежним встроенным кодом (`_legacy_violations` — копия, оставлена сознательно: функция у потребителей набора не снимается); любой иной сбой — fail open. Файл хука — файл набора claude-kit: хеш в `.seed-manifest.json` расходится (как у `executor-brief.md`, см. «Последствия») — решает лид плана с владельцем. `lint_brief.py` и `replay.py` — синтаксис не выше Python 3.11: `$PY` хука — первый python из PATH, не `.venv`.

**2.6. REDS** — пункты `<path>::<test>`, ≤ 10, или `n/a — <почему>`.

#### 3. Инъекции — `tasks/<id>.injections.json`

JSON-массив объектов, у каждого ровно восемь ключей:

| ключ | тип | смысл |
|---|---|---|
| `id` | str | `inj-<n>`, n = 1, 2, … по порядку массива; узел ADR-ATL-001 `injection` = `<slug>#<id>/inj-<n>`; не перенумеровывается |
| `prop` | str | нарушаемое свойство — строка DESIGN или ACCEPTANCE, одной строкой |
| `file` | str | путь от корня репозитория, `/` |
| `old` | str | дословная подстрока `file` на коммите, где инъекция прикладывается; в файле ровно один раз (1.9c) |
| `new` | str | замена; может быть пустой |
| `forecast` | list[str] | nodeid, которые покраснеют; пишется ДО прогона и не правится; `[]` — «не поймает ни один тест» (дыра, названная заранее) |
| `observed` | null \| list[str] | `null` до прогона, затем nodeid красных из радиуса `test` |
| `test` | str | радиус: аргументы pytest от корня через пробел (`scripts/atlas/tests/test_x.py -k y`); прогон — `python -m pytest -q -p no:cacheprovider <test>` |

nodeid — `^[^\s:]+\.py::\S+$` (класс `::Class::test` и параметры `[…]` допустимы). Совпало — `observed` не `null` и множества `observed` и `forecast` равны. Сводка — «N инъекций, совпало M, расхождений K» и «, не прогнано L» при L > 0. Ребро `breaks` (ADR-ATL-001) строится по `observed` — не по `forecast` и не по `test`; `TEST_NEVER_RED` — 1.5b (DEFERRED), без изменений. Легенды, алиасы (`T2`), лишние ключи писателю запрещены: пояснения — в шапку брифа.

Старые формы — читатель 1.9e терпит, писатель не пишет: `1.6c.injections.json` (id `A01…`; нет `observed` и `test` — считать `null`; forecast без `::` сравнивается по имени функции), `1.9a.injections.json` (объект без `id` пропускается; алиасы `T<n>`/`H<n>` не разрешаются — инъекция «не сверяема»; лишний ключ `note` игнорируется). `tasks/<id>.injections.md` — проза, машиной не читается; новые не создаются (у `1.7a.injections.md` H1 `# Task 1.7a — инъекции` засчитан заголовком задачи).

#### 4. Итог — `tasks/<id>.result.md`

Форма 1.9a: только `## `-заголовки, семь обязательных разделов и необязательные `## Для следующего брифа`, `## Память`; читатель — `result_form`. `## Инъекции`: при `injections.json` — строка `- N инъекций, совпало M, расхождений K — tasks/<id>.injections.json` (`, не прогнано L` перед ` — ` при L > 0, как в §3), каждое расхождение — ещё строкой в `## Не проверено`; без JSON — таблица прежней формы (её читает `views._result_parts`) или `- нет`. Таблица не обязательна: итог упирается в 2 КБ (прецедент 1.9a).

**Принятая потеря до 1.9e.** `pack` не печатает «предсказано ≠ наблюдалось» для итогов со сводкой — у 1.9a 4 расхождения не видны. Читатель JSON в `pack` — обязанность, предложенная строке 1.9e (итог 1.9d, `## Для следующего брифа`); до неё расхождения видны только строками `## Не проверено`.

#### 5. Отчёт ревью

Файлы: `plans/<план>/reports/<id>.review-r<N>.md` — стадия 0 (`MODE: plan`), `reports/<id>.review-code-r<N>.md` — ревью после кода; N с 1. Пишет reviewer последним сообщением, лид сохраняет дословно. Первые четыре строки:

```
# <id> — ревью <стадии 0|после кода>, раунд <N>
Вердикт: APPROVED|CHANGES REQUESTED
Итог: blocker <n>, major <n>, minor <n>, nit <n>
Классы: fact <n>, dryrun <n>, form <n>, context <n>, design <n>, scope <n>, process <n>
```

Строки 2–4 — ровно `^Вердикт: (APPROVED|CHANGES REQUESTED)$`, `^Итог: blocker (\d+), major (\d+), minor (\d+), nit (\d+)$`, `^Классы: fact (\d+), dryrun (\d+), form (\d+), context (\d+), design (\d+), scope (\d+), process (\d+)$`: все семь классов в этом порядке, нули пишутся, после чисел ничего. Раздел `## Замечания`: замечание — пункт `^- \[(blocker|major|minor|nit)/(fact|dryrun|form|context|design|scope|process)\] \S`, продолжение — строки с отступом 2 пробела; у замечания одна степень и один класс. Счёт — по всему файлу: число пунктов по каждой степени равно `Итог`, по каждому классу — `Классы`; строка с `- [` вне грамматики — нарушение. Заголовок `## Замечания` сравнивается целой строкой (`## Замечания р.1` — другой раздел); статусы прошлых раундов пишутся пунктами без `- [`. Замечание несёт `вход → наблюдение`, без него — слово «совещательно». Прочие разделы свободны; `## Что я оставил открытым / ненадёжным` обязателен (заголовок целой строкой) и непуст (правило проекта).

**Классы** — в порядке старшинства; подходят несколько — берётся первый:

1. `fact` — неверный факт: число, путь, `файл:строка`, имя или вывод команды не совпадает с репозиторием;
2. `dryrun` — план не исполняется как написан: команда, тест или инъекция не работает либо проверяет не то (зелёное без свойства);
3. `form` — текст нарушает свой формат или читается исполнителем двояко;
4. `context` — бриф не знает потребителя, соседа, хвоста прошлой задачи, правила или урока проекта;
5. `design` — само решение неверно или неполно: гонка, порядок, граница API, выбор механизма;
6. `scope` — граница задачи: лишнее, недостающее, пересечение с другой задачей;
7. `process` — порядок стадий, правила tester, инъекций, ревью, коммита.

M2 (1.9f) — blocker+major классов `fact`, `dryrun`, `form`: их ловит механика (`lint-brief`, `inject`). `nit` — только степень. **Отклонение от ревизии CTO §1** (`fact|dryrun|form|context|design|process|nit`): добавлен `scope` (в употреблении с 1.7a р.1), `nit` убран из классов — дублирует степень (у 1.9a р.1 — `nit 0`).

**С `reviewer.md`** (`.claude/plugins/dev/agents/reviewer.md:256-270`: категории `spec`…`tests`, степень по категории, `nit` нет): форму отчёта несёт промпт спавна лида со ссылкой на `review-report.md` — для `MODE: plan` и для ревью кода. Категория `reviewer.md` (о какой области) может стоять в тексте замечания, класс (откуда дефект) — в теге. Правка `reviewer.md` и грейдера `dev/evals/` — не 1.9d; владелец — лид плана (предложено строке 1.10b).

Старые формы — K0 `1.2.review-r1.md` (шапка с `**…**`, нумерованные списки по степени, без классов) и строки «Классы:» в брифах 1.7a, 1.9a (`nit` классом) — читатель `review_form.parse` не принимает: он строг. Отчёты K0 1.1 р.1, р.2 и 1.2 р.1 переразмечены лидом плана (коммит `a36b70948`). Фраза «читатель терпит только перечисленные здесь старые формы» в разделе «Контекст» остаётся про итог и бриф.

#### 7. Метрики (1.9f)

`python -m scripts.atlas metrics [<spec>...] [--base <spec>]...` — таблица `| метрика | <колонки> |` и пять строк. Колонка — `<slug>#<id>`; голый `<slug>` разворачивается в колонки всех задач плана с `tasks/<id>.md` (натуральный порядок id). Колонки `--base` идут первыми с меткой `база`, остальные — `сейчас`. Читается рабочее дерево репозитория cwd, не ревизия; реестр, SQLite и сборка не нужны. Код выхода: 0 — все ячейки посчитаны, 1 — есть `?` (нарушение формы отчёта §5 или хеш DONE, которого нет в репозитории), 2 — нет плана или задачи, usage.

| строка | ячейка |
|---|---|
| M1 доля фактов Атласа | `<p>% (<a>/<b>)`: b — строки `- ` блока FACTS брифа `tasks/<id>.md`, a — из них строки формы факта с первой командой `python -m scripts.atlas …`; p округляется половиной вверх; нет файла, блока или закрывающего маркера, b = 0 — `—` |
| M2 blocker+major р.1 по классам | `blocker <класс> <n>, …; major <класс> <n>, …` по `reports/<id>.review-r1.md`; нет blocker и major — `0`; нет файла — `—`; нарушение формы — `?` |
| M2 из них fact+dryrun+form | число пунктов blocker и major этих трёх классов; `—` и `?` как у строки выше |
| M3 раундов до APPROVED | наименьший N отчёта `review-r<N>.md` с вердиктом APPROVED; нет такого — `нет (раундов K)`; отчётов нет — `—`; нарушение формы в любом — `?` |
| M4 коммитов после DONE | `<n> (не docs <k>) после <7 знаков хеша>`; нет строки `- Task <id>:` или группы DONE — `—`; DONE без хеша — `— (DONE без хеша)`; хеш не найден — `?` |

**О1 (M4).** Печатаются оба числа: все коммиты с трейлером `Task: <slug>#<id>` после DONE-коммита и из них не типа `docs`. K0b гейтом M4 не пользуется.

**О6 (механика печатает то, что в файлах).** M3 K0 1.2 — `нет (раундов 1)`, хотя по записи брифа раунд 2 был: отчёт р.2 не сохранён.

**Известное ограничение.** Статус DONE читается только из строки `- Task <id>:` плана; DONE на строке продолжения и хеш из одних цифр без обратных кавычек не читаются.

**U1/U2** — после 1.10b: журнала вызовов нет, строка `U1/U2: не считаются — журнала нет (Task 1.10b)` печатается всегда.

### Последствия

- Три новых шаблона (`task-brief.md`, `injections.md`, `review-report.md`); `task-result.md` — правило `## Инъекции` по §4. `executor-brief.md` не меняется: его первый fence — постоянные блоки спавна (`build_brief`), а не форма задачи; хеш в `.seed-manifest.json` уже расходится с файлом (хеш манифеста — версия файла на коммите `b1e03bafb`, не HEAD) — вопрос claude-kit, не 1.9d.
- `validate.py` форматы не читает; проверка — `test_formats_1_9d.py` в job `atlas` CI.
- Обязанности задач-читателей (предложение лиду плана, итог 1.9d): 1.9b — `brief --check` и маркер FACTS по §2.5; 1.9c — `lint-brief` по §2.3–2.6 и §3, разбор меток — импорт `plans_ledger` (`_brief_label_positions`, `_label_blocks`), без второго парсера; 1.9e — `inject summary` и хвост `pack` из JSON, тест на пример `injections.md`, терпимость к старым формам §3; 1.9f — `metrics` на пример `review-report.md`; 1.10b — форма отчёта в `reviewer.md`.
- ADR-ATL-001 §1–2: строки `injection`, `breaks`, `lists` получили источник по этому ADR.

### Отклонённые альтернативы

- **Брифы ролей в fence одного файла (1.7a)** — `build_brief` их не видит; научить его fence — второй вариант разбора.
- **Поля брифа заголовками `## DESIGN`** — правка регулярки в трёх копиях (`plans_ledger.py`, зеркало, `lint-brief.sh`).
- **Форма задачи внутри `executor-brief.md`** — его первый fence читается как постоянные блоки спавна.
- **Таблица инъекций в итоге как источник** — `old`/`new` многострочны, ячейка markdown их не держит; итог упирается в 2 КБ.
- **`nit` классом** — дублирует степень.
- **Литерал пересказом** — повтор команды его не сверит.
