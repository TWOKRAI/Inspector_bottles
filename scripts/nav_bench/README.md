# nav_bench — как быстро ИИ-агент находит нужное `файл:строка`

Инструмент меряет, за сколько вызовов, токенов и секунд агент (`claude -p`) доходит до верного адреса в коде при заданном
**условии** (читает только исходники, только карту, исходники плюс справку). Только стандартная библиотека; ничего не знает
о проекте: корень репозитория — аргумент `--root`, вопросы и условия — JSON-файлы.

Один повтор = одна headless-сессия, которая отвечает на ВСЕ вопросы набора. Повторов несколько, чтобы видеть разброс:
один прогон — наблюдение, не замер.

## Быстрый старт

```
# 1. что будет запущено и сколько это примерно стоит (ничего не стартует)
python scripts/nav_bench/bench.py run --questions scripts/nav_bench/questions/k0.json \
    --condition scripts/nav_bench/conditions/source-only.json --repeats 3 --dry-run

# 2. реальный запуск — только с --yes
python scripts/nav_bench/bench.py run --questions ... --condition ... --repeats 3 --yes

# 3. пересчитать оценку записи (поправили эталон — сессии повторять не надо)
python scripts/nav_bench/bench.py score --run data/nav_bench/<дата>_k0_grep-read.json [--questions другой.json]

# 4. две записи рядом
python scripts/nav_bench/bench.py compare A.json B.json

# 5. потолок набора: сколько ожидаемых адресов вообще есть в JSON-эталоне (модель не вызывается)
python scripts/nav_bench/bench.py ceiling --questions Q.json --reference ref.json [--min N]
```

Запись прогона и таблица markdown лежат в `<root>/data/nav_bench/<дата>_<набор>_<условие>.{json,md}`
(`--out` меняет каталог; повтор в тот же день получает суффикс `_2`, старая запись не затирается). Каталог `data/`
в этом репозитории в `.gitignore`.

## Набор вопросов для любого репозитория

JSON-файл:

```json
{
  "name": "мой-набор",
  "repo_sha": "abc1234",
  "questions": [
    {
      "id": "Q1",
      "question": "Где определён интерфейс X и кто его реализует?",
      "expected": [
        {"path": "pkg/interfaces.py", "line": 21, "symbol": "X"},
        {"path": "pkg/impl.py", "line": null, "symbol": null}
      ],
      "scored": true,
      "note": "как проверен эталон"
    }
  ]
}
```

- `repo_sha` — коммит, на котором проверены строки эталона (можно сокращённый). Прогон идёт в чистой копии этого коммита (HEAD не важен);
  правки эталонных файлов в рабочем дереве дают предупреждение, сверка — `verify-set`.
- `expected` — допустимые места ответа; по умолчанию достаточно любого (`require: "any"`), с `require: "all"` нужны все (см. «Раунд 2»). Нужно перечисление «все места» — разбейте на
  отдельные вопросы. `path` — posix-путь от корня репозитория. `line: null` — совпадение по одному пути (файловый ответ,
  например «какой файл держит тесты»). `symbol` — подсказка человеку, в оценке не участвует.
- `scored: false` — вопрос в прогоне есть, но в пороги не входит (эталон неполный или нет способа выставить адрес);
  в итоги «по всем вопросам» он входит.
- Эталон обязательно сверить с кодом: `git show <repo_sha>:<path>` и `git grep -n`. Счётные ответы («17 членов»)
  оценкой по адресу не проверяются — число читает человек в поле `answer`.

### Формат ответа агента (зашит в промпт)

По одному JSON-объекту на строку: `{"id","answer","locations":["путь:строка"],"confidence":"sure"|"unsure"|"unknown"}`.
Разбор терпим к прозе, ``` -ограждениям и многострочным объектам; битый объект = нет ответа = `unknown`.

### Оценка

- `hit` — есть адрес с тем же путём и строкой в пределах **±3** (или у эталона `line: null` и пути равны);
- `false` (ложный адрес) — уверенность `sure` и в ответе есть адрес мимо эталона либо адресов больше потолка `len(expected)+1`, а чистого попадания нет;
- `miss` — всё остальное (включая «не ответил»).

Абсолютные пути агента приводятся к корню (`--root`); обратные слэши — к `/`.

Колонка `файл (справка)` в таблице записи — `files_hit/scored`: у скольких оцениваемых вопросов с адресами агент назвал пути эталона (по `require`, строки не важны). Это справка о том, где агент ошибается — в файле или в строке; в сводку (`METRICS`) и вердикт она не входит, вердикт — только `hits` по правилу V3. У записи, снятой до этой колонки, ключа `files_hit` нет, и `score` показывает `н/д`. Трасса записи (`tool_uses`) кроме `target` хранит `pattern` и `glob` вызова, если они были: `target` берёт путь раньше шаблона, и без этих ключей шаблон поиска терялся.

## Условия (`conditions/*.json`)

| поле | смысл |
|---|---|
| `name`, `model` | имя и модель (`--model`: алиас `haiku`/`sonnet`/...) |
| `allowed_tools`, `disallowed_tools` | `--allowedTools` / `--disallowedTools` |
| `context_files` | файлы, названные агенту в промпте как справка (он читает их сам, это вызовы Read) |
| `prompt_prefix` | `--append-system-prompt`; подстановки `{repo_root}`, `{repo_sha}`, `{run_root}` (пути — posix) |
| `bash_allow` | необязательно: шаблоны Bash (`"git log *"`, `*` — любой текст). Непустой: `Bash` в `--tools`, `Bash(<шаблон>)` в `--allowedTools`, `--setting-sources user` (источники project и local — `.claude/settings.json`, `settings.local.json` копии — не грузятся и не вливаются в разрешения; `~/.claude/settings.json` пользователя остаётся в силе) и аудит Bash (см. ниже). Нужна копия `copy: clone`. Те же подстановки; иное имя в `{}` — отказ (код 2) |
| `max_turns` | лимит ходов; в `claude --help` v2.1.289 флага `--max-turns` **нет**, поэтому он не передаётся, а проверяется после прогона (`over_max_turns` в записи) |
| `max_budget_usd` | необязательно; `--max-budget-usd` — единственный жёсткий стоп-кран по деньгам |
| `expected_tokens` | оценка токенов на один повтор — для строки стоимости |
| `thresholds` | `hits_min` (8), `false_max` (1); необязательные: `facts_hit_min`, `calls_median_max`, `tokens_median_max` (абсолютные), `calls_ratio_max`, `tokens_ratio_max` (доля от базового прогона; в поставляемых условиях 0.5 и 0.6) |
| `output_format` | необязательно, по умолчанию `stream-json` (см. ниже) |
| `audit_reads` | необязательно: любое `Read` вне `context_files` — нарушение (`violations`, вердикт `TAINTED`) |
| `mcp_config`, `requires` | MCP-условия: шаблон конфигурации серверов и предпроверки индекса (см. «Раунд 2») |

Поставляются (`conditions/`): `grep-read` (код: `Read`, `Grep`, `Glob`; `source-only.json` — прежнее имя, тот же набор), `qex`
(+`mcp__qex__search_code`), `graphify` (+чтения `mcp__graphify__*`), `map-only` (только `docs/arch-map/{units.md,findings.md,model.json}`),
`reference` (справка `docs/arch-map/_bench/k0_reference.json` плюс право читать код; файл справки строит другой агент —
этого условия без него не запустить), `all` (код, qex, graphify, карта и справка). Условия `qex`, `graphify`, `map-only`,
`reference`, `all` несут относительные пороги (`*_ratio_max`): они считаются от базового прогона `grep-read` на том же наборе.
`run` **отказывает** (код 2), если в порогах есть `*_ratio_max`, а `--baseline` (или `thresholds.baseline`) не задан, и если
набор базы (поле `set` её записи) не совпал с набором прогона. `score` без базы не отказывает, а пишет `unmeasured` (и полосу `UNMEASURED`, если иначе было бы `PASS`).

**Вердикт по повторам:** `hits` — по худшему повтору (min), `false` — по худшему (max), вызовы и токены — по медиане.
Не измеренное значение (нет базы, нет числа вызовов при `output_format: json`, имя поля в выводе не совпало) не проходит молча:
оно попадает в `unmeasured`; если иначе была бы полоса `PASS`, `pass` ложно, а полоса — `UNMEASURED` (`FIX` и `FAIL` по измеренным порогам сохраняются).

### `map-only`: техническое ограничение и аудит

- принудительно: `--tools Read` (в сессии нет `Bash`, `Grep`, `Glob`, `Edit`, `Write`), плюс `--disallowedTools` и всегда
  `--strict-mcp-config`;
- `Read` остаётся разрешённым: «запретить всё, кроме трёх файлов» правилами не выразить, а запрещать каталоги кода поимённо — значит
  зашить в условие имена проекта. Поэтому ограничение на какие файлы читать — совет в `prompt_prefix`, а проверка — аудит;
- у `map-only` включён `audit_reads`: после прогона каждый `tool_use` вне `allowed_tools` и каждое `Read` вне `context_files`
  попадает в `violations`. Любое нарушение в любом повторе даёт вердикт `TAINTED` (прогон недействителен, не `PASS`);
  аудит работает только при `output_format: stream-json`.

**Ограничение, не исправленное в коде.** `context_files` копируются в чистую копию из рабочего дерева `--root`, а не из `repo_sha`.
Пока в `main` нет `docs/arch-map/` (до Task 3.1 / 4.3), условия `map-only`, `reference`, `all` упадут в `prepare_clean_copy`
с `FileNotFoundError` — это ожидаемо, запускайте только `grep-read`, `qex`, `graphify`.

## Формат вывода claude

Команда строится в одном месте (`build_command` в `bench.py`, константы вверху файла). Промпт идёт через stdin.
`--output-format json` отдаёт `num_turns`, `usage`, `result`, но **не перечисляет вызовы инструментов**, поэтому по
умолчанию взят `stream-json` (`--verbose`): из него считаются вызовы инструментов и аудит чтений. Парсер понимает оба.
Имена полей разбора взяты из документации, **не проверено живым прогоном**.

«Токены» в записи = `input_tokens + output_tokens + cache_creation_input_tokens`; чтение кэша (`cache_read`) не входит.
Это определение одно в `parse_session_output`; если порог 50000 выбран по другой сумме, поправьте там.

## Защита от расхода

Реальный запуск печатает `Оценка стоимости: повторы x expected_tokens` и **не стартует без `--yes`** (код выхода 2).
`--dry-run` ничего не запускает и `--yes` не требует. Сессия, упавшая по ошибке или таймауту (30 минут), записывается
в запись (`error`), остальные повторы продолжаются.

## Известные ограничения

- Сессия `claude` в каталоге репозитория сама подхватывает `CLAUDE.md` и настройки проекта — это одинаково для всех
  условий **без** `bash_allow`, но подсказывает агенту структуру кода. `--bare` отключил бы это, но требует
  `ANTHROPIC_API_KEY` (не OAuth). При непустом `bash_allow` команда идёт с `--setting-sources user`: проектный
  `CLAUDE.md` и project-хуки Bash в этом режиме, возможно, не грузятся (по документации Agent SDK источник `project`
  грузит проектный `CLAUDE.md`; для CLI живым прогоном не проверено). Пока это не проверено живым зондом в 7.2b,
  `grep-read+git` не сопоставимо с `grep-read`. Запасной вариант без флага: убрать `.claude/settings*.json` из клона
  тем же `skip-worktree` и удалением.
- Версия `claude` в запись не пишется.
- Оценка — только по адресам; качество текстового ответа (`answer`) не проверяется.
- Аудит Bash, `bash-meta` (раскрытие shell, раздел «Раунд 2»): fail-closed даёт ложный `TAINTED` (виден в `violations`) на
  `HEAD^{tree}`, `HEAD@{1}`, `git grep class.*Router` без кавычек, `-G"a$"` (`-G'a$'` чисто), путь с `\` (`src\gui.py`),
  `#`, `(`; чисты `HEAD~3`, `HEAD^`, `'*.py'`, `"class [A-Z].*Base"`. Перебор 304 форм (bash и zsh, git 2.51.2, macOS):
  237 запустили пейджер, все помечены. Белый список рассчитан на опции shell по умолчанию: `setopt extendedglob` и
  `RC_QUOTES` в zsh пользователя, Git Bash на Windows не проверены.

## Раунд 2: что изменилось (при расхождении с текстом выше прав этот раздел)

**Чистая копия.** Сессия идёт не в репозитории, а в каталоге `%TEMP%/nav_bench/<repo_sha>-<hash>`: `git archive <repo_sha>`,
затем удаляются пути поля набора `exclude` (для k0 и arch: `scripts/nav_bench`, `scripts/atlas/tests`, `docs/handoffs`,
`docs/reports`, `docs/reviews`, `plans`, `docs/claude/memory`), затем докладываются `context_files` условия из рабочего дерева.
Поле набора `copy`: `archive` (умолчание; в копии нет `.git`) или `clone`; иное — отказ (код 2). Копия `clone`:
`git clone --shared` -> `checkout --detach <repo_sha>` -> удалены все ссылки, `origin` и reflog (иначе `git log --all`
показал бы эталон) -> `repack -a -d` и удалён `objects/info/alternates` (иначе `Read` источника достал бы любой файл) ->
пути `exclude` помечены `skip-worktree` и удалены (`git status` чист). В копии есть история до `repo_sha` и только она.
Условие с `bash_allow` перед сессией проверяет `git rev-parse HEAD` копии (начинается с `repo_sha`), иначе отказ.
Ключ копии `archive` не изменился; у `clone` в хеш входит `copy`. Копия переиспользуется при том же sha + хеше (`exclude` и `context_files`: иначе карта прошлого условия осталась бы
видна следующему; в хеш входит и имя условия: граф graphify, собранный внутри копии, не должен попасть в `grep-read` и `qex`). `--root` — репозиторий-источник; каталог записей по умолчанию `<root>/data/nav_bench`.

**Оценка адресов.** `require: "all"|"any"` на вопрос (по умолчанию any; Q1, Q2, Q4 = all); `tolerance` на запись эталона
(по умолчанию 3; Q2 и Q3 = 0); диапазон `path:a-b` попадает, если пересекает окно `line ± tolerance`; учитываются только первые
`len(expected)+1` адресов, лишние при `sure` — ложные (даже если эталон закрыт: попадание засчитывается, только если адресов не больше потолка); `sure` без адресов — miss; уверенность — `.strip().casefold()`, неизвестные
значения (`high`) = `unknown`. **Факты:** `expected_facts: [{"any_of": [...]}]`, целое слово без регистра в поле `answer` (границы слова, `re.escape`),
`facts_require` (по умолчанию all); `facts_hit` считается отдельно от hits. Вопрос без `expected` — только факты.

**Метрики прогона.** `tool_calls`, `final_context_tokens` (input + cache_creation + cache_read последнего assistant-события),
`cumulative_tokens` (in + out + cache_creation), `cache_read_tokens`, `subtype` (обрыв по бюджету виден: `error_max_budget_usd`).
Пороги: абсолютные (`calls_median_max`, `tokens_median_max` — по final_context_tokens) или относительные к базовой записи
(`calls_ratio_max`, `tokens_ratio_max`; база — `--baseline run.json` или `thresholds.baseline`; без базы `run` отказывает, `score` пишет `unmeasured` (полоса `UNMEASURED`, если иначе было бы `PASS`); база должна быть снята на том же наборе).
Пороги набора перекрывают пороги условия. `bench.py floor` — один тривиальный вопрос теми же флагами: фиксированные накладные расходы. Запись floor хранит пороги условия без ключей `*_ratio_max` и **не годится как база** для относительных порогов; при `floor` проверка набора базы не выполняется.

**Вердикт — пять полос:** `PASS` (главная метрика >= порога, false <= 1, пороги выполнены), `FIX` (главная метрика на 1-2
ниже порога, либо выше, но не выполнен другой порог), `FAIL` (ниже), `UNMEASURED` (все измеренные пороги выполнены, но порог без метрики остался), `TAINTED` (любое нарушение доступа в любом повторе —
прогон недействителен; первее остальных). Главная метрика: `facts_hit`, если задан `facts_hit_min`, иначе `hits`.
Полоса `FIX` возможна и при выполненных `hits`: например, `hits` в норме, а `calls_ratio` провален (31 вызов против базы 40 = 0.775 > 0.5) — это шире определения «6-7 попаданий».

**Аудит доступа — по списку разрешённого:** любой `tool_use` вне `allowed_tools` (имена без регистра, шаблоны `fnmatch`) и,
при `audit_reads`, любое `Read` вне `context_files` (пути без регистра, posix) — нарушение. Технические пределы:
`--tools` (встроенные из `allowed_tools`) и всегда `--strict-mcp-config` (MCP только из `--mcp-config`).

**Аудит Bash (`bash_allow`):** команда без шаблона — `bash-pattern`; в тексте группы `*` шаблона (литералы шаблона не
проверяются): путь из `exclude` (`shlex`-токены, куски по `:` и `=`, без регистра, без `./` и префикса копии) —
`bash-exclude`; `;` `&&` `||` `|` `&` перевод строки `>` `<` `` ` `` `$(` — `bash-chain`; флаги `--output`, `-O`,
`--git-dir`, `--work-tree` (регистр значим) — `bash-flag`. Любое нарушение — `TAINTED`; текст `<правило>:<команда до 80
символов>`. Аудит видит только аргументы: `git log -p` без пути и `git grep x HEAD` показывают файлы из `exclude`
(история копии их содержит). Поставляемое условие `grep-read+git` такие вызовы **допускает**; утечка через вывод
остаётся и закрывается отдельной проверкой вывода (решает лид, вне 7.2).
Известное ограничение: `bash-chain` не учитывает кавычки (fail-closed), поэтому `git grep -E 'a|b'` даёт ложный
`TAINTED`; он виден в записи (`violations`), долю таких считает 7.2b. Флаг `-O` ищется в связке коротких флагов слева
направо: после флага, берущего значение, остаток токена — значение. Набор букв зависит от подкоманды: у `git log`,
`git show`, `git blame` это `S G L e f A B C m`, у `git grep` и неопознанных команд (fail-closed) — `e f A B C m`; `n`
нет нигде (у `git grep` это флаг без значения). У `git grep` `-G` и `-L` — флаги без значения, поэтому `git grep
-GOsh x` — это `-G` и `-O`, пейджер запускается, и вызов `TAINTED`. Чисты `git log -SOrder`, `git log -GOsh x`,
`git grep -eObject`; `bash-flag` — `-nOsh`, `git grep -GOsh x`, `git grep -lLOsh x`. `--open-files-in-pager` (и сокращения `--open`) — `bash-flag`.
**`bash-meta`** (проверка после `bash-chain`, до `bash-flag`): аудит разбирает слова через `shlex`, а shell до запуска git
раскрывает `$'..'`, `$".."`, `${..}`, `$IFS`, `{a,b}`, глоб, `~`, обратную косую — так `git grep $'-O'"cmd" x` запускал
пейджер при чистом аудите (git 2.51.2). Класс закрыт белым списком, без перечня форм: вне кавычек допустимы буквы, цифры,
пробел, таб и `_ . / : = @ % + , - ^`, `~` — только внутри слова (zsh раскрывает `""~` и `=git` в абсолютные пути: флага из них не выходит, но аудит их пропускает); внутри `'...'` — всё; внутри `"..."` — всё, кроме `$` и
`` ` ``; непарная кавычка — нарушение. Цена и пределы — в «Известных ограничениях». У вызова Bash в `tool_uses` поле
`denied` = `is_error` его `tool_result` (отказ CLI либо код выхода != 0); отказанный вызов нарушением быть не перестаёт.
Поставляется `grep-read+git` (`grep-read` + Bash по шаблонам `git log`, `git show`, `git blame`, `git grep`).

**Условия:** `grep-read` (прежний `source-only`, файл-алиас оставлен), `map-only`, `reference`, `qex`
(+`mcp__qex__search_code`), `graphify` (+чтения `mcp__graphify__*`), `all` (всё, включая карту и справку). MCP-условия:
`mcp_config` (шаблон с `{python}`, `{repo_root}`, `{run_root}`; готовый файл пишется рядом с копией) и `requires`
(`qex-index`, `graphify-graph`) — предпроверка отказывает с точной командой сборки; индексы bench сам не строит.

**Защиты запуска:** `expected_tokens > 0` обязателен; реальный запуск без `max_budget_usd` — отказ, кроме `--no-budget`;
печатается `повторы x max_budget_usd`; предупреждение, если эталонные файлы изменены в рабочем дереве (`git status --porcelain`).

**Наборы.** `bench.py verify-set --questions Q.json` — каждый путь эталона существует на `repo_sha`, `symbol` (последняя часть
после точки) встречается в `line ± tolerance`; поле `evidence` (`{path, contains}`) проверяется так же. `questions/arch.json`
(10 архитектурных вопросов, только факты, порог `facts_hit_min: 8`): доказательства фактов — в `evidence` и в отчёте.

**Предупреждения `verify-set`.** После строки итога `verify-set` печатает `ПРЕДУПРЕЖДЕНИЕ: …` и строку `предупреждений N` (даже при 0); код возврата зависит только от проблем. Правила: а) число в `note` (`tolerance N`, `N-line tolerance`, `anchor line N`) не совпадает с записями вопроса; б) оцениваемый вопрос вида «which/what … file», а эталон требует строку; в) путь из `exclude` с тем же текстом на `repo_sha`, что у ожидаемого пути (двойник); г) окно `line ± tolerance` `.py`-записи выходит за объемлющую функцию. Допуски и эталон задним числом не правятся: предупреждение только сообщает.

**`ceiling`.** `bench.py ceiling --questions Q.json --reference R.json [--min N]` — какие ожидаемые адреса набора есть в JSON `R` (эталон 3.1 или вывод `atlas ref --format json`): строка на оцениваемый вопрос `<id> reachable=yes|no`, для `no` — недостающие адреса, итог `ceiling <набор>: K/N`. Адрес эталона достижим, если у адреса того же пути строка входит в окно `line ± tolerance` (запись без строки — любой адрес пути); вопрос — по `require`. Код 0; с `--min N` при K < N — 1; нет файла или не JSON — 2 (`ОШИБКА: …` в stderr).
