# commit_audit — классификатор срывов `git commit` / `git merge`

Читает транскрипты Claude Code и считает, сколько вызовов `git commit` / `git merge` сорвались и почему.
Нужен как **база замера** для плана `commit-mechanism`: после Task 3.2 те же числа пересчитывают на новом окне
и сравнивают с базой.

Определения (попытка, каталог, исход, сигнатуры классов, разбивка A1 по писателю, `hidden`) — в спеке
[`tasks/2.3.md`](../../plans/2026-10-03_commit-mechanism/tasks/2.3.md), разделы DESIGN (a)–(i) и «Ред. 3».
Регэкспы здесь не копируются: правка одного из двух мест рассинхронизирует их молча.

## Запуск

```bash
python scripts/commit_audit/classify.py \
    --root C:\Users\INNOTECH\.claude\projects --since 2026-09-02 --until 2026-10-03 [--json]
```

| Ключ | Смысл |
|---|---|
| `--root` | каталог `projects` с транскриптами |
| `--since`, `--until` | окно, местные даты по `timestamp` записи; обе границы включительно |
| `--project-substr` | подстрока имени каталога проекта (по умолчанию `Inspector-vision-Inspector-bottles`: основной каталог и каталоги worktree) |
| `--json` | тот же набор чисел JSON-ом плюс `attempts` — метки по каждой попытке (ключ — `tool_use.id`) |

Только stdlib. Транскрипт читается построчно; файлы с mtime раньше `--since` пропускаются. Прогон по ~900 МБ
транскриптов за 32 дня занимает около 20–40 секунд.

Скрипт пишет в stderr всё, что пропустил или додумал: битые строки JSONL, попытки без `timestamp`, попытки без
`tool_result` (считаются исполненными с исходом `unknown`). Пустой stderr — ничего не пропущено.

## Что считает

Знаменатель — **вызовы** `Bash` (один вызов с двумя `git commit` = 1), отдельно для `commit` и `merge`; вызов с
обоими идёт в обе колонки и в `both_calls`. Не исполненные (отказ в разрешении, блок хука кроме `protect-branch`)
в знаменатель не входят — их число в `not_executed`. Опыты в `commitlab`, `/tmp`, `Temp` не считаются.

| Строка | Что это (подробно — в спеке) |
|---|---|
| `A1` | хук `ruff format` сорвал коммит и переписал файлы |
| `A1-Edit/Write`, `A1-Bash`, `A1-undecided` | разбивка `A1` по тому, кто последним писал `.py`: инструмент Edit/Write, Bash или не решить |
| `A1-F401` | `ruff check --fix` изменил файл (код F401 в выводе не печатается) |
| `A2` | `trim trailing whitespace` / `fix end of files` |
| `A3` | `patch does not apply` (откат автоправок pre-commit) |
| `C1` | `E501` в блоке ruff |
| `C2` | ошибка разбора shell: `unexpected EOF`, незакрытый heredoc |
| `C4` | `git` не прочитал файл сообщения (`-F -` без stdin, файла нет) |
| `B1` | нет `Refs:` у коммита в ветке с планом |
| `B2` | тип `merge` не разрешён валидатором |
| `hidden` | вывод попытки отфильтрован (`2>/dev/null`, `2>&1 \| tail/head/grep`): срыв мог не дойти до читающего |

`hidden` — не исход, а флаг: скрытая попытка с меткой считается и в своём классе. Классы `C3`, `C5`, `C6`, `B3`
в таблицу не входят.

## Оговорка: транскрипты живут 30 дней

Claude Code удаляет транскрипты старше 30 дней (`cleanupPeriodDays` не задан, решение за владельцем). База за
2026-09-02…2026-10-03 пересчитана по выжившим дням: часть дней окна уже удалена, а за 09-10…09-27 файлов нет.
**Пересчёт по тому же окну позже даст другие числа** — поэтому таблицу базы фиксируют в
`plans/2026-10-03_commit-mechanism/amendments.md` в день пересчёта, а замер Task 3.2 сравнивают с ней, а не с новым
прогоном по старому окну. Окно замера 3.2 начинается со слияния Task 2.2.

## Тесты

```bash
PYTHONPATH=$PWD python -m pytest scripts/commit_audit/tests -q
```

`test_classify.py` — приёмка независимого tester (19 попыток из настоящих транскриптов, обрезанные, в `tests/fixtures/real/`
плюс малые синтетические корни); `test_classify_hazards.py` — риски механизма от автора: цитата через строки,
heredoc внутри `$(...)`, `tool_result` списком блоков, битый JSONL, большие и враждебные входы, пути Windows с `\`,
порядок писателей.
