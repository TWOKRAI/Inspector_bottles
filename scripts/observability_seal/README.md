# observability_seal — проверяющий пломбы (2.V1)

Читает логи **с диска** и ищет дырки в сквозной нумерации записей процесса.
Счётчики логгера при этом не спрашивает вовсе — в этом весь смысл: самоотчёт
логгера имеет тот же класс отказа, что и он сам.

```bash
python -m scripts.observability_seal.seal_check <каталог логов> [--report seal.txt]
```

## Что доказывает

`LoggerCore.log` ставит каждой прошедшей гейт записи сквозной номер процесса.
Номер доезжает до файла префиксом строки `#<seq> ` и до `errors_floor.jsonl`
полем `seq`. Отсюда свойство, считаемое по байтам:

> объединение номеров по всем файлам процесса непрерывно от min до max.

**Дырка = запись прошла гейт и не легла ни в один файл**, то есть потеря.

## Коды возврата

| Код | Значение |
|-----|----------|
| `0` | непрерывно — потерь нет |
| `1` | дырки, дубликаты или записи без пломбы |
| `2` | **проверить не удалось** — читать нечего, файл нечитаем или ни одной пломбы |

Код `2` существует отдельно намеренно: оракул, молчащий при неспособности
прочитать, был бы очередным проглоченным сбоем — его тишину приняли бы за
одобрение.

## Чего НЕ доказывает

1. **Предусловие:** у каждой записи окна есть хотя бы один из проверяемых файлов
   в приёмниках. Запись только в консоль или только в IPC-канал GUI даст дырку,
   не будучи потерей. На дефолтном конфиге предусловие держится (закреплено
   тестом во фреймворке); полный учёт — задача 2.V3.
2. **Ротация.** Вытесненный ретеншеном бэкап уносит свои номера с собой.
   Окно проверки — от старта процесса до первой ротации либо каталог целиком
   (`*.log.*` и `.gz` читаются).
3. **Подмену полей** (текст, уровень) — пломба про наличие записи, не про её
   содержимое. Это задача 2.V4.

## Правила, по которым он написан

Из шапки Ф2.V плана `observability-unified-routing`:

* радикально проще проверяемого — чтение, регулярка, арифметика на множестве;
  ни конфига, ни локов, ни батчинга;
* **не импортирует `multiprocess_framework`** — иначе это согласие двух моих
  компонентов, а не проверка;
* вывод в `stderr` и в отдельный файл, никогда через сам логгер;
* сам проверяется слом-инъекцией: `tests/test_seal_check.py`, десять инъекций
  на десять заявленных свойств (журнал — в плане).
