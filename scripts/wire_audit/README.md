# scripts/wire_audit — аудит провода CVT_JOB по файлам журналов

Независимый от скрипта α столбец проверки: по журналу обмена с роботом (`robot_exchange.log`) и журналу диска
(`layout/messages.log`) проверяет, что каждое задание `CVT_JOB` ушло с верными словами, а каждое взятие диска
получило ровно одно задание. Только чтение файлов; стенд, сим и сеть не нужны. Код скрипта α не импортируется и не читается.

## Состав

- `core.py` — чистые функции: `parse_exchange`, `parse_layout`, `decode_cvt`, `expected_*`, `audit`, `render`.
- `__main__.py` — CLI.
- `collect.py` — сборщик живых данных (паспорта сима, журнал сим-робота) в JSONL; отдельная задача, ядро его не вызывает.
- `tests/` — приёмочные тесты (`test_wire_audit_acceptance.py`, слепые), тесты автора (`test_wire_audit.py`),
  тесты сборщика, фикстуры run1 (`fixtures/`).

## Запуск

```
python -m scripts.wire_audit --exchange robot_exchange.log --layout layout/messages.log \
    --registers registers.json [--words ПЕРЕМИРИЕ,МИР] [--zone-max-mm 500] \
    [--sim-objects sim_objects.jsonl] [--sim-journal sim_journal.jsonl] [--out report.md]
```

Таблица и итог всегда в stdout (при `--out` ещё и в файл). Последняя непустая строка stdout —
`ИТОГ: PASS|FAIL (взятий N, заданий M, FAIL K, пропусков S, повторов R, предупреждений W)`.

## Входы

| вход | формат |
|---|---|
| `--exchange` | `#476 2026-11-12 13:33:27,133 [INFO] S.d.d.e.robot_main: #422 in W* CMD_OPCODE = 32 (CVT_JOB)`. Судится последняя инкарнация: от последней строки с номером `#1` (обычно `connect ok`). Блок `CVT_JOB` открывает `CMD_OPCODE` с именем `CVT_JOB`, перед ним `CMD_SEQ`; ответ — первая строка `R` с тем же `RES_SEQ` после `CMD_FLAG`. Другие блоки (`SERVO`, `SC_RUN`, `STOP_REQ`) и склейки `… ×k` пропускаются молча |
| `--layout` | строки `WordLayoutPlugin:` — `слово '…'`, `смена слова '…' → '…'`, `диск 'Е' 91.9° → ячейка 3: взять(…) …`, `диск … → пропуск: …`. Судится последняя инкарнация: от последней `LoggerManager initialized`. Слово и смена слова режут журнал на заливки (до первого слова — заливка 0) |
| `--registers` | JSON: `first_x, first_y, pitch_mm, disk_radius_mm, line_angle_deg, place_z_mm, pick_z_mm, angle_zero_deg, angle_invert, use_pitch`, необязательные `word_gap_slots`, `p_pick_rz_deg` (умолчание −100,0; значение печатается в шапке). Тот же файл пишет сборщик `collect.py`: `p_pick_rz_deg` он читает один раз параметром робота `P_PICK_RZ` (`robot_param_get_all` процесса `devices`, `raw/10`), источник — `p_pick_rz_deg_source` в `meta.json` и ключ `p_pick_rz_source` (`robot_param_get_all` или `default`) в `registers.json`, по нему шапка отчёта печатает «с робота: robot_param_get_all» или «умолчание: не получен»; не прочитан — умолчание −100,0 с пометкой `default` |
| `--words` | слова заливок через запятую, по порядку появления в журнале диска; число слов равно числу строк слова и смены слова, иначе код 2. Без `--words` слово берётся из журнала, шапка печатает «слово не независимо» |
| `--zone-max-mm` | радиус досягаемости, мм (умолчание 500): `hypot(place x, place y)` больше — предупреждение `~`, не FAIL |
| `--sim-objects` | JSONL паспортов сима `{"object_id", "class_name", "angle_deg", "lateral_px", "t"}` — включает столбец Б |
| `--sim-journal` | JSONL журнала сим-робота `{"t", "side", "text"}` — включает сверку множеств `seq` с `[v2] CMD seq=… op=CVT_JOB` |

## Что проверяется

Слова провода: `ARGS[0..1]` — ecap (печатается как `ARGS[1]·65536 + ARGS[0]`), `[2..4]` — взятие x/y/z, `[5]` — flags (3),
`[6..8]` — укладка x/y/z, `[9]` — rz. Мм и градусы = слово / 10 (слово ≥ 32768 — отрицательное). Ожидания считаются из регистров, слова
заливки и сырого угла сети: `place = first + i·pitch` по линии `line_angle` (`pitch = pitch_mm`, при 0 — два радиуса диска),
`rz = p_pick_rz_deg + wrap180(angle_zero − sign·a)`. Допуск колонки А — один квант (±0,10 мм, ±0,10°). Сверх этого:
`передача` (слова взятия против `взять(px,py)` строки диска), `окно` α (`ARGS[2]` 4549…4615, `ARGS[3]` 62096…62116).

Привязка «диск ↔ задание»: для взятия — первое по порядку строк файла свободное задание с временем не раньше взятия,
словом `ARGS[7]` ожидаемой ячейки и временем раньше следующего взятия в ту же ячейку. Задание без взятия — `лишнее` у
ближайшей предшествующей строки диска (`после пропуска` или `до первого взятия`).

Повтор после отказа (E_BUSY): отказанный блок, за которым идёт блок с теми же `ARGS[2..9]` и принятый (в цепочке — до принятого),
не занимает взятия и не FAIL; он считается в `повторов` и не входит в `заданий` и в проверку уникальности `seq`.

Ключи причин в последней ячейке: `потеря`, `лишнее`, `дубль seq`, `нет ответа`, `ответ противоречив`, `статус N`, `argc`,
`нет ARGS[i]`, `ячейка`, `слово`, `x`, `y`, `z`, `rz`, `окно`, `передача`, `flags`, `сим не видел`, `лишнее у сима`.
Столбец Б, привязка паспорта (ред. 3, прогон 1b): паспорт ставится в пару ко ВСЕМ строкам диска (взятиям и пропускам) в порядке
времени; диску достаётся самый поздний ещё не занятый паспорт с `t` ≤ времени строки диска (не задания), один паспорт — не
более одного диска, нет такого — «нет паспорта» (не FAIL). Буква не критерий привязки, потому что сеть путает буквы (М→И):
буква диска ≠ буква паспорта — ячейка «не судится: буква сети X ≠ паспорт Y» (`~`, не FAIL, не в медиане `e`; счётчик в строке
прогона «не судится из-за буквы сети ≠ паспорт: N»); FAIL `x` и `e` — только при равных буквах. У пропусков столбец Б пуст
(пара лишь расходует паспорт). Допущение: задержка распознавания (паспорт → строка диска) меньше шага подачи; в прогоне 1b
шаг ≈ 8,1 с, задержка ≈ 4,3 с. На другом стенде (скорость ленты, нагрузка сети) это проверять: иначе пары сдвинутся.
Столбец Б (паспорта сима): ошибка доворота `e` больше 15° — `PASS~` («ТОЧНОСТЬ сети», не FAIL), подачи 0° и 180° не
судятся; медиана `e` по ≥ 9 судимым дискам больше 10° по модулю — `ПРОГОН: FAIL сдвиг нуля или знак` (увеличивает FAIL на 1);
pick x против `458,2 − lateral_px/8,163265`: ≤ 1,0 мм PASS, (1,0; 2,0] `~`, > 2,0 FAIL `x`. Формула — гипотеза знака
`lateral_px`: при систематическом расхождении ≈ `2·lateral/8,163` проверить формулу, а не делать вывод о дефекте.

## Коды возврата

| код | значение |
|---|---|
| 0 | все PASS (допускается `PASS~`) |
| 1 | хотя бы один FAIL, включая ноль заданий при взятиях > 0 |
| 2 | ошибка аргументов, неполные регистры, число слов не совпало, `use_pitch=false` или слово с пробелом («не поддержано») |
| 3 | файл обмена, диска, регистров, паспортов или журнала сима не читается; файл обмена или диска пуст |

Тексты отказов кодов 2 и 3 идут в stderr без значений аргументов (путей, слов, чисел).

## Не покрыто независимо

Блок печатается в каждом отчёте: pick y и ecap (только окно α, расчёта нет); pick x против общих углов калибровки и
масштаба сим/рецепт (8,163 против 6,135 px/мм); rz против истины — только ±30° сети, сдвиг нуля до 10° не виден, знак не виден
на подачах 0°/180°; `angle_valid=False`; место укладки сим не проверяет.

## Известные границы

- Печатная сеть в журнале диска округлена до 0,1°: у ±180° доворот не различает сторону, поэтому `rz` принимается и со
  значением `rz − 360°`. Ячейка с буквой не из слова или повторная в заливке — `ячейка`.
- Время строк — наивные локальные метки; строки диска сортируются по времени (устойчиво), задания идут в порядке строк файла.
- `--sim-journal`: кольцо журнала сим-робота короткое; без сборщика с частым опросом часть заданий будет `сим не видел`.
