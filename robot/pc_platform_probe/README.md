# Проба платформы Delta SCARA (GATE-1)

Пара «программа на робота + скрипт на ПК», как `pc_robot_test/` и `pc_vfd_test/`. Отличие: эта пара
выясняет не «работает ли CVT», а **что умеет сам контроллер**. Протокол v2
([`plans/robot-protocol-v2/`](../../plans/robot-protocol-v2/plan.md)) опирается на эти факты. Задача —
**один раз залить `probe.lua` и за один визит снять всё**.

| Файл | Что это |
|---|---|
| `probe.lua` | программа для контроллера: ничего не делает сама, отвечает на тесты с ПК |
| `pc_probe.py` | ПК-сторона: прогоняет тесты, пишет отчёт с выводами |
| `dry_run.py` | сухой прогон без робота: `probe.lua` в Lua 5.1/5.4 (lupa) + локальный Modbus |
| `test_dry_run.py` | тесты пары на сухом прогоне (46 шт., обе версии Lua) |
| `reports/` | появляется после прогона: `report.json`, `report.md`, `globals.txt` |

## Что уже известно из мануала и что проба перепроверяет

Источник — `DELTA_IA-ROBOT_DRAStudio_RL_EN_20240920.pdf` (мануал языка RL, 2024; лежит в
`PROJECT_INNOTECH/knowledge-base/inbox/books/`). Мануал говорит, проба подтверждает на **этом** контроллере.

| Факт из мануала (страница) | Что это значит для v2 | Тест пробы |
|---|---|---|
| Пользовательский Modbus `0x1000..0x1FFF`; `0x3000..0x3FFF` **сохраняется при выключении** (12-2) | карта v2 в официальном диапазоне; параметры можно держать на роботе между перезапусками | адреса, `retain-write/check` |

| `ReadPoint` есть (5-9) | точку можно сверить перед ходом, не двигая робот | 13, 23 |
| Hand: 0 правая, 1 левая (5-3) | параметр руки v2 | 14 |
| Глобальные точки хранятся во внутренней памяти; локальные (1001..31000) — нет, но должны быть заведены в проекте (5-2, 5-5) | рабочие «скретч»-точки v2 — локальные, если их можно завести | 24 |

| `MotionStop` тормозит с текущим замедлением; для резкого стопа — поднять замедление (1-51) | «быстрый стоп» v2 | motion «стоп» |
| Встроенный мастер RS-485 `RSmasterRead/RSmasterWrite` (12-6) | мост к ПЧ без своего CRC и `SCM_FreePort` | 22 |

## Шаг 0 — дома, без робота (если DRAStudio стоит на ноутбуке)

В DRAStudio есть режим **Virtual Robot**: окно подключения → Ethernet → Virtual Robot → Connect
([FAQ Delta](https://www.deltaww.com/en-gb/FAQ/2336)). Исполняет ли он программу на Lua и открывает ли
Modbus TCP для внешнего ПК — неизвестно, это и проверить:

1. подключиться к Virtual Robot, загрузить `probe.lua`, запустить;
2. `python pc_probe.py --host 127.0.0.1 safe` (или адрес, который покажет DRAStudio).

Заработало — у нас официальный симулятор для прошивки v2, и тесты без движения можно гонять дома.
Не заработало — это тоже ответ, визит к роботу покроет всё.

## Визит к роботу

1. Проверь адрес в `pc_probe.py` (`ROBOT_IP`, `ROBOT_PORT`, `ROBOT_UNIT`) или передай `--host/--port/--unit`.
2. В DRAStudio загрузи `probe.lua` вместо рабочей программы и запусти. В консоли:
   `probe: СТОП ПЧ подтверждён` и `probe: готова, поза при старте прочитана …`.
   Если «СТОП ПЧ НЕ подтверждён» — проверь ленту глазами.
3. Освободи зону ±50 мм вокруг инструмента, включи серво: `python pc_probe.py servo on`.
4. **`python pc_probe.py all`** — всё за один запуск: сначала без движения (около минуты), затем спросит
   `yes` и выполнит тесты с движением. Отчёт — в `reports/<время>_all/`, пишется даже при обрыве.
5. По желанию — сохраняется ли `0x3000..`: `python pc_probe.py retain-write` → выключить и включить
   контроллер → снова запустить `probe.lua` → `python pc_probe.py retain-check`.
6. Руками, по документам (проба этого не знает):
   - **модель робота с шильдика** (DRS40L / DRS60L / DRS70L…) — по паспорту серии вылет 400/600/700 мм,
     ход Z 150–300 мм, J4 ±360°; от модели зависят параметры зоны `P_WS_*`;
   - мануал INVT GD20: номер параметра таймаута связи (группа P14) — сверить с тем, что прочитал тест 17;
   - в каком режиме настроен порт RS-485 в DRAStudio (свободный порт или Modbus-мастер) — если тест 22
     (`RSmasterRead`) не прошёл.
7. Верни рабочую программу. Папки `reports/` закоммить — это факты GATE-1, на них ссылается план.

Отдельные команды: `globals`, `call ИМЯ` (опасные имена — движение, серво, выходы, запись — запрещены),
`clock ИМЯ`, `vfdread 0x0E00 6`, `servo on|off`.

## Безопасность

Проверено ревью 2026-09-27 (вердикт первой итерации — BLOCK, все блокеры закрыты, каждый охраняется тестом
с доказанной инъекцией):

- при старте проба не двигается и серво не трогает; ПЧ получает СТОП с повтором и подтверждением;
- движение только после «якоря»; **каждая цель** — в пределах ±50 мм от якоря по X/Y/Z, скорость ≤ 30 %,
  `Override` из Mirror тоже ≤ 30 %;
- нет позы (геттер вернул nil) — нет движения;
- 4-я ось на ходу не пишется: точки объявлены со стартовой RZ, ушёл RZ больше чем на 1° — отказ;
  поворот делают только тесты оси (+5° и обратно);
- перед каждым ходом точка сверяется через `ReadPoint`: «принятая, но не записанная» координата — отказ;
- ПК проверяет возврат в исходную позу после каждого теста и прерывает набор при расхождении;
- стоп с ПК прерывает и одиночный ход, и PASS-цепочку;
- ПК пишет только в будущие адреса v2 и в сохраняемую область, каждый раз восстанавливая прежнее
  значение; остальные адреса только читает.

## Сухой прогон

```bash
uv run --no-project --with lupa --with pymodbus==3.15.0 python robot/pc_platform_probe/dry_run.py --lua 54
python robot/pc_platform_probe/pc_probe.py --host 127.0.0.1 --port 5020 all
```

Тесты пары (около трёх минут, обе версии Lua):

```bash
uv run --no-project --with lupa --with pymodbus==3.15.0 --with pytest \
    python -m pytest robot/pc_platform_probe -q -c /dev/null
```

`lupa` в зависимости проекта не входит, поэтому окружение временное (`--no-project`), `.venv` не
трогается. Зелёный сухой прогон доказывает **пару** (Lua-файл исполняется в 5.1 и 5.4, каждый тест
отвечает, ПК правильно разбирает ответы, защиты срабатывают), но **не платформу**: заглушки знают только
факты v1 и мануала. Флаги заглушки воспроизводят неудобные варианты контроллера — геттер позы отдаёт nil,
`WritePoint` принимает, но не пишет, блочная запись неатомарна.

Сухой прогон уже нашёл: `os.clock()` в Lua — **процессорное** время, во время `DELAY` оно стоит.
Сторожевой таймер на нём не сработал бы никогда. Часы v2 — `TimerRead` (мануал, 3-4).

## Язык

Точная версия Lua неизвестна (мануал: ≥ 5.2). `probe.lua` пишется только на том, что доказала рабочая
v1: `#`, `%`, `pcall`, `tostring`, `type`, `string.char/byte/sub`, `math.floor`, локальные функции,
таблицы. `pairs`, `table.sort`, `error`, `_G`, `ReadPoint`, `TimerOn` вызываются только после проверки
`type(...)` — иначе проба упала бы раньше, чем успела рассказать о платформе. Общее состояние Motion и
Mirror — в глобалах, как в v1. То же правило действует для прошивки v2 до получения отчёта.
