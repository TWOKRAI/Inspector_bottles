# backend/config — значения по умолчанию прототипа

> Сверено **2026-08-10**, коммит `b04a0c12`.
> Механику наблюдаемости описывает фреймворк:
> [`docs/observability/CONTROL_PANEL.md`](../../../multiprocess_framework/docs/observability/CONTROL_PANEL.md)
> (слои, команды, вердикт) и [`SINKS_MAP.md`](../../../multiprocess_framework/docs/observability/SINKS_MAP.md)
> (приёмники и хранилища). Здесь — **что и почему выбрало приложение**.

## Что здесь лежит

| Файл | Роль |
|---|---|
| `system.yaml` | значения по умолчанию для всех процессов и плагинов. **Слой L1** («что верно на этой машине при любом рецепте») |
| `user_overrides.yaml` | локальные правки поверх, не уезжающие в git |
| `schemas.py`, `manifest.py`, `displays_loader.py` | загрузка и валидация перечисленного |

**Топологию описывает не этот каталог.** `topology/*.json` и рецепты задают **структуру**
(процессы, плагины, провода); `system.yaml` — **значения**. Плагин в топологии может переопределить
любое поле отсюда.

## Граница «фреймворк / приложение»

Правило простое и было куплено дорого: **фреймворк владеет именами своих источников, приложение —
тем, где на диске лежат его файлы** (решение Р-2.6-Г). До Ф2.6 девять per-module файлов приезжали
из дефолта фреймворка и создавались в каталоге каждого процесса — **384 файла за прогон, непустых
четыре**.

Отсюда следует, что в `system.yaml` законно живут прикладные имена (`gui_file`, `trace_file`,
`busy_file`, группа `служебное`), а во фреймворке их быть не должно.

## Секция `observability` — что уже решено и почему

Читать её стоит вместе с комментариями в самом файле: там записаны замеры, а не намерения.

| Ключ | Значение | Почему так |
|---|---|---|
| `log_level` | `INFO` | корневой порог; адресные исключения — через `loggers` |
| `documents.factory` | `Services.documents.wiring:make_document_sink` | фреймворк знает отсюда только **строку**: правило слоёв запрещает ему импортировать `Services`. Пустая `factory` → плоскости нет |
| `documents.config.db_path` | `data/documents.db` | **не** в каталоге логов намеренно: у логов свой ретеншен, и документ, положенный рядом, однажды уедет вместе с ними |
| `documents.retention_sec` | `audit: 1 год`, `verdict: 10 лет` | род, которого здесь нет, уборка **не трогает никогда**: молчание конфига не разрешение потерять документ |
| `channels.busy_file` | служебная болтовня фреймворка | замер 2026-08-03: `command_manager` 17.4% + `dispatcher` 15.0% веса `system.log` у ProcessManager (28.9% + 27.6% у `region_splitter`) |
| `name_max_len: 20` у **каждого** канала | потолок длины имени источника в выводе | схема по умолчанию печатает имя целиком, прикладной канал настройку фреймворковых **не наследует**. Живой прогон 2026-08-04: `busy.log` печатал полное имя и это давало **+19.2%** к весу самого объёмного файла |
| `loggers.gui/trace` → `channels_extra` | «И свой файл, И унаследованный набор» | через `channels` (замещение) поведение изменилось бы молча: файл остался бы непустым, а из `system.log` записи исчезли |
| `loggers.служебное` → `channels` | замещение — увести совсем | иначе разгрузки не будет |
| `retention_days: 7`, `retention_total_mb: 200` | **включены** (дефолт фреймворка — 0/0, то есть выключено) | арифметика от замера: 5.4 МБ/час по восьми процессам ≈ 16 МБ/сут на процесс; 200 МБ ≈ двенадцать суток. Потолок задаётся **на каталог процесса**, а не на всё дерево |
| `stats.aggregation_interval: 10.0` | ровно 10.0, не 5.0 | здесь стояло 5.0 и **не действовало ни разу**: темп = `max(flush_interval, aggregation_interval)`, а пол по умолчанию 10.0. Хотите чаще — опускайте **пол**, не это число (B1) |

## Как правят наблюдаемость

| Намерение | Где править | Что происходит |
|---|---|---|
| «так должно быть всегда на этой машине» | `system.yaml` | слой **L1**; hot-reload watcher подхватывает файл |
| «так для этого конвейера» | рецепт / его спутник | слой **L2** |
| «кручу прямо сейчас» | `config.reload` с inline-секцией | слой **L3**, срок по умолчанию **300 с**, потом авто-возврат |
| «правка из L3 должна пережить рестарт» | `observability.persist` | ключи переезжают L3 → L2 |

**Чего правка `system.yaml` не сделает на лету:** секции `documents` и `history` сшиваются один раз
на старте процесса — новое значение вступит в силу со следующего запуска.

## Проверить, что правка подействовала

```
config_reload_verified(process="camera_0", observability={...})
```

`verdict=confirmed` означает «значение действует», `delivering=true` — «записи идут». Это разные
утверждения, и ни одно не выводится из другого. Опечатка в **имени** ключа схемой отбрасывается
молча и ловится вердиктом (`unknown_keys` → `failed`); мусор в **значении** отвергается на записи
в слой с адресом ключа и списком допустимых значений.
