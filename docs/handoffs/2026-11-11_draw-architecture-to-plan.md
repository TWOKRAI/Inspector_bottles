# Handoff 2026-11-11: универсальный рисовальщик и разметка → план

Сессия-лид, `main`. Следующий шаг — `/dev:plan` по этому файлу. Ничего не закоммичено (см. «Файлы»).

## Что решено

Архитектура — по двум отчётам CTO (Fable 5.2), раунд 2 главный:
- [`docs/reports/2026-11-11_draw-architecture-cto.md`](../reports/2026-11-11_draw-architecture-cto.md) — раунд 1: контракты, замеры, фазы 0–6.
- [`docs/reports/2026-11-11_draw-architecture-cto-r2.md`](../reports/2026-11-11_draw-architecture-cto-r2.md) — раунд 2: `labeling`, `layer_render` на `draw`, шрифты, шаблоны, `max_fps`, правки страницы.

Коротко: три модуля в `Services` с импортом сверху вниз — `draw` (нижний: сцена фигур → 5 примитивов → сменный бэкенд `render(canvas, ops)`; реестр шрифтов; экспорт YOLO/COCO), `layer_render` (строится на `draw`, пакет отдельный), новый малый `labeling` (пары «кадр + `.json`», сессия разметки, сортировщик). Один тонкий плагин `overlay_draw` (регистры `backend`, `burn`, `max_fps`, `mapping`, `styles`; выходы `frame`, `scene`) заменяет `circle_draw`, `contour_draw`, `render_overlay` и подпись `ml_inference` (те замораживаются, не удаляются). `ItemTemplate`/`get_path`/`RateGate` — в SDK плагинов framework, общие с DS-1. Первый и единственный бэкенд — cv2 + текст PIL-патчем; Rust/C++/GPU/Qt — только по замеру (Orin p95 > 5 мс/кадр после фазы 4).

## Решения владельца (2026-11-11)

1. `ml_inference` выдаёт только данные; рисует общий рисовальщик.
2. Один универсальный рисовальщик; реализация (библиотека) сменная — слой функционала отдельно от бэкенда.
3. Нужен сервис/функционал разметки (выделение объектов, контуры для обучения) — принят вариант CTO r2 §2.1.
4. RGB/BGR — не причина разделять; `layer_render` строится на `draw` (CTO r2 §2.2).
5. Шрифты подключаемые (реестр по имени + папка пользователя).
6. Общий помощник шаблонов полей — да.
7. Ограничение частоты — на ветку/плагин (`max_fps`), не глобально; правка `fps_limit` во framework — необязательная отдельная задача.
8. **Вопрос r2 №1 закрыт:** метки реального кадра — в `.json` рядом с кадром, то же имя, расширение `.json` (расширяет решение 2026-10-02 «регион в пресете» — для синтетики остаётся пресет).
9. План `layer-render` пересмотреть **позже**, с учётом этого плана (Ф7 шрифты, Ф9 регионы = фигуры `draw`, правка LR-001).

## Открыто (в план — как вопросы с умолчанием CTO)

- r2 №2: для класса кадра истина — папка, `.json` догоняет при `reconcile` (умолчание CTO: да).
- r2 №3: два файла DejaVu (~1,4 МБ) в репозитории — владелец спросил, что это; ответ дан в чате (свободный шрифт с кириллицей, лицензия разрешает распространение — не проверено); решение не принято.
- r2 №4: правка LR-001 при старте Ф7 — отложено до пересмотра плана `layer-render`.
- r2 №5: контуры (L2) после Ф5 `layer-render` или раньше — отложено туда же.

## Для `/dev:plan`

**Пожелание владельца по объёму:** план не раздувать — большая часть инструментов готова и протестирована; собирать из готового, а не писать заново. Что переиспользуется как есть:
- `overlay_draw` — разбор `overlay`, `color_table` (стили по фигуре/группе/типу), серый/BGR кадр, 26 тестов; `geometry.vline_segments` переезжает в ядро без изменений;
- `circle_draw` / `contour_draw` / `render_overlay` — их отрисовка становится правилами mapping, логика рисования переносится, не изобретается;
- текст PIL — `_put_text_unicode` из `ml_inference` (переделать на патч вместо полного кадра);
- `frame_saver` — атомарная запись `*.tmp` + `replace`, `write_sidecar`;
- `ml_train.FolderDataset` — уже читает папки-классы; `Services/ml_inference/backends` и `camera_service/backends` — образец реестра бэкендов;
- GUI: регистры `list[dict]` уже правятся JSON-редактором.

Первый план — только ядро пути показа (фазы 0–3, при желании 4). `labeling`, сортировщик, экспорт и контуры — следующими фазами или отдельным планом после DS-1 и пересмотра `layer-render`.

- Slug (предложение): `draw-universal`, план — `plans/draw-universal/plan.md` (многофазный), ветка `feat/draw-universal`.
- Фазы (CTO r1 §5 + r2 §3): 0 база-замеры стенда → 1 ядро `Services/draw` (сцена, lower, cv2, текст-патч, реестр шрифтов, conformance, адаптер `overlay`) + `ItemTemplate`/`get_path`/`RateGate` в SDK → 2 mapping/styles/`burn`/`max_fps`, замена `circle_draw`/`contour_draw`, опись остальных мест рисования → 3 чистый кадр (`ml_inference` не рисует, ветка `recog_draw`) → 4 `render_overlay` → правила, топологии `inspection_basic/full` → 5a пары `labeling` + `frame_saver` (вместе с DS-1) → 5b сортировщик → 5c экспорт → L2/L3 контуры (после пересмотра `layer-render`) → 6 второй бэкенд по замеру.
- Соседи (правило «новый план — среди соседей»): DS-1 (`plans/queue/backlog.md`, «Кандидат 2026-11-11 … DS-1») — фазы 5a/5b делят `frame_saver` и `ItemTemplate`; `plans/layer-render/plan.md` (Ф7, Ф9, LR-001) — таблица владения и обратные ссылки.
- Найденные баги `frame_saver` (из разбора DS-1, ещё не заведены): имена по `frame_id` перезаписывают fan-out и прошлые запуски; `_cleanup_tmp` удаляет чужие `.tmp`; счётчик по скану папки гоняется между процессами; картинка без `.json` при сбое/без `sidecar`; retention удалит датасет при раскладке `<дата>/<класс>`.
- Поправки к прежним утверждениям лида (проверены по коду): регистры `list[dict]` уже есть (`overlay_draw.color_table`, GUI — JSON-редактор); SHM возит любой числовой ndarray верхнего уровня ndim 2–3 от 8192 байт; `render_overlay` живой в `backend/topology/inspection_basic.yaml`/`inspection_full.yaml` (дисплей на `rendered_frame`); `fps_limit` дисплея никто не исполняет (по grep).
