## Два места, где гейт упрётся — знать до старта, а не в процессе

**1. Пункт 2 программы гейта («закрытое окно = ноль телеметрийного трафика уровней») в текущей
конфигурации НЕ проходит, и это не регресс.** Опрос (`introspect.telemetry -> levels`) отдаёт
**3 ключа из 11**: `status`, `pid`, `frame_count`, `error`, `uptime`, `drops`, `paused`, `frozen`
пишут другие публикаторы и опросом не приходят. Погасив push, оператор потеряет эти ключи —
поэтому флип дефолта (РТ-2) заблокирован до Task 3.5, а не «ждёт решения». До флипа Ф3 трафик
**добавляет** (+2 запроса/с поверх фона 20.5 дельт/с), а не снимает.

**2. Пункт 6 («приёмники не пухнут, фон ≤ ~2 МиБ/ч на 8 процессов») зависит от режима отбора
широких записей.** Дефолт `observability.events = {first_n: 0, every_mth: 0}` укладывается
тривиально (пишутся только фронты вердикта). Названный в 4.1 режим `every_mth=9` при 21.3 ед/с
даёт **3.88 МиБ/ч — вдвое выше ориентира**. Гейт гонять на дефолте и сказать это вслух; расчёт
«не чаще ~1/18» записан в `CONTROL_PANEL.md` рядом с ручкой.

## Что нового в системе после Ф4–Ф5 (что гейту трогать)

- `ctx.write_event(kind, summary, /, *, unit, decisive, **fields)` — широкая запись о единице
  работы, носитель существующий (`log_info`, scope BUSINESS). Ручки `observability.events.*`.
  `trace_id` едет в ТЕКСТЕ сообщения (FTS5 не смотрит в `extra`) — по нему запись и ищется.
- `ctx.flight_dump(reason, /, **fields)` — дамп кольца записей процесса в
  `<база логов>/<процесс>/flight/<ts>_<reason>.jsonl`. Ручки `observability.flight.{enabled,
  sink, keep, limit}`, дефолт **выключен**. Кольцо — memory-канал логгера, объявляется рецептом.
- Обе плоскости видны в `introspect.observability` (секции `events` и `flight`) и подтверждаются
  `config_reload_verified`.

## Живые числа, снятые на стенде `inspection_full` (можно опереться, можно перепроверить)

- 8 процессов, `inspector` 21.4 Гц;
- **1107 кадров брака → 1 фронт → 1 дамп**; в дампе широкая запись той же единицы, `trace_id`
  совпал с шапкой манифеста;
- `keep=3` при 7 фронтах → вытеснено 4, на диске 3, 4 голоса INFO;
- выключенный рекордер: 3 фронта → 0 файлов, `refused_disabled=3`, голос один раз с адресом ручки;
- `config_reload_verified` по `flight.*` → **confirmed, checked 4/4**.

**Ловушка стенда:** камера-симулятор рисует красный прямоугольник каждый кадр, но детектор на
дефолтных порогах отдаёт **ноль детекций** — фронта брака не будет сам собой. Фронт получают
расширением порогов `blob_detector` через регистры (`s_min`/`v_min` → 0, `max_area` → 0). Запись
в 4.1 «детектор не находит контуров даже при `min_area=1`» **неточна**: порог площади ни при чём,
отсекал HSV-гейт.
