### Как `run.py` находит рецепт (из кода, подтверждено запуском)

- `multiprocess_prototype/run.py <аргумент>` -> `main.main(<аргумент>)` (`main.py:176-180`); `frontend/run.py <аргумент>` делает то же с окном (`frontend/run.py:81-86`).
- `_resolve_pipeline` (`backend/launch.py`): если аргумент абсолютный, или с суффиксом (`.yaml`), или с `/` либо `\` — это путь как есть; голое имя -> `<recipes каталога манифеста>/<имя>.yaml` (`multiprocess_prototype/recipes/`).
- Следствие для чек-листа §9 вопрос 1 («как запускать рецепт из `data/mvs_stand/`»): `run.py /абсолютный/путь/hikvision_capture.yaml` работает (проверено на рецепте из scratchpad). Класс-имена плагинов — те же, что в обычных рецептах.
- Побочный эффект: `run.py <рецепт>` записывает рецепт в `multiprocess_prototype/app.state.yaml` (в `.gitignore`, `*.state.yaml`). После репетиции файл остаётся указывающим на scratchpad-рецепт; я его удалил (`rm`), иначе следующий запуск без аргумента искал бы несуществующий файл. В боевой копии после такого запуска проверить, что `app.state.yaml` указывает на нужный рецепт.

## 3. Что реально отличается от предположений чек-листа §4

1. **Имена команд и регистра** — как в чек-листе: процесс `saver`, регистр `frame_saver`, команды `save_now`, `get_stats`. Сверка по `introspect_*` выполнена (на синтетике, не на камере).
2. **Счётчик кадров.** Для рецепта репетиции: `get_stats` у `saver` -> `total_frames` (рос с частотой источника, 24,92 Гц); частота процессов — `system_overview` (`camera_0` `hz` 24,98, `color_convert` 25,03, 1-й прогон) и `state.get_subtree processes.camera_0` -> `state.fps` 25.0; номер последнего кадра — `processes.camera_0.plugins.synthetic_frame_source.io_peek.output.items[0].seq_id` и `processes.saver.plugins.frame_saver.io_peek.input.items[0].seq_id`. Для `Services.hikvision_camera` путь счётчика циклов остаётся неизвестным (чек-лист §3 п.3) — на камере искать через `state.get_subtree processes.camera_0`; ключ `io_peek` зависит от плагина.
3. **Индекс «сквозной внутри префикса» — неверно.** Индекс один на каталог, не на префикс: смена `filename_prefix` в том же каталоге счётчик не обнуляет (`a045_000011` -> `a090_000012`, п. 13). Пересканирование по диску делается только при смене каталога, по префиксу, действующему в момент первой записи в новый каталог (`plugin.py`, `_resolve_dir`: `if d != self._cur_dir: … _scan_last_index`), п. 14–15. Для схемы `<БУКВА>/a<УГОЛ>_<индекс>` это значит: индекс внутри ячейки не начинается с 000001, если в том же каталоге до этого писался другой угол (после `a045` идёт `a090_000012`). `day1_capture_check.py` это переносит (регэксп `^a(\d{3})_(\d+)$`, п. 19–21); для анализа важно, что номер не равен «числу кадров ячейки».
4. **Смена каталога/префикса на ходу работает без перезапуска**, `set_register_verified` возвращает `verified: true`. Кадры не «протекают» в старый каталог в режиме `trigger`: буфер хранится в памяти, пишется в каталог, действующий в момент `save_now`.
5. **`chain_targets` обязателен, провод один не доставляет.** Вариант рецепта с `chain_targets: [gui]` и проводом `color_convert -> saver` (без `saver` в `chain_targets`): за 5 с `total_frames` 0 -> 0, `pending 0`, `save_now` -> `saved 0`, каталог не создан (2-й запуск). Вариант §4.3 (оба: `chain_targets: [gui, saver]` + провод) даёт 24,92 Гц без удвоения. Значит п.1 из §4.3 («в `color_convert`: `chain_targets: [gui, saver]`») не опционален.
6. **Порядок каналов (синтетика).** Штамп источника в канале 0 после `bgr2rgb` лежит в файле в канале R, ровно как ожидает схема «камера старого пути отдаёт RGB -> `color_convert` -> BGR -> `cv2.imencode`». Это проверка кода `frame_saver`/`color_convert`, не камеры.
7. **Два `save_now` подряд.** Ответ `saved` может быть меньше `buffer_size` (3 и 2 без паузы): буфер очищается при сбросе. Для процедуры §4.4 («дождаться перекладки диска») это штатно, но оператору проверять `saved` в ответе, а не `saved_count` как «+3».
8. **Каталог создаётся при первом сохранении**, а не при `set_register`; `get_stats.output_dir` до этого показывает прежний каталог (по коду: `self._cur_dir or output_dir`; на живом после смены, но до `save_now`, отдельно не замерено).
9. `buffer_size` читается только в `configure()` (по коду, `plugin.py:151`); на живом не менялся.

## 6. Что осталось открытым / ненадёжно

- **Прогон на синтетике, не на камере.** Ничего про `Services.hikvision_camera`, MVS, Windows, порядок каналов реальной камеры, дебайер, цвет, резкость настоящих кадров — не проверено. Единственная проверка каналов — штамп синтетического кадра (разд. 3 п. 6).
- **Единичный прогон.** Каждый сценарий (п. 8–15) выполнен один раз; повторов и разброса нет. Частота 24,92 Гц измерена одним окном 5,02 с (не 10 с, как в критерии §5); `pending=3` на момент замера.
- **Содержимое кадров почти плоское** (серый 128, штамп в 1 строке): PNG 23 816 байт, резкость 6,7. Размеры файлов камеры 1624x1240 (оценка места на диск для ~240 кадров), время записи кадра и нагрузка на диск **не измерены**.
- **Пороги `day1_capture_check.py`** (100 / 60…230 / 0,10) по-прежнему предложения из чек-листа; прогон показал только, что скрипт читает имена `frame_saver` и считает ячейки, пороги на синтетике не калибруются (п. 19–21).
- **`backend_ctl` через Python-драйвер, а не MCP-инструменты.** MCP-сервер `backend-ctl` этой сессии смотрит на другой порт; соответствие инструментов — разд. 2. Типизированное поле `Capabilities.processes` пусто, работает `raw` (п. 2) — не расследовано, в `defects.md` не искал отдельно.
- **Выход стенда по `kill <pid PM>`:** на stderr оба раза `resource_tracker: There appear to be 332 leaked semaphore objects` и `16 leaked shared_memory objects`; ERROR-записей `[ERROR]` в логах 0, WARNING в stdout 9 (метрика heartbeat/телеметрия, `devices.yaml` по прежнему пути, `documents.db`, неприёмники). В `plans/queue/defects.md` нашёл только C-93 (утечка SemLock в тестах PM на macOS, другой вход); утечки при остановке стенда `kill` там нет. Остановка штатной командой `system_shutdown` не пробовалась. **Занести в `defects.md` — решение лида.**
- **Побочные следы в worktree** (все в `.gitignore`, `git status --short` пуст): `data/documents.db` (создан стендом), `.claude/logs/`, `multiprocess_prototype/app.yaml.lock`; `app.state.yaml` я удалил. Был ли `app.state.yaml` до прогона — не помню точно (в worktree только что созданном обычно нет).
- **`get_stats.output_dir` после смены каталога до первой записи** — вывод из кода, на живом отдельно не снимал (разд. 3 п. 8).
- **Не запускал**: `pytest Plugins/io/frame_saver/tests` (чек-лист: 53 passed на 2026-11-15, повторно не гонял), `camera_device_demo` (серый 4x2), `letter_robot_sim`/`line_sim`, режим `stream`, `jpeg`, `write_sidecar` (кадры камеры его не несут, §4.1), смена `buffer_size` на ходу, длительный прогон, заполнение диска.
