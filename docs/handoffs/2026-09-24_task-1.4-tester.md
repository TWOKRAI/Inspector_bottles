## Root cause (confirmed by reading, NOT by running — a live repro is still owed)

Read: `multiprocess_framework/modules/process_manager_module/launcher/spawner.py`,
`.../launcher/process_tree_guard.py`, `.../core/process_registry.py` (`stop_one`/`stop_many`/
`stop_all`), `.../process/process_manager_process.py::shutdown()`, `.../launcher/system_launcher.py`,
`.../runner/process_runner.py` (`_run_lifecycle`), `backend_ctl/harness.py`
(`BackendHarness.start/stop`, `_subtree`, `_force_kill_tree`, `_shutdown_with_watchdog`).

**Two independent bugs compound:**

1. **Nested timeout inversion.** PM's own inner escalation for a hung child, WITH DEFAULTS,
   is a LITERAL `5.0 (graceful join) + 1.0 (join after terminate) + 1.0 (join after kill) = 7.0s`
   (confirmed: `process_registry.py` `stop_one`/`_stop_many` — `timeout=5.0` default param,
   `process.join(timeout=1.0)` after terminate, `process.join(timeout=1.0)` after kill;
   `process_manager_process.py::shutdown()` — `shutdown_timeout = self.get_config("shutdown_timeout")
   or 5.0`). The OUTER wait — `ProcessSpawner.stop()`'s `self._process.join(timeout=effective_timeout)`
   — defaults to `stop_timeout=5.0` too (`ProcessSpawner.__init__` default, and
   `SystemLauncher.__init__` default, both `5.0`). **5.0 < 7.0**: at t=5.0s the spawner sees the PM
   still alive (busy inside its own `stop_all()`), logs "did not stop", and calls
   `self._process.terminate()` — SIGTERM to the PM's OS process. **The PM installs NO signal
   handler for SIGTERM/SIGINT anywhere** (grepped `process_manager_process.py`,
   `process_module/core/process_module.py`, `runner/process_runner.py` — zero `signal.signal`
   calls other than the hung child's own SIG_IGN and the spawner's OWN handler in the PARENT
   process). Default Python action for SIGTERM = immediate process death, interrupting the PM
   mid-`stop_all()` — before it reaches `child.kill()` for the hung child. **This is the exact
   mechanism of the live incident** (SIGINT to main pid → 4 orphans, PPID 1, ~8.5h).

2. **`ProcessTreeGuard._terminate_posix_group()` treats "leader pid already reaped" as
   "group already gone".** `os.getpgid(self._pm_pid)` raises `ProcessLookupError` once the PM's
   own OS pid has been reaped (which it has, by the time `guard.kill_tree()` runs — the
   spawner's own `self._process.join()`/`.terminate()`/`.kill()` sequence already reaped it).
   The code catches `ProcessLookupError` and returns `True` ("killed" — WRONG, nothing was
   signalled), so `kill_tree()`'s `if not killed: self._kill_via_psutil(fallback_procs)` is
   **skipped even though a correct `fallback_procs` snapshot was passed in**. The fix should
   call `os.killpg(pgid, sig)` using the PM's pid AS the pgid directly (POSIX: pgid == session
   leader pid == PM's original pid, by construction — `setsid()` is called BY the PM at spawn),
   never re-resolving it via `os.getpgid(pid)` which needs a LIVE process at that exact pid.
   This is the same bug in both call sites: `spawner.stop()`'s own `guard.kill_tree(...)` at the
   end of `stop()`, AND (if a test constructs the scenario directly) `ProcessTreeGuard` used
   standalone.

3. **`BackendHarness` compounds it a third way**: `self._descendants = _subtree(self._orch_pid)`
   in `start()` is captured **immediately after `self._launcher.start()` returns** — i.e. right
   after the PM OS process is spawned, but BEFORE the PM's own `initialize()` has had time to
   spawn ANY of its children (spawning children is part of what PM's `initialize()` does, and
   `start()` does not wait for it — only `wait_until_ready()` does). So `self._descendants` is,
   in practice, **always PM-only**, never includes real children. On `stop()`,
   `_force_kill_tree` unions this stale snapshot with `_subtree(orchestrator_pid)` computed
   fresh — but if the PM is already dead by then (either bug 1's SIGTERM-death, or a test's
   deliberate `SIGKILL(pm_pid)`), `_subtree` returns `[]` (`psutil.Process(dead_pid)` raises
   `NoSuchProcess`, caught). Net: orphaned children are invisible to the harness's own
   cleanup net.

  import sys, time, threading
  from multiprocess_framework.modules.process_manager_module.launcher.spawner import ProcessSpawner
  from multiprocess_framework.modules.process_manager_module.tests._no_orphans_helpers import (
      HUNG_CHILD_CLASS_PATH, snapshot_children,
  )

  spawner = ProcessSpawner(processes_config={"hung": {"class": HUNG_CHILD_CLASS_PATH}}, stop_timeout=5.0)
  spawner.launch_orchestrator()
  proc = spawner.get_process()
  time.sleep(2.0)  # let PM's initialize() spawn the hung child
  children = snapshot_children(proc.pid)
  print(children[0].pid if children else -1, flush=True)

  done = threading.Event()
  _orig_stop = spawner.stop
  def _stop(*a, **kw):
      try:
          _orig_stop(*a, **kw)
      finally:
          done.set()
  spawner.stop = _stop  # _signal_handler calls self.stop() — instance attr shadows the class method

  done.wait()
  sys.exit(0)
