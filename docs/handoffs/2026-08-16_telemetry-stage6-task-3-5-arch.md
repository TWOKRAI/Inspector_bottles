## Ловушки, стоившие времени здесь

- **`telemetry_set` отдаёт `verified_effect: true`, когда секции `telemetry.publish` у процесса
  ещё нет.** Я объявил первый прогон доказательством, имея зелёный readback; контроль
  (`latency_ms`, `shm`) продолжал течь вместе с `fps`, и вывод устоял только после того, как
  контроль дал ноль. Гейт считается закрытым по `gate_active: true` + `resolved`, не по ответу
  ручки.
- **Вырезка листа троттлом молчалива:** `proceed=True`, `rejection_reason` отсутствует. Потерю не
  видит даже отправитель. Любой замер «значение не доехало» без этого знания уводит в камеру.
- **`git add plans/`** затягивает чужой untracked `plans/line-sim/`. Добавлять пофайлово.
- **pre-commit стеш конфликтует с автоправкой session-log** — коммит откатывается целиком.
  Лечится повторным коммитом вместе с `docs/sessions/<дата>.md`.
- Стенд поднимается `BACKEND_CTL=1 INSPECTOR_GUI_UNATTENDED=1 QT_QPA_PLATFORM=offscreen
  .venv/Scripts/python.exe multiprocess_prototype/frontend/run.py`. Перед подъёмом проверять
  `capabilities` — два бэкенда конфликтуют за PID-реестр и SHM.
- Ревьюер оставил на стенде секцию `telemetry.publish` у `camera_0` (`frame_count: enabled=true`,
  семантически no-op) и трогал правило троттла `processes.**.state.fps` (вернул 0.05).

## Поручение владельца, ещё не исполненное

**W-1 в `plans/QUEUE.md`** — после закрытия 3.5 прогнать сквозной поиск того же класса по всему
дереву (`processes.**`, `system.**`, `devices.**`, `cameras.**`, `recipes.**`): где ещё в один лист
пишут двумя дорогами. Два случая уже известны (`state.fps`, `state.status`). Детектор назван:
у стора уже есть `source` на каждой записи, поэтому дженерик-детектор «второй источник на том же
листе» с голосом один раз на пару (путь, источник) делает класс наблюдаемым без прикладных имён.
