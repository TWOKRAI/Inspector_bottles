## Решения реализации (выведены из чтения; DESIGN не меняют)

1. `process/pre_stop.py`: pydantic `PreStopStep` (`extra="forbid"`, `frozen`).
   - Поля: `process`, `command` — `str` strict, `min_length=1`; `args: dict[str, Any]` (по умолчанию `default_factory=dict`); `timeout_s: float` с `strict=True, gt=0, le=60, allow_inf_nan=False`.
   - ПРОВЕРИТЬ запуском: strict float принимает `int`, но отвергает `bool` и `"5"`.
   - Текст ошибки: `pre_stop[i]: <loc[0], если поле известно, иначе «поле»> — <msg>`. Для `extra_forbidden` — `поле — неизвестный ключ`. Все ошибки записи — в ОДНУ строку через `; `: REDS 7 ждёт ровно одну ERROR на запись.
   - Сумма Σ — по принятым записям, граница 120 включительно (с допуском 1e-9).
2. Состояние PM. Атрибуты уровня класса: `_pre_stop_steps = ()`, `_pre_stop_executor = None`, `_pre_stop_cancel_reason = None`. Флаг отмены — ленивое свойство `self.__dict__.setdefault("_pre_stop_cancel_obj", threading.Event())`, как `_system_stop_lock` (нужно для h4).
   - `_setup_pre_stop()` зовётся в `initialize` сразу после `_setup_lifecycle_executor()`. Порядок: parse, затем ERROR на каждую ошибку. Если шаги есть и `executor_manager` есть — `manager.create("pm-pre-stop", {"kind": "keyed", "serial": True, "max_pending": 1}, should_reject=lambda: self._pre_stop_cancel_source() is not None)`; `ValueError` → ERROR, шагов нет. Если менеджера нет — ERROR `pre_stop: исполнитель недоступен — шаги отключены`.
3. `_pre_stop_cancel_source() -> "force" | "event" | None`: сначала флаг отмены (force), затем `_system_stop_event.is_set()`. Путь force взводит флаг ДО событий.
4. Шаг (на потоке `pm-pre-stop`):
   - Сначала реестр (`процесс не найден`). Затем готовность: `_child_ready_event`, `ev.wait(≤0,05)` по срезам (`ребёнок не готов`).
   - Затем `request_async(build_command_message(...), on_response, timeout=остаток)`.
   - Колбэк: если шаг закрыт — no-op. Иначе кладёт ответ и `threading.get_ident()` в box, затем `Event.set()`.
   - Синхронный отказ отправки = колбэк вызван на потоке шага (ident совпал) → `ошибка отправки`.
   - Конверт подметания `{"success": False, "error": "timeout"}` без `type` → `timeout`. `success is True` → выполнен; иначе `ошибка ответа`. Исключение → `исключение <Класс>`.
   - `self._set_pre_stop_step(label)` — ПОЗИЦИОННО и вне try шага: REDS 2, шаг 7 подменяет метод на экземпляре.
5. Поток шагов: `try: for ...` / `except Exception: ERROR "pre_stop: поток шагов — исключение <Класс>"` / `finally: self._finish_pre_stop()`.
   - `_finish_pre_stop` = `_leave_pre_stop()` + `_system_stop_event.set()` + `stop_event.set()` + `_publish_system_stop()`. Идемпотентен.
   - `reply` у `submit`: если action не стартовал (отказ `system_stopping`) — тоже `_finish_pre_stop()`.
6. `_leave_pre_stop()`: бюджет читается до лока. Под `_system_stop_lock`, только при `phase == "pre_stop"`: `phase = "children"`, `pre_stop_step = None`; при `graceful` — `deadline_at = time.time() + pm_graceful_s`. Возвращает `bool`.
   - ДОБАВЛЕНИЕ (лиду сообщено): `_set_system_stop_phase` при выходе из `"pre_stop"` делает то же самое. Причина: при внешнем событии `_ChildrenStop.request_stop` (:4986) сам ставит `children` → `pre_stop_step` остался бы не None (REDS 3(б)). Записать в ADR-044.
7. `_begin_system_stop(..., phase="pre_stop", window_s=Σ)`: новый keyword `window_s` задаёт `deadline_at` фазы `pre_stop`.
8. `_cmd_system_shutdown`:
   - `graceful` (запрошенный): `with_steps = bool(steps) and executor and not self._pm_stopping()`. Если `_begin_system_stop` вернул False → ранний `return {"success": True, "accepted": False, "reason": "already_stopping", "phase": <снимок>}`. Иначе `reply` + `accepted: True, mode: "graceful", phase`. При шагах — `submit(action, frozenset({"system"}), reply_cb)`, publish, return БЕЗ событий.
   - `force`: шаги никогда (и в fallback без `_children_stop`).
     - Свежий: `accepted True, phase "children"`.
     - Поверх graceful (`set_force_deadline` True, `begin` False): `_escalate_system_stop` → флаг отмены (reason force) → `_leave_pre_stop()` → события → `accepted True, escalated True, phase "children"`.
     - Повтор force (`already_set`): + `accepted False, reason "already_stopping"`.
     - Fallback без `_children_stop`: `mode "graceful"` + `accepted True, phase "children"`.
   - `pm-lifecycle`: `should_reject=self._lifecycle_rejected` = `_pm_stopping() or phase == "pre_stop"`.
9. Драйвер: сигнатура `wait_timeout: float | None = None, pm_name="ProcessManager"`. Только `time.monotonic/time/sleep` через модуль `time` (DR подменяет `driver_mod.time`).
   - Опрос: `_leaf_result(self.supervision_status(pm_name=pm_name, timeout=...))`. Без `processes` или `success False` — пропуск такта.
   - Порядок в такте: снимок → проверка «у всех итог» / `done` → только потом `connection_lost`. Иначе DR (а) съест чтения счётчика.
   - Срок: 20,0 до первого снимка с `system_stop`; затем `max(20, deadline_at − time.time() + 12)` от момента этого снимка.
   - После конца по итогам/`done` — ожидание сокета `min(остаток, 3,0)`. `BackendUnavailable`/`connection_lost` → `pm_gone True`.
   - `outcomes` — объединение последних не-null по детям (без `pm_name`); `unconfirmed` — по алфавиту.
   - Стражи `test_system_shutdown_driver.py`: в фикстуру `_driver` добавить подмену `supervision_status` (конверт с `result`, снимок без итогов), поправить docstring, `outcomes` и :119.
