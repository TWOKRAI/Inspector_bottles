## Контракт 1.4, на который опирается 2.1 (из переписанной `tasks/1.4.md`)

- `system.shutdown`: аргумента `initiator` нет (инициатор — `sender` конверта, 1.2a). Ответ: `{"success": True, "message": "Shutdown initiated", "accepted": True, "mode", "phase": "pre_stop"|"children"}`;
  повтор `graceful` → `{"success": True, "accepted": False, "reason": "already_stopping", "phase"}` (события не взводятся); `force` поверх `graceful` → `accepted: True, escalated: True`, шаг прерывается.
- `system_stop`: `phase` `pre_stop` → `children` → `last_wave` → `done`; `deadline_at` (`time.time()`): в `pre_stop` = `started_at + Σ timeout_s`, на переходе в `children` = `time.time() + pm_graceful_s` (5,0),
  `force` = момент команды + `deadline_s`; `pre_stop_step` = `"<process>.<command>"` или `null`; `initiator` ∈ {имя отправителя, `event`, `unknown`} (`parent_death` нет).
- В фазе `pre_stop` `process.stop`/`restart`/`topology.apply` получают отказ `system_stopping`. Внешний взвод `system_stop_event` прерывает шаг.
- «Все остановлены» = у каждого ребёнка `stop_outcome` ∈ {`exited`, `terminated`, `killed`} (ADR-PMM-042); `survived`/`handed_over` — жив; после `done` `null` = «не подтверждено».
- Драйвер `system_shutdown` отдаёт `outcomes`, `unconfirmed`, `timed_out` — GUI его не использует, но подписи итога должны совпадать по смыслу.
- Вариант А Task 1.3 (ADR-PMM-043): `last` сигналят на `D − last_wave_s` (= 5,0 с) или раньше; у ребёнка с окном `g` `stop_deadline_at` (5,0) совпадает с сигналом `gui`.
