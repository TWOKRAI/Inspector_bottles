## Что оставил открытым / ненадёжно
Ключи и формы, которых в DESIGN 1–5 нет и которые я зафиксировал минимально (лид проверяет контракт до слепого tester; любой пункт — вопрос, не решение):
- `purpose.called_from` — список из 0/1 записи `{qualname, text}` и `purpose.called_from_more` (int). DESIGN 4 даёт только текстовую форму «зовут из: <qualname> - <абзац>; ещё M».
- `purpose.text == ""`, когда докстринги нет (не `null`); `status.doc_missing` — bool от него.
- `interface.signature` и `members[].signature`: хвост строки `reference._sig` после имени (`(key: str) -> None`); у `property` — `-> T`. Формат записи члена `{name, signature, where}` из DESIGN 1, но «signature без имени» — мой выбор.
- `links.structural`: словарь `{required, twins, note}` / `null`; `links.call_sites_unresolved` — в `links` (источник — `Links.of`).
- `runtime.threads` запись `{pattern, daemon, where}`; `runtime.io` запись `{op, path, where}`; `runtime.commands` запись `{name, where, how: "declared"}` (поле `form` из `scan` в паспорт не идёт).
- Область `runtime.commands` («область - юнит» в DESIGN 5) — самый неясный пункт: я записал «символ-класс или функция, чьё тело содержит `def command_specs`». Если область — файл или юнит слоя, контракт и RED меняются.
- Порядок «форм» в тексте связей (`import`, `name-call`, `same-file`, `test-body`) — по порядку упоминания в `links.py`; DESIGN говорит «его порядок», не называя его.
- Расположение образцов внутри раздела `links` в тексте (подзаголовки по `used_by`/`call_sites`/...) не зафиксировано — RED утверждает только литералы образцов. Склейка «найдено N (...); не видно: ...» и «из продукта A, из тестов B» в одну строку или две — не сказана.
- `exclude`: префиксы путей от `root` в posix; правило совпадения (`равен` или `начинается с`) я не фиксировал дальше слова «префикс».
- `build_passport` бросает `AtlasError` на неизвестный `ident` (текст не фиксирован).
- `passport.py` не получает `con`: `build_passport`/`passports_for` берут только `root`, `ref`. Кэш фактов (`scan_cache` в `data/atlas.sqlite`) придётся открывать внутри или сканировать без кэша — для гейта «тёплый ref ≤ 2,0 с» (ACCEPTANCE 4.2a) это решение GREEN.
- Тип ошибки `render_text` при неизвестном `show_all` (`ValueError`) — мой выбор; CLI проверяет раньше.
- Тестов под контракт нет (RED пишет слепой tester). Импорт модуля и существующие тесты — единственная проверка этой стадии.
- Пользователь `id <номер>` в stderr — 1-based; DESIGN не уточняет.
