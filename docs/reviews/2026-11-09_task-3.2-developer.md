## Что я истолковал, а не выполнил буквально

- `ceiling`: вопросы без `expected` (только факты) не считаются в N (как `scored` в `score_run`), хотя бриф говорит лишь «`scored: true`». Для k0 N=8 (Q1-Q7, Q10), совпало с приёмкой.
- Для записи `line: null` в отчёте `ceiling` печатается `  <путь> -> нет в эталоне` без `:line ±tol` (формат брифа для этого случая не задан).
- `note`-правила: берётся первое совпадение каждого из двух шаблонов (`tolerance N` и `anchor line N`); если в note несколько чисел, проверяется только первое.
  Если в записи вопроса нет ни одной ненулевой `line`, в сообщении о якоре печатается `line null`.
- Правило в: одна строка на пару «вопрос - exclude», путь называется первый совпавший по порядку `expected`. `exclude` — как пути `git show`; каталоги
  в `exclude` на реальном git дают непустой вывод `git show` (листинг дерева), но он не равен тексту файла, так что не срабатывает.
- Правило г: «ближайшая» функция — самая вложенная (наибольший `lineno` среди охватывающих `lineno < line <= end_lineno`).
- `files_hit` не режет адреса агента до потолка `len(expected)+1` (в отличие от `classify`): считает все названные пути.
