## Находки

1. **[major, ADVISORY — luacheck на машине нет]** `build_fw.py:121/134`: luacheck зовётся `[exe, <root>/robot/v2/src]`
   без cwd и `--config`; в `src/00_header.lua:3` — `FW_BUILD = @@FW_BUILD@@`, не Lua (`@` не токен Lua). `.luacheckrc`
   нет, хотя tasks.md:159 его требует. Как только luacheck появится (CI) — build и `--check` всегда 1. Варианты:
   luacheck по собранному артефакту или валидный Lua в заглушке.
2. **[minor]** `:54/85` BOM: в `20_body.lua` EF BB BF попадает в середину артефакта (байт 132), `--check` молчит;
   в `10_generated.lua` — «нет строки-заглушки» без причины.
3. **[minor]** `:91/97` остатки токенов: `@@FW_BUILD@@` в `20_body.lua` молча остаётся; `-- @@GENERATED@@` дважды →
   два блока (`REG count = 2`). Фикс: после сборки `"@@"` в выводе нет.
4. **[minor]** `:51` регистр glob: на win32 `20_UP.LUA` попадает, с `case_sensitive=True` (Linux) — нет → на Windows
   свежий, в Linux-CI устаревший. Фикс: `glob(..., case_sensitive=True)`.
5. **[minor, в рамках «одного grep» плана]** `:68` 80_mirror: пропускает `print("--") while true do end`,
   `--[[ note ]] DELAY(5)`, `WAIT (3)`, `DELAY"5"`; ложное срабатывание на многострочном `--[[ … while … ]]` и
   `s = [[\nwhile\n]]`.
6. **[tests]** argv luacheck не закреплён: мутации `[exe, str(src_dir)]`→`[exe]` и `_luacheck(root / ARTIFACT_REL)`
   → `9 passed`. Контроль мутационного плагина: снятие маски 0x7FFF валит ровно 3 предсказанных.
7. **[nit]** мимо BuildError: cp1251-исходник → `UnicodeDecodeError`, каталог `20_x.lua` → `PermissionError`
   (rc=1 через traceback).
8. **[nit]** коллизия FW_BUILD при сдвиге границы файлов: (`"ab"`,`"c\n"`) и (`"a"`,`"bc\n"`) → 0x1bcb оба,
   артефакты разные (только файлы без LF в конце).
9. **[nit]** `# nosec BXXX — пояснение`: подавления верные (`--ignore-nosec` → ровно B404:25, B105:38, B603:121),
   но текст после id bandit читает как имена тестов → 5 WARNING.

11. **[nit, тесты]** `test_mirror` / `test_missing` — по 4–10 сценариев в одном тесте; parametrize.
