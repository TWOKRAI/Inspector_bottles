## Расхождения и находки

- Ожидали, что все CVT_JOB примутся; первый прогон (до перезапуска) выдал 2 из 5 заданий с E_ZONE_TRIP (errno 12, TLM_MISS_COUNT +1, DONE не пишется, scene не получила события). Причина — моя выборка pick: r=514/520 мм вне кольца P_ZONE_MIN..P_ZONE_MAX = 120..500 мм (PARAM_GET raw 1200/5000, scale 10). Комментарий тестов "кольцо [100,600]" не соответствует дефолтам ядра. Не дефект хоста; чистый прогон (pick r 471-477) 5/5. В журнале того прогона: jobs=5, done=3 — журнал считает принятые, не выполненные.
- TLM_PROTO_VER на v1 по адресу 0x1040 читается 0 (карта v1 покрывает адрес) — не ошибка Modbus; проверка "v1 отличим от v2" по этому регистру даёт 0, по 0x3080 — исключение.
- job_ms=1000 в pipeline.yaml на v2 не действует (README): DONE за ~0.41 с вместо ~1 с v1.

## Что я оставил открытым / ненадёжным

- Имена OS-потоков (`sim-robot-motion`/`sim-robot-server` отсутствуют) НЕ проверены напрямую: py-spy нет, Python 3.12 не выставляет имена потоков в ОС. Доказательство косвенное: список воркеров (`sim_robot_ticker`, `sim_robot_listener` есть; на v1 их нет), число потоков 33–34 (v2) против 31 (v1). Это не доказательство отсутствия сырых потоков.
- Окружение отличается от боевого: `data/line_sim` в дереве нет; camera/layers читают пресет и тайл из соседнего worktree `stand` (пресет идентичен diff'ом). Правка pipeline.yaml сверх `protocol` — абсолютные пути.
- backend_ctl порт 8765 вместо README-шного 8766 (MCP подключается к 8765; порт был свободен). Конфликта с прототипом не было.
- Точка WDG: срабатывание по моим выборкам с шагом ~0.11 с, момент последнего HB восстановлен по расписанию скрипта (±0.2 с), не по журналу. Точное время — только "в окне 2.4–3.0 с от последнего HB".
- Pick в (e) берётся из паспорта объекта (state `sim.objects`) и формулы продукта `object_robot_xy`, а не из пикселей кадра: путь "кадр -> зрение" не проверялся.
- Один прогон каждого замера, разброса нет (число — наблюдение, не оценка). done_ms включает ~24 мс ACK mailbox и опрос 10 мс.
- jog d4: время остановки 0.582 с включает шаг опроса ~60 мс и рампу; точнее 500 мс не разрешить этим способом.
- Не тестировались: reverse, рестарт воркеров v2 на живом процессе (повторный start), нагрузка/длительность (прогоны по минуте).
- Журнал `recent` на v2 даёт строки `[v2] CMD/DONE`, а не v1-формат; потребители `recent` (пульт) не проверялись.
