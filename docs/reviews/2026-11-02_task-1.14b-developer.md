## Решения и расхождения с брифом

1. `_foundation_names(manifest, warn=None)`: бриф даёт сигнатуру `(manifest)`, но W1 требует `warn` на сбой — добавил второй необязательный параметр; без него — `_log.warning`. Вызов в `app.py` передаёт тот же `process._log_warning`, что слияние. Побочное следствие: при битом фрагменте два предупреждения (слияние и имена).
2. Рецепты репо в тестах — копии `fixtures/<slug>_head.yaml`, снятые `git show HEAD:` (subprocess `git` в тесте не нужен: зависел бы от наличия git и истории). Фикстуры вне списка FILES; бриф прямо разрешил такой вариант. Чтение — с заменой `\r\n`, как у фикстуры A. `base.yaml` берётся из рабочего дерева (не рецепт, `git status` по нему чист).
3. F2a/b, S1/S2 и тесты F1 лежат в `test_save_protected_owner_extra.py`, P1 и F2 через презентер — в `test_save_conflict_rev.py`.
4. W1 использует настоящий манифест (`load_manifest(resolve_manifest_path())`) — читает `app.yaml` и `base.yaml` из дерева; при включении `observability_sink.yaml` ожидание станет `{"devices", "telemetry_sink"}` (ограничение из TRAPS, красный тест будет сигналом).
