## G1: подключение не стоит на `_param_lock`

- Без гонки: замок держит тест, связь сброшена -> `tick()` за 0,0 с, транспорт и `probe` не тронуты, `reconnects` +0. После отпускания: один `connect`, один `probe`, `reconnects` +1, подключён.
- `locked()` — подсказка, а не «проверить, затем действовать» для корректности. Корректность держит захват без блокировки в `_sync_on_connect`. Гонка стоит только лишней работы.
- Гонка воспроизведена: замок берёт другой поток сразу после `probe`.
  - Тик 1: `connect` отложен (`_connect_deferred` True), транспорт оставлен открытым при `_ready` False; `connect` 1, `probe` 1, `reconnects` +1.
  - Тик 2: `disconnect` 1, `connect` 2, `probe` 2, `reconnects` +2 на одно логическое подключение. Счётчик попыток не растёт (+0): риска «сдался» нет.
- По чтению: `_connect_deferred` не сбрасывается на ранних выходах `connect` (выключение, задание тика). После отсрочки такие тики идут без порога и без счёта неудачи. Вреда нет: ранний выход дешёвый.

### Замечание 1 [IPC] minor, решает лид: более простая форма G1

«Замок — это действие»:
- `_ensure_connected` берёт `_param_lock` без блокировки ДО порога, счётчика и транспорта и зовёт `_connect_locked()`;
- публичный `connect()` (ручной путь, поток очереди подключения) — `with self._param_lock: return self._connect_locked()`;
- `_sync_on_connect` замок не берёт.

Уходят `_connect_deferred`, `locked()` и отрицательная метка `_last_reconnect`; окна гонки нет по построению.

Воспроизведение на копии с этой формой (правка ~20 строк, только в моём worktree):
- проба гонки -> тик 1 подключил: `connect` 1, `probe` 1, `reconnects` +1;
- `test_robot_v2_ops.py` + `test_robot_v2_ops_timing_acceptance.py` + `test_robot_v2_connect_data.py` + пробы -> `46 passed, 1 failed`. Упал `test_connect_defers_when_param_lock_taken_after_probe`: он проверяет флаг нынешней формы, а его шов берёт замок внутри `probe`, который в новой форме уже держит тик. Этот тест заменяется на «замок занят -> тик без работы транспорта».

Цена новой формы: ручной `connect` ждёт `param_set` (ограничено его вводом-выводом); `param_set` во время подключения и так отвечает «нет связи с роботом» до замка.
