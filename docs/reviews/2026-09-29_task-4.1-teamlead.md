## Что интерпретировал, а не следовал

- Неизвестный `slot` в тикете → кольцо frame (как до 4.1 весь release шёл в единственный пул).
- Пул колец не-frame создаётся, если пул есть у кольца frame (в т.ч. при инжектированном `pool`) —
  для них дефолтный `LoanLedger`.
- `on_send` (top-level `msg["frame"]`, путь wire.configure) остался только для frame — C8/брифом
  про него ничего не сказано.
- Сбой записи одного не-frame ключа — не drop, а inline + pickle-fallback (как frame).

## Что оставил открытым / ненадёжно

- Унаследованные ссылки: item, пересланный дальше, несёт `_shm_refs` верхнего владельца (как frame
  несёт плоские поля). Если плагин удалил ключ, следующий потребитель восстановит его из чужого
  слота и пошлёт тикет чужому владельцу — паритет с frame, не проверялось live.
- Copy-on-write словаря колец не имеет красящего теста: под GIL `list(dict.values())` атомарен, и
  инъекция «мутировать на месте» не упадёт — защита не доказана, только рассуждение.
- Два `test_reader_gone_hazards` падают только в полном прогоне; причину не искал.
- Живой стенд не гонял (вне зоны задачи); кросс-процессный приём проверен только C3 (spawn).
- Diff middleware крупный (501+/264−): состояние слота переехало в `_Ring`; поведение frame-пути
  держат старые тесты (`test_g5d_loan`, `test_frame_shm_middleware`, ring_depth, live2) — не больше.
