Выход (по коду): `after = _denormalize(recipe.to_dict())` (`model_dump(mode="json")`, все умолчания) → `patch_recipe` без `on_insert`. **b) `write` нового рецепта.** Решение автора не нарушает DESIGN, но обходит `minimize`: см. F2.

**c) `save_layout(expected_rev=None)` берёт `rev` через `read_recipe_rev`.** Обнаружение конфликта не теряется сверх того, что задаёт Protocol 1.7: «`expected_rev` как у `save_raw`; `None` — стор берёт `rev` своего чтения внутри операции» (`domain/protocols/recipe_store.py`, Pre `save_layout`). Рецепта нет → `read_recipe_rev` даёт `(None, None)` → менеджер возвращает `None` — совпадает с Post Protocol. Правка файла между чтением GUI и `save_layout` без ревизии GUI не обнаруживается — это план, а не дефект стора: `layout_controller.py:303` не передаёт ревизию, Task 1.8 (DESIGN 4–5) передаёт `expected_rev=base_rev_for(slug)`. Между чтением стора и локом конфликт обнаруживается и не глотается (P4(iii)). Нет теста на явную ревизию — F3.

**d) `expected_rev if expected_rev is not None else rev`.** Верно и строже, чем `or` из текста задачи: пустая строка уходит менеджеру и даёт `RecipeConflict` (`expected_rev != current_rev`), а не молча заменяется на свежий `rev`. `compute_rev` возвращает непустой hex, поэтому на практике различие касается только вызывающего с `""`.
