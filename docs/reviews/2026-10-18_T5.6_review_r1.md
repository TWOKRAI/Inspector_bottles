## Ответы по фокусу брифа

1. **Потоки.** Под замком: `_count_locked`, `_append_locked` (часы `t`, `seq`, склейка, кольцо), `_close_tail_locked`, `_state_locked`, копия строк в `get`. Вне замка: транспорт, форматтер, `_emit`, `logger.warning`. `_note_failure` зовут: внутренний `except` в `_record` (до `with`), внешний `except` (после выхода из `with` — `with` отпускает замок при исключении), `_emit` (его зовут только вне замка из `_record` и `set`). Пути «`_note_failure` при удержанном замке» нет. Обратного порядка с `RLock` `ModbusDevice` нет: журнал не держит замок на транспорте, транспорт журнал не зовёт. Склейка правит хвост только под замком; `get` копирует `dict(line)` под замком.
2. **Обёртка.** Результат отдаётся как есть (`ok is False` — только для строки и счётчика), исключение — голым `raise` (тот же объект). `transaction -> False` даёт `err` и `errors += 1`. `connect -> False` даёт `connect fail` без причины (у `ModbusDevice` причина в `get_status()["last_error"]`) — совет. Мост: `build_transport` отдаёт `carrier.transport` = обёртку. Время: журнал работает после выхода из `RLock` транспорта, но в потоке вызывающего (синхронная запись логгера на новой строке — по спецификации).
3. **Ноль при выключенном.** По коду: одно чтение `log._enabled` и лишний кадр вызова; ни часов, ни форматирования, ни замка, ни аллокаций. `__getattr__` и `is_connected` от флага не зависят.
4. **Врезки.** Совпадают со спецификацией и наброском. `isinstance` на транспорте в не-тестовом коде Services/Plugins нет. Подмена `drv.transport.transaction` в тестах T5.3 (`test_robot_driver_v2.py:764-775`, `..._jobs_acceptance.py:341-355`) ложится атрибутом на обёртку; `original` — метод обёртки, обмен журналируется. `test_robot_driver_v2.py:529` пишет `closed` во внутренний фейк — не затронуто. v1-робот (`kind == "robot"`) на команду журнала отвечает «Неизвестная операция робота» (`robot_driver.py:587-588`) — приемлемо.
5. **Правила владельца.** Один писатель: только `get_std_logger`, `open()` нет. Ручки на ходу без переподключения (A12). Ответы операций — `int`/`float`/`str`/`bool`/`dict`/`list`, JSON-безопасны.
6. **Тесты.** Находки 1, 2. Фейки повторяют `RegisterTransport` (`is_connected` property, `read_registers`, `transaction`) плюс `connect`/`disconnect`/`get_status`. `_HandshakeRing` зависит от `_ring.append` — приемлемо, пока `clear` не перепривязывает `_ring`.
7. **Формат.** `W` / `W*` / `R ..+n`, `(PTP_MOVE)`, строка `res` с `ERR_TEXT`, `W* SC_BUF[0..29] (30 слов)`, теги — по спецификации.

## Советы (не блокируют)

- В файле порядок записей между потоками не гарантирован: логгер вне замка (по дизайну). Запись `#k … ×n` может лечь раньше `#k`. Не воспроизводилось. Добавить в README: «сортировать по `#seq`».
- `_tx_op_name(ops)` и `_addr_name(address)` считаются вне `try` у `_record`. Для `ModbusDevice` легального входа, который их ломает, не нашёл. Адрес-`float` вне карты (`f"0x{4160.5:04X}"`) даст `ValueError` до вызова транспорта. Перенос в `_record` закрывает класс.
- Открытый хвост `×n` не попадает в файл до следующей строки / `clear` / выключения (по спецификации; в кольце он есть).
- `get(limit=0)` отдаёт `last_seq` = последний выданный `seq` без строк: читатель по курсору пропустит хвост. Pre допускает `0`.
