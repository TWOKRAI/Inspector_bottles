### J5: находка (вход -> наблюдаемый выход)
Предложенный тест «байты после Save без правок прежние» на настоящем сторе под J5 ОСТАЁТСЯ ЗЕЛЁНЫМ. Вход: файл `name: r1 / version: 3 / gui_positions: {producer: [1.0, 2.0]} / blueprint: {processes: [producer], wires: [], displays: []}`, Save с той же топологией. Выход при основе `canon` и при основе `raw`: `path.read_bytes() == original` в обоих случаях. Проверено ещё на 3 формах (gui_positions+locked_nodes сверху; верх и metadata расходятся; `meta:`): тоже идентично. Причина: `RecipeStoreFromManager.save_raw` -> `RecipeManager.patch_recipe` сам канонизирует (`{**канон файла, **data}` + хук), поэтому выбор основы на байтах файла не виден. Каноническое чтение — не по байтам, а по шву: канон переносит legacy top-level `gui_positions` в `blueprint.metadata`, и в `save_raw` уходит `data` без top-level `gui_positions`. Тест ловит J5 именно этим ассертом на `data`; байтовый ассерт оставлен как регрессия. Прошу лида решить, достаточно ли этого (ассерт на шве — деталь реализации, но других наблюдаемых различий нет).
