## Находки

1. **[major, tests]** `test_cv_threads.py::_child_config` кладёт ключ на оба уровня, поэтому runner, читающий
   только верхний уровень, остаётся зелёным. Инъекция: форма tester'а → 4 (зелёно), настоящий proc_dict
   ассемблера → 2 (цепочка сломана). Лечение: реальная форма `{"config": {...}}` плюс один тест
   `ProcessConfig(extras).as_generic_config().build()` → ребёнок.
2. **[minor]** Запасной путь runner'а не ограничивает значение снизу: `-1` → 16 потоков, `0` → 1, `True` → 1,
   `2.9` → 2. На пути рецепта `FieldMeta(min=1)` работает: `0` → `ValidationError`.
3. **[minor]** `int(cv_threads)` в blueprint срабатывает раньше pydantic: `'abc'` → голый
   `ValueError: invalid literal for int()` без имени ключа, `2.9` молча становится 2. Тот же приём уже есть у
   `frame_ring_depth` и `chain_max_lag_items`.
4. **[minor, docs]** Drift-guard ссылается на `TEMPLATE.yaml`, а на `fcc80b9b` ключа там нет: правка лежала
   незакоммиченной в основном дереве.
5. **[minor, docs]** В docstring runner'а написано «импорт только здесь», хотя `introspect.status` тоже импортирует cv2.
   Описание команды не упоминает `cv_threads`.

## Ответы на вопросы брифа (замеры)

- **Цена `import cv2` в каждом ребёнке:** около 30 мс и +8 МБ RSS (+7 МБ USS). Ни один из классов процесса
  (GenericProcessApp, HeadlessGuiProcess, ProcessManagerProcessApp) cv2 сам не импортирует.
  `OPENCV_FOR_THREADS_NUM` эта сборка не читает (cv2 **5.0.0**, бэкенд Concurrency): при любом значении
  `getNumThreads` = 16. Значит, `setNumThreads` после импорта — единственный рабочий рычаг, цена приемлема.
- **Реакция cv2 на значения:** `0` → 1 поток, отрицательное → все ядра, `bool`/`float` → `TypeError`.
- **Порядок поиска ключа** (сначала вложенный `config`, потом верхний уровень) совпадает с реальным путём
  реестра. У всех классов из рецептов ключ достижим. У PM вложенного `config` нет, ему достаётся дефолт 2.
  `setNumThreads` из главного потока действует и на рабочие потоки.
- **`introspect.status`:** медиана 0.5 мкс, максимум 135 мкс под нагрузкой. Без cv2 — около 0.24 мс на вызов.
  Команду не блокирует.
