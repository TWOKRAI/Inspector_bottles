# fix-Q1 — сбой старта потока run-fault-stop оставлял аварию без итога

Ветка worktree-agent-acb5e42b20df94ef6 (от 700bdcdfa). Не закоммичено: коммитит лид.

## Изменение

`multiprocess_framework/modules/process_manager_module/process/process_manager_process.py`:

- `_submit_run_sequence(..., *, seq: int = 0)` — новый ключевой аргумент (номер аварии подачи).
- В `detached()`, ветка `except` у `Thread.start()`: к существующей ветке `run-stop` добавлена
  `elif name == "run-fault-stop": self._run_stop_finish(fault=True, seq=seq, names=[], timeout_s=0.0)`.
- `_start_fault_stop` передаёт `seq=seq` (он уже читал `self._fault_seq` под `_run_lock`).
- Docstring `_submit_run_sequence` дополнен. `run-shutdown` и STOP не тронуты (seq по умолчанию 0, STOP его не использует).

Почему `seq` ключевым аргументом, а не чтение `self._fault_seq` в `except`: к моменту `except` могла начаться новая авария; её
итог поставить нельзя. `_run_stop_finish` сам сверяет `_fault_seq != seq` и тогда выходит без действия.

Новый файл `multiprocess_framework/modules/process_manager_module/tests/test_run_sequence_thread_start_hazards.py`
(на `_Rig` из `test_run_stop.py`: настоящие PM и монитор, двойник детей; `_lifecycle_submit = None` — путь одноразового
потока; `Thread.start` подменён только для потока с заданным именем; ожидание через `_wait` с дедлайном, `pytest.mark.timeout`):

1. `test_fault_stop_thread_start_failure_still_finishes_and_allows_ack` — running -> авария соседа `b`, `run-fault-stop` не
   стартует: состояние `fault`, `fault_stop_done is True`, `ack_allowed is True`,

2. `test_stop_thread_start_failure_still_finishes` (контроль) — тот же сбой для `run-stop`: `ready`, `run_event` снят, START принят.

## Что оставил открытым / ненадёжно

- Сбой старта потока в `run-shutdown` не рассматривался (вне задачи); путь `finish` для него — отдельный вход, не проверял.
- Тест подменяет `threading.Thread.start` глобально на время такта: другие потоки с иным именем стартуют штатно, но подмена
  задевает любой поток в окне `with`. Окно короткое (один такт), других потоков с именем `run-fault-stop` в нём нет.
- Сообщение DESIGN вверх по протоколу не слал: бриф дал DESIGN и разрешение (BRIEF-OVERRIDE), инструмент отправки был отложенным.
- Исход `ack` в тесте — `not_ready` (причина `b.p` ещё жива, `ack` принимается по `fault_stop_done`); это наблюдение, не
  выведенное из кода значение; если контракт `ack` из `fault` при живой причине изменится, ожидание нужно пересмотреть.
- В выводе `test_run_*.py` есть G4 "threads without scope path: 1" в `test_run_flag.py` (`run-flag-parent-ops`) — прежнее,
  к правке не относится (не проверял на чистой ветке).
