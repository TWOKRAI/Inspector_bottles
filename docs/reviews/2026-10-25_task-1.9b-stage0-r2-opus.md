## Находки

### 1. [spec / IPC, блокер] D4: стоп детей стартует в фазе 1, пока операция исполнителя ещё ждёт того же ребёнка — I1 ложен по построению
- **Где в спеке:** T1.9b.md:138-147 (`request_stop`: `finally` — запуск стопа детей; `join_until`: сначала
  `_lifecycle_executor.join_until(d)`), :148, Acceptance :234-236 («двух `ChildProcessStop` на одного ребёнка нет»).
- **Где в коде:** сегмент закрывается фазой 1 по ВСЕМ записям, потом фазой 2 в обратном порядке (`lifetime.py:568-572`);
  порядок записей в `work`: исполнители (`process_module.py:539-540`), `children` (PMP:3584-3586), `workers`
  (`process_module.py:280`); фаза 1 `_ChildrenStop.request_stop()` → `_start()` → `children_stop()` +
  `group.request_stop()` (PMP:4406-4432); группа берёт всех живых, в том числе `slow` (`process_registry.py:411-434`).
- **Вход → наблюдение:** системный стоп во время `process.stop slow` на исполнителе. Группа создаёт свой
  `ChildProcessStop` для `slow` и взводит его в фазе 1, пока `ChildProcessStop` операции ещё опрашивает `slow`; ожидание
  исполнителя начнётся только в фазе 2. Два объекта на одного ребёнка. Опись (`pm-lifecycle-commands.md:121-122`) держала
  порядок вызовом внутри `request_stop()`; р.2 перенесла ожидание в `join_until`. R6, R7, H1 объекты не считают.
- **Исправление:** в `request_stop()`: `_children_stopping = True` → `_lifecycle_executor.request_stop()` → если не
  `is_executor_thread("pm-lifecycle")`, то `_lifecycle_executor.join_until(now + infra_s)` → `finally: _start()`; пауза
  монитора — остатком срока (блок в фазе 1 уже признан исключением, PMP:4382-4384). `join_until` — как сегодня.
  Hazard-тест: число созданных `ChildProcessStop` с `slow` = 1; инъекция: ожидание исполнителя вернуть в `join_until` →
  этот тест красный.

### 2. [spec, блокер] «Без terminate» одним `join_until` не получить: временная область `pm/stop` в фазе 3 зовёт `kill()`
- **Где в спеке:** D4 :129-131; R7 (T1.9b_tests.md:23-25): «0 `terminating`».
- **Где в коде:** `stop_one` → `_stop_many` → `open_scope("pm/stop")`, `scope.close()` (`process_registry.py:352`,
  :461-465); `join_until` = `False` → `pending` → `_phase3` → `kill()` (`lifetime.py:579-588`, :627-639); `kill()` пишет
  `did not stop in` и зовёт `terminate()` (`child_process_stop.py:172-186`); затем ERROR «всё ещё жив после kill —
  остановка НЕ подтверждена» (`process_registry.py:473-475`).
- **Проба** (scratchpad сессии, `probe_abort_phase3.py`): подкласс `ChildProcessStop`, `join_until` при взведённом abort
  сразу `False`, во временной области `pm/stop`:
  ```
  elapsed_s=0.000 terminated=1 killed=0 survivors=('slow',)
  W Process 'slow' did not stop in 0.0s, terminating...
  ```
- **Исправление:** D4 — после `should_abort() == True` `kill()` — no-op (без строки, без `terminate`); `_stop_many` пишет
  прерванные имена отдельной строкой («стоп прерван системным стопом»), без ERROR «после kill»; R7 — «0 строк `всё ещё жив
  после kill`»; инъекция И3б «`kill()` не смотрит abort» → R7 красный.
