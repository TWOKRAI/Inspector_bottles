## Что сделано

1. **`Services/robot_comm/server/sim_core.py`** (§1):
   - `RobotSimCore.__init__` получил `on_job_done: Callable[[dict], None] | None = None`.
   - Счётчик `self._job_index` (принятые задания, с 1) — инкремент в ветке приёма
     (`_accept_countdown <= 0`, то же место, где `REG_JOB_FLAG -> 0`).
   - Правка дефекта: `self._job_ecap` теперь декодируется как 32-битное значение из ПАРЫ слов
     `REG_JOB_ECAP`/`REG_JOB_ECAP+1` через `decode_int32` (`Services/modbus/sdk/datatypes.py`) —
     раньше читалось одно слово (106016 давало 40480).
   - Вызов колбэка — в ветке завершения (`_job_countdown <= 0`), сразу после
     `self._emit("[CVT]  выполнено -> робот свободен")`. Исключение из колбэка не ловится
     (по контракту — защита на стороне хоста).

2. **`Services/line_sim/core/matching.py`** (новый, §2): `BeltGeometry`, `JobDone`, `MatchResult`
   (frozen dataclasses), `object_robot_xy()`, `match_job()`. Алгоритм: минимальная невязка XY
   среди `active`, затем `removed` (порядок важен — реализует «ничья -> active», т.к. `removed`
   заменяет текущего победителя только при строго меньшей невязке). `match_radius_mm <= 0` ->
   `ValueError` с именем параметра в тексте.

3. **`Services/line_sim/core/spawner.py`** (§3): `ObjectSpawner.remove(object_id) ->
   ObjectPassport | None` — линейный поиск по `self._active`, `pop()` найденного, `None` для
   неизвестного id. `_last_spawn_encoder`/`_next_spacing_mm`/`_deadline`/`_next_id_n` не тронуты.

4. **`Services/line_sim/core/__init__.py`** — реэкспорт `BeltGeometry`, `JobDone`, `MatchResult`,
   `match_job`, `object_robot_xy`, добавлены в `__all__` по алфавиту вперемешку с остальными.

5. **`Services/line_sim/tests/test_hazards_3_5.py`** (новый, автор) — 4 теста:
   - `test_second_job_on_already_removed_object_is_dup_not_silent_match` — второе задание на тот
     же object_id (переданный в `removed`) -> `dup`, не тихий повторный `matched`.
   - `test_ecap_far_ahead_of_spawn_no_exception_exact_arithmetic` — `ecap` на порядки больше

   - `test_jobdone_and_beltgeometry_roundtrip` — `from_dict(x.to_dict()) == x` для обоих.
   - `test_remove_does_not_disturb_interval_deadline` — `remove()` в режиме `interval_s` не
     трогает `_deadline` (регрессия была бы: снятие объекта сдвигало бы следующий спавн).

## Что я интерпретировал, а не просто выполнил

- Контракт даёт `off = encoder_to_offset_mm(ecap, spawn_encoder)` буквально — использовал как
  есть, не поменял местами аргументы (проверено литералом приёмки: identity-геометрия даёт
  `(0.0, 144.473)`).
- Порядок обхода `active` затем `removed` в `match_job` — не написан явно как «сначала active»,
  но это единственный порядок, реализующий «ничья -> active» через строгое `<` без отдельного
  флага приоритета; вывел это из формулировки контракта и проверил на литерале с ничьей
  (`test_nearest_active_wins_and_tie_goes_to_active`, часть 2).
- `ValueError` текст — `f"match_radius_mm должен быть положительным, получено {match_radius_mm!r}"`
  — конкретную формулировку контракт не диктовал, только что имя параметра должно быть в тексте
  (`pytest.raises(..., match="match_radius_mm")`).
- Место docstring Post: в `spawner.py` — контракт сказал «обнови Post-строку», сам сформулировал
  добавление одним предложением в существующий Post-абзац, не переписывал весь докстринг.
