Но обратите внимание: `success=True` при `vacuous=True` означает, что читающий только `success` видит «успех» у записи, которая ничего не доказала. План (цель 10) требует `success=False` только для ОТВЕРГНУТОЙ записи при равном значении; для принятой равной записи требование не сформулировано. Вопрос лиду: нужен ли `success=False` и для принятой vacuous.
- Контроль с изменением: `scale_factor` 1.0 → 1.5 → 1.0: оба раза `confirmed`, `success=True`, `vacuous=False`.

Ожидаемый `vacuous` недостижим: у процесса без обработчика нет регистра в образе, значит «равного текущему значения» нет. Сценарий «регистр есть в образе, обработчика нет» на стенде не существует.
