## Что я толковал, а не выполнял буквально

1. **Добавлено сверх DESIGN: повторный автовыбор после последнего такта.** Один автовыбор в начале давал
   выход 0, если второй камерный плагин процесса появился позже: его никто не наблюдал. Теперь он получает
   `no_samples`; отказ повторного чтения даёт `detect_failed:<p>`. Новых кодов `failures` нет. Цена — один
   IPC на процесс.
2. `--plugins` с несколькими процессами: объединение. Плагин не найден, только если его нет ни в одном
   процессе; у каждого процесса должен найтись хотя бы один из списка.
3. Неверные аргументы дают код 2 (argparse), не 1.
4. Причины уровня стенда лежат в `errors` отчёта (`no_camera_plugin:`, `detect_failed:`, `plugin_not_found:`,
   `driver:`), рядом поле `exit_code`. DESIGN этих ключей не называет.
5. Нечисло, nan, inf и bool в метрике считаются отсутствующей метрикой.
6. Старый файл `--out` удаляется в начале прогона.
7. Первая правка сделана позже пятого вызова инструмента: сверял формы ответов по коду, как велел лид.
   Сообщение `DESIGN/FILES` не отправлялось: под `src/` правок нет.

## Что оставлено открытым / ненадёжным

- Живой стенд не запускался. Формы ответов выведены из кода, а не записаны с живой системы.
- Автовыбор не видит камерный плагин, который не опубликовал блок ни разу (не загрузился). Если в том же
  процессе есть другая камера, будет выход 0. `--plugins` закрывает это только при уникальных именах:
  из-за объединения (п.2) `--processes p1,p2 --plugins a,b` пройдёт, когда в p2 нет `b`, а в p1 есть.
  Нужна строгая пара «процесс-плагин» — это решение лида.
- `frames_stalled` смотрит два последних удачных опроса. Остановка в середине прогона с восстановлением
  даёт выход 0 (так задано DESIGN).
- `--interval` меньше окна публикации плагина (1 с) или опрос дольше интервала (такты тогда идут подряд)
  даст ложный `frames_stalled`. Это ложный красный, не зелёный.
- Блок без `link` на позднем такте (или при `--plugins` на некамерный плагин) не даёт своей причины отказа:
  `link_state` будет пустым. Такой плагин всё равно обязан быть `grabbing` с растущими `frames`.
- `--help` выходит с кодом 0 (стандарт argparse): обёртка не должна считать код без файла `--out` приёмкой.
- Весь набор `backend_ctl/tests` не запускался: файлы новые, их никто не импортирует.
