## Находки (по убыванию)

### 1. [architecture, major] `server/sim_core_v2.py:277-284` — `joints()` возвращает `None` после хода, принятого зоной; докстринг утверждает обратное
Докстринг: «`None` … не должно происходить для позы, уже прошедшей проверку зоны при ходе». Это неверно: зона (`P_WS_*`, правда прошивки) и досягаемость модели (`|l1−l2|..l1+l2`) — две независимые границы.

Воспроизведение (через mailbox):
```
servo (1, 0)
set R_MAX=700mm (1, 0)            # PARAM_SET P_WS_R_MAX=7000, диапазон параметра 0..32767
move JOINT (650,0) (1, 0)         # ACK
pose (650.0, 0.0, -75.0, 0.0) activity 0
joints() None
chain_points(joints()) -> TypeError cannot unpack non-iterable NoneType object
```
`model.chain_points(core.joints())` — ровно выражение из брифа T2.V (`tasks.md:257`): окно-вид упадёт. То же при `P_WS_R_MIN < |l1−l2|` и — штатно — когда длины с шильдика дадут `l1+l2 < 600` при дефолтном `P_WS_R_MAX=600`.
**Исправить:** докстринг назвать условие (`None`, когда зона прошивки шире досягаемости модели: `P_WS_R_MAX > l1+l2` или `P_WS_R_MIN < |l1−l2|`); тест, закрепляющий `joints() is None` в этом сценарии; в бриф T2.V — обработка `None` (рисовать только TCP + пометка). Проверку зоны не менять (И6).

### 2. [tests, major] `joints()` проверен только на загрузке, где источники неразличимы
`test_sim_joints_match_home_ik` смотрит сразу после boot: там `TLM_*` == `P_HOME_*` и `TLM_HAND` == `P_HAND`. Две инъекции (pytest-плагины в scratchpad), прогноз «0 упавших» до запуска:
- `joints()` берёт `P_HAND` вместо `TLM_HAND` → `728 passed`;
- `joints()` решает IK от `P_HOME_*` вместо `TLM_*` → `728 passed`.
Расхождение достижимо: после `SERVO 1` + `PARAM_SET P_HAND=0` → `TLM_HAND= 1  P_HAND= 0  joints().J2= -105.29` (верно, левая рука); инъекция (a) дала бы `+105.29`.
**Исправить:** тест после `PARAM_SET P_HAND=0` (литерал: `J2 < 0`, рука по `TLM_HAND`) и тест после хода (`fk(joints())` == новая поза `TLM_*` с допуском 0.1).

### 3. [tests, major] `server/sim_core_v2.py:304` — вызов `self.model.check_segment` на LINE не закреплён
Инъекция: `_check_motion` для LINE зовёт `geometry.check_segment` напрямую (проводка до T2.K). Прогноз «0 упавших» → `728 passed, 5 skipped, 2 xpassed`. Причина: подставная модель в `test_sim_zone_goes_through_model` отвергает всё в `check_point`, до `check_segment` ход не доходит. Это второе незакреплённое место помимо JOG_CONT (~458), которое закрывает `ba649b77`.
**Исправить:** подставная модель `check_point → 0`, `check_segment → R_DEAD_ZONE`; LINE `PTP_MOVE` → `NAK`, `E_RANGE`, `rvals[0] == R_DEAD_ZONE`.

### 4. [architecture, major — дизайн шва] `kinematics.py:60` — `chain_points → list[(x, y, z)]` = одна ломаная = допущение последовательной цепи
Дельта Клавеля — три параллельные цепи (база_i → локоть_i → платформа_i). Единственная кодировка в нынешнем типе — плоский список, и вид, рисующий ломаную, нарисует фантомные звенья. Иллюстрация (заглушка дельты, 9 точек):
```
segments drawn: 8  phantom: [(50, 0, '->', -100, 173), (-25, 43, '->', -100, -173)]
```
T2.V будет написан под ломаную → дельта = переделка Protocol + вида + тестов, то есть ровно то, чего владелец хочет избежать. Приёмка T2.V («подставная модель с тремя звеньями») проверяет только последовательную цепь.
**Рекомендация (решает ведущий, дешевле всего — до T2.V):** `chain_points → list[list[point]]` (ломаная на каждую цепь), SCARA возвращает `[[base, elbow, tool]]`. Если отложить — записать в план как известный предел шва.

### 5. [architecture, minor — дизайн шва] `kinematics.py:56` — `fk → Pose` без `None`
Для последовательных рук FK тотальна; у дельты FK — пересечение трёх сфер, для части троек углов решения нет. Продакшен-вызывающих `fk` пока нет (grep: kinematics потребляет только `sim_core_v2`, и только `check_*`/`ik`) — сменить на `Pose | None` сейчас бесплатно.

### 6. [architecture/docs, minor] «смена типа руки не требует правок ядра» — шире, чем правда
`check_point/check_segment(ws: geometry.Workspace, …)` — зона SCARA (кольцо + сектор J1 + бокс); `ws` строит само ядро из `_WS_PARAM_NAMES`; правило `R_HAND` (`TLM_HAND != P_HAND`) живёт в ядре (`sim_core_v2.py:301`, `:649`), не в модели. Для дельты/6-осевой с другой зоной прошивки ядро править придётся. Утверждения: `server/README.md` (+22..27), докстринг `sim_core_v2.py:38-41`, `README.md` (+86..92).
**Исправить:** сузить формулировку («для прошивки с зоной `P_WS_*` кольцо/сектор и `P_HAND`»). Вариант на потом: `model.workspace(eng_params)` — не требую.

### 7. [quality, minor] `kinematics.py:112` — `hand` вне {0, 1} молча = правая
`ik((300,-210,-40,0), 2)[1] -> 105.29424849603144` == `ik(…, 0)[1]`. Через sim недостижимо (`P_HAND` 0..1). Исправить: документировать `hand` как код конфигурации, определяемый моделью (6-осевая: биты плечо/локоть/кисть; дельта: игнор), SCARA → `None` для `hand ∉ {0,1}`.

### 8. [quality, minor] `kinematics.py:145-153` — `make_model` без проверки на границе (Dict at Boundary)
```
make_model l1=0 then ik((275,0,0,0),0) -> ZeroDivisionError float division by zero
make_model l1=-325 then ik((300,0,0,0),0) -> None
make_model typo L1 -> TypeError ScaraModel.__init__() got an unexpected keyword argument 'L1'
make_model l1="325" then fk -> TypeError can't multiply sequence by non-int of type 'float'
```
Исправить: `ScaraModel.__post_init__` — `l1, l2` конечные числа > 0, иначе `ValueError`; неизвестные ключи → `ValueError` со списком допустимых. Заодно снимет warning pyright на `:148`.

### 9. [quality, minor] `server/sim_core_v2.py:117-119` — комментарий противоречит сам себе
«должен быть выставлен ДО `_boot()`, т.к. `_boot` ничего с моделью не делает». Переписать: порядок относительно `_boot` не важен, модель нужна с первой команды хода.
