## Что оставлено открытым / ненадёжно
- Заглушка `_map_passport` ловится общим `except Exception` как `internal error`, код 2: слепой tester не отличит «заглушку»
  от «цель не найдена» по коду, только по stderr. Для RED-тестов цели это приемлемо (они проверяют stdout/JSON).
- Докстринг `render_text` обещает `ValueError` по набору `kind`, а код проверяет только `SHOW_ALL_SECTIONS`: расхождение
  до GREEN (`render_text` пока вызовет `ValueError` на `members`, `threads`, `io`). `_render_map` и `_alloc` с параметром
  имён в INTERFACE не заводились (в задаче они только в DESIGN/FILES `passport.py`, подписи публичного API не нужны).
- `_stale`: докстринг описывает порог <= 100 путей, код его не знает (всегда pathspec); `OSError` при длинном argv
  по-прежнему даёт `null` — на `map process_module` (359 путей) это значит `stale: null` до GREEN. Пин 4.2b-1 не менялся.
- Описание `build_map` для файла с `error`/`v2_error` и для файла в `--exclude` внутри юнита (член юнита) выбрано
  не договаривать: форма и задача молчат; решает GREEN, закрепит hazard-тест.
- «Последствия» ADR-ATL-005 по-прежнему говорят «`map`, `stale`/`frozen` — 4.2b» — не правил (вне запрошенной строки).
- Слово «юнит|файл» как `metavar` в usage argparse: `|` в `metavar` на справку не влияет (проверено `map --help`), но
  при переносе строк usage на других версиях argparse не проверялось.
- Живых прогонов (`map config_module`, времена, числа) не делал: нет реализации.
