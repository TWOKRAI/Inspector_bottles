## 3. Сторож L3 test_recipe_to_dict_keeps_process_null_fields

Инъекции в процессе (monkeypatch):
- Topology.to_dict -> model_dump(exclude_none=True): сторож КРАСНЫЙ (ловит прямой Topology.to_dict()). При той же инъекции Recipe.to_dict()["blueprint"]["processes"][0] сохраняет ключ priority (True), прямой Topology.to_dict() уже без него (False) — это и объясняет вакуумность первой версии.
- Recipe.to_dict -> exclude_none=True: сторож КРАСНЫЙ (первая половина).

Почему Recipe.to_dict идёт мимо Topology.to_dict: Recipe.to_dict = model_dump(mode="json"), pydantic сериализует вложенную модель своим core-сериализатором (в него входит model_serializer Topology), метод Python Topology.to_dict не вызывается. Это не дыра в DESIGN 1, а его причина: сериализатор стоит на модели именно поэтому. None name/description в Recipe.to_dict НЕ проходят (р1: ключи отсутствуют; смешанный случай теперь в тесте: name="bp" остаётся, description нет). Побочный эффект: exclude_none в Topology.to_dict не затрагивает путь записи файла, но затрагивает потребителей прямого to_dict (TopologyRepositoryStore.save); их держит вторая половина сторожа.
