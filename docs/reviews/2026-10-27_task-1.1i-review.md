## Находки

### F1 — major — `_ruamel_doc.py:239-257` (`_lift_item_tail`) двигает комментарий нетронутого flow-элемента

Загрузчик ruamel кладёт EOL-комментарий непустого flow-элемента (`- {a: 1}  # q`, `- [1, 2]  # q`) именно в
`seq.ca.items[i][0]` со значением `"# q\n"` (проверено дампом слотов). Условие `_lift_item_tail`
(`slots[0] is not None and isinstance(item, (dict, list)) and len(item)`) его принимает и переносит в
комментарий-перед-элементом с колонкой 0. Срабатывает на любой записи в файле, правка может быть в другом ключе.

Вход `ka:\n  - {a: 1}  # q\n  - z\nkb: 1\n`, дельта `kb: 1 -> 2`:

```
OLD (оба механизма выкл.): 'ka:\n  - {a: 1}  # q\n  - z\nkb: 2\n'
NEW (59ca2fa11):           'ka:\n# q\n  - {a: 1}\n  - z\nkb: 2\n'
```

Те же расхождения: `- [1, 2]  # q` (первый, не первый, последний элемент), `ka:  # e` перед списком
(`'ka:  # e\n# q\n  - [1, 2]\n...'`), два flow-элемента подряд (`# q1`, `# q2` оба уезжают вверх), вложенный
список (`-\n# q\n      - {a: 1}`), правка внутри того же списка (`ka[1] = "zz"`). Комментарий остаётся один раз, поэтому
ни T1, ни корпус не краснеют: маркеры выживших считаются по числу, не по месту.
На 22 боевых рецептах таких элементов нет (`git grep -nE '^\s*-\s*[\[{].*[\]}]\s+#'` — 0 строк; 644 правки OLD == NEW).
Живого вреда сегодня нет, но это ровно «байты вокруг правки не те, что были», и код сработает в любом файле с таким стилем.

Не пострадало: полнострочный комментарий и пустая строка после flow-элемента (`# about z`, пустая строка) — загрузчик
кладёт их в заголовок следующего элемента, `slots[0]` пуст (6 входов OLD == NEW).

Исправление (проверено в памяти, не в дереве): не трогать элемент, который эффективно flow. Эффективный стиль —
`_ORIG_STYLE` из `item.__dict__`, если он есть (контейнер опустел и наполнился снова: `finalize` вернёт стиль только при
обходе самого элемента, а `_lift_item_tail` зовётся при обходе родителя), иначе `item.fa.flow_style()`. С такой охраной
4 flow-входа выше дают байты OLD, B1–B9 все зелёные. Наивная проверка `item.fa.flow_style()` ломает B8 и B9 (проверено) —
не использовать. Текстовая эвристика `startswith("#")` запрещена DESIGN 2 — не использовать. Тест: правка постороннего
ключа в файле с `- {a: 1}  # q` и `- [1, 2]  # q` (первый и не первый элемент, с `ka:  # e` и без) — байты списка
прежние; красный до охраны.

### F2 — minor — `_ruamel_doc.py:61-65` (охрана `not eol`) оставляет склейку у `- {}  # x`

гонял. Решение за лидом: снять охрану и добавить тест на `- {}  # x`, либо записать остаток в OPEN_QUESTIONS/Task 1.3.
Непустой `{x: 1}  # q` этим не лечится (другая ветка, `expect_flow_mapping_key`).

### F3 — nit — `_ruamel_doc.py:46-62` комментарий и поправка №5 называют не тот механизм

### F4 — minor — комментарий перед следующим соседом уезжает к заменённому элементу (следствие поправки №5)

| flow: `k: [{}, {a: 1}]`, `k: [{}]`, `k: [{}, {}, 1]`, `k: {a: {}, b: 1}`, `- [{}, 1]  # x`, 900 штук `{}` в строке | равны | равны |
| конец документа: `ka:  # e\n  - a\n  - {}\n`, `ka:\n  - {}\n`, `- a\n- {}\n`, `{}`, `? {}\n: 1` | равны | равны |

В 12000 документов: 130 расхождений, все «склейка -> валидно»; регрессий 0; «оба валидны, но разные» 0; для режима
«EOL у пустых контейнеров» остаток «то же, но невалидно» был 9 в р1, стал 0.

Единственный входной случай, где текущий эмиттер проигрывает р1-эмиттеру: `ka:  # e\n  - {x: {}, y: 1}  # q\n  - a: 1\n    b: 2\n`.
Р1-эмиттер чинил его случайно (сброс на вложенном `{}` внутри flow), текущий не чинит: вывод равен стоку `- a: 1 b: 2`.
Это тот же остаток, что в п. 3; до 1.1i поведение такое же.

## 3. Остаток автора: `- {x: 1}  # q` после EOL-комментария ключа

Вход `ka:  # e\n  - {x: 1}  # q\n  - a: 1\n    b: 2\nkb: 1\n`. Запуск на `c2ab057e4` (OLD) и на `8b4e972b6` (NEW):

```
load -> dump  OLD: 'ka:  # e\n  - {x: 1}  # q\n  - a: 1 b: 2\nkb: 1\n'   (PyYAML: ScannerError)
load -> dump  NEW: тот же байт в байт
patch kb 1->2           OLD: ValueError              NEW: YamlWriteRefused   — байты и mtime целы в обоих
patch ka[1].b 2->3      OLD: ValueError              NEW: YamlWriteRefused   — байты и mtime целы в обоих
```

Склейка есть и до 1.1i, и после, одинаковая. Файл не пишется: невалидного или неверного файла не появляется, отказ
громкий (до 1.1i `ValueError` из `_verify_dump`, сейчас его подкласс `YamlWriteRefused`). Это не регрессия, старое
поведение. Цена остатка: файл с таким стилем нельзя сохранить вообще (любая правка, хоть постороннего ключа, получает
отказ). Без EOL-комментария ключа (`ka:\n  - {x: 1}  # q\n...`) склейки нет: правка пишется, комментарий на месте (OLD
и NEW равны). `- [x, 1]  # q` после `ka:  # e` склейки не даёт. В 22 боевых рецептах `- {...}  # c` нет (`git grep`, р1).
Лечится, вероятно, отдельным переопределением ветки закрытия непустого flow-map с EOL (`expect_flow_mapping_key`); я это
не пробовал.
