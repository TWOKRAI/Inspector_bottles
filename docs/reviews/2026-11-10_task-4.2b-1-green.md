## Что оставил открытым и ненадёжно

1. **Длина командной строки на Windows (не проверено).** Все пути паспорта идут в `argv` одного `git diff`. У
   символа с сотнями файлов `used_by`/`call_sites` строка может превысить лимит `CreateProcess` (32 767 символов).
   Тогда `subprocess` бросит `OSError` (не `AtlasError`), и паспорт упадёт. DESIGN ловит только `AtlasError`, я
   его не расширял. Максимум путей паспорта по репозиторию не мерил. Варианты для решения лида: `git diff` без
   pathspec + пересечение (тот же один вызов, но diff всего дерева), или ловить `OSError` -> `null`.
2. `--no-renames` и `--literal-pathspecs` тестами не ловятся: фильтр пересечением с путями паспорта скрывает
   разницу. Лид об этом знает, флаги стоят по DESIGN.
3. Строки `FREEZE` в докстринге с экранированием `\n` или продолжением строки `\` внутри литерала дадут сдвиг
   `line`. Это ограничение схемы «`Constant.lineno` + индекс» из DESIGN 3; тестом не закрыто.
4. Пропуск звена с `error` в `_frozen` сейчас нельзя наблюдать: у непарсящегося файла `freeze=()`. Ветка
   `pkg.error is not None` — эквивалентный мутант. Наблюдаемо только то, что обход идёт дальше (I1).
5. Тёплое время 1,27 с против 1,64–1,81 с в 4.2a. Сравнение между сессиями не доказывает ускорения; предел 2,0 с
   выполнен с запасом.
6. `scripts/atlas/DECISIONS.md` — 94,6 KB при бюджете 32 KB (хук doc-size-guard). Файл был большим и до задачи;
   моя правка — +9 строк. Делить файл — не эта задача.
7. В `test_one_git_diff_per_passport_none_in_resolve` подменён `passport.git_z`. Тест держится за имя импорта
   (implementation API) ради контракта «один вызов на паспорт» из DESIGN 1. При переименовании импорта тест
   упадёт, а не пропустит поломку.
