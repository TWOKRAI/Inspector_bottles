## Q1 — ведомость исходов на узле-исполнителе

**Решение:** исход кадра = широкая запись плагина-решателя (`robot_control`). Storage — ведомость кадров, не исходов.
Маркер `stale_exec`/`door` с `source=inspector`, у чьего `trace_id` есть строка журнала, — надгробие кадра («осмотрен,
копия кадра испорчена»), не второй исход; без строки журнала — pre-chain, «не осмотрен». Поле маркеру не нужно.

- R1 (риг `test_frame_ref_gen`, every): журнал `[('t1','verdict')]`, в storage 2 маркера `stale_exec`, результатов 0.
- **Вариант ревьюера (не делать post-chain stale в процессе с `accepts_markers`) отвергнут.** R1b: без post-chain проверки
  результат уходит, и дверь того же процесса заменяет его маркером `door` — дубль переезжает на хоп ниже. Плюс
  `accepts_markers` — не тот сигнал: `[blob_detector, robot_control]` пропустила бы вердикт по рваным пикселям.
- R1c: при `reject_delay_ms ≥ глубина/fps` маркером становится каждый брак (ring 3, sleep 30 мс → 10/10; 20 мс → 0/10).
  Стенд: глубина 8 @100 fps = 80 мс, умолчание задержки 0 — редкая гонка. Под `latest` тот же брак сегодня молча
  выпадает из storage — дефект старше 4.7d.

Код не меняется. Спека 4.7d-5: два инварианта (storage: результат XOR маркер на `trace_id`; журнал: ровно одна строка на
`trace_id`, дошедший до цепочки) и кросс-ведомость `J = |вердикты журнала ∩ маркеры storage с source=inspector| ≤
not_inspected_stale_exec(inspector) + not_inspected_door(inspector)`. ADR фиксирует чтение и порог `reject_delay_ms ≥
ring_depth/fps`; строка в README `robot_control`. Стенд: J при delay=0 (ожидание ≈0) и прогон с `reject_delay_ms=100`
(ожидание J ≈ числу браков). Если J>0 при delay=0 — отдельная задача после стенда.

## Q2 — потолок склейки маркеров

**Решение: потолка в 4.7d нет.** Потолок уже есть и считается: IPC data-очередь соседа `drop_oldest` + `data_evicted`
(ADR-173); 2000 маркеров → приёмник соседа принял 64, `overload_events=1`. Рост головы ограничен длительностью стоянки:
351 Б/маркер, @100 fps ≤ 35 КиБ/с, худшее 346 МиБ/ч — вопрос watchdog. Голова дешева: 23.7 мкс/кадр при 19998 маркерах,
дренаж 19998 отправок за 10 мс. ADR — абзац «голова не ограничена на время стоянки; потолок — когда стенд покажет RSS > X».
Стенд: `pause_event` исполнителя 10 с под `every` → длина головы ≈ fps×10, ΔRSS, время дренажа, `data_evicted` соседа.

**Находка для владельца:** `robot_control` с `reject` и `delay>0` отработает задел по задержке на каждый маркер
(20k × 100 мс = 33 мин отбраковки ушедших бутылок) — потребитель должен старить маркеры по `capture_ts`. → OPEN_QUESTIONS.
