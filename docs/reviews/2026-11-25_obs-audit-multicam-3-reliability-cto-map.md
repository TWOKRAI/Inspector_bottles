### 8.2 Нейросети в конвейере

- Место: `MLInferencePlugin` — processing-плагин внутри процесса пайплайна (`Services/ml_inference/plugin/plugin.py:75-85`, `thread_safe=False`). Своего процесса, пула и выбора номера GPU нет; устройство `cpu|cuda` (`registers.py:34-36`); torch молча откатывается на CPU (`torch_backend.py:51-52`) [помощник]. В рецептах quad инференса нет.
- Медленный потребитель не тормозит камеру: кольцо SHM перезаписывается. Потери по причинам: data-очередь вытесняет старые (`queue_data_evicted`), DataReceiver отбрасывает по лагу (`lag_dropped_items`, у draw_1 2506 [запуск]), кольцо перезаписало слот (`not_inspected_stale_restore`). Внутри процесса цепочка блокируется («Q6 — не дропаем», `data_receiver.py:411-420`) [код]; `overflow="latest"` только хранится, поведения нет (`data_receiver.py:145`) [код].
- Наблюдение: средняя/последняя/максимальная задержка, `inference_fps`, `active_providers` (`plugin.py:408-431`) [помощник]. Нет загрузки GPU и VRAM, версии и хэша модели, возраста кадра на входе, `declare_metric`.
- Если инференс медленнее камер: теряются кадры с отметками «не проинспектировано»; возраст кадра на входе не ограничен очередью 64 (`generic_process.py:146`) [помощник]. Для инспектора это решение о браке, не только метрика.
- Как должно быть: на входе инференса тот же LatestMailbox по sender (`process_module/generic/latest_mailbox.py`), он уже в framework и проверен фазой A: возраст кадра ограничен, камеры получают инференс поровну. При одном GPU и N≥8 альтернатива — один процесс на GPU с пакетами; решает CTO.
