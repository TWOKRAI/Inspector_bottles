## Что я ИНТЕРПРЕТИРОВАЛ, а не выполнил (каждое — кандидат на «неверную модель, навязанную как контракт»)
1. Форма `RawFrame`: контракт даёт «байты изображения + разобранный список кодов» без имён. Взято
   плоско: `image, width, height, pixel_type, trigger_index, frame_num, no_read_num, codes`, где `codes[i]`
   — копия `BCR_INFO_EX2` с C-именами полей. Все догадки собраны в `_frame_view`/`_code_view` (блок HOOKS).
2. `sdk.loader.IDMVS_PLUGIN_DIR` — модульная константа (по указанию лида). Подменяется `monkeypatch.setattr(..., raising=True)`.
3. `open()` при `OpenDevice != 0` обязан САМ вызвать `DestroyHandle` для созданного handle и поднять
   `SdkError` (`test_open_access_denied_raises_sdk_error_and_destroys_created_handle`). Вывод из отсутствия у
   вызывающего handle; контракт молчит.
4. `close()` при ошибке `CloseDevice`: тест допускает и raise, и молчание, требует только `DestroyHandle`.
5. `enum_devices` спрашивает слой `GIGE_DEVICE` (=1), `ip` — точечная запись из `nCurrentIp`, старший байт первым.
6. Нулевой указатель списка кодов -> `codes` пуст, без исключения (контракт не описывает).
7. `load_library`: подмена `ctypes.WinDLL` и `os.add_dll_directory` на уровне модулей `ctypes`/`os`
   (реализация обязана звать их через `ctypes.WinDLL(...)`/`os.add_dll_directory(...)`, а не через `from ctypes import`).
8. Имена полей ctypes = имена из заголовка (`nCurrentIp`, `SpecialInfo`, `UnparsedBcrList` ...). `SpecialInfo` проверен только по смещению/размеру.

## Что осталось открытым / ненадёжно
- Не Windows -> `SdkNotFoundError`: НЕ тестировал (реализация может проверять `sys.platform`, `os.name` или `hasattr(ctypes, "WinDLL")`; любая подмена навязала бы выбор).
- Реальная DLL и прибор не использованы вовсе: раскладка сверена только с моей арифметикой по заголовку, не с `sizeof` на C-стороне. Зелёный контроль (ниже) подтверждает согласие моей арифметики с ctypes, но не с компилятором MSVC.
- `nCodeNum > 300` (мусор из SDK) не тестирован: контракт молчит, а чтение за границей массива в ctypes — это IndexError или чтение чужой памяти.
- Кодировка `chCode` (GBK/UTF-8) не тестирована; `RawFrame` хранит байты, декод — задача 6.2.
- `import` в подпроцессе проверяет только загрузку DLL с именем `MvCodeReader*` через `ctypes.WinDLL`; загрузку через `ctypes.CDLL`/`windll` не ловит.
- Тесты с `_run` защищены дедлайном 10 с от зависания; у подпроцесса дедлайн 120 с.
