## Решение: вариант (d)

Фундамент определяется по именам процессов `manifest.base`, а не по флагу `protected`; флаг из правила 1.14 убрать.
Почему: `protected` метит два разных класса (`gui` — узел рецепта, `devices` — фундамент), а цель C-30 — не писать в рецепт именно фундамент; имя известно там, где фундамент подмешивают (`app.py:72-74`), это один `frozenset`, не новый слой.
Отвергнуты: (a) убирает функцию «копия живого графа в выбранный рецепт» для 3 из 22 рецептов (принцип 2); (b) эвристика по ссылкам, вернёт `devices` в чужой файл всякий раз, когда его адресуют `chain_targets`; (c) возвращает шум фундамента на двух путях.

## Форма правки

1. `TopologySession.foundation_names: frozenset[str]` + `capture_foundation(names)`; ставится один раз в `app.py` из имён процессов фрагментов `manifest.base` (там же, где слияние); в `RecipeActivated` не нужно.
2. `save_editor_topology_to_recipe(..., foundation: frozenset[str] = frozenset())`; `_editor_owned_topology(topology, doc, foundation)`: из редактора убрать процессы с именем ∈ `foundation`; файловые с именем ∈ `foundation` — теми же элементами по якорю
   предшественника; `_is_protected` и `protected_names` убрать. Три вызывающих (`app.py:120`, `layout_controller.py:470`, `recipes/presenter.py:601`) передают `foundation=session.foundation_names`. Пустой `foundation` -> правило no-op.
3. `expected_rev=None` и чужой slug — без особых веток: правило не зависит от базы.

## Тесты и замеры, подтверждающие (d)

F2 в оба целевых рецепта (процессы B `== ['synthetic_source', 'gui']`, `store.read` читается, `devices` нет); тот же slug `bridge_synth` без сцены `+0/-0` и с базой, и с `expected_rev=None`; `webcam_sketch` тот же slug в обоих режимах `+0/-0`;
