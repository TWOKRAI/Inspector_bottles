## Что я интерпретировал, а не следовал буквально

1. **`RegistersManager.from_catalog` не инстанцирует НИ ОДНОГО регистра** — только
   наполняет `_fields_cache` через `FieldInfo.from_dict()` и `_plugin_categories`.
   `register_names()`/`get_categories()`/`model_dump_all()` на таком менеджере вернут
   пусто — сознательно: единственный реальный потребитель (`params_form_section.py`)
   зовёт только `rm.get_fields(plugin_name)`, и RED-тест (`test_form_schema_without_
   plugin_code`) тоже не идёт дальше construction. Если появится второй потребитель,
   ждущий `register_names()` от catalog-based менеджера — это находка, не мой баг.
2. **`CommandCatalog.from_catalog` строит `commands` как identity-словарь `{name: name}`**
   вместо реального `{публичное_имя: метод_плагина}` — на wire едет только СПИСОК имён
   команд (`entry.commands: [str]` по брифингу), метод плагина физически не пересекает
   границу вместе с классом. `resolve_field_command`/`resolve_action_command` смотрят
   только на членство `in pc.commands` и на сам `command_name` — identity-маппинг для
   них неотличим от настоящего. Если где-то код читает `pc.commands[x]` ожидая имя
   МЕТОДА (а не команды) — это разойдётся; не нашёл такого потребителя в scope задачи.
3. **`FieldInfo.from_dict` для тега `unsupported` восстанавливает `field_type=object`**
   (не сохраняет исходный Python-тип — физически невозможно после сериализации).
   `object` сам классифицируется обратно в `unsupported` через `_type_tag`, поэтому
   round-trip тега стабилен; проверено ТОЛЬКО синтетически (test_fieldinfo_unknown_
   type_is_unsupported_not_exception) — среди 62 реальных плагинов ни один field не
   бьёт в `unsupported`-ветку (см. hazard-тест 4: весь каталог JSON-safe без единого
   `default=str` фоллбэка на реальных данных, значит и unsupported-тег среди них не
   встретился).
4. **`Literal` default НЕ восстанавливается в специальный тип** — от `from_dict` он
   идёт как есть (обычно str/int), только `field_type` оборачивается в `Literal[...]`.
   Path и tuple3int default — восстанавливаются в исходный Python-тип (`Path`, `tuple`)
   явно, т.к. это было прямо в hazard-требовании брифинга; для Literal явного
   требования не было, оставил default как JSON-примитив.
