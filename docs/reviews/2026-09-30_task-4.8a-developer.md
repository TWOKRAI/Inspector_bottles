## Что я трактовал, а не выполнял по букве

1. **venv-редиректор Windows (главное отклонение).** Первый прогон дал 6 красных: `ProcessCpu(Popen([sys.executable…]).pid)`
   читал 0.0 ядра. Причина (замерено `psutil`): `.venv/Scripts/python.exe` — редиректор, настоящий интерпретатор —
   его единственный потомок (`…\uv\python\cpython-3.12.12…\python.exe`), busy-цикл крутит внук. Ни тесты tester,
   ни DESIGN этого не учитывали. Решение: `cpu_probe._resolve_launcher(pid)` — на Windows в venv, если exe процесса
   совпадает с `sys.executable` и у него ровно один потомок, читается потомок. Для pid, полученных из процесса
   (стенд: `introspect_status` отдаёт `os.getpid()` настоящего интерпретатора) ветка не срабатывает. Плюс в
   `clock_selfcheck` перед `child.kill()` убиваются потомки `psutil`-ом. Это не в DESIGN — прошу подтвердить.
2. `passport.commit`: тест `not_a_repo` красный, потому что `%TEMP%` лежит внутри домашнего git-репозитория
   пользователя и `git -C tmp rev-parse HEAD` возвращал ЧУЖОЙ HEAD. Добавлена сверка `rev-parse --show-toplevel`
   с `repo` (`os.path.samefile`); подкаталог репозитория как `repo` теперь даёт `commit=None`. Не в DESIGN.
3. `run_case.py`: «keys of recipe["processes"]» — в рецепте `processes` это СПИСОК словарей, взяты `process_name`.
   Опрос `system_overview` раз в 2 с оставлен по спеке; его `hz` попадает в результат только как запасной, если
   `state.fps` из телеметрии пуст (спека: `hz` = `state.fps`).
4. `run_case.py` при импорте как часть пакета (тесты) использует относительный импорт, при запуске скриптом —
   `sys.path.insert` по DESIGN; так `import fields`/`import cpu_probe` не засоряют `sys.path` процесса pytest.
5. `extract_fields`: `shm` = `None`, если в `state.shm` нет ни одного из пяти ключей контракта (пустой dict
   не возвращается); нечисловые значения в числовых полях (в т.ч. `bool`) считаются отсутствующими.
6. Формат отчёта в спеке не задан: числа с двумя знаками, `None` — «—», заголовок кейса содержит метку
   `baseline`/`candidate` (тест этого требует). `freq_mhz` — `psutil.cpu_freq().current` (на этой машине 3100.0,
   что равно `~MHz` из реестра, т.е. это НОМИНАЛ, а не реальная частота под turbo).
7. Рецепт рендерится через `yaml.safe_dump(sort_keys=False)`: комментарии базы в отрендеренном варианте пропадают.
8. Упавший кейс: `run_matrix` дописывает результаты в общий список по мере готовности, `main` ловит исключение,
   печатает в stderr, пишет отчёт с готовыми кейсами и возвращает rc 1. В спеке «всегда write_report» — трактовка.
