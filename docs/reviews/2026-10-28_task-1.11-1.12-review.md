## Находки

### 1. [architecture, major] Удаление дисплея без привязки в файле двигает базу, пока в модели редактора висит несохранённая привязка к нему -> Save пишет рецепт, который не читается

Воспроизведено запуском (проба `scratchpad/rev/test_probe_rev.py::test_p1_dirty_binding_to_deleted_definition`, настоящая цепочка
каталог -> `RecipeStoreFromManager` -> `RecipeManager` -> tmp-копия фикстуры A, настоящая `TopologySession`).

Вход: база захвачена; `register("probe_disp")`; редактор (несохранённо) добавил привязку `recog.ml_inference.frame -> probe_disp`;
`unregister("probe_disp")` (в файле привязки нет -> ветка `_write`, база сдвинута); Save редактора
(`save_editor_topology_to_recipe(..., expected_rev=session.base_rev_for(slug))`).

Наблюдаемо: Save вернул `rev` без ошибки; `store.read(slug)` -> `ValidationError: Ссылка на несуществующий display_id: 'probe_disp' — определение отсутствует`;
в файле `blueprint.displays` содержит `probe_disp`, а `displays` — только `main, recog, mask, phone`.
Контроль (та же последовательность, но каталог без сессии, база стоит): Save -> `RecipeConflict`, файл цел.

Причина: `save_editor_topology_to_recipe` проверяет структуру blueprint (`validate_recipe_blueprint`), но не ссылки привязок на
определения `displays` верхнего уровня (их проверяет только валидатор модели `Recipe`, а Save пишет канон через `save_raw`).
До 1.11 эту дыру закрывал ложный конфликт Save (база не двигалась после записи Дисплеев). 1.11 убрал ложный конфликт и открыл путь.
Относительно `main` это не регресс (там Save вообще без сверки), относительно инварианта CTO «без молчаливой потери данных» — дыра.
Редактор на `DisplaysChanged` не подписан (`git grep DisplaysChanged` -> подписчик один, `app.py:1106`, главная панель), поэтому
устаревшая привязка в модели достижима через UI: создать дисплей -> привязать выход к нему в редакторе -> удалить его во вкладке «Дисплеи» -> Save.
Шаг UI «привязать в редакторе к дисплею из файла» не прогонял — по чтению.

Fix (решение выше задачи, FILES 1.11 это не покрывает):
- (A, рекомендую) `recipes/save.py::save_editor_topology_to_recipe`: до `save_raw` проверить, что каждый `display_id` из
  `after["blueprint"]["displays"]` есть среди `id` в `after["displays"]`; иначе `RecipeValidationError` (текст без значений
  входа — id дисплея не секрет, как в валидаторе модели). Закрывает и путь Q1f, и этот. Тест: проба 1 как RED.
- (B) в `unregister` вообще не двигать базу (запись с `expected_rev=base`, без `rebase`) — защита от ручной правки остаётся,
  но D7/F тестера («unregister без привязок двигает базу, Save ок») придётся переписать, а ложный конфликт Save вернётся.
Решение сужает вердикт CTO по Дисплеям -> ESCALATION ниже.

### 2. [UI, minor] Конфликт при переключении «Показывать в главной области» оставляет чекбокс в новом состоянии, файл в старом
