## Ответы на вопросы брифа
- keep-alive: HTTP/1.0 → `handle()` обрабатывает ровно один запрос, флаг на экземпляре = флаг на запрос. Конфликта с pipelined-запросом или прочитанным телом не воспроизвелось (0/200).
- DoS: ≤2 с и ≤1 МиБ на соединение; часы GetTickCount64 с шагом 15.6 мс дают перебег 18 мс — несущественно. Потоки daemon, `server_close` их не ждёт. Долг B (read без таймаута, без границы) хуже и не ухудшен фиксом. Для локального пульта с проверкой Host приемлемо.
- `except OSError: return` — только RST/таймаут/уже закрытый сокет, то есть поведение клиента. Логгер у обработчика отсутствует намеренно. Не находка.
- GET/стриминг: в pult_web нет ни MJPEG-прокси, ни SSE (`<img>` указывает на внешний 8091). GET без Content-Length выходит из linger на строке 893.
