# Приёмка плана lifecycle-graceful-stop — вердикт CTO (Fable), 2026-09-24

> Записано ведущим по отчёту CTO (роль без Write). База `277d96e8..92dab480`. Скрипты repro — scratchpad
> сессии (`sigkill_repro.py`, `false_alarm.py`, замер размеров сообщений через sitecustomize).

**VERDICT: ACCEPT_WITH_DEBT.** Механизм работает и честно протестирован (стенд 10/10 1.29–1.43 с, PM exitcode 0;
16/16 тестов под spawn, forkserver и fork), но это компенсация, а не лечение: метка привязана к одному триггеру
останова и лечит следствие того, что по 64-КБ pipe'ам летят сообщения по 0.3–1.2 МБ. Откатывать не надо.

## Три линзы
1. **Причина или симптом — симптом.** Замер (`len(pickle)` на `Queue.put`, 3 прогона): `gui/data` avg 745 КБ, max
   1 229 548 Б; `renderer/data`, `inspector/data`, `storage/data` — 307 848 Б (маска 640×480 из `blob_detector.py:106`
   inline); `processor/data` — 448 Б (claim check только для ключа `frame`, `frame_shm_middleware.py:661`). Feeder
   ВСЕГДА посреди сообщения, когда читатель ушёл. ADR-SRM-015 — лечение корня; ADR-SRM-016 — заплатка на выход писателя.
2. **Скрытые костыли — есть, два воспроизведены** (№1, №2 ниже).
3. **Направление — не мешает, но не готово к Пульту.** Слои верные; наблюдаемость — по букве, не по сути (№3);
   кнопка «стоп» внешнего Пульта пойдёт через `system.shutdown` — незащищённый путь (№1).

## Костыли и риски
1. **HIGH, сегодня — `system.shutdown` без метки.** `BackendDriver.system_command({"cmd":"system.shutdown"})`, 3 прогона
   (8853–8855): **5.83 / 1.39 / 1.28 с**, в первом `Process 'renderer' did not stop in 5.0s, terminating...`, при этом PM
   exitcode 0. `process_manager_process.py:639 _cmd_system_shutdown` взводит только `self.stop_event`. Решение CTO по
   контракту: `system.shutdown` == системный стоп, обязан взводить `system_stop_event`.
2. **HIGH, на Orin с зависшей камерой — знание не там.** Читатель, убитый `terminate/kill` (`process_registry.py:334-338`),
   метку не ставит; хук писателя ждёт вечно. `sigkill_repro.py`: кадр 921 600 Б, читатель `kill()` → хук «STILL BLOCKED
   after 3.01s»; внешний `mark_reader_gone()` → мгновенно `(1, 0)`. Метку должен ставить владелец жизненного цикла — PM.
3. **MEDIUM, сегодня — строка потерь шумит без потерь.** `false_alarm.py`: всё прочитано, буфер 0, метка → `(1, 0)` →
   WARNING. Живьём 25 строк за 10 циклов, у PM каждый раз `7, buffered dropped: 0`. Метка проверяется раньше, чем feeder
   выходит по sentinel после `close()` (`reader_gone.py:112-119`). Настоящая потеря (pipe + в полёте) не считается.
4. **MEDIUM, корень — 0.3–1.2 МБ в pipe**; ~40 МБ/с pickle при 25 fps на четырёх хопах; `storage` получает маску 308 КБ на кадр.
5. **LOW, позже — приватные внутренности CPython**: в 3.13.13 и 3.14.7 имена и `__getstate__` те же; сбой — громко
   (`_sentinel` на импорте) или деградация до старых 5 с через `except` + `emergency_log`. На Linux default `fork`
   (`platforms/base.py:17` форсирует spawn только на win32) — Event наследуется; fork/forkserver на macOS 16/16.
6. **LOW — `close()` всех известных очередей в хуке**: поздний put даст `ValueError`, глотается как потеря. По чтению.

## Как правильно
- **Оставить:** ADR-SRM-015; `ReaderGoneQueue` как транспорт метки; «ждать слив, если не помечено» (защищает медленного читателя).
- **Заменить триггер:** метку ставит **PM** — после join/terminate/kill ребёнка без рестарта и при `system.shutdown`
  (который взводит `system_stop_event`); самопометка детей остаётся быстрым путём. Строку потерь печатать только при
  `buffered_dropped > 0` или feeder, живом через один poll после `close()`. Строки плана **L-5**, цена **S**, успеть **до gui-service 1.3a**.
- **Убрать корень:** claim check с ключа `frame` на объявленный набор image-портов (`mask`, отрисованный кадр) — ndarray > N КБ
  через SHM, сообщение ~1 КБ, окно зависания сжимается на 2–3 порядка + IPC-выигрыш. Строка в rework/QUEUE, цена **M**.
- **Отвергнуто CTO:** закрывать read-конец у не-читателей (EPIPE пришёл бы сам) — несовместимо с `restart_reuse_queues`;
  порядок «источники → приёмники» и двухфазный стоп — после двух пунктов выше не нужны.
