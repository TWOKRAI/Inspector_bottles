### 1. [major, quality] `DECISIONS.md:586-587` — утверждение про ключ `0:` неверно для листового пути

ADR пишет: «Целый ключ `0:` в ручном файле переписывается в строку `'0'`, комментарий при нём теряется».

Вход (запуск `RecipeEngine(store=TreeStore({"cameras": {"0": {"config": {"fps": 2}}}}), recipe_version=2).save("p", paths=["cameras.0.config.fps"])`
на файле `meta: {name: p, version: 2}` / `data:` / `  cameras:` / `    0:` / `      config: {fps: 1}  # c`):

```
  cameras:
    0:
      config: {fps: 1}  # c
    '0':
      config:
        fps: 2
```

Наблюдено: int-ключ `0:` остаётся со старым значением и комментарием, рядом дописан второй ключ `'0'` (PyYAML читает `{0: ..., '0': ...}`).
Строкой ключ становится только когда путь снимка указывает на родителя (`paths=["cameras"]` и `["cameras"]` с комментарием на строке ключа дали
`'0':` без `0:`, комментарий потерян). Причина по коду: `before = yaml.safe_load(file)` держит int `0`, `_set_nested` по пути из строк создаёт
строковый `"0"` рядом (`recipe_engine.py:225-232`). Первоначальная догадка developer 1.4 («дубль-ключ», `docs/reviews/2026-11-06_task-1.4-developer.md:96`)
верна для листового пути; формулировка «переписывается в строку» взята из ревью 1.4+1.5 п. 8 без указания пути снимка и в ADR попала как общее правило.
Оговорка ADR «на практике недостижимо» (движок ключи кавычит) сохраняется, но факт описан неверно.
Правка: заменить фразу на «ключи путей — строки; целый ключ `0:` в ручном файле не сопоставляется с путём `"0"`: при листовом пути рядом
с ним дописывается строковый `'0'` (int-ключ остаётся), при пути на родителя поддерево заменяется целиком, а комментарий при `0:` теряется».
Брифа 3a(i) автор держался буквально; расхождение унаследовано от брифа, но ADR — итоговый документ.
