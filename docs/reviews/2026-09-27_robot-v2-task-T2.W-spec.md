# T2.W — спецификация приёмки (ведущий, 2026-09-27)

Бриф: `plans/robot-protocol-v2/tasks.md` §T2.W. База: `1491dbe3` (T2.J + T2.J2 слиты). Эта спецификация —
общий контракт для тестера (пишет тесты вслепую) и разработчика: публичные имена, цвета и геометрия
зафиксированы здесь, чтобы пиксельные проверки были писаемы до кода.

## Решения ведущего (сверены с YAML и кодом до брифа)

- **Отметки высот на шкале Z** — только то, что есть в `delta_v2.yaml`: `P_PICK_Z` («pick», глубина забора),
  `P_PLACE_Z` («place», укладка), `P_HOME_Z` («home», дом). Параметра высоты переезда в YAML нет — отметки
  «переезд» нет (бриф: «каких нет — не выдумывать»).
- **RZ(t)** — `TLM_RZ` как есть, без разворота (вердикт cto T2.J2).
- **Время ленты** — часы зрителя (`clock`, по умолчанию `time.monotonic`), не время ядра: вид читает только
  регистры и должен работать поверх настоящего робота (T3/T5), где времени ядра нет. В тестах `clock` подменяется.
- **Раскладка** — три независимых read-only виджета, собирает их `main()`: `SimView` (вид сверху, как был +
  значок RZ), `ZScale` (справа), `TimeTape` (внизу). Каждый со своим `QTimer` `_REFRESH_MS`, останавливаемым
  в `closeEvent` — как у `SimView` (T2.3 `--view` переиспользует виджеты).

## Контракт

### 1. Значок поворота инструмента — `Services/robot_comm/gui/sim_view.py`, `SimView`

- Из TCP (`_to_widget(*_tool_xy())`) рисуется **указатель**: отрезок длиной **30 px**, перо **3 px**, цвет
  **`#ffb86c`**, направление — угол `TLM_RZ` в градусах: RZ = 0 → +X робота (вправо на экране), рост RZ —
  против часовой стрелки на экране (+Y робота вверх). Указатель рисуется поверх цепей, шлейфа и маркера TCP.
- Указатель рисуется и при `joints() is None` (RZ — ось позы протокола, модель не нужна).
- Существующее API `SimView` (`refresh`, `scene_chains`, `status_text`, `_to_widget`, `_tool_xy`,
  `widget_to_robot`, `clicked`) не меняется.

### 2. Шкала Z — `Services/robot_comm/gui/z_view.py`, `ZScale(core, parent=None)`

- `refresh()` — перечитать ядро (только чтение) и запросить перерисовку.
- `z_value() -> float` — текущий `TLM_Z`, мм.
- `z_limits() -> tuple[float, float]` — `(P_WS_Z_MIN, P_WS_Z_MAX)` в мм, **читаются заново** на каждый
  `refresh()` (`PARAM_SET` меняет их в рантайме).
- `marks() -> dict[str, float]` — ровно ключи `{"pick", "place", "home"}` → `P_PICK_Z`, `P_PLACE_Z`,
  `P_HOME_Z` в мм, читаются заново на каждый `refresh()`.
- `z_to_widget_y(z) -> float` — вертикаль: `z_max` вверху, `z_min` внизу, строго убывает по z.
- Отрисовка: горизонтальные линии **на всю ширину** виджета (x от 0 до width), перо **3 px**:
  границы зоны `#ff5c57`, отметки `#8be9fd`, текущий Z `#5af78e`. Порядок: границы → отметки → текущий Z
  (текущий сверху). Подписи — не левее x = 12 px. Столбец x = 4 свободен от подписей (для пиксельной проверки).

### 3. Лента времени — `Services/robot_comm/gui/z_view.py`, `TimeTape(core, clock=time.monotonic, window_s=10.0, parent=None)`

- `refresh()` — одна выборка `(clock(), TLM_Z, TLM_RZ)` в мм/°, затем отбросить выборки старше
  `clock() - window_s`; перерисовка.
- `samples() -> list[tuple[float, float, float]]` — выборки по возрастанию времени.
- Отрисовка: кривая Z(t) цветом `#5af78e`, кривая RZ(t) цветом `#ffb86c`, перо 2 px. Вертикаль Z — по
  `[P_WS_Z_MIN, P_WS_Z_MAX]`, RZ — по `[P_WS_RZ_MIN, P_WS_RZ_MAX]` (обе читаются заново), горизонталь — окно
  `window_s` с правым краем «сейчас».

### 4. Общее

- Ни один из трёх виджетов не пишет в регистры: снимок `core.regs` до и после `refresh()` + `grab()` идентичен.
- `python -m Services.robot_comm.gui.sim_view --quit-after 1` (offscreen) собирает окно из трёх виджетов и
  выходит с кодом 0.
- Все тесты T2.V/T2.J/T2.J2 зелёные.

## Приёмка (tester, offscreen, worktree `team-t2w-tester` на `1491dbe3`)

A1. Значок RZ: при двух разных RZ (например 30° и 120°) пиксель на расстоянии 20 px от TCP по направлению RZ
    — цвет указателя (допуск ≤ 8 на канал); при ±15° от направления — не цвет указателя; после смены RZ на
    втором углу указатель есть, на первом — нет.
A2. Значок RZ при `joints() is None` (сценарий `test_unreachable_pose_no_chains_and_warning`) — есть.
A3. Шкала: `z_value()` = TLM_Z; `z_limits()` = дефолты `(-150.0, 0.0)`; `marks()` = `{"pick": -100.0,
    "place": -90.0, "home": -40.0}` — литералами, не из кода; пиксель столбца x = 4 на `z_to_widget_y(z)` —
    цвет текущего Z; на `z_to_widget_y(z_min)` — цвет границы.
A4. `PARAM_SET P_WS_Z_MIN` → после `refresh()` `z_limits()[0]` новое, `z_to_widget_y` для того же z другой,
    пиксель границы на новом месте. То же для одной отметки (`PARAM_SET P_PICK_Z`).
A5. Лента: ход Z вниз и обратно вверх (ядро тикает, `refresh()` на каждом тике, поддельные часы) →
    `min(z)` выборок = нижняя цель ±0.1, первая и последняя выборки — верхняя; цвет кривой Z присутствует в `grab()`.
A6. Окно ленты: после выборок на протяжении > 10 с поддельного времени самая старая выборка не старше 10 с.
A7. Ни один из трёх виджетов не пишет в регистры.
A8. Смоук — подпроцессом (Qt-приложение не поднять в потоке теста): `python -m Services.robot_comm.gui.sim_view
    --quit-after 0.5` с `QT_QPA_PLATFORM=offscreen`, таймаут 30 с, код 0, в stderr нет `Traceback`.
