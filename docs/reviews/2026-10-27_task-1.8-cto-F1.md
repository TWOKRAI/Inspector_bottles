## Почему (принципы владельца)

- Без молчаливой потери данных только общая база: H2 — конфликт, H3 — успех, Q1d/Q1e — данные целы. Слепой rebase (a)
  теряет ручную правку (H1b); rebase после записи внутри секций редактора теряет данные (Q1c) или портит файл (Q1f).
  Событие (b) без знания секций даёт те же потери — лишний слой.
- Меньше слоёв: `TopologySession` уже в `RuntimeDeps.topology_session` (`frontend/runtime_deps.py:127`), механизм — один
  `expected_rev` модуля `recipe`; нового события не нужно.
- GUI формирует топологию: у секций `blueprint.processes/wires/displays` один владелец — редактор. Команды есть:
  `SetPluginConfig` (`domain/commands.py:99`), `UnbindDisplay` (`:173`).
- Framework не меняется. (c) отвергнут: ложный конфликт и остановка автосохранения на каждой записи Устройств/Дисплеев.
