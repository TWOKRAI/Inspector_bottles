## Воспроизведение

**A. Шов J1 ±180.** hand 1, JOINT `(-458.3, 246.2, -75, 119)` → `(-466.6, 230.0, -75, 119)`, хорда 18.2 мм.
`ik(a,1) = (179.0, -60.0, ·, -0.01)`, `ik(b,1) = (-178.99, -60.0, ·, 358.0)`. Наблюдение:
`tick 1: step=543.5 mm (MAX_STEP_MM=33.3) joints=(-179.0, -60.0, -75.0, 358.0)`, DONE за 1 тик. Частота: hand 1,
3000 случайных пар в зоне с хордой < 100 мм → 51 пара с |ΔJ1| > 180. `max|J1|` по сетке дефолтной зоны = 180.0° для
обеих рук: сектор ±165 ограничивает угол TCP, а не сустав (угол TCP = J1 + сдвиг от J2, до ±58°).

**B. Устаревший TLM_HAND.** P_HAND=0 JOINT (400,100); P_HAND=1 JOINT (100,450); 20 тиков; STOP_REQ=2 → ERRNO 13.
Наблюдение: суставы хода `(68.75, -24.98, ·, -43.77)` (J2 < 0 — левая), `TLM_HAND = 0`,
`joints() = (45.87, +25.0, ·)` — вид рисует правый локоть; следующий LINE → `NAK errno 3 rvals [7]` (R_HAND).
Мануал RL 5.2.8: `RobotHand()` читает текущую физическую руку — контроллер сообщает состояние, а не последнюю точку.
Sim делает наоборот (`TLM_HAND = P_HAND` при DONE).

**C. Заглушки пределов J1 ±132 / J2 ±150** (паспорт DRS по памяти, не сверено): из тех же 3000 хорд 1046 → NAK,
среди принятых |ΔJ1| > 180 — 0. Дефолтная зона (r 100..600, ±165): 66.6% достижимо каждой рукой, 14.6% — ни одной.
Сценарий приёмки T2.J `(-250,350)` hand 1 → J1 = 165.3° → NAK под пределами; смена руки `(400,100)→(100,450)` и HOME —
OK обеими руками. Макс |ΔJ|/хорда на принятых парах одной руки — 1.34 °/мм (у r_min).

## Решения

**Q1 — диапазоны до GATE-1.** Данные модели рядом с `l1`/`l2`: в `RobotModel` — `joint_limits:
tuple[tuple[float, float] | None, ...]` и `joint_speed: tuple[float, ...]` (°/с или мм/с при 100%), выровненные с
`joint_names`; `None` — не ограничен моделью. Z моделью не ограничивать: правда о Z — `P_WS_Z_MIN/MAX` (прошивка),
вторая правда нарушила бы И6. Заглушки: J1 ±132, J2 ±150, J4 ±360 (последнее уже в `params.md:33`), скорости — честно
помеченное число. `make_model` принимает их из spec-dict, `__post_init__` проверяет `lo < hi` и конечность. Не `P_*`:
пределы — физика контроллера, прошивка их не читает. Метода `check_joints()` не заводить. Каждая заглушка — строка
GATE-1 в `plan.md` §2.

**Q2 — суставы как состояние: да.**
- `_joints` при загрузке = `ik(pose, TLM_HAND)`; `None` (вне досягаемости модели) → как сейчас.
- Приём JOINT/HOME: `j_end = ik(target, P_HAND)` (J1/J2 при фиксированной руке единственны); вне `joint_limits` →
  NAK `E_RANGE`, reason `R_OUT_OF_ZONE`, в одном месте, ⚑ GATE-1. Другой дороги для J1/J2 нет: у J1 SCARA упор.
  J4 — оборот `j4 + 360k`, ближайший к текущему в пределах ±360; нет такого → NAK (⚑ GATE-1).
- Прогресс: lerp от состояния к `j_end`, состояние пишется каждый тик, финальный тик — цель точно.
- `TLM_HAND` выводится из состояния при каждой записи позы (знак J2; J2 == 0 — прежняя). `_abort` не править.
- LINE/JOG не меняются, но состояние следует `ik(pos, TLM_HAND)` каждый тик (J4 — ближайший оборот).
- Фолбэк `ik → None` — только для недосягаемости по радиусу; нарушение предела в фолбэк не попадает.

NAK, а не ACK + `E_MOTION_FAULT`: функции предпроверки достижимости в мануале RL не найдено (отрицательный grep);
прошивка, вероятно, узнаёт о недостижимом суставе по аварии в `MovP`. Выбор NAK живёт в одной ветке одного метода;
клиент T3.1 обязан обрабатывать оба пути; новый reason-код без факта с прошивки не вводить.

**Q3 — длительность.** `duration = max(T_cart(T2.2), max_j |Δj| / v_j)`,
`v_j = joint_speed_j × P_SPD_J/100 × spd_pct/100` (сейчас JOINT берёт `P_SPD_L` — `sim_core_v2.py:683,701`).
Продвижение за тик — доля пути с тем же `MAX_STEP_MM` на эквивалентной длине `duration × speed`. В докстринге:
декартов пол — совместимость с контрактом T2.2, не физика (мануал 1.1.1: `MovP` — все оси одновременно; реальный
JOINT обычно быстрее LINE). Потолок только по шагу сустава отвергнут: не зависит от `spd_pct`.

**Q4 — объём.** Выделить в **T2.J2** с полной цепочкой (tester до кода в worktree на `b4cbbcf3` → developer →
инъекции ведущего → reviewer), не «итерацией 2»: это новый механизм, на который сядут T2.W, T2.3, T2.4. `b4cbbcf3`
отдельно не сливать (три ложных утверждения докстринга и телепорты коротких ходов). Находки ревью T2.J 2 и 3
(устаревший `TLM_HAND`, мёртвый ключ `"start"`) — в T2.J2. Тестеру: сценарий `(-250,350)` hand 1 под заглушками —
NAK; точки брать с запасом |J1| ≤ 100.

## Свойства приёмки T2.J2 (вход → наблюдаемое; каждое ломается отдельно)

1. **Шов исчезает.** hand 1, JOINT `(-458.3, 246.2, -75, 119)` из HOME → NAK `E_RANGE` `[R_OUT_OF_ZONE]`,
   `TLM_ACTIVITY` 0, `TLM_X` не менялся; тот же таргет при `P_HAND=0` → ACK, каждый тик `check_point == 0`, шаг
   XYZ ≤ MAX_STEP_MM, DONE. Слом: убрать проверку пределов.
2. **Предел — не фолбэк.** Тот же NAK-таргет: ни одной записи позы. Подлинная недосягаемость (`P_WS_R_MAX=700`,
   `(650,0)`) → по-прежнему ACK + декартов путь. Слом: завести нарушение предела в ветку `ik → None`.
3. **Рука по факту после стопа.** Репро B → после `E_ABORTED`: `joints()` == суставы тика (J2 < 0),
   `TLM_HAND == 1`, `ik(pose, TLM_HAND)` ≈ `joints()` (≤ 1e-6); следующий LINE `(100,450)` при P_HAND=1 → ACK;
   следующий JOINT при P_HAND=0 стартует без скачка. Слом: `TLM_HAND = P_HAND` только при DONE.
4. **`joints()` — состояние, не `ik` позы.** На 20-м тике смены руки `joints()` == lerp (J2 < 0), хотя
   `ik(pose, 0)` дал бы J2 > 0. Слом: `joints()` через `ik`.
5. **Ближайший оборот J4.** Таргет, чей сырой `rz − J1 − J2` вне ±360, но оборот внутри есть → ACK,
   `joints()[3]` = этот оборот, `TLM_RZ` при DONE = цель точно; оборота внутри нет → NAK. Слом: сырой J4.
6. **Время по суставам.** Подставная модель `joint_speed=(1, 1, 1e9, 1e9)`, свинг J1 10°, spd 100, `P_SPD_J` 70 →
   1429 тиков ±1 независимо от хорды; дефолтная `ScaraModel()` на фикстурах T2.2/T2.J → счёт тиков прежний ±1.
   Слом 1: убрать суставный член; слом 2: убрать декартов пол.
7. **Потолок на явном dt для JOINT.** `tick(1.0)` посреди JOINT 150 мм от HOME → ход не завершён, пройденная
   доля = `MAX_STEP_MM / path_len_eq`. Слом: снять `min(..., MAX_STEP_MM)` в суставной ветке.
8. **Пределы из модели.** `make_model({"type":"scara","joint_limits":[[-10,10],[-150,150],None,[-360,360]]})` →
   JOINT в точку с J1 = 20 → NAK; `lo ≥ hi` → `ValueError`; неизвестный ключ → `ValueError`. Слом: пределы в sim.
9. **LINE/JOG нетронуты, состояние следует.** Тесты T2.2 LINE/JOG зелёные без правок; после LINE
   `joints()` == `ik(pose, TLM_HAND)`; следующий JOINT без скачка. Рестарт `regs=old.regs` посреди JOINT →
   `joints()` == `ik(pose_after_restart, TLM_HAND)`. Слом: не обновлять состояние на LINE-тике.

Условие без свойства: переписать `sim_core_v2.py:55`, `:66`, `:99` («тайминг тот же», «повторяет траекторию руки»,
«жёсткий потолок смещения» — ложны на `b4cbbcf3`).

Строки GATE-1 (`plan.md` §2): диапазоны J1/J2 DRS; замер `MovP` при SpdJ 100%; `MovP` в точку с J1 за пределом —
NAK прошивки или авария контроллера; `RobotHand()` после стопа посреди смены руки; RZ −170→+180 через `MovP`.

Что переубедит: GATE-1 покажет, что прошивка не может предпроверить достижимость → одна ветка `_check_motion`
меняется на ACK + `E_MOTION_FAULT`, остальное стоит.

- Репро A: 1 тик вместо 2 у ревьюера (ход выдан сразу по приходе); величина совпадает (543.5 мм/тик).
- 777 passed только с `QT_QPA_PLATFORM=offscreen`; без него два теста окна падают и на `7cdac463` — окружение,
  follow-up для conftest, не для T2.J2.
- Нарушение предела сустава посреди LINE (реальный контроллер встанет аварией, sim примет) — вне T2.J2, открыто
  для T2.3/T2.4.
