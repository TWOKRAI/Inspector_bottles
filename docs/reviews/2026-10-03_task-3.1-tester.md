## Что прочитано строго (выбрано самое строгое чтение)

1. `ready` плана по DESIGN: «не закрыт, …». Закрытый (все DONE) план сам `ready: false`. Поэтому проверяемый план держит PENDING-пункт. P1 в тексте не оговаривает, что у плана есть открытая задача.
2. План без задач вообще — НЕ закрыт («есть задачи и ни одной…»): ожидаемый `A` без задач держит `B` (`open_no_tasks_at_all`).
3. План только из DEFERRED/SUPERSEDED — закрыт (DESIGN прямо: «Deferred/superseded закрыты»).
4. Маркер списка `*`, цитата `>`, ограждение `~~~` читаются как «маркер списка / цитата / ограждение кода» из DESIGN. Если разработчик не хочет их, решение за лидом: тесты `star_list_marker`, `inside_tilde_fence_is_ignored` вычеркнуть.
5. Строка находки `<КОД> <план>[:<id>] <blocking|info> — <текст>`; тест требует `— нет плана <имя>` / `— нет задачи <id>` литералом из DESIGN. Вне §4.1 и вне ORDER — ровно `info`.
6. `after` у неизвестного имени хранит имя (`after: ["ghost"]`, `dep_unknown: ["ghost"]`): DESIGN «Ненайденное имя держит и идёт в `dep_unknown`».
7. Порядок в `after` — порядок записи (`["1.1", "1.0"]`).
8. `DEP_UNKNOWN` — одна строка на пару (ссылка, имя); повтор имени в одном поле — одна строка.
9. `DEP_CYCLE` — ровно одна строка на участника.
