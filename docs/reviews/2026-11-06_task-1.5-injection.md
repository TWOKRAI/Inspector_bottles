## Расхождения (одна строка причины на каждое)

- `b2_json_dump`: ноль красных вместо `I[json_dump]` + `Wdump`. Причина: предфильтр `_PREFILTER` (`yaml`/`recipe`/`canonicalize_gui_positions`) отбрасывает исходник `import json\njson.dump({}, f)` ДО разбора AST — самопроверка не доходит до правила и не может покраснеть ни на какой мутации ветки `.dump(`. `Wdump` тоже ноль: в репозитории нет `json.dump` в файлах с этими подстроками вне allowlist.
- `b4_any_from_dict`: красный только `Wnorm`, нет `I[r4_other_from_dict]`. Причина та же: в `topology = Topology.from_dict(x)` нет ни одной подстроки предфильтра (`from_dict` в нём не числится), `scan_source` возвращает `[]` до AST.
- `c9_r2_no_alias_check`: красные `D[ruamel_alias]` и `Wdump` вместо `I[json_dump]` + `Wdump`. Причина: `I[json_dump]` — см. предфильтр выше; `D[ruamel_alias]` покраснел из-за артефакта моей мутации — без проверки `Name` первая ветка берёт `Y().dump(...)` и падает на `func.value.id` (AttributeError), а не из-за логики формы.
- `c18c_r4_recipe_module`: ноль красных вместо `Wnorm`. Причина: в модуле `recipe` нет вызова из списка R4 (`format.py` только определяет `normalize_recipe_v3_raw`, `__init__` его импортирует) — исключение модуля для R4 живой точкой не проверяется.
- `c19_engine`: ноль красных вместо `Wdump`. Причина: `recipe/yaml_io.py` не импортирует ruamel/`yaml` на уровне модуля (`_ruamel_doc`, лениво) и принимает `yaml` параметром, поэтому ни R1, ни R2 в нём не срабатывают и без исключения.
- `c20_prefilter`: красных больше прогноза — `D[r3_div]`, `D[r3_recipes_dir_attr]`, `D[r4_build]`, `D[r4_canonicalize]`, `D[r4_normalize]`, `D[r4_recipe_from_dict]`, `S[R4:…/recipe_format_hook.py]`, а `S[R3:…/prefs_store.py]` не покраснел (в файле есть `yaml`). Причина: мой прогноз был слишком узким; ключи предфильтра `recipe` и `canonicalize_gui_positions` охраняются самопроверкой.

## Не охраняется (ни один тест не покраснел)

Тестов я не дописывал (по указанию) — только список для лида:

1. **`I[json_dump]` недостижим для правила**: исходник без подстрок предфильтра, `scan_source` выходит до AST. Ослабление ветки `.dump(` в файле с ruamel (`b2`) тестом не ловится. Действенная проверка — `rel`/`source`, содержащие, например, `yaml` в соседнем импорте (`import json, yaml` + `json.dump`).
2. **`I[r4_other_from_dict]` недостижим по той же причине**: сужение `Recipe.from_dict` до любого `.from_dict` (`b4`) ловит только живой обход (`Wnorm`), самопроверка зелёная. Добавить в `_PREFILTER` ничего не нужно — нужно изменить источник теста так, чтобы он содержал подстроку предфильтра (например, `# recipe`), либо вынести предфильтр из проверки ignores.
3. **`b1a`** (добавить `load_settings` в `WRITERS` при цельной сверке модуля): ноль красных — ожидаемо, не дефект: `load_settings` из чужого `yaml_io` отсекается проверкой модуля. `I[other_yaml_io_load_settings]` краснеет только вместе с ослаблением модуля (`b1b`), и тогда одновременно с `I[other_yaml_io_writer_name]` — по построению (писательское имя — подмножество). Прогноз лида «ровно один красный» для `load_settings` невыполним: изолировать его от `writer_name` мутацией нельзя.
4. **`c8_make_yaml_not_ruamel`**: условие `alias.name == "_make_yaml"` в определении «файл с ruamel» не охраняется — ноль красных (живых файлов с `_make_yaml` и `.dump(` вне плана/exempt нет, самопроверки с такой формой нет).
5. **`c10_r4_names_only`**: атрибутная форма вызова из `R4_CALLS` (`mod.build_recipe_v3_raw(...)`) не охраняется — ноль красных (все самопроверки R4 и живые вызовы — `Name`).
6. **`c12_r1_star`**: `from <движок> import *` в R1 не охраняется — единственный `star_import` тестирует R2 (`from yaml import *`).
7. **`c13_r1_dotted_tail`**: разрешение цепочки `import a.b.c` без псевдонима + `a.b.c.patch_yaml_preserving(...)` не охраняется — `engine_import_alias` использует `as`.
8. **`c15_r1_level_gt1`**: относительный импорт уровня > 1 к движку не охраняется (достижимо только из подпакета `recipe/…`; нет ни живой точки, ни самопроверки).
9. **`c18c_r4_recipe_module`** и **`c19_engine`**: структурные исключения «модуль `recipe` для R4» и «движок для R1/R2» не охраняются — без исключения тест не краснеет (причины выше). Исключение для R3 (`c18a`) и для адаптера R4 (`c18b`) охраняется живыми точками.

Охраняется (красный получен ровно или с предсказанными побочными): все 15 ещё не покрытых `detects`-ids (`yaml_dump`, `safe_dump_alias`, `from_yaml_import`, `module_alias`, `dump_all`, `ruamel_dump`, `ruamel_alias`, `shim_import`, `engine_import_alias`, `r3_literal`, `r3_div`, `r3_fstring_slug`, `r4_build`, `r4_normalize`, `r4_canonicalize`); `ignores`: `r3_in_docstring` (`b3`), `other_yaml_io_load_settings` (`b1b`, вместе с `writer_name`); условия `c1`, `c2`, `c4`, `c5`, `c6` (через `Wpath`), `c11`, `c18a`, `c18b`.

Замечание по `ruamel_alias`: сканер не различает алиас импорта (`YAML as Y`), поэтому «ровно эта форма» выражается только формой приёмника (`Y().dump` против переменной) — мутация `a6` это ловит; сам `as Y` ни одной мутацией не отличим от `ruamel_dump`.
