# gui-service 1.3a — приёмка лида: инъекции, стенды, ревью

Ветка `feat/gui-service-1.3a`. Цепочка: тестер в worktree на `main` (часть A — 3 RED / 3 GREEN
`8aff4506`, часть B — 6 RED `6ce25189`) → teamlead (GREEN `44bbbb60`, ADR-RTR-012) → инъекции лида →
фикс-раунд по инъекциям (`b7e99a9f`, `f41757c7`) → ревью ×2 (`a853e6e8`, `697028be`).

## Решения лида по дизайну

- HOL снимается на **одном соединении**, а не только между соединениями: у Пульта одно
  мультиплексированное соединение (Task 1.2), поэтому «один воркер на соединение» из edge cases плана
  отвергнут — быстрый запрос встал бы за медленным.
- Обработчики — daemon-потоки под `BoundedSemaphore(8)` на соединение, не `ThreadPoolExecutor`:
  рабочие потоки пула не-daemon, интерпретатор ждёт их на выходе (запрос с `timeout=60` держал бы
  останов процесса).
- Привязка session — синхронно в read-потоке до передачи обработчику.
- `on_session_closed` — только после последнего обработчика сессии, на любом пути снятия; сбой
  записи лишь помечает сокет мёртвым + `shutdown`, снимает соединение выход read-loop.

## Break-injection (предсказания записаны до прогона; финальный код `697028be` — 10/10)

| J2 | потолок in-flight 10⁶ | 9-й запрос, close при полном семафоре, оба теста порядка закрытия (ожидание берёт все слоты) |

| J8 | байт-вытеснение не считается | видимость вытеснения |
| J9 | байты не снимаются при maxlen-вытеснении | дрейф сумм |

**Находки инъекций:**
- J5 — в первой редакции все 49 тестов зелёные: заявленное в дизайне и докстринге свойство
  «bind до передачи» не охранялось ничем. Добавлен хазард.
- Порядок закрытия сессии (гипотеза лида, класс Н3-1 «призрак подписки»): до 1.3a все обработчики
  соединения шли в read-потоке, и `forget_session` гарантированно звучал после последнего
  `note_point`. Воспроизведено до правки: `сессия закрыта при живом обработчике: ['closed:s7']`.
- J6 — клиентская приёмка тестера ловила поломку 2 раза из 5: гонка accept (push сразу после
  `connect()` терялся, `pushes == []` выполнялось вхолостую). Синхронизация round trip — 10/10.
- Тестер: тела клиентских запросов без `type: command` — хост их не исполнял, тест таймаута зеленел
  вхолостую (найдено teamlead, тот же класс, что `b7664ad4`).

## Стенды (числа, не прилагательные)

**HOL, одно соединение драйвера** (`camera_0` под SIGSTOP получает команду с `timeout=5`, в том же
соединении — `ProcessManager introspect.plugins`; порог = p95 без нагрузки × 2):

| Дерево | База p95 | Быстрые под медленным | Вердикт |
|---|---|---|---|
| `main` | 25.9 мс | **4224.2** / 25.3 / 23.8 / 26.7 / 25.0 мс | FAIL |
| ветка, прогон 1 | 25.6 мс | макс **27.1** мс | PASS |
| ветка, прогон 2 | 26.9 мс | макс **27.7** мс | PASS |

**Медленный читатель** (второй драйвер подписан на `state.**` и не читает сокет, 16 потоков
заливают ответами по ~29.6 КБ; обычный драйвер ходит каждые 20 мс):

|---|---|---|
| ветка до ревью-фикса (ревьюер, 2 прогона) | 1011.6 / 997.2 мс | 2 `timed out` + 7 EBADF |
| ветка после (лид, 3 прогона) | 512.6 / 497.2 / 508.8 мс | 1 `timed out`, 0 EBADF |
| ветка после (ревьюер, 1 прогон) | 534.1 мс | 1 `timed out`, 0 EBADF |

Остаток ~0.5 с — один тотальный таймаут `sendall` медленному клиенту, записан в ADR как граница.

## Ревью

- Итерация 1 — REQUEST_CHANGES, два major с живыми репро: инвариант порядка держался только на
  выходе read-loop (путь сбоя записи закрывал сессию раньше обработчика: `closed:s1 0.704 …
  handler_done 1.501`); обещание «≤ 0.5 с, один раз» опровергнуто замером ~1.0 с.
- Итерация 2 — APPROVE_WITH_NOTES: порядок на пути сбоя записи `handler_done 1.505, closed:s1 1.505`;
  гонка «пир закрыл, пока отправитель в `sendall`» 3/3 без утечки `_dead`; `close()` без
  `_write_lock` — 0 EBADF за 6 прогонов. Заметка о ссылках на удалённый `_drop_clients` закрыта `697028be`.

## Открыто

- Сквозной сценарий «призрачный форвардер у ребёнка» живьём не прогонялся — порядок доказан на уровне
  канала; цепочка до `errors_delivery_failed` выведена из кода.
- Потолка на число соединений нет: до 9 потоков × N соединений.
- `get_info()["clients"]` считает помеченный мёртвым сокет до выхода read-loop.
- Все замеры — macOS; Linux (Orin) не проверялся.
