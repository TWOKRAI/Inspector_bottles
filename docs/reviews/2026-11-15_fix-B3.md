## Что изменено
1. F1 (`monitor/process_monitor.py`): функция модуля `normalize_leaf(name, raw)` — единственное место проверки формы; зовёт `_admit_heartbeat` под листовым замком. Годный лист (`at` — конечное число, не bool; `reasons` — список dict; `ready`, `paused` — bool, если есть) копируется как есть. Негодный заменяется листом `ready: false`, одна причина `failure` / `report` «лист готовности негоден: <процесс>» (значений входа нет), `paused: false`, `at` = сейчас. Heartbeat остаётся фактом жизни: время (`_last_heartbeat`), статус `paused`/`running` и воркеры принимаются; теряется только содержимое листа. `paused: false` в заменяющем листе — остановку мусорный лист подтвердить не может (STOP такого процесса дойдёт до срока `unconfirmed_stop`, честно). Поле `readiness` не dict (число, строка) раньше считалось «поля нет»; теперь это негодный лист. Живой путь `evaluate` не менял. Выбрал `normalize_leaf` в мониторе, а не в `run_state.py`: импорт `process/run_state` из монитора тянет `process/__init__` -> цикл с `process_manager_process`.
2. F4: `ProcessMonitor.unmark_restarting(name)` (pop под `_readiness_lock`, время не трогает). `restart_process` после `mark_restarting` вызывает новый `_restart_process_replace` (тело замены перенесено без изменений) в `try/finally`: любой выход без `True` (stop_process ложь, `create_and_register` None, исключение) зовёт `unmark_restarting`; исключение уходит вызывающему как раньше. Успех пометку не снимает (её снимает heartbeat нового pid).

## Что оставил открытым / ненадёжно
- ЧУЖАЯ НАХОДКА (не B3): `test_process_manager_process.py::TestOrchestratorReadySignalIsHonest::test_initialize_hands_the_event_over_instead_of_setting_it` и `::TestInitializeRequiresExecutorManager::test_with_executor_manager_initialize_reaches_lifecycle_registration` красные: `_settle_run_state -> _evaluate_run_readiness -> _run_auto_restart_flags -> self._get_protected_names()` бросает `AttributeError: ... no attribute '_process_configs'` (PM из теста собран без конфигов). Решение для fix-A: читать `getattr(self, "_process_configs", None) or {}` перед `_get_protected_names` или брать protected только при непустом `expected` с флагом. Я не прогонял весь набор раньше, поэтому поймал это лишь сейчас.
