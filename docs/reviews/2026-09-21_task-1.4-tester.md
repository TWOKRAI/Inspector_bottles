## Инцидент по ходу написания (важно для лида и разработчика)

Первая версия теста `test_line_sim_default_port_busy_aborts` занимала ТОЛЬКО
порт 8766 (логически «порт сима»). Сегодняшний зонд проверяет ЗАХАРДКОЖЕННЫЙ
`PORT = 8765` независимо от любых аргументов — при свободном 8765 он реально
поднял полный стенд `inspection_full` (7 процессов, подтверждено `ps`), тест
упёрся в `subprocess.run(timeout=30)`, что убило только лист-процесс, а
multiprocessing-дети (`spawn_main`, 7 штук, PPID 1) остались сиротами и
держали порты 8765/8766 до сих пор — среде (`.claude/plugins/core` sandbox)
запретила мне их `kill` («Interfere With Workloads», auto-mode classifier).

Исправлено: `_all_busy(PROTOTYPE_PORT, ...)` — 8765 занимается ЗАЩИТНО в
КАЖДОМ прогоне зонда в этом файле (даже там, где сценарный порт другой), плюс
`_run_probe` переведён на `Popen(start_new_session=True)` с `killpg` всей
группы на таймауте (раньше `subprocess.run` гасил только лист). Повторный
полный прогон — 2.25 с, ни одного нового процесса.

**Оставлено открытым:** осиротевшие 7 процессов от инцидента (PID 11898,
11900-11905, стартовали 13:29:01) я НЕ смог погасить — среда блокирует `kill`
из-под тестировщика. Порты 8765/8766 сейчас foreign-busy (либо эти сироты,
либо легитимный боевой стенд — не различить снаружи). Лиду нужно проверить
`ps aux | grep spawn_main` и погасить вручную, если это мои сироты.

## Коммит — НЕ выполнен (блокер окружения)

`git commit` в этом worktree (`test/line-sim-task-1.4`) отбивает
`.claude/plugins/core/hooks/protect-branch.sh`: `BRANCH=main`. Хук вызывает
`git symbolic-ref --short HEAD` в СВОЁМ процессе, чей cwd — это дефолтный
корень harness'а (внешний репозиторий на `main`), а не cwd команды, в которую
я оборачивал `cd <worktree> && git commit` — `cd` внутри проверяемой команды
хук не учитывает вовсе (подтверждено: `git -C /Users/.../Inspector_bottles
branch --show-current` → `main`, при этом `git -C <worktree> branch
--show-current` → `test/line-sim-task-1.4`). Не пытался обойти регэксп хука
(`-C` вместо `cd`) — это выглядело бы как обход гейта, а не как легитимный
путь.

Файл **застейджен** (`git add`) в
`.claude/worktrees/team-1.4-tester/backend_ctl/tests/test_probe_acceptance_app_param.py`,
но не закоммичен. Лиду нужно либо закоммитить самому из своего окружения,
либо поправить хук (учитывать `-C`/фактический cwd команды), либо разрешить
одноразовый оверрайд.
