# Вердикт CTO по архитектуре пути кадра (Фаза 4) — 2026-09-29

**План:** [`transport-single-policy`](../../plans/transport-single-policy/plan.md), [`phase-4.md`](../../plans/transport-single-policy/phase-4.md).
**База:** HEAD `53d17d9d`, ветка `feat/qr-code-reader`, Windows 10, флаги SHM по умолчанию.
**Кто:** два независимых прогона роли `cto`.
- Первый по ошибке шёл на Opus: модель не передали явно, хотя во frontmatter стоит `fable`.
- Второй — на **Fable** (`model: fable` явно). Выводы первого он получил как гипотезы и перепроверил прогоном.

**Вердикт обоих: BLOCK.** Перепроектировать один слой: время жизни ссылки и владение слотом. Кольца на ключ, claim check по размеру, темп 4.3a, `LoanLedger`, `FrameReader` и seqlock-формат годятся как строительный материал.

## Простыми словами

На 100 fps 1080p система анализирует не те кадры и молчит об этом.
- Fable поставил метку в пиксели каждого кадра на живом стенде `if_100_1080.yaml`, 30 с.
- **processor:** из 1798 кадров правильных 0, чужих 1797, порванных 1.
- **renderer:** из 1218 кадров правильных 0.
- Кадр в обработке на 48–51 кадр (≈0.5 с) новее своих метаданных.
- Штатные `frame_torn_reads` / `frame_stale_drops` / fallback при этом = 0.

Все прежние «0 torn / 0 дропов», включая приёмку 4.1 и разведку 4.3, не измеряли целостность.

**Причина:** сообщение указывает на ячейку кольца (слот 0/1/2), а не на кадр. Кольцо — 3 ячейки, data-очередь — 50 сообщений (`process_manager_process.py:64`). Пока сообщение ждёт в очереди, ячейку перезаписывают, а поколение записи в сообщение не кладётся, так что сверять не с чем. seqlock ловит только запись под чтением (torn), а не подмену (stale).

## Где Fable расходится с первым аудитом

1. **Loan не делать «всегда».** Это самый забагованный слой: три воспроизведённых дефекта. С поколением в ссылке он перестаёт отвечать за корректность и становится оптимизацией.
   - Заморозить за флагом, не включать.
   - Удалить после 4.3, если честный `frame_stale_drops` = 0 на 60/100 fps.
   - Пересмотреть, если stale > 0.1 % при coll = 8 и очереди 6.
2. **Первыми идут честные счётчики, а не потоки OpenCV.** Без них стенд докладывал «всё по нулям» при 100 % брака.

## Целевая архитектура (Fable)

1. **Ссылка — это кадр, а не ячейка:** `{owner, ring, idx, gen, name}` для каждого ключа.
   - `frame` — обычный ключ, плоские поля и дубль `shm_owner` удалить.
   - `gen` — чётное поколение seqlock после записи. seqlock-заголовок всегда, флаг снять.
2. **Читатель** сверяет `gen` до и после чтения: не совпало → stale-drop или torn-drop, оба счётчика настоящие. Для zero-copy view — тот же post-use re-check против `ref.gen`.
3. **Владение — один хоп.** Процесс владеет только кольцами, в которые пишет сам; входы читает и никогда не пересылает.
4. **Глубина кольца — из рецепта** (`buffer_slots`), по умолчанию `ceil(fps × 60 мс) + 2` (≈8 на 100 fps).
   - data-очередь = `кольцо − 2`, выводится из кольца, одна правда вместо `HUB_QUEUES=50` / QoS.
   - Нарушение — громкая ошибка на старте и поле в introspect.
5. **Уникальные имена сегментов, кэш handles и zero-copy view для читателей-пайплайнов — всегда.** Флаги снять.
   - Кэп кэша = число реально используемых имён, не 8.
   - Copy-out (GUI/bridge) — копия с проверкой gen.
6. **Loan** — заморозить (см. выше).
7. **B-7 в том же send-middleware:** в SHM пишутся и в сообщение кладутся только ключи, проведённые к данной цели. На разные цели — разные dict.
8. **`cv2.setNumThreads(N)`** в composition root (`GenericProcessApp`), N из рецепта, по умолчанию 2. Замерить 1 / 2 / 4.

## Порядок работ (перекрывает прежний «темп → наблюдаемость → 4.2 → 4.3»)

0. **Честные счётчики:**
   - `gen` в ссылке + stale/torn;
   - точный CPU по процессам (QueryProcessCycleTime / `CLOCK_PROCESS_CPUTIME_ID`) в introspect;
   - байты SHM на процесс;
   - глубины кольца и очереди в introspect.
1. `cv2.setNumThreads` — параллельно с (0), мерить `cpu_truth`.
2. Один редизайн:
   - формат + gen;
   - имена, кэш и zero-copy всегда;
   - кольцо и очередь из рецепта;
   - флаги снять, loan заморозить.
3. B-7 per-target.
4. Плагины:
   - `render_overlay` — заливка по ROI или маске;
   - `blob_detector` — копия перед рисованием;
   - `color_mask` без потребителя убрать из рецепта.
5. Приёмка 4.3 в одной конфигурации, без флагов: 480p и 1080p × 60 и 100 fps.
   - `stale = torn = 0` по настоящим счётчикам плюс независимая пиксельная метка (хук Fable годится как приёмочный тест);
   - запись ≤ 21 МБ на кадр;
   - CPU по процессам;
   - очередь меньше глубины кольца.

## Наблюдаемость: что должно быть постоянно при ~0 стоимости на горячем пути

**Постоянно:**
- точный CPU по процессам; по потокам — по запросу, раз в секунду;
- байты SHM, записанные и прочитанные по процессу;
- настоящие `frame_stale_drops` / `frame_torn_reads`;
- `queue_size` против глубины + алерт при устойчивом `≥ depth − 1`;
- EMA времени плагина в `PluginRunner` (одна пара `perf_counter`; только это показало бы 10 мс `render_overlay`);
- `FramePacer` target / achieved / late;
- число потоков cv2 (однократно в introspect);
- сконфигурированные глубины кольца и очереди.

**Не постоянно:** выборка размера сообщения 1 из 100 — это второй pickle, только opt-in через `telemetry_set`.

## Прочие находки Fable

- Кэп кэша handles `_HANDLE_CACHE_CAP=8`: GUI читает 15 имён, при включённом кэше будет LRU-трэш (арифметика, не прогон).
- Две правды глубины data-очереди: `HUB_QUEUES["data"]=50` против QoS `history_depth=4` под `FW_QOS_PROFILES`.
- `_read_ref` / `_receive_frame_key` сначала зовут `mm.read_images` для чужого owner. Возможен warning на каждый кадр у copy-out (не проверено).
- Повтор fan-out определяется по `item["shm_name"]` (`strip_and_write`): плагин с собственным ключом `shm_name` сошёл бы за уже стрипнутый item.

## Открыто и ненадёжно

- F1 (loan ON) не перезапускался ни одним из CTO. Loan ON живьём на 1080p не гонялся.
- На каждую конфигурацию — один прогон стенда по 30 с. Калибровка тактов по busy-loop может сдвигаться от turbo.
- Qt GUI (copy-out) не проверялся: стенд headless. POSIX не проверялся.
- «Loan не нужен при gen + глубине» — расчёт (hold 17 мс ≪ wrap 80 мс при coll = 8), а не замер.
