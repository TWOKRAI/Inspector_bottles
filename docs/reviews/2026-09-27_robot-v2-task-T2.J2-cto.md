# Вердикт cto по эскалации T2.J2 — TLM_RZ против оборота J4

Роль: `cto` (Fable), синхронно. Эскалация ревью T2.J2 (п.3, п.5, `joint_speed`). Объект `7ee5b0d6`. Записал ведущий по
отчёту (у роли нет Write). Скрипты — scratchpad сессии (`cto/{jump,flip,e_rule,limitnone}.py`, `e_patch.py`, `spd_patch.py`).

**Вердикт: правило Q2 «J4 — ближайший оборот» отозвано** — несовместимо с «TLM_RZ = цель».

## Воспроизведение (`7ee5b0d6`)

- HOME → JOINT `(−157.1, −57.9, 0, 284)`: `tick 32: TLM_RZ=284.0 J4=−185.01 fk[3]=−436.0 dRZ=717.6`; 8 тиков RZ вне зоны;
  после DONE и LINE `fk[3]=−436.0` при `TLM_RZ=284`.
- Обычная цель `rz=−76`: `j_end J4=−185.01`, `dRZ=357.6` на тике 32, 8 тиков вне зоны — перемотка срабатывает на любой
  цели, где до −185 ближе, чем до 175.
- J4 без предела: `J4=534.99`, `max|dRZ|/tick=12.0`, `fk[3]==TLM_RZ` — единственный путь с одной правдой.
- Смена руки `(400,100)→(410,100)` 0→1: 1 тик, J2 +91 → −91 за 10 мс — потолок XYZ хорды 10 мм этого не видит.

## Решения

1. **Правда TLM_RZ = `fk(_joints)[3] = J1+J2+J4`**, без обёртки, на каждом тике включая DONE. Командный RZ — та же
   величина (оборот выбирает оператор значением RZ). J4 = `rz − J1 − J2` сырой, перемотки нет нигде; J4 вне
   `joint_limits` → NAK `E_RANGE [R_OUT_OF_ZONE]` в той же ветке, что J1/J2. `_nearest_j4_turn` и `reference` удалить;
   `_continuity_joints` = `ik` как есть. Следствие: RZ(t) — прямой lerp старт→цель, `max|dRZ|/tick = 0.8`, все тики в
   зоне, DONE ровно цель.
   Мануал RL: `RobotRZ()` 5.2.7 — диапазон не назван; `MovJ` 1.2.1 — «−360~360, по модели»; `RobotJ4()` 5.3.4 —
   физический угол; JRC (5.1.1, 5.2.14) — оборот сустава хранится в точке отдельно от RZ, т.е. контроллер оборот из RZ
   «ближайшим» не выводит. ⚑ GATE-1: диапазон/обёртка `RobotRZ()`; `MovP` в RZ=284 и −76 при одной XY с JRC {0};
   правило JRC. Прошивка T4 может считать `TLM_RZ = RobotJ1()+RobotJ2()+RobotJ4()` — та же правда, что у sim.
2. **Зона RZ — только на командной цели.** При правиле 1 каждый тик в зоне по выпуклости. Клиент T3.1: после DONE
   `TLM_* == цель` (±0.1), без mod 360. Окно T2.W: значок и RZ(t) — из `TLM_RZ` как есть. Условие: два
   `check_point(rounded)` посреди хода (`sim_core_v2.py:772`, `cart_dist` в `_joint_tick_capped`) — только XY, иначе
   узкая зона RZ ложно уводит в `_clamp_pose_to_zone`.
3. **J4 при пределе `None` — сырой.** Одно правило.
4. **`joint_speed` = `(450, 720, 1100, 2500)`** — порядок класса SCARA, не паспорт DRS, ⚑ GATE-1. Замер: 796 passed,
   счёт тиков фикстур не изменился; смена руки 1 → 37 тиков, max шаг XYZ 17.9. `1e9` оставляет телепорт локтя.
5. **Свойства:** 5 «одна правда RZ» (`rz=−76` → J4 175.0, каждый тик `TLM_RZ == fk[3]`, `|ΔRZ| ≤ MAX_STEP`, в зоне,
   DONE −760 raw, после LINE держится; слом — перемотка); 5b (`rz=284` → NAK; слом — перемотка → ACK); 5c (предел J4
   None, `rz=284` → ACK, J4 534.99; слом — любая перемотка); 9 жёстче (после LINE `joints() == ik(pose, TLM_HAND)`
   точно; слом — nearest-turn в continuity); 6 дополнено (`(400,100)→(410,100)` 0→1 → ≥ 30 тиков; слом — `1e9`).
   `test_zone_rz_max_boundary[360.0-accept]` под правилом падает верно (J4 при rz=360 в той XY > 360) — взять XY с
   J1+J2 ≥ 0 или модель без предела J4.

## Открыто / ненадёжно

- Правило оборота контроллера (JRC или сырой) не проверено → GATE-1; если контроллер перематывает сам, меняется одна
  ветка NAK 5b на «ACK + оборот», правда RZ = J1+J2+J4 остаётся.
- Числа заглушки скоростей — по памяти о классе SCARA, не DRS.
- `test_belt_drive::test_live_ticker_no_jump_on_first_vfd_command` упал один раз под патчем (709.98 vs 689.07±20.7),
  отдельно проходит — флак по wall-clock, не разбирался.
- Отсутствие диапазона `RobotRZ()` — отрицательный grep по pdftotext.
