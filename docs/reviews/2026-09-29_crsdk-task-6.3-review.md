   возврата `take_device`.** `reader.start()` запускает поток, потом `_forget_errors()` затирает `_last_error`, а
   `_cleared_error` прячет текст читателя по равенству строк.
   Вход: `FakeApi(script=[sdk_error(-1)]*3)`, `timeout_ms=10`, `take_device`, 50 прогонов →
   26/50: `{'device_state': 'error', 'last_error': '', 'errors': 3}`, ответ команды `{'status': 'ok', 'device_state': 'error'}`;
   одна ошибка вместо трёх — 33/50 `errors>=1` при пустом `last_error`. Нарушен критерий «три ошибки → last_error непуст».
   Слепой тест зелёный: `GatedApi` пускает ошибки только после ответа `take_device`.
   Исправление: убрать `_cleared_error`, `_forget_errors`, fallback на `stats["last_error"]`; обнулять `_last_error`
   под замком ДО `reader.start()` (все ошибки читателя приходят через `on_error`). Патчем: 15 passed, гонка 0/50.
2. **[major, tests] `test_sdk_plugin.py:333-343` — «картинка только под `frame`» ловится только для bytes/ndarray.**
   `item["preview"] = base64(frame.image)` → 15/15 зелёные; `item["pixels"] = ….tolist()` → `test_item_has_no_bytes…`
   зелёный. Исправление: точный набор ключей item.
3. **[minor, quality] `sdk_plugin.py:332-335, 258` — «прибор ещё отпускается» после выхода потока.**
   `FakeApi(block_s=3.0)`, take → release (2.01 с, `released: False`) → поток вышел → `get_status`:
