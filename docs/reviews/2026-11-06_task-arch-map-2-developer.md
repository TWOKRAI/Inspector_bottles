## Что я истолковал, а не выполнил буквально

- Раскладка: не `cytoscape-elk`, а `elkjs` напрямую. Причины: на cdnjs нет `cytoscape-elk` (404), результат ELK читается в чистую функцию и проверяется в node, нет неизвестного API адаптера. Позиции передаются в cytoscape готовыми.
- Контейнеры (слой, группа, раскрытый юнит) — обычные узлы с размером из ELK, а не compound-узлы cytoscape. Проводы всегда идут между листьями текущего вида, поэтому compound не нужен; перетаскивание узлов выключено.
- Раскладка идёт по слоям отдельно (ELK внутри слоя, слои — колонки в порядке `meta.layers`). Единый ELK-проход по всей иерархии не давал гарантии порядка слоёв слева направо. Внутри слоя рёбра для раскладки развёрнуты (импортируемый — левее), как цепочка слоёв.
- «Только нарушения» показывает провода с error или warn; info (например `unit-hygiene`) нарушением не считается.
- Фильтры hard/lazy/tc применяются и к панели «Провод» (список импортов под проводом соответствует нарисованному).
- Находки `unit-cycle` несут поле `members` (в README его нет, но генератор пишет): все рёбра между участниками цикла получают серьёзность находки, так что провод краснеет на любом уровне раскрытия. Находки без совпавшего ребра (без `src`/`dst`) красят провод между представителями `src_unit` и `dst_unit`.
- Значок находок — отдельный маленький узел у правого верхнего угла рамки, а не часть самого узла.
- Двойной клик реализован временем между тапами (380 мс): у cytoscape нет `dbltap`. Первый тап выделяет, второй раскрывает.
- Вес находки на узле: считается каждая находка, которой узел или его потомок касается (по `src`, `dst`, `src_unit`, `dst_unit`, `members`), один раз на узел.

## Что оставлено открытым / ненадёжно

1. **Визуально не проверено ничего.** Браузера у меня нет. Проверено только логикой в node и headless-cytoscape: число элементов, классы, отсутствие исключений. Положение подписей контейнеров (`text-valign: top` + `text-margin-y: 15`), положение значков, вид линий `taxi`, цвета в обеих темах — только на глаз лидера.
2. **Читаемость при «вписать».** Вся схема ~5500x2200 px; при полном вписывании в экран масштаб ~0,2, подписи узлов скрыты (`min-zoomed-font-size: 5`). Понятно только после приближения. Если лидеру это мешает — правки: уменьшить размеры рамок, повысить порог или стартовать с масштаба 0,5 на левом слое.
3. **Оранжевый шум.** Из 384 проводов стартового вида 234 имеют warn (в модели 1042 `deep-import`), красных проводов нет (в модели error — только 6 `unresolved-relative`, без пары юнитов). Схема будет в основном оранжевой; это данные, не ошибка страницы, но для читаемости можно ввести порог.
4. **Провода `taxi` не обходят рамки.** Ортогональные маршруты cytoscape не знают о препятствиях; провода идут поверх рамок слоёв и юнитов. Маршруты ELK не используются. Двунаправленные пары получают разный `taxi-turn` (35 и 65 процентов), чтобы не сливаться, — проверить на глаз.
5. **Большое раскрытие.** Раскрытие самого большого юнита (`multiprocess_prototype.frontend`, 280 файлов) даёт 172 узла и 487 проводов, перерисовка ~180 мс в headless; отрисовку в реальном браузере с 487 `taxi`-проводами не мерил.
6. **Блокирующий ELK.** `elk.bundled.js` работает в основном потоке (без Worker, из-за file://): раскладка framework ~260 мс блокирует интерфейс на это время.
7. **Допущения о данных.** `card.contour` может быть строкой или списком; `card.sources` может быть словарём — показывается построчно. Файлы под `__init__` пакета считаются детьми каталога, как в README. Полей, которых нет в README (`members`), страница ждёт необязательными.
8. **Ограничение сопоставления находок с рёбрами.** Находка с `src`/`dst` привязывается к ребру по паре файлов и, если в `where` есть `:номер`, по строке; без номера — ко всем рёбрам пары.
9. **Ящик «Находки» не фильтруется** текущим контуром или раскрытием; строки находок без `dst_unit` выделяют юнит.
10. Не проверено: открытие по `file://` в конкретном браузере (SRI + `crossorigin` по `file://` должны работать, так как оба CDN отдают `Access-Control-Allow-Origin: *`, но в браузере не пробовал); поведение `details`-меню при клике вне его (само не закрывается).

Расчёт экранных размеров. Ширина обзора по модели: 5·420 + 4·120 = 2580. Окно 1800 px при открытых панелях (290 слева, 400 справа) даёт холст ~1110 px; масштаб по ширине (1110 − 32) / 2580 = 0,418 (по высоте запас: ~930 px холста против ~1100–2200 модельных единиц с дугами, масштаб по высоте 0,42–0,82, то есть ширина или высота определяют масштаб примерно одинаково, не меньше ~0,416). Итог: имя слоя 46 · 0,418 = 19,2 px, подпись провода 32 · 0,418 = 13,4 px, сводка 26 · 0,418 = 10,9 px, рамка слоя ~175x125 px. Если холст уже ~1010 px (оба боковых окна шире), масштаб падает до ~0,38: имя 17,5 px, подпись 12,2 px — граница.

Проверки: `node harness.js` 72/72 (новые: `layerCaption` fw/svc/ctl, `breakName`, размер рамки слоя 420x300); `node smoke.js sample` всё ок (рамка 420x300, узел сводки `c:fw`, стиль шрифта подписи 32, масштаб после `select=` ≥ 0,7); `node smoke.js real` всё ок.

## Что оставлено открытым / ненадёжно
1. Размеры на экране посчитаны, не измерены. Масштаб `fit` у cytoscape зависит от охвата дуг и подписей (если в охват входят контрольные точки кривых, высота растёт до ~2200 единиц и масштаб упирается в высоту, ~0,416 — результат близок к расчёту, но не подтверждён).
2. Положение имени (`text-margin-y` 124 при двух строках; однострочные имена `Services`, `Plugins` сидят ниже двухстрочных) и узла сводки (центр на 88 от нижнего края рамки) подобрано без снимка; наложение имени на сводку возможно, если имя из двух строк выше расчётных 110.
3. Подпись `246/58/33` шириной около 150 единиц шире зазора 120: она лежит над рамками (первая дуга выше их верхнего края), но у соседних дуг одинаковой длины подписи могут касаться друг друга.
4. Узкий холст (< ~1000 px) даст имя слоя < 18 px; для него нужен либо один ряд с меньшим зазором, либо переход на две строки рамок.
