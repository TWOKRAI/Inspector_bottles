## Модель `<select>` в харнессе (принята на веру — проверить в живом Chrome)

Самопроверка `select_selfcheck` (зелёная) фиксирует ровно это:

1. Без явного выбора выбран ПЕРВЫЙ пункт (`selectedIndex` 0, `value` = его `value`); пунктов нет → `value ""`, индекс −1.
2. `select.value = X` выбирает пункт с `value === X`; несуществующее X снимает выбор (−1, `""`).
3. `option.value` без явного значения = `textContent`; `option.selected = true` (до или после `appendChild`) выбирает пункт.
4. `innerHTML = ""`, `textContent = ""`, `replaceChildren()`, `length = 0`, `removeChild` сбрасывают выбор на «первый».
   Пункты добавляются `appendChild`/`add`; `options` — живой список.
5. Событий харнесс сам не шлёт: шаг `select_option` ставит `selectedIndex` и шлёт `input` затем `change`. Чтение
   `select.value` в обработчике кнопки видит выбранный пункт (в браузере — тоже).
Чего харнесс НЕ знает: `select.options.add(new Option(...))` (нет `Option` в контексте), `optgroup`, `size>1`/`multiple`,
фокус/выделение при клике по кнопке, стрелки на сфокусированном `<select>` (страница их уже игнорирует —
`presetKeyFromField` включает `SELECT`), поведение при частичном удалении пунктов (в браузере выбор сдвигается, у меня
сбрасывается на первый).

## Что я истолковал, а не выполнил буквально

1. Имя слоя = основа ИМЕНИ файла: последний компонент пути без расширения, регистр расширения не важен
   (`sub/b.PNG` → `b`, `sub/двойной диск.png` → `двойной диск`). План говорит «основа имени файла».
2. «Добавить» читает выбранный пункт `<select>` в момент клика (план: функция принимает запись, кнопка берёт её из
   `<select>`). Запись для `class://` тест не диктует — только `sprite_source == "class://"` и имя `class`.
3. После «Заменить» слой остаётся выбранным; после «Выше/Ниже» и «Добавить» выбор — на том же/новом слое (по плану).
4. Текст отказа списка должен ВКЛЮЧАТЬ сообщение бэкенда (`data/line_sim` из `message`) — иначе «текст отказа» было бы
   неверифицируемо. Если реализация покажет только «HTTP 500» — это спорный пункт, а не баг теста.
5. Пункт `class://`: `value == "class://"`, ровно один, положение не пинится; текст пункта не пинится.
6. `layer_template` в двойнике несёт лишний ключ `future_field: 7` (нет в `LayerSpec`) — проба «страница берёт ключи из
   шаблона, а не из своей константы» (план: «новое поле LayerSpec попадает в шаблон само»). Он же виден в форме.
7. «Ровно одна запись undo» измеряется поведением цепочки (своя запись перед операцией / цепочка разных операций и
   счёт «Отмен»), а не чтением `presetUndoStack`, потому что дубль записи даёт то же состояние при «Отмене».
   Тесты читают `presetState.layers` (имя из плана) и `collectPresetFromFields()` (имя из плана) через `vm`.
8. Положительные контроли в C6-edges и C8: «ничего не изменилось» без контроля прошло бы вхолостую, пока кнопок нет.
