### M4 — Camera Save гасит `layout_unsaved` без записи позиций (нужно решение лида)
Вход: `session.mark_layout_unsaved()` (автосейв наткнулся на конфликт, правку откатили), Camera Save `fps=30`. Проба E: `save() -> True`, `layout_unsaved: True -> False`, дифф файла только `['+            fps: 30']`, `gui_positions` не записаны. Причина: `app._save_active_topology` зовёт `save_editor_topology_to_recipe` без `gui_positions` и затем `session.mark_saved()`, который снимает `layout_unsaved` (`topology_session.py:191-193`). Тот же класс «ложный флаг», что чинит 1.15, но с обратным знаком (молчание вместо ложного вопроса).
Достижимость узкая: конфликт, ручной откат файла, Camera Save раньше следующего переноса узла. `app.py` вне FILES обеих задач — решает лид. Правка на выбор: `_save_active_topology` не зовёт `mark_saved()` целиком, а гасит одну `dirty` (нужен метод вроде `mark_graph_saved()`), либо принять и записать в DESIGN.
