## Неоднозначности в acceptance/DESIGN

1. **Префикс процесса.** DESIGN п.4: «`check()` добавляет префикс `<process>.`». Acceptance требует, чтобы вывод содержал `processor.color_mask.frame`. Если `check()` склеит `processor.` + `Вход 'color_mask.frame'...` или `processor: Вход 'color_mask.frame'...`, подстроки `processor.color_mask.frame` в тексте нет, хотя смысл соблюдён. Тест ищет подстроку буквально (как в acceptance). Реши, какой формат верен.
2. **Узел 0 в `validate_chain`.** Сегодня цикл идёт с `i=1`. DESIGN не говорит, проверяет ли новая `validate_chain` узел 0. Я это НЕ тестирую напрямую; только через `check()` (ровно одна ошибка).
3. **Семантика `available_keys(chain)`:** все узлы цепочки считаются «выше»; при совпадении имени из провода и выхода узла приоритет не задан. Тестирую только однозначное (провод -> any; выход узла выше со своим портом; последний из двух производителей).
4. **Дословный текст п.4(а)** запинен целиком (`Вход 'B.frame' (image/bgr) не подключен: ключ 'frame' не производит ни провод процесса, ни узел выше по цепочке`). Это взято из DESIGN; тест хрупок к любой правке слов.
