## Допущения и слабые места

1. **Живой view в отставке** (`..._closed_later`) красный сначала из-за ПРЕДПОСЫЛКИ «view по умолчанию», а не из-за отставки:
   дефолтного способа получить живой view без zero-copy нет. Сама логика отставки на старом коде проверена только косвенно
   (копия с флагами, выше). Настоящая проверка — после реализации.
2. «Закрыт ли handle» наблюдается через ОС: `SharedMemory(name=old)` -> `FileNotFoundError`. Работает на Windows (`os.name == "nt"`);
   на POSIX имя снимает unlink писателя, и проверки существования там пропущены (остаются чтение и счётчики). На этой машине
   (Windows) пройдены только Windows-ветки.
3. `reader._reader.close_errors` — приватный путь (`FrameShmMiddleware._reader`). Публичного счётчика у middleware нет. Если
   реализация переименует/уберёт — тест упадёт AttributeError, это сигнал править тест, а не баг.
4. Счётчик отложенных закрытий НЕ назван и не проверяется. Критерий «отложенные закрытия видны счётчиком» тестом не покрыт.
5. Имена: тест использует короткие `owner="A"/"B"`, ключ `mask`. Имя длиннее `_MAX_BASE_NAME_LEN=26` схлопывается в хеш
   (`output_fra_8e67d541_0` для `output_frames`+`cam0`), и тогда «владелец и pid в имени» неверно по построению. Критерий
   «в имени есть владелец, pid и инкарнация» буквально для реальных owner/slot (`cam0`/`output_frames`) невыполним без
   правки лимита — вопрос лиду/разработчику: проверять ли это только для коротких имён. Инкарнация отдельным токеном не
   утверждается (разный результат двух вызовов покрыт).
6. Подмена платформы: `monkeypatch.setattr(shm_mod, "is_windows", ...)`. `is_posix` не подменяется (на Windows это no-op
   unlink/cleanup). Если реализация перейдёт на другую проверку платформы — подмена станет вхолостую, и тест сойдёт
   на реальной платформе.
7. Сканер флагов берёт файлы через `git ls-files -co --exclude-standard`, пропускает каталоги
   `tests/docs/plans/.git/.venv/.claude/graphify-out/__pycache__/node_modules`, файлы `test_*.py`/`conftest.py` и файл реестра.
   Шаблон `FW_SHM_[A-Z_]+` ловит и обрубки (`FW_SHM_OWNER_` в `dualcam_synth.yaml`) — это намеренно.
8. Конструкторы middleware вызваны без `zero_copy/cache_shm_handles/owner_incarnation`. Ctor-аргументы сейчас существуют, но
   после 4.7b могут исчезнуть — тесты от этого не зависят.
