**Порядок ответа и потолок дренажа — закрыты и доказаны.** Тест

**Новая регрессия — подтверждена прямым воспроизведением.** `timeout = _DRAIN_TIMEOUT_S`
(`plugin.py:815`) — атрибут `BaseHTTPRequestHandler`, `StreamRequestHandler.setup()` вызывает
`connection.settimeout(2.0)` один раз на всё время жизни соединения этого обработчика. Это
покрывает ОБЫЧНОЕ чтение тела в `_read_command_body` (`self.rfile.read(length)`, строка 921),
а не только `_drain_body`.

Пробы (одноразовые скрипты в scratchpad, не в репозитории — план воспроизведения ниже):

1. Легитимный медленный клиент, тело `/api/preset/commit` (валидный JSON, далеко от потолка
   262144) отправлено дробно за 3.0 с равными интервалами короче 2 с между чанками — таймаут не
   срабатывает (устройство `socket.settimeout`: дедлайн на каждый `recv()`, не кумулятивный на
   весь запрос). Ответ 200 пришёл нормально. Это НЕ регрессия сама по себе.
2. Тот же клиент с ОДНОЙ паузой 2.8 с посреди тела (сетевая заминка, не атака) —
   `_read_command_body` виснет на `self.rfile.read(length)`, таймаут срабатывает, необработанное
   исключение уходит в `socketserver.BaseServer.handle_error` (закрывает сокет без HTTP-ответа).
   Клиент получает `ConnectionAbortedError: [WinError 10053]` — не 413, не 408, никакого
   HTTP-статуса вообще. Команда `preset.commit` на бэкенд ни разу не ушла (двойник подтверждает).

регрессий... старые маршруты»). Категория `architecture` (таймаут выбран для одного пути и

**Минимальная адресная правка** (без переоткрытия остального): не вешать таймаут на класс
целиком. Варианты: (а) `self.connection.settimeout(_DRAIN_TIMEOUT_S)` непосредственно перед
вызовом `_drain_body`, не трогая таймаут сокета для обычного чтения тела; (б) обернуть
`self.rfile.read(length)` в `_read_command_body` в `try/except (socket.timeout, TimeoutError)`
и вернуть управляемый отказ (408) вместо необработанного исключения, которое рвёт сокет без
ответа. Второе нужно в любом случае — необработанное исключение, убивающее соединение без
HTTP-статуса, плохо само по себе, независимо от источника таймаута.

## Н3 — закрыт, и это сильнее, чем «харнесс не браузер»

`renderPresetLayers` (`plugin.py:650-654`): `nameEl = document.createElement("b");
nameEl.textContent = layer.name`. Это `textContent`, не `innerHTML` — экранирование здесь
гарантия уровня спецификации DOM, одинаковая в реальном браузере и в любой корректной
реализации DOM (включая офлайн-харнесс для этого вызова). Опасение разработчика и лида
«доказано только в харнессе, не в браузере» — избыточная осторожность именно для этой правки:
`textContent` не интерпретирует разметку по построению, харнесс здесь ничего не может
смошенничать в пользу зелёного теста. Остаток строки (`fieldsHtml`) собирается из ключей схемы
(`Object.keys(layer)`), не из значений пресета — граница, которую заявил разработчик,
подтверждается чтением: значения слоя (`layer[key]`) в `presetFieldMarkup` идут только в
атрибуты `id`/`type`, построенные из ключа, не из строки, которую вводит оператор. Закрыто
увереннее, чем говорит сам отчёт разработчика.
