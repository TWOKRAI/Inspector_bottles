Что изменено в `test_stop_wave_last_guards.py`:

  процессов. Шаги: `request_stop`, затем `kill()` группы до сигнала `last`, затем `join_until(t_kill + 2,0)`.
  Ожидания: terminate `main` ≤ 0,1 с, kill `main` в [1,0; 1,1] с после `kill()`, сигнал `last` ≥ `t_kill`,
  у `last` 0 terminate и 0 kill, итоги `killed` / `exited`.

Находка по (11). `poll` берёт `now` до вызова `_kill_at`, а `_kill_at` возвращает чуть более позднее
`time.monotonic()`. Поэтому `now >= kill_at` не выполняется, и инъекция сводится к снятию зажима
`deadline − kill_confirm_s`: kill уходит в `kill_start + 1,0`. При `until = t_kill + 2,0` (сценарий из брифа)
это тот же момент 1,0. Зажим держит существующий `test_kill_goes_at_deadline_minus_confirm_when_deadline_is_short`.
С5 ловит немедленный kill (11b). Снятие зажима С5 не ловит: для этого нужен `until < t_kill + 2,0`
(например, 1,5 → kill на 0,5). Я этого не добавлял: бриф задал `until = now + 2,0`.
