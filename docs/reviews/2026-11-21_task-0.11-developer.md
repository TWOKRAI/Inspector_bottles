## Что сделано

1. `registers.py::set_register_verified`: читает поле ДО записи, пишет, читает ПОСЛЕ. Ответ — `verdict.judge(pre, ack, post,
   target, unreadable=..., eq=RegisterOps._values_match)` плюс прежние ключи (`verified` = `success`, `found`, `expected`,
   `actual`, `known_registers`, `ack`). Новые ключи из `judge`: `verdict`, `vacuous`, `pre`, `post`, `unverifiable`.
   Различение «чтение не удалось» / «регистра нет» — новый хелпер `_read_registers_checked` (внешний или листовой `success
   is False`, либо не dict -> `unreadable`); `_read_registers` теперь вызывает его и ведёт себя как раньше.
   Регистр/поле не найдены при успешном чтении -> не `unreadable`, `post = None` -> `failed`.
2. `registers.py::register_restore`: образ до фиксируется копией при первом проходе; каждое поле судит `judge` (тот же `eq`);
   `success` = все поля success; новые счётчики `failed`, `vacuous`; `written`, `skipped`, `verified`, `mismatches` — как
   раньше (`mismatches` строится прежним строгим `got != value`). Решение «писать или нет» прежнее (`cur != value`).
   Поле без записи: `ack = None`, вердикт `vacuous`, success поля `True`. Restore с равным образом: `written 0`,
   `success True`, `vacuous` = число полей.
3. `driver.py::config_reload_verified`: при `success False` и переданной inline-секции `verdict_reason` называет ответ хоста:
   отказ -> `хост отверг config.reload: <error>`; таймаут (не отказ по 0.3) -> `config.reload без ответа хоста: timeout`.
   `success` остаётся `False`, `verdict` — `unverifiable`, `judge` не применялся (BCTL-ADR-008).
   Ветку для таймаута лид не называл: без неё таймаут при inline-секции получил бы либо старую ложь, либо ложное «отверг».
4. `driver.py::_verify_telemetry_effect`: `is_refusal(res)` -> `verified_effect False`, `verification.reason` =
   `хост отверг запись телеметрии: <error>`, поллинг не запускается (обе плоскости). Таймаут не отказ. `success` ответа не
   тронут. Вспомогательный `_host_error_text` (`error`, иначе `reason`).
5. `README.md`: строки `set_register_verified` (ключи `verdict`/`vacuous`/`pre`/`unverifiable`, «`verified` включает
