## Что я истолковал, а не выполнил буквально
1. Каждый `ProcessHeartbeat` держит СВОЙ `CpuClock()` вместо `process_clock().sample()`. Причина: окно дельты синглтона переходило между экземплярами heartbeat, и «на первом тике cpu нет» (тест tester'а) зависело от порядка тестов (воспроизведено: `test_none_allowed_backward_compatible` краснел после t45b). В проде heartbeat один на процесс — поведение то же. `process_clock()` остаётся для `introspect.status`.
2. Правка файла ВНЕ списка FILES: `test_telemetry_default_enabled_hazards.py` — литерал `due_metrics()` из пяти имён стал семью (+cpu, +plugin_ms). Один hunk. Сообщено лиду отдельным сообщением; откатывается независимо.
3. Тест в `test_telemetry_gate.py` переименован `..._five_metrics` -> `..._seven_metrics` (ссылок на старое имя нет: git grep).

## Что оставил открытым / ненадёжно
- Частота для `cycles` берётся из реестра один раз (`~MHz` ядра 0); при турбо/энергосбережении реальная частота другая — калибровки нет намеренно (Task 4.6). Порядок величины верен (busy-поток читается 0.9..1.1), точность не доказана.
- `sample()` не потокобезопасен (зовётся только из потока heartbeat); `introspect.status` зовёт только `seconds_total()`.
- Hazard-тесты не проверены break-injection (это делает лид): особенно тест «опрос не двигает окно» — обещанный отказ при `sample()` в снимке я предсказываю, но не запускал.
- `_maxsize` у `multiprocessing.Queue` — CPython-приватное поле; при переименовании вернётся `None`.
- `pre_report_gate` красный в worktree по среде — не трогал.
