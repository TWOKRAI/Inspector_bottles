## Раунд 2 — фикс-раунд по break-injection + reviewer REQUEST_CHANGES

### MAJOR — R1: ложный dup в журнале при drop поверх delay_ms

Ревьюер воспроизвёл: `fault.delay_ms{ms:1500}`, запись JOB_FLAG-кадра, через
0.3с внутрь ЕЩЁ висящей (задержанной внутри биндера) записи —
`fault.drop{seconds:0.3}`. Клиент не получил ответ, переподключился после
восстановления и повторил ТУ ЖЕ запись. Журнал видел ДВЕ записи
(`{'jobs': 2, 'dups': 1}`) вместо одной (`{'jobs': 1, 'dups': 0}`).

Причина: в биндере `_make_register_binder` (`sim_robot.py`) задержка
(`asyncio.sleep`) стояла ПОСЛЕДНЕЙ — ПОСЛЕ `core.attach`/`on_write`. Журнал
уже засчитал запись (`on_write`), а сам pymodbus применяет запись в регистры
только ПОСЛЕ возврата из `action` — обрыв соединения отменял (`CancelledError`)
зависшую в `sleep` корутину уже ПОСЛЕ ложного счёта.

Фикс: задержка — ПЕРВАЯ строка биндера, до `attach`/`on_write`. Отменённая на
полпути (во время `sleep`) корутина не успевает дойти ни до одного из них —
обрыв не оставляет "недошедшего" следа, его видит только успешный повтор.

Новый авторский hazard-тест —
`Plugins/sim/robot_host/tests/test_faults_hazards.py::test_delay_then_drop_does_not_double_count_journal`
(полный повтор репро ревьюера, с клиентским retry).

### LISTENER ROBUSTNESS — K2, K3, R5

- `start_listener()`: внутри цикла ожидания готовности — если наш
  `_server_thread` уже мёртв, немедленно `RuntimeError` (успешный TCP-коннект
  иначе мог бы быть к ЧУЖОМУ листенеру на том же порту).
- `start()` (обычный подъём процесса) зовёт `start_listener(ready_timeout=5.0)`;
  восстановление после `fault.drop` (`_run_drop`) держит тесный дефолт 0.5с.
- `_run_drop`: после `cancel.wait(seconds)` — retry-цикл восстановления,
  отдельный от `cancel` сигнал `self._shutdown_event` (плагин), взводимый
  `shutdown()`. Каждый неуспешный `start_listener()` -> `report_error(...,
  context="sim_robot_host.drop_restore", throttle=30.0)` + пауза 0.5с. Пока
  идёт retry — `drop` остаётся в `sim_robot.status["faults"]` (честно: связь
  ещё не работает). ponytail: без backoff, потолок — одна попытка/0.5с.

### VALIDATION/CONTRACT — K1, R2, R3, R4

- Все успешные ответы `fault.*` теперь `{"ok": True, "faults":
  self._collect_faults()}` (было только у `fault.clear`).
- `seconds`: число в `(0, 3600]` (была без верхней границы).
- `ms`: округляется (`round(value)`), диапазон `[1, 10000]` после округления
  (была без округления, `(0, 10000]` от сырого значения).
- `math.isfinite` на `int`, не помещающийся в `float` (`10**400`), кидает
  `OverflowError` — поймано в обоих валидаторах (`seconds`/`ms`), отдаётся как
  обычный `bad_args`.

### STATE — R7, R8

- `shutdown()`: взводит `self._shutdown_event` ДО отмены drop (будит retry-цикл

  `server`/`core`, пока сервер ещё жив) — `sim_robot.status` после останова

  упомянуто здесь как известный долг.
