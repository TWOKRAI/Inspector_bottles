## Что я интерпретировал, а не взял буквально из документа (не покрыто тестами directly)

- `params.*.scale/unit/signed/label` НЕ проверяются тестом (проверяются только `id/min/max/default/
  apply/group/gate1`). Я применил правило из вводной params.md §11.3 "Координаты и длины — ×0.1 мм,
  углы — ×0.1°" ко всем координатным/угловым параметрам (`scale: 10`), остальным — `scale: 1`.
  `signed` выставлял по `min < 0` (включая W_MIN-параметры). Это моя интерпретация конвенции YAML,
  не отдельно прописанная в params.md построчно — при кодогене (T1.1) стоит свериться отдельно.
- `P_BELT_FACTOR` (id 35): unit в params.md — "мм/имп ×1e−5", что не укладывается в семантику поля
  `scale` (`Reg.scale`: `stored = value * scale`; 1e-5 как scale для u16-регистра не имеет смысла).
  Записал `scale: 1`, unit как есть текстом целиком ("мм/имп ×1e-5") — реальный смысл этого множителя
  для регистра пока не проверен, тест этого не пинует. Флаг для T1.1/GATE-0.
- `label` в params — взял русский текст из колонки "Смысл" params.md (единственная подходящая русская
  строка); DESIGN просил "label (Russian)" без указания источника колонки.
- `pmir_dict`, `pmir_crc`, `pmir_magic` — `access: rw`, как и весь блок `pmir`: DESIGN явно требовал
  `rw` "for pmir/pmir_*", хотя по смыслу это скорее read-heavy/write-on-boot регистры; не отступал от
  инструкции.
- `tlm_belt_mms`: спека не задаёт множитель (только "s16, скорость ленты", в отличие от X/Y/Z/RZ с
  явным "×0.1"), поставил `scale: 1`. Возможно тоже ×0.1 по аналогии — не пинуется тестом, не факт.
