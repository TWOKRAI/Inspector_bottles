## Что интерпретировал, а не следовал
- Слово в сообщении о зеркале: regex `WAIT\(` / `DELAY\(`, в сообщение идёт найденный фрагмент (`WAIT(`, `DELAY(`, `while`) — тест требует вхождения слова, `WAIT(` его содержит.
- Строка-заглушка `-- @@GENERATED@@` заменяется во ВСЕХ совпавших строках (спека: «missing -> ошибка», про дубли молчит); `lua_block` зовётся один раз.
- Порядок проверок: mirror-проверка идёт в порядке файлов, т.е. после вызова `lua_block` из 10_generated; при ошибке в 80_mirror lua_block всё равно отработает.
- `main`: luacheck запускается и с `--check`, и без; при отсутствующем `src` luacheck-путь просто передаётся (BuildError придёт из build).
- Ошибка первого запуска (моя): `WAIT(` как regex падал `re.error`; исправлено `re.escape`-подобной записью.

## Открыто / ненадёжно
- luacheck ни разу не запускался по-настоящему (его нет в PATH); ветка «запущен и нашёл проблемы» проверена только тестом с подменой subprocess.run.
- Вывод предупреждений в stderr на консоли Git Bash выглядит мойбаке (кодировка консоли cp866/1251); в самом коде проблемы нет, но на Windows без UTF-8 stderr возможен UnicodeEncodeError для нестандартных кодовых страниц — не воспроизводил.
- Хеш зависит от порядка `sorted` по имени файла: NN_ префикс из двух цифр, сортировка лексикографическая — при >99 файлах или префиксе 100_ не сработает (не в spec).
- Артефакт зависит от точного вывода `codegen.lua_block`; смена codegen требует пересборки main_v2.lua (это ловит `--check` / test_repo_artifact_fresh).
- Break-injection не делал (за лидом).
- bandit (pre-commit) ругался на B404/B105/B603 (subprocess, токен @@FW_BUILD@@) — поставлены `# nosec` с причиной; экономил бы отдельную bandit-настройку, но её в FILES нет.
