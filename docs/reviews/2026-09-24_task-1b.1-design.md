+ identity/`unwrap_recipe`). Заметка: `to_topology` может быть identity — PM сам делает `unwrap_recipe`
в `_build_proc_dicts` (`backend/orchestrator_hooks.py:161`), GUI сегодня шлёт **сырой** рецепт

## 2. Хостинг

**Проверка G1b.** Утверждение «у хаба нет receive-мидлвари ни для кого» неточно. Точнее: PM
**ставит** fence + contract-check (`builtin_commands.py:280` → `_register_message_guards` `:3931`,
`add_receive_middleware` `:4004/:4024`), но `RouterManager.receive()` опрашивает только каналы с
префиксом `<process>_` (`router_manager.py:1511-1514`), и сокет `backend_ctl` под него не подходит →
команды через сокет PM обрабатывает **мимо** `_recv_mw` (память `project_backend_ctl_socket_bypasses_mw`,
подтверждено экспериментом 2026-07-21). Для Пульта/драйвера по сокету вывод тот же: хаб их не судит.
Команда дочернему процессу приходит в его `<name>_system` через relay PM → проходит его мидлварь
(вывод по коду, живьём НЕ проверено).

**Кандидаты:**
- **A. PM (хаб).** + `recipe.activate` зовёт `self.apply_topology(td)` в процессе
  (`process_manager_process.py:754`), синхронный результат. − Сокет мимо мидлвари (1b.4 auth негде
  встать); один message_processor-поток на heartbeat/`topology.apply` (`:4056`) → `recipe.list/get`
  стоят за 90-180 с switch-а.
- **B. `devices`** (единственный always-on protected процесс фундамента, `backend/topology/base.yaml`,
  `GenericProcessApp` + `DeviceHubPlugin`, свой реестр `data/devices.yaml`). + ноль новых процессов,
  переживает switch. − смешение доменов, общий приёмный поток с устройствами.
- **C. Новый protected процесс `recipes` в `base.yaml`** (`GenericProcessApp` + плагин-адаптер).
  + переживает switch (protected, `backend/assembly/planner.py:243-251`), мидлварь есть, изоляция.
  − +1 процесс.

**Образец регистрации команд:** плагин объявляет `commands = {"имя": "метод"}` (`Plugins/hub/device_hub/plugin.py:86`),
`base.py:1597-1603` регистрирует **имя как есть** в процессный `command_manager` → `"recipe.list"` ляжет так же,
как `"topology.apply"` у PM (`process_manager_process.py:474`). Коллизий `recipe.*` нет (`rg` → 0 команд).

**Рекомендация: C** (B — допустимый дешёвый фоллбек). Решение и причина — в DECISIONS до кода.

**Главная ловушка хостинга вне хаба:** обработчик команды исполняется на приёмном потоке роутера,
синхронный `router_manager.request()` оттуда → `RouterReentrantRequestError`
(`router_manager.py:1015-1047`, `generic_process.py:62-64`). Механизма отложенного ответа нет (`rg deferred` → 0).
Значит `recipe.activate` в C/B **не может вернуть результат `topology.apply` синхронно**. Варианты:
(1) `request_async` (`router_manager.py:1106`, колбэк на приёмном потоке): ответ `{accepted:true, activation_id}`,
итог публикуется в дерево состояния (`recipes.active`, `recipes.last_activation`); (2) рабочий поток плагина + `request()`
оттуда (легально, как `Plugins/sim/pult_web/plugin.py:21-27`), но ответ на исходную команду всё равно уходит раньше.
Приёмка «после activate `get_status` показывает X» совместима с (1) через `await_condition`.

## 4. Ревизия и запись

- `rev` = `sha256(file bytes).hexdigest()` — считать от байтов на диске, не от dict (ruamel перепишет форматирование).
- Запись сегодня **не атомарна**: `yaml_io.update_yaml_preserving` `open(path,"w")` (`yaml_io.py:81`),
  `update_blueprint_metadata_preserving` (`:124`), `RecipeEngine.save` (`:191`), миграция в `load` (`:276`).
  Атомарный образец — `ManifestStore` (tmp + `os.replace`). Хазард (в) — потребует атомарный writer в `yaml_io`.
- Семантика GUI `save_raw` — **merge top-level ключей** (`adapters/stores/recipe_store.py:98-108`), не замена.
  Решить для `recipe.save`: `body` = полный документ; ключи, которых нет в `body`, удаляются (иначе удаление
  секции невозможно). Комментарии на уровне ключа ruamel сохранит.
- Каталог: манифест уже несёт `recipes: recipes` (`app.yaml`, `backend/config/manifest.py:81`,
  `app_module/manifest.py:71`) — сервис берёт `recipes_dir` оттуда, не хардкод GUI.
- CAS: все редакторы идут через один процесс → `threading.Lock` на имя + сравнение `rev` с хешем
  **текущих байтов на диске** под локом (ловит и ручную правку).

## 5. Контракты команд

Общая форма ошибки: `{"success": false, "error": <code>, "message": str, ...}`;
коды: `not_found`, `conflict`, `invalid`, `bad_request`, `io_error`, `apply_failed`.

| Команда | Запрос | Ответ (успех) | Ошибки |
|---|---|---|---|
| `recipe.list` | `{}` | `{success, names:[str], active: str\|null}` | — |
| `recipe.get` | `{name}` | `{success, name, rev, body}` | `not_found` |
| `recipe.save` | `{name, base_rev: str\|null, body}` (`null` = создать, файл не должен существовать) | `{success, name, rev}` | `conflict {current_rev}`, `invalid {errors:[{path,message}]}` |
| `recipe.validate` | `{body}` или `{name}` | `{success, valid: bool, errors:[{path,message}]}` | `not_found` |
| `recipe.activate` | `{name}` | C/B: `{success, accepted:true, name, activation_id}`; A: `{success, name, apply:{...ответ PM}}` | `not_found`, `invalid {errors}`, `apply_failed` (A) |
| `recipe.delete` | `{name, base_rev?}` | `{success, name}` | `not_found`, `conflict`, `active` (удаление активного — отказ) |

`name` — slug без `.yaml`; отказ на `/`, `\`, `..`, пустую строку (`bad_request`) — иначе path traversal.

## 6. Ловушки (план vs код)

1. `recipes/manager.py` — шим; миграции/`unwrap_recipe`/save — в трёх других файлах (§1).
2. `launch.py:414-465` — это `persist_pipeline_choice`, не чтение рецепта при старте (`:512-590`).
3. «Перенос `app.yaml` под activate» при GUI вне скоупа — фактически второй писатель (§3).
4. Хостинг вне хаба ⇒ activate асинхронный (`RouterReentrantRequestError`); план молча подразумевает синхронный ответ.
5. Хаб не «без мидлвари»: мидлварь есть, её обходит сокетный канал (§2) — критерий верен по сути, неверен по формулировке.
6. Запись не атомарна нигде, кроме `ManifestStore` — хазард (в) требует правки `yaml_io`.
7. `save_raw` — merge, не replace; `save_layout` (автосохранение позиций при перетаскивании, `recipe_store.py:110`)
   меняет байты → меняет `rev` → в 1b.3 собственный save GUI получит `conflict` после любого перетаскивания.
8. `check_structure()` отдаёт строки без путей — `{path, message}` у хука будет с `path=""`/`"blueprint"`, пока валидатор не научится адресам.
9. ADR-RCP-006 (предложен, 2026-08-18): единица рецепта станет **папкой** (`topology.yaml` + `params/`).
   `name` → файл сегодня, контракт `get/save` по «одному документу» разойдётся с v4. Назвать в DECISIONS.
10. Upsert устройств до apply (`presenter.py:407`) — ещё один шаг активации в GUI; «второго пути применения
    не появляется» соблюдается, только если activate его тоже делает или это явно вынесено.
11. Хост в `base.yaml` появится в каждом рецепте/тесте характеризации сборки — снапшоты `SystemBuilder` покраснеют.
