## Арбитраж CTO — ACCEPT WITH CONDITIONS

Воспроизведено CTO: находка 2 (тик gen2=2, 89.3 мс; автосборка gen2=0); `len(gc.get_objects(2))` на 1.5M = 35.3 мс (страж long_lived из Python не дешевле паузы); полная сборка 1.5M 76–92 мс, после `freeze` 0.0 мс; вариант «gen2 никогда» течёт (100 000 циклов в gen2 резидентны до `collect(2)`); куча импорта GUI 127 433 объекта → полная сборка 32–36 мс; модель гейта: заморозка на каждой границе — total 17 245 → 81 мс.

- **D1** — тик: вход при `counts[0] > thresholds[0]`; выбор поколения по `>`; gen2 не чаще `full_interval_s` (новый параметр `collect_on`, по умолчанию 60.0, `>= 0`, 0 = без ограничения), иначе gen1; `collect(full=True)` — без ограничения. Docstring, ADR-PM-053, спек: «страж long_lived недоступен — вместо него ограничение по времени».
- **D2** — стенд: устойчивый режим = от заморозки (или `install`) + 60 с; разовые сборки заморозки — отдельно. Тики gen0/gen1 `max ≤ 50 мс`; полных сборок ≤ `600/full_interval_s + 1`; полная `max ≤ 100 мс` при `FW_GC_FREEZE=1`, при 0 — отчёт владельцу; RSS ≤ 1.15× медианы 2 прогонов; ≥ 2 прогона на режим; разбивка пауз по поколениям; объяснить 14 против 147 сборок.
- **D3** — гейт: `total_pause / (wall − total_pause) ≤ 0.10`; пауза границы ≤ 250 мс; контроль HEAD/база на `process_module`, `router_module`, `state_store_module` (медиана 3) ≤ 1.10×; `foreign_collections` — храповик от 281; нарушений 0, abort 0/N. Средство: `gc.freeze()` после полной сборки на границе теста (только фикстура сессии; в прод-тик — никогда).
- **D4** — ядро остаётся в `process_module/lifecycle/gc_discipline.py`; ленивый `__getattr__` в `process_module/__init__.py` — в план `gui_client`.
- **На приёмке:** инъекции «gen2 без ограничения», «граница без freeze», «`>=` обратно» (эквивалентная мутация допустима с записью); гейт `n=3` с числами D3; имя внутреннего упавшего теста во флаке `test_declarations_leak_order_independence`; стенд по D2; Q5 — «не различает на этой машине»; числа в `plan.md`; поправка ADR-PM-053.
