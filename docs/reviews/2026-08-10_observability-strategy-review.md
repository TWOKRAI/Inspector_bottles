## Вердикт

Система **несимметрична**: плоскость сбора и управления (control plane) — на уровне лучших индустриальных систем, местами объективно выше; плоскость **потребления** (поиск, панели, человек за экраном) и **выход в экосистему** — заметно ниже, и это ровно то, чем выигрывают коммерческие продукты. Для конструктора перекос правильный — при условии, что OTel-экспорт (этап 7) не задерживается: он один закрывает ось «экосистема» целиком.

| Плоскость | Против рынка | Одной строкой |
|---|:---:|---|
| Модель записи | 9 | OTel-словарь принят до провода: severity_number, Resource-пятёрка, `observed_ts` приёмником, `trace_id` W3C |
| Control plane | 9 | verified-вердикт + TTL + аудит + L0–L3 + рецепт — этого набора нет ни у кого из массовых |
| Цена и учёт потерь | 8 | всё посчитано и говорит; сэмплер ни разу не жил (С-8) |
| Метрики | 6 | 4 типа и p95 есть; бакетов/скетчей/exemplars нет, `histogram()` в проде не зовётся |
| Потребление человеком | 3–4 | вкладка ERROR-only (чинит этап 1), поиска нет (С-2), группировки ошибок нет (С-3) |
| Экосистема | 2 | экспортёра нет; «соответствие OTel остаётся заявленным» — до этапа 7 |

## §1. Что уже лучше коммерческих систем — капитал, беречь

1. **Verified-смена конфига** — `config_reload_verified`: трёхзначный вердикт (`confirmed/failed/unverifiable`) + окно доставки (`delivering/losing/silent_source`) + вычет цены самого опроса (~5.1 записи/опрос, замер live). Spring/Envoy отдают `200 OK`; Datadog Remote Config докладывает «applied» — но связку «значение действует + записи фактически идут + цена проверки вычтена» не даёт никто из массовых.
2. **TTL-автооткат операторских правок** (300 с, исполняет такт heartbeat; `ttl_enforced: false` там, где гарантии нет). В облаке эту роль играет рестарт пода; промышленная установка, живущая неделями, такого выхода не имеет.
3. **Аудит смен с origin, обязательным сигнатурой** (TypeError вместо тихого «источник неизвестен»; 8 закрытых действий; схлопывание повторов). У Datadog/Grafana Enterprise аудит есть, но дисциплинарный; здесь — конструктивный.
4. **Потеря со счётом и голосом как закон**: пять именованных классов потерь + счётчик доставки + `observed_at`; первый отказ говорит с адресом; очередь наблюдаемости отделена от рабочей (`drop_oldest` 256, `observability_evicted`) — по итогам собственного замера 97 066 отказов на общей очереди. Уровень лучших агентов (Vector/Fluent Bit), выше любых in-process логгеров.
5. **Слои L0→L3 с provenance и сбросом-удалением** + **наблюдаемость как часть рецепта** (L2 едет со switch, `persist` переводит правку в рецепт). Богаче Spring `configured/effective/null`; привязка к рецепту — фича, которой у generic-систем нет и не будет: преимущество именно конструктора.
6. **Плоскость документов** (вердикты/аудит, ретеншен по роду: год/десять лет, допуск структурный). MES-мышление; коммерческая наблюдаемость per-part traceability не покрывает.
7. **Методика доказательства** — break-injection на каждое свойство, оракул контракт↔хендлер (36 команд, AST), стражи writers/testpaths. Не фича продукта, но причина, по которой этим цифрам можно верить.
8. **Алертинг и recorder уже есть в правильной форме**: декларативные supervision-правила с cooldown ([`alert_rules.py`](../../multiprocess_framework/modules/process_manager_module/core/alert_rules.py), чистый модуль без I/O) и driver-recorder `record_*` с offline-реплеем (аналог rosbag из ROS 2 — редкая вещь вне робототехники).

## §2. Паритет

- **Модель записи** выровнена по OTel Logs Data Model — но «совместимы по модели, а не по проводу»: ни один внешний потребитель ни разу запись не разобрал (снимает этап 7).
- **Метрики**: counter/gauge/timing(p95)/histogram — модель есть; но histogram = тот же сырой список с p95, без бакетов/HDR/скетчей, и `histogram()` в проде не вызывается; перцентиль только p95; плоскость stats без стора и хвоста (осознанно, этап 6).
- **Редакция секретов всегда включена, fail-closed** (18 имён + текст + URL-креды + auth-схемы, предфильтр 0.57 мкс) — у Datadog это платный Sensitive Data Scanner.
- **Сэмплер повторов** (first-N-then-every-Mth по level+тексту, стиль zap; ERROR+ не трогает) — есть, но `sampling_first_n=0` по умолчанию и **дважды в приёмках «не проверено live»**. По закону проекта «названный механизм — не обязательство» — пока не существует (С-8).
- **trace_id-корреляция реально работает** (подтверждено инвентаризацией §8): рождение у `SourceProducer`, доставка через `log_correlation` в каждом потоке, покрыто тестами. Спаны кадра (transport/process/merge, critical path на fan-in) существуют за `MULTIPROCESS_FRAME_TRACE`.

## §5. Производительность — приемлемо и, что важнее, доказано

Гейт отклонённой записи ~240 нс, эмиссия ~4.3 мкс, полная запись с файлом ~20 мкс, **вся плоскость на живой нагрузке 8×21 Гц — 0.03 % ядра** — для Python это уровень лучших (loguru того же порядка; spdlog/C++ — другой язык, не наша лига и не наша необходимость). Отдельно одобряю как анти-карго-культ: буфер записи **снят по замеру** (Ф7.4: p99 хвоста эмитента 1348 → 75 мкс — индустрия дефолтит async, здесь измерили и отказались), фон меряется дельтой (~2.75 МиБ/ч на 8 процессов; главный источник — stats-снапшоты, 56 % объёма у ПМ по замеру 2026-08-03, этап 3 срежет пустые). Стор: 542 Б/строка, потолок 200 000 строк ≈ 110 МБ ≈ 40 ч — арифметика названа.

Единственное узкое место по построению: синхронная запись в потоке-эмитенте при шторме сериализуется в горячем потоке; защита — сэмплер, который выключен и не проверен (С-8), плюс лесенка ADR-LOG-009 спасает соседей, но не поток-жертву (факт инвентаризации). Не дефект — названная граница; она и делает С-8 обязательным.

## §6. Стратегия для конструктора

Архитектурная позиция выбрана верно и она редкая: наблюдаемость — **core-ярус** ([MODULE_TIERS.md](../../multiprocess_framework/docs/MODULE_TIERS.md)): каждое приложение получает её даром, плагин — через `PluginContext`, седьмой тип стока — без правок фреймворка, AcmeWidgets поднялся тремя ручками без доменных слов. Это форма Erlang/OTP и .NET `ILogger`, а не «прикрученного агента».

- **Ров (moat) — control plane**: verified/TTL/audit/слои/рецепт. Продолжать копать там — у рынка этого нет.
- **Потребление — тонкое локально, тяжёлое наружу** (С-1/С-2/С-3).
- **Дефолты поставки решить явно**: из коробки ретеншен выключен (`retention_days`/`retention_total_mb`=0) и сэмплер выключен (`sampling_first_n=0`) — для конструктора «безопасно по умолчанию» стоит зафиксировать отдельным решением (стенд включает через конфиг, но чужое приложение получит «диск пухнет» молча).
- **DX — продукт**: слепой прогон рецепта повторяемым гейтом (С-9).
