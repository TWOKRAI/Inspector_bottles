## Смены поведения для ADR-RCP-009 (HANDOFF OUT)

- `recipe.save`: комментарии, порядок и стиль YAML сохраняются (пишется дельта).
- Post: «на диске normalize(body)» -> `normalize(YAML файла после записи) == normalize(body)`; умолчания, которых нет в файле, не создаются.
- Непарсимый текущий файл или не mapping (в том числе пустой файл) -> `invalid` (раньше перезаписывался), файл цел.
- Рецепт v1 (top-level `topology:`) -> `bad_request` «рецепт v1: сначала миграция», файл цел.
- Legacy top-level `gui_positions` (и другие ключи, которые `normalize` переносит) при `save` сохраняются в файле (раньше стирались).
- Несериализуемое тело -> `bad_request` до записи, но ПОСЛЕ сверки `base_rev` (устаревший `base_rev` + несериализуемое тело теперь `conflict`); текст исключения в ответ не попадает.
- Пустая дельта: файл не тронут (байты и mtime), `rev` прежний.
- `TypeError` из движка (тело с `bytes`, `1j`) -> `io_error` (принято, не прослежено).
- `RecipeEngine.save` по существующему файлу: `meta` не переписывается (`created_at`, `name`, `description` сохраняются), `meta.version` приводится к `recipe_version`; ветви `data` вне `snapshot_paths` целы; путь, которого нет в сторе, удаляется вместе с опустевшими предками (корень `data` остаётся); непарсимый файл -> `yaml.YAMLError`, файл без `meta` (v3) -> `ValueError`, файл цел.
- Новый файл (создание) обоих писателей теперь пишется ruamel-дампом: порядок ключей — как в словаре (у engine `meta` перед `data`; старый `yaml.dump` сортировал ключи по алфавиту — `data` перед `meta`), стиль/кавычки могут отличаться от прежних.
- Миграция в `load` пишет дельту: комментарии сохраняются, `meta.version` и `migrated_from_v1` проставляются, `.yaml.bak` как раньше.
