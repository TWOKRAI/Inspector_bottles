## Трактовки спеки

1. **Р4 потребовал правки движка** (в FILES: `yaml_io.py`). Тест `yaml11_scalar_unchanged_not_rewritten` красный по существу:
   `_verify_dump` сверял чтение дампа PyYAML с ruamel-документом, а неизменённое `yes` ruamel (YAML 1.2) держит строкой, PyYAML (1.1) читает
   `True` — запись по ЛЮБОМУ файлу с `yes`/`on` отказывала `ValueError`, даже при правке соседнего листа. Исправление: ожидаемое чтение =
   исходный текст, прочитанный PyYAML, плюс та же дельта (`apply_delta` на plain-dict, `_expected_by_pyyaml`). Если PyYAML исходник не читает
   или дельта на plain-dict не ложится — сверка с ruamel-документом, как раньше. Страж «лист стал строкой `On`» остаётся (тест
   `test_dump_unreadable_by_pyyaml_refuses_write` зелёный). Это решение шире DESIGN 1–4; лид вправе его пересмотреть.
2. `on_insert` добавлен в `apply_delta` и в `_Delta`; в `patch_yaml_preserving` НЕ добавлен (DESIGN: «apply_delta и движок»; адаптер 1.1g зовёт `apply_delta`).
3. Путь элемента списка для `on_insert` — место в `after` (`j1 + overlap + offset`), не индекс промежуточного списка цели.
4. Отказ на смене корня действует и в `save_layout` (общий `_write`): иначе раскладка v1-файла дописала бы второй ключ `blueprint` рядом с `topology`.
5. «Пустая дельта» в контракте — сквозная: файл из `doc` -> `read_canonical` -> `patch_recipe` без правок -> `rev`, байты, `mtime` те же и без отказа. Поэтому
   хук, вводящий корневой ключ (даже идемпотентный), контракт не проходит; `docs` должны быть рецептами текущей формы (записано в docstring).
6. `RecipeFormatError` сейчас импортируется как `recipe.manager.RecipeFormatError`; в `recipe/__init__.py` не экспортирован — файл вне FILES.
7. Пустой файл (`safe_load` -> `None`) для `read_canonical` — не mapping -> `RecipeFormatError`; в `_write` поведение прежнее (`before = {}`). Тестом не закреплено.

## Что осталось открытым / ненадёжно

- **`recipe/__init__.py` не экспортирует `RecipeFormatError`** (вне FILES) — две строки (импорт и `__all__`); решение лида.
- **Flaky-тест вне задачи:** `test_yaml_patch.py::test_property_patch_with_comments_reaches_after` (hypothesis) находит падения; воспроизводятся и на `HEAD`-версии
  `yaml_io.py` (повтор сохранённых примеров дал красный с теми же примерами: `PyYAML читает дамп иначе` и `ScannerError: mapping values are not allowed`
  — перенос комментария даёт невалидный YAML). Два чистых прогона на `HEAD` прошли, один из двух на моей версии упал — вероятностный тест, моё изменение его
  причиной не доказано, но и «чисто» не доказано. Примеры сохранены в `multiprocess_framework/modules/.hypothesis/examples*` (в gitignore); при красных повторах этого
  теста сначала убрать каталог `examples` в сторону. Для лида: открытый дефект 1.1a (F16), не 1.1f.
- Тест `hook_contract_accepts_identity_hook` на каркасе зелёный (ничего не отвергающий каркас). Силу даёт связка: отрицательные тесты красные без проверок и положительный — зелёный с ними.
- Контракт не проверяет «хук не мутирует вход» (Post протокола `RecipeFormatHook`) — в списке лида нет; проверка стоит строки, тест — хука-мутанта.
- Подпроцессы контракта: ~1,5–2 с на вызов (4 параллельно); потолок 120 с на всех. Кодировка вывода дочернего процесса — UTF-8 (`PYTHONUTF8=1`); хуки, печатающие в stdout, допустимы (результат — строка с меткой).

- `yaml.safe_dump` тел `docs` в контракте: тела с ключами не-строками/не-JSON типами не пройдут через JSON-файл подпроцессов (записано в docstring).
- Лок POSIX, как и в 1.1e, не исполнялся; контракт запускает `RecipeManager` -> `recipe_file_lock` во временном каталоге на Windows.
- Документы модуля (`README.md`, `STATUS.md`, `DECISIONS.md`) не обновлены — вне FILES; ADR-RCP-010 пишет Task 1.3.
