Задача: [`plans/line-sim/phase-5-ground-truth.md`](../../plans/line-sim/phase-5-ground-truth.md), Task 5.1, п.4 контракта лида. Стенд вёл лид; скрипты — в scratchpad сессии, вводы и выводы ниже.

Два приложения на `main` (`3c16fe3c`): сим 8766/5021/8091/8092, прототип `letter_robot_sim --headless`
на 8765, оба с `FW_SHM_OWNER_INCARNATION=1`. Лента 101.13 мм/с, диски с шагом ≈ 1190 отсчётов (164 мм).

**Отклонения от формулировки п.4 — сказаны вслух:**
- **Задания шли не из зрения прототипа, а через его драйвер:** `backend_ctl` 8765 → `devices.robot_enqueue_job`
  → настоящий `RobotDriver` → Modbus → сим. Петля «кадр сима → распознавание → задание» сейчас не
  замыкается по трём независимым причинам: кадр сима 640×180, а ROI прототипа `x=246, y=297, w=800` —
  целиком вне кадра; нет `config/calibration/cam0.yaml` (без `pick_xy` `word_layout(require_pick=True)`
  не шлёт); на этой машине нет модели `mobilenet_v3_large_20260616_050828` (ошибка `ml_inference` в
  логе). Это Ф4 (виртуальная камера) + калибровка сим-варианта. Ответ на вопрос владельца «одна
  деталь → три задания: прототип или робот» этот стенд **не даёт** — он проверяет только измерение.
- **`job_ms` = 20 мс, не ≥ 1000:** в `robot_host` нет ручки тайминга, ядро идёт с `job_ticks=2`.
  Медленный робот важен только в петле со зрением (камера успевает переснять деталь); без неё на
  результат не влияет. Ручка `job_ms` — вместе с петлёй Ф4.

Ошибок в логах сима за прогон — 0.

**Находка — ошибка модели в п.1 контракта (моя), а не в реализации.** Офлайн-повтор правила п.1
на тех же 21 задании даёт ровно `dups 0 / repeats 11` — код делает то, что написано в контракте.
Неверна сама категория: «те же X/Y с новым энкодером» — это ещё и **нормальный режим линии**.
Неподвижная камера и триггер (`line_filter`) снимают каждый диск в одной и той же точке кадра, поэтому
`pick_xy` у разных дисков совпадают в пределах миллиметров, а энкодер у каждого свой. По тройке
`(x, y, ecap)` такой случай неотличим от «повтор кадра / энкодер прочитан при постановке». Окно
`dup_window_s = 10 с` при шаге дисков 1.6 с держит ~6 предыдущих заданий. Итог: на живой линии
`repeats_frozen_xy` ≈ N−1 при нуле повторов, а пульт подпишет это «те же X/Y с новым энкодером».
Владелец прочитает это как «прототип повторяет задания», то есть получит неверный ответ ровно на
свой вопрос. `dups` / `dups_same_capture` / `dups_tracked` находка не задевает: (а) и (а') дают 0 на
разных дисках, (б1) ловит дубль.

**Статус 5.1:** `dups` и его разбивка на причины приняты. `repeats_frozen_xy` в текущем смысле на
линии с триггером **не годится** — решение в п. «Открыто» ниже.

**Открыто (решение владельца):** что делать с `repeats_frozen_xy`. Отличить повтор кадра от
соседнего диска можно только тем, чего в регистрах задания нет: номером кадра / id объекта на
стороне прототипа (Task 5.3) или правдой сима (Task 5.2, сопоставление с объектом). Варианты:
(1) убрать счётчик и строку пульта до 5.2/5.3, строка журнала с Δenc остаётся для глаз;
(2) оставить, но переименовать в «совпадение X/Y с недавним заданием» без слова «повтор»;
(3) классифицировать по правде сима — задание, совпавшее с другим объектом (`matched` в 3.5),
повтором не считать. Рекомендация лида — (3): правда уже есть в процессе сцены, и это единственный
вариант, который отвечает на вопрос владельца, а не только перестаёт врать.
