### Репро (воспроизведены ревьюерами на реальных функциях)

* **Ф-1:** recipe `{scopes:{DEBUG:{enabled:true}}}`, сессия владеет `scopes: {}` → `resolve() == {'scopes': {}}` ✓; после переезда L3→L2 (`builtin_commands.py:2055`) → `resolve() == {'scopes': {'DEBUG': {'enabled': True}}}`. Файловый путь тот же: `persist_session_to_companion(..., {"scopes": {}})` → success, keys=['scopes'] → `compose_over_base` возвращает scopes рецепта.
* **Ф-2:** `resolve_recipe_section({"defaults":{"scopes":{DEBUG...}},"processes":{"p1":{"scopes":{}}}}, "p1")` → `{'scopes': {'DEBUG': ...}}`.
* **Ф-3:** L1 `telemetry.throttle={"processes.a.state.fps":1.0}` + сессия владеет листом `{"processes.b.state.fps":2.0}` → resolve даёт **слитый** `{a:1.0, b:2.0}`, provenance — «session владеет листом целиком». Достижимо файловым reload (`builtin_commands.py:1677`).
* **Ф-4:** `session_set("scopes.trace.min_level", ttl=0)` (бессрочно) → inline `{"scopes": {}}` → сессия не изменилась, но `ttl == {'scopes': 300.0}` → через 301 с `expire_due()` снял чужую бессрочную правку.
* **F1:** `repro_hol.py` — инкарнация A не готова, replay в очередь → switch, событие B взведено сразу → второй replay. Выход `[('stale_replay_A', 4.02), ('fresh_replay_B', 4.02)]` при дедлайне 4 с. До B-5-1 свежий поток ждал своё живое событие и доставлял сразу. Стейлы штабелируются последовательно (N×дедлайн).
* **F2:** инъекция-откат (ранний `system_ready_event.set()` в `initialize()`, `attach_ready_event` снят) → `test_capabilities.py` 12 passed ×3 прогона. Красный на HEAD был гонко-зависимым.
* **F3:** before `{"logger": written=100}`, after `{}` → `reset=False planes=['logger']`. То же при счётчике-строке.

### Предложенные фиксы (от ревьюеров)

1. **Ф-1/Ф-2/Ф-4:** перевести четыре шва на `layer_merge` — отношение «новее/частное поверх старшего/общего» то же самое, что слой над слоем. Для inline-дельты принять явное решение (владеть или громко отказывать) и закрепить тестом.
2. **Ф-3:** prefix-параметр в `layer_merge` + запрет рекурсии в opaque-путь (третий обход, забывший список; два других — `flatten_section`, `_overlay_owner` — помнят).
3. **F1:** в цикле опроса `_run_child_action_after_ready` перечитывать текущее событие реестра на каждом срезе 0.25 с (захваченное ≠ текущее → ждать текущее). Либо дать трём вызывающим `still_relevant` = «инкарнация та же». **Либо снять ложное утверждение из ADR.**
4. **F2:** детерминированная пара юнитов: (а) `initialize()` PM не взводит `system_ready_event`, а прикрепляет; (б) `ProcessModule.run()` взводит прикреплённое последним действием, после регистрации builtins.
5. **F3:** в missing-ветке `counters_reset=bool(reset_planes)`; ремень `reset = bool(reset_planes) or loss_delta < 0`.

## Костыли — поимённо (ответ на вопрос владельца)

1. **Правило Г3 живёт в одном merge из пяти** — главный костыль корзины: каждое новое место сборки слоя обязано помнить, каким merge мержить, и следующий забудет (Ф-1/2/4 — уже забыли).
2. **Опора очереди на выгорание дедлайна** для стейлов без `still_relevant` (F1). ADR утверждает, что проблемы нет — это хуже, чем признанный долг.
3. **`OPAQUE_LAYER_PATHS`** — честно назван спецслучаем в ADR-PM-024, но требует, чтобы КАЖДЫЙ обход слоёв о нём помнил. Три обхода — два помнят.
4. **`_apply_section` ×2 в тестах** — байт-идентичные копии без стража идентичности, разойдутся молча. Один helper в conftest стоил бы столько же.
5. **Lazy-`__dict__` свойства** ради no-op `__init__` в тестах — продакшн-код изогнут под способ постройки тестовых PM; корзина добавила три новых экземпляра.
6. **`telemetry_owned`/`throttle_owned` липкие флаги** — `telemetry: {}` через них означает «вернись к boot», а не «владею пустым»; рядом с Г3 это нигде не записано.
7. **Безусловные `errors.level`/`stats.log_level`** — граница сегодня честная (проверено кодом), станет костылём при появлении env-источника; ADR-PM-026 это сам называет.

**НЕ костыль (проверено):** `cost_exceeds_window` — не прячет проблему, а вслух признаёт недостоверность арифметики; `losing` не трогает (репро E9); честный вычет по авторству назван резидуалом корзины 3.

## Advisory (знать, не обязательно чинить)

* **A1** Старое агрегатное правило `loss_delta < 0` поглощено не полностью: плоскость с потерями, но БЕЗ счётчика доставки, исчезнувшая между снимками, не флагуется. Сегодня нереалистично (все плоскости несут `channel_written_records`), но правило беззащитно к будущей плоскости без него.
* **A2** `forget_*`: окно «снял под локом → разослал вне лока» — конкурентный `subscribe_all` того же адреса может уехать ДО unsubscribe. Самолечится на следующем шве инкарнации; для сессий недостижимо (session-id уникален).
* **A3** Ленивые `__dict__`-property — гонка первого обращения (два потока → два разных Lock). Реально первый вызов одноредочный на boot.
* **A4** Провал `threading.Thread.start()` оставит имя в `_child_action_running` навсегда → очередь ребёнка застревает молча. Обёртка со сбросом флага в `except` — три строки.
* **A5** `forget_session` из read-потока тянет `_broadcast_command`; с учётом известной ветки kind-channels read-поток может подвиснуть на секунды.
* **A-2 (область слоёв)** `ObservabilityAudit.record` возвращает **живой** словарь кольца первому вхождению (копию — только при схлопывании): после A-A6-1 запись мутирует спустя время. Продакшн-держателей ответа нет — ловушка API; вернуть `dict(entry)` в обеих ветках.
* **A-3** `log_level: null` в слое (по Г3 легальное «владею null») валит пересборку `ValidationError` — громко, но нигде не названо.
* **A-4** Неизвестные ключи `config.reload` (опечатка `observability_resett`) молча игнорируются — тот же класс ловушки, из которого только что вынули `persist`.
* **A-1** Зонд L4 (`publish=null`) без контрольной половины: зелен и если гейт на шаге 1 вообще не поднялся.
