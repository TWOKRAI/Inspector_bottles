## Решения, которых не было в файле задачи

1. **Триггер довыставления только при `record_history=True`.** Файл задачи говорит «хвост пополняется только внутри `if record_history:`», про триггер молчит. Я привязал оба: источник уровня (инвариант 1) метку потока не закрывает. Сторож и инъекция — `test_level_sources_do_not_restamp_history`, I10.
2. **`read` включает в метку только присутствующие поля** (через часового `_MISSING`), а не `get(..., None)`. Иначе писатель без `incarnation` вышел бы `fresh` там, где `read_value` над деревом даст `no_data`. Сторож и инъекция — `test_mark_without_incarnation_is_no_data`, I14.
3. **Не-конечный `src_ts`** (`None`, строка, `nan`, `inf`) довыставления не даёт. Хвост остаётся и ждёт следующую метку (ограничен числом колец корня).
4. **Поля метки перечислены локально** (`_MARK_FIELDS`), приватное `_MARK_KEYS` из `freshness.py` не импортировано; дрейф ловит `test_mark_fields_match_the_writer_stamp`.
5. **Ключ хвоста** — `processes.<P>` (`_process_root`); пути вне `processes.` хвоста не имеют и остаются на времени приёма.
6. `read` всюду определена: ключ не строка, ключ сквозь лист метки (`_fresh.seq.x`) -> `no_data`, без исключения.

Тест, который может зависнуть: нет. Ни лока, ни потока, ни `sleep`; daemon-поток с дедлайном не нужен.
