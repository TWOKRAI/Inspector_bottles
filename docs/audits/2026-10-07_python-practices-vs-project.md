## Что выяснилось по ходу (не из статьи)

1. **Профилирование и телеметрия — разные вещи.** Телеметрия: «`processor` тратит 16.8 мс». Профилирование: «потому что у OpenCV 16 потоков на процесс». Перформанс-аудит `2026-09-29_high-fps-perf-review.md` нашёл всё одноразовыми хуками (py-spy, psutil, перехват `Queue.put`) и перечислил, чего штатно не хватает: CPU по процессам и потокам, размер сообщений по очередям, байты SHM за кадр. Это пробелы **телеметрии**, а не повод строить профайлер.
2. **`Utils/profiling.py` — заглушка** (20 строк, `tracemalloc` + `print`, не импортируется). Профилированием не является.
3. **py-spy на Windows ненадёжен в одиночку.** Аудит: `--nonblocking` плохо отличает ожидание от работы; CPU камеры py-spy 0.31 против psutil 0.02–0.03 — одно из измерений неверно. Выводы сверять двумя инструментами.
4. **asyncio на Windows будит `sleep` раньше срока** на грубых часах (шаг `monotonic` ≈ 15.6 мс). В нагруженном цикле 241 из 300 засыпаний по 0.3 с оказались короче, минимум 0.2835 (`docs/reviews/2026-09-29_sim-windows-tests-debugger.md`). Подтверждено на `asyncio.sleep` симулятора; на других путях не проверялось. Для будущего async-рантайма это первое условие дизайна: абсолютные дедлайны и `perf_counter`.
5. **`anyio` отдельно брать не нужно:** `asyncio.TaskGroup`, `asyncio.timeout`, `asyncio.to_thread` есть в 3.12. `uvloop` на Windows не работает.

**3. Раннее пробуждение `asyncio.sleep` воспроизведено на этой машине (Windows, 3.12.12), и на 3.13+ его нет.**

Скрипт: 100 засыпаний по 0.05 с, 3 повтора, с фоновым тикером 1 мс и без.

| Версия | Разрешение `monotonic` | Без тикера | С тикером |
|---|---|---|---|
| 3.12.12 | 15.625 мс | 0/100 рано | **97–100 из 100 рано**, минимум 0.032 с при заказанных 0.05 |
| 3.13.2 | 100 нс | 0/100 | 0/100, минимум 0.0502 |
| 3.14.0 | 100 нс | 0/100 | 0/100, минимум 0.0598 |

Значит: (а) дефект из `2026-09-29_sim-windows-tests-debugger.md` — не артефакт симулятора, он общий для asyncio на Windows/3.12; (б) на 3.13+ он исчезает, потому что `monotonic` переехал на QPC — это закрывает вопрос аудита «Python 3.13 мог перевести `monotonic` на QPC — не сверено»; (в) по тому же механизму 15.6-мс квантование `latency_ms` камеры и `time.sleep`-пейсинг (находка 4 перформанс-аудита) — артефакт именно 3.12. Ограничение замера: одна машина, 300 засыпаний на строку таблицы, только `asyncio.sleep`.

- Пробелы телеметрии из аудита (CPU по процессам/потокам и др.) — в трек наблюдаемости, с ручкой «выключено = ноль нагрузки».
