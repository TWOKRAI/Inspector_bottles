Это не одна программа, а конструктор. Сценарий инспекции описывается в одном текстовом файле: какая камера, какие блоки обработки, куда отправлять результат. Блоки переставляются без изменения кода, параметры меняются на ходу с пульта.

  • Несколько процессов на всех ядрах процессора, кадры между ними без копирования
  • Автоматический перезапуск упавшего блока без остановки линии
  • Изменение настроек на ходу, без перезапуска
  • Встроенные журналы, телеметрия и удалённое управление по сети
  • Подключение промышленных устройств: робот, частотный привод, Modbus
  • Графический редактор схемы обработки и режим без экрана для встраиваемых устройств

Качество, которое проверяется автоматически

  • Архитектурная проверка: 0 циклических зависимостей, 0 «монстров», оценка 7023 из 10000
  • Каждое заявленное свойство подтверждено тестом, который краснеет, если свойство сломать
  • Независимая приёмка каждой задачи отдельным агентом-ревьюером с воспроизведением
  • Границы между слоями системы контролируются инструментом, а не договорённостью

Единственное место, где Python проигрывает в сто раз, это цикл по пикселям, написанный на самом Python. В системе такая функция одна: обход контура для построения траектории робота. Проверено поиском по всему коду. 4 сентября она закрыта за один день в два шага, и это показывает, как в Python лечится такая проблема: без смены языка, без компилятора на машине, тем же кодом.

Обход контура на детальном кадре 640×480 (35 тыс. точек скелета). Шаг 1: переписать структуру данных. Шаг 2: включить компилятор Numba на ту же функцию, одна строка. Оба шага прошли одни и те же 104 теста.

Раздел 5

Преимущества и недостатки

Обе колонки одинаково честные. Недостатки названы теми же словами, что и в внутреннем аудите.

Преимущества

  • Скорость разработки. Конструктор с 17 сценариями за год одним инженером вместо команды. Новый блок обработки агент пишет по описанию за часы.
  • Сценарий без программиста. Инспекция описывается текстовым файлом, параметры меняются с пульта на ходу.
  • Всё тяжёлое уже на скорости C. OpenCV, NumPy, PyTorch. Обвязка меньше 5% кадра, измерено.
  • Промышленная обвязка встроена. Журналы, телеметрия, удалённое управление, автоперезапуск, Modbus, робот, привод.
  • Один код для Windows, Linux, Jetson, Raspberry Pi. Режим без экрана: устройство работает, оператор смотрит с ПК.
  • Проверяемое качество. Тестов больше, чем кода; 0 циклических зависимостей; каждое решение записано с обоснованием.
  • Выход в C++ или Rust предусмотрен. Сверхбыстрый блок подключается к той же шине, система не переписывается.

Недостатки

  • Один носитель знаний. Систему знает один человек. Документация большая, но второй человек её ещё не проходил.
  • Ядро больше приложения. 318 тыс. строк ядра против 129 тыс. приложения. Часть слоёв держится на дисциплине, а не на необходимости.
  • Нет чисел с реальной линии. Замеры на синтетике и веб-камере. Проект называется «инспектор бутылок», а показывает рисующего робота.
  • Память и старт. Процесс с нейросетью 400 МБ и 3 с старта. На Raspberry Pi это ограничивает число процессов.
  • Потолок скорости. Сотни кадров в секунду и отклик быстрее 1 мс на чистом Python недостижимы, нужен нативный блок.
  • Linux не проверялся автоматически. Одно известное место в общей памяти надо исправить до первого Jetson. Версия Python прибита к 3.12, на Jetson Orin стоит 3.10.
  • Файл сценария многословен. Рабочий рецепт 529 строк, треть из них пульт. Адресация блоков по номеру ломается при вставке нового.
  • Документации 1 673 файла. Такой объём дорого держать в актуальном состоянии одному человеку.

Раздел 8

Что просим одобрить

Направление и один измеримый этап, после которого оценка становится не оценкой, а фактом.

1
Стенд с реальной камерой и бутылками на 6–8 недель
Результат: бутылок в минуту, доля пропущенного брака, доля ложных срабатываний, видео работы. Это единственное, что закрывает вопрос «правильно ли потрачено время».
2
Опубликовать таблицу скорости
Три разрешения, до пяти передач между процессами, Windows и Linux. Две недели параллельно со стендом. После этого спор «Python или C++» ведётся по таблице.
3
Проверка «второй руками»
Коллега или ИИ-агент собирает новый сценарий по документации. Измеряем время до рабочего результата. Так проверяется, что это конструктор, а не одна программа.
4
Считать команду C++ не конкурентом, а второй линией
Сверхбыстрые блоки могут писаться на C++ и подключаться к этой же шине. Одна система, два языка там, где каждый сильнее.

Вывод. Выбор Python не стоил скорости там, где скорость нужна. Он купил год одного инженера вместо года команды, сценарии без программиста и разработку с ИИ-агентами. Что осталось доказать, доказывается за один этап со стендом.
