# Почему коммиты падают и откатываются — разбор и предложение (2026-10-03)

Заказ владельца: «часто возникают проблемы и откаты — то строка длинная, то ещё что-то; нужно проработать механизм и
формат»; раньше — «нужен единый формат у всех». Исполнитель: `investigator` (Opus), только чтение; опыты — во временном
репозитории `commitlab` (scratchpad лида). Источник чисел — 552 транскрипта 2026-09-02..2026-10-03: 1004 вызова
`git commit`, 301 `git merge`; отказ виден минимум у 140 коммитов и 32 слияний. Числа — нижняя граница: 662 вывода
отфильтрованы (`-q`, `| grep -v Passed`).

## Ответ

Большинство отказов дают не правила формата, а три источника:

1. Хуки pre-commit правят файлы и рвут коммит: `ruff-format`, `trailing-whitespace`, `end-of-file-fixer`.
2. `ruff` находит E501 («строка длинная» в коде), который сам не чинится, а при правке файла его никто не показывает.
3. Хук `session-log` пишет в общий `docs/sessions/<дата>.md` на каждом коммите и ломает стеш pre-commit. **Только этот
   класс теряет работу.**

Формат сообщения роняет меньше коммитов, но его правила противоречат друг другу: часть проверок молча выключена, слияния
идут мимо проверки.

## Формат v2 (предложение)

```
<type>[(<scope>)][!]: <описание>
<пусто>
- тело, буллеты (опционально)
<пусто>
Why: …            обязателен
Layer: a[, b]     обязателен; framework|services|plugins|prototype|docs|scripts|tests|infra|mixed
Refs: plans/…md   обязателен, если ветка из плана; подходит любой существующий plans/**.md
Risk|Reversible|Tested|Rejected: …   опционально
<пусто>
Co-Authored-By: … для агентов; хук не проверяет
```

- type: feat fix refactor perf test docs chore build ci style revert **merge** (у merge нет scope); scope `[a-z0-9_./,-]+`.
- Длина subject: ≤100 символов, предупреждение после 72; считается по символам (кириллица = 1). Под 100 уже 96.5 % истории.
- Merge: `merge: <что вошло>`; синхронизация — `merge: main (<sha>) в <ветка> — <зачем>`. `Merge branch …` — отказ.
- Без проверки только `Revert "…"`, `fixup!`, `squash!`, `amend!`.

Сегодняшний валидатор пропускает: `merge:` без трейлеров (rc=0), `Layer: tools` (rc=0), сообщение без Layer (rc=0),
subject в 1960 символов (rc=0). Проверено в commitlab (git 2.50): хук видит итоговый текст и в потоке
`--no-commit` → подмена `MERGE_MSG` → `git merge --continue` — схема соседа 5a работает.

## Механизм (предложение)

- **commit-msg** — единственный валидатор, fail closed; v2 в обеих копиях, правка в каждую отдельно.
- **pre-commit** — убрать `session-log` (журнал уже в `git log --stat`; при нужде — post-commit в gitignored `data/`).
- **protect-branch** — учесть вызов помощника.
- **autoformat-python.sh** — печатать оставшиеся после `--fix` ошибки (E501) при правке; fail open.
- **Помощник `scripts/commit.py`** (сообщение — файлом через Write, Bash-кавычки не участвуют):
  `--msg <file> -- <paths…>`: отказ на защищённой ветке → проверка сообщения тем же `validate()` до индекса →
  `git add` только перечисленных путей (чужие в индексе — отказ) → `pre-commit run --files`, правки хуков стейджатся,
  не больше одного повтора → `git commit -F` без pathspec и без пайпа → сверка `git show --stat`.
  `--merge <ветка> --msg <file>`: `--no-ff --no-commit`, при конфликте — выход со списком, затем `--continue`.

Воспроизведено в commitlab: A1 (сорван → повтор прошёл); 2 записи журнала на 1 коммит; **A3 — потеря незастейдженной
правки с `session-log`**, контроль без `session-log` — правка цела; все пути merge. Выведено, но не прогнано: сам
помощник, `pre-commit run --files` как поглотитель, обход protect-branch.

| Task | Что | Acceptance |
