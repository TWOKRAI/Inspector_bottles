## Известные слабости метрики (для первого вопроса)

1. Потолок называет путь и символ — измеряет «адрес есть в тексте паспорта», не «агент дойдёт» (запись 22, п. а). Строгое число — «адрес из окна в собственном блоке», не «определение найдено» (хвосты 3.4).
2. `fw1`/`fw2` писал один автор, знавший эталон; ~половина адресов `fw2` — символы, добавленные коммитом; `line` — строка объявления, правки лежат ниже на 6–57 строк (запись 18).
3. Пилот: n = 3, один Haiku, набор лёгкий для агента с оболочкой (потолок ≈ 95 %), условие B/C не изолирует atlas (`--allowedTools` не запрещает read-only Bash — arm B TAINTED).
4. Kill-2 в плане привязан к `r1`/C0 на `r1` (вне охвата атласа по записи 11 п. 1); новый набор суда и C0 на нём не сняты; 4.3 (условие `atlas` в бенче) не сделана.
5. Оценка по `hits` с `require: all` даёт пол для Haiku; V3 принято, V1/V2/V3b отвергнуты (запись 9) — пилот использовал долю адресов как справку.
