## Правка

### Вариант A (точечный, в тесте)

`test_run_app_prototype.py`, вместо строк 61-62 (`# Задан только каноничный ключ … tracked → восстановится` и `monkeypatch.delenv("INSPECTOR_MANIFEST", raising=False)`):

```python
    # Задан только каноничный ключ; легаси-ключ отсутствует. setenv → delenv: setenv
    # запоминает «ключа не было», и откат УДАЛИТ то, что main() допишет в os.environ
    # (голый delenv(raising=False) на отсутствующем ключе ничего не запоминает — C-99).
    monkeypatch.setenv("INSPECTOR_MANIFEST", "")
    monkeypatch.delenv("INSPECTOR_MANIFEST")
```
Проверено: один `monkeypatch.setenv("INSPECTOR_MANIFEST", "")` (вариант из defects.md) тоже даёт `2 passed`, потому что `apply_env_aliases` считает пустое значение отсутствующим; но пара `setenv`+`delenv` оставляет ключ именно отсутствующим, как задумывал тест. Рекомендуется пара. Старый комментарий «tracked → восстановится» был неверным, его надо заменить (в тексте выше он заменён).

Результат A одна: писатель + жертва = `2 passed`; оба целых файла = `6 passed`.

### Вариант B (autouse-фикстура)

Где: **корневой `conftest.py`** — ближайший общий предок писателя (`backend/tests`) и жертвы (`frontend/tests`) в дереве `multiprocess_prototype`; `multiprocess_prototype/conftest.py` не существует, создавать новый файл ради одной фикстуры не нужно. Ограничение: тесты под `multiprocess_framework/modules/` корневой `conftest.py` не грузят (`--setup-show` на `app_module/tests/test_env_aliases.py` не показывает корневую `no_blocking_modals`, только фикстуры `modules/conftest.py`), поэтому утечка смоука (`system_launcher`) корневой фикстурой не закрывается — см. «Открытое».

Дописать в конец `conftest.py`:

```python
#: Ключи env, в которые код приложения пишет НАПРЯМУЮ через ``os.environ`` (не через monkeypatch):
#: 8 пар ``MULTIPROCESS_*``/``INSPECTOR_*`` (``apply_env_aliases``, ``system_launcher``, ``launch``)
#: и ``INSPECTOR_PRESENTATION`` (``frontend/run.py``). Литералы, а не импорт ``ENV_ALIAS_PAIRS``:
#: корневой conftest грузится до любого теста и не тянет фреймворк; сверку со списком пар
#: держит ``multiprocess_prototype/backend/tests/test_env_alias_isolation.py`` (C-99).
_APP_ENV_KEYS: tuple[str, ...] = (
    "MULTIPROCESS_PID_FILE",
    "INSPECTOR_PID_FILE",
    "MULTIPROCESS_LOG_DIR",
    "INSPECTOR_LOG_DIR",
    "MULTIPROCESS_MANIFEST",
    "INSPECTOR_MANIFEST",
    "MULTIPROCESS_LOG_LEVEL",
    "INSPECTOR_LOG_LEVEL",
    "MULTIPROCESS_FRAME_TRACE",
    "INSPECTOR_FRAME_TRACE",
    "MULTIPROCESS_HEALTH_LOG_ONLY",
    "INSPECTOR_HEALTH_LOG_ONLY",
    "MULTIPROCESS_HEALTH_BREAKER_THRESHOLD",
    "INSPECTOR_HEALTH_BREAKER_THRESHOLD",
    "MULTIPROCESS_HEALTH_BREAKER_COOLDOWN",
    "INSPECTOR_HEALTH_BREAKER_COOLDOWN",
    "INSPECTOR_PRESENTATION",
)


@pytest.fixture(autouse=True)
def _restore_app_env_keys():
    """Тест не оставляет следов в env приложения (C-99).

    ``monkeypatch.delenv(k, raising=False)`` на ОТСУТСТВУЮЩЕМ ключе ничего не запоминает, а
    ``apply_env_aliases()`` / ``SystemLauncher`` / ``launch`` пишут ``os.environ`` напрямую —
    значение переживало тест и красило соседа (``test_app_foundation_names``: ``KeyError: 'system'``).
    Снимок берётся ДО теста, откат — после: присутствовавший ключ получает прежнее значение,
    отсутствовавший — удаляется.
    """
    saved = {key: os.environ.get(key) for key in _APP_ENV_KEYS}
    yield
    for key, value in saved.items():
        if value is None:
            os.environ.pop(key, None)
        else:
            os.environ[key] = value
```
(`os` и `pytest` в `conftest.py` уже импортированы. `ruff check` и `ruff format --check` по трём файлам — чисто.)

Рекомендация: **A + B вместе**. A дешёвый и чинит ложный комментарий в самом писателе; B закрывает класс (любой будущий писатель, любой из 17 ключей) и стоит 17 `os.environ.get` на тест. Одного A мало: он не защищает от других писателей (`launch`, `frontend/run.py`, `system_launcher` в тестах вне `modules/`). Одного B достаточно для зелёного, но тест остаётся с неверным комментарием; оба независимо покрывают C-99 (таблица ниже, I1/I2).

### Тест гарантии отката
