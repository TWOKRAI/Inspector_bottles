## Вопрос 16. Тезис про MCP и агентов

**Подтверждено рынком** (источники добыл `web-researcher`; помечена первичность): ревизия спецификации MCP **2026-07-28** — stateless, `server/discover`, tasks вынесены в расширение, JSON Schema 2020-12 для `inputSchema/outputSchema`, упразднены Roots/Sampling/Logging/HTTP+SSE (modelcontextprotocol.io/specification/2026-07-28/changelog, первичный). Agentic AI Foundation при Linux Foundation, 9 декабря 2025: MCP, goose, AGENTS.md; platinum — AWS, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft, OpenAI (пресс-релиз LF, первичный). MCP в OpenAI Agents SDK (документация, первичная). Вывод: **MCP как слой совместимости — консенсус отрасли, не мода.** A2A в LF — только сниппет: контест на уровне агент↔агент, не инструмент↔агент.

**Преувеличено:** «будущее ПО за агентами» как производительность. METR 2025-07-10: опытные OSS-разработчики на 19 % медленнее (n=16); METR 2026-02-24 (57 разработчиков): −18 % (ДИ −38…+9) и −4 % (ДИ −15…+9), «unreliable signal» (первичные; знак в отчёте помощника неоднозначен). DORA 2025: 90 % используют, 30 % мало/не доверяют, пропускная способность вверх, стабильность вниз. Stack Overflow 2025: доверяют сильно 3,1 %, не доверяют 46 %. Gartner 2025-06: >40 % агентных проектов отменят к 2027 (сниппет, первичный 403). Профиль этого проекта — опытный разработчик, большая кодовая база — та группа, где выигрыш не показан. Собственные замеры проекта согласны: без дизайна лида — 181k/175k токенов и ноль кода (team-protocol §3).

**Безопасность:** tool poisoning (Invariant Labs, 2025-04-01), CVE-2025-6514 (mcp-remote, 9.6). «Безопасность после фундамента» допустимо **только** с bind=localhost и охранником bind (S).

**Токены — довод за CLI пока слабый:** Anthropic «code execution with MCP» 98,7 % на одном сценарии; Tool Search 85 %; Scalekit 2026-03 — MCP 4–32× токенов против CLI, 25 прогонов, один сервис, авторы оговаривают малое n. Единственное измерение CLI-vs-MCP. Направление реально, число мерить на своих пробах.

**Три решения сейчас:** (1) каталог — единственный источник с `access` и стабильными ключами результата (готовность к `outputSchema` 2020-12: `params_schema` — входная половина); (2) меньше инструментов, по намерению (стр. 44) + CLI над `dispatch_tool` без новых MCP-инструментов; (3) идемпотентность и верификация как свойства контракта: флаги `access`/`idempotent` в объявлении — клиент повторяет чтения автоматически и никогда destructive. **Три отложить:** MCP resources/prompts/tasks (спецификация их только что перетряхнула); серверный токен (gui-service 2.2 PENDING; localhost хватает); кадры агенту (ADR-RTR-008) — JPEG на диск, когда появится потребитель.

**Агент против человека:** объём вывода (агент платит за токен — курсоры `events_page` есть; `capabilities` всего дерева подходит для 85 команд, не для 1000); идемпотентность (агент повторяет — `*_verified` есть, флага нет); откат (`snapshot/restore`, `commit-confirmed` есть; пакетного нет); права (`TOOL_SAFETY` + режимы — только клиент); аудит (`session_log` — только клиент). Четыре из пяти есть **на клиенте**, ноль на сервере. `access` в каталоге — первая серверная деталь.

**Что в идеях владельца CTO считает ошибкой.**

1. «Все сервисы на `service_module`, он на `BaseManager`» — единообразие наследованием, когда проблема в содержимом: оболочки останутся оболочками.

4. «`console_module` — терминал разработчика с потенциалом» — терминал уже есть и скриптуется: `backend_ctl`; консоль — экран; God Mode дублирует `backend_ctl` внутри процесса без проверки доступа.
5. «Безопасность после фундамента» — допустимо только с localhost и охранником bind; поле контракта обязано появиться сейчас (бриф согласен).
