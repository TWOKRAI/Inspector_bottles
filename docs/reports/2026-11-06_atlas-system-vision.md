## Зачем

Агент (и владелец) должен **понимать архитектуру и быстро находить нужное место, не перечитывая модуль или класс
целиком**. Код читается только при входе в конкретный «дом». Мерило — эффективность: если с атласом агент не тратит
меньше шагов и токенов, чем без него, атлас сделан неправильно. Слова владельца: «qex удобен для поиска, grep — точечное
чтение, а наша карта (атлас) должна быть чем-то вроде graphify, но более информативной и понятной»; «автоматически
формируется мануал с разделами, как для любого технического устройства, все одинаковые по структуре».

## Принципы

1. Истина — только из кода или из того, что модуль объявил о себе сам (первая строка докстринга, шапка `Tier:` /
   `Contour:`, `__all__`). Ни рукописных каталогов, ни карточек, написанных моделью.
2. Один механизм без дублей: один сканер, одна модель, один гейт, много видов поверх.
3. Одинаковый паспорт у всех элементов на всех уровнях.
4. Универсально: любой репозиторий, особенности проекта — только в конфиге.
5. Быстро: секунды на новый коммит, без выгрузки на диск.
6. Честно: чего не видно (динамика, поток данных) — помечено «не найдено», а не «не используется».
7. Мерится: что остаётся в системе, решает замер, а не мнение.

## Что на входе

| Источник | Что даёт |
|---|---|
| код в ревизии git (блобы, без выгрузки) | импорты, классы, члены, сигнатуры, описания, команды, потоки, ввод-вывод |
| объявленное в модуле | назначение, ярус, контур, витрина |
| YAML топологии и рецепты | процессы, какой модуль где работает, IPC-каналы между процессами |
| тесты | какие тесты закрепляют символ (nodeid) |
| снимок живого стенда (`backend_ctl`), по желанию | сверка: каналы и процессы на деле совпадают с объявленным |

## Как работает, от начала до конца

1. **Скан (A1).** Каждый файл ревизии → факты; кэш по содержимому (неизменённый файл не перечитывается). Тот же код
   читает git и фикстуру в памяти.
2. **Индекс.** Связи между файлами: чей импорт куда ведёт, кто наследует, кто вызывает по имени, какие тесты что
   проверяют. Модули — из `modules.yaml`, слои — по правилам.
3. **Модель.** Уровни: слой → модуль → пакет → файл → класс/функция. Дороги: импорт, вызов, наследование,
   рецепт → плагин, IPC-канал, файл (пишет/читает/следит). У каждого элемента — паспорт.
4. **Проверки.** Находки (импорт против слоёв, мимо витрины, нет описания, модуль вне списка, неразрешённый импорт) →
   один гейт `atlas check`; новые — только предупреждения.
5. **Виды из одной модели.** Для агента: `atlas ref <символ>` (паспорт), `atlas map <где> --depth N` (зум),
   `atlas route A B` (маршрут), `atlas find "<вопрос>"` (qex по смыслу + паспорт к каждому попаданию); всё и в JSON.
   Для владельца: страница как Google Maps без интернета — уровни с приближением, карточка при наведении,
   слои-наложения (импорты, вызовы, IPC, находки, ярус), отдельный вид процессов.
6. **Связка с другими инструментами.** qex — поиск по смыслу; graphify — сообщества как подсказка для «районов»;
   grep — точный текст. Атлас по каждому коммиту знает изменённые файлы и обновляет индексы qex и graphify только по ним.
7. **Замер (`nav_bench`).** Два набора вопросов: «найти место» и «понять устройство». Условия: grep / +qex /
   +graphify / +атлас / всё вместе; 3 прогона; пороги — доли от точки отсчёта. Замер — на каждом стопе и при регрессе.

## Паспорт — одинаковые разделы

**Назначение** → **Подключение** (правило слоя, витрина, интерфейсы, сигнатура, члены) → **Связи** (использует меня /
использую я, наследники, места вызова) → **Где работает** (процессы, потоки, команды, ввод-вывод) → **Проверка**
(находки, тесты) → **Состояние** (ярус, нет описания).

## Что сознательно не делаем

Отдельный генератор карты (`scripts/arch_map` переносится в атлас и удаляется); закоммиченные сгенерированные файлы;
рукописные карточки; дома как узлы схемы; обещание «потока данных»; наложение «контур» (не заполнено ни у одного модуля).
