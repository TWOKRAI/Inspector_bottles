## 2. Баги и костыли, подтверждённые запуском

Баги вывода (подробно — `2026-11-10_cto-atlas-system-review-passport-output.md`):

1. `ref` теряет использования через фасад модуля. Причина глубже, чем реэкспорт: фасады ленивые.
   `process_module/__init__.py:38-42` отдаёт `ProcessModule` через `def __getattr__(name)`. Такой импорт не разрешает
   ни `links.of`, ни языковой сервер (§3).
2. `commands` пуст на всём дереве: сканер ждёт `def command_specs`, таких функций в коде 0.
3. `threads` видит поток, только когда создание и `.start()` стоят в одной функции: `map worker_module` → `threads: —`.
4. Срез: члены класса не режутся (`ref ProcessModule` — 69 строк при бюджете 40); в `used_by` тесты раньше продукта.
5. `call_sites_unresolved` считает голое имя по всему репозиторию: у `ConfigFileWatcher.start` — 1612.
6. `atlas ref X` без `--format` → `module not found`.

Костыли:

1. Два разных `ref` в одной команде, переключатель — `--format`.
2. Версия кэша = хеш файла `scan.py`: правка комментария сбрасывает кэш (19 с). База своя у каждого worktree
   (7 баз, 312 МБ), старые ключи не чистятся (основная база 112,7 МБ).
3. `where: путь:1` у членов юнита и тестов — заглушка, не адрес.
4. `structural` — совпадение имён методов без сверки сигнатур.
5. Паспорт импортирует приватные `reference._sig/_methods/_tag` (долг 4.2a).
6. `_stale`: отдельная ветка кода при > 100 путей (обход предела argv).
7. Шаблон команды в Task 4.3 требует от агента десять `--exclude` в каждом вызове.
8. Суд Kill-2 на наборе, для которого не считали потолок.

Баги уровня кода ищут два ревьюера; их результат будет в отдельном файле.

## 4. Выводы

1. **Готового инструмента, который закроет пропуски паспорта одной командой, нет.** Причина в стиле самого
   фреймворка: ленивые фасады `__getattr__` и нетипизированные вызовы через атрибут не разрешает ни Jedi, ни pyright.
2. **Языковой сервер — сосед, а не замена.** Там, где типы и импорты обычные, он точнее паспорта (1 вызов против
   счётчика 1612) и уже установлен. Предлагаю включить плагин `pyright-lsp` агентам и добавить условие `lsp` в
   `nav_bench` рядом с `atlas`. Тогда парный прогон покажет, что из двух окупается. Для этого `include` в
   `[tool.pyright]` должен покрывать `Services` и `Plugins` — решение владельца.
3. **В самом Атласе пропуски честнее закрыть списком «по имени через фасад»** с явной меткой, и тестом полноты
   против `git grep -w` на десяти паспортах. Вывод типов своими силами не строить.
4. **Поиск по описанию задачи дёшев для Python и не решён для остального.** FTS5 встроен в SQLite, индекс строится
   за 5 с и ставит `plans_ledger.py` первым там, где агент C0 дважды выбрал `plans_progress.py`. Для `.md` и `.toml`
   лексический поиск слаб; проба через `qex` не сделана (Ollama выключен).
5. **Порядок не меняется:** сначала поправка о наборе суда, затем задача на пропуски и срез, затем парный прогон.
   Новые инструменты до решения о наборе суда подключать не предлагаю, кроме плагина LSP: он не требует кода.
