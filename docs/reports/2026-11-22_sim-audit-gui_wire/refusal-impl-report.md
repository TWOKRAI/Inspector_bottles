## Красный тест, который считаю неверным (не правил)

`scripts/wire_audit/tests/test_refusal_acceptance.py::test_a5_refusal_after_second_disk_binds_only_to_the_second`

- Вход: слово ПЕРЕМИРИЕ, **одна заливка**; диски `Е 91.9° -> 3` (с заданием), `Р 30.0° -> 2` (t=20, без задания),
  `Р 40.0° -> 2` (t=30, без задания); system.log: один отказ `Р`, ячейка 2, t=30.028.
- Ждёт: `40.0` — не FAIL (`PASS~: отказ hub…`), итог `FAIL`, `fail == 1`, `hub == 1`.
- Выдаёт: `40.0` -> `FAIL: ячейка (отказ hub: робот остановлен: включите серво)`; `ИТОГ: FAIL (взятий 3, заданий 1, FAIL 2, …, предупреждений 1,
  отказов hub 1)`.
- Причина: две `Р` в ячейку 2 в одной заливке — повтор ячейки, существующий FAIL `ячейка` (`core.py::_disk_rows`, README «Известные границы»:
  «повторная в заливке — ячейка»). Физически невозможно: сборщик слов занимает слот при выдаче строки диска (`Plugins/processing/word_layout/plugin.py`
  :218-255), отказ hub слот не освобождает; в живом прогоне (`docs/reports/2026-11-22_sim-audit-live-home-c104.md`) повторы ячейки 2 шли
  в **разных** заливках. Привязка отказа верна: `30.0` остаётся `FAIL: потеря`, `40.0` закрыт отказом.
- Доказательство: тот же сценарий с `слово` между дисками (две заливки, `--words ПЕРЕМИРИЕ,ПЕРЕМИРИЕ`) даёт
  `40.0 -> PASS~: отказ hub: …`, `ИТОГ: FAIL (… FAIL 1, … предупреждений 1, отказов hub 1)` — то, что ждёт тест. Это же закреплено моим
  `test_refusal_of_the_second_disk_does_not_close_the_first` (две заливки).
- Варианты: (а) лид правит фикстуру a5 (слово между дисками, `--words` из двух слов) — рекомендую; (б) отказать диску с отказом в FAIL
  `ячейка` — это ослабит проверку журнала диска ради теста, не делал.
