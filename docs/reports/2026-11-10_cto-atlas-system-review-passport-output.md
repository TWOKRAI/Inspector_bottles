Три замечания к таблице.

- **Строки 1–2 — одна причина, и она в плане известна.** Долг 4.1 «реэкспорт `__init__` теряет вызовы» в 4.2b-2
  исправлен для `map` юнита (`ImportIndex.resolve`), но `ref` по-прежнему идёт через `links.of`. Итог: `map
  process_module` показывает 392 оператора импорта из 37 юнитов, а `ref ProcessModule` — «из продукта 8». По
  `map-form.md`, прямых операторов 79 из 388: через реэкспорт идёт около 80 %. Импорт через фасад модуля — правило этого
  фреймворка, поэтому пропуск систематический.
- **Строка 5 в масштабе.** В prod-коде 1 801 файл. Вызовов по имени `f(...)` — 24 798, из них 4 070 на функции верхнего
  уровня репозитория. Вызовов через атрибут `x.m(...)` — 33 116 (57 %), из них 21 631 с именем метода, объявленного в
  репозитории (верхняя оценка), 7 031 — `self.m(...)`. Вопрос «кто вызывает этот метод» паспорт закрывает счётчиком.
- **Строка 3.** Ключ `commands` ждёт соглашения `command_specs()`, которого не придерживается ни один модуль. Пока
  соглашения нет, ключ на всём дереве говорит «нет».

Кэш и цена запуска:

- Ключ кэша — `(oid блоба, хеш scan.py)`. Новая ревизия при готовой базе стоит 1,1 с. Это хорошее решение.
- Холодный запуск 19 с — после любой правки `scan.py` и в каждом новом worktree (база своя у каждого дерева).
  Сейчас 7 баз в worktree — 312 МБ; база основного дерева — 112,7 МБ. Строки старого ключа сканера не удаляются.
- В Task 4.3 агент сам набирает команду с десятью `--exclude` и `--format passport` после списка имён. Для Haiku это
  ошибки и лишние токены на каждый вызов. Проще дать в копии готовую обёртку с зашитыми флагами.

Старые карточки. `card process_module` — 10,7 с, 46 строк: открытые задачи по модулю (148 в 16 планах), коммиты,
находки. Это рабочий контекст, с паспортом он не пересекается. `pack atlas-passport#4.3` предлагает 27 файлов из
`scripts/atlas`, а файлы задачи лежат в `scripts/nav_bench`. Оба вида под FREEZE — трогать не предлагаю.
