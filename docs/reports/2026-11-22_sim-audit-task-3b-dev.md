## Что я оставил открытым / ненадёжным

1. **Живьём не проверено ничего.** Сим и прототип не запускались (по границам). Форма ответов взята из исходников: `state.get` → `result.value` (как в α), `sim_robot.journal` → `wire` (`Plugins/sim/robot_host/plugin.py:845`), регистр — `result.registers.word_layout` (копия спуска из α). Если в живом ответе форма другая, сборщик молча (без ошибки) запишет пустые файлы; признак — `meta.json`: `journal_lines: 0` / `registers: missing` при работающем стенде. Реальный `BackendDriver` проверен только до отказа соединения.
2. **Склеенные строки кольца (правка лида, было дублями keepalive).** Кольцо `wire` склеивает подряд идущие одинаковые строки счётчиком `n` и двигает у склейки `t` (`robot_host/plugin.py:799–803`). Теперь строка с `n > 1`, чьи `(side, text)` совпадают с последней записанной строкой файла, считается ростом уже записанной и не пишется (её ключ `(t, side, text)` всё равно запоминается, повторное появление в кольце тоже не пишет). Критерий «совпадает с последней записанной» мой, а не буквальный «ключ `(side, text)` для `n > 1`»: буквальный дал бы двойную запись, если строка сначала увидена с `n = 1` (запись), а потом выросла до `n = 2` (ещё запись). Основание: кольцо склеивает только последнюю строку, значит после записи другой строки склейка прежней расти уже не может; тот же текст после другой строки — новый прогон и пишется (тест `test_same_text_run_after_another_line_is_a_new_line`). Строки с уникальным текстом (`[v2] CMD seq=… op=CVT_JOB`) идут прежним путём. Не проверено живьём: что кольцо ведёт себя как в исходнике (склеивает только последнюю строку и сбрасывает счётчик при новой строке). Если на стенде склейка устроена иначе, строка может быть либо записана лишний раз, либо пропущена. Числа `n` в файл по-прежнему не пишутся (итоговое число повторов keepalive в данных не видно).
3. **`t` в файлах — время сборщика при первом виде, а не время сима.** Запаздывает до периода (0,25 с) плюс задержка опроса. Для паспортов ядро сопоставляет `t ≤ время задания` — задания идут заметно позже спавна, но на живом стенде это не проверено. Монотонное `t` сима в файл не пишется.
4. **`lateral_px` в паспорте.** Кэшируется при первом появлении `object_id`. Спавнер ставит `lateral_px` через `replace(...)` (`Services/line_sim/core/spawner.py:363`); я не проверял, что это происходит ДО первой публикации в `sim.objects`. Если после — в файл попадёт 0.0 вместо значения. Проверить живым прогоном (стадия 4): `lateral_px` не должен быть 0.0 у всех.
5. **`p_pick_rz_deg`.** Источник «параметры драйвера» не нашёл (у `BackendDriver` такого нет); берётся только из регистра, а есть ли он в `word_layout`, не знаю — скорее всего будет умолчание −100,0 с пометкой в `meta.json`. Если у прототипа на стенде другой `P_PICK_RZ`, столбец А получит неверное ожидание: лиду проверить на стенде и при необходимости передавать значение отдельным аргументом.
6. **Тест «формат читается `parse_*` ядра» не написан:** `core.py` не влит, сигнатур нет. Вместо него проверены литералы формата (набор ключей, regexp времени). После слияния Task 3 — добавить.
7. **Мёртвый или зависший сим.** Таймаут вызова 2 с (`_POLL_TIMEOUT_S`, мой выбор, не из брифа): при зависшем симе один опрос может занять до 4 с, кольцо (200 строк `wire`) за это время может обернуться — потерянные строки не видны ни в файле, ни в счётчиках, только в `errors`. Ошибка `state.get` со `status: error` не считается ошибкой (ключа до спавна нет), так что мёртвый источник объектов отличим только по пустому `sim_objects.jsonl`.
8. `_seen_rows` ограничено окном 5000 ключей (`_RecentKeys`, правка лида). Обоснование: кольцо `wire` держит 200 строк (`_JOURNAL_WIRE_MAXLEN`, `robot_host/plugin.py:83`); строка может вернуться в ответе только пока она в кольце, поэтому 5000 — запас в 25 колец, и вытесненный ключ больше не встретится. Это рассуждение по исходнику, не замер на живом стенде: если кольцо на стенде окажется больше 5000 строк, повторы вернутся. Множество паспортов `_seen_objects` не ограничено (один идентификатор на диск; на сотнях тысяч дисков — единицы МБ, не измерял).
9. `tests/__init__.py` не создан; тесты запускаются по пути файла и импортируют `scripts.wire_audit.collect` при `PYTHONPATH` = корень дерева.
