## F1 — вердикт CTO

Своя запись вкладок Устройства/Камера/Дисплеи делает базу редактора устаревшей → ложный конфликт, автосохранение
молча не пишет. CTO запуском показал, что для Камеры конфликт истинный: rebase после записи внутрь `config` плагина →
Save редактора откатывает правку (Q1c); `unregister` дисплея + rebase → файл невалиден (Q1f); rebase на `rev` своего
чтения поглощает ручную правку (H1b). Решение (d): одна база на весь GUI, вкладки пишут с базой и двигают её, секции
`blueprint.processes/wires/displays` пишет только редактор. Код 1.8 по F1 не меняется; условия — в design.md
(§9.1, Р7, §10 п. 3), docstring `rebase`, задачи 1.9 (переписана, стадия 0 р2), 1.10, Дисплеи.
Вердикт: `docs/reviews/2026-10-27_task-1.8-cto-F1.md`.

## Решение владельца нужно

- `unregister` дисплея с привязками в графе: (i) отказ или (ii) снятие через `UnbindDisplay` в модели редактора —
  `docs/claude/OPEN_QUESTIONS.md` (2026-10-27). Задачи Дисплеев в плане ещё нет; без неё запись Устройств после
  записи Дисплеев даёт ложный конфликт (TRAPS 1.9).
