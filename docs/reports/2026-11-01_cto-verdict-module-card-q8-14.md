# Вердикт CTO: вопросы 8–14

Основной файл (общая оценка, Q16, Q17, открытое): [2026-11-01_cto-verdict-module-card.md](2026-11-01_cto-verdict-module-card.md). Вторая часть: [2026-11-01_cto-verdict-module-card-q1-7.md](2026-11-01_cto-verdict-module-card-q1-7.md).

**8. Порядок — ИЗМЕНИТЬ.** Вырезать шаги 7–8 пакетом; шаг 10 слить со 2. Порядок: (1) `access` в каталоге, умолчание `write`, `backend_ctl` читает его, кортеж `READ_SAFE_*` замораживается — единственный шаг, меняющий видимое агенту свойство; живой тест ненуля; (2) `command_specs()` + `register_from` + тест «дамп `introspect.capabilities` до и после побайтно равен»; пилот `StatsAdapter` (5) и `StateStoreManager` (7 — тесты держат `len == 7`, `state_store DECISIONS.md:571`, число не менять); (3) `module.list/info`; (4) семьи `BuiltinCommands` — где владелец существует, мерило — падение `self._services` с 92; (5) адаптер плагинов — **после** camera-device 1.3 (тот же `base.py`, один писатель). Вместе нельзя: ничего в `process_module`, пока полоса Ф не прошла приёмку CTO (стр. 6а): C-60 влит `116ed6964`, 1.11 DONE, открыты C-36, C-57, C-58, C-53/54. **Прототипировать первым** — не автоадаптер, а стенд тождества таблицы: 5 команд stats через `command_specs()` в тестовом процессе, сравнить два дампа.

**9. Готовое — ПРИНЯТЬ.** Часть карточки уже: `introspect.capabilities` (+`capabilities_extra`, `driver.capabilities()`, `dump_capabilities.py`, `docs/contracts/CAPABILITIES.yaml|md`), `introspect.plugins` (манифест), `introspect.lifetime` (`IScope.live()`), `introspect.registers` (+`meta` 1.4), `declare_log_source/declare_metric`, `PluginBase.commands/command_options` (+`command_contracts` 1.3), Atlas-карточка, `health.*`. Дублирует предложенное: `module.info` ↔ `introspect.status`/`stats_snapshot`; `describe(модуль)` ↔ `python -m scripts.atlas card` (запущено: API, потребители, правила ADR-175 — второй статический описатель не нужен; Atlas можно научить печатать `command_specs`); консольные `help/status/ps/stats` ↔ каталог.

**10. Политика доступа — ПРИНЯТЬ.** С первого дня в контракте: `access` (4 класса, умолчание `write`), `source` в конверте (консоль уже кладёт `"source": "console"`, `console_adapter.py:66-73`), поле аудита. Точка проверки в `handle_command` — да, но как одна инжектируемая функция `policy(spec, envelope) -> bool`, `None` = ноль стоимости (принцип владельца). Уровни L0–L3 не строить. Условие: `access` обязан быть в `introspect.capabilities` и в CI-дампе, иначе клиентский кортеж останется второй правдой.

**11. `console_module` — ИЗМЕНИТЬ.** Экран и аварийный ввод оставить; God Mode остаётся FREEZE (`MODULE_TIERS.md:38, 82`, воспроизведено) до стенда. Доказать: (а) при заблокированном `message_processor` (спящий обработчик по IPC) консольный `introspect.status` отвечает — пока гипотеза; `process_module/DECISIONS.md:3749` показывает, что консоль и IPC делят `layers.lock` на `config.reload`, значит часть команд с консоли повиснет на том же зависании; (б) потокобезопасность обработчиков при вызове с `ConsoleInput-*` параллельно `message_processor` — `handle_command` писался под одного потребителя. До доказательства — с консоли только `access=read`. `reg` не переносить (registers — полоса К, 1.4). Находка дрейфа: `console_module/README.md:47` («отдельный процесс-консоль») против ADR-CM-002 («флаг `interactive=True`»).

**12. Масштабируемость — ИЗМЕНИТЬ (находки).** При 50–100 модулях ломаются: бог-файл `BuiltinCommands`; число MCP-инструментов (карточка помогает, только если инструменты станут по намерению); `modules.yaml` руками; коллизии имён в `ExactMatch` — `set_config` регистрируется один раз первым плагином (`base.py:1733-1742`), карточка покажет не того владельца. Удалённые процессы: каталог процессный, свод у драйвера — выдержит; `access` обязан ехать в каталоге. Слои: `sentrux` CLI отсутствует в venv — находка лиду; направление `Services → framework` чистое; `AuthManager` в GUI-процессе (`frontend/app.py:666, 688`) — нарушение принципа 6 (GUI ничего не запускает), не слоя; есть ли там `CommandManager` — не проверялось.

**13. Процесс — ИЗМЕНИТЬ.** Противоречия: (а) шаги 1, 2, 4, 5 правят файлы полосы Ф до приёмки PM — старт только после стр. 6а; (б) запрет новых MCP-инструментов не нарушается; правка read-only фильтра `mcp_tools.py` — внутрь `backend-ctl-review-remediation` (4/18, «без движения с 10-01»); (в) camera-device 1.3/1.4 — живой прецедент объявления, строить поверх, не параллельно; (г) полосы Ф, Р2, Д/К заняты — у карточки нет слота писателя в 1.0. Честно: карточка — пункт 2.0 (решение 23; «архитектура — когда тянет продукт», ORDER §1), если владелец не обменяет строку 1.0. Куда: малый план `command-cards` (фаза 1 = пп. 1–3 порядка выше), владелец `constructor-master` (его 1.9 и 4.2 закрыты) — не раздувать.

**14. Упущено.** `CommandCatalog` прототипа; Task 1.3/1.4 camera-device; 92 связки `self._services` («объём не оценён» — оценён); `sentrux` не установлен; `set_config` без владельца; стр. 44 ORDER — ответ владельца на раздувание инструментов, карточка с `access`+`tags` даёт сырьё для инструментов «по намерению»; STATUS `backend_ctl` 47 против 53; приёмка PM (6а) — настоящие ворота перед всем этим; `assert` на импорте в `sql/service.py:69`.

**Пять главных рисков:** седьмая форма регистрации без снятия шести; конфликт писателей с Ф на `process_module`; оболочки в красивой обёртке; две правды о классе доступа в переходный период; опора на консоль как аварийный вход без воспроизведения зависания при общем `layers.lock`.
