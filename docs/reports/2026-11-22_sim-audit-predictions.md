## 2. «Домой» при диске в полёте (n ≥ 3)

Что именно делает робот с диском — вне ПК-части. Инварианты на стороне ПК (в каждом из n ≥ 3):

- одно нажатие → ровно один park `SC_RUN`, `RES_STATUS = 1`, `RES_ERRNO = 0`;
- число `CVT_JOB` в журнале не уменьшается, `CMD_SEQ` без дублей;
- взятий в журнале `layout` = `CVT_JOB` (нет взятия без задания и задания без взятия). `CVT_JOB` без строки взятия после park — находка.

## 4. Что не предсказываю (честно)

- Знак `rz`: СНЯТО после проверки (`geometry.py:102`): `r` в журнале — доворот, формула `wrap180(angle_zero − sign·угол_сети)`; в первой версии этого файла знак значился открытым по ошибке чтения. Теперь он проверяется столбцом Б (раздел 5).

### 5.2 Уровень Б — истина сима (допуски порядка точности сети, не 0,1)

- **rz против подачи.** `corr_истина = wrap180(0 − f)`, `f` — `passport.angle_deg` из `sim.objects` (кэшировать при спавне, взятый объект удаляется). Предсказание: у каждого взятого диска `|wrap180(corr_провод − corr_истина)| ≤ 30°` (в α сеть давала до 18,5°); медиана по прогону лежит в **[−4,5°; −1,5°]** (прошлые медианы Δ сеть−подача +2,4…+3,2°). Переворот знака дал бы `2f` = 60/120/180/120/60° для подач 30/60/90/300/330 — виден на каждом диске; на подачах 0° и 180° не виден, их по знаку не судить. Пороги 30° и 20° (медиана) — моё предложение, неизмеренные.
- **pick x.** `x_ожид = 458,2 − lateral_px·78,4/481`, `lateral_px` — знаковое из паспорта; `|x_провод − x_ожид| ≤ 0,5 мм` у 15 из 15 на прогон (допуск — предложение: шум центроида не измерен, 1 px ≈ 0,16 мм). Знак `lateral_px` в формуле — гипотеза по коду; если Δ около `2·0,163·|lateral|` (до 6,5 мм), это сначала проверка формулы, потом уже находка в плагине. Встроенное расхождение масштаба сим/рецепт до 0,81 мм при lateral 20 px учтено в допуске ±1,0 мм как «жёлтая зона» (отчёт, не FAIL).
- **pick y.** Независимо по каждому диску **не вычисляется** (на проводе нет `e_capture`, `ecap` = энкодер момента постановки задания). Судится только окно α: `ARGS[3] ∈ 62096…62116` (−344,0…−342,0). Это «окно, не расчёт».
- **Третий наблюдатель провода — `sim_robot.journal`.** Для каждого `CVT_JOB` в нём строка `[v2] CMD seq=<CMD_SEQ> op=CVT_JOB`; множество `CMD_SEQ` равно множеству `CMD_SEQ` `CVT_JOB` из журнала драйвера: **15 = 15 на прогон**, каждый один раз. Кольцо журнала переполняется за ≈ 15 с — опрос каждые 0,25 с с дедупликацией по `(t, side, text)`; недобор при пропущенном опросе — сначала проверка опроса, не находка о потере. `DONE seq=…` — не обязательны для диска в полёте при остановке, строго не предсказываю.

### 5.3 Непокрытое независимо (идёт в «Открыто» отчёта)

1. `pick y` и `ecap` по каждому диску.
2. `pick x` — только против `lateral_px` сима с неизмеренным шумом центроида; углы калибровки `lin_*` общие у рецепта и сима, их ошибка не ловится; масштаб поперечной оси сим/рецепт расходится до 0,81 мм.
3. `rz` против истины — только ±30°; знак не виден на подачах 0° и 180°.
4. `angle_valid=False` — слепое пятно уровня А.
5. Место укладки сим не проверяет вовсе (`scene.job_done` несёт только pick): правильность `place` держится на уровне А (рецепт) и на третьем наблюдателе (те же слова).

## 6. Из паспорта готовности (`docs/handoffs/2026-11-22_hardware-readiness.md`, main `dc7883ce6`) — до прогонов

## 8. Приоритет владельца: судится механизм, точность сети — отдельно (сообщение владельца 2026-11-22, до прогонов)

Владелец: ошибки нейросети допустимы (доучит позже), главное — механизм и взаимодействие с роботом. Следствия для вердикта:

- Вердикт «ПК-часть готова к дню №2» строится только по МЕХАНИЗМУ: целостность провода (seq, ответы, ARGC), привязка диск↔задание, кодирование x, y, z, rz по рецепту (столбец А), досягаемость как предупреждение, сим-наблюдатель, «Домой»/«СТОП»/GUI.
- ТОЧНОСТЬ сети (неверная буква, ниже порога, угол сети против подачи) идёт в отчёт отдельной строкой «информативно» и вердикт не меняет. Поэтому в столбце Б ошибка `rz` одного диска — только `~`; FAIL по `rz` возможен лишь по систематическому сдвигу (медиана `|e| > 10°` при ≥ 9 дисках: ошибка знака или нуля, то есть механизм).
- Потеря диска из-за сети (например «М» прочитана как «И») — не дубль и не потеря механизма: равенство «взятий = заданий» держится, число 15 может упасть (§1, условие).

## 9. Условия живых прогонов: дефекты-«квадраты» сима выключены (сообщение владельца 2026-11-22, до прогонов)

Чёрные квадраты на дисках рисует генератор сима как «дефект»; в реальности их нет, для проверки провода они не нужны. Код сима не меняем: у сима есть команда `scene.defect_rate {"probability": p}` (`Plugins/sim/scene_source/plugin.py:682`, `camera scene.defect_rate`), α шлёт `0.0` перед случаем B (`scripts/alpha_sim/run_alpha.py:514`).

- В каждом живом прогоне (и в видимом прогоне с GUI) `{"probability": 0.0}` отправляется **сразу после старта сима**, до первой подачи, а не только перед B — чтобы диски фазы P3 до случая B тоже были без квадратов. Это изменение рабочего параметра сима, а не кода; его фиксируют в журнале прогона («изменено в симе»).
