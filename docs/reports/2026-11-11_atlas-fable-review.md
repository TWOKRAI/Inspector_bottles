## (а) Вывод для владельца

1. Идея «паспорт по известному имени» работает как справка, но польза для агента не показана ни одним замером. На задачах «где править» запаса нет: grep-агент находит 17–21 адрес из 22.
2. Главная проблема не вход (его чинит 4.7), а то, что агент Атлас не зовёт: 12 вызовов из 677 во всём пилоте (2 %).
3. На отношениях Атласу нельзя доверять по полноте: `ref RouterManager` называет 3 продовых файла-импортёра из 7. Агент обязан перепроверять grep'ом — экономии нет.
4. Ориентация (гипотеза владельца) не измерена. Бесплатный разбор трасс пилота говорит, что запас мал: чужие файлы — 4 % вызовов, первый верный файл читается на 3–7-м вызове.
5. Метрика после E0 честнее, но три счётчика считают «адрес» тремя способами, и широкий диапазон строк засчитывается как точный ответ.
6. Первым делать дешёвый решающий опыт «карта без инструментов» (≈ 60–100k токенов), не 4.7 и не `rel1`.
7. До его исхода развитие паспорта заморозить. `atlas check` и хуки `lint-brief`/`lint-result` живут как есть.
8. При отрицательном исходе план закрывается заморозкой паспорта, без удалений.

## (б) Ответы на вопросы

### 1. Честна ли метрика

Правка разбора (E0) честна и нужна; пересчёт пилота сходится (A 19/17/20, B 21/20/21, C 17/15/19, D 16/19/8). Но метрика пока не судья:

- **Нет предела ширины диапазона.** `["a.py:1-100000"]` при трёх адресах эталона (100, 300, 500, `require: all`) даёт `hit`. У A r1 из 19 засчитанных адресов 10 закрыты только заявками шире 10 строк (диапазоны тел функций): «11 → 19» — это решение считать тело функции адресом.
- **Правило «лишний → false» наказывает точность и поощряет размытость.** 5 точных строк (3 верные) → `false`; тот же охват диапазоном `a.py:100-900` → `hit`. «Верный def + два места вызова» при одном адресе эталона → `false`. Счётчик `false` смешивает «соврал» и «назвал больше потолка».
- **Три счётчика — три единицы «адреса».** `score.classify` — заявка после слияния, с потолком; `analyze_pilot` — «любая заявка закрывает запись», без потолка; `relset` — строка ответа (`a.py:10,200,400,600,800` закрывает одну запись, пятью строками — пять). Класс ошибки, исправленный E0 в `score.py`, жив в `relset.py`.
- **`relset`: обход диапазонами и воздержанием.** Пять разных широких диапазонов → recall 1,0 и precision 1,0; один верный ответ и три пустых → macro precision 1,0.
- **Молчаливая потеря формата.** `a.py#L100`, `a.py:L100`, `a.py (line 100)`, `a.py lines 98-102` → путь без строки → `false`, `unparsed()` пусто. В записях пилота таких адресов 0 [П]; для Sonnet/Opus риск открыт.
- **Токены — не цена.** `final_context_tokens` 100–147k, `cache_read_tokens` 2,5–7,3M за сессию. Порог Kill-2 `tokens_ratio` стоит на первом числе. «B 136k против A 116k» по cache_read не подтверждается (B 4,9/2,9/4,0M, A 4,2/4,6/3,2M).
- **Копия `clone` не исключает пути.** `git show HEAD:plans/…/plan.md`, `git grep --cached`, `git log -S"def as_generic_config"` в копии `fw2-pilot` видят исключённое. Протокол `rel1` разрешает arm A `git grep/log/show`. В трассах пилота команд `git` 0 [П] — пилот не затронут.

**Независимость rel1.** Эталон строит `ast`, не Атлас; `truth.py --check` — 0 расхождений [П]. Слабее другое: «разумный grep» писал автор, знавший ответ — это тоже потолок, не оценка. Протокол сам предсказывает «сигнала не будет»; тратить 7,5M на такой опыт нет смысла.

### 2. Стратегия

| Класс | Что измерено | Вывод |
|---|---|---|
| «Найди строку, где править» | grep-агент 17–21 из 22; реалистичный потолок Атласа 2 / 13 / 18 | ценности нет по построению |
| Отношения (кто зовёт, кто импортирует) | потолок Атласа 61/81 в идеале против 81/81 у grep; `RouterManager`: 3 из 7 импортёров | ценность возможна только при полноте ≈ 1; сейчас её нет |
| Ориентация и суть | не измерено | гипотеза; запас по трассам мал |

Разбор трасс пилота (12 сессий, 677 вызовов): поиск 56 %, чтение файлов эталона 38 %, чужие файлы 4 %, atlas 2 %. 12 файлов эталона целиком — 564 КБ (≈ 165k токенов) при контексте сессии 100–121k: агент уже читает кусками. Оговорка: трасса хранит одно поле `target`, у Grep это шаблон без пути.

**Самый дешёвый решающий опыт — лестница из двух шагов.**
1. «Карта без инструментов», ≈ 60–100k токенов: 12–20 вопросов-описаний без слов кода (`relset lint` умеет проверять), эталон — юнит и файл. Haiku без инструментов получает вопрос и список юнитов с назначением, отвечает юнитом. Порог до прогона: верный юнит с первой попытки ≥ 70 %. Ниже — гипотеза «подсказка приходит сама» опровергнута за копейки. Код 4.7b не нужен: список собирается скриптом по `modules.yaml` и `map <id юнита>`.
2. A против P, ≈ 1,5M токенов, только если шаг 1 прошёл. A — оболочка плюс раздел «Ключевые пути» корневого `CLAUDE.md`; P — то же плюс карта в системной подсказке. n = 6, Haiku. Метрика — медиана вызовов и `cache_read_tokens`, попадания по файлу. Порог до прогона: вызовы −25 % и cache_read −20 % при попаданиях не ниже.

Опровержение: если подача с нулевой ценой вызова не снижает расход, то паспорт «по запросу» не снизит тем более → заморозка. Если снижает — продукт есть, это **сгенерированная карта плюс `map`**, а не `ref`.

«Агент зовёт» опровергнута пилотом (0, 0, 1 вызов при предложении; 5, 5, 1 при обязательном порядке). Поиск по описанию в Атласе — не делать (новый слой рядом с qex и grep). `rel1` (7,5M) — не стоит.

### 3. Спецификации 4.7

- **Делать ли вообще.** Дефект входа настоящий (13 из 24 целей). Но 4.7 стоит ≈ 285–375 строк кода, ≈ 470 строк тестов, правки 11 мест в старых тестах (6 — в слепых файлах) и не отвечает на вопрос «зовёт ли агент». Рекомендация: до исхода шага 1 не реализовывать.
- **Порядок T0 > T1 > T2 спорен.** `ref _capture` отдаёт паспорт тестовой функции, продовые `SdkCodeReader._capture` и `UiEventTap._capture` скрыты; после 4.7a ответ тот же плюс строка-шаблон. Таких имён 107 [П]. Инвариант «0 изменений у 18 094 имён» защищает поведение без пользователей (12 вызовов за всю историю). «Прод вперёд тиров» отвергнут за 85 изменений ответов — но это 85 замен «тест → прод», в нужную сторону. Расчёт альтернативы не делался.
- **«Один продовый»** полезен (122 имени), но 512 имён остаются неоднозначными из-за зеркал в `.claude/plugins/` [П]; спека этого не называет.
- **Строка «есть ещё M»**: число 502 включает привязки, а спека их из M исключает; строку получат 439 имён, в успешных паспортах — 260 [П]. Шумит и не называет класс — убрать.
- **Код 0 при частичном успехе** разумен, но п. D не покрывает всех потребителей: `relset.py:234,255` (по флагу `denied`), `atlas_ceiling.py:57-58`, `analyze_pilot.py:83`. `denied` ненадёжен: в записях пилота стоит у 2 вызовов из 12 при 9 с кодом 2 на повторе [П].
- **Привязки вне кэша фактов.** T1/T2 разбирают файлы заново: 1,6–2,3 с на частое слово, на каждый id; потолок времени — только для одного id [П]. Второй индекс рядом с фактами; по принципу «меньше слоёв» — в факты сканера (пересмотр записи 16, решение уровня ADR).
- **Подсказки `difflib`**: пул «только определения» при том, что T1 находит привязки — `ref LIMITT` подсказки не получит [П].
- **4.7b**: 9 юнитов одновременно юнит и предок вложенных (`frontend_module` — 7); `map <такой каталог>` отдаст паспорт, вложенные не перечислит [П]; слепой `test_passport_map_cli.py` не помечен как слепой [П].
