## Цель

Пересчёт по задаче владельца: дефект воспроизведён заново, цена и достижимость на реальной телеметрии измерены (вывод: правка нужна как согласование с C-98, но на реальном ритме не воспроизводится).

## Красный до правки (реальный вывод)

Воспроизведение (скрипт-проба, офскрин, график 800×400, `crosshair=True`, `downsample` по умолчанию, одна серия «a», две точки с зазором 8e-6):

```
base=1700000000.0 view[0..1] after feed: values_at_x(1700000000.0)=[] | series_points=[(1700000000.0, 1.0), (1700000000.000008, 2.0)] | getData lens=[0, 0] | orig lens=[2, 2]
base=0.0          view[b,b+1e-6] after feed: values_at_x(0.0)=[('a', 'A', '#2563eb', 0.0, 1.0)] | getData lens=[2, 2]
```
То есть `series_points` отдаёт обе точки, `values_at_x` — `[]`; пока вьюбокс узкий (порядок зазора) — оба в порядке. Механизм (замер): `getData()` применяет peak-даунсэмплинг; шаг считается от ширины вьюбокса, а не от числа точек, и при двух точках на вьюбоксе в 1 с шаг больше числа точек → пусто. Вьюбокс [0..1] при данных около 1000 / эпохи: точки вне вида (clipToView) — это и так пусто; осмысленный случай — вьюбокс, содержащий точки (base0 при [0..1], либо `[base, base+1]`, см. тест ниже).

Красный тест (предлагаемый; сейчас красный). Место: `class TestCrosshair` в `test_telemetry_chart.py`, после `test_values_at_x_excludes_empty_series`; в шапку файла добавить `import pytest` отдельным блоком после `from __future__ import annotations`.

```python
    @pytest.mark.parametrize("base", [0.0, 1_700_000_000.0], ids=["base0", "epoch"])
    def test_values_at_x_two_points_8us_apart_wide_view(self, qtbot, base: float) -> None:
        """C-100: две точки с зазором 8 мкс при вьюбоксе шире на порядки — кроссхейр видит обе.

        ``getData()`` отдаёт даунсэмплированный набор и на таком вьюбоксе пуст (авто-peak-шаг больше
        числа точек); исходные данные — ``getOriginalDataset()`` (как у ``series_points``, C-98).
        """
        chart = TelemetryChart(_specs("a"), crosshair=True)
        qtbot.addWidget(chart)
        chart.resize(800, 400)
        chart.show()
        chart.set_series_data("a", [(base, 1.0), (base + 8e-6, 2.0)])
        chart._plot.setXRange(base, base + 1.0, padding=0)
        assert chart.values_at_x(base) == [("a", "A", "#2563eb", base, 1.0)]
        assert chart.values_at_x(base + 8e-6) == [("a", "A", "#2563eb", base + 8e-6, 2.0)]
```

## Правка

`telemetry_chart.py`, строка 211 (+ остаётся защита следующей строки):
```python
            xs, ys = curve.getOriginalDataset()  # исходные точки, не даунсэмплированный дисплей (C-100, как C-98)
            if xs is None or len(xs) == 0:
                continue
```
Проверено на пустой кривой (наблюдение, `getOriginalDataset()`): свежая кривая `pi.plot([], [])`, `set_series_data("a", [])`, `clear_series("a")` и серия только из нечисловых точек возвращают `(None, None)` — не бросает; существующая проверка `xs is None or len(xs) == 0` их отсекает (`values_at_x(1.0) == []`). Для непустой — `numpy.ndarray` float64 (тот же объект при повторных вызовах, копии нет; код его не мутирует). Проверка `ys is None` в `values_at_x` нет: при непустом `xs` `ys` непуст (как в `series_points`, где проверяются оба) — оставить без изменений (правка в 1 строку).

## Что осталось открытым / ненадёжно

1. **Вьюбокс [0..1] с данными около 1000/эпохи**: проба пусто объясняется clipToView (точки вне вида), а не даунсэмплингом; осмысленный красный дают `base0` при `[0..1]` и `[base, base+1]` для эпохи — именно их проверяет предложенный тест. Утверждение в defects.md про «[0..1]» без базы неточно.
2. **Зависимость от версии pyqtgraph**: механизм (шаг peak-даунсэмплинга от ширины вида) проверен только на 0.14.0; на другой версии красный может не воспроизвестись. Тест от этого не защищает.
3. **Offscreen-размер**: красный получен на 800×400 offscreen; на другом размере окна шаг даунсэмплинга другой, граничная комбинация «n=2, 8 мкс, 1 с» устойчива, но другие комбинации (например n=10) от ширины зависят — мерил только при 800.
4. **Реальная телеметрия не мерилась живьём**: ритм взят из конструктора `TelemetryReadModel` (1 Гц, 600 точек), синтетическими точками; реальный живой стенд не гонял, поэтому «недостижим» относится к ритму из кода, а не к снятому логу.
5. **Выборка проб**: ближайшая точка проверена на 400 позициях курсора на вьюбокс, не на всех пикселях; ошибка в узком окне «между пробами» не исключена.
6. **`ys is None` не проверяется** в `values_at_x` (как и раньше); на практике `getOriginalDataset()` возвращает обе оси сразу (None/None или массивы), отдельного случая не наблюдал.
7. **Регрессия по каталогу `frontend_module/tests` не гонялась** (нужен `medium`); прогнаны два файла графика и `test_system_dashboard.py`.
8. **Параметризация одной ячейкой**: оба параметра падают по одной причине; отдельный красный «только эпоха» не нужен, но и отдельного «только base0» тоже нет.
