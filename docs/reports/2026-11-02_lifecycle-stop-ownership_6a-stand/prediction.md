# Ветка 6а — прогноз живого стенда (лид, записано до прогона)

Сессия: inspector-bottles-5e. Дерево: `fix/lifecycle-6a-defects`. Стенд `stand_l9.py` / `stand_backend.py` (T1.11), новые сценарии. Наблюдение через router-команды backend_ctl, без чтения внутренних полей.

| Строка | Вход | Прогноз после правки | На базе `dcf7bc22c` (контроль, 1 повтор) | Порог приёмки |
|---|---|---|---|---|
| S9a (C-64) | провод `direct` между двумя живыми детьми, `wire.setup`, затем `topology.apply` с блюпринтом, который отказывает до команд | ответ `success: False`, `rolled_back: True`; `wire.status` = `active`; `system.health.broken_wires` = 0; pid обоих детей те же; 3 из 3 | `broken`, 1 | литералы |
| S9b (C-64) | тот же провод; откат: блюпринт, отказывающий после части команд | ответ `success: False`, `rolled_back: True`; pid детей новые; `wire.status` = `active` в опросе ≤ 10,0 с; `broken_wires` = 0; 3 из 3 | `broken`, 1 | литералы; если вход на живом стенде невыполним — стоп, вопрос лиду |
| S10 (C-66) | `health.report status=degraded reason=x`, чтение `health.status`, затем `health.report status=ok` | `degraded`, причина `x`; затем `ok`, причина пусто, в state-дереве тоже; 3 из 3 | то же | литералы, страж публикации |
| S11 (стоп) | `system.shutdown` после S9a | выход дерева < 2,0 с, строк `did not stop in` 0, 3 из 3 | то же | < 2,0 с |

Вероятность S9b с первого раза ~60 %: вход «отказ после части команд» на живом PM не отработан, шов `create_process_fn` на стенде недоступен, нужен настоящий отказ. Запасной вход назван лидом, если первый не сработает: процесс с валидным классом, чей `initialize` бросает, при том что readiness-барьер этого не считает откатом — может дать `success: True`, тогда S9b не покрыт живьём, и это записывается открытым, а не подгоняется.
