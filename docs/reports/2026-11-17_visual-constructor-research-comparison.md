### 2.2 Визуальные среды: что у каждой сделано лучше всех

| Система | Механизм, который стоит взять |

| **ComfyUI** (GPL-3.0 — код не копировать) | Разделение «граф в JSON → сервер → события по websocket» [И]. Перезапуск только изменившейся части графа [И]. Схема узла V3: типизированные входы, ленивые входы, сокеты с выводом типа [И]. Подграф: внешние слоты строятся из связей выделенных узлов [И] |
| **Blender Geometry Nodes** | Группа узлов с явным интерфейсом (узлы «вход группы» и «выход группы»), вложенность без рекурсии; цвет сокета = тип; оверлей времени исполнения на узле [З] |
| **Unreal Blueprints** | Точка останова на узле, «следить за значением» на пине, пульсирующий активный провод [И]. Поиск узла при вытягивании провода с фильтром по типу [З] |
| **LabVIEW** | Цвет и толщина провода по типу; пробник на проводе; подсветка исполнения; subVI с панелью подключения [З] |
| **Node-RED** (Apache-2.0) | Значок состояния под узлом; боковая панель отладки; развёртывание только изменённых узлов; subflow [З, режимы — по форуму] |
| **n8n** | Просмотр данных каждого узла после прогона, закрепление данных для повторного запуска [З]. Лицензия Sustainable Use: только внутреннее использование [И] — код не брать |

### 2.3 Рантаймы исполнения: что у каждого сделано лучше всех

| Система | Механизм, который стоит взять |
|---|---|
| **ROS 2** (Lyrical Luth, 2026-05 [И]) | Композиция: код узла не знает, в каком процессе он запущен; размещение задаёт запуск [З]. Управляемые узлы с конечным автоматом состояний [З]. QoS на подписку: надёжность, глубина истории, срок, живость [З]. Передача внутри процесса окупается от ~5 КБ [И] |
| **GStreamer / DeepStream 9.2** | Элемент `queue` — граница потока; режимы `leaky=upstream/downstream` — политика потерь на связи [И]. Согласование форматов между pad до старта [З] |
| **NVIDIA Holoscan** (Apache-2.0 [И]) | Три планировщика на выбор: один поток, много потоков, событийный [И]. Условия запуска оператора как отдельная сущность [З] |
| **MediaPipe** | Пакеты с метками времени, синхронизация нескольких входов по метке [З]. Ограничитель потока: обратная связь «закончил» ограничивает число кадров в работе [по фрагменту исходника] |
| **dora-rs** (Apache-2.0 [И]) | Ближайший открытый аналог: узлы — процессы, операторы — внутри общего рантайма, Arrow + разделяемая память для сообщений от 4 КБ, граф в YAML, горячая перезагрузка Python-операторов [И] |
| **Erlang/OTP** | Стратегии надзора и эскалация «больше N перезапусков за T секунд» [И] — у вас уже есть |
| **Python 3.14 free-threading** | Необязательная сборка, цена 1–8% [И]. Модель процессов не менять; использовать для лёгких узлов потоками |
| **`multiprocessing.shared_memory`** | Ловушка `resource_tracker`: блок может быть удалён раньше времени, нужен `track=False` [И] — сверить со своим кодом |
| **BehaviorTree.CPP** (MIT) + Groot2 (бесплатно до 20 узлов, PRO 590 €/год [И]) | Деревья поведения — для реактивной логики робота, не для потока кадров. Сейчас не нужны |
| **Rerun** (MIT/Apache [И]) | Готовая визуализация и запись потоков данных с Python SDK — кандидат на точечную интеграцию |

**Почему не стратегия 3 (переход на готовую основу).**

- Среди Python/Qt-библиотек нет живой с отделённой моделью. Ваша модель «проект → команды →
  проекция» лучше, чем у NodeGraphQt и Ryven. Переход был бы шагом назад по архитектуре ради
  миникарты и рамок, которые пишутся за дни.
- QtNodes v3 хорош, но это C++ без найденных привязок: пришлось бы вести свои привязки.
- Холст на xyflow через QWebEngine дал бы лучший UX, но добавил бы второй стек (TypeScript,
  мост QWebChannel) и тяжёлый QtWebEngine. Тесты страницы слепы к поведению браузера — это
  уже записано в памяти проекта.
- ROS 2 и dora-rs как движок: ADR «почему не ROS 2» уже есть (`TECH_STACK_2026.md` §3). Ваши
  рецепты, регистры, надзор и `backend_ctl` в них пришлось бы писать заново.

## 4. Лучшие идеи для заимствования

Отсортированы по отношению пользы к цене.

1. **Одна связь — один путь данных** (все зрелые системы). Основа всего остального.
2. **Композиция ROS 2:** узел не знает своего процесса; размещение — отдельный слой.
3. **Политика потерь на связи** (GStreamer `leaky`, QoS ROS 2): «последний», «очередь N»,
   «ждать».
4. **Группа узлов с интерфейсом** (Blender, ComfyUI): составной узел разворачивается при
   компиляции, движок о нём не знает.
5. **Автопреобразование типов на связи и красная недопустимая связь** (Aurora Vision).
6. **Оверлей времени и состояния на узле** (Blender, Node-RED) и **пробник на проводе**
   (LabVIEW, Aurora, Blueprints).
7. **Применение только изменённой части** (Node-RED, ComfyUI).
8. **Поиск узла при вытягивании провода с фильтром по типу порта** (Blueprints).
9. **Ограничитель потока с обратной связью** (MediaPipe) — частично уже есть (`inflight.py`).
10. **Выбор планировщика на группу узлов** (Holoscan): цепочка, DAG, пул потоков.
