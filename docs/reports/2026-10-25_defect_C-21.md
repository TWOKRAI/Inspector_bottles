# C-21(б) — последний активный рецепт вне git · 2026-10-25

**Полоса:** Д (сессия inspector-bottles-53). **Ветка:** `fix/app-active-recipe-state`.
**План:** `plans/app-active-recipe-state.md`, Task C21.1. **ADR:** ADR-APP-008 (уточняет ADR-APP-003).

## Дефект

Выбор рецепта переписывал tracked-файл `multiprocess_prototype/app.yaml`. Воспроизведено дважды:
- 2026-10-21, стенд `letter_robot_sim`: `run.py <recipe>` → `persist_pipeline_choice` → `pipeline:` переписан.
- 2026-10-25, main: владелец выбрал рецепт в GUI → `_persist_active_recipe` → `pipeline:`
  `qr_reader_sdk_dual_demo` → `letter_robot_sim`. Правка в main не закоммичена (файл трогает только владелец).

## Решение

- `ManifestStore.set_pipeline` пишет только `<stem>.state.yaml` рядом с манифестом. Файл под `.gitignore` (`*.state.yaml`).
  Тот же лок `<manifest>.lock`, атомарная подмена, повтор `os.replace` при `PermissionError` (до 20 × 25 мс).
- `resolve_active_pipeline` (framework, без лока, никогда не бросает) берёт состояние, если оно валидно.
  Иначе — умолчание из `app.yaml` и `note` с причиной.
- Оба парсера манифеста (framework и прототип) зовут этот резолвер. `AppManifest` получил `pipeline_origin` и `pipeline_note`.
- Голое имя рецепта в CLI резолвится от `app.recipes`, а не от каталога активного pipeline.
- Видимость: stderr `[run] pipeline: … (источник: состояние …)`, баннер ` (state)`, предупреждение в логе GUI.
- `app.yaml` в ветке не менялся.

## Открыто (после merge, ни одно не блокер)

1. Хаб рецептов даёт удалить рецепт-умолчание, если активен другой. Проба: `delete a` → success; после удаления
   состояния `load_manifest` даёт несуществующий путь, `note=None`. Было и до ветки. Предложение: `RecipeService.delete`
   отказывает и для умолчания, или резолвер пишет `note`, если файла умолчания нет.
2. `backend_ctl/probes/probe_observability_consumer_acceptance.py:129` читает сырой `pipeline` из `apps/line_sim/app.yaml`.
   Расхождение только при появлении `apps/line_sim/app.state.yaml`. Брать `load_manifest(...).pipeline`.
3. `persist_pipeline_choice` пишет литерал `recipes/<name>.yaml`, а `_resolve_pipeline` — `app.recipes`. Для прототипа совпадает.
4. Предупреждение GUI о `pipeline_note` тестом не покрыто.
5. `main.py:162`: `state_path_for` внутри `except`; бросает только на пути с NUL (на Windows в env недостижимо).
6. Тест на лимит повторов чтения фиксирует «≥ 1 повтор», но не «3».
7. Нет `fsync` (как и у старого писателя `app.yaml`).
