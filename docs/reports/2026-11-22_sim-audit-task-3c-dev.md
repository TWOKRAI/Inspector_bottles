### Что я оставил открытым / ненадёжным (раунд 4)

- Допуск ±1 слово в «РАСЧЁТ СЛОВ» применён и к словам из регистров (place x/y/z, pick z), а не только к значениям layout: так показ совпадает с аудитом (он допускает один квант везде). Владелец просил для расчётных по регистрам точное совпадение: сейчас ±1 там помечено «≈ (допуск аудита ±1 слово)», а не «✗».
- «ПО ПЛАНУ … ФАКТ» может показать ✗ только у привязанных заданий; задание с неверным y аудит не привязывает к диску (потеря/лишнее), блока «ПО ПЛАНУ» у него нет. Такое расхождение видно в сводке и в разделе «Диски без команды» (⚠ проверить).
- Таблицу PARAM_SET печатаю сырым словом (масштаб и знак параметра не расшифрованы); имена — таблица id→имя из `param_ids.snapshot` (58 штук), её нужно обновлять вручную при смене протокола. Для опкодов, кроме CVT_JOB/SC_RUN/SERVO/PARAM_SET, расшифровки нет, кроме `PARAM_APPLY` (только название).
- Назначение полей SC_RUN: только имена аргументов из протокола (`count, sc_id, offset, spd_pct, accel, accur`) без смысла значений; смысл STOP_REQ: уровни SOFT/HARD/HALT по `STOP_LEVEL` протокола (0 → «уровень 0»).
- Служебные записи регистра `0x1200/0x1201/0x1202/0x1204` показаны как «не команда роботу» по решению лида; их смысл (ПЧ) не расшифрован. Строка «… ×N» привязывается к записи по внутреннему номеру; повтор внутри блока CVT_JOB игнорируется молча (такого в данных нет).
- Файл большой (≈ 650 строк на 13 заданий); читаемость глазами владельца не проверялась — только структура и тесты. Номера строк layout/messages.log считаются по последней инкарнации журнала, строки файла нумеруются физически.
- Первая версия правки сломала приёмочный тест `test_i_runs_3_summary…` (ссылки отдельными строками дублировали `runK`); исправил размещением ссылки в колонке «путь», приёмочный тест не менял.
