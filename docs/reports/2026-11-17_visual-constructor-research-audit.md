## 1. Аудит текущей архитектуры

### 1.1 Визуальный слой

Живой редактор — `multiprocess_prototype/frontend/widgets/tabs/pipeline/`, не три названных
каталога. `widgets/topology/` — остаток старого редактора (жив только `TopologyPresenter` для
YAML). `frontend_module/graph/` — раскладка и утилиты DAG. `entity_editor` — отдельный
редактор-дерево, к графу не подключён.

**Что сделано хорошо**

| # | Что | Где |
|---|---|---|
| 1 | Модель проекта без Qt, неизменяемая, с чистой функцией `apply()` и инвариантами | `multiprocess_prototype/domain/entities/project.py:291,344` |
| 2 | Команды + снимочный undo (50 шагов, склейка, память выделения) | `adapters/dispatch/command_dispatcher.py:104-200`; общий `SnapshotHistory[T]` уже во framework |
| 3 | Сцена — чистая проекция модели, сервисов не знает | `tabs/pipeline/graph/graph_scene.py:53` |
| 4 | Кодек, валидация, diff, ввод-вывод — без Qt, закреплены тестами | `graph_codec.py`, `wire_validation.py`, `diff.py`, `io.py` |
| 5 | GUI ничего не запускает: только `apply_topology/start/stop` с подтверждением | `runtime_control.py` |

(`modules/recipe/migrations.py:45-89`). Покрывает ли она GUI-метаданные рецепта (`gui_positions`,
`locked_nodes`) — не выяснено.

**Раскладка.** `frontend_module/graph/layout.py` — упрощённый алгоритм Sugiyama: слои по
длиннейшему пути, уменьшение пересечений барицентром в три прохода. Нет фиктивных узлов для
длинных рёбер и нет учёта порядка портов. Работает на уровне процессов.

### 1.2 Слой исполнения

**Модель исполнения.** Единицы: процесс ОС → потоки → упорядоченный список плагинов →
`plugin.process()`. Несколько узлов могут жить в одном процессе (в `webcam_sketch.yaml` процесс
`lines` держит 6 плагинов). То есть «один узел — один процесс» уже не догма, и это верно.
Размещение решает автор рецепта; движок процессы не делит и не сливает.

**Плоскость данных.** Управляющие сообщения идут очередью `system`, данные — очередью `data`.
Массив от 8192 байт пишется в именованное кольцо разделяемой памяти (глубина 8), в сообщении
едет ссылка `_shm_refs`. Заголовок слота — seqlock: читатель сверяет поколение до и после
чтения, рваный кадр отбрасывается и считается.

| Операция | Копий |
|---|---|
| Запись кадра в кольцо | 1 (`np.copyto`) |
| Чтение в конвейере | 0 (представление только для чтения) |
| Чтение для GUI | 1 |

Измеренная цена перехода между процессами — около 0,3 мс (p50), синтетика 640×480, Windows
(`docs/audits/2026-09-04_honest-verdict-bus-and-niche.md` §4).

**Что сделано хорошо**

| # | Что | Где |
|---|---|---|
| 1 | Seqlock и повторная сверка после использования: рваный кадр — учтённая потеря, а не битые пиксели | `shared_resources_module/.../shm_frame_reader.py` |
| 2 | Чтение без копирования, измеренная цена перехода | аудит 2026-09-04 §4 |
| 3 | У каждого класса потерь есть счётчик; системные сообщения не теряются молча | `qos.py:63`, `queues/core/manager.py:469` |
| 4 | Надзор в стиле Erlang/OTP: `rest_for_one`, `one_for_all`, экспоненциальная задержка, возврат памяти после гибели читателя | `process_manager_module/core/restart_policy.py:69-81` |
| 5 | Жизненный цикл плагина с `readiness()` и предохранителем на плагин | `process_module/plugins/base.py:1565` |
| 6 | Проверка портов, join, циклов и недостижимых адресов до запуска | `topology/blueprint.py:825,878` |
| 7 | Маленький контракт плагина: `Plugins/processing/flip/plugin.py` — 47 строк; регистрация декоратором | `process_module/plugins/registry.py` |
| 8 | Наблюдаемость: трасса кадра, метрики цикла, реактивное дерево состояния, `backend_ctl` | `telemetry_readmodel_module`, `state_store_module` |

**Что не так** (E-1 и E-2 проверены по коду мной)

| # | Находка | Где | Проверка |
|---|---|---|---|
| E-1 | Связь не является путём данных. Маршрут: `item["target"]`, иначе `chain_targets` процесса. `wires` вне `topology/` во framework никто не читает.
