## 1. Красные `validate` и `test_qr_reader_sdk*`

- **Источник — данные уроков, не Атлас.** Теги вне словаря (`backend_ctl` → `tools/backend_ctl`; лишние `tests`, `mcp`) в двух уроках; урок роли `tester` лежал в `.claude/agent-memory`, а не в каноне (вернулся слиянием `06cc2ef2f`); индексы `BY-MODULE*.md` пересобраны. Словарь и проверка не тронуты.
- **`test_qr_reader_sdk*`.** Причина — тест `multiprocess_prototype/frontend/forms/tests/test_catalog_kind_roundtrip.py`: первым в процессе вызывал `discover()` и откатывал реестр `PluginRegistry.restore(snapshot)`; откат стирал регистрации первого импорта `plugin.py`, модули оставались в `sys.modules`, следующий `discover()` ничего не регистрировал. Красное — только когда он первый импортёр (`forms + recipes` без «наполнителей»); в полном прогоне зелёное. Было 3 failed / 316 passed → стало 319 passed. Правка — только тест; код framework не менялся.
- **Системное решение не принято** (контракт реестра, teamlead/владелец): `PluginRegistry.discover()` должен возвращать регистрацию уже импортированного модуля после `clear()`/`restore()`. Класс остаётся хрупким.
- Попутно найдено, на `main` не проверялось: 6 красных в `multiprocess_prototype` (`test_integration::test_shutdown_cleans_proxy`, `test_entities_roundtrip::test_every_pick_key_reaches_framework_from_domain`, `test_app_foundation_names`, `test_gui_process`, `test_headless_process`, `test_system_dashboard`) и один во framework (`test_unapplied_metadata_check::test_m10_recipe_set_is_the_known_22`: 23 рецепта вместо 22). ## 2. C-92: гонка импорта `heartbeat.cpu_clock`

- Два потока ребёнка лениво импортировали пакет `heartbeat` (`message_processor` → `cpu_clock`, основной `run()` → `process_heartbeat`); цикл замков импорта CPython 3.12 → `_DeadlockError` на старте.
- **Правка (ADR-PM-060):** П1 — `ProcessHeartbeat` в шапке `core/process_module.py` (пакет грузится до потоков); П3 — PEP 562 в `heartbeat/__init__.py` (ребро `__init__ → process_heartbeat` снято). Решение лида: импорт в `builtin_commands.py` не трогали (избыточен, принцип «меньше слоёв»).
- **Доказательства.** Скрипт `repro_import_deadlock.py` ×40: `main` — 21 `natural` и 40 из 40 `det` дедлоков, ветка 0; П3 один (без П1) тоже 0. Тесты R1–R5: 23 passed; матрица инъекций I1–I3, I6 совпала, I4 и I5 разобраны (дыры нет). Радиус `process_module/tests` 3648 passed, `modules/tests` 292 passed, тяжёлый `test_declarations_leak_order_independence` 5 passed.
- **Стенд.** 240 рестартов на сторону с потоком `introspect.status`: `main` 2 дедлока (та же трасса, что на стенде 1.10), ветка 0 из 202 (38 образцов цензурированы смертью system-очереди, см. ниже). Мощность серии низкая (шанс 0 из 240 без правки ≈ 13,5 %): основное доказательство — детерминированные тесты и механический контроль.
- **Находка по ходу, шире C-36.** Preflight на ветке ответил 202 из 240: после kill №99 (`camera_0`) и №103 (`consumer_0`) system-очередь умерла навсегда (ступенька, а не накопление; на `main` не случилось; код чтения очередей одинаков, старт ветки не медленнее, Фишер p ≈ 0,5). Ребёнок глух к командам (`routing.refresh` теряется, `introspect` отклоняется), супервизор показывает `running`.

## 3. F3: вкладка «Устройства» не роняет слот

- **Решение лида** (владелец 2026-10-28 оставил выбор): **перевод на границе `RecipeDevicesStore`**, а не общий обработчик слотов — одна точка вместо слотов и будущих слотов, слой не добавляется, перевод `RecipeConflict` уже сделан на этой границе. Слоты, robot/vfd, framework не менялись.
- **Состав переводимых ошибок** (расширен стадией 0): `RecipeLockTimeout`, `RecipeFormatError`, `YamlWriteRefused`, `YamlPatchConflict`, `OSError` (порядок существенен: `RecipeLockTimeout` — подкласс `OSError`). Тексты — литералы без пути и содержимого; в лог только имя класса.
- **Доказательства.** 25 тестов слепого tester (17 красных на `main`) + 2 hazard (`OSError` без `chmod`) = 27 passed ×15; матрица инъекций 10 из 11 совпала (I7: R5 краснеет сверх прогноза — безвредно); радиус 112/441/436 passed; ревью воспроизвело живыми слотами (лок, битый YAML, `chmod`, ENOSPC, каталог вместо файла, общий якорь YAML): исключение из слота не вышло, путь в UI и 31 записи логов не просочился.
- Проба: `YamlPatchConflict` воспроизводится на рецепте с общим якорем YAML (`transport: &tr`) при правке значения, на которое ссылается алиас.

## 4. C-91: честный `start_worker`

- **Контракт:** `start_worker` возвращает `True` только если после вызова жив ровно один не остановленный поток (таблица A/B/C под `_start_lock`); `False` вместо лжи, когда прежний поток ещё жив. Запрос остановки не теряется авто-рестартом (корневая проверка в `_restart_worker_internal` + снимок под замком в `stop_worker`). ADR-WRK-007.
- **Доказательства.** Тесты R1–R10 (слепой tester; 7 красных на `main`) + hazard R11–R15; матрица инъекций; два раунда ревью со стресс-воспроизведениями (раунд 1 нашёл три реальных дефекта правки, раунд 2 подтвердил закрытие). Стресс ветки ~32 800 операций, 0 зависаний, 0 двух писателей; `main` — 22 из 30 тактов с двумя писателями. Стенд: 1500 циклов ×3 режима — ветка 0 нарушений, `main` воспроизводит (`raise_stop` 1500 из 1500; `overlap` рост до 34 потоков); камера на фейке: 3+3 цикла `release/take`, воркеров всегда 7, shutdown 1,11 с, ERROR 0.
- Поведение для вызывающих: ответ `worker.start`/`worker.restart` в состоянии B теперь `success: False` (раньше `True` без потока); `camera_device/session.py:330` теперь откатывает цикл вместо вечного `held`.
