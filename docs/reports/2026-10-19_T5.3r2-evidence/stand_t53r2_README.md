# stand_t53r2.py — замер процессной остановки роботов (T5.3 круг 2)
1. Запуск (окно стенда лида): `PYTHONUTF8=1 PYTHONPATH=<корень репо> <venv>/python stand_t53r2.py --scenario {s1..s5|all} --out <dir> [--s4-unconfirmed]`. `all` — каждый сценарий в своём дочернем процессе (до ~155 с на сценарий); порт бэкенда свободный (не 8765/8766), каталоги данных и логов — свежий temp на сценарий.
2. Сценарии: s1 один робот, эхо штатно; s2 один, эхо не приходит; s3 два, оба без эха; s4 два, у r1 ответ на запись STOP_REQ держится 3 с (`--s4-unconfirmed` — r1 ещё и без эха, как слепой a2b); s5 один в движении, процесс `devices` убит жёстко (PM без авто-рестарта, `FW_AUTORESTART=0`).
3. Вывод: одна JSON-строка на сценарий в stdout и `<out>/<s>.json`; stdout дочернего процесса — `<out>/<s>.stdout.log`. `verdict`: OK / PRECONDITION_FAILED (робот не движется или не подключился) / ERROR / TIMEOUT (потолок 90 с) / TIMEOUT_HARD.
4. Поля s1-s4: `stop.stop_reply_s` — от отправки `process.stop` до ответа PM (процесс остановлен); `stop.shutdown_log.detected_s` — когда скрипт увидел строку «DeviceHubPlugin: shutdown» (опрос 25 мс), `line_ts_s` — штамп самой строки минус t0 (мс); `stop.pid_gone_s_readonly_psutil` — PID исчез (только чтение).
5. `robots.<id>.stop_req_writes_in_window` — записи STOP_REQ, пришедшие в Modbus-сервер симулятора в [t0, t0+6 с]; `stop_req_rel_s` / `stop_req_values` — моменты и значения; `..._after_window` — запоздавшие; `moving_after` — TLM_MOVING после стопа; `first_write_spread_s` — разброс первых записей роботов.
6. `exchange_log` — строки со `STOP_REQ` из `<logs>/devices/robot_exchange.log`: `stop_req_lines`, `stop_req_by_device`, `stop_req_rows[].rel_s` (штамп строки минус t0). `supervision_*` — запись `devices` из supervision.status до стопа / после ответа / через 3 с (alive, status, pid, instance_restarts).
7. Поля s5: `wdg.p_wdg_timeout_ms`, `tripped`, `trip_after_kill_s`, `trip_after_last_hb_s`, `tlm_wdg_state_end` (0/1/2), `err_events_since_kill` (строки sim `[v2] ERR ... E_WDG_TIMEOUT`), `hb_changes_in_2s_before_kill` (хаб шлёт HB_PC), `last_hb_before_kill_s`.
8. НЕ меряется: остановка в jog (в backend_ctl нет robot_jog_hold — движение только robot_enqueue_job, CVT-задание, скорость sim занижена до P_SPD_DEFAULT=10); время до сброса буферов файлового логгера (метка могла быть записана раньше, чем прочитана); стоп всей системы (`system.shutdown`) — только `process.stop` одного `devices`; прод-авторестарт после kill (в s5 выключен).
9. Часы: записи робота и t0 — `time.monotonic()` одного процесса; строки логов — стенное время (мс), сравнение с t0_wall; погрешность — порядка опроса 25 мс плюс буферизация логгера.
10. Уборка: `harness.stop()` (убивает только дерево своего PM) и остановка симуляторов, каждое под дедлайном; при `TIMEOUT_HARD` убит один PID дочернего скрипта — дети бэкенда могли остаться (проверить вручную по PID-файлу harness в temp).
