# Отчёт: T5.3h — SOFT при обычном «Отключить» посреди `connect` драйвера робота v2 (полоса Р2, 2026-10-21)

Лид: inspector-bottles-a9. Ветка `feat/robot-v2-t53h`, перебазирована на main `09c3fcdb5` (с 1.9m). Слияние — «да»
владельца (~16:50, через координатора) при условии стенда на середине подключения; условие выполнено стендом тика.

## Итог

Решение владельца 2026-10-21 выполнено. Простой робот, которому обычное `disconnect()` пришло после подъёма связи (A3),
получает ровно один SOFT; до подъёма связи записи нет. Это правило T5.3g, перенесённое на `disconnect()`.

| что | на main (проба, факт) | на ветке |
|---|---|---|
| `disconnect` внутри `probe`/`sync`/действий при подключении (H1–H4) | 0 SOFT | 1 SOFT |
| `connect` выходит между секциями `disconnect` (H5) | 0 | 1 |
| тик закрыл сокет до решения о SOFT (H16) | 0, сокет закрыт тиком | 1, закрывает хвост `disconnect` |
| `request_stop` между секциями `disconnect` (H15) | 0 | 1 (монотонный снимок) |
| тик после «Отключить» успевает SERVO/DO (H13) | probe 1, servo [True] | повторная проверка `desired_connected` под замком |
| до A3 (H6, H7, T0 стенда) | 0 | 0 |

Как: точка линеаризации — `disconnect_stop_plan`. Там пишется монотонный снимок
`(_stopping and _stop_linked) or (_connecting and _connect_linked and link_up())`, только при `not _shutdown` и до
`_stopping = True`. Добавлены новые переходы `disconnect_soft_plan` и `disconnect_owns_close`. Новых полей и замков нет.
Решение и все остатки описаны в ADR-DH-011.

## Уроки

- Окно стенда — только для запуска. Подготовка и сухой прогон идут вне окна, каждая команда с timeout, срок держит лид
  (`docs/claude/memory/feedback_a_stand_window_is_for_running_not_preparing.md`).
- Ручные `device_connect`/`device_disconnect` супервизор исполняет по очереди. Живая «середина connect» достижима
  только через тик. Стенд ручными командами её не покажет — и это не дефект.
- Протокол рецепта: `robot_demo` объявляет `delta_universal3` (драйвер v1). Для стенда драйвера v2 нужна копия рецепта
  с `delta_v2`. У CLI симулятора нет `--protocol v2` (T2.3) — понадобился свой скрипт с `RobotSimCoreV2`.
- Колонка «связь поднята до disconnect», посчитанная по времени ОТПРАВКИ команды, вводит в заблуждение. Судить надо по
  журналу обмена бэкенда.

## Что осталось открытым

- `request_stop` после решения D3 (или с записью, ещё идущей в этот момент) даёт 2 SOFT, как у подключённого робота на
  main. Владелец: оставить, отдельной задачи нет (очередь `86a522927`).
- C-29 (новая): «Отключить» не прерывает идущее ручное подключение — `connect` успевает записать параметры и выполнить
  SERVO/DO. Не регресс. Очередь: после T5.3h, перед SPI хаба.
- Остатки ADR-DH-011, разобранные только чтением кода:
  - I1 (а/б/в);
  - `_shutdown` вместе с «Отключить»;
  - ручной `connect` на падении связи между D2 и C3;
  - исключение из `transport.is_connected` до D6.
- Свойство 9 («закрывает только хвост disconnect») держит один тест — H16. Слепой B5 не различает, кто закрыл сокет.
- Повторов барьерных тестов ×5 на нестабильность нет.
- Сторож `test_no_private_driver_state.py` считает обращения к шву `_client` литералом (40). Задача SPI хаба, закрывая
  шов, меняет и тесты T5.3h.
