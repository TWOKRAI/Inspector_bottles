## 5. Правки, без которых cto работает вслепую (блокируют)

**Б1. tasks/1.8.md:27-33 (п.2) и :37-38 (п.4)** → окно автоперезапуска покрывает только «не жив или без свежего листа».
Перезапущенный ребёнок публикует свежий лист `ready: false` с причинами плагинов (например 2.2 RED
`test_readiness_failure_until_model_loaded`) → `failure` → `tick` в `running` → `fault`. Флаг для тяжёлого процесса не
работает никогда, окно `grace_s` не используется. Заменить в п.2 текст от «только при `running=True`» до «START
запрещён.» на:

> только при `running=True`. Окно процесса из `auto_restart` **открывается**, когда процесс не жив или без свежего листа
> (записи в `down_since` нет — окно началось сейчас, `now - down_since.get(name, now) = 0`); PM пишет
> `down_since[name] = now` на этом тике и **снимает** запись, когда у процесса нет причин `failure`. Пока запись есть
> (или окно только открылось), `now - down_since.get(name, now) < grace_s` и процесса нет в `given_up`, — **все**
> причины `failure` этого процесса (liveness и причины листа, например «модель не загружена») заменяются одной
> `out_of_spec` «перезапуск <процесс>», `node` = имя процесса, `source: liveness`; на `ready` они не влияют. Процесс с
> флагом, который жив, со свежим листом и без записи в `down_since`, — как без флага: его `failure` → `fault`. При
> `running=False` (`ready`, `not_ready`, `booting`) флаг не действует: мёртвый процесс — `failure` «процесс не жив»,
> START запрещён.
