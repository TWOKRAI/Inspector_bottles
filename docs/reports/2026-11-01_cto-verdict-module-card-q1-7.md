# Вердикт CTO: вопросы 1–7

Основной файл (общая оценка, Q16, Q17, открытое): [2026-11-01_cto-verdict-module-card.md](2026-11-01_cto-verdict-module-card.md). Вторая часть: [2026-11-01_cto-verdict-module-card-q8-14.md](2026-11-01_cto-verdict-module-card-q8-14.md).

**1. Абстракция — ПРИНЯТЬ с уточнением.** Карточка — вид, не модуль: обратного пути `BaseManager → CommandManager` в графе нет; `base_manager/interfaces.py` защищён сторожем stdlib (`test_interfaces_imports_only_allowed_stdlib`), значит `CommandSpec` там держит `params` только непрозрачной ссылкой, не Pydantic-типом. Роль «одно ядро, фронты CLI/REPL/MCP» не потеряна — уже реализована: `capability-manifest-idea.md` статус «v0 РЕАЛИЗОВАН 2026-07-07, CI-gate живой», `driver.capabilities()` сводит процессы. Уточнение: ядром назвать **существующий каталог**, а не новый `CommandSpec`. Бриф пропустил третий каталог — `CommandCatalog` прототипа (`frontend/bridge/command_catalog.py:1-70`, из `PluginRegistry`); gui-service 1b.2b «убирает `PluginRegistry` из GUI» (ORDER стр. 33) — GUI должен стать потребителем `introspect.capabilities`; записать как цель.

**2. Объём — ИЗМЕНИТЬ.** Сразу: команды (имя, описание, теги, `params_schema` — уже есть) + `access` (новое) + владелец команды. `router_handlers` и `registers` **уже в карточке** (`builtin_commands.py:884-902`) — бриф просит их как недостающие. Вырезать: «Конфиг» (FieldMeta — бог-узел 143 ребра; `introspect.registers` с `meta` — уже Task 1.4 camera-device) и «Здоровье» (`_register_health_commands`, строка 3487 — команды, не блок). «Состояние» — через `module.info` из `get_stats/get_debug_info`, S. Версии контрактов: у плагинов `api_version` в `introspect.plugins` есть; для команд преждевременно. Зависимости между модулями — статика Atlas, не рантайм.

**3. Источник объявления — ИЗМЕНИТЬ: `@expose` отклонить как основной путь.** Зонд (`sig_probe.py`, Pydantic 2.13): `show(title: str, lines: int = 20)` → схема `required=['title']`, `{'lines':'7'}` → `7`; `enable_input(callback: Callable)` → `PydanticInvalidForJsonSchema`. Автоадаптер работает ровно для JSON-типов — бриф это предвидел. Решающее не это: 38 настоящих обработчиков — приватные `_cmd_*`, не методы интерфейсов; у плагинов форма — словарь `commands` + `command_options`; **camera-device Task 1.3 (W7, бриф лида написан) добавляет плагинам `command_contracts: dict[str, type[BaseModel]]`** — форма объявления уже решена. `@expose` стал бы второй новой формой параллельно 1.3. Решение: одна форма = обобщение плагинной на любой `BaseManager`: `command_specs()` возвращает кортежи, 1:1 ложащиеся в kwargs `register_command` + `access`. `@expose` — сахар после пилота. Имена без префикса (`set_config`, `get_metrics`) замораживаются; новым командам обязательный `<модуль>.<действие>`.

**4. Сервисы — ИЗМЕНИТЬ.** `BaseService(BaseManager)` как **доступная** база — принять: направление `Services → framework` разрешено, три сервиса уже на `BaseManager` (`auth/manager.py:91`, `device_hub/manager.py:54`, `sql/core/sql_manager.py:33`). Отмену ADR-SVC-002 — **отклонить**: `IService` остаётся контрактом, `BaseService` — реализация по умолчанию; довод ADR «фреймворк не диктует структуру application-слою» не устарел — «один репозиторий» не значит «один слой». «Все 18 получают `service.py` с настоящим `start()`» — **отклонить пакетом**: библиотеки (`layer_render`, `line_sim`) не имеют жизненного цикла, `ServiceRegistry` хранит классы (ADR-SVC-003) — обёртка будет ложной единообразностью. Против оболочек-лгунов: (а) `get_status()` оболочки возвращает `state: "shell"`, не `"running"` — правка по строке в пяти файлах, S; (б) приёмка на сервис — «после `start()` виден ресурс» (аналог ADR-007); (в) `assert isinstance(SqlService(), IService)` на уровне модуля (`sql/service.py:69`) снимается `python -O` — заменить тестом. Очередь: `ServiceHost._cmd_start` → `KeyedExecutor` уже стоит (ORDER стр. 31, 2.0; план lifecycle строка 475) — `BaseService` после него, в полосе Services, не Ф.

**5. Сбор менеджеров — ИЗМЕНИТЬ: реестр не расширять.** `register_manager` — 9 вызовов (`process_managers.py:172-200`, воспроизведено). `StateStoreManager` создаётся в `app_module/orchestrator.py:411`, `RegistersManager` — в `plugin_orchestrator.py:367`, `PluginManager` — в `plugins/manager.py:12`; у `StateStoreManager` уже есть `register_commands(command_manager)` (`state_store_manager.py:613`) — образец «владелец зовёт в месте сборки». `register_from(obj)` зовёт владелец после своего `initialize() == True` и до `log_registration_summary`; `module.list` читает реестр `ObservableMixin` плюс владельцев из `metadata` команд. В `BaseManager.initialize` не класть — база не видит `CommandManager`.

**6. Единый источник — ИЗМЕНИТЬ.** `modules.yaml` остаётся единственным статическим источником идентичности/яруса/назначения; `declare_module(...)` в коде не вводить — это третий реестр. `declare_log_source` — процессный реестр импорта; идентичности рантайм не нужна. Дешёвый шаг: Atlas уже считает «кто использует модуль» из кода (вывод `card command_module`) — добавить находку «модуль в yaml без `interfaces.py` и наоборот» (план atlas, 2.0, стр. 38). `module.info` отдаёт `type(obj).__module__` и первую строку docstring — без yaml.

**7. Динамика — ИЗМЕНИТЬ: `unregister_command` не добавлять.** Воспроизведено: в `dispatcher.py` только `delete_scenario` (495) и `remove_handler_from_scenario` (528); `del storage[key]` лишь внутри `overwrite_handler` (633-639); `CommandManager` чистит только `_executors` (`command_manager.py:638`). Каталог — контракт с CI-гейтом; исчезающая команда ломает кэш клиента и принцип FREEZE. Сервис после `stop` отвечает `{"success": False, "reason": "service not running"}`. Удаление — парным ADR, когда появится горячая смена рецепта (stand-recipe-switch, 2.0, стр. 34). Команды плагинов после останова плагина — не проверялось.
