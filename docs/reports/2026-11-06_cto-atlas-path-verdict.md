## 1. Вердикт о пути

Путь верный, направление не менять. Схема «один сканер → факты по oid → индекс связей → паспорт → виды» даёт
эффективность, не красоту. Поправить три вещи до следующего шага. Первое: E2 строит паспорт третьим сканером поверх
файлов, которые решено удалить, — его код дальше не чинить, а перенести на факты A1. Второе: qex и graphify не вплетать
в атлас — они соседи, не части. Третье: до A3′ зафиксировать контракт паспорта и состав фактов, иначе A3′, бенч,
страница и карточка будут собраны трижды. Останавливать ничего не нужно; E2 раунд 2 — урезать (§5).

## 2. Ответы на 7 вопросов

**1. Костыли, дубли; атлас против graphify.** Проверено: `graphify get_node ConfigFileWatcher` → `watcher.py L196,
Type: code, Community: ObservabilityPort, Degree: 9`. Всё. Ни сигнатуры, ни описания, ни членов, ни тестов; имя
сообщества вводит в заблуждение (это `config_module`). Граф: 48 870 узлов, 76 391 ребро, 3 015 сообществ; свежесть не
проверена. Паспорт E2 на тот же класс даёт первый абзац, сигнатуру, члены с сигнатурами, базы. Решение: сосуществовать;
атлас от graphify не зависит; сообщества как «подсказка районов» — выбросить (районы = каталоги, решено). Замену
graphify примет бенч: если условие `graphify` не добавляет попаданий к `atlas`, graphify для кода уходит из правил ролей.
Дубли: (а) третий сканер в `signboard.py` (свой `Index`, `scan_file`, `get_index`, ~8 с); (б) `signboard.py:33`
импортирует из `build.py`, а слой/юнит/пакет читает из `docs/arch-map/model.json` — оба удаляются в B2; (в) «атлас
обновляет индексы qex и graphify» — чужая работа внутри атласа.

**2. Паспорт из кода против карточки модуля в `base_manager`.** Один источник — объявление в коде модуля; два
читателя. `@expose` на методе интерфейса и `CommandSpec` — литералы в AST: сканер читает их статически,
`CommandManager` — в рантайме. Второй реестр не возникает при двух условиях: паспорт никогда не хранит рантайм (нет
`get_stats`, нет состояния процесса); `backend_ctl capabilities` — только сверка (стоп 3), не источник. До `@expose`
паспорт читает литералы `commands = {…}` и `register_command("…")` и пишет «динамических: M», а не «0».

**3. `modules.yaml`.** Проверено: 1 022 строки, 88 записей, «ведётся руками» (строка 1). Карта по правилу «юнит =
каталог с `__init__.py`» нашла 128 юнитов (111 настоящих + 17 синтетических); расхождения с yaml уже есть
(`registry-drift` 1; 4 файла без модуля в `Services/camera_device`). Решение: модули выводятся правилом; `modules.yaml`
сжимается до конфига проекта — корни слоёв, группы плагинов, исключения («этот путь — часть того модуля»,
`other_allowed`). `purpose` и `tier` уходят в докстринг. Id модуля = имя каталога, как сейчас: ссылки в ADR и памяти не
ломаются. Нужно слово владельца (вопрос 3 проекта слияния).

**4. Где хранить модель.** И то и другое, с разными ролями. sqlite — кэш: факты по oid, виды по ключу; выбрасывается
без потерь. Модель для SHA — файл-вид (`data/atlas/map/model.json`, паспорта по запросу); его читают страница, бенч и
агенты; в git не кладётся. Проверено: `data/atlas.sqlite` = 288 935 936 байт при 1 858 файлах — запах, причина не
выяснена. A2 получает условие: размер базы ограничен или чистится.

**5. `atlas find`.** Не сейчас. Проверено: индекс qex от 2026-10-18 (19 дней), 32 816 файлов, 90 964 чанка — втрое
шире кода и несвежий. `find` = попадание qex + `ref` на символ; это вид над `ref --format json`, ~30 строк, когда `ref`
есть. Окупаемость решает условие `qex` в бенче (E1 добавляет): нужен, только если сумма лучше каждого в отдельности.
Мерить, не строить.

**6. Порядок, стопы, пороги.** Верны. Три правки: E2 раунд 2 урезать до ложных фактов; стадия 5 A1 (весь каталог
тестов, инъекции, ревью) — до начала A3′; точка отсчёта стопа 1 — запись самого `nav_bench` в чистой копии (решение E1
п. 2); пробный прогон 39 вызовов/85k не сравним. Пороги — §5.

**7. Чего не хватает для эффективности.** (а) Цена входа: `k0_reference.json` = 58 759 байт ≈ 17k токенов; агент,
читающий его целиком, тратит треть порога до первого вопроса. Паспорт — по одному символу на запрос, не блоб.
(б) Скорость: тёплый `ref` ≤ 2 с, иначе агент берёт grep; A1 даёт 0,06 с тёплого скана (по отчёту), узкое место —
сборка паспорта и старый `codemap`. (в) Привычка: инструмент без вызовов не эффективен; после стопа 1 — строка в
правилах ролей «перед чтением модуля — `atlas ref`» и счёт вызовов `atlas` в транскриптах за неделю. (г) Провенанс:
каждый факт несёт `файл:строка`, «объявлено» или «не найдено» — агент прыгает, а не ищет.

## 4. Решения зафиксировать сейчас

**Д1. Контракт паспорта v1 (JSON и текст).** Конверт: `passport: 1`, `kind` ∈ {layer, unit, package, file, class,
function, method}, `id`, `path`, `line`, `sha`, `scanner`. Шесть разделов с постоянными ключами, одинаково у всех видов;
пустое = `null` или `[]`, ключ не опускается: `purpose` (текст, `declared_at`), `interface` (правило слоя, `all`,
интерфейсы, сигнатура, члены), `links` (`used_by`, `uses`, `subclasses`, `call_sites`, `bases`), `runtime`
(`processes`, `threads`, `commands`, `io`), `checks` (`findings`, `tests`), `status` (`tier`, `doc_missing`, счётчики
`dynamic`). У каждой связи — `where: файл:строка` и `how: import|name-call|structural|declared`. Текст печатает те же
шесть заголовков в том же порядке, пустые — «—». Один объект кормит `ref`, `map`, страницу, бенч.

**Д2. Состав фактов v2 (A3′ поднимает `SCANNER`).** Всё, что считается из одного блоба, живёт в `FileFacts`: у каждого
`def` — `qualname`, `line`, `signature`, декораторы (листовые имена), `abstract`, `async`, первый абзац докстринга; у
класса — члены с тем же, базы текстом; у файла — вызовы по имени `(имя, строка, объемлющий qualname)`, ввод-вывод
`(операция, выражение пути, строка, объемлющий)`, имена test-функций с их идентификаторами. Всё, что требует второго
файла (наследники, места вызова, структурные двойники, тесты по символу), — индекс над фактами, не факты. Правила ревью
E2 (F1 `args[1]` у `.schedule`, F2 вызов в том же файле с объемлющим символом, F3 `replaces`, F7 порог двойников)
становятся красными A3′.

**Д3. Где живёт код.** `scripts/atlas/passport.py` (паспорт всех уровней; `module_spec` из проекта слияния — его часть),
`scripts/atlas/links.py` (индексы над фактами), `scripts/atlas/assets/` (страница и библиотеки с диска).
`scripts/nav_bench/` остаётся отдельным и атлас не импортирует: измеритель не зависит от измеряемого. `scripts/arch_map/`
замораживается сегодня, удаляется в B2 вместе с `docs/arch-map/`.

**Д4. Один источник команд.** Паспорт читает только объявленное в коде модуля; рантайм — только сверка. Одна строка в
ADR атласа и в план карточки модуля, чтобы его шаги 1–2 выбрали литеральные формы (`@expose`, кортеж `CommandSpec`),
читаемые статически.

**Д5. Юниты по правилу, `modules.yaml` → исключения.** Ждёт слова владельца; до него A3′ читает оба и пишет
расхождение как находку.

**Д6. Хранилище.** sqlite = кэш, файлы-виды = модель; сгенерированного в git нет.

**Д7. graphify и qex** — не зависимости атласа. Решение о замене — по бенчу на стопе 1.
