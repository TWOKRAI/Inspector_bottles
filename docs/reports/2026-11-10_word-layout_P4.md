## Что оставил открытым

1. **Окна съёма §2.8** не сходятся с геометрией сима у части дисков (py смещён к −341). Решение владельца: оставить FAIL, расширить (с причиной в `amendments.md`) или править сим/калибровку (полоса Д).
2. **Потеря диска «М» сетью:** нет строки layout в прогонах 2 (D), 4 и 5 (B); в 6–8 распознан. Правдоподобная причина — предсказание ниже порога (`WordLayoutPlugin._top_pred` отбрасывает молча); не доказано: `recog` не пишет предсказаний. Находка для Task 1.2 / ORDER #27.
3. **Угол:** точность сети хуже окна ±5° у части дисков (до 14°); вердикт скрипта по Д6 — «иное», не «совпала».
4. **Подача против списка** скриптом не проверяется (после снятия `feed` ±0,5°); R1 подтвердил подачу точной.
5. **Остаток привязки стопа:** файл прошлого запуска с поздним mtime даёт PASS (`touch`, `cp` без `-p`); защита работает только через `main()`.
6. **Поздняя строка диска** — INFO, не FAIL.
7. Реальный `BackendDriver` (тайм-ауты, `events_page`) проверен только стендом; Windows вне объёма; `park.servo: False` в ответе park — смысл не разобран; `recog` в итоге `shutdown` не виден (предел драйвера, PASS с пометкой).
8. `data/line_sim`, веса сети и `data/logs/prototype` на стенде лежат вне git; прототип нужно запускать свежим перед каждым прогоном.
