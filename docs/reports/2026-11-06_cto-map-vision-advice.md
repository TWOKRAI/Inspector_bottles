## 0. Вердикт в одну строку

Направление верное. Реправка лида верна в метрике, в уровнях и в «одна модель — два вида». Она ошибается в трёх местах:
источник IPC-дорог (не код, а YAML топологии), «файловые дороги по литералам закрывают K0 8–9» (не закрывают), и место A2

## 1. Что оставить, что поменять, что выбросить

Мерило — аналогия владельца. Материки = слои (5). Страны = юниты (128). Города = пакеты (310). Районы = файлы (1859).
Дома = классы и функции (1853 класса, 1390 функций, 6215 публичных методов). Дорога = связь двух адресов. Войти в дом =
открыть код.

Оставить:
1. **Метрика навигации** вместо «N из 10 без исходника». Эталон уже есть: ключевые ответы в handoff, все с `файл:строка`.
   Проверка скриптом: назвал ли агент ожидаемое `файл:строка`. Пороги — §3.
2. **Шильдик на каждом уровне из докстринга.** Данные есть: докстринг у 1815/1859 файлов, 1702/1715 публичных классов,
   4895/5933 методов, 1118/1390 функций. Шильдики заполнятся из кода на ~97% домов без единой рукописной строки.
   Исключение — `backend_ctl` (181/381).
3. **Одна модель кормит браузер и агента.** Это решение 5 проекта слияния (`module_spec`). Расширить до `symbol_spec` для
   дома: одна функция для `ref --format json`, для `map --depth N` и для карточки при наведении.
4. **A1 без изменений.**

Поменять:
5. **«Дороги IPC из кода».** В коде `FieldRouting(channel=…)` литералом — 8 файлов, 2 имени (`control_example`,
   `control_pilot`). `channel_map.py --root multiprocess_framework/modules` даёт `decl` 1–2 и `?` почти везде. Магистрали
   между процессами объявлены в YAML: `multiprocess_prototype/backend/topology/inspection_full.yaml` (11 строк
   routing/targets), `system.yaml`, рецепты. Задача «дороги IPC» читает YAML топологии (`yaml.safe_load`, не регулярка);
   литералы кода — добавка. Рантайм-истина — `backend_ctl capabilities` / `introspect_router_stats`, отдельный снимок, как
   уже отложено в §5 проекта.
6. **«Файловые дороги по литералам путей закрывают K0 8 и 9».** Нет. Вопрос 9: companion пишет через
   `companion_path(recipe_path)` (`process_module/configs/observability_companion.py:49-51`, `:119`, `tmp.write_text`
   `:137`). Вопрос 8: watcher берёт путь параметром (`config_module/tools/watcher.py:216`). Литералов нет ни там, ни там.
   Честная замена — **шильдик ввода-вывода у дома**: `пишет: <выражение пути>`, `читает: …`, `следит: …` (вызовы
   `open/write_text/safe_dump/observer.schedule`, аргумент через `ast.unparse`). Это навигация: агент находит оба дома
   одним поиском по слову. Это не поток данных. В коде 227 таких вызовов и 247 литералов `.json/.yaml/.log/.sqlite` —
   объём посильный.
7. **«Нет докстринга = находка».** Для методов и функций это ~1300 находок, 200 из них в `backend_ctl`. Находка — на
   уровне юнита и класса; у методов — счётчик в шильдике («без описания: 12 из 40»).
8. **`atlas route A B`** — оставить, но последним и только по графу юнитов (384 ребра, BFS). «Развилки» = второй и
   третий путь. По файлам не строить до замера.

Выбросить:
9. **Дома как узлы схемы.** 9,5 тыс. символов убьют раскладку. Дом — строка в карточке района, не узел.
10. **«Дороги-потоки» как рёбра.** 31 поток с именем и `файл:строка` — это шильдик юнита, не дорога.

## 2. Вид Google Maps по уровням

Что есть сейчас (снимок безголового Edge, первый вид): пять материков в ряд, провода между ними с числами
`hard/lazy/tc`, в коробке слоя — юниты, файлы, строки, ошибки/предупреждения. Наведение только подсвечивает
(`index.html:1956-1962`); карточка — по клику («Выберите узел»). Материки есть. Нет подписи «что это» и правила
направления.

| Уровень | Карточка при наведении (всё из кода) | Дороги видны | Сегодня в карте |
|---|---|---|---|
| Материк = слой | имя; одна строка назначения (докстринг `__init__.py` слоя: есть у 4 из 5, у `Services` нет — находка); правило «импортирую из …, меня импортируют …»; юниты/файлы/строки; находки по серьёзности | агрегат между слоями с числом; красный — против правила | коробка и провода есть; назначения и правила нет |
| Страна = юнит | назначение (111/128 из докстринга; 17 без — все синтетические `__root__`); ярус (27/128, остальные «не задан»); витрина `__all__`; интерфейсы с видом Protocol/ABC; команды с пометкой «N динамических»; потоки; рецепты, где назван; fan-in/out; тесты | юнит→юнит по виду импорта; **рецепт→плагин как отдельный вид дороги** | карточка по клику есть; рецептной дороги нет (только список) |
| Город = пакет | назначение из `__init__.py`; `__all__`; файлов и классов | пакет→пакет | узел есть, карточки почти нет |
| Район = файл | первая строка докстринга; список домов: имя, вид, одна строка, публичный/нет, «кто зовёт: N» | файл→файл с именами на проводе | узел и имена классов есть; шильдиков домов нет |
| Дом = класс/функция | сигнатура; первый абзац докстринга; вид (Protocol/ABC/plugin/manager); `abstractmethod`; базы и наследники; до 3 мест вызова `файл:строка`; тесты как nodeid; ввод-вывод (п. 6) | вызов по импортированному имени; наследование | нет ничего — это A3 |

«Понятно с первого взгляда» — три правила. Первая строка карточки — «что это» одним предложением. Вторая — «кто меня
использует / кого использую я» числами. Третья — красное только там, где нарушено правило. Остальное ниже сгиба.

### 2а. Слои как материки

Нарисовано: пять коробок в разрешённом порядке, стрелки справа налево. Не нарисовано правило. Нужно: строка в карточке
слоя «можно → framework; нельзя ← Services/Plugins/prototype» и красная дорога при `layer-reverse`. На HEAD таких находок
0 — это тоже показать словами («нарушений направления: 0»), иначе владелец не знает, что проверено.

### 2б. Слои-наложения

| Наложение | Данные | По умолчанию | Откуда |
|---|---|---|---|
| Импорт hard/lazy | есть | вкл | модель |
| Импорт tc | есть | выкл (не дорога в рантайме) | модель |
| Находки, «только нарушения» | есть | вкл | модель |

| IPC-каналы между процессами | нет | вкл только в «виде процессов» | новый скан YAML топологии + литералы кода |
| Ярус core/optional/frozen | 27/128 | выкл, пока покрытие < 80% | шапки `Tier:` в 36 `__init__.py` (§5 отложено) |
| Контур | 0/128 | не делать | — |
| Ввод-вывод (пишет/читает/следит) | нет | в карточке, не на схеме | новый скан вызовов |
| Тесты | только число файлов | число — в карточке; nodeid — A3′ | покрытие строк = pytest-cov, тяжёлый прогон, не сейчас |
| Процессы в рантайме | нет | отдельный снимок | `backend_ctl`, живой стенд (§5) |

**«Вид процессов» — отдельный материк:** процесс не каталог. Его строит рецепт: какой юнит в каком процессе, какие
каналы между процессами. Это и есть транспортные пути владельца. Сегодня их нет ни в атласе, ни в карте, ни в плане.
Это главное расхождение с аналогией.

## 5. Один дешёвый эксперимент до пяти задач Senior+

Предложение лида верно с одной поправкой: эталон строить не руками, а скриптом. Руки внесут суждение, которого сканер не
даст, и опыт соврёт в пользу плана. Скрипт на `ast` за один заход Sonnet собирает по десяти символам K0 ровно поля строки
«Дом» из §2: сигнатура, первый абзац, `abstractmethod`, базы, наследники по имени, вызовы по импортированному имени,
nodeid тестов, ввод-вывод. Один файл JSON. Дальше три прогона Haiku «только эталон» и три «эталон плюс код». Порог — как
стоп 1. Цена: ~1 задача Sonnet + 6 прогонов Haiku по ~50k. Эталон даёт < 6 из 10 — шильдики в этом виде не решают, и A3′
меняется до первой строки кода.

Второй, ещё дешевле, для владельца: три карточки-макета (слой, юнит, класс) в HTML руками, 1 час, показать владельцу до
B2′. «Понятно с первого взгляда» нельзя проверить после задачи Middle — только до.
