# gui-graceful-close · Task 1.1a · проба на Mac (2026-11-07)

Что проверено: PM отвечает на `supervision.status` в окне остановки детей. Машина — Darwin, `BackendHarness` с `launcher_factory`, `drv.system_shutdown()`, опрос `drv.supervision_status(timeout=1.0)` раз в 50 мс. Считаются только ответы, начатые после отправки команды.

Скрипты лежат рядом: каталог `2026-11-07_gui-graceful-close_1.1a_mac-probe/`. Выбор: скрипты, а не тест в каталоге PM. Реальный запуск процессов на ~8 с не место среди быстрых тестов, а механизм уже закреплён там тестом с фейковым ребёнком (`test_pm_responsive_during_children_stop.py`, инъекция I1 «`children` обратно в `_own_work`» краснит PM 1, 2, 3, 6, 7).

Запуск из корня репозитория (`R` — корень, `D` — каталог скриптов, на Windows `.venv/Scripts/python.exe`):

```
# слабая проба: minimal_app без медленного ребёнка
PYTHONPATH=$R $R/.venv/bin/python $D/probe_stop10.py 10 8797
# различающая проба: ребёнок с shutdown 4 с
PYTHONPATH=$R:$D/slowapp $R/.venv/bin/python $D/probe_slow.py 3 8799
```

Для замера «до» — `git archive 315fdbf51` в чистый каталог, `cd` в него, тот же `PYTHONPATH` с этим каталогом первым; путь импорта проверять: `python -c "import backend_ctl; print(backend_ctl.__file__)"`. Через `machine_gate.sh medium <session>`.

## Слабое свидетельство: minimal_app без медленного ребёнка

Дети умирают мгновенно, поэтому проба не различает версии. Это не приёмка.

| Дерево | Прогонов | Стоп | Ответов за стоп | `did not stop in` |
|---|---|---|---|---|
| main с 1.1a (`0f1883a64`), `harness.stop()` + `system_shutdown` | 10 | 0,59–0,65 с | 2–4 (макс. 13 мс) | 0 |
| до 1.1a (`315fdbf51`, копия `git archive`) | 5 | 0,66–0,71 с | 2 | 0 |

## Различающая проба: ребёнок с медленным shutdown

Потребитель `minimal_app` с `time.sleep(4.0)` в `shutdown` плагина; `ticker` обычный.

| Дерево | Прогонов | `system_shutdown` до выхода | Ответов после команды | Макс. ответ | `did not stop in` |
|---|---|---|---|---|---|
| до 1.1a (`315fdbf51`) | 3 | 4,24–4,38 с | 1, 0, 0 | 11 мс | 0 |
| после (`main`, `0f1883a64`) | 3 | 4,35–4,37 с | 69, 68, 68 | 14 мс | 0 |

Вывод: механизм 1.1a различается на Mac. До правки `message_processor` PM закрывается раньше детей, и ответы пропадают. После правки он отвечает всё окно.

## Не проверено

- Серия 10 из 10 на графе `inspection_full` с порогом 1,77 + 0,3 с — ждёт Windows.
- Граф с одним зависшим ребёнком (стоп дольше `pm_graceful_s`) — ждёт Windows.
- Проба идёт на фейково-медленном плагине, не на реальном детском процессе камеры.
- Прогонов 3 на сторону; для числа «ответов» этого хватает, для распределения времени стопа — нет.
