DESIGN (решено лидом — ты печатаешь, а не выводишь):
  1. `collect.py` — CLI `python -m scripts.wire_audit.collect --proto-port 8765 --sim-port 8766 --out-dir <каталог> [--period 0.25]`; работает до Ctrl-C или файла-стопа `<out-dir>/STOP`. Только чтение: не меняет сим, прототип, регистры. Клиента `backend_ctl` брать тем же способом, что `scripts/alpha_sim/run_alpha.py:210–213` и `:309` (читать как образец, **не импортировать α-логику**; сам драйвер `backend_ctl` импортировать можно).
  2. В начале один раз: `introspect_registers layout` → `<out-dir>/registers.json` (поля: `first_x, first_y, pitch_mm, disk_radius_mm, line_angle_deg, place_z_mm, pick_z_mm, angle_zero_deg, angle_invert, use_pitch, word_gap_slots`; `p_pick_rz_deg` — из параметров драйвера, если доступен, иначе −100,0 с пометкой в `meta.json`).
  3. Каждые `--period`: сим `ProcessManager state.get sim.objects` → новые `object_id` дописываются в `<out-dir>/sim_objects.jsonl` как `{"object_id":…, "class_name":…, "angle_deg":…, "lateral_px":…, "t":"YYYY-MM-DD HH:MM:SS,mmm"}` (паспорт один раз на `object_id`); `robot sim_robot.journal` → строки `{t, side, text}` в `<out-dir>/sim_journal.jsonl` без повторов по `(t, side, text)`; `t` — наивное локальное время сборщика в том же формате, что логи прототипа.
  4. Ошибка одного опроса не останавливает сбор: строка в `<out-dir>/collect.log` (без значений аргументов), счётчик пропусков в `meta.json` при выходе (`polls`, `errors`, `objects`, `journal_lines`). Недоступный порт на старте — код 3.
  5. Файлы пишутся построчно с `flush` после каждой записи (Ctrl-C не теряет данные).
