## 1. Luna Line (VisionLabs)

### Компания

- ООО «ВижнЛабс», Москва, основана в 2012 г. Известна распознаванием лиц (семейство LUNA: PLATFORM, SCANNER, CARS, ID, PASS, KIOSK). <https://visionlabs.ru/products>
- С 13.12.2021 принадлежит МТС (через «Интему», дочку МТС AI), сделка ≈ 7 млрд руб. Продавцы: основатели 51,77%, Сбер 25,07%, Sistema_VC 23,16%. <https://incrussia.ru/news/mts-visionlabs/>
- Самореклама на главной (не проверено): 13 лет на рынке, 270 клиентов, 500 проектов, 1,7 млн камер, 38 стран. <https://visionlabs.ru/>
- Клиентов поимённо не нашли.

### Продукт

- Анонс: июнь 2025 (дата уточняется: 11.06 или 16.06). No-code веб-платформа для обучения и запуска CV/VLM-моделей: классификация, детекция, сегментация на фото и видео. <https://ict.moscow/news/visionlabs-razrabotala-no-code-platformu-luna-line-dlia-sozdaniia-ml-modelei/>
- Порог входа: от 50 размеченных изображений; первая версия модели за 2–3 дня вместо 4–6 месяцев; авторазметка. Заявлено сокращение сроков и стоимости на 20–30%.
- Отрасли: безопасность, логистика и транспорт, медицина, промышленный контроль качества, экология, медиа. <https://docs.visionlabs.ru/luna-line/0.1.0/quick-start/general/>
- Проверяли на: дефектах в металлургии, разбитых стёклах на остановках, нанесении VIN.
- Архитектура (Хабр, МТС AI): ClearML для обучения, Triton для инференса, мультимодельные пайплайны. Классификация: RegNetY при датасете < 5000, ConvNeXt при > 5000. Лимит 10 ГБ VRAM при обучении. <https://habr.com/ru/companies/mts_ai/articles/1049438/>
- Развёртывание: облако или свои серверы.
- Требования к серверу: Docker ≥ 20, CUDA ≥ 12.4, драйвер ≥ 550.144.03, CPU ≥ 8 ядер, GPU Tesla T4 или аналог, RAM ≥ 64 ГБ, диск ≥ 128 ГБ. <https://docs.visionlabs.ru/luna-line/0.1.0/admin/requirements/>
- Цены и лицензирование: не найдены.

### Чего публично нет

Интеграция с PLC/АСУ ТП (Modbus, OPC UA), список камер и протоколов (кроме упоминания CCTV и смартфонов), подсчёт объектов, инспекция бутылок и упаковки, визуальный редактор пайплайнов, дашборды. Отсутствие в публичных источниках не доказывает отсутствие в продукте.

### Оговорки к источникам

- Сайт lunaline.visionlabs.ru отдал только `<title>` (похоже на JS-приложение), тело не прочитано.
- Часть страниц документации описывает другой продукт (LUNA Access), вероятно копипаст. Доверяем тем, что совпадают с прессой.

## 2. VisoNode и VisoLabel (Pysource)

### Компания

- Pysource: «computer vision platform company», заявлено 2017 г., 400+ клиентов, обучение 75 000+ инженеров. Автор — Sergio Canu, консультант и преподаватель. Юрисдикция — Болгария. <https://pysource.com>
- По сути обучающий бренд с консалтингом, выросший в продукты. Платные курсы (AI Vision Academy).
- YouTube-канал: около 75 тыс. подписчиков (из сниппета поиска, не проверено).

### VisoLabel

- Локальное приложение для разметки и обучения. Авторазметка: SAM2 (интерактивно), SAM3 (пакетно). Обучение RF-DETR (детекция, сегментация, классификация). <https://pysource.com/docs/faq>
- Импорт: COCO, YOLO, Pascal VOC. Экспорт датасетов: YOLO, COCO, Pascal VOC. Экспорт моделей: `.pt`, ONNX, TensorRT. <https://pysource.com/docs/export-deploy>
- Free: разметка и экспорт датасетов, только некоммерческое использование; обучение только платно. Pro: $29/мес, 1 пользователь, до 3 компьютеров. <https://pysource.com/pricing/>
- Требования: RAM 8 ГБ (рек. 16), диск 5 ГБ (рек. 20+), GPU опционален (рек. NVIDIA 8+ ГБ VRAM для обучения). <https://pysource.com/docs/installation>

### VisoNode (коммерческий сайт)

- «No-code visual computer vision automation platform». Входы: IP Camera, Video File, RTSP, Image Folder. ИИ: Object Detection, Classifier, Tracker, Counter. Логика: Filter, Condition. Выходы: REST, Alert, live display, recording, database, API. <https://pysource.com/visonode/>
- Развёртывание: локально, on-prem, edge, «compatible cloud».
- Pro: $49/мес (beta-цена), включает VisoLabel Pro; 1 пользователь, 2 компьютера (1 production + 1 test); одна площадка. Enterprise по запросу (multi-user, multi-site, offline, кастомные интеграции). Триал 14 дней. <https://pysource.com/pricing/>
- Pro требует периодической онлайн-проверки лицензии; Enterprise может работать офлайн.
- Ссылки на скачивание на дату проверки помечены «Not available for download» (возможно, артефакт рендера).
- Документации по VisoNode нет, docs целиком про VisoLabel.
- PLC, Modbus, OPC UA, MQTT нигде не упомянуты. В блоге есть лишь общая фраза про интеграцию с PLC/CRM для остановки конвейера.

### VisoNode (публичный репозиторий)

<https://github.com/pysource-com/VisoNode> — AGPL-3.0, первый коммит 21.05.2026, 29 коммитов, 61 звезда.

**Проверено по коду (клон в scratchpad, 2026-09-30):**

- Около 3300 строк Python (`main.py` 1347, `app.py` 1648, `core.py` 330) плюс веб-UI (`web/`) на ~2400 строк.
- **Не граф-движок.** Узлы захардкожены по id: `detector`, `segmenter`, `classifier`, `filter`, `preview`, `alert`. Каждого типа по одному. Рёбра нужны только для проверки достижимости от входа (`has_active_path`, BFS, `main.py:555`). Данные по рёбрам не текут: детекции собираются в общий список и фильтруются по достижимости.
- Один поток на весь workflow (`Thread(target=self._run)`): читать кадр → прогнать все модели подряд → нарисовать → отправить. Нет очередей, разделяемой памяти, процессов, воркер-пулов.
- **Alert** — только текст и cooldown (`main.py:1189–1200`). Grep по `modbus|serial|socket|mqtt|opc|plc|webhook` — пусто.
- Нет рецептов, реестров, телеметрии, истории, управления живым процессом. Workflow — один JSON.
- Логика цикла `WorkflowRunner` продублирована в `main.py` и `core.py` (~200 строк). Кодовая база из двух половин: сначала браузерный UI на HTTP-сервере, поверх него PySide6-версия.
- Зависимости тяжёлые: ultralytics, rfdetr, SAM3 из git Facebook, triton-windows. ONNX/TensorRT-узлы в roadmap.
- Node-редактор на `QGraphicsView`: `NodeItem`, `EdgeItem`, `NodeEditor` ≈ 550 строк (`app.py:349–917`).
- `REQUESTED_FEATURES.md`: единственная запись — монитор как источник.

**Лицензионное предупреждение:** AGPL-3.0. Копировать код оттуда в наш проект нельзя. Идеи и общая схема свободны.

### Оговорки

- Не знаем, совпадает ли платный VisoNode с публичным репозиторием: сайт перечисляет Tracker, Counter, RTSP, REST, database, а в репозитории они только в roadmap.
- Приложение не запускали, `web/app.js` не читали.
- Независимых отзывов не нашли (поиск ограничен, YouTube не открылся).

## 4. Выводы (гипотезы)

**Где мы можем быть лучше:**
1. Промышленный runtime: Modbus, реестры, рецепты, состояние, изоляция процессов.
2. Наблюдаемость и управление живым бэкендом (telemetry, backend_ctl, логирование).
3. Надёжность: многопроцессность, настоящий DAG, воркер-пулы.
4. Офлайн и on-prem без онлайн-проверки лицензии.

**Где мы, вероятно, отстаём:**
1. Цикл разметка → обучение → экспорт (SAM-авторазметка, обучение прямо в приложении).
2. Простота входа: «50 фото и модель за день», выбор модели одним списком.
3. Готовые типы узлов: трекер, счётчик, классификатор как блоки редактора.

Оба пункта про «отстаём» требуют проверки по коду репозитория: в этом документе они основаны на описании проекта в CLAUDE.md.

## 5. Что осталось открытым

- Матрица возможностей по коду нашего репозитория не составлялась (предложено, не выполнено).
- Платную сборку VisoNode и Luna Line не видели: только публичные страницы и репозиторий.
- Цены и требования брали из пересказа страниц малой моделью; при решениях, зависящих от чисел, сверить по первоисточникам.
- Возможные PLC-интеграции у обоих вендоров вне проверенных страниц (Enterprise «custom integrations» у Pysource) не исключены.
