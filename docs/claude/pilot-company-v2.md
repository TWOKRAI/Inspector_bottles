## Наблюдения по ходу

- **2026-10-01, обрыв по лимиту (HTTP 429).** Оба слепых тестера (4.7d-1, 4.7d-4) оборвались на 8–9 вызовах,
  ~100k токенов каждый, файлов не записали. После обрыва имя агента недоступно (`SendMessage` по имени: «No agent named
  … is reachable»), дозов прошёл только по agentId. Для «живущего весь трек» агента лид хранит agentId рядом с именем.
- **2026-10-02, имена не живут:** `know-transport` завершился штатно накануне — по имени тоже «not reachable», по
  agentId дозов прошёл. Имя адресует агента только в пределах его «жизни» в движке; адрес личности на трек — agentId.
- **Долгоживущий знаток держит устаревшую спеку.** На дозове (сверка карты после 4.7b) `know-transport` назвал
  «конфликтами со спекой» два пункта, которых в спеке уже нет (typed-поле убрано, валидация портов вписана в шаг 5) —
  он помнит редакцию, прочитанную в первой задаче. Сам код сверил верно. Вывод: на дозове знатоку давать SHA спеки и
  велеть перечитать раздел, а не полагаться на память.
- Хук `lint-brief` требует DESIGN/FILES/REDS и у слепого тестера; DESIGN тестера = устройство тестов (не реализации),
  REDS = `n/a — выход тестера`. Обход `BRIEF-OVERRIDE` не понадобился.

- Красные на main, не наши (нашёл reviewer-47d4): `test_catalog_kind_roundtrip.py:67` пинит 417 полей, на `d60bd59ad`
  уже 448 (4.7d-4 делает 449); `registers_module/tests/test_field_info_codec_*` ×4 (пустой discover в общем прогоне +
  `\tmp\x` против `/tmp/x` на Windows). Владельцу — в итоговый отчёт.
- Свежий ревьюер дешевле не стал (139k, 168k), зато оба раза нашёл то, чего не видели автор и слепой тестер: страж
  дрейфа в прототипе (вне радиуса автора) и неразличимость маркера в широкой записи (тест с поддельным `_Ctx`).
