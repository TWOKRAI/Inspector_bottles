## Вывод (лид, 2026-10-02)

Итого по треку ≈ 163k (тестер) + 199k (ревью спеки) + 130k + 17k (developer) + 209k + 15k (teamlead) + дозовы тестера и ревьюера.

**Где дозов окупился.** Каждый дозов стоил +7…48k против 120–210k у свежего агента: ревьюер прошёл 4 захода (спека → 1b.2d-1 → 1b.2d-2 → ит.2) одним контекстом,
и на каждом заходе знание предыдущего работало — на ит.2 он сам вспомнил свой repro и проверил его прогоном за 5 вызовов. Teamlead дозвался после 429 посреди
работы без потерь: код лежал незакоммиченным, но дозов с явным списком «что сделано / что осталось» продолжил с места.

**Где общий контекст навредил.** Явного вреда не замечено. Риск — ревьюер, ревьюивший спеку, ревьюит и код по этой спеке: он не перепроверяет собственные
спековые решения (например, принятый дрейф регулярки он сам и предложил). Контрмера здесь сработала частично — инъекции лида независимы от ревьюера.

**Ревью спеки до кода окупилось сильнее всего:** 3 блокера (атомарность через `model_validate` ломала otel целиком; утечка секрета; двусмысленность `list[dict]`)
закрыты правкой текста, а не итерациями кода. Сравнение: в 5.3 layer-render ошибка спеки стоила 3 итерации ревью кода.

**Сбой процесса:** тестер запущен ДО ревью спеки (образец v3 ставит ревью спеки первым). Обошлось — его тесты описывали поведение, не механизм, и ревьюер
признал их без неверной модели; но 3 недостающих RED (откат update_field, cmd_set_config, утечка) пришлось дозаказывать отдельным дозовом.
