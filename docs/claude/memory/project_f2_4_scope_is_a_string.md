Ф2.4 (`d8ab81b5`, 2026-08-04, ветка `feat/observability-unified-routing`): `LogScope`
из `Enum` → строковые константы + `PRESET_SCOPES` (дефолты, НЕ whitelist — валидация
по ним отменила бы задачу). Одно написание вместо двух (`perf`/`PERFORMANCE`);
регистр приводится на ОБЕИХ границах конфига — `LoggerManagerConfig` и
`ObservabilityConfig`, потому что слои мержатся между собой до менеджера.

**Остаток фазы 2:** 2.5 (группы-ярлыки) → 2.3b (`default_level` корневым правилом,
была заблокирована до 2.4/2.5) → 2.7 (объявление источников рядом с модулем +
громкий конфликт двух объявлений на префикс — долг из 2.6).

**Пробелы 2.4:**
- живьём детектор незаявленной группы показан ТОЛЬКО молчащим: писателя в
  незаявленную группу в системе нет (`AUDIT`/`SECURITY` в проде не зовут);
- ось «группа» до GUI/стора не доезжает — в `observability.db` колонки `scope` нет
  вовсе, запись хранится по `kind`/`severity`. Именно поэтому смена написания была
  безопасной, и именно поэтому фильтровать логи по группе с пульта пока нечем;
- бенч ключа кэша сторожит слабо: замер дал ПАРИТЕТ (53 против 52 нс), а при таком
  запасе узкий допуск ловит шум (флейк 1 из 5 при 1.10) — расширен до 1.5, реальный
  страж нормализации не он, а тест со строкой-шпионом.

**Why:** без этих трёх оговорок 2.4 читается как полностью доказанная, а две её
гарантии держатся на тестах, а не на живом стенде.

**How to apply:** при первом же появлении прикладной группы со своим писателем —
показать детектор красным живьём. Родня: [[project_observability_config_layers]],
[[feedback_signal_placed_in_a_branch_goes_blind]].
