Закрытый publisher-гейт телеметрии (`enabled=False` на всех метриках каталога) **не даёт нуля
IPC-сообщений**: `status` воркеров публикуется мимо гейта (always-on, ADR-PM-018), и тик
по-прежнему шлёт один `proxy.merge` на `processes.<name>` каждый такт — с одними статусами и без
единого числа. Обнуляется другое — **дельты** `state.changed`: `TreeStore.set` возвращает `None`
на неизменившемся значении, поэтому `merge` тем же статусом дельт не порождает.

Воспроизведено 2026-08-14 (Task 3.2 `telemetry-stage6`): гейт закрыт на всех пяти метриках,
2 тика → 2 merge'а по `processes.camera_0`; `TreeStore` тем же `{"w0":{"status":"running"}}`
→ 1 дельта, затем 0, 0; смена на `stopped` → снова 1.

**Why:** критерий приёмки был сформулирован как «ноль push-трафика». Померь IPC-сообщения —
получишь ненулевое число и прочитаешь рабочую фичу как несработавшую; померь дельты — увидишь
ровно то свойство, ради которого заводился опрос. Полное обнуление сообщений потребовало бы
вынести `status` из тика, то есть тронуть инвариант фронтов.

**How to apply:** формулируя и проверяя «ноль трафика» у любого гейта с always-on полями,
называть ЕДИНИЦУ счёта: дельты по конкретным путям, а не сообщения и не вызовы публикатора.
Тот же разбор — ADR-PM-035. Связано: [[telemetry-publisher-gate]],
[[feedback_read_timestamp_is_not_data_freshness]].
