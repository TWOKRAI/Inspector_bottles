Тест `test_plugin_subtree_history_hazards.py` в `finally` звал
`forget_declarations("metric", names={"fps"})` — снимал имя, которое объявляет
**фреймворк** импортом (`heartbeat/telemetry.py:39`), а не своё. После Ф1 «порта
наблюдений» повторное объявление метрики стало идемпотентным no-op, поэтому тест
в каталог ничего не добавлял и только **разрушал** его до конца процесса.
Красил соседа в прототипе (`test_rt2_config_flip_acceptance`): `assert {'fps',
'latency_ms'} <= gated_metrics()` → `Extra items in the left set: 'fps'`.

Найдено фазовым ревью Ф1, 2026-08-20.

**Why:** нарушитель лежит в `testpaths` фреймворкового гейта, жертва — корневого.
`python scripts/run_framework_tests.py` → 8640 passed. `python -m pytest` →
7031 passed. Красное существует только в **совмещённом** прогоне, которого не
делает никто. Такая база потом молча искажает любую матрицу инъекций поверх неё:
один и тот же тест числится красным во всех прогонах и его приходится вычитать
руками, а если не заметить — счёт красных врёт на каждой строке.

**How to apply:**
- Правило владения: **уборка снимает только своё**. Узор из репозитория —
  `before = set(declared_metrics())` … `forget_declarations(KIND_METRIC,
  names=set(declared_metrics()) - before)` (`test_writer_subtree_hazards.py:82`).
  Безусловный `names={"имя"}` в `finally` — дефект по построению, даже когда имя
  сегодня «своё»: завтра его объявит импорт.
- Перед матрицей инъекций **сначала снять базу тем же охватом**, каким пойдут
  инъекции, а не поверить двум зелёным гейтам. Красная база — стоп, см.
  [[feedback-inject-only-after-the-work-is-committed]].
- Любой процесс-глобальный реестр (каталог метрик, реестр объявлений, синглтон
  конфига) — общая земля между наборами тестов. Тест, который его правит,
  обязан быть подозреваемым номер один при «зелено поодиночке, красно вместе».
- Смежное: [[feedback-project-root-gate-misses-framework-modules]] — там гейты
  расходятся по ОХВАТУ, здесь по СОСЕДСТВУ; симптом одинаковый.
