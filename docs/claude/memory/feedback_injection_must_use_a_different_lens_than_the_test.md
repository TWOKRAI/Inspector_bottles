Инъекция обязана смотреть **другим объективом**, чем тест, которому она адресована. Совпали
объективы — красный доказывает лишь, что тест и инъекция согласны между собой, а не что свойство
есть.

Измерено на Task 3.5 `telemetry-stage6` (2026-08-17). Заявленное свойство П6: «уровень
остановленного плагина исчезает». Тест П6 судил **payload тика** (`_apply_merges` собирал дерево
только из merge, отправленных ПОСЛЕ остановки). Моя инъекция «убрать вызов `retract`» тоже судила
payload. Оба зелены, свойство держится — и оба слепы к тому, что **лист в дереве живёт вечно**:
`retract` снимает публикацию, а `state.delete` в модуле нет вовсе (0 совпадений грепом), хотя
докстринг ссылался на прецедент `throttle.prune при state.delete`. Нашёл ревьюер, потому что
посмотрел на ДЕРЕВО, а не на payload.

Второй случай той же сессии, обратной полярности: инъекция И1 («владение → назад на членство в
каталоге») оставила зелёными **три** теста, якобы сторожившие владение. Они сторожили имя
ФРЕЙМВОРКА, а его в дереве защищал fail-safe порядок сборки, не владение. Проверено потом
инъекцией ревьюера с пятью случаями: порядок страхует **1 из 5**, и только когда агрегат есть на
том же тике.

**Why:** «тест зелёный, инъекция краснит» читается как доказательство, но доказывает только
внутреннюю согласованность, если оба смотрят в одну точку наблюдения. Дефект живёт там, куда не
смотрит ни один из них.

**How to apply:** перед инъекцией назвать вслух **точку наблюдения** теста (payload / дерево /
опрос / лог / БД) и выбрать для инъекции ДРУГУЮ из того же тракта. Если для свойства доступна
только одна точка — сказать это в отчёте: свойство проверено частично. Ноль красных там, где
ожидались красные, и полный набор зелёных при выключенном механизме — оба симптома одного класса:
объектив не туда. См. [[feedback_prove_test_red_without_fix]],
[[feedback_three_lenses_three_defect_classes]], [[feedback_silent_detector_proves_nothing]].
