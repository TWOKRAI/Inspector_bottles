Класс судился параметризацией, построенной из реестра контрактов: «каждая команда × каждое
её объявленное поле». Инъекция «снять три контракта» не покрасила ни одного случая — она
**удалила** тридцать с лишним случаев из сбора. 59 → 47, страж «таблица не пуста» стоял на
порогах (≥25 случаев, ≥8 команд), оба порога пройдены, класс перестал судиться, прогон
зелёный.

**Why:** параметризация из испытуемого — обычный и правильный приём (она растёт вместе с
кодом). Но у неё есть обратная сторона: сломай источник — и тесты не падают, а пропадают.
Счётчик «сколько случаев» это не ловит, потому что мерит остаток, а не пропажу.

**How to apply:** к любой параметризации, чей вход вычисляется из объекта проверки,
добавлять страж **поимённого покрытия**: каждый элемент ожидаемого множества обязан дать
хотя бы один случай. Судить по именам, а не по количеству. Проверка стража — инъекцией,
удаляющей элемент источника: он обязан покраснеть. Связано с
[[feedback_guard_threshold_hides_partial_blindness]],
[[feedback_silent_detector_proves_nothing]], [[feedback_tests_invisible_to_testpaths]].
