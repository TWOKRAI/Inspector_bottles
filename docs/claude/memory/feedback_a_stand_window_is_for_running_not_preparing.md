**Ловушка.** Лид отдаёт субагенту стенд целиком — «подготовь и прогони к 15:41» — и следит за сроком через сам бриф.

**Замер (T5.3h, 2026-10-21, два окна подряд).**
- Окно 1 (15:23–15:43): агент 17 мин читал README, писал скрипт симулятора, копию рецепта. Вход: окно 20 мин. Выход: 0 замеров, ничего не запущено.
- Окно 2 (16:07–16:24), подготовка уже сделана вне окна: агент работал 2036 с — 34 мин, `system_shutdown` в 16:41. Перерасход 17 мин, очередь соседней полосы сдвинута. Агент списал это на «прыжок часов 16:15 → 16:41». Ложь не по злу: один вызов висел долго, а срок он проверял только `date` между вызовами. Длительность агента в уведомлении (`duration_ms`) совпала с реальными часами.
- Во втором окне ещё и сценарий не попал в цель. Две команды ушли в одну миллисекунду, супервизор обработал disconnect раньше connect, и «посреди connect» не случилось ни разу. Сухой прогон без бэкенда этого не показал бы, но порядок «connect, затем disconnect через N мс» можно было заложить в скрипт заранее.

- C-42 (2026-10-26, окно 14:08–14:29): стенд из worktree — в дереве нет gitignored `.venv` и `data/line_sim`
  (`belt_tile.png`, `letters_ink`); сцена сима не собралась, диски пошли за 30 с до стопа. Вход: окно 21 мин.
  Выход: 0 замеров. Следующее окно с готовым окружением — S1 снят за 12 мин.

- T5.3e (2026-10-27, окно stand 20:31–20:48): после живых тестов — `pytest Services Plugins` одной командой без
  потолка. Вход: окно 17 мин. Выход: 22 мин без итога, окно просрочено на 9 мин, напомнил координатор. Повтор по
  частям с `-v` и `timeout`: device_hub 6 мин, robot_comm 2 мин; Plugins и фреймворк упёрлись в потолок на тестах,
  которые по одному зелёные за 5–13 с. `timeout` убил bash гейта, а дерево python (7 процессов) осталось жить.

**Правило.**
1. До запроса окна сделать вне окна: в worktree — junction `.venv` и копия gitignored `data/` нужных приложений; собрать рецепт без запуска, проверить симулятор, взять команды из кода, написать runbook. Окно просить, только когда непроверенным остался один запуск.
2. Срок держит лид, не субагент. Каждая команда стенда идёт с явным `timeout`, гонка — одним скриптом со своим дедлайном. Гашение (`system_shutdown`, симулятор по PID) — отдельный шаг с запасом 3–5 мин до конца окна. Suite — по частям, каждая с `-v` и потолком; после потолка дерево python гасить по PID (`taskkill //PID <pid> //T //F`): `timeout` его не убивает.
3. Объяснение агента про «часы» сверять с `duration_ms` из уведомления. Если цифры сходятся, перерасход реальный.
4. В сценарии гонки порядок задаётся явно (задержка второй команды, задержка ответа симулятора). «Две команды одновременно» порядок не задают.

**Триггер:** бриф субагенту на живой стенд; запрос окна stand у координатора.
