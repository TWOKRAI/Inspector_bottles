Приёмка F2 раунда 3 судила мерило 4 только по `backend_ctl/tests` (598/44 ×3), а «полный гейт»
взяла из отчёта исполнителя; шесть хвостовых коммитов раунда 2 легли после последнего прогона
корневого гейта — сутки на HEAD жил 21 красный, пойманный стражами, но не запуском (2026-08-12,
HR-1/HR-3 жёсткого ревью).

**Why:** «N passed ×3» — свойство конкретного HEAD; каждый следующий коммит делает подпись
описанием состояния, которого больше нет. Сужение мерила до одного каталога открывает щель ровно
там, где стражи уже стоят и ждут запуска.

**How to apply:** перед закрытием этапа/раунда — полный корневой гейт на итоговом HEAD; коммит
после подписи = пере-прогон; в программе приёмки мерило «сетка не врёт» покрывает все прогонщики,
а не один каталог. Правило внесено в «Правила исполнения» `plans/observability-roadmap.md`.
Связано: [[observability-tail-repair]].
