Диагностическое поле ответа считать **последней строкой ленты применений**, а не там, где
удобно по коду. Иначе ответ судит по состоянию ДО стадий, которые эта же команда ещё выполнит.

**Замер (Task 3.0a, 2026-09-04, `config.reload`).** Отчёт `capped_by_throttle` считался внутри
`apply_observation_policy`, то есть выше стадий такта и телеметрии. Два ОДИНАКОВЫХ вызова подряд:

```
троттл {'processes.*.state.plugins.**': 0.5}, такт 1.0
reload#1 {"heartbeat_interval_sec": 0.2} -> caps={}                      # «потолков нет» — ЛОЖЬ
reload#2 тот же вход                     -> {'…plugins.**': {0.2, 0.5}}  # потолок был уже в #1
```

и то же по вееру «не судил»: `heartbeat_interval_sec: 0` в первом ответе не даёт ключа
`capped_by_throttle_unjudged` вовсе, во втором даёт. Живьём на стенде: первый вызов вернул
`heartbeat_interval_applied: 0.0` и отчёт, посчитанный по СТАРОМУ такту 5.0.

**Ловушка глубже, чем «перенести под стадию такта».** Эффективный такт — `min(heartbeat_interval,
tick_sec)`, и вторую половину правит ТЕЛЕМЕТРИЙНАЯ стадия, стоящая ниже стадии такта: перенос
только под heartbeat оставляет третью грань (вход `telemetry.publish.tick_sec` даёт ту же ложь),
и инъекция «перенести только под такт» краснит ровно один сторож. Считать надо после ВСЕХ стадий,
которые правят вход отчёта.

**Почему не переставлять сами стадии применения:** соседний голос (`_warn_capped_metrics` внутри
`reconfigure_telemetry`) считает по живой политике, и перестановка заставила бы его говорить по
политике прошлой правки. Переезжает ОТЧЁТ, а не применение.

**Why:** «повтор команды даёт тот же ответ» — не эстетика, а различие между «потолков нет» и
«я посмотрел раньше, чем ты изменил». Первый ответ читают как факт.

**How to apply:** трогая поле диагностики в многостадийной команде — сначала выписать ленту стадий
и спросить, какие из них правят ВХОД этого поля; сторож обязателен и формулируется как
«два одинаковых вызова подряд дают одинаковый ответ», литералами. Связано с
[[feedback_checked_true_answers_for_the_call_not_the_coverage]] и
[[feedback_zero_observations_looks_like_a_result]].
