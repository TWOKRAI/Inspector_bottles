**Замер 2026-10-20, T5.3d2, стадия 0 Opus.** Живой RED 16 считал записи `STOP_REQ` у робота в jog при выключении.
Чтобы допустить законную гонку (поводок пишет свой SOFT до стопа выключения), лид сменил критерий на
`d1 - L1 == 1`, где `L1` — строки «jog остановлен поводком: окно удержания истекло». Регресс, который тест стережёт
(B1: поток поводка переживает выключение и пишет второй стоп), тоже истекает окном и пишет ту же строку →
`d1 = 2, L1 = 1` — зелёный на регрессе. Плюс `d1 - L1 == 1` краснел на верном коде при гонке защёлки (`d1 = 1, L1 = 1`).
Вторая ловушка там же: строка после `_stop_jog` писалась и тогда, когда стоп записал соседний поток (`stop_sent`).

**Правка:** сигнал несёт состояние, отличающее законный путь от регрессного (`late = self._stopping` в момент решения →
строка «после начала остановки»), критерий `A1 == 0` (детерминированно красный под откатом B1, проверено инъекцией);
строка только если этот поток сам записал (`wrote = not run.stop_sent` под тем же замком).

**Триггер:** оракул вычитает самоотчёт кода (лог, счётчик) из наблюдаемого числа — проверить, что регрессный путь не
может выдать тот же самоотчёт; лог «я сделал X» после вызова, который может пропустить X, — сперва узнать, сделал ли.
См. [[feedback-a-sampling-watcher-misses-a-fast-overwrite]].
