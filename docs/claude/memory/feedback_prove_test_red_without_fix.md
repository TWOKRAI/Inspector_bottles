Требование владельца 2026-07-26: «покрывай честными и полезными тестами всегда **и проверяй**».

Зелёный тест на зелёном коде не доказывает ничего — он может быть тавтологией, проверять не тот путь, или молча зеленеть по ложной причине (файл не создан, дочерний процесс упал раньше, сработал другой триггер).

**Приём (Ф0.1, `792e72a5`):** после написания тестов временно откатить **только call-site** правки через `git stash push -- <файлы>` (helper/константы оставить, иначе тесты падают на импорте, а не по существу) → прогнать → убедиться, что упали **ровно ожидаемые** тесты и **не упали** регресс-стражи противоположного поведения → `git stash pop` → снова зелено. Число упавших сверять арифметически с числом тестов на новое поведение.

Для пар «болезнь → исчезла» болезнь фиксируется **в самом suite навсегда**, а не только stash'ем: дочерний процесс/фикстура подменяет прод-функцию на до-фиксное поведение. Флаг в проде для этого заводить нельзя — см. [[flags-must-not-become-crutches]].

**Why:** проект уже ловил «26 зелёных тестов на моке при мёртвой фиче» и «образцовый тест сам лгал дважды». Красный-без-правки — единственная дешёвая проверка, что тест сцеплен с механизмом.

**How to apply:** перед тем как отдавать задачу в ревью — прогнать откат call-site. Если ни один тест не покраснел, тестов на эту задачу нет, сколько бы их ни было написано. Связано: [[plausible-is-not-verified]], [[single-marker-verdict-lies]], [[check-red-on-main-first]].
