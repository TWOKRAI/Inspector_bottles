Владелец (2026-10-16), стенд `qr_reader_sdk_dual_demo`, два дисплея сверху главного окна, вкладки снизу: «баг при масштабировании картинки при изменении вкладки. Картинка меняет качество. Так не должно быть. ЭТО запомни».

**Что наблюдали (3 скриншота).** Область дисплеев при смене вкладки сжималась (~480 → ~175 px по высоте), кадр уменьшался. После возврата на прежнюю вкладку размер вернулся, но кадр стал заметно грубее: ступеньки и блоки на краях, которых до смены не было.

**Условие.** Оба источника — считыватели по триггеру: после срабатывания новых кадров нет, ресайз перерисовывает СТАТИЧНЫЙ последний кадр. Для непрерывного потока дефект маскируется: следующий кадр приходит и заменяет испорченный.

**Требование владельца (постоянное).** Любой ресайз дисплея, включая туда-обратно, не меняет качество показанного кадра: масштабируется ИСХОДНЫЙ кадр, а не уже уменьшенная копия. Это свойство дисплея как механизма конструктора, а не рецепта.

**Причина (доказана 2026-10-16, код прочитан лидером, воспроизведено offscreen).** `DisplaySlot.resizeEvent` (`image_panel/display_slot.py:58-68`) масштабирует `self._label.pixmap()` — уже уменьшенную копию; исходный pixmap после `update_pixmap` (`:39-46`) нигде не хранится. Вниз 700×560 → 300×240, обратно растягивается именно эта копия. Гипотеза про `FastTransformation` отвергнута: везде `SmoothTransformation`.

**Замер (кадр 1280×1024 с мелкой деталью, эталон — свежее масштабирование из исходника).** После кадра: MAD 0.00. После сжатия: MAD 2.82, PSNR 31.9 дБ. После возврата: MAD 28.92, PSNR 14.1 дБ. После ещё 3 циклов: MAD 32.76, PSNR 13.5 дБ — каждый цикл портит дальше. Контроль со слотом, хранящим исходный pixmap: MAD 0.00 на всех шагах.

**Дисплеи главного окна — `ImagePanelWidget`/`DisplaySlot`, не `PreviewWindow`.** Поля дисплея `fit` и `scale` из рецепта к ним не применяются: слот всегда `KeepAspectRatio`.

**Статус (2026-10-16): исправлено в рабочем дереве, не закоммичено, на живом стенде не проверено.** `DisplaySlot` хранит `_source_pixmap`, общий `_show_scaled()` масштабирует из него; пустой pixmap = `clear()`. Тесты `image_panel/tests/test_display_slot_resize.py` (12), соседи 122 passed; матрица из 7 инъекций совпала с предсказаниями. Тот же дефект остался в `widgets/camera/view.py:44-54` (`CameraView`, боевых вызовов нет — заморожен, не удалять). Цена фикса: слот держит один полноразмерный pixmap (~20 МБ на слот на кадр 5 Мп). HiDPI не проверялся.

**How to apply.** Чинят в `multiprocess_prototype/frontend/widgets/image_panel/display_slot.py`: хранить исходный pixmap, `resizeEvent` масштабирует его; `set_placeholder`/`clear` сбрасывают поле (иначе после «Нет сигнала» ресайз вернёт старый кадр). Тест — кадр фиксированного содержимого, сжать и вернуть панель, сравнить с исходником числом, ожидание MAD == 0 (не «выглядит нормально»); сегодня тестов на resize нет. Проверять на источнике по триггеру, не на потоке. См. [[feedback_a_source_frame_shape_must_not_crash_the_display]].
