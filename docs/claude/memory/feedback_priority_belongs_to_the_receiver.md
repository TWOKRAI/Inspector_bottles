Если приёмник применяет команды **последовательно поверх живого состояния** (last-write-wins,
merge поверх текущего эффективного) — у него **нет модели уровней**, и отправитель не имеет права
доигрывать «по приоритету слоёв». Единственный приоритет там — порядок приёма. Доигрывать надо
**порядок записи**, то есть ту же последовательность, что применил бы выживший.

**Как кусалось (3.4 telemetry-stage6, 2026-08-16).** Я вписал в спеку «лестницу файл → глобальная
дельта → адресная дельта» по аналогии со слоями L0–L3. У `ProcessHeartbeat.reconfigure_telemetry`
слоёв нет. Реализация честно исполнила спеку, и получился **зеркальный** дефект тому, который
чинили: оператор правит ребёнку точечно, затем делает общий проход по системе → respawn возвращает
старое значение, молча.

```
оператор: адресно lines fps=7.0 → фан-аутом fps=20.0
выживший 20.0 · пересозданный 7.0
```

Ни 806 тестов, ни 8 инъекций не увидели: во всех сценариях адресная правка стояла последней —
фиксированный порядок случайно совпал с временным. Нашло ревью запуском.

Вторая моя правка («монотонный номер поверх двух уровней») тоже неверна: накопление **по уровню**
схлопывает историю через голову чужой записи. Верное — **один журнал** правок, ребёнку уезжает
его срез в порядке записи.

**Why:** «уровни» — модель отправителя. Пока приёмник о них не знает, любая расстановка
приоритетов на стороне отправителя верна лишь при случайном совпадении с хронологией.

**How to apply:** прежде чем вводить приоритет уровней — **прочитать приёмник**. Есть у него
модель слоёв? Нет → хранить журнал и воспроизводить порядок. Приёмка формулируется как
**эквивалентность с выжившим соседом**, параметризованная ОБОИМИ порядками; последовательность,
где узкая правка стоит последней, доказывает половину контракта.

И отдельно: **рекомендация в плане — гипотеза, а не задание.** Исполнитель обязан опровергать её
воспроизведением, а не исполнять по авторитету. В этой задаче teamlead отверг мою правку дважды,
оба раза числами, и оба раза был прав. Отвергнутую рекомендацию оставлять в плане, а не стирать.
