Ф8.7, живой прогон `inspection_full` 2026-08-09. Рецепт объявлял провод
`processor.blob_detector.detections → inspector.robot_control.detections`, но у процесса
`processor` в `chain_targets` инспектора НЕ БЫЛО. Порты и процессы — две независимые оси:
провод описывает, какой порт чем питается, `chain_targets` — куда процесс вообще
отправляет item. Инспектор ждал коллекцию из двух портов, она не собиралась никогда, и
`RobotControlPlugin.process` не вызывался **ни разу**.

Симптом снаружи: `total_inspected=0` при `received=1772` и `hz=21` — то есть процесс жив,
данные принимает, статус `running`, аномалий нет. **Ни одной строки в журнале.**
Валидация `SystemBlueprint.check()` этого не ловит: провода корректны сами по себе.

Починка в рецепте: оба входа инспектора от ОДНОГО отправителя (детектор даёт кадр и
детекции в одном item), renderer переведён на дорогу показа.

**Why:** «процесс running, очереди пустые, ошибок нет» читается как «работает», а плагин
при этом не исполнялся ни разу — класс «проглоченный сбой» на уровне топологии.

**How to apply:** при живой проверке плагина сверять его СОБСТВЕННЫЙ счётчик вызовов
(`get_stats`), а не router-счётчики процесса. Заводя провод портов между разными
процессами — проверить, что у процесса-источника адресат есть в `chain_targets`.
См. [[feedback_swallowed_failure_class]], [[feedback_single_marker_verdict_lies]].
