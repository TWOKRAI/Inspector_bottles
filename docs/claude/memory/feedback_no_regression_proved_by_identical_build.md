Когда правка не должна была задеть соседний режим, доказывай это **идентичностью
сборки**, а не похожестью чисел двух живых прогонов.

Найдено в D8 (2026-08-10). Приёмка требовала «режим с презентацией не деградировал».
Живой прогон GUI дал ненулевые отказы доставки (`lines` 22, `points` 22, `seg` 21 за
60 с) — по числам не отличить «мой регресс» от «так было всегда», потому что величина
плавает от загрузки машины. Решающим оказалось другое: снимок `proc_dict` ВСЕХ 7
процессов из чистого `git worktree` на `HEAD` против текущего дерева — **0 добавленных,
0 удалённых, 0 изменённых** ключей после нормализации корня пути. В режиме с окном
дифф не меняет ни бита, значит наблюдаемые отказы породить не мог.

**Why:** шумная метрика отвечает «похоже на прежнее», структурное сравнение — «то же
самое». Второе не требует порога, взятого с потолка, и не краснеет от посторонней
нагрузки (ср. [[feedback_test_values_near_defaults_test_the_default]]).

**How to apply:** `git worktree add /d/<короткий-путь> HEAD` (в длинный путь Windows
падает с «Filename too long»), собрать артефакт в обоих деревьях одним и тем же
скриптом, нормализовать корень пути и сравнить рекурсивным обходом по путям ключей.
Расхождения при этом раскладывать по причинам — «моё» отдельно от предсуществующего
дрейфа, см. [[feedback_check_red_on_main_first]].
