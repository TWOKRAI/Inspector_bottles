Решение владельца (2026-11-01). Фреймворк — открытый конструктор многопроцессных приложений, «блоки как в Майнкрафте»: каждый модуль прозрачен и управляем до низкого уровня. На нём строятся сложные системы, а ИИ-агенты помогают разработчикам создавать, отлаживать, настраивать и улучшать (Python как оркестратор над сервисами).

Решено владельцем:
1. **Одно ядро** (модуль фреймворка) даёт инструменты ко всем модулям и функциям. `backend_ctl` и прочие привязываются к нему как фронты: CLI, REPL, MCP.
2. **Инструментов может быть много**, у них **уровни доступа**; для агентов — **каталог инструментов**.
3. **God Mode** нужен и связан с `backend_ctl` (одно ядро, общий аудит).
4. **Кадры** — и в файл, и через MCP; цель — максимальная функциональность отладки.
5. **Один план на MCP**, новое добавляется фазами (правило «один активный план на инструмент»).
6. **Безопасность сознательно после фундамента:** сначала функциональное здание, потом надёжные ворота и двери.

7. **Уточнение 2026-11-01 (позже в тот же день):** «ядро» — это универсальная карточка модуля в `base_manager` (образец — карточки Atlas), а `CommandManager` читает из неё команды. `console_module` остаётся: терминал разработчика и видимая среда каждого процесса (логи, ввод команд в `CommandManager`), потенциал есть. Слои добавлять только по необходимости, архитектура лаконичная. Проект — `docs/reports/2026-11-01_module-card-architecture.md`. Решения владельца в тот же день: (а) `stats`, `state_store`, `console` регистрируют команды каждый по-своему, их надо привести к общему пути; (б) ВСЕ сервисы (`Services/`) строятся на `multiprocess_framework/modules/service_module`, а он на `BaseManager` (сегодня `service_module` на `BaseManager` НЕ стоит: `IService` — Protocol, ADR-SVC-002; нужен новый ADR); при добавлении в проект сервис сам отдаёт информацию о себе и командах (API и прочее); (в) формировать правильные интерфейсы и импортировать `interfaces.py` каждого модуля, так сбор автоматизируется (идея: маркер `@expose` на методах интерфейса). Моё условие, владелец пока не подтвердил: `start()` сервиса должен быть настоящим, не оболочкой со строкой статуса (`SqlService` сейчас такая).

**Why:** универсальность и прозрачность важнее раннего закрытия; ворота проще строить на готовом фундаменте. Согласуется с [[feedback_framework_first]] (конструктор, fix-forward, меньше слоёв, FREEZE не KILL).

**How to apply:**
- Спорное решение по управляющему слою оценивать по тому, делает ли оно ядро универсальнее, а не по удобству одного фронта.
- В контракт инструмента закладывать поле уровня доступа и точку политики/аудита с первого дня: включение защиты позже не должно ломать контракты. Принудительная аутентификация — перед любым релизом наружу.
- Не плодить второй реестр рядом с `CommandManager`/CAPABILITIES — ядро обобщает их, дубли замораживать.
- Подробности и оценка: `docs/reports/2026-11-01_control-core-vision-and-review-brief.md`, `docs/reports/2026-11-01_backend-ctl-control-plane-assessment.md`.

**Карта архитектуры и карточки — тот же принцип (владелец 2026-11-06).** Слова владельца: «максимально автономно и строилось по документам и коду самого модуля или класса, чтобы в дальнейшем не расходилось», «один универсальный механизм и не было дубля».
- Ловушка (сессия 2026-11-06): лид спроектировал карту, не открыв `scripts/atlas`, `modules.yaml` и `docs/reports/2026-11-01_module-card-architecture.md`, и поручил Haiku написать 112 карточек YAML по README — третью рукописную копию назначения модуля. Владелец отклонил.
- **Как применять:** перед любым каталогом, картой, списком модулей или карточкой — сначала `ls scripts/atlas`, `modules.yaml`, отчёт о карточке модуля. Модель (агент) в карту ничего не пишет: факт либо вычисляется из кода (`scripts/arch_map/build.py`), либо объявлен в самом модуле; суждения — только в отчёте ревью с датой и SHA.
- Толкование лида, не слова владельца: объявляемые поля живут в докстринге `__init__.py` модуля — назначение = первая строка, ярус и контур = строки шапки `Tier:` / `Contour:`; где исполняется — не объявляется. Нового типа файла нет: шильдик `module.yaml` лид сначала предложил, потом отменил как дубль ADR-175 (решение D11, `docs/reports/2026-11-06_atlas-map-merge-design.md` §3).
- Замер 2026-11-06 (один прогон, Haiku, 10 вопросов разведки K0): агент по сырой карте `model.json` — 54 вызова, ~105k токенов, полностью закрыл 1 вопрос; агент по исходникам — 40 вызовов, ~85k, закрыл 6. Вывод: большой JSON — не справка для агента; справка — это команда-запрос (`atlas ref`), которая отдаёт сигнатуру, докстринг, наследников и тесты одного символа.
- **Цель карты — навигация, как Google Maps (владелец 2026-11-06).** Слова владельца: «издалека карта материков, потом страны, города, районы, дома… видно транспортные пути, точки А и Б, развилки… важно увидеть, какой дом есть что; смотреть внутрь — уже читать код»; «вид как гугл карты: наводишь на дом, а там понятно, что он такое». Карта не заменяет чтение кода, она сокращает путь к нужному `файл:строка`. Уровни: слой → модуль → подпакет/файл → класс/функция; дороги — импорт, вызов, IPC-канал, поток, файл на диске. Метрику приёмки (K0 «N из 10 без исходника») лид предложил заменить навигационной: шаги и токены до правильного места; советы CTO по этой идее — в отчёте от 2026-11-06.
- **Дороги карты не видны в Python AST (замер CTO 2026-11-06, `main` 1dc6c71b7).** `FieldRouting(channel=<литерал>)` — 8 файлов, 2 имени; `channel_map` по модулям framework даёт `?` почти везде. Магистрали между процессами объявлены в YAML топологии (`multiprocess_prototype/backend/topology/*.yaml`, `system.yaml`, рецепты), рантайм-истина — снимок `backend_ctl capabilities`. Пара K0 «кто пишет / за чем следит» получает путь параметром (`observability_companion.py:49-51, :137`, `watcher.py:216`) — литералы путей её не закрывают. Докстринги есть у 1815/1859 файлов, 1702/1715 публичных классов, 4895/5933 методов, 1118/1390 функций (`backend_ctl` 181/381). **Как применять:** IPC-дороги читать из YAML (`yaml.safe_load`), литералы кода — добавка; «файловая дорога» — шильдик ввода-вывода у символа (`пишет: <выражение пути>` через `ast.unparse`), слово «поток данных» не обещать; «нет докстринга» — находка на уровне юнита и класса, у методов — счётчик. Полный совет — `docs/reports/2026-11-06_cto-map-vision-advice.md`.
