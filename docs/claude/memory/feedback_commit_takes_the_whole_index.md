Две ловушки коммита, каждая стоила времени в один заход (2026-08-10, фаза D):

1. **`git commit` коммитит индекс целиком, а не перечисленные пути.** Удаления,
   сделанные `git rm` в начале сессии, лежали в индексе и уехали в первый же
   коммит другой задачи: 34 удалённых файла D2 оказались внутри `fix(store): D3`.
   Лечится либо `git commit -- <пути>`, либо `git reset` перед каждой группой и
   `git add -A <пути>` ровно своей задачи. Проверять — `git show --stat` СРАЗУ
   после коммита, а не в конце.
2. **Сорванный хук pre-commit не возвращает спрятанное.** При наличии
   незастейдженных правок pre-commit прячет их в `~/.cache/pre-commit/patchNNN`.
   Если хук (`ruff format`) что-то переформатировал, восстановление патча падает
   с «patch does not apply», и **рабочее дерево остаётся без правок** — выглядит
   как потеря работы. Правки живут в том самом файле-патче: возвращать
   `git apply --3way <патч>`. Профилактика: прогнать `ruff format` по своим
   файлам ДО `git add`, тогда хуку нечего менять.

**Why:** обе ловушки тихие — первая портит трассируемость (`Refs:` указывает не
на ту задачу), вторая выглядит как исчезнувший час работы.

**How to apply:** перед серией коммитов — `git status --short`; стейджить
группу, коммитить, немедленно `git show --stat`. Форматирование — до `git add`.
