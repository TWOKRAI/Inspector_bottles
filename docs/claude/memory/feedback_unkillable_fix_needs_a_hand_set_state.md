Когда пакет закрывает ОДИН класс дефекта несколькими точками, часть правок
после починки соседних становится **недостижимой снаружи**: откат такой правки
по отдельности не убивает ни одного поведенческого теста, и это не признак
лишней правки.

**Why:** Ф0 Task 0.2 (`observation-port`, 2026-08-19). Правка 3 («живое
побеждает» сверяется с до-гейтовым срезом) закрывала Д2' вместе с правкой 1.
Но правка 1 (снятие откладывает только владелец) и правка 2 (отменяет снятие
только владелец) вместе делают пару «живая публикация владельца + отложенное
снятие того же имени» недостижимой: publish владельца снимает запас, чужой уход
его не заказывает. Итог — откат правки 3 в одиночку не красит ничего, хотя
страж после отката читает придержанный гейтом лист как «показания нет».

**How to apply:** предсказывая инъекции по пакету правок, для КАЖДОЙ спроси
«достижимо ли её состояние после остальных правок пакета». Где ответ «нет» —
не выдумывай имя жертвы («несколько тестов»), а честно пиши «ноль» и добавь
авторский тест, который ставит недостижимое состояние РУКАМИ (прямая запись в
приватное поле хранилища) — с докстрингом «сегодня недостижимо, сторожим ради
следующей правки соседа» и парой-контролем, что штатная дорога жива. Иначе
правка остаётся без сторожа, а при следующей правке соседа страж сработает
молча и неправильно. Смежное: [[injection-verdict-reading]].
