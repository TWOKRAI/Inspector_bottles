Если одна функция обслуживает **две позиции** с противоположными безопасными
дефолтами, это может работать годами — но только пока совпадают константы. Ф3.1
(2026-08-05): `level_rank` возвращала «неизвестное → 0» и для **порога** приёмника
(fail-open, tap получает всё), и для **уровня записи** (проходит tap порога DEBUG).
Годилось ровно потому, что 0 был числом DEBUG. При переномерации в словарь OTel
(DEBUG=5) совпадение исчезает, и одна из двух позиций сломалась бы **молча**.

**Why:** дефект не в функции — она корректна для каждой позиции по отдельности.
Дефект в том, что позиций две, а имя одно, и различие держится на арифметическом
совпадении, о котором никто не знает. Тесты обеих позиций зелены и до, и после
слома — ломается только та комбинация, которую никто не проверял.

**How to apply:** перед сменой числовой шкалы (рангов, приоритетов, кодов) —
перечислить ВСЕ позиции, где значение сравнивается, и для каждой спросить: «каков
безопасный дефолт, если значение не опознано?». Разные ответы = разные функции,
даже если сегодня они возвращают одно и то же. Найдено независимым ревьюером
(Fable), не автором и не тестами — см. [[feedback_review_finds_the_seam_between_own_pieces]],
[[feedback_defect_fixed_on_one_path_only]].
