Владелец (2026-10-17, после Opus-прохода по камерам штрихкодов): «Sonnet пишет код и реализует», Opus проверяет, как реализовано; «главное без костылей и багов, делать как полагается, с лучшей архитектурой»; «может Sonnet'у давать больше работы для экономии токенов»; «пусть использует qex и графы, если нужно».

**Why:** замеры сессии (Opus-оценка в `docs/reviews/2026-10-17_codereader-multicamera-opus-review.md`, «Проход 2»): Sonnet надёжен при точном DESIGN (код, тесты с литералами, hazard-тесты), слаб вне файлов брифа (живые логи, связь выхода приложения с возвратом режима, сомнение в посылке плана). Коммит Sonnet без ревью дал реальный дефект (`labels` с опечаткой роняет `produce()`); коммиты с ревью Sonnet — без новых дефектов. Около четверти токенов ушло на старт новых агентов вместо дозыва.

**How to apply:** реализацию, тесты, hazard-тесты, ревью обычных коммитов — Sonnet (Haiku — механика, опись логов); Opus — стадия 0 и ревью кода только для задач с потоками, IPC, жизненным циклом процесса/прибора, и вердикты по живым дефектам; повторные раунды — `SendMessage` тому же агенту. Правила сессии (слепой тестер, инъекции, ревью после каждой задачи) не отменяются. Связано: [[feedback_always_latest_models]], [[feedback_explicit_model_per_agent_role]].
