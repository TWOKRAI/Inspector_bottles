Ф6 плана `observability-unified-routing` закрыта 2026-08-03 целиком (6.0–6.9).

**Что сделано.** Голый `logging.getLogger(__name__)` уходил в stdlib-root, у которого в
процессах фреймворка нет хендлеров — то есть 100 файлов писали в никуда. Кодмод
`ast-grep` (`scripts/codemods/`) перевёл 98 файлов на `get_std_logger(__name__)`, ещё
3 правились руками (импорт внутри метода, алиасы `_log`/`_logging` в `try`). Регресс
закрыт стражем `logger_module/tests/test_std_logger_guard.py` — скан по AST, а не
грепом, потому что греп видит одну форму написания из трёх.

**Главное число для Ф7: пробуждение 100 файлов НЕ добавило объёма.** Три точки на
`webcam_sketch`: 5.4 → 5.0 → **4.78 МБ/час**. Вклад самих мигрированных файлов — 10
записей / 1.7 КБ за 11 минут, 0.2%.

**Куда целиться в Ф7 (сэмплинг).** Разбор приращения логов по источнику за окно:

| источник | доля | строк |
|---|---|---|
| `stats: metrics snapshot` | **64.1%** | 587 (≈1 КБ на строку) |
| `command_manager` | 10.7% | 930 |
| `dispatcher` | 10.3% | 930 |
| `queues.core.manager` (детектор вытеснений) | 7.6% | 155 |

То есть объём делает **один** источник — текстовый дамп списка метрик, а не сотня
мигрированных файлов, как предполагалось при постановке фазы.

**Открытые хвосты после Ф6:**
- `observability_tail` не доставляет ничего — воспроизведено дважды, кольцо драйвера
  пусто (`all:0`), форвардер не эмитит. Резидуал 5.11, см. [[project-observability-subscription-broker]].
- `introspect_failed` у `gui` в `system_overview` — это **таймаут**, а не мёртвая
  ручка: прицельный вызов с `timeout=20` отдаёт полную статистику.
- Кадры теряются на старте, пока `gui` поднимается. Механизм барьера (`depends_on`,
  `FW_DEPENDS_ON_BOOT_ORDER`) существует и включён, но рецепты его не объявляют; и
  вешать его на нынешний ready `gui` нельзя — тот приходит liveness-фолбэком.
  Решение владельца: старт после полного подъёма либо по кнопке «Старт».
