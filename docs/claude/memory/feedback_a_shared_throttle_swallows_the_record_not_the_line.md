Когда дроссель один на «строку в журнал» и «запись в плоскость», подавление роняет **запись**,
а не голос. Замер 2026-08-31, `process_module/health/state.py`: `self._safe_track(exc, ctx, fields)`
стоит **внутри** `if should_log:` (строка 290), окно `DEFAULT_THROTTLE = 5.0` с на ключ
`(тип исключения, context)`. При повторе в окне плоскость ошибок не получает **ничего** — ни трассы,
ни полей, ни контекста. Счётчик health растёт на все (строка 259), и это создаёт видимость
«потеря компенсирована числом»: число компенсирует только число, содержимое подавленных инцидентов
не восстановимо ниоткуда.

Комментарий в коде сам называет причину — *«Дроссель общий с логом намеренно: у плоскости ошибок
своего нет»*. То есть общий дроссель был **обходным путём вокруг отсутствующего механизма окна**,
и выглядел он как осознанное решение, потому что был так и описан.

**Why:** «подавлено» тихо означает два разных факта — «голос не прозвучал» и «события не было».
Второе внутри фазы про невидимые отказы производит ровно тот дефект, который фаза лечит. А оговорка
«зато счётчик считает все» звучит как закрытие вопроса и потому не перепроверяется.

**How to apply:** у механизма окна должно быть ДВА обязательства, не одно: **факт** учитывается
всегда, **голос** идёт по окну с числом подавленных. Увидев `if should_log:` — проверить, что стоит
внутри блока: если там запись, а не только строка, это дефект, как бы уверенно ни звучал соседний
комментарий. Каноничная дорога ошибок в этом проекте — `ErrorManager`
(`ObservableMixin._track_error` → слот `error` → `ErrorManager.track_error`), и **своего окна у неё
нет** — она пишет каждый инцидент; окно добавляют виды поверх неё (`HealthState`). Родственное:
[[one-log-writer]], [[feedback_zero_observations_looks_like_a_result]],
[[feedback_a_control_can_exist_and_be_dead]].
