**Замер 2026-10-19, T5.3d d1.** `test_stop_levels` ждал SOFT в списке значений `STOP_REQ`, который поток-наблюдатель
снимал раз в 1 мс. Клиент через 0,8–3,8 мс сам дописывает HARD; при зазоре < 1 мс наблюдатель видел только `[2]` —
1 падение на 14 запусков (ревью Opus р.1). Продукт был исправен: журнал `issue_stop` показывал обе записи.

**Ловушка:** выборка регистра — не счётчик записей. Плюс к ней: когда заменяешь опрос журналом обмена, проверь
полноту ответа (`len(lines) < limit`), иначе обрезанный ответ молча пропустит «HALT не писался» — и проверяй это
только на чтении, чьи строки считаешь (кольцо на входе может быть полным — ложный красный, ревью р.3).

**Триггер:** тест считает записи/события, подглядывая за состоянием с периодом. Считать в точке записи.
