Ф2.4: тест однократности слал три ОДИНАКОВЫЕ записи, а детектор зовётся с промаха
кэша маршрута (ключ — тройка «скоуп-уровень-источник»). Сигнал был бы один и без
дедупликации — свойство сторожил кэш, а не тест. Вскрыто инъекцией (снять дедупликацию
→ тест остался зелёным); чинится вариацией уровня.

**Why:** «повторил вызов — сигнал не повторился» выглядит доказательством
идемпотентности, хотя доказывает лишь наличие кэша. Тот же класс, что вакуумный тест,
сравнивающий значения после сброса при неизменной таблице.

**C-40 (2026-10-26) — кэш по периоду прячется фазой.** Тест «после смены модели первый кадр —
свежий инференс» на двух одинаковых dummy-моделях был зелёным и под кэшем (ревью: `calls=[1]`).
С разными метками и одним `pre` кэш периода 2 ловился только при `pre=2`, периода 3 — только при
`pre=1,3`. Лид предсказал красный авторский тест под возвратом кэша — он остался зелёным: в нём 2
кадра, а кэш периода 2 отдаёт только с 3-го. Ловят кэш слепые тесты с 6 кадрами разного содержимого.

**How to apply:** прежде чем писать тест на «ровно один раз», выяснить ключ ближайшего
кэша на этом пути и варьировать вход ПО ЭТОМУ КЛЮЧУ — иначе проверяется кэш. Для кэша по
счётчику кадров: последовательность длиннее периода и параметр по фазе (`pre` = 1…N), входы с
разным содержимым и ожидание-литерал, которое отличает «этот кадр» от «прошлого».
