Страж со счётчиком-порогом остаётся зелёным, когда часть его области видимости
исчезает: остаток перекрывает порог. Проверять надо **каждую запись списка
отдельно** — «эта запись разрешается хотя бы в один файл», а не «всего файлов
≥ N».

**Why:** D2.3 (2026-08-10). Новый страж дедлайнов `test_thread_deadlines.py` нёс
самопроверку «страж видит ≥ 40 файлов». Инъекция и-3 сломала путь одного из
четырёх охраняемых каталогов — страж **остался зелёным**, потому что оставшиеся
три плюс глобы дали больше сорока. Проверка, ради которой самопроверка и
писалась («молчащий детектор ничего не доказывает»), сама оказалась молчащей.
После переписывания на поимённую сверку та же инъекция даёт красный.

**How to apply:** в любом стороже, у которого есть список охраняемых мест
(каталоги, globы, имена команд, ключи конфига), пиши цикл по записям и собирай
`blind = [...]`, а не сравнивай общее число с порогом. Порог допустим только
там, где потеря ЛЮБОЙ записи уводит сумму ниже него — то есть почти нигде.
