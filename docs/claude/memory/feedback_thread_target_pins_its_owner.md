`threading.Thread(target=self._loop)` держит объект сильной ссылкой — стенд,
который тест забыл погасить, НЕ мусор: он бессмертен (GC не финализирует) и
тикает до конца прогона. В Inspector_bottles 23 теста (18 в
`state_store_module/tests`, 5 в `app_module` — включая два, где `shutdown`
подменён спаем: вызов доказан, поток жил) звали `StateStoreManager.initialize()`
(стартует `StateCoalesceFlusher`, тик 0.12 c) без `shutdown()`. После закрытия
утечек `Windows fatal exception: access violation` корневого гейта прекратился:
было 3 падения из 3 прогонов, стало 5/5 зелёных на том же составе; вторая
одновременная правка доказано инертна → атрибуция по остатку. **Микромеханизм
связки потоки↔AV не доказан и не утверждается.**

**Why:** «утечку объектов» не покажет ни один счётчик мусора — граф жив; по коду
виновников не найти (вызовы разбросаны, фикстуры путают).

**How to apply:** (1) виновников называет проба: одноразовый pytest-плагин,
после каждого теста сравнивающий множество живых потоков по имени-маркеру
(печать глотается капчей — писать в файл); (2) класс закрывает autouse-страж в
conftest зоны: множества до/после, краснеет ДОБАВИВШИЙ, best-effort гашение,
реестр долгоживущих — только с причиной; (3) стража сперва показать красным на
живом дефекте с предсказанием набора. Образец: `_no_leaked_state_flushers` в
`multiprocess_framework/modules/conftest.py`; досье
`docs/sessions/2026-08-12_access_violation.md`.
