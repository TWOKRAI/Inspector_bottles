Восемь раз чинили класс «тесты-невидимки» поимённо, и каждый раз ставили страж на **свою
зону**: `modules/`, `Services`+`Plugins`, дерево фронта. Девятый случай (задача 4.0,
2026-08-11) завёлся ровно в непокрытом промежутке — **114 файлов в 19 каталогах, 1464
теста**, среди них четыре красных, проживших красными после ренейма никем не замеченными.

**Why:** зонный страж кодирует «здесь уже обожглись», а не свойство. Свойство — «каталог с
тестами обязан быть виден прогонщику», и оно про репозиторий целиком. Пока страж зонный,
«невидимый» остаётся состоянием ПО УМОЛЧАНИЮ для всякого нового места, и класс живёт.

**How to apply:** страж пишется на КЛАСС и обходит весь репозиторий, а законные исключения
выносятся в реестр «имя → причина» с парным стражем против гниения (запись существует,
ещё нужна, причина непуста). Три исхода вместо двух: покрыто, покрыто другим прогонщиком,
либо названо решением, за которым кто-то стоит. Проверять инъекцией именно в **непокрытой**
зоне — зонный страж на своей зоне краснеет и создаёт ложное чувство закрытого класса.
