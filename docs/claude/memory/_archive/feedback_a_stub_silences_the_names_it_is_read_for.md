**Дублёр глушит ровно те имена, которые код у него ЧИТАЕТ.** Имена, которые код ему
ПИШЕТ, продолжают падать громко — и это создаёт ложное чувство, что гарнитура честная.

Измерено 2026-08-18 (S-26, две инъекции одного вида):

| Инъекция | Имя | Кто его трогает | Результат |
|---|---|---|---|
| И6 | `_full_replace_planner` | хук **пишет** его на оркестратор | **все 5** тестов упали ошибкой фикстуры |
| И10 | `live_process_config` | хук **читает** его у оркестратора | **69 тестов каталога зелены**, дефект невидим |

Разница механическая: чтение уходит в дублёра, у которого имя есть; запись уходит туда же,
но тест потом сам берёт результат по старому имени и не находит его. Соотношение сил на
момент замера: живых вызывающих у `live_process_config` — **1**, копий в дублёрах — **5**.
Молчание пятерых перевешивает.

**Как применять:** к каждому дублёру продакшн-объекта — контракт-тест на ИМЕНА:
`hasattr(РеальныйКласс, имя)` плюс поиск `self.<имя> =` по исходникам всей иерархии
(часть имён — атрибуты экземпляра, на классе их нет; первая же попытка сверить всё
через `hasattr(cls, ...)` это и поймала). Пять строк закрывают все копии дублёра сразу.
Список имён брать грепом `orchestrator\.[_a-zA-Z]*` по файлу-потребителю, не по памяти,
и не забыть те, что берутся через `getattr(..., default)` — их в присваиваниях не видно.
