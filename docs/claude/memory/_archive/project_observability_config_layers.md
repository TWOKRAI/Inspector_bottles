Закрыта 2026-07-28 (`1f23396c`…`5bdbcf6b`, ветка `feat/observability-unified-routing`).

Конфиг наблюдаемости — четыре ИСТОЧНИКА, а не один: **L0** дефолт фреймворка
(`ObservabilityConfig`) → **L1** `system.yaml observability:` → **L2** рецепт +
спутник `recipes/<имя>.observability.yaml` → **L3** память процесса.
Отсутствие ключа на слое = наследование снизу.

Ключевое решение: **`config.reload` ПЕРЕСОБИРАЕТ конфиг из слоёв**, а не мержит
дельту поверх живого. Причина структурная: дельта не умеет выразить «ключ удалён
из слоя → вернись к нижнему», а с четырьмя слоями «вернуть как было» — основная
операция. Цена названа тестом: живое состояние, которого нет ни в одном слое,
пересборку не переживает.

Адресаты команд: inline `config.reload` = ручка оператора → **L3**; файловый
reload → **L1**; `observability.persist` → **L2** (спутник, отдельным явным
действием — запись на каждое нажатие навсегда меняла бы рецепт).
`introspect.observability` отдаёт **provenance**: слой-победитель и конкретный
файл у каждого действующего ключа.
