**Правило владельца (2026-08-27): `search_code` в qex формулировать по-английски,
терминами близкими к коду — не русским абстрактным перефразом.**

**Почему.** 2026-08-27 эмбеддер qex переключён с `qwen3-embedding:4b` (не
работал вообще — VRAM/таймаут, 0% успешных прогонов три недели, см.
[[project-qex-reindex-timeout]]) на `qwen3-embedding:0.6b` (влезает в 4 ГБ
карты с запасом). После первого успешного полного реиндекса — стресс-тест
трёх формулировок одного и того же вопроса (fencing-token / stale incarnation
после замены инстанса, код и тесты реально существуют — `test_fencing.py`,
`test_fencing_live.py`):

| Запрос | Результат |
|---|---|
| EN точные термины (`fencing token stale sender incarnation`) | топ-1, score 25.4 — в точку |
| EN абстрактный перефраз, без точных слов | топ-3, score 21.7 — тоже в точку |
| **RU абстрактный перефраз** того же вопроса | **мимо совсем** — топ-4 сплошь нерелевантные GUI-виджеты |

Разница ровно в языке запроса, не в абстрактности — английский перефраз
сработал нормально. Слабость **кросс-языковая**: код и большинство
идентификаторов/терминов в проекте английские (`fencing`, `incarnation`),
а привычная формулировка вопроса — русская. У 0.6B этот перенос заметно
слабее, чем у большой модели (сравнить не с чем — у 4b baseline никогда не
было, три недели 0% аптайма).

**Как применять.**
1. Смысловые (не точечные keyword) запросы к `search_code` — формулировать
   по-английски, лексикой ближе к коду/идентификаторам, а не русским
   абстрактным пересказом идеи.
2. Точные термины на русском (из докстрингов/комментариев) BM25-половина
   гибрида ловит по-прежнему нормально — от смены эмбеддера не зависит.
   Слабое место — именно RU-абстракция без точных слов.
3. Субагентам, которым эта память не видна напрямую — передавать бисером в
   промпте: «формулируй qex-запросы по-английски, ближе к коду».
4. Если RU-семантика станет критичной — пробовать `embeddinggemma` (заявлена
   сильной мультиязычностью, 250+ языков); не проверено на этом проекте.
