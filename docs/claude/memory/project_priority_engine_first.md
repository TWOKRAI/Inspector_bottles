**АКТУАЛЬНО (2026-07-26): приоритет развёрнут — сначала движок.** Владелец: «сейчас работаем над движком в первую очередь; продукт параллельный, для тестов». То есть прототип с бутылками перестал быть целью и стал стендом, на котором движок проверяется живьём.

**Why:** конструктор-фреймворк — самостоятельная ценность («мощный инструмент»), а не побочный продукт линии инспекции. Прототип нужен как источник реальных нагрузок и живых прогонов, а не как результат.

**How to apply:** архитектурные работы во фреймворке (наблюдаемость, адресация, схлопывание реестров, конструкторские фазы планов) больше НЕ требуют оправдания «это блокирует продукт» — они самоценны. Продуктовые задачи прототипа берутся, когда нужны для проверки движка или когда владелец просит явно. При оценке планов не резать конструкторские фазы автоматически под предлогом «product over engine» — этот аргумент устарел; но честно называть, какие фазы окупаются вторым приложением, а какие чинят сегодняшнюю боль.
