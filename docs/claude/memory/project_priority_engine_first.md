**АКТУАЛЬНО (2026-08-18): приоритет — маятник, привязанный к свободному времени.** Владелец: два свободных
месяца (июнь–июль) ушли в движок сознательно; «затягивать тоже нехорошо — нужно переходить к стенду для
видимости работы». Работодателю важен **результат прототипа**, фреймворк — собственная инвестиция владельца.
Значит сейчас: **полоса A — продукт задаёт темп** (после merge телеметрии: line-sim Ф0→Ф1, затем robot-protocol-v2
или line-sim Ф2–Ф5 — что раньше нужно работодателю, решение открыто), **полоса B — фреймворк по одной задаче между
продуктовыми**, только то, что окупается продуктом сейчас (rework 1.1 страж, 2.1 глаголы, 2.3 диагностика
robot/vfd, 2в.2 sparse-рецепты). **Окно codemod Ф3 — не датой, а естественной паузой** (железо уехало, ждём
прошивку, отпуск).

**Why:** ни «движок первым», ни «продукт первым» не константа — оба были правдой в своё время. Правило, которое
не протухает: *направление задаёт бюджет свободного времени; когда его много — движок, когда работодателю нужен
результат — стенд*. Продуктовые треки (line-sim, robot-v2, ML, интерфейс) живут в `Services/Plugins/prototype` и
потребляют фреймворк по префиксу импорта — codemod для них механичен, поэтому «продукт ждёт rework» ложно;
по-настоящему ждёт только frontend-constructor Блок В.

**How to apply:** не спрашивать «движок или продукт» заново — спросить «сколько сейчас свободного времени и что
работодателю нужно раньше». Один активный план на полосу; планировать не дальше одной фазы вперёд; ревью плана до
8+ — только у того, что стартует следующим (rework — отложить до паузы перед окном, иначе якоря протухнут и
платить дважды); стенд один (порт 8765) → один live-гейтуемый трек за раз, ML/интерфейс — параллельная полоса без
стенда. Если сессия ушла в планы целиком — сигнал, не работа. См. [[feedback-one-active-plan-per-tool]],
[[feedback-a-plans-premise-expires]].
