Владелец 2026-11-22: «главное запомнить и добавить в файл очереди»; «как полагается архитектурно, без костылей».

**Что установлено (сим, журнал обмена):** 6 CVT_JOB совпали с расчётом (PASS); 8 «потерь» были отказами hub при выключенном серво, не потерей команд. `wire_audit --layout-system` (ветка test/sim-wire-audit) показывает отказ предупреждением «отказ hub: причина» — это честный ИНСТРУМЕНТ, не исправление потока.

**Корневые дефекты не нашей зоны (Р2, заявки `plans/queue/inbox/2026-11-22_simaudit-gui-bd_*.md`, сводная строка очереди — `_27`):**
1. ячейка слова занимается при выдаче задания, отказ hub её не освобождает (`word_layout/plugin.py:218-255`);
2. health-breaker один на процесс, не закрывается после успеха (ADR-PM-011);
3. ответ об отказе без `reason`;
4. «ЗАПУСТИТЬ» не возвращает ленту (решение 1B: opt-in `params.resume_action`, нужен ADR, код `device_hub`);
5. «Домой»: SERVO 0 ждёт DONE, журнал DONE не показывает.

**Why:** обход в инструменте аудита маскирует причину; на железе (дни №1–2, 23–25.11) отказ при выключенном серво повторится, а слово не соберётся.
**How to apply:** правки в чужих зонах — заявкой (inbox), не кодом. Вопросы (2), (3) и общий взгляд отдать `cto` (Fable, явная модель) ПОСЛЕ всей практики полосы Н2. Не выдавать `wire_audit` за исправление.
