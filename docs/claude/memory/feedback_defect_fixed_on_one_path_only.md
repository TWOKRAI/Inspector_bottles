Починка дефекта в одном месте не закрывает его класс. Ревью 5.10 нашло **два
воскрешения уже закрытых дефектов** на соседних путях:

- «`ttl` принят и молча потерян» — закрыто замечанием 2 ревью 5.8 на пути
  «`config.reload` из файла + ttl», воскресло на `telemetry.reconfigure` с
  throttle-only секцией;
- «неизвестный режим проходит как успех» — закрыто находкой 1 задачи 1.2 в
  `apply_telemetry_reconfigure`, воскресло на пути `config.reload`, где ветка
  наблюдаемости вливала секцию в слой **раньше** валидации. Отказ зависел от
  того, приехала ли рядом секция observability.

**Why:** оба дефекта одного класса — «поле ответа значит не то». Первый фикс
ставился там, где симптом наблюдали, а не там, где развилка. Вторая ветка
оставалась и ждала.

**How to apply:** закрыв дефект, найти ВСЕ места с той же развилкой (grep по
имени параметра, по имени поля ответа) и проверить каждое парой. Если развилок
больше одной — валидацию поднимать в общую точку до неё, а не дублировать после.
Связано с [[feedback-plausible-is-not-verified]] и
[[feedback-swallowed-failure-class]].
