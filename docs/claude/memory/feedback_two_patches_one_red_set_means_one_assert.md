Если две заплаты, снимающие РАЗНЫЕ свойства, красят один и тот же набор тестов — вероятно,
оба свойства стережёт один ассерт, и второе свойство сторожа не имеет. Совпадение наборов
читать как находку, а не как подтверждение.

**Замер (матрица добора Task 3.0a, 2026-09-04).** S3 («нечитаемое правило читается как
„правила нет“») и S4 («обе причины веера одним литералом») дали дословно одинаковую пару
красных. Это два разных факта: «кандидат назван вслух» и «назван ИМЕННО этой причиной» —
и если оба падают на одном ассерте, то подмена литерала причины на соседний останется
незамеченной везде, кроме этого одного места.

Обратный полезный случай в той же матрице: заплата, красящая РОВНО один тест
(S2 → два теста класса `TestABooleanRuleIsARule`, K6 → единственный
`test_criterion7_unjudged_key_absent_when_empty`), доказывает, что сторож существует и
не вырожден — именно так снялось подозрение тестера в вакуумности своего же зелёного.

**Why:** матрица инъекций отвечает на вопрос «у какого свойства есть сторож», а не «сколько
тестов покраснело». Одинаковые наборы — это ответ «у одного из них сторожа нет», сказанный
неявно.

**How to apply:** после прогона матрицы сверять наборы попарно, а не только числа; на совпадении
— назвать вслух, какое из двух свойств осталось без своего ассерта, и требовать разделяющий тест.
