`test_100_subscriptions_1000_matches_under_50ms` проходил соло и краснел в полном гейте:
113.2 мс и 158.5 мс при пороге 100. Триггером оказалось добавление **двух несвязанных
тестов в другой части репозитория** (задача 4.3, 2026-08-11): к моменту теста в процессе
живут объекты ~6000 других тестов, и сборщик обходит их на каждом такте измеряемого окна.

**Why:** окно мерило сумму «скорость кода + цена GC по чужой куче», а утверждало только
первое. Такой красный означает «сегодня в прогоне стало больше тестов» — его начинают
игнорировать, и вместе с ним игнорируют настоящий регресс. Прогрев не спасает: он греет
кэши, а не уменьшает кучу.

**How to apply:** мерить окно с остановленным сборщиком (`gc.disable()` + восстановление
в `finally` — иначе соседним тестам достаётся чужой режим памяти), **порог не трогать**:
подгонка мерила под результат запрещена. Обязательная пара — инъекция настоящего
замедления (здесь `sleep(60 мкс)` на вызов → 819.5 мс, красный): без неё «стало зелено»
неотличимо от «измерение спрятано». Тот же класс — любой ассерт по стенным часам в общей
сьюте: сперва спроси, что ещё живёт в этом процессе.
