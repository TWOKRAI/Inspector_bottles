2026-09-04 владелец попросил честную оценку проекта, языка и себя как специалиста. Итог
записан в `docs/audits/2026-09-04_honest-verdict-bus-and-niche.md`, очередь действий —
`plans/QUEUE.md` секция 5b + решение владельца №12.

Ключевое: итог **6.5/10** (Python 8, ниша 7, архитектура 7.5, дисциплина 9, **доказанность
как продукта 4**). Шина измерена в G.7: ~0.3 мс p50 / ~0.6 мс p99 на хоп при 640x480, в
`webcam_sketch` < 5 % кадра, узкое место GPU (TEED 50–70 мс). Реальный потолок FPS 21 —
таймер Windows 15.6 мс в sleep-пейсинге источника, не шина (строка B-1). ADR «почему не
ROS 2» уже существует: `docs/direction/TECH_STACK_2026.md` §3 — не предлагать писать заново.

**Why:** балл меняют не модули фреймворка, а два теста: P-1 инспектор бутылок с числами на
реальной камере и P-2 второе приложение чужими руками (агент в чистой сессии по документации).
Фреймворк съел приложение: 137k строк ядра против 60k прикладного.

**How to apply:** при предложении новой фреймворк-задачи сверять с 5b: стоит ли она выше
P-1/P-2. Любое утверждение «шина медленная» опровергать числами G.7, а не спорить.

**2026-09-09, дополнение.** Управленческий бриф `docs/audits/2026-09-04_management-brief.html`
руководству НЕ показан — владелец держит его как «карту в рукаве». Владелец беспокоится, что
вклад «не зря», и спросил, был ли путь эффективнее. Ответ, данный по данным: задним числом
тонкое приложение поверх готового рантайма дало бы инспектор быстрее, но не дало бы тех же
навыков; вперёд единственный «плод» — P-1 с числами (line-sim: 0 из 5 задач, план не трогался
с 2026-08-19, при том что полоса наблюдаемости идёт непрерывно с 2026-07-26). Бриф показывать
ТОЛЬКО вместе с числами P-1, иначе первый вопрос руководства — «а что оно инспектирует?».

(closure Ф4) и otel-export → робот (robot-protocol-v2); улучшения фреймворка параллельно, второй
полосой, не замораживать. Решения №10 и №12 очереди закрыты этим. Записка переработана в тот же
