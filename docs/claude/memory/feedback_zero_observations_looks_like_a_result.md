**Сработало ТРИЖДЫ за один день (2026-08-23, Ф2 `observation-port`), в трёх
разных обличьях.** Общее — измеритель молчал, и молчание читалось как факт.

1. **Два агента умерли беззвучно.** Правку продакшн-кода записали, тестов не
   начали, уведомления о завершении не пришло. Полтора часа я считал тишину
   работой. Вскрылось только по прямому вопросу владельца «они хоть двигаются?».
   Проверка, которая решает: `mtime` целевых файлов + факт, что `.pytest_cache`
   не трогали, + `ListAgents` → *No reachable agents*.
2. **Харнесс инъекций соврал «9 из 9 не охраняются».** `pytest-timeout` не
   установлен, pytest падал на неизвестном флаге, `passed=0`. Сторож проверял
   только `failed`, а ноль упавших при нуле запущенных выглядит как «всё
   сломано». Лечение: сторож на `passed > 0` И сверка с базой.
3. **Приёмка выживала под инъекцией, потому что не касалась настоящего кода.**
   Сломанный `StateProxy.delete` не покрасил ни одного приёмочного теста — весь
   файл гоняет дубль. Ноль красных читался как «свойство охраняется».

## Правило

Любой сторож обязан проверять ЗНАМЕНАТЕЛЬ, а не только числитель:

| Числитель (чего ждём) | Знаменатель (без него ноль ничего не значит) |
|---|---|
| `failed == 0` | `passed > 0` и совпадает с базой |
| «инъекция никого не покрасила» | тот же прогон собрал тесты; правка реально применилась |
| «агент работает» | `mtime` менялся за последние N минут |
| «ключ исчез из строки» | строка вообще была записана (см. [[feedback-unconnected-driver-reads-as-a-clean-zero]]) |

## Ещё одно, из того же дня

**Инъекция, написанная с ошибкой, даёт правдоподобный неверный ответ.**
`{w for _, w in self._values}` распаковывает строку-ключ на символы вместо
имени писателя — прогон не упал, выдал 7 красных и «опроверг» находку агента.
Верная форма (`set(self._values)`) дала обратное. Перед тем как объявлять
расхождение с чужим результатом — перечитать СВОЮ инъекцию.
См. [[feedback-injection-must-reproduce-the-mechanism-not-the-shape]].

**Четвёртое обличье (2026-09-03, Task 2.11 того же плана): сторож сработал на СОБСТВЕННОМ разборе.**
`test_declarations_leak_order_independence` гоняет pytest в подпроцессе и разбирал сводку по
ПОСЛЕДНЕЙ строке вывода. Логгер процесса `hook_leak_probe` печатает предупреждение при гашении
интерпретатора — то есть ПОСЛЕ сводки. Регулярка по такой строке даёт `{}`, и абсолютный пол теста
(`passed > 0`, заведённый ровно против этого класса) честно закричал «прямой порядок не собрал ни
одного пройденного теста» — при 3235 реально пройденных. Красный сообщал не о том, о чём написан.
Лечение: искать сводку по ФОРМЕ строки (счётчик исходов плюс хвост `in <секунды>s`), беря последнюю
подходящую — тогда чужая вложенная сводка в середине проигрывает своей, а посторонняя строка после
неё в разбор не попадает. Пол при этом сохраняется: контрольный тест «нет сводки вовсе → пусто»
обязателен, иначе починка неотличима от «всегда что-нибудь находить».

## Слито из feedback_silent_detector_proves_nothing (_archive/feedback_silent_detector_proves_nothing.md)

Прежде чем принимать «сигнала нет» за доказательство исправности, детектор надо
показать **стреляющим** — хотя бы один раз, на заведомо сломанном состоянии.

**Как это выглядело (5.11-R4, 2026-07-29).** Живую пару до/после строили по строке
`No handler for key '...'` в логе ребёнка. Оба прогона дали ноль — «значит,
починено». Ноль был ложным дважды подряд:

1. **Детектор смотрел не туда.** `INSPECTOR_LOG_DIR` направлял логи в один каталог,
   а дети писали в каталог рецепта (`logs/prototype_2/`). Grep честно возвращал
   пусто по пустому месту.
2. **Детектор был не про то.** Когда каталог нашёлся, строка оказалась в ОБОИХ
   прогонах и с одинаковым счётом: фикс не отменял раннюю рассылку, он добавлял
   вторую копию. То есть выбранный признак не отличал состояния в принципе.

Годным доказательством стало **измерение вместо признака**: сверка routing-эпохи
ребёнка с авторитетной эпохой оркестратора. Без фикса — эпоха ребёнка 1 при эпохе
PM 2 и `routing_refresh_applied=0`; с фиксом — 2 = 2. Число, а не наличие строки
в логе.

**Проверка перед тем, как поверить нулю:**
- покажи детектор красным на заведомо сломанном состоянии (слом-инъекция, откат правки);
- убедись, что признак вообще МОЖЕТ различить два состояния, а не присутствует в обоих;
- предпочитай счётчик/значение наличию строки — строку глушит фильтр, ротация,
  уровень логирования и чужой каталог.
