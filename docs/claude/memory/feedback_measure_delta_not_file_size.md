При замере объёма логов на живом прогоне считать **дельту** размеров: слепок
`путь → размер` до старта, разность после. Размер файла — накопленное за всю его
жизнь, а не за прогон.

**Why:** 2026-08-03, база «до» для Ф6 плана `observability-unified-routing`.
`find logs -name "*.log" -newermt "<старт>"` вернул `gui/system.log` = 9 МБ, и я
заявил «9 МБ меньше чем за минуту» — воспроизведение инцидента 645 МБ. Неверно:
`-newermt` отбирает файлы, **изменённые** в окне, а `%s` печатает полный размер.
Файл копился с 18 июня. Настоящая дельта — 0.70 МБ за 7.7 мин = **5.4 МБ/час**,
то есть в сотни раз меньше. Ошибка была видна сразу: временной спан записей внутри
файла (`первая строка → последняя`) сходу опровергает «за минуту».

**How to apply:** до прогона — `find logs -name "*.log" -printf "%s\t%p\n" | sort -k2`
в файл; после — та же выборка, разность по каждому пути, суммировать только
положительные. Проверка на вменяемость: спан таймстемпов внутри самого крупного
файла обязан лежать внутри окна прогона. Скрипт замера —
`scratchpad/measure.py` того же прогона.

Тот же класс, что [[feedback_plausible_is_not_verified]]: число выглядело
правдоподобно и совпадало с ожиданием («логов слишком много»), поэтому не было
перепроверено. Ожидание — худший рецензент. См. также
[[project_live_findings_webcam_2026_07]] (там же инцидент 645 МБ).
