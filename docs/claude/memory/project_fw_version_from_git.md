Решение владельца 2026-08-05 (хвост Н-5 ревью Ф3): поле `fw_version` в `Resource`
каждой записи выводится из git, а не из рукописной константы.
`multiprocess_framework/version.py` → `code_version()` = `2.0.0+<hash>[.dirty]`.

**Why:** проблема была НЕ в том, что версий две (`__version__` 2.0.0 против
pyproject 0.1.0 — последняя вообще инертна, `[build-system]` в проекте нет).
Проблема в том, что константа не менялась с 2026-04-25 — сквозь `state_store`,
`chain` и всю переделку наблюдаемости, — и записи двух разных срезов дерева были
неотличимы. Выравнивание одной рукописной константы по другой идентичности не
добавляет. Ср. [[feedback_plausible_is_not_verified]].

**How to apply:**
- цена — один вызов git на процесс (35 мс), кэш на процесс, фолбэк на голую
  константу; раздачи через env/конфиг сознательно нет (форма доставки конфига
  уже дважды давала тихие дыры — [[feedback_config_delivery_shape_differs]]);
- `.dirty` — про **весь репозиторий**, не про поддерево фреймворка: правка
  `app.yaml` пометит записи всех процессов. Ошибка в безопасную сторону;
- **два предела названы в докстринге, не закрыты:** git ищет `.git` вверх по
  дереву (копия внутри чужого репо даст чужой хеш — правдоподобный и ложный);
  во frozen-сборке идентичности не будет вовсе — версию надо запекать при сборке
  (стык с NEW-9 packaging).
- `# nosec` для bandit обязан стоять **последним** на строке и с пробелом между
  ID (`# nosec B603 B607`) — запятая и хвостовой `# noqa` после него ломают разбор.
