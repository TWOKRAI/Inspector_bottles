Критерий «grep `<снятый механизм>` по docs = 0» **невыполним и вреден**. Часть упоминаний — это
**записи о снятии**: ADR, который удалил механизм, обязан называть его по имени, иначе исчезает
причина решения. Удаление имени из ADR — потеря знания, а не уборка.

Правильная формулировка того же намерения:

> ноль упоминаний, описывающих механизм как **ЖИВОЙ**. Историческая запись обязана нести дату
> снятия и ссылку на ADR.

**Why:** E2 плана `observability-review-remediation` (2026-08-10): 36 упоминаний `BatchBuffer` в 18
файлах. После разбора — 20 исторических (в четыре ADR добавлены врезки «что из этого устарело») и
16 описывавших живой код (переписаны). Буквальное «= 0» потребовало бы выпотрошить ADR-LOG-008,
который этот механизм и снял.

**How to apply:** перед правкой разложи упоминания на два класса — «описывает настоящее» и
«объясняет прошлое». Первое переписывай, второму добавляй врезку с датой и ссылкой. Если критерий
плана требует нуля — переформулируй его вслух в «Ходе» задачи, а не тихо не выполняй и не выполняй
буквально. Побочно: список задачи почти наверняка неполон (план называл 8 файлов, греп дал 18) —
тот же класс, что [[feedback_removal_leaves_a_tail_in_the_neighbour]].

Родственное: [[feedback_docs_assert_what_registration_never_set]] — документ утверждает то, чего
код не делает; здесь обратное — документ обязан продолжать утверждать то, чего код уже не делает.
