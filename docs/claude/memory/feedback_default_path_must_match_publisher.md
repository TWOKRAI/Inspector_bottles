Правило алертинга NEW-7 по умолчанию читало `processes.<name>.state.drops_count`.
Такой путь **не публикует никто**: живой публикатор — capture-плагин
(`Plugins/sources/capture/plugin.py`), он пишет поле **`drops`** в
`processes.<name>.state`; имя `drops_count` живёт под другим корнем
(`cameras.<id>.state`, RingBuffer). Фича «дропы растут → тревога» отгружалась бы
неработающей, а **26 тестов были зелёными** — они гоняли синтетический store,
куда тест сам клал произвольный путь. Поймало только ревью (Fable).

**Why:** тест с моком проверяет ЛОГИКУ (сравнение, антидребезг), но ничего не
говорит о ПРОВОДКЕ — существует ли ключ, который логика читает. Зелёный тест на
своём же выдуманном пути создаёт ложную уверенность. Это тот же класс, что
[[feedback_swallowed_failure_class]] (следствие без причины) и
[[feedback_plausible_is_not_verified]].

**How to apply:** любой дефолтный путь/ключ/имя поля в новой фиче (state-путь,
имя метрики, ключ конфига) — грепнуть по РЕАЛЬНЫМ публикаторам до коммита. В
тесте оставлять **регресс-страж**, связывающий дефолт со схемой публикации
(`assert rule.counter_paths[0].endswith(".state.drops")`). Если имя поля —
конвенция публикующей стороны, а не инвариант, держать **список кандидатов**
(первый резолвящийся выигрывает), чтобы переименование не убивало фичу молча.
