**Полосу прогноза стенда берут из факта прошлого прогона того же сценария, а не из его прогноза.** Иначе прогноз
повторяет уже опровергнутое число, и стенд даёт заранее известный ложный FAIL.

**Замер 2026-10-27, T1.10.** Прогноз S1 (`process.stop devices`, 2 робота) взял «ответ 0,85–1,20 с» из раздела прогноза
1.9b. Факт 1.10: 0,406 / 0,516 / 0,625 с на 10 прогонах — FAIL по нижней границе. Тот же FAIL уже был у 1.9b: факт
0,313 / 0,469 / 0,859 с записан в `T1.9b_tests.md` строкой ниже прогноза. Свойство задачи (`outcome: exited` 10 из 10,
0 зависаний) совпало; время к задаче не относилось и ложный красный дал только скопированный порог.

**Why:** прогноз пишут до прогона, чтобы ловить расхождения кода, а не собственные описки. Порог, опровергнутый прошлым
фактом, гарантирует расхождение без информации; задним числом его не правят, и строка вердикта остаётся красной.

**How to apply:** перед записью прогноза стенда открыть раздел «Стенд — факт» прошлой задачи с тем же сценарием и брать
полосу как min…max факта с запасом; строки, которые задача не меняет, помечать «наблюдение, не порог». Порог в скрипте
стенда (`THRESHOLDS`) сверять с тем же фактом. Родня: [[feedback_a_number_without_spread_across_repeats_is_an_observation]],
[[feedback_a_plans_premise_expires]].
