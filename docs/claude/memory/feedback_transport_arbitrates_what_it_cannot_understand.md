Инвариант «один лист — одно значение — один владелец» может держаться при ОБЪЯВЛЕНИИ и не
действовать при ПУБЛИКАЦИИ. Тогда конфликт писателей разрешает транспорт — по порядку прибытия и
окну троттла, — у которого нет ни семантики, ни голоса для этой роли.

Найдено 2026-08-16 (Task 3.5 `telemetry-stage6`), воспроизведено вход → выход:
`ThrottleMiddleware` пропускает одну запись на путь за окно. Два merge одного тика приходят в
0.5 мс друг от друга — агрегат воркеров проходит, одноимённый лист второго merge **вырезается из
payload**, а вызов возвращает `proceed=True` **без `rejection_reason`**. Потерю не видит даже
отправитель. На Windows-сетке `monotonic` 15.6 мс два прихода в 0.5 мс читают один таймстамп →
одно окно ВСЕГДА; разнос на 51 мс проходит. До миграции записи разносило по фазе случайно, и
система «работала» по везению.

Вторая половина болезни — в модели данных, и доставкой не лечится: под именем `fps` ехали две
физически разные величины (частота цикла воркера и измеренная камерой), под `status` — статус
процесса и статус захвата.

**Why:** симптом выглядит как «метрика врёт», и его ищут в источнике — в камере. Объяснение
«побеждает последний по порядку наложения» звучит правдоподобно, пишется в ADR и переживает баг.

**How to apply:**
- Прежде чем чинить «неверное число», спроси **сколько писателей у этого листа**. У стора есть
  `source` на каждой записи — это готовый детектор второго писателя.
- **Для метрик плагинов конфликта больше нет.** С Ф1 плана `observation-port` (2026-08-20) каждый
  плагин публикует в свой путь: `processes.<P>.state.plugins.<писатель>.<имя>`. Два плагина с одинаковым
  именем метрики дают ДВА разных листа дерева (`plugins.a.fps` и `plugins.b.fps`), спорить за имя
  синтаксически невозможно (адресант — сегмент пути, не значение поля). Старый механизм (парный ключ,
  проверка владельца при публикации, `metric_owners()`) удалён целиком.
- **Конфликт остаётся для данных фреймворка,** которые пишут плоский путь `state.<имя>`: там два
  писателя (процесс и PM-агрегат, или два разных процесса через PM) могут дать два значения. Правило:
  один merge на тик (конфликт разрешается в процессе, до транспорта). Порядок отправки — не авторитет.
- Не учи троттл приоритетам писателей: он предохранитель от runaway, не авторитет частоты. Источник
  тика («сколько писателей за одно изменение пути») — фактор для детектора, не для гейта.
