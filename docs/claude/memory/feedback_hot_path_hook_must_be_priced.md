Первая честная реализация редактора секретов (Ф4.5) стоила **+5.64 мкс на
запись при цене эмиссии 4.04 мкс** — то есть удваивала `log()`. Виновником
оказалась не логика маскирования, а детект: регулярка из 18 альтернатив с
`\b` и `IGNORECASE` — 3.9 мкс на КАЖДОЙ записи, включая те (все, кроме
считанных), где искать нечего.

Лечится двухступенчатым детектом: сперва семь подстрочных поисков по
lowercase-копии (0.57 мкс), полная регулярка — только при их согласии. Итог
**+2.16 мкс (+54 %)**. Цена ступени-предфильтра — риск рассинхрона двух
перечней (корни ↔ имена), поэтому связь сторожат тесты, а не глаз.

**Why:** «перехватчик же простой» — оценка стоимости по размеру кода, а не по
работе, которую он делает на каждой записи. Регулярка выглядит как одна
строка и стоит дороже всей эмиссии.

**How to apply:** для любого хука на горячем пути мерить **дельту** — тот же
стенд с хуком и без него (`mgr._processors = ()`), медиана 5 прогонов по 20k
записей, а не абсолют ([[feedback_measure_delta_not_file_size]]). Число
называть в ADR и в плане. Если дельта сравнима с ценой самой операции —
разделять детект на дешёвую и точную ступени.
