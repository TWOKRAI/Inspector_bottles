**Ловушка.** `.program` публикует поток исполнителя на каждом шаге прогресса
(`programs.py:136-138`), а `.status` (поза, `moving`, `free`) — только цикл тика хаба раз в
`poll_interval_s` (0,5 с, `plugin.py:520-532`). Рисунок из 11 записей на sim v2 идёт ~0,37 с —
целиком между двумя тиками.

**Замер (REVIEW-5, У1).** Проба ждала `.program done`, затем статус с `moving False and free True`
и увидела позу СТАРТА рисунка (240, −210) вместо дома — решила, что робот не вернулся домой.
По проводу sim в тот момент стоял в доме (300, −210); следующий тик (+0,07 с) показал дом.
`E2eRig` с тактом 0,5 с воспроизвёл то же.

**Признак.** «Точная поза старта при `moving False` после программы» — подпись старого снимка:
ни один шаг программы не целит в точку старта, а без движения `done` не пришёл бы.

**Как применять.** Позу после терминального `.program` брать из `robot_get_telemetry` (свежее
чтение TLM), `sim.robot.state` или `rig.pose_wire()`; либо ждать снимок `status` новее `done`.
Свойство «из позы ≠ дом программа кончается домом» тест должен проверять со старта вне дома —
тесты T5.5 стартовали из дома и не различали «дом» и «старт».
