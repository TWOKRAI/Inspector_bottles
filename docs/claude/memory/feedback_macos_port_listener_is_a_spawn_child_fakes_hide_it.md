**Ловушка.** Сторож «порт занят нашим процессом» (lsof → PID → `ps -o command=`) на macOS видит команду
`Python -c from multiprocessing.spawn import spawn_main; spawn_main(...)`: слушает spawn-потомок, а `run.py` — его родитель.
Тест-фейки tester'а подставляли корневой процесс и зеленели.

**Замер (P4, 2026-11-10).** Первый живой прогон скрипта α: P0 rc 3 на верном процессе (8766, 8765: PID потомков 16068 и
17418, родители 16063 и 17409). Лечение: подъём по `ps -o ppid=` (до 5 уровней, стоп на PID ≤ 1 и цикле), команда
первого предка без `spawn_main`; корень не найден — ошибка с цепочкой (сторож Г10 с парным тестом без подъёма).

**Правило.** Всё, что опрашивает ОС о слушателе/процессе, один раз гонят на живом стенде до вердикта «зелёные тесты»; фейк
берёт форму ответа ОС из реального вывода (`lsof`, `ps`), а не из представления о нём. Тот же прогон нашёл ещё три
дефекта оснастки, которых фейки не показали: сим остаётся в режиме «список исчерпан» после прогона (нужен `random`),
файл журнала обмена дописывается между инкарнациями прототипа (судить по последней, mtime ≥ момента `shutdown`),
красный случай не должен блокировать следующие (хвост ждёт фактически выданные задания).
