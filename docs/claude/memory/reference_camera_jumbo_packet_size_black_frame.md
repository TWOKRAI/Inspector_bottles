Стенд 2026-11-26: камера DA1689923 (.20) включилась с `GevSCPSPacketSize 8164`, вторая — с 1500. Признаки: картинка из
чистых нулей, ~248 потерянных пакетов на битый кадр (= ceil(1624·1240 / (8164−36))), 13 кадр/с вместо 25, здоровье
приложения при этом `ok`. Соседняя камера тоже теряла (~5 пакетов на кадр), хотя её настройки были в порядке.

Контроль одним изменением: ключи рецепта `packet_managed: true`, `packet_size: 1500`, `packet_delay: 400` только на .20
-> обе камеры 25 кадр/с, новых потерь 0.

Не установлено: кто выставляет 8164 (настройка включения питания — догадка), настройка Jumbo адаптера, обратный
контроль. MVS при открытии сам переписывает размер пакета, поэтому после него симптом пропадает.

**Why:** 2026-11-25 тот же симптом разбирали полдня и причину потеряли, открыв MVS.
**How to apply:** при чёрном кадре или потерях сначала прочитать `GevSCPSPacketSize` обеих камер
(`mvs_probe --dump`, только чтение), до MVS и рестартов. В рецептах с этими камерами ключи пакета задают явно.
Подробности: `docs/reviews/2026-11-26_stand-camera-packet-size.md`.
