**Протокол двух сессий (2026-09-06).** otel и closure идут двумя сессиями в **двух деревьях**:
closure — главное дерево, otel — `.claude/worktrees/otel` на `feat/otel-export`. Довод не в
аккуратности стейджа, а в механизме: pre-commit-фреймворк на **каждом** коммите стешит все
незастейдженные правки tracked-файлов и накладывает обратно, поэтому в общем дереве чужая работа
проходит stash-цикл при любом чьём угодно коммите. Актуальность — односторонним `closure → otel`;
обратно только на фазовой точке рукой closure. Живой стенд эксклюзивен (`8765` за closure,
токен `.claude/stand.lock`); коллектор `4318` — нет. Ф1 стенда не требует, сырьё в git.

**Признак старта Task 2.4:** не «closure 3.3 закоммичена», а **принята ревью, хэш в
`phase-3-store-and-signal.md` + merged**. Довод фактом: 3.2 двигала лексику ПОСЛЕ первого коммита
(`13208686` → `757a2d4c` → `1f40ce0d`), старт от первого коммита означал бы переписывание имён вслед.

**Предохранитель 2.4 — импортируется, не пишется.** Вердикт Fable ADR-уровнем: bounded-канал +
`drop_oldest` + счётчик + исход `flush()` — один переиспользуемый класс во фреймворке, не знающий
про стор; `Services → framework` слоями разрешено. Три требования моей плоскости к его форме:
неблокирующий `put` (критерий «1000 записей при закрытом коллекторе не держит поток роутера»),
`flush(timeout) → (записано, потеряно)`, имя счётчика параметром (`store_evicted` против
`dropped_overflow`).

**Вторая ограниченная очередь — внутри SDK** (`opentelemetry.sdk._shared_internal.BatchProcessor.emit`,
1.44.0, прочитано в источнике): своя `deque(maxlen)`, вытеснение справа = тот же `drop_oldest`,
`emit` неблокирующий. **Но голос — WARNING на КАЖДУЮ запись**, логгер
`opentelemetry.sdk._shared_internal`: упавший коллектор на 1000 записей даёт 1000 предупреждений —
ровно та болтовня, которую closure 3.2 убрала с этой плоскости, и приходит она изнутри SDK, куда
переиспользуемый класс не дотягивается. Следствие: число потерь в 2.4 сводится из **двух** ступеней,
логгер SDK глушится/перенаправляется. Там же подтверждено `self._export_timeout_millis` =
`# Not used` с апстрим-TODO — дедлайн финального flush держать самому.
