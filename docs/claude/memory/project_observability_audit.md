Задача 5.9 плана `observability-unified-routing` закрыта 2026-07-28 (`fb5fdf49`).
Смена наблюдаемости — командой, правкой файла, подметальщиком сроков или
`switch` — оставляет запись в кольце `ObservabilityLayers.audit` и строку в
журнале процесса. Читающая `introspect.observability` следа не оставляет.

**Решения, которых не видно из кода:**

1. **Полнота держится СИГНАТУРОЙ, а не дисциплиной.** `origin` — обязательный
   keyword у каждой мутации L3 и у пересборки; забыть = `TypeError` на вызове.
   Thread-local контекст отвергнут сознательно: он дал бы дефолт, а дефолт
   («источник неизвестен») и есть та ложь, которую задача устраняет.
2. **Один писатель.** Кольца `session_reverts` больше НЕТ — это выборка из
   аудита по `action="expire"`. Форма поля изменилась вместе с переездом
   (`ok`/`ts` вместо `success`/`at`): два написания одного факта не заводятся
   даже ради совместимости. Ср. [[feedback-one-log-writer]].
3. **Долговечности своего файла нет.** Каждая запись кладёт строку в журнал
   процесса — он уже долговечен, ротируется и уже единственный писатель на диск.
   Кольцо отвечает «что сейчас», журнал — «что было до рестарта».
4. **`expire_due` — единственная мутация L3, не пишущая сама.** Запись за такт
   кладёт подметальщик: снятие ключей и исход пересборки для оператора один
   факт, а исход известен только после применения. Отсюда `record_rebuild=False`
   у пересборки на этом пути — узкий флаг, не «не пиши в аудит».
