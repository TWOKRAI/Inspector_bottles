План `plans/observation-port/plan.md`, ветка `feat/observation-port`. Цель — убрать шесть уникальных
машин плоскости уровней телеметрии, заменив их принципом **владение = путь**: каждый писатель
публикует только в своё поддерево `state.plugins.<писатель>.*`, спорить за имя становится
синтаксически невозможно.

**Закрыто на 2026-08-25: Ф0, Ф1, Ф2, Ф3.**

- Ф3.1 — `ObservationManager` как ЧЕТВЁРТЫЙ канонический слот рядом с logger/error/stats
  (`6ab55da8`, `4cc8cb7f`, `7302e08b`). Живёт в `statistics_module/observation/`, наследник
  `ChannelRoutingManager` по образцу `StatsManager`.
- Ф3.2 — записи порта в хаб наблюдаемости под родом `kind=observation` (`d6e4f615`, `005d8b2c`,
  `5300e56c`). Хвост и стор видят уровни без второго механизма; секция порта добавлена в
  существующую `introspect.observability` БЕЗ новой команды. ADR-SM-013.
- Ф3.3 — второго тестера не было СОЗНАТЕЛЬНО (правило «тестер один раз на механизм и ДО кода»);
  вместо него матрица из 14 инъекций и синхронное ревью → APPROVE-WITH-NITS, все ниты закрыты.

**Живой замер цены (стенд `multiprocess_prototype`, 8 процессов, плагин `capture`):** 3 метрики ×
1 писатель, 30 с → 18 записей в хаб, 18 доехало до хвоста, `dropped=0`, ровно **3.00 записи на тик**
при потолке `метрик × писателей`, темп 0.60 записей/с. Тик процесса — 5 с, и ручка `interval_sec`
быстрее тика не делает. Гейт закрыт по умолчанию (`telemetry.publish.default_enabled: false`,
белый список `{fps, latency_ms}`), поэтому в проде уровни плагинов НЕ едут никуда, пока гейт не
откроют — это и есть заявленное «под тем же гейтом, что и лист дерева».

**Открытые концы Ф3 — названы, не закрыты:**
1. GUI-вкладки `observation` нет: `_TABS` — тройка `log/error/stats`, presenter фильтрует по роду.
   Запись доезжает до GUI-процесса, и падать ей некуда. Плюс кнопка «Очистить» зовёт
   `clear(kind=self._kind)` — observation-строки из GUI не вычищаются ничем, кроме общего `purge`.
2. `backend_ctl/events.py` `_KIND_TO_PLANE` — тройка родов, `observation` попадает в `other`.
   Видно статически, запуском не подтверждено.
3. Ретеншен — ось стора: фан-аут за тик ограничен, суммарный объём нет. В дереве уровень стоит
   `O(1)`, в сторе `O(t)`; `max_rows` общий на все процессы и все роды.
4. sentrux `pass`, но 9 правил из 39 (бесплатный тариф).
5. Корневой гейт эти файлы не собирает — 7134 без изменений при 8794 → 8814 во фреймворочном.

**Дальше по плану:** Ф4 — политика одним glob (у неё в шапке стоит ОТКРЫТЫЙ ВОПРОС владельцу,
решить ДО задач фазы: glob сам по себе не делает добавление метрики бесплатным, пока гейт закрыт
по умолчанию). Затем Ф5 — обязательная завершающая: порт должен стать для ЧИСЕЛ тем же, чем
`LoggerCore` является для СТРОК — единственным писателем, а агрегация — видом поверх него. Исход
«три пишущих дороги остаются» объявлен неприемлемым.
