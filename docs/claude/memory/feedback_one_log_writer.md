Решение владельца 2026-07-27: «изначально у меня была идея что должен быть один
пишущий логгер-менеджер. нужно постараться сократить как можно сильнее
количество писателей».

**Why:** семь писателей — это семь представлений о том, что такое запись. Ф2.1
чинила ОДИН дефект (запись теряла имя источника) в трёх из них по отдельности
(коммиты 4ad94637, 180284c1, 4e2ed357). Один баг — три починки; следующий будет
так же.

**How to apply:** новый способ «записать строку» не заводить. Обстоятельство
(менеджера ещё нет / наследовать не от чего / нужен буфер) закрывается **видом**
поверх единственного писателя, а не новым классом. Целевая раскладка 2.2:
`LoggerCore` (писатель) + именованный view + одна аварийная функция.

**Единственное исключение — отказ самого писателя:** рассказывать о нём через
него нельзя (рекурсия в момент поломки). Но это функция на ~20 строк без гейта,
роутинга и конфига, в ОДНОМ месте — не класс и не второй писатель. И даже это
обязано быть подтверждено слом-инъекцией, а не объявлено.

**Закрываемое окно bootstrap** (ради `None` из `get_logger()` живут два класса):
ленивое создание менеджера + `reconfigure` на том же экземпляре. Оба препятствия
сняты уже сейчас — путь к файлу резолвится без конфига (env/temp), цикл импорта
снимается импортом внутри метода (так уже делает `FallbackLogger._lm()`).
