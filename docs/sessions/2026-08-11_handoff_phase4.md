## Что нужно знать, начиная 4.0 и 4.1

### Посылка 4.1 разошлась с реальностью — проверять заново, не сверять номера

План говорит «11 failed ×2 в полном прогоне». Наблюдается **другое и хуже**: полная
фреймворковая сьюта **падает целиком** —

```
Windows fatal exception: access violation
  logger_module/core/sampling.py:213 → test_sampler_ceiling_policy.py:292 (_hammer)
  тест: test_no_exceptions_under_a_storm_of_unique_keys
```

Проверено как положено: воспроизведено **на дереве без правок сессии, дважды подряд**;
тот же файл в одиночку — `10 passed`. То есть результата полного прогона нет вовсе, а не
«11 красных». Это зависимость от состава прогона — предмет 4.1, но форма другая.

### 4.0 — что предстоит

857 тестов в 15 каталогах вне обоих прогонщиков, из них 5 красных (4 в
`multiprocess_prototype/domain/tests/test_entities_roundtrip.py`, 1 в
`scripts/sync/tests/test_cli.py::test_list_shows_three_modules`). **Эти числа взяты из
отчёта прошлой сессии и в этой НЕ перепроверялись** — инвентаризация заново идёт первым
шагом. Страж `test_every_testpath_points_at_something_that_exists` усилен в 3.3 до «в пути
ЕСТЬ тесты» — новые записи он покроет.

## Уроки сессии, применимые к этапу 4

1. **Живой прогон судит проводку, тесты — механику.** Ручка `log_line_max_bytes` была
   объявлена в `StatsManagerConfig`, тест менеджера был зелёным — а из конфига приложения
   она не управлялась вовсе: дорога идёт через фасад `ObservabilityStatsConfig`, который
   транслирует только перечисленные ключи. `config.reload` дал `failed` на 8/8 процессов.
2. **Зонд может врать убедительнее кода.** Четыре дефекта подряд, каждый давал ложный
   вердикт: несуществующая команда → пустой список получателей → PASS по нулю отказов;
   сравнение голых МиБ/ч при плавающем числе снапшотов; сравнение строки файла с пределом
   на сообщение (~75 байт префикса логгера); и рестарт процесса, стирающий runtime-конфиг.
3. **`config.reload` не переживает рестарт процесса** — новый инстанс поднимается с конфига
   с диска. Для замеров «до/после» с рестартом нужны два прогона с разным конфигом на старте.
4. **Стенд `webcam_sketch` headless by design:** рецепт поднимает `HeadlessGuiProcess`, окон
   нет, метрик презентации нет. Нагрузка беднее окон F1 — строки ~1900 байт против 40–53 КБ.
5. **Инъекции ловят дефекты тестов, а не только кода.** Из 10 инъекций две первые редакции
   тестов оказались негодными: «предел в байтах» не краснел от подсчёта в символах, резерв
   под голос почти не сторожился.

## Гигиена, которую стоит сохранить

- Тяжёлые сьюты **не запускать параллельно живым замерам** — они искажают и темп, и байты.
- В рабочем дереве лежит **чужая незакоммиченная правка** `docs/direction/TECH_STACK_2026.md`
  (пересмотр msgspec/orjson). Не трогать, в коммиты не втягивать.
- Открытые находки прошлой сессии, не закрытые здесь: **П-9** (worktree агента 45.7 МиБ),
  **П-10** (28 из 34 зондов пишут мимо `logs_live/`), **П-11** (два противоположных правила
  приоритета конфиг/env, назван долгом в ADR-138).
