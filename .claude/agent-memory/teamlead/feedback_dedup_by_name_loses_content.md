Любой механизм «последний побеждает» (поколения досылки, дедуп очереди, коалесцирование
событий) обязан ключеваться на СОДЕРЖИМОЕ конверта, а не на имя команды/события. Как
только под одним именем поедут два разных payload'а, бедный конверт погасит богатый,
ничего взамен не привезя.

**Why:** ФР-1 / находка B-4-1 сквозного ревью Ф5 (2026-08-02, ADR-PMM-022). Поколения
досылки ready-gate велись на `command`; под `config.reload` ехали конверт switch'а со
слоем L2 и пустой фан-аут watcher'а. Поздний пустой гасил switch-конверт → protected-процесс
навсегда оставался на слое покинутого рецепта. Класс — «связка двух порознь верных правок»:
57 зелёных тестов досылки/брокера стык не смотрели ни одним.

**How to apply:** ключ дорожки = `(имя, ключи содержимого)`, гранулярность по КЛЮЧАМ
payload'а (по значениям каждое сообщение станет «новым родом» и перестанет гасить
предыдущее). Снятие — по правилу `any` (перекрыт хотя бы один ключ → конверт ещё нужен):
`all` объявляет частичное перекрытие полным и воскрешает тот же дефект. «Пусто» — не
отсутствие содержимого, а свой род: своя дорожка, иначе пустые перестают гасить даже друг
друга. Цена правила `any` — безвредный дубль, поэтому применимо только там, где команды
идемпотентны; иначе нужен явный порядок доставки.

тестов и совпал 5/5 (RF1=7, RF2=5, RF8=2, RF9=1, RF10=1); зонд —
`backend_ctl/probes/break_inject_review_fixes.py`, у него теперь есть фильтр по ID.
