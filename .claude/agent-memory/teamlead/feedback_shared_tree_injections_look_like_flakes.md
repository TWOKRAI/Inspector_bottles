Если по тому же рабочему дереву кто-то гоняет break-injection (пишет файл → прогон →
восстанавливает), твои прогоны начинают «мигать»: каждый раз падает ДРУГОЙ тест, а между
прогонами файл на диске цел и `diff` ничего не показывает.

**Why:** окно инъекции живёт секунды. Прогон, стартовавший внутри него, импортирует
покалеченный модуль; следующий — целый. Симптом неотличим от гонки в тесте, и лечить его
начинают там, где ничего не сломано. Измерено на Task 4.1 `telemetry-stage6` (2026-08-16):
за шесть прогонов покраснели пять РАЗНЫХ тестов, включая чистый юнит без общего состояния —
именно это и выдало причину: у такого теста флейка быть не может, значит менялся ИСХОДНИК.

**How to apply:**
- Прежде чем объявлять тест флейким, снимай md5 подозрительных исходников В ПОТОКЕ во время
  прогона (не до/после — до/после совпадут). Прогон, в котором набралось больше одной версии
  файла, к результату не относится, его надо перезапустить.
- Чистым считать только прогон, где дерево не двигалось И тестов красных нет; так и
  докладывать («3 из 3 при стабильном дереве»).
- Договориться о разделении: параллельные инъекции и прогоны — в разных worktree, иначе
  оба агента получают ложные факты (см. [[parallel-agents-commit-race]] — тот же класс,
  другая грань).
- Никогда не проверять «а как на HEAD» через `git stash` в общем дереве: соседний агент в
  этот момент читает файлы, а свою работу можно потерять целиком.
