Заменяя «прочитать значение по точному пути» на «прочитать поддерево и собрать
одноимённые листья», проверь ДВЕ вещи, которых у точечного чтения не было.

1. **Пусто → `None`, никогда `0`.** Нет поддерева, поддерево пусто, ни одного
   подходящего листа — сигнала нет. Ноль выглядит как измеренный ноль и, если
   механизм перебирает кандидатов «первый резолвящийся выигрывает», НАВСЕГДА
   заслоняет запасные пути. Правило починится «в одну сторону»: новый адрес
   заработает, старый умрёт молча. Инъекция «пусто читается нулём» покрасила
   13 тестов, из них 4 — существующих на плоском пути.
2. **Агрегация — сумма, а не первый.** «Первый резолвящийся» теряет рост второго
   писателя целиком (A стоит на 5, B растёт 0→50 → прирост 0). Сумма монотонна по
   каждому слагаемому. Цена называется вслух: величина суммарная по процессу, не
   по писателю. Нечисловой лист в сумму не входит и её НЕ отменяет — сломанный
   писатель теряет видимость сам, но не ослепляет соседей.

**Why:** ровно эти две развилки — тихие. Ни ноль вместо None, ни «первый вместо
суммы» не бросают исключений и не пишут в лог: правило просто перестаёт стрелять.

**How to apply:** пиши hazard-тесты парами «отсутствует поддерево» / «поддерево
пустое» — это РАЗНЫЕ ветки (`status: error` против `ok` со словарём), починка одной
не чинит вторую. Свойство «рост любого писателя виден» проверяй ОБЕИМИ
перестановками: одного сценария достаточно механизму, который смотрит на первого.
Двойную подстановку отвергай ГРОМКО (лог), тихий `None` неотличим от «правило мертво».
