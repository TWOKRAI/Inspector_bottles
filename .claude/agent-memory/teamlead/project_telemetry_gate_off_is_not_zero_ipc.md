Закрытый publisher-гейт телеметрии (`enabled=False` на всех метриках каталога) **не даёт
нуля IPC-сообщений**: `status` воркеров публикуется мимо гейта (always-on, ADR-PM-018), и
тик по-прежнему шлёт один `proxy.merge` на `processes.<name>` каждый тик — с одними
статусами и без единого числа. Обнуляется другое: **дельты** `state.changed`. `TreeStore.set`
возвращает `None` на неизменившемся значении, поэтому `merge` тем же статусом дельт не
порождает.

Воспроизведено 2026-08-14 (Task 3.2 `telemetry-stage6`): гейт закрыт на всех пяти метриках,
2 тика → 2 merge'а по `processes.camera_0`; `TreeStore` тем же `{"w0":{"status":"running"}}`
→ 1 дельта, потом 0, 0; смена на `stopped` → снова 1.

**Why:** критерий приёмки Ф3 сформулирован как «счёт `state.changed` по телеметрийным путям
за окно = 0». Померь вместо этого IPC-сообщения — получишь ненулевое число и прочитаешь
рабочую фичу как несработавшую. Полное обнуление сообщений потребовало бы вынести `status`
из тика, то есть тронуть инвариант фронтов.

**How to apply:** на живом стенде для «ноль трафика уровней» (3.3, развилка РТ-2 о флипе
дефолта публикации) считать ДЕЛЬТЫ по путям уровней, а не сообщения и не merge-вызовы. Тот же
разбор — ADR-PM-035. Связано: [[telemetry-publisher-gate]].
