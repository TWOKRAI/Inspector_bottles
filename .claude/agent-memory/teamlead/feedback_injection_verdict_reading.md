Когда слом-инъекция дала НЕ то, что предсказано, не спеши записывать тест в
вакуумные (или в «нашёл лишний баг»). Два механизма дают ложное расхождение, и
оба проверяются повторным прогоном, а не рассуждением.

**1. Не упало ничего → предохранителей было ДВА.** Свойство сторожится в двух
местах, и снятие одного оставляет второе. Task 3.3 `telemetry-stage6`: убрал
guard `if self._stopped: return` из `set_active` — ни один тест не покраснел,
потому что терминальность `stop()` проверяется ещё и в `_tick`. Снял оба —
упал ровно один нужный тест, свойство доказано. Вывод: **инъекция обязана
снимать ВСЕ пути, которыми свойство держится**; найди их grep'ом по флагу
(`self._stopped`), а не по одному месту, куда сам его писал.

**2. Упало лишнее → осколок аварии соседа в том же процессе.** В одном
pytest/Qt-процессе необработанное исключение из слота (например, инъекция
сломала parse и параметризованный кейс упал внутри QTimer-слота) роняет
состояние следующим тестам. Дважды за задачу «лишняя жертва» в изоляции
оказывалась ЗЕЛЁНОЙ под той же инъекцией. Вывод: **вердикт по инъекции
читать per-test, перепрогнав кандидата в одиночку** (`pytest путь::имя`), а не
по множеству упавших за прогон.

**Why:** без этих двух проверок инъекция врёт в обе стороны — объявляет
рабочий тест вакуумным (случай 1) и приписывает тесту чувствительность,
которой у него нет (случай 2). Оба вывода потом живут в отчёте как факты.

**How to apply:** предсказание пиши ДО прогона поимённо; на любое расхождение
— два действия перед выводом: grep всех точек, где свойство сторожится, и
одиночный прогон каждой «лишней жертвы». Расхождение объяснять
воспроизведением, а не версией. Связано с
[[feedback_prove_test_red_without_fix]] и
[[feedback_silent_detector_proves_nothing]].
