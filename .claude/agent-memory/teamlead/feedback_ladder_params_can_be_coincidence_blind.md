Тест на периодический отбор (`first_n` + каждая `M`-я) с параметрами `(0, 3)` остался ЗЕЛЁНЫМ под
инъекцией «фронт двигает счётчик потока»: при одном фронте на каждую потоковую единицу номер
удваивается, а `2n % 3 == 0` равносильно `n % 3 == 0`. Тест сверял совпадение, а не свойство.

**Why:** у периодических правил целый класс «поломок», сохраняющих остаток по модулю. Круглые
параметры (`0`, `1`, кратные друг другу) — ровно те, на которых совпадение вероятнее всего.
Найдено собственной инъекцией на Task 4.1 `telemetry-stage6`; без инъекции тест выглядел бы
доказательством.

**How to apply:** выбирая числа для теста периодичности, СНАЧАЛА посчитать ожидаемую
последовательность для сломанной версии и убедиться, что она расходится с правильной на первом же
шаге. Ненулевой `first_n` вместе с некратным `every_mth` (`(2, 3)`) разводит их сразу; `(0, M)` —
почти всегда нет. То же правило для любых тестов на «каждый N-й»: сэмплинг, троттлинг, ретеншен,
дельта-публикация.
