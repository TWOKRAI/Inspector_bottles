Исследование перед Ф2.2 (иерархия имён), 2026-07-27. Замеры на машине проекта (Win10, py3.12, min-of-rounds):
stdlib rejected debug() = 116 нс, isEnabledFor кэш = 78 нс; наш rejected целиком = 785 нс, через миксин со штампом = 1694 нс, гейт = 324–379 нс.
picologging 0.9.3: rejected ×1.9, accepted ×15 к stdlib — но проект заморожен (PyPI 2023, нет колёс 3.13+).
OTel Logs Python = статус Development, API ломается между минорами (1.39, 1.44); единственная библиотека со встроенным учётом дропов.
stdlib/structlog/loguru — учёта потерь нет ни у кого (handleError/catch=True → stderr или тишина).
**Why:** решение владельца — не начинать 2.2 без сравнения с готовыми; вердикт: рантайм не брать, взять семантику stdlib-резолва + конфиг-поверхность loguru filter-dict, из OTel только словарь полей.
**How to apply:** при работе над Ф2.2/Ф3 не перепроверять эти числа заново; при появлении соблазна «перейти на stdlib» — сначала вопрос трёх плоскостей на одном process-global дереве и Handler-контракта без accept/refuse.
