# Task brief — form for `tasks/<id>.md` and `tasks/<id>.<role>.md`

The task file the lead writes before a spawn; `python scripts/plans_ledger.py brief <id> --plan <plan>` turns it into
the spawn prompt (the task text from its first label onward + the standing blocks of `executor-brief.md`). The format
is ADR-ATL-004 §2 (`scripts/atlas/DECISIONS.md`); the readers below are code, so the rules are a contract.

**Readers:** `plans_ledger.build_brief` (needs TASK, ROLE, DESIGN, FILES, REDS, TESTS, OUT OF SCOPE); the spawn hook
`dev/hooks/lint-brief.sh` (DESIGN >= 3 lines, FILES <= 6, REDS <= 10 or `n/a`, REPORT); the plan gate
`TASK_INCOMPLETE` (Files, Acceptance, CHAIN); `atlas pack` (`## Открыто для лида` via `views._lead_parts`);
`atlas brief --check` (1.9b) and `atlas lint-brief` (1.9c). Contract test: `scripts/atlas/tests/test_formats_1_9d.py`
builds the two examples below.

## Rules

1. **One file — one role — one spawn.** `tasks/<id>.md` is the main brief, H1 `# Task <id> — <what>`, role = the writer
   (`developer`, `teamlead`, `junior`, `debugger`) or `lead` (solo). A second role goes to `tasks/<id>.<role>.md`,
   `<role>` ∈ {`tester`, `developer`, `teamlead`, `junior`, `debugger`}, H1 `# <id> — бриф <role>` — no word `Task`, so
   the plan counters do not see a second task. Spawn it with `brief <id>.<role>`. Suffixes `.result` and `.injections`
   are reserved. Never put a role's brief inside a fence: `build_brief` skips fenced lines.
2. **Lead's head** — everything before the first label; it never reaches the agent. Order: H1; «Основание: …»;
   `## Открыто для лида` (table `| № | вопрос | замер | умолчание брифа |`, rows `| О<n> | …`); `## Ревью стадии 0`
   (one line per round: `- р.<N> → reports/<id>.review-r<N>.md: <verdict>, Классы: …`); `## Инъекции (план)` until
   `tasks/<id>.injections.json` exists (form: `injections.md`).
3. **A label** is a line outside a fence matching `^[ \t]*([A-Z][A-Z \-/]{2,})(?:[ \t]*\(.*)?:` (one regex in
   `plans_ledger.py:429`, its mirror and `lint-brief.sh:75`). Main brief: TASK, ROLE, CHAIN, FACTS, DESIGN, FILES, REDS,
   ACCEPTANCE, TESTS, OUT OF SCOPE (+ TRAPS, HANDOFF IN). Role file: the same without FACTS and ACCEPTANCE. Allowed
   extras: FORBIDDEN PATHS, GUARDS, PROBE, COMMIT, REPORT (override the standing blocks), BRIEF-OVERRIDE.
4. **A label's body** — list items (`- `, `N. `), indented continuations, fenced blocks. Never a line that opens
   another label: an ALL-CAPS Latin word with `:` even when indented (`  API: x`), and for the plan gate also a list
   item or a Cyrillic ALL-CAPS word with `:` or a bold `**…:**` (`  - API: x`, `ВАЖНО: z`, `- **Итог:** x`).
5. **FACTS and ACCEPTANCE lines** — items with `- ` only (never `N. `): `- <what> — `command` → `literal``, or `→ exit <N>` for a return code. The dash is
   U+2014, the arrow U+2192, both with spaces; no backticks inside the command or the literal. The literal is an exact
   substring of the command's stdout+stderr run from the repo root; two pieces of output — two lines; bytes via
   `git cat-file -s <sha>:<path>`, never `wc -c` (CRLF on Windows). FACTS sit between `<!-- atlas:facts <sha7> -->`
   and `<!-- /atlas:facts -->`, `<sha7>` = the commit the literals came from; a fact that needs an uncommitted file
   goes to ACCEPTANCE. Until `atlas brief` (1.9b) the lead writes FACTS by hand in the same grammar.
6. **REDS** — `<path>::<test>` items, <= 10, or `n/a — <why>`.

## Example — main brief

Illustrative (K0 task 1.2): the shape is the contract; FACTS literals are not re-run against HEAD.

````markdown
# Task 1.2 — watcher перечитывает конфиг после записи (бриф, ред. 1)

Основание: строка Task 1.2 в `plan.md`; итог 1.1 — «Не проверено»: потеря второй записи в окне debounce.

## Открыто для лида

| № | вопрос | замер | умолчание брифа |
|---|---|---|---|
| О1 | debounce 1,0 с оставить? | две записи с паузой 0,05 с — одно событие | оставить; таймер перезапускается на каждое событие |

## Ревью стадии 0

- нет (раундов не было)

## Инъекции (план)

- таймер не перезапускается → `test_second_write_is_reloaded`

TASK: 1.2 — watcher перечитывает конфиг после второй записи в окне debounce   PLAN: plans/2026-10-07_k0-framework-quality/plan.md
ROLE: developer
CHAIN: tester (RED) -> developer -> lead (injections, review)

FACTS (generated by `atlas brief k0-framework-quality#1.2`; edit DESIGN, not this block):
<!-- atlas:facts 24a229e -->
- объект задачи — `python -m scripts.atlas ref config_module --symbol ConfigFileWatcher` → `tools/watcher.py:`
- потребитель в коде — `git grep -n "ConfigFileWatcher(" -- multiprocess_framework/modules/app_module` → `orchestrator.py:166:`
- радиус тестов — `python -m pytest --collect-only -q multiprocess_framework/modules/config_module/tests/test_watcher.py` → `8 tests collected`
<!-- /atlas:facts -->

DESIGN (decided by the lead — you type it, you do not derive it):
  1. `ConfigFileWatcher._on_modified` перезапускает таймер на каждое событие (`Timer.cancel()` + новый `Timer`).
  2. `_reload` под замком; флаг ожидания снимается до чтения файла, не после.
  3. `stop()` отменяет таймер и ждёт идущий колбэк; публичный API не меняется.

FILES (complete list — nothing else; need another file -> stop and ask the lead):
  1. multiprocess_framework/modules/config_module/tools/watcher.py — таймер, замок, `stop()`
  2. multiprocess_framework/modules/config_module/DECISIONS.md — строка о новом потоке

REDS (predicted red tests):
  - multiprocess_framework/modules/config_module/tests/test_watcher.py::test_second_write_is_reloaded

ACCEPTANCE (every number with its command):
  - тесты модуля — `python -m pytest multiprocess_framework/modules/config_module -q` → exit 0
  - новый тест собран — `python -m pytest --collect-only -q multiprocess_framework/modules/config_module/tests/test_watcher.py` → `9 tests collected`

TESTS: python -m pytest multiprocess_framework/modules/config_module/tests/test_watcher.py -q

OUT OF SCOPE: `DataConverter.save_to_file`, атомарная запись, `observability_reload.py`.
TRAPS: проверка «stop() сразу» не ловит гонку — пауза 0,2 с перед `stop()`.
HANDOFF IN: none
````

## Example — role file

````markdown
# 1.2 — бриф tester

Файл роли: спавн — `python scripts/plans_ledger.py brief 1.2.tester --plan plans/2026-10-07_k0-framework-quality`.

TASK: 1.2 — blind acceptance tests for the watcher reload after a second write (RED before code)   PLAN: plans/2026-10-07_k0-framework-quality/plan.md
ROLE: tester
CHAIN: lead (brief, stage 0) -> tester -> developer (makes these tests green) -> lead (injections, review)

DESIGN (decided by the lead — you type it, you do not derive it):
  1. Two writes 0,05 s apart inside one debounce window -> the reload callback sees the second content.
  2. The test waits by polling up to 5,0 s while fewer than 2 reloads arrived; never a fixed sleep.
  3. Each run builds its own watcher on a temp file; `stop()` in `finally`.

FORBIDDEN PATHS (no edits): multiprocess_framework/modules/config_module/tools/**
FILES (complete list — nothing else; need another file -> stop and report):
  1. multiprocess_framework/modules/config_module/tests/test_watcher.py — one new test

REDS (expected RED before code):
  - multiprocess_framework/modules/config_module/tests/test_watcher.py::test_second_write_is_reloaded

TESTS: python -m pytest multiprocess_framework/modules/config_module/tests/test_watcher.py -q

OUT OF SCOPE: other watcher tests, the implementation.
REPORT: STATUS (DONE|BLOCKED), file, collected and red counts, the reason each RED fails.
````
