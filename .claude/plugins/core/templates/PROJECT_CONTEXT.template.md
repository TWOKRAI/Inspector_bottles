# Project Context Registry

Summary registry of the project's per-module knowledge. Generated by the
`scripts/aggregate_context` script from per-module `CONTEXT.md` and `DECISIONS.md`.
Content between the markers is auto-generated, **do not edit by hand**.
Text outside the markers is hand-written and preserved on rebuild.

**Run:** `uv run --no-project python -m scripts.aggregate_context` (write) /
`--check` (CI gate).

**Conventions:**
- `<module>/CONTEXT.md` — lightweight per-module document (Purpose / Gotchas / …)
- `<module>/DECISIONS.md` — formal ADRs (numbered `ADR-{CODE}-NNN`)
- Global cross-module ADRs — in `docs/claude/DECISIONS/NNNN-*.md`
  (created via `/dev:adr`)

## How to add a new module with CONTEXT.md

1. Create `<package>/<module>/CONTEXT.md` from the template
   `.claude/plugins/core/templates/CONTEXT.template.md`.
2. Fill in at least `Purpose`. Other sections — as they accumulate.
3. (Opt.) If the module will have formal ADRs — also create
   `<package>/<module>/DECISIONS.md` from `.claude/plugins/core/templates/DECISIONS.template.md`
   with a unique `module_code:` in the frontmatter.
4. Run `uv run --no-project python -m scripts.aggregate_context` — the registry updates.
5. Commit both `CONTEXT.md`/`DECISIONS.md` and the updated `PROJECT_CONTEXT.md`.

## How to add a cross-module (global) ADR

Use `/dev:adr <title>` — creates `docs/claude/DECISIONS/NNNN-<slug>.md`.
These ADRs use the `ADR-NNN` format (no module code) and are not indexed
by the `aggregate_context` script — they have their own numbering and storage location.
