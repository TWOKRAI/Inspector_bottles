Запусти приёмку наблюдаемости **как потребитель** — зонд поднимает headless-стенд `inspection_full`
на порту 8765, проходит чек-лист (самоописание, чтение, ручки, задержки, ошибки, жизненный цикл)
и пишет таблицу вердиктов с цитатами наблюдений.

**Перед запуском — три проверки, без них вердикт ничего не стоит:**

1. Порт свободен: `netstat -ano | grep 8765` → пусто. Стенд эксклюзивен (PID-реестр и SHM-cleanup
   конфликтуют). Если занят — спросить соседние сессии (`ListAgents` → `SendMessage`), не убивать.
2. Дерево: `git status --short` — зонд не мутирует tracked-файлы, но соседи могут держать
   незакоммиченное; зонд грузит топологию из дерева как есть.
3. Ollama не нужна; MCP `backend-ctl` не нужен (зонд идёт голым `BackendDriver`), но если MCP-сессия
   параллельно держит соединение — её `self_cost` сдвигает счётчики строк.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m backend_ctl.probes.probe_observability_consumer_acceptance
```

Длительность ~135–155 с стенда. Артефакты: `logs_live/<дата>_qa-acceptance_<ts>/` —
`acceptance_results.md` (таблица), `acceptance_results.json`, `observability.db`, журналы процессов.

**Что читать после прогона:**

- Живой чек-лист с колонкой «статус в плане» и правилами честности:
  [`multiprocess_framework/docs/observability/ACCEPTANCE_CHECKLIST.md`](../../../../multiprocess_framework/docs/observability/ACCEPTANCE_CHECKLIST.md)
- Эталонный протокол прогона 2026-09-08 (51 строка, задержки, находки F1–F13, «где ошибался зонд»):
  [`docs/reviews/2026-09-08_observability-consumer-acceptance.md`](../../../../docs/reviews/2026-09-08_observability-consumer-acceptance.md)

**Как читать вердикты:** `PASS` только при непустом «наблюдал»; `NOT_REACHED` с причиной —
не поломка (топология без писателя чисел, правило «не мутировать общее дерево», функция в работе
у другой полосы); `UNVERIFIED` — задокументировано, не гонялось. Колонка «приёмник» говорит,
кто принял данные вердикта: если это наш драйвер, а не файл/SQLite/внешний коллектор,
вердикт проверяет и оснастку — урок otel Ф2.

**Когда запускать:** на фазовой точке closure/otel/line-sim и перед merge в `main`, не на каждой
задаче. Сравнивать с эталоном 2026-09-08: сдвиг вердикта по строке, где код не менялся, — находка.
Число строк за прогон эталоном не является (меняется задачами 4.13/4.14).

**Расширение:** новая функция наблюдаемости = новая строка чек-листа (семья, ручка, приёмник,
литерал ожидания ДО прогона) + шаг в зонде. Правила — §5 чек-листа.
