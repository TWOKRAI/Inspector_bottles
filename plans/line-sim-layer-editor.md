# Plan: Редактор слоёв объекта для line_sim

- **Slug:** line-sim-layer-editor
- **Дата:** 2026-09-21
- **Статус:** DRAFT — ждёт Task 3.1 + 3.1a плана `line-sim`
- **Ветка:** feat/line-sim-layer-editor (создаётся при старте, от ветки с закрытой 3.1a)
- **Родительский план:** [`line-sim`](line-sim/plan.md), контракт —
  [`phase-3a-layer-contract.md`](line-sim/phase-3a-layer-contract.md)

## Контекст

Слова владельца (2026-09-21): «должен быть редактор, похожий как в paint или фотошопе».
Движок `Services/line_sim` собирает объект из слоёв (`LayeredObject` ← `ScenePreset`), но
создать пресет можно только одним способом — написать YAML руками. Для диска (один
вырезанный спрайт) это терпимо. Для бутылки — тара, наполнение, этикетка, крышка, кольцо,
у каждого слоя смещение, масштаб, угол и диапазоны вариации — подбирать числа вслепую
нельзя: результат не виден, пока не запущен стенд.

Прецедент в истории git: `6116adf3:Create_bottles/generate_pyqt.py` (641 строка) — окно с
живым превью, у бутылки/крышки/кольца/этикетки видимость, смещение, масштаб, угол.
Перенимается идея, не код: набор слоёв там зашит в класс окна (новый продукт = правка
кода), мыши нет, рендер свой. Здесь слои — данные пресета, рендер — движка.

**Это не Photoshop.** Рисования, кистей, выделения, фильтров нет: спрайты приходят
готовыми (`Services/dataset_gen/tools/cut_real_disks` или любой внешний редактор).
Редактор делает одно — компонует готовые RGBA-слои в объект и пишет пресет.

## Цели

- Новый продукт заводится без правки кода и без ручного YAML: открыл редактор → добавил
  PNG-слои → расставил мышью → задал диапазоны → сохранил пресет → лента едет с ним.
- Что видно в редакторе, то и поедет по ленте: превью рендерит **тот же**
  `LayeredObject`, своего рендера у редактора нет.
- Эффект аугментации виден до запуска стенда: сетка случайных образцов по кнопке.

## Out of scope

- Рисование и ретушь спрайтов, вырезание из фото (это `cut_real_disks`).
- Редактирование сцены: лента, фон, камера, ROI, поток — это пульт (`line-sim` Ф6).
- Фотометрия (блик, размытие, гамма) — свойство сцены, Ф4.3, не слоя.
- Встраивание во вкладку прототипа: редактор — автономный инструмент (см. решения).
- Визуальные «призраки» границ диапазона на канве — сетка образцов закрывает ту же
  потребность дешевле; добавлять, если сетки окажется мало.

## Решения

- **Автономное окно, не вкладка прототипа.** Запуск:
  `python -m Services.line_sim.tools.layer_editor [preset.yaml]`. Прецедент —
  `Services/robot_comm/server/sim_monitor.py` (PySide6-окно внутри сервиса, флаг `--gui`).
  Решение владельца 2026-08-31 — симулятор самостоятелен, прототип о нём не знает;
  вкладка в прототипе это нарушила бы. Процессов стенда редактору не нужно, поэтому он
  **не ждёт** `GuiBootstrap` для generic-приложений, на котором стоит Task 6.3.
- **PySide6 только внутри `tools/layer_editor/`.** Критерий Task 3.1 «`from
  Services.line_sim import …` без PySide6» остаётся в силе: пакет `tools` не
  реэкспортируется из `Services/line_sim/__init__.py`.
- **Канва своя, не из прототипа.** Единственная `QGraphicsView`-канва проекта —
  `multiprocess_prototype/frontend/widgets/tabs/pipeline/graph/graph_view.py`; импорт
  `Services → prototype` запрещён правилом слоёв (`.sentrux/rules.toml`). Вынос канвы во
  `frontend_module` ради одного потребителя не оправдан. Приёмы drag смотреть там, код не
  импортировать.
- **Модель редактора — сам `ScenePreset`.** Отдельного «документа» нет: правка = новая
  копия Pydantic-модели, undo = стек словарей `to_dict()`. Вторая модель рядом с
  `ScenePreset` разошлась бы с ним на первом же новом поле.
- **Тестовый контент — демо-бутылка из истории git.** `6116adf3:Create_bottles/Images/`:
  `bottle.png` 656×850, `cap.png`, `ring.png`, `eticet.png` — все четыре проверены
  чтением, 4 канала (RGBA). На однослойном диске редактор проверить не на чем.

## Открытые вопросы

1. **Эффект налива** (`fill_level` — маска заливки по уровню, был в историческом
   `LayerImage`) — нужен ли в первой версии редактора или вместе с настоящим пресетом
   бутылок? Сейчас вынесен в Task 2.1 и помечен как необязательный.
2. **Один пресет — один класс объекта или каталог классов?** `ScenePreset` Task 3.1 несёт
   каталог классов (буквы). Для диска класс меняет один слой (букву), остальные общие.
   Редактору нужно правило «какой слой зависит от класса» — уточняется по факту контракта
   3.1, до старта Task 1.2.

## Execution order

### Phase 1: Редактор-компоновщик

#### Task 1.1 — Демо-пресет из нескольких слоёв

**Level:** Junior+ · **Assignee:** developer
**Goal:** многослойный пресет, на котором проверяются и движок, и редактор.
**Files:** `Services/line_sim/presets/bottle_demo.yaml`,
`Services/line_sim/presets/bottle_demo/{bottle,cap,ring,label}.png` (из `git show
6116adf3:Create_bottles/Images/…`), `Services/line_sim/tests/test_bottle_demo_preset.py`.
**Acceptance criteria:**
- [ ] `ScenePreset.from_yaml(".../bottle_demo.yaml")` грузится, слоёв ровно 4, у слоя
      `label` режим `augmented` с ненулевым диапазоном `offset_x_px`.
- [ ] Объект из пресета рендерится в RGBA выше 800 px по высоте (тара 850 px не обрезана
      канвой) с ненулевой альфой.
- [ ] 8 объектов с `seed` 1…8 дают не меньше 2 разных рендеров; с вырожденными
      диапазонами — ровно 1.
**Dependencies:** `line-sim` Task 3.1 + 3.1a.

#### Task 1.2 — Окно: список слоёв, панель параметров, превью, сохранение

**Level:** Middle+ · **Assignee:** developer
**Goal:** рабочий редактор без мыши на канве — уже полезный: всё, что умел исторический
стенд, но слои берутся из пресета, а не из кода.
**Files:** `Services/line_sim/tools/__init__.py`,
`tools/layer_editor/{__init__,__main__,window,layer_list,layer_panel,preview}.py`,
`tools/layer_editor/README.md`, `Services/line_sim/tests/test_layer_editor.py` (pytest-qt).
**Steps:**
1. `layer_list`: добавить PNG (не-RGBA — отказ с текстом, правило Task 3.1), удалить,
   порядок вверх/вниз, видимость, режим `static` / `augmented` / `defect`.
2. `layer_panel`: базовый трансформ (`offset_px`, `angle_deg`, `scale`); для `augmented`
   — пары «от–до» по полям `LayerAugment`; для `defect` — вероятность. Поля строятся
   **по схеме Pydantic-модели**, не руками: новое поле контракта появляется в панели само.
3. `preview`: рендер через `LayeredObject` после каждой правки (debounce ~50 мс); кнопка
   «случайные образцы» — сетка из 8 объектов с `seed` 1…8.
4. Открыть / сохранить / сохранить как — `ScenePreset.from_yaml` / `to_yaml`. Пути
   спрайтов в YAML — относительно файла пресета. Undo/redo — стек `to_dict()`.
**Acceptance criteria:**
- [ ] Открыть `bottle_demo.yaml` → сохранить без правок → файл по содержимому
      (`from_yaml(a) == from_yaml(b)`) не изменился.
- [ ] Правка `offset_px` слоя `cap` с `(0, 0)` на `(15, 0)` через панель → после
      сохранения и повторной загрузки у слоя `offset_px == (15, 0)`.
- [ ] Превью после этой правки **побитово** равно `LayeredObject(...).render()` для того
      же пресета и того же `seed` — редактор не рисует сам.
- [ ] Диапазон `lo > hi`, введённый в панели, не попадает в модель: поле подсвечено,
      «сохранить» недоступно, файл на диске не тронут.
- [ ] Undo после правки возвращает прежнее значение и в панели, и в превью.
- [ ] Тест с реальными объектами, без фейков: окно поднимается на `bottle_demo.yaml`
      под `pytest-qt` и закрывается без исключений.
**Out of scope:** мышь на канве (Task 1.3).
**Dependencies:** Task 1.1.

#### Task 1.3 — Канва: слой мышью

**Level:** Middle+ · **Assignee:** developer
**Goal:** то самое «как в Paint»: слой берётся мышью и ставится на место.
**Files:** `tools/layer_editor/canvas.py` (`LayerCanvasView(QGraphicsView)`,
`LayerItem(QGraphicsPixmapItem)`), правка `window.py`, тесты в `test_layer_editor.py`.
**Steps:**
1. Клик выбирает верхний слой, под курсором у которого альфа > 0 (не по bbox — иначе
   тара перехватывает клики по этикетке); выбор синхронен со списком слоёв.
2. Перетаскивание → `offset_px`; ручка поворота → `angle_deg`; угловая ручка → `scale`.
   Колесо — зум канвы, средняя кнопка — панорама.
3. Модель обновляется **на отпускание** кнопки (одна запись undo на жест); во время
   жеста двигается только `LayerItem`.
**Acceptance criteria:**
- [ ] Программное перетаскивание слоя `cap` на `(+30, −10)` px сцены (`QTest`) →
      `offset_px` в модели изменился на `(30, −10) ± 1`, панель показывает то же.
- [ ] Один жест перетаскивания = одна запись undo (не по записи на каждое движение мыши).
- [ ] Клик в прозрачную область верхнего слоя выбирает слой под ним.
- [ ] При зуме канвы 200 % перетаскивание на 60 экранных px даёт `30 ± 1` в `offset_px`.
**Dependencies:** Task 1.2.

### Phase 2: Эффекты слоя (после ответа на открытый вопрос 1)

#### Task 2.1 — Налив: `fill_level` как эффект слоя [НЕОБЯЗАТЕЛЬНО]

**Goal:** слой «наполнение» заливается до уровня 0…1 внутри своей альфа-маски; уровень —
диапазон в `LayerAugment`, недолив — дефект-вариант того же слоя.
**Контракт:** необязательные поля `fill_level` (`LayerSpec`) и диапазон в `LayerAugment`,
дефолт «нет эффекта» — пресеты без поля грузятся как раньше. Идея — из
`6116adf3:Create_bottles/generate_bottle_module.py` (`_generate_fill_mask`).
**Acceptance criteria:**
- [ ] `fill_level=0.0` и `1.0` дают разную долю залитых пикселей внутри маски: 0 % и
      100 % ± 1 %; `0.5` — 50 % ± 2 % по высоте маски.
- [ ] Пресет без поля `fill_level` рендерится побитово так же, как до задачи.
**Dependencies:** Task 1.2; затрагивает контракт `Services/line_sim` — отдельный заход
тестера на механизм налива.

## Порядок запуска задач

По стоящему правилу проекта: независимый `tester` до реализации (один раз на механизм:
1.1 — пресет, 1.2 — модель и окно, 1.3 — канва), break-injection по каждому заявленному
свойству, `reviewer` синхронно после каждой задачи. GUI-тесты, способные зависнуть
(`QTest`-жесты), идут с дедлайном, а не до таймаута сьюты.

## Риски

- **Контракт 3.1a изменится при реализации.** План написан до кода `Services/line_sim`;
  имена полей здесь — из спеки, не из кода. Перед стартом Task 1.2 сверить с фактическим
  `interfaces.py`.
- **Скорость превью.** Тара 656×850 × 4 слоя через `rotate_expand`/`composite` на каждую
  правку — не замерено. Если медленнее ~100 мс, превью рендерить в уменьшенном масштабе;
  сетку образцов — в фоне.
- **Права на спрайты демо-бутылки** — картинки из собственной истории репозитория;
  если среди них есть чужие изображения, заменить на нейтральные фигуры.
