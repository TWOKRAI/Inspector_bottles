## Решения по неоднозначностям

1. **Статус `**Статус:**` строки** читается как слово набора где угодно в строке (без скобок): `**Статус:** BLOCKED` нужен тесту.
2. **Пункт обрывается** на пустой строке, заголовке и любом другом пункте списка (в том числе вложенном не-Task). Иначе статусы из `Приёмка:` подпунктов утекали бы.
3. **Родитель без маркера** пропускается, только если следующий пункт раздела глубже по отступу.
4. **Чекбокс** `- [x] Task …` без слова набора статуса не даёт (`unknown`). `[x]` + статус не `done` и `[ ]` + `DONE` — `STATUS_CONFLICT`.
5. **STATUS_CONFLICT с заголовками:** сравнивается только явная строка `**Статус:**` в теле заголовка; чекбоксы и группа в строке заголовка не сравниваются.
6. **Дубли заголовков** в наборе из заголовков схлопываются (побеждает первый в порядке plan.md, затем phase-файлы по естественной сортировке).
7. **Таблица `✓`:** читаются `plan.md`, `tasks.md`, `tasks-*.md`; побеждает первое вхождение id. Строки `T-00`, `PROBE` по регэкспу из плана не задачи.
8. **Архив:** каталоги `_archive/<YYYY-Qn>/` раскрываются на один уровень; всё остальное в `_archive/` (файлы `.md` и каталоги) — отдельный план. Не-`.md` файлы пропускаются. Находок у архива нет.
9. **Блок-ограждения** ```` ``` ```` и `~~~`: внутри пункты и заголовки игнорируются.
10. **`total=0`, но задачи есть** (все снятые): `<progress value=0 max=1>` и подпись `0 из 0`, чтобы `max` был валиден.
11. **Вывод `--check`** при `--json` уходит в stderr, чтобы не портить JSON. Известные по базе блокирующие находки печатаются с пометкой «(известна, в базе)».
12. **`--sync-order`** не реализован (Фаза 2).

Не блокирует. В `--json` поле `unmarked`; в HTML чип `<span class="chip warn" data-chip="unmarked">` на `<summary>` и `data-unmarked="1"` на ячейках. Планы со списком дают `unmarked=0`. Правило «PENDING по умолчанию» не менялось.
