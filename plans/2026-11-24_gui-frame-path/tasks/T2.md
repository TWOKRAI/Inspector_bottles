DESIGN (decided by the lead — you type it, you do not derive it):
  1. Таймер на ключ: `QTimer` с `setTimerType(Qt.PreciseTimer)` явно; причина — `Coarse` привязан к сетке 15,625 мс и даёт 16,0 / 21,4 / 21,0 Гц вместо 20 / 25 / 30, `Precise` — 20,1 / 25,0 / 30,3. Период = `ceil(1000 / clamp(fps_limit or 60, 1, 60))` целых мс; причина — `int()` на 60 Гц даёт 16 мс = 62,5 Гц выше потолка, `ceil` даёт 17 мс = 58,8 Гц. Потолок 60 Гц: `0`/`None` -> 60 (дисплей не нужен чаще кадра монитора; решение 1 вердикта). Нечисловой/NaN `fps_limit` не роняет `set_keys` (О8). Обработчик таймера делает один `take(key)` -> `(item, age_s) | None` и один `sink(key, item)`; `None` — тик пропущен без вызова `sink`. Причина «таймер на ключ»: быстрый sender не голодит медленный, у каждого свой предел.
  2. Публичный API и жизненный цикл (одна фраза причины к каждому): конструктор `FramePump(mailbox, sink, parent=None)`; `set_keys({key: fps_limit})` — повторный вызов меняет период существующих таймеров, останавливает таймеры снятых ключей, перехватывает ключ, найденный сканом (рецепт может сменить набор дисплеев на живом процессе); `stop()` — идемпотентный, гасит скан и таймеры (закрытие окна не оставляет вызовов `sink` в разрушенный виджет); `stats() -> dict[key, dict]` — аксессор счётчиков (его читает T4); старт скана — внутри насоса при создании; часы для `busy_ms_total` и возраста — `time.perf_counter` (`monotonic` на Windows грубее); сбой `sink` логируется с ограничением частоты (иначе строка на тик на ключ).
  3. Ключ без настройки (О1): сканирующий таймер насоса (период 100 мс, тип не важен) вызывает `mailbox.pending_keys()`; ключ, которого нет в `set_keys`, получает таймер на 30 Гц (причина: 30 Гц — разумное умолчание дисплея; неизвестный sender в gui идёт в слот «main»). Ни один Signal кадр не несёт, поток-источник (`put`) Qt не трогает; `sink` получает весь item без изменений (`capture_ns`, `capture_ts`, `replay` насос не читает и не трогает).
  4. Счётчики на ключ: `shown`, `max_age_ms`, `busy_ms_total`, `errors`; `max_age_ms` — из `age_s`, который возвращает `take`. Исключение `sink` увеличивает `errors`, не останавливает насос. ПОПРАВКА ЛИДА (2026-11-24, по стадии 0 T4; причина: `stats()` читает поток heartbeat, а `set_keys` меняет словарь ключей в Qt-потоке): (а) `stats()` потокобезопасен — копия словаря счётчиков под одним `threading.Lock`, который держат и `set_keys`, и обновление счётчиков; чтение из другого потока во время `set_keys` не бросает `RuntimeError`; (б) к счётчикам ключа добавлен `window_max_age_ms` — максимум возраста с последнего вызова `stats(reset_window=True)`; `stats()` без аргумента окно не сбрасывает (второй вызывающий, например тест, не искажает окно); `max_age_ms` остаётся накопленным за прогон. Тест на (а) — потоковый hazard-тест вне REDS: читатель `stats()` в цикле, пока основной поток 200 раз вызывает `set_keys` с меняющимся набором ключей, `setswitchinterval(1e-6)` с восстановлением; тест на (б) вне REDS: два кадра с возрастами 40 и 10 мс, `stats(reset_window=True)` даёт 40, следующий даёт 10 после нового кадра.
