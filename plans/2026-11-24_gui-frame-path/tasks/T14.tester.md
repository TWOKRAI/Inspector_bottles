DESIGN (decided by the lead — you type it, you do not derive it):
  1. Input is raw YAML only: every `multiprocess_prototype/recipes/*.yaml` (glob, sorted; not `recipes/tests/fixtures`), read with `yaml.safe_load`; processes are `raw["blueprint"]["processes"]`, wires are `raw["blueprint"].get("wires") or []` (each `{"source": "<proc>.<plugin>.<port>", "target": "<proc>.<plugin>.<port>"}`). A pure helper `copy_out_violations(raw) -> list[str]` lives in your test file.
  2. Rule (final contract). A recorder process = a process with a plugin whose `plugin_class` is `"Plugins.io.frame_buffer.plugin.FrameBufferPlugin"`. A display process = a process whose `process_class` is `"multiprocess_prototype.frontend.headless_process.HeadlessGuiProcess"` or `"multiprocess_prototype.frontend.process.GuiProcess"`. For a sender S: targets = first dotted part of each `S.chain_targets` entry, plus first dotted part of each wire `target` whose `source` starts with `"S."`, minus S. Effective copy-out of S = `set(S["extras"]["copy_out_targets"])` when that list is present and non-empty, else the literal `{"gui"}`. Violation `"<S> -> <T>"` for every target T that is a recorder or a display and is not in the effective copy-out of S. Violation `"<S> copy_out_targets: <X>"` for every entry X of `copy_out_targets` that is not a process name of the recipe. Order: senders in recipe order; within a sender, target violations by target name sorted, then `copy_out_targets` violations in list order.
  3. Facts of the new recipe `rec_overload_synth` (written by the developer, not by you): processes `gui` (display), `camera_0..camera_3`, `rec_0..rec_3` (recorders); `camera_N.chain_targets == ["gui", "rec_N"]`; `camera_N.extras.copy_out_targets == ["gui", "rec_N"]`; wires `camera_N.synthetic_frame_source.frame -> rec_N.frame_buffer.frame` for N = 0..3. Every other recipe in the tree has no recorder, no `copy_out_targets` and zero or one display process (named `gui`; three recipes have no `gui` process at all).
  4. Scenarios. `test_every_recorder_target_is_copy_out` (one test, not parametrized): loop over all recipes; the dict `{stem: violations}` of recipes with a non-empty violation list equals `{}` (the failure message lists them); the set of recipe stems that contain a recorder process equals `{"rec_overload_synth"}` (the guard is not vacuous: red before the recipe exists). `test_guard_fails_on_recipe_without_copy_out`: load the real `rec_overload_synth.yaml`, deep-copy it per case: (a) unchanged -> `[]`; (b) delete `extras.copy_out_targets` of `camera_0` -> `["camera_0 -> rec_0"]`; (c) set `camera_1.extras.copy_out_targets` to `["rec_1"]` -> `["camera_1 -> gui"]`; (d) set `camera_2.extras.copy_out_targets` to `["gui", "rec_9"]` -> `["camera_2 -> rec_2", "camera_2 copy_out_targets: rec_9"]`; (e) remove `"rec_3"` from `camera_3.chain_targets` and from its `copy_out_targets` (wire stays) -> `["camera_3 -> rec_3"]`; (f) set `camera_0.extras.copy_out_targets` to `[]` (an explicit empty list means the default `{"gui"}`) -> `["camera_0 -> rec_0"]`; (g) set `camera_0.extras.copy_out_targets` to `["rec_9"]` -> `["camera_0 -> gui", "camera_0 -> rec_0", "camera_0 copy_out_targets: rec_9"]` (two target violations sorted by name, then the unknown-name one). To check your helper before the recipe exists you MAY build a model dict in a temporary directory (outside the repo tree, never committed) from the facts of item 3 and run the cases (a)-(g) on it by hand; the committed tests still read the real recipe.
  5. A missing `rec_overload_synth.yaml` fails inside a fixture with an assertion naming the path (ERROR, not collection failure). Literals, never values computed from the YAML under test. New file: `__all__` and a `Purpose:` line in the docstring.
