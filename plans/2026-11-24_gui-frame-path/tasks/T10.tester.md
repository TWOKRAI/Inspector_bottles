DESIGN (decided by the lead — you type it, you do not derive it):
  1. Tests use the real plugin and the real `TimeRing`; the context is a `MagicMock` built the way `Plugins/io/frame_saver/tests/test_frame_saver.py` does it (`ctx.config` holds the overrides, `ctx.registers = None`, `ctx.publish_metric` and `ctx.health` are mocks). Counters are read from the calls of `ctx.publish_metric(name, value)` (the last value per name). Expected values are literals from the ACCEPTANCE block of `tasks/T10.md`, never derived from the code under test.
  2. CONTRACT (the plugin files are closed to you, so these names are the whole interface): `Plugins.io.frame_buffer.plugin.FrameBufferPlugin`; `configure(ctx)`; `process(items) -> items`; the commands are looked up through `plugin.commands["buffer.range"]`, `plugin.commands["buffer.seek"]`, `plugin.commands["buffer.pin"]` and called as `getattr(plugin, plugin.commands["buffer.seek"])(data)` (the dotted names are valid: the registration passes them verbatim, checked by the reviewer); registers (config keys): `buffer_seconds`, `buffer_max_mb`, `pin_max_mb`, `jpeg_quality`. `buffer.range` returns `{"t_min_ns", "t_max_ns", "frames", "gaps"}`, a gap is `{after_seq, before_seq, missed, capture_ns, restart}`. `buffer.seek` takes `{t_ns, mode, max_width, max_height}` (a missing or `None` `max_width` / `max_height` means no limit on that side) (`mode` is `nearest`, `prev` or `next`) and returns a dict with `status` (`"ok"`, `"empty"` or `"error"`), `frame` (decoded BGR ndarray) and `capture_ns` of the real frame. `buffer.pin` takes `{t0_ns, t1_ns, tag}`. Published counters: `frames_in`, `encoded`, `enc_ms_p99`, `bytes_held`, `span_s`, `gaps`, `missed_seq`, `missed_device`, `rejected_no_capture_ns`, `encode_errors`, `lag_markers`, `rejected_order`, `rejected_oversize`, `rejected_invalid` (a `ValueError` of the ring). They are published at the end of EVERY `process()` call, including a call where all items are rejected or the item is a marker. The plugin class declares `accepts_markers = True`; a marker reaches `process()` as an ordinary item without `frame`.
  3. An item is a dict with `frame` (numpy BGR uint8), `capture_ns` (int), `capture_ts` (float), `seq_id` (int), optional `device_frame_num` and `group_id`. In EVERY test every frame item carries `seq_id` (an int, consecutive from 1 unless the test sets it otherwise) and `capture_ts`; an item without `seq_id` is rejected by design as `rejected_invalid` (the plugin uses `item.get("seq_id")` and the ring raises `ValueError` on `None`). The stamp is valid only when `type(capture_ns) is int` (a `float`, a `bool` and `None` are not stamps). A loss marker is an item without `frame` and `capture_ns`: `{"inspection_status": "not_inspected", "overflow_marker": True, "reason": "lag", "count": N, "capture_ts": float}`; it is counted in `lag_markers` by `count`, never in `rejected_no_capture_ns`, and is not put into the ring.
  4. Definitions as literals: `missed_seq` is the sum of `seq - prev_seq - 1` over accepted frames with `seq > prev_seq` (a restart, `seq <= prev_seq`, adds 0 and is a gap with `restart: True`, `missed: 0`); `missed_device` is the same over `device_frame_num` when it is not `None` on both neighbours; `gaps` is the number of gaps in the window (`len(buffer.range()["gaps"])`); `buffer.seek` fits the frame into `max_width` x `max_height` keeping the aspect ratio, rounding to the nearest integer, and never enlarges it; axis order: input `np.zeros((1080, 1440, 3), np.uint8)` gives the decoded `frame.shape` `(540, 720, 3)` for `max_width` 720, `(1080, 1440, 3)` for limits 4000 x 4000, `(300, 400, 3)` for `max_width` 720 and `max_height` 300; `at()` of the ring returns nothing outside the range for `prev` below `t_min` and `next` above `t_max` — the command answers `status: "empty"` and does not raise.
  5. A test that can block runs the call in a daemon thread with a join deadline. Each new `.py` has `__all__` and a `Purpose:` line in its module docstring. Flat-colour frames are BGR `(b, 0, 0)` with b = 40, 120, 200; the JPEG tolerance at q85 is 3 levels (measured by the reviewer, not a hypothesis). In the seek and pin tests `seq_id` 1, 2, 3, ... and `capture_ts` are set on every item. The text of an `error` answer carries no input values. The seq test: after the sequence 1, 2, 3, 7, 8 there is exactly ONE gap record (`after_seq` 3, `before_seq` 7, `missed` 3); after the restart (`seq_id` 1) there are two, the second with `restart` True and `missed` 0, and `missed_seq` stays 3. The pin test order: `buffer.pin` is called BEFORE the first frame (the ring protects future frames); frame values are in the ACCEPTANCE block of `tasks/T10.md` and were reproduced by a run on the real ring. The 100-frame test also checks `gaps` 0, `bytes_held` > 0, `span_s` == approx(3.96), `enc_ms_p99` >= 0.
  6. `cv2.imencode` is replaced with `monkeypatch.setattr(plugin_module.cv2, "imencode", fake)`; the fake calls the saved original on the 1st and 4th call, returns `(False, None)` on the 2nd and raises `cv2.error` on the 3rd; the plugin module must have `import cv2` at module level; the plugin must survive both failures and keep accepting frames.
