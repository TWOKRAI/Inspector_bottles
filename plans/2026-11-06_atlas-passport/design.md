## 1. Решения, на которых стоит план

**Три слоя, у факта один владелец** (источник: `cto-atlas-unified-tool.md` §A):
1. объявление в коде — владелец истины: первая строка докстринга, шапка `Tier:`, `__all__`, `interfaces.py`, `command_contracts.py` + оракул AST `process_module/tests/test_command_contract_oracle.py`, цель — `command_specs()` (форму выбирает Ф9.7, ниже); `params_schema` в паспорте — только ссылка `where`, не копия схемы;
2. `atlas` — единственный статический читатель: скан A1 → факты → индексы → паспорт → виды `ref`/`map`/`check`/`route`; рантайм не хранит никогда (`get_stats`, регистры, роутер);
3. живой каталог `introspect.*` и его клиенты (`backend_ctl`, GUI, консоль); атлас его не читает.

**Три правила против второго реестра** (источник: `cto-atlas-plans-review.md` §C(д)):
- **R1** — `scripts/atlas` не импортирует `multiprocess_framework|Services|Plugins`; тест-сторож в Task 4.1 (сегодня 0 таких строк — источник: там же, A10);
- **R2** — каждая запись `runtime.commands` несёт `where: файл:строка` и `how: declared`, иначе `atlas check` красный — Task 4.2a;
- **R3** — на стопе 3: статические имена команд модуля ⊆ `introspect.capabilities`, разница = счётчик `dynamic`, расхождение — находка; тест живёт в `process_module/tests`, не в атласе (иначе нарушен R1).

**Контракт паспорта Д1 и факты Д2** — `cto-atlas-path-verdict.md` §4, без изменений, плюс поправка Д1 из `cto-atlas-improvements.md` §A3: у каждой связи поле `scope: prod|test`. Д3: код — `scripts/atlas/passport.py`, `scripts/atlas/links.py`; `nav_bench` атлас не импортирует. Д6: sqlite = кэш, сгенерированного в git нет. Д7: qex, graphify — не зависимости.

**Форма объявления команд одна; её выбирает Ф9.7** (`f9-foundation-above-8-tasks.md:17-26`: `command_specs() -> list[CommandSpec]`), не этот план. Ф9.7 — отдельная фаза мастер-плана (решение владельца 2026-11-01), атлас её не поглощает. **Читатель атласа терпим к обеим литеральным записям** (вердикт CTO 11-07, правка 3, вариант (б)): элемент тела `command_specs()` — кортеж литералов **или** `ast.Call` с именем `CommandSpec` и литеральными позиционными/ключевыми аргументами; всё прочее (переменные, вызовы, comprehension) → «динамических: M», не «0». Это не второй реестр: форма одна — та, что выберет Ф9.7. `@expose` в Ф9.7 уже «Out of scope» (`f9-…-tasks.md:26`), Д4 поправлен в `cto-atlas-unified-tool.md` §D — отдельной строки в Ф9.7 про `@expose` не нужно.

**Два `ref` до A2 — осознанный дубль** (`cto-map-vision-advice.md:124`, вердикт 11-07 Q-H(5)): `reference.py` (старый текст `ref` модуля, оракул пинов) и `passport.py` (`ref --format passport|json`). При PASS С1 A2 сводит их; при KILL остаётся `passport.py` (он измерен), `reference.py` — FREEZE.

**Шапка FREEZE (для `status.frozen`, Task 4.2b):** строка докстринга модуля (`__init__.py` пакета или докстринг файла), начинающаяся с `FREEZE YYYY-MM-DD: <причина>; <ссылка>`; **не первая строка** (первая — `purpose`). Атлас ищет `^FREEZE \d{4}-\d{2}-\d{2}:` по строкам докстринга, только читает. Сегодня таких шапок 0 (`git grep -E '^(""")?FREEZE'` по `*.py` — пусто, проверено).

**Д5** (юниты по правилу «каталог с `__init__.py`», `modules.yaml` → исключения) — ждёт слова владельца (вопрос В1). До слова: Task 4.1 читает оба, расхождение — находка. Task 0.1 чинит yaml сейчас (fix forward), не дожидаясь Д5.
