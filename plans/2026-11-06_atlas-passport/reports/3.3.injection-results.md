## Расхождения

1. **F1, F2 — выжили; ошибка в моём тесте, не в коде.** В `test_load_targets_rejects_invalid` у Q1 одна запись `expected`, а
   `ids += len(argv) - 1` считает и опции: `["ref","S1","--format","json"]` даёт 3 id > 1 и падает на проверке `id > expected`
   раньше проверки опций. Все десять случаев `bad7..bad16` проходят ложно (ни один не доходит до `_forbidden_option`). Прогон
   FT-F1/FT-F2 показал, что исправление — тест на вопросе с тремя записями — их ловит. Не применено (по условию: новых тестов без
   доклада нет; `91e80712e` закоммичен). Для запрета флагов настоящей защиты в тестах сейчас нет.
2. **P3, P3b — выжили по построению: сброс пути стоит в двух местах** (при `== … ==` и при чтении второй строки паспорта). Каждый по
   отдельности избыточен; тест ловит только отсутствие обоих (P3c -> RED 2). Это не дыра в тесте: убрать любой одиночный сброс
   поведения не меняет. Прогноз «(г) без сброса -> RED 2» верен для P3c, неверен для одиночной инъекции.
3. **M3 — выжила.** Путь вне `root` и без проверки `relative_to` передаётся git как есть, `ls-files --error-unmatch` падает, код
   всё равно 2 с `ОШИБКА:`. RED 8 проверяет только код и `ОШИБКА:` (не «вне репозитория»), поэтому отличить проверку нельзя.
   Прогноз «RED 8» был неверен. Чтобы поймать: утверждать текст `вне репозитория` в stderr для `outside_t.json`.
4. **Лишние красные у P1, R2, X1, X2** — прогноз был неполным: эти правила и литералы используют RED 2, 3, 5, 7, 8 (P1), RED 7 (R2),
   RED 8 и RED 9 (X1), `git_failure` и RED 8 (X2). Названные в прогнозе красные есть во всех четырёх.
