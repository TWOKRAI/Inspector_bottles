DESIGN (decided by the lead; поправка 10):
  1. `ceiling` (П5). `bench.py ceiling --questions Q --reference R [--min N]`: какие ожидаемые адреса набора есть в
     JSON `R` (эталон 3.1 или вывод `atlas ref --format json`). Функции `reference_addresses(obj) -> set[tuple[str,
     int | None]]` и `ceiling(qset, addrs) -> tuple[list[str], int, int]` (строки отчёта, достижимо, оцениваемых)
     рядом с `verify_set`. Адреса — обход как в черновике Опуса (`scratchpad/improve-opus/ceiling.py`): словарь со
     строковым `path` задаёт путь потомкам; `path` + целый `line` → `(path, line)`; словарь с путём без ключа `line` и
     без `path_expr` → `(path, None)`; строка `^[\w./-]+\.\w+:\d+$` → `(путь, строка)`; строка `^[\w./-]+\.py(::.*)?$` →
     `(путь, None)`. Ожидаемый адрес достижим, если `score.location_matches("путь:строка" | "путь", exp)` у адреса того же
     пути; вопрос — по `require` (`all`/`any`), считаются `scored: true`. Вывод: строка на вопрос
     `<id> reachable=yes|no`, для `no` — `  <путь>:<line> ±<tol> -> нет в эталоне`, итог `ceiling <name>: K/N`. Код: 0;
     с `--min N` при K < N — 1; нет файла или не JSON — 2, `ОШИБКА: …` в stderr.
  2. Трасса (П7). `parse_session_output` (`bench.py:640`): `target` не меняется; рядом `entry["pattern"]` и
     `entry["glob"]`, если ключ есть во входе вызова. Старые записи не правятся, читатели трассы ключ не требуют.
  3. Предупреждения `verify-set` (П4). Новая `verify_set_warnings(qset, root, show_fn=git_show) -> list[str]`;
     `verify_set` и её возврат не меняются. `verify_set_command` печатает `ПРЕДУПРЕЖДЕНИЕ: <текст>` и строку
     `предупреждений N` после строки итога; код возврата — только по проблемам. Правила (`tol` — `tolerance` записи,
     иначе `score.TOLERANCE_LINES`):
     а) `note`: `tolerance (\d+)` или `(\d+)-line tolerance` — число не равно ни одному `tol` записей вопроса →
        `<id>: note: tolerance <n>, в записи tolerance <tol через ", ">`; `anchor line (\d+)` — не равно ни одной `line`
        → `<id>: note: anchor line <n>, в записи line <line через ", ">` (регистр не важен);
     б) вопрос `scored` и текст `question` ловит `(?i)\b(which|what)\b[^?]{0,40}\bfiles?\b`, а у записи `line` не
        `null` → `<id>: вопрос о файле, эталон требует строку: <путь>:<line>` (первая такая запись);
     в) путь из `exclude`, чей текст на `repo_sha` (`show_fn`) не `None` и равен тексту ожидаемого пути →
        `<id>: двойник <exclude> исключён, текст равен <путь>`;
     г) `.py`, `line` не `null`: ближайший `FunctionDef`/`AsyncFunctionDef` с `lineno < line ≤ end_lineno` (`ast` текста
        на `repo_sha`; `SyntaxError` — пропуск); окно `line ± tol` выходит за `lineno..end_lineno` →
        `<id>: окно <путь>:<line> ±<tol> выходит за <имя> (<lineno>-<end_lineno>)`.
  4. Колонка «файл» (П6, справка). `score.py`: `files_hit` в итоге `score_run` — число оцениваемых вопросов с адресами,
     где пути эталона названы в `locations` (по `require`; пути — `normalize_path` с `prefixes`, строки не важны), как
     V1 разбора r1 (поправка 9 п. 1). В `METRICS`, `aggregate`, `verdict` не входит. `render_markdown`: колонка
     `файл (справка)` сразу после `hits`, ячейка `files_hit/scored`; у старой записи без ключа — `н/д`; под таблицей
     строка «вердикт — только hits по правилу V3; `файл` — справка».
  5. `README.md` бенча: подкоманда `ceiling`, предупреждения `verify-set`, колонка «файл» — по абзацу.
