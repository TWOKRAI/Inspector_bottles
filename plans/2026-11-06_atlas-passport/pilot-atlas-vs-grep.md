## Метрика

**Основная — доля адресов:** из 22 адресов `expected` сколько назван в ответе (тот же путь, строка в окне ±3, `score.location_matches`), каждый адрес отдельно; по повторам берём медиану и min. Причина: у `fw2` `require: all` и 2–6 адресов на вопрос, строгое `hits` бенча (названы ВСЕ адреса вопроса) на Haiku даёт пол: в C0 на `r1` — 1 из 8 (запись 9). Оценка по адресам — без свободных параметров (запись 9 отвергла V1/V2/V3b именно за параметры; здесь окно и правило те же, что у бенча, а «частичный зачёт» — подсчёт, не вес).
**Рядом:** `hits` бенча (из 6), ложные, вызовы, токены (`final_context_tokens`, `cumulative_tokens`), секунды, число вызовов atlas, чтения вне копии, нарушения аудита.
**Диагностика только для atlas:** каждый адрес × повтор — «доставлен» (есть в тексте вывода вызовов atlas этого повтора; вызовы воспроизводятся по трассе) × «назван в ответе» → 4 класса. Для «не доставлен, не назван» — причина: atlas не звали на этот символ / `not found` / `ambiguous` / выдан, но мимо окна.

Скрипт: `reports/pilot-2026-11-11/analyze_pilot.py <запись grep> <запись atlas>`.

## Правило чтения (до прогона)

Сравнение медиан доли адресов, n = 3:

- **«сигнал есть»:** медиана(atlas) − медиана(grep) ≥ **4** из 22 **и** min(atlas) ≥ медиана(grep) **и** atlas звали в каждом повторе;
- **«сигнала нет»:** |разность медиан| ≤ **2**;
- **«неясно»:** разность 3 или условие min не выполнено — нужен повтор или больше вопросов (на `r1` у одного условия разброс повторов 4–11, то есть 7 адресов: порог 4 по n = 3 — на границе шума, поэтому «сигнал» — не вывод);
- **«вредит»:** медиана(atlas) ≤ медиана(grep) − 3, или токены atlas > 1,5× grep без прироста адресов.

Относительные пороги Kill-2 (`calls_ratio` ≤ 0,5, `tokens_ratio` ≤ 0,6) печатаются рядом как справка (ожидаемо не достигнуты).

Любой из этих исходов — запись 24+ в `amendments.md` с числами. Результат не меняет цели, потолки (записи 22–23) и вопросы `fw2`; «потолок ≠ польза» читается из пилота: чем больше доля «доставлен, не назван» — тем больше пробел в агенте/формате, чем больше «не доставлен» — тем больше пробел паспорта.

**Чтение по правилам, записанным до запуска.**
- Основное (A против B): «сигнал есть» не выполнено — atlas звали 1 раз на три повтора; разность B−A = 4 адреса — не вклад atlas.
- «База занижена» (D−A ≥ 3): нет, D−A = −1.
- «atlas экономит вызовы» (C ≤ 0,8·D): нет, C/D = 1,45; atlas звали 5, 5, 1 раз, а не ≥ 5 в каждом повторе.
- «atlas тратит впустую» (вызовы C > 1,2·D без прироста адресов): формально да (68 против 47, адресов +1), но разброс вызовов внутри D — 44–82, внутри адресов D — 8–19: это не вывод, а запись.
- Прогнозы: A (8–13 → 17) мимо; D (19–22 → 16) мимо; C (вызовов ≤ 40 → 68, atlas ≥ 10 → 1–5) мимо. Из трёх прогнозов сбылся лишь «экономии токенов нет».

**Что выяснилось (читать честно).**
1. **Различия между arm не отделимы от шума.** Медиана адресов 17 / 21 / 17 / 16, разброс повторов внутри одного arm до 12 адресов (A: 11–20, D: 8–19); n = 3 не годится для разности в 4. Пилот не показывает ни пользы atlas, ни вреда.
2. **Haiku почти не зовёт atlas даже при прямой инструкции:** в C — 11 вызовов на три сессии вместо «на каждый вопрос»; в B — 1 вызов. По умолчанию агент идёт в привычные `grep -n`/`find`/Read.
3. **Набор лёгкий для агента с оболочкой/grep:** 16–21 из 22 без atlas; потолок набора (≈ 95 %) не оставляет места для выигрыша по адресам. Выигрыш atlas, если он есть, лежит в вызовах и токенах, а они на этом пилоте у atlas не лучше (ratio ≈ 1,0–1,45 против порогов Kill-2 ≤ 0,5 / ≤ 0,6).
4. **Пробелы паспорта по реальным вызовам агентов (C):** из ~19 id в вызовах `ref`/`map` не ответ дали ~8: (а) голое имя метода или вложенной функции — `ref system_shutdown`, `ref as_generic_config` → `not found` без подсказки, хотя `ref BackendDriver.system_shutdown` и `ref ProcessConfig.as_generic_config` работают (проверено: `backend_ctl/driver.py:680`, `blueprint.py:306`); агент берёт имя из текста вопроса, где метод назван без класса; (б) `map <путь каталога юнита>` (`multiprocess_framework/modules/app_module`) и `map .` → `not found`, а `map app_module` (id юнита) работает; (в) `ref ProcessConfig` → `ambiguous` (два класса, один — в тестах) с двумя кандидатами; агент не повторил с путём; (г) `ref RecipeBlueprint` / `is_valid_window` — имена, которых нет (вымысел агента), `not found`. Пункты (а), (б) — дефекты паспорта: вход, каким агент его реально зовёт, даёт тупик.
5. **Метрика и инструмент.** `--allowedTools Bash(<шаблон>)` не запрещает остальной Bash: read-only команды (`ls`, `find`, `grep -n`, `cat`) Claude Code одобряет сам; в arm B агент ими пользовался вместо atlas, бенч пометил arm TAINTED (аудит `bash-pattern`, 27/7/16 нарушений; обращений к чужим путям нет — трасса проверена). Для чистого условия `atlas` (4.3, 5.1) нужен запрет по списку (`Bash(find *)` и др. в `disallowed_tools`) или сессия без Bash вовсе; границы «живая проверка грамматики `Bash(...)`» (`tasks/5.1.md`) этим закрыта отрицательно: грамматика ограничивает автоодобрение, а не набор команд.
6. **Kill-2 по порогам вызовов и токенов (≤ 0,5 / ≤ 0,6) на этом опыте недостижим** при Haiku и текущем способе подачи; это справка, не вердикт, но вопрос «что должен делать агент, чтобы atlas помогал» — главный для Fable-ревью.
