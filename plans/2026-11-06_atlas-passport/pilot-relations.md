**Проверка порядка (протокол раньше данных).** Коммит протокола должен быть предком коммита, в котором записи прогона
впервые попали в репозиторий, а сам протокол между ними может только расти (строки удалять нельзя, поправки —
дописываются в §11):

```
P=$(git log --diff-filter=A --format=%H -- plans/2026-11-06_atlas-passport/pilot-relations.md | tail -1)
R=$(git log --diff-filter=A --format=%H -- plans/2026-11-06_atlas-passport/reports/pilot-relations/records | tail -1)
git merge-base --is-ancestor "$P" "$R" && git diff --numstat "$P" "$R" -- plans/2026-11-06_atlas-passport/pilot-relations.md
```

Верно: код выхода 0 и во втором столбце `--numstat` (удалённые строки) — `0`. Иначе пилот читается как post-hoc.

## 2. Гипотеза и условие опровержения

**H1.** На вопросах-отношениях агент с Атласом (arm C) отдаёт множество адресов точнее (precision выше) при той же
полноте (recall), чем агент с grep/Read (arm A), или той же точности и полноты достигает заметно меньшим числом
вызовов/токенов. Arm B (только Атлас) показывает, сколько из потолка Атласа агент реально забирает.

**Опровержение («Атлас бесполезен на отношениях при текущей подаче»)** — записывается, если ВСЁ верно:
1. ни на Haiku, ни на Sonnet нет «сигнала» по §7 (ни по precision, ни по вызовам/токенам);
2. в arm B на вопросах с идеальным потолком Атласа ≥ 0,8 (A2, B1, D1, E1) медиана macro recall по повторам < 0,5 —
   то есть агент не забирает даже то, что Атлас выдаёт целиком.

При опровержении повтор на `rel1` без изменения инструмента или подачи не делается; вопрос «что менять» — Fable.

## 3. Метрики (все считает `relset.py score`, §10)

- На вопрос и повтор: **recall** = закрытых записей / записей; **precision** = адресов в паре / различных адресов
  ответа (без потолка `len(expected)+1`: у отношений длина ответа — часть метрики; пустой ответ — recall 0,
  precision не определена).
- На повтор: **macro recall / macro precision** (каждый вопрос — вес 1) — главные; рядом сумма верных/ложных/пропущенных.
- По повторам: **медиана и минимум**.
- Вызовы (`tool_calls`), токены (`cumulative_tokens` — расход, `final_context_tokens` — размер контекста).
- Для arm B и C: вызовов Атласа за повтор, **доля ошибочных вызовов** (`denied` / вызовы Атласа), «доставлен» и
  **«доставлен и назван»** (вызовы трассы воспроизводятся на тёплом кэше, `--replay-atlas`; модель не зовётся).
- Нарушения доступа (`violations`): любое в arm B — повтор недействителен (не входит в медиану, записывается).
- `hits` бенча (`require: all`) печатается справкой; это пол, не метрика.

## 4. Повторы: n = 6 на arm × модель

Шум первого пилота: внутри одного arm (Haiku, n = 3) разброс до 12 адресов из 22 (A: 11–20, D: 8–19). При n = 3
правило «min(C) ≥ медиана(A)» выполняется случайно с вероятностью около (1/2)³ = 12,5 % (каждый повтор C выше
медианы A с вероятностью ~1/2 при равных arm); при n = 6 — (1/2)⁶ ≈ 1,6 %. Медиана из 6 устойчива к одному обрыву
(D r3 первого пилота — ранний отказ модели). n = 6 — меньшее n, при котором правило §7 даёт ложный «сигнал» реже 2 %.

## 5. Arm-ы и модели

| arm | инструменты | что изолирует |
|---|---|---|
| A grep | Read, Grep, Glob + read-only оболочка (`grep`, `find`, `ls`, `cat`, `git grep/log/show`) | реальный агент без Атласа (первый пилот: база без оболочки не слабее, D−A = −1) |
| B atlas-only | Read + Атлас; Grep/Glob/оболочки нет | сколько из потолка Атласа агент забирает сам |
| C atlas+grep | A + Атлас, Атлас предложен первым, но не обязателен | польза Атласа там, где у агента есть всё |

Модели: **Haiku и Sonnet** (одни и те же arm-ы): отделить модель от инструмента. 3 arm × 2 модели × 6 = 36 сессий.

**Требования к условиям (condition-файлы — отдельная задача, здесь не создаются):**
- R1 (B, изоляция механизмом). Первый пилот показал: `--allowedTools Bash(<шаблон>)` не ограничивает read-only
  оболочку (arm B — TAINTED). Предпочтительно — **Атлас без Bash**: тонкий MCP-сервер stdio с двумя инструментами
  (`atlas_ref`, `atlas_map`, аргументы — id и разделы), `--tools Read` + `--strict-mcp-config`; Bash в сессии нет.
  Тогда и в C Атлас — тот же MCP (иначе B и C несравнимы по подаче). Запасной путь — Bash только с шаблоном обёртки
  плюс явный `disallowed_tools` на `Bash(grep:*)`, `Bash(find:*)`, `Bash(ls:*)`, `Bash(cat:*)`, `Bash(rg:*)`,
  `Bash(git:*)`, `Bash(head:*)`, `Bash(sed:*)`, `Bash(awk:*)`; допустим, только если одна пробная сессия показала
  отказ read-only команды (не автоодобрение). В обоих путях — аудит бенча (`bash-pattern`/список разрешённого).
  Выбор — лид; MCP-шим — новый компонент (оценка 60–100 строк), требует слова.
- R2. Обёртка (или MCP) подставляет `--ref 1e085652f`, `--root`, `--exclude` **восьми путей `rel1`** (не 43 пути
  `fw2`), `--format passport`; агенту доступны `--all <раздел>` и `--full` (без них потолок B1/A2 недостижим).
- R3. Подача (append-system-prompt) одинакова для Haiku и Sonnet; формы id — по тексту Task 4.7 (`Класс.метод`,
  `путь::Имя`, `map <юнит>`, `map <каталог>`); в подаче нет имён и путей из эталона.
- R4. Формат ответа бенча; в подаче для всех arm одна строка: «перечисли ВСЕ адреса множества в `locations`».

- R6. Порядок arm-ов в прогоне перемешан по повторам (A, C, B / C, B, A …), не блоками: дрейф времени суток и

## 7. Пороги чтения (для каждой модели отдельно; C против A)

- **«сигнал есть»**: (медиана macro precision C − медиана A ≥ 0,15 И min precision C ≥ медиана A И медиана recall C
  ≥ медиана recall A − 0,05) ИЛИ (медиана вызовов C ≤ 0,8 × A И медиана `cumulative_tokens` C ≤ 0,9 × A И медиана
  recall C ≥ A − 0,05 И медиана precision C ≥ A − 0,05); в обоих случаях Атлас вызван в каждом повторе C ≥ 3 раз.
- **«вредит»**: медиана recall C ≤ A − 0,10, ИЛИ `cumulative_tokens` C > 1,3 × A без прироста precision ≥ 0,05.
- **«сигнала нет»**: |Δ медиан recall| ≤ 0,05 И |Δ медиан precision| ≤ 0,05 И вызовы C/A в 0,9–1,1.
- Иначе — **«неясно»** (число записывается, вывода нет).
- **Модель или инструмент:** сигнал на Sonnet и нет на Haiku → «зависит от модели»; нет на обеих → инструмент или
  подача; B/потолок-идеал (macro recall B / 0,59) — доля потолка, которую агент забирает; < 0,5 → узкое место во
  входе/подаче, не в фактах.
- Таблица по вопросам читается описательно (n по вопросу мало), в вердикт не входит.

## 10. Пересчёт одной командой

```
python scripts/nav_bench/relset.py score --questions scripts/nav_bench/questions/rel1.json \
    <records>/<дата>_rel1_*.json --replay-atlas --marker <имя обёртки или MCP-инструмента>
```

Печатает по каждой записи таблицу «вопрос × медиана/мин recall и precision, доставлен, доставлен и назван», таблицу
повторов (macro recall/precision, верных/ложных/пропущенных, вызовы, токены, вызовы и ошибки Атласа, нарушения) и
строку `СВОДКА` (медиана/мин). Числа §11 берутся только из этого вывода (вывод кладётся рядом с записями).
Если R1 выберет MCP, `_atlas_uses` в `relset.py` нужно научить имени MCP-инструмента (сейчас считает вызовы Bash
с подстрокой `--marker`) — до первого прогона.
