# code-reader-gui — Фаза 3 — стенд и приёмка

Шапка плана, решения, общие правила и лимит итераций: [`../code-reader-gui.md`](../code-reader-gui.md). Статус задач пишется один раз — в разделе «Порядок выполнения» шапки.

### Task 3.1 — ⚑ Живой стенд: показ + настройки на новой камере
**Level:** Senior (не делегируется; сбор чисел — `haiku`) · **Assignee:** лидер · **Gate:** `heavy` (окно координатора)
**Goal:** числами подтвердить обе функции на железе и вернуть прибор в исходное состояние.
**Что переиспользуем:** `backend_ctl` (`state_get_subtree`, `send_command`), GUI в режиме
`INSPECTOR_GUI_UNATTENDED=1`, `qt-mcp` — только для скриншота дисплея; таблицу 2.1 как «исходные значения».
**Что НЕ пишем:** зонды и скрипты стенда — всё через существующие инструменты.
#### Шаги и приёмка
**Steps / Acceptance criteria:**
- [ ] ⚑ 20 срабатываний (12 с кодом, 4 без, 4 прикрытых) → 20 кадров в дисплее `main`; `draw` без ошибок;
      счётчики строки статуса на скриншоте последнего кадра = дерево.
- [ ] ⚑ Владелец подтверждает глазом: рамка лежит на коде (2 разных кода, 2 положения).
- [ ] Размер data-сообщения `reader_sdk → draw` без кадра ≤ 16 384 Б; `frame_pickle_fallbacks 0` в обоих процессах.
- [ ] Инспектор Pipeline: `exposure_time` → значение ×2 от исходного → `params.ExposureTime.cur` = новое;
      время перезахвата (от `register_update` до `device_state running`) — число; ⚑ средняя яркость кадра
      выросла (число по SHM-кадру или по скриншоту).
- [ ] `gain` +6 дБ — то же; `trigger_mode Off` → кадры идут без кнопки (частота — число, ≤ 30 с, затем
      обратно `On`); ⚑ после `On` кадры только по кнопке.
- [ ] Значение вне пределов прибора → `param_errors` с кодом, захват жив.
- [ ] Возврат: все параметры = исходные из таблицы 2.1, перечитаны и записаны в «Итоги»;
      `RunningMode` не менялся.
**Out of scope:** перезапуск питания прибора (сохранение в `UserSet` вне объёма — записать, что после
питания параметры вернутся к прибору).

### Task 3.2 — Документы сервиса + ревью фазы + приёмка `cto`
**Level:** Middle (документы) / Senior (вердикты) · **Assignee:** `tech-writer` (sonnet) → `reviewer` → `cto`
**Handoff:** `tech-writer` → `reviewer`(express) ; фаза → `cto` (S7, один раз)
**Что переиспользуем:** структуру `README/STATUS/DECISIONS` сервиса; `/core:quality:sync-context` после ADR.
**Что НЕ пишем:** отдельный документ «как настроить считыватель» — раздел в `README.md`.
**Files:** `Services/code_reader/README.md`, `STATUS.md`, `DECISIONS.md` (ADR-CR-010 «показ через `overlay` +
`overlay_draw`, без `code_view`»; ADR-CR-011 «параметры: явные поля, запись между Open и Start, правка =
перезахват»); `Plugins/render/overlay_draw/README.md` (`image/*`, `label_scale`); `plans/qr-code-reader.md`
(Ф3 → ссылка сюда, статус).
#### Приёмка
**Acceptance criteria:**
- [ ] Каждая цифра в STATUS — из «Итогов» этого плана, со ссылкой на задачу.
- [ ] Раздел «что ненадёжно» непустой; названы потолки решений 6, 8.
