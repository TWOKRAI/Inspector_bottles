## Порядок эффектов

- **Контракт — порядок списка в файле** (так уже работает `apply_effects`).
- **Схема проверяет только ступени:** `scene` (glare, shadow, occlusion) → `optics` (gaussian_blur, motion_blur,
  vignette) → `sensor` (brightness_contrast, gamma, color_temperature, channel_shift, noise) → `codec` (jpeg). Ступень по
  списку не убывает; внутри ступени порядок свободный и значимый.
- **Кто пишет файл** (конвертер ЛР-30, шаг миграции `train.augment`, место вставки в форме), берёт нынешний порядок
  `EFFECTS`, записанный литералом: glare, shadow, occlusion, gaussian_blur, motion_blur, vignette, brightness_contrast, gamma,
color_temperature, channel_shift, noise, jpeg.
- **Тесты:** литерал равен этим 12 именам; не убывает по ступеням; каждый зарегистрированный вид есть в литерале (новому
  виду — явное место); мост `augment_config_to_effects` выдаёт литерал.

## Тест тождества старого и нового адреса (ЛР-28)

Списки — литералы, снятые до переезда.

1. Каждый старый подмодуль `Services.layer_render.*` — тот же объект модуля, что новый.
2. Каждое имя из старого `__all__` — тот же объект, что в новом модуле.
3. То же для `dataset_gen.core.layer_scene`, `labels`, `symmetry`.
4. В чистом подпроцессе `import Services.imaging.layers` не грузит ни cv2, ни свои подмодули; импорт модулей схем не грузит
   cv2.
5. Подмена через старый путь видна живому коду.

## Общее правило

**Для README сервиса.** Функция под эталоном m4 меняет байты только через новую функцию или новый вид.
`DatasetEngine` зовёт живые `apply_effects`, `composite`, `get_background`, `procedural_background`,
`cast_contact_shadow`: это замороженный контракт. В m4 добавить случаи: три вида процедурного фона держит один случай
каждый (задачу вердикт не назвал).
