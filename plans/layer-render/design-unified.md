## 2. Коротко (первый экран)

1. Один сервис картинок — `Services/imaging`. В нём две части: `layers` (слои и обработка) и `draw` (рисование).
2. Генератор картинок один: симулятор, обучение и редактор зовут один код.
3. Старый генератор обучения замораживается: на выходе те же картинки, байт в байт. Всё его лучшее переходит в новый.
4. Сначала код переезжает на новое место, потом строится новое. Старый адрес ведёт к тому же коду, это не копия.
5. Один пресет на всё: объект, фон, эффекты, обучение. Старый пресет переводится сам при чтении; на диске он меняется,
   только когда его сохранят.
6. Эффект есть, только если он в списке. Порядок задаёте вы; программа не даёт поставить крупные группы задом наперёд
   (сначала сцена, потом оптика, сенсор, сжатие).
7. Опечатка в настройке — ошибка, а не тишина.
8. У повёрнутых объектов найден тёмный край. Чиним в новом пути; старый не трогаем.
9. Редактор — на Qt, веб-редактор заморожен. Не доказано, что вкладку можно сделать до новой оболочки: сначала проба.
10. Обучение переходит на новый генератор только после сравнения на реальных кадрах.
11. Возможности перечислены в таблице (матрице). Три сняты с причиной; судьба части строк ещё не решена.

**Где дизайн не согласен с первой группировкой владельца.** (1) Генерацию не кладём в `draw`: `draw` рисует и на реальных
кадрах, а генерация — это пресеты, каталог и правило случайных чисел. CTO согласен. (2) «`scene_source` = `DatasetEngine`»:
двойник `DatasetEngine` — `LayerSceneGenerator`; `scene_source` — процесс ленты, его картинку уже рисует `render_scene`.

## 3. Целевая система

### 3.1 Пакеты и направление импорта

```
Services/imaging/              __init__.py — только docstring: импорт draw не тянет layers
  draw/                        рисование: примитивы, шрифты, текст; стили и правила — схемы data_schema (план draw-universal)
    blend.py                   alpha_over — одна смесь по альфе (целая формула)
    fonts.py text.py scene.py backends.py mapping.py export.py geometry.py interfaces.py
  layers/                      слои и обработка (бывший Services/layer_render); __init__ ничего не грузит
    io compose layers background effects catalog metadata procedural_backgrounds
    preset preset_store factory scene crop preview
    samples.py                 LayerSceneGenerator — единый генератор обучения
    editing.py                 модель правки без UI: замороженный ScenePreset, история пресетов (для Qt)
    labels.py symmetry.py      метка, симметрия (SymmetryConfig — схемой), реестр классов
  tools/                       глифы, вырез дисков из фото, выравнивание, бесшовный тайл
```

Импорт: `imaging.draw` ← `imaging.layers` ← `line_sim`, `dataset_gen` ← `ml_train`; плагины ← прототип. Обратно нельзя.
Правила sentrux: перенести `.sentrux/rules.toml:157-177` на новые пути; добавить `imaging/draw ↛ imaging/layers`,
`↛ line_sim`, `↛ dataset_gen`, `↛ ml_*`; живой код ↛ старые пути `Services.layer_render.*`. Тест «импорт `draw` не
грузит `layers`» — в чистом подпроцессе. Схемы пресета — модули без cv2 и numpy (тест в чистом процессе): окно Qt берёт
схемы и модель правки без рендера. Старый `Services/layer_render/__init__.py` — отдельный пакет-фасад (раздел 4).

### 3.3 Единый генератор обучения (`LayerSceneGenerator`, ЛР-31)

Шаги одного сэмпла: класс → `ObjectFactory.render` → место (смещение, разброс) → фон (`solid` / `tile` / `photo` /
`procedural`) → тень (если задана) → `render_scene` с эффектами кадра → вырез → `resize_square` → метка.
Секция `train` пресета v2: `crop.size_mode: fixed | radius | fraction`, разброс центра в px или доле, смещение со знаком,
`label.angle_layer`, `symmetry`, `defect_probability`, `frames_per_class`. Эффекты — общий список `effects:` пресета.

Порядок розыгрышей — контракт, как сегодня (`layer_scene.py:15-19`); новые шаги разыгрываются только при включённой
опции и всегда в конце своего шага. Нет опции — ноль новых розыгрышей, эталоны 6.3.0 прежние.

Экспорт пишет паспорт набора: sha256 пресета, зерно, список эффектов. Зерно при этом не в файле пресета, а аргумент
CLI. Паспорт закрывает и случай «экспорт молча без эффектов».

Двойник пресета DE даёт **ту же постановку** (диапазоны, фоны, эффекты), но **не те же байты**: другой порядок rng и
холст слоёв (раздел 9, А2). Поэтому переход `ml_train` — только по замеру (ЛР-32, решение Р13, [планка](design-unified-migration.md)).

### 3.4 Где сервис кончается

Внутри — всё, что делает пиксели и их правду. Снаружи: лента, энкодер, спавн, сверка с роботом (`line_sim`); запись
набора и torch (`dataset_gen`); обучение (`ml_train`); процессы и команды (плагины `scene_source`, `layer_preview`,
`overlay_draw`). Плагины остаются тонкими хостами: `Services` не импортирует `Plugins`.

## 4. Переходные части и когда они уходят

| Часть | Зачем | Условие снятия |
|---|---|---|
| фасад `Services/layer_render/__init__.py` и старые имена подмодулей в `sys.modules` (ЛР-28) | старый публичный путь | **не удаляются** (принцип владельца 3). Фасад кладёт в `sys.modules` старые имена подмодулей, указывающие на новые модули, и повторяет нынешний `__all__` импортом из новых. Он жадный, как сегодня, и это не копия. Живой код его не импортирует (правило sentrux) |
| старые подмодули `dataset_gen.core.layer_scene`, `labels`, `symmetry` — те же объекты, что новые | то же | то же |
| ключи `train.augment`, `train.background_layers` | старые пресеты | шаг миграции v1→v2 (ЛР-39): при чтении ключ переводится в `effects` и `background`; файл меняет только сохранение |
| мост `augment_config_to_effects` | DE и конвертер | остаётся только у замороженных; живой путь его не импортирует (правило sentrux) |
| ключ `background_layers` в конфиге `scene_source` | стенд до переноса фона | после ЛР-05: `apps/line_sim/pipeline.yaml` и рецепты без ключа → ключ отвергается |
| `source: synthetic` в `ml_train` | повтор боевой модели | остаётся навсегда как путь замороженного DE; боевые пресеты уходят с него по Р13 |
| веб-редактор слоёв `pult_web` | работает, пока нет Qt | новых функций нет сразу; после паритета ЛР-17 — заморожен окончательно, не удаляется. Пресет v2 возвращает без потерь (приёмка ЛР-06) |
| конвертер `convert_to_layered` (ЛР-30) | `GeneratorConfig` — другой формат, цепочка версий его не заменит | разовый инструмент; замораживается вместе с `DatasetEngine` |

Своя смесь в `_fit_tile` переходной частью не остаётся: Р14 решено «да» (шаг 2). `EffectContext` обязателен, поэтому двух
поведений одной функции нет. Флагов «старое / новое поведение» в живом коде нет: новые опции — поля пресета с нулевым по
умолчанию действием.

## 9. Допущения

- **А1.** Спрайты каталогов нарисованы в масштабе камеры: эффекты в пикселях окна = в пикселях камеры. Для каталогов DE
  (256 px) не проверено.
- **А2.** Двойник DE не повторяет байты: проверено запуском (один слой через фабрику ≠ спрайт, RGB до 60) и чтением
  (порядок rng).
- **А3.** Повтор боевой модели требует байтов DE — поэтому DE заморожен, а не переведён.
- **А4.** «Не хуже» мерится протоколом letters-retrain 0.4; проход на симе нужен, но не достаточен; планка — решение Р13.
- **А5.** Поправка draw-universal (путь, `blend.py`, тест импорта) решена (Р5); в тот план ещё не записана.
- **А6.** Живой код зовёт `layer_render` из 19 файлов (`git grep`); `from Services import layer_render` не искал.
