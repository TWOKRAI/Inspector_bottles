## Запрос владельца (2026-10-01)

> «объединить механизмы и функционал, чтобы не было дублирования Симулятора со слоями и аугментацию… вынести
> отдельный механизм слоёв, чтобы было идентично и так и там. Чтобы сам механизм был мощный и гибкий… потом
> модернизировать — шумом, светом и т.п.»
>
> «фон тоже чтоб был из слоёв: нижний слой чёрный, а сверху такая же плитка. Короче универсальный механизм тоже»

Контекст второй цитаты: в плитке ленты сима (`data/line_sim/belt_tile.png`, RGB 410×484, непрозрачная, собрана из фото
`Services/line_sim/tools/make_seamless_texture.py`) просветы между звеньями — светло-мятные. Под реальной лентой чёрное.
Замер лида: по яркости V просветы не отделяются (медиана 79 против 78 у звеньев), отделяются по насыщенности/тону
(мятный) и по положению между зелёными бортами (борта сверху/снизу ~12–20 строк, S≈100, V≈190).

## Решение (архитектура)

Новый пакет **`Services/layer_render/`** — **ниже** обоих сервисов: `line_sim → layer_render`, `dataset_gen → layer_render`,
`layer_render` не импортирует ни одного из них; `dataset_gen` никогда не импортирует `line_sim` (цикл). Границы — в
`.sentrux/rules.toml` (Task 1.3), проверка — CLI `sentrux check .`, не MCP.

| Файл | Что | Задача |
|---|---|---|
| `background.py` | стек фона: `solid` + `tile` (RGB/RGBA, прокрутка с лентой), альфа-«over» снизу вверх | 1.1 |
| `crop.py` | ОДНА функция квадратного выреза + сторона по радиусу + ресайз к входу модели | 2.1 |
| `compose.py` | `composite`, `rotate_expand`, `crop_to_alpha`, `fit_longest_side`, `cast_contact_shadow` (переезд) | 3.1 |
| `layers.py` | `LayerSpec`, `LayerAugment`, `AUGMENT_FIELDS`, `canvas_size`, чистая `compose_layers()` (переезд) | 3.2 |
| `effects.py` | `EFFECTS: dict[str, fn]`, `EffectSpec`, `apply_effects(frame, specs, rng)`; канонический список из `AugmentConfig` | 3.3 |

Старые места импорта **остаются реэкспортом** — ни один потребитель не правится ради переезда. Имена полей слоя
(`offset_px`, `augment`, `color_rgb`, …) не меняются: на них стоит веб-редактор `Plugins/sim/pult_web/plugin.py:1126-1183`.
Реестра плагинов эффектов, Protocol «на будущее» нет: новый эффект = функция + строка в `EFFECTS`.

**Порядок сцены (один и тот же в симе и в генераторе):** стек фона (снизу вверх) → объекты (каждый — стек своих слоёв,
эффекты «материала» слоя из sub-rng слоя) → эффекты камеры/сцены на весь кадр → вырез → вход модели.

**Контракт rng (нарушение = красные золотые эталоны):** порядок розыгрышей `ObjectFactory.make` и `rng.spawn` на слой не
меняются; пустой список эффектов = ноль розыгрышей; эффекты сцены в симе — отдельный поток `default_rng([seed, 1])`;
ключ конфига отсутствует = кадр байт в байт прежний.

## Связь с letters-retrain

- **Task 0.1 letters-retrain («чёрный фон под лентой» через `--gap-fill` в инструменте) — ЗАМЕНЕНА** задачами
  **1.1 + 1.2 + 1.3** этого плана. Причина: красить просветы в RGB-пикселях плитки — частный случай; владелец попросил
  фон слоями («нижний слой чёрный, сверху плитка»). Плитка получает альфу (1.2), чёрный — отдельный слой (1.1, 1.3).
  Лиду: вычеркнуть 0.1 в `letters-retrain` со ссылкой сюда. Приёмка 0.1 переехала почти дословно в 1.2.
- **Task 0.2 (каталог букв по замеру, данные) и 0.3 (подпись всегда, `below_threshold`) — идут сейчас, здесь не дублируются.**
  Каталог 0.2 — обычный `catalog_dir` пресета; этот план его не трогает.
- **Ребро зависимости:** Фаза 1 letters-retrain (дообучение) стартует **после слияния Task 2.3** этого плана (а с ним —
  1.1, 1.2, 1.3, 2.1, 2.2). 2.3 даёт команду `python -m Services.line_sim.tools.export_sim_crops`, чей выход читает
  `ml_train` с `data.source: exported` без правок `ml_train`. Фазы 3–5 этого плана дообучение **не блокируют**.
- Task 0.4 letters-retrain (базовая линия) может идти сразу после 1.3 — ей нужен только сим с чёрным под лентой.

## Out of scope

- Собственные torch-аугментации `ml_train` (`config.py:60-64`) — работают на тензорах в DataLoader и угол не пересчитывают
  (запрет в `TrainConfig._check_cross`); сводить их с `effects.py` — отдельный вопрос после замера пользы.
- Свести две модели размера (px/мм сима против `object_size_frac` датасета): у них разные задачи. Генератор 2.2 идёт через
  px/мм — значит обучение получает реальный масштаб.
- Эффекты на слоях фона, процедурные фоны, анимация освещения во времени — когда попросят.
- Ветка `_background_only_frame` `scene_source` — остаётся сплошной заливкой.
- Дефекты в обучающих данных (letters-retrain: «диски будут без дефектов»; генератор ставит `defect_probability: 0`).

## Решения владельца — открыто (≤ 3)

- **О-1. Вырез в `holdout_eval`.** План держит его байт в байт (своя формула стороны `2·round(r(1+margin))`, replicate) и
  лишь переводит на общую функцию. Рекомендация: отдельным коммитом после Фазы 2 перевести на формулу конвейера
  (`2r·1.0 + 2·14`, pad) — тогда отложенная выборка мерит то, что реально получает сеть; старое и новое число — рядом.
- **О-2. Эффекты сцены из пульта (4.4)** — только живьём (по умолчанию в плане, пропадают при перезапуске) или с
  записью в `apps/line_sim/pipeline.yaml`. Рекомендация: живьём; запись — когда набор устоится.
- **О-3. `make_ru_letter_sprites` (5.2)** — байт в байт прежние эталоны (ядро получает режим «буква на белом диске») или
  новые пиксели с геометрией по замеру (высота/D ≈ 0.486). Рекомендация: байт в байт — от этих эталонов зависит
  воспроизводимость текущей модели `mobilenet_v3_large_20260616_050828`.

## Риски

- **Производительность кадра.** Альфа-смешение плитки (1.1) и эффекты сцены (4.1) — на каждом кадре 1440×1080.
  Приёмка обеих задач содержит замер медианы `render()`/`produce()` до и после; подсказка для 1.1 — сплошные слои под
  одной плиткой сворачиваются в непрозрачный тайл один раз при сборке.
- **rng-дрейф** при переезде (3.2) и при новых эффектах (4.1, 4.2) — ловят золотые эталоны выше; их нельзя
  «перезаписать под новый код» — красный эталон = находка.
- **Каталог фонов `dataset_gen` читает `IMREAD_COLOR`** (`core/catalog.py:245`): RGBA-плитка там потеряет альфу.
  Генератор 2.2 берёт фон из стека 1.1.
- **Угол метки** = угол паспорта + угол слоя класса; ошибка молча испортит обучение — приёмка 2.2 сверяет маски числом.
