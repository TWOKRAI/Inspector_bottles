## Запрос владельца (2026-10-01)

> «объединить механизмы и функционал, чтобы не было дублирования Симулятора со слоями и аугментацию… вынести
> отдельный механизм слоёв, чтобы было идентично и так и там. Чтобы сам механизм был мощный и гибкий… потом
> модернизировать — шумом, светом и т.п.»
>
> «фон тоже чтоб был из слоёв: нижний слой чёрный, а сверху такая же плитка. Короче универсальный механизм тоже»
>
> «не генератор букв, а генератор изображений или объектов. Так как он должен быть универсальным под разные объекты и
> продукты. Система слоёв и аугментации»

Плитка ленты сима (`data/line_sim/belt_tile.png`, RGB 410×484) непрозрачна; просветы между звеньями мятные, под реальной
лентой — чёрное. Замер лида: по V просветы не отделяются (79 против 78), отделяются по S/тону и положению между бортами.

**Рамка плана.** Результат — **универсальный генератор изображений объектов**: система слоёв, источников спрайтов и
аугментации для любых объектов и продуктов, одна и та же в симе и в обучении. Буквы на дисках — **первый продукт-потребитель**
(`letters-retrain`), не цель. Правило: в коде механизма нет ничего продуктового — классы, симметрии, слой, чей угол
идёт в метку, параметры выреза, джиттеры, шрифты и символы живут в **пресете и каталоге**. Новый продукт = пресет +
каталог, без кода. Проверка в приёмке каждой задачи с кодом: `grep -inE "letter|букв|disk|диск"` по новым/изменённым
файлам механизма (`Services/layer_render/`, `sim_crop.py`, `export_sim_crops.py`) — 0 совпадений вне примеров в README.

## Как сейчас

`line_sim` уже стоит на примитивах `dataset_gen`; дублируются источник «текст-глиф», вырез объекта, фотометрия (только в
`dataset_gen`), фон и модель размера — таблица с file:line в [context.md](context.md).

## Решение (архитектура)

Новый пакет **`Services/layer_render/`** — **ниже** обоих сервисов: `line_sim → layer_render`, `dataset_gen → layer_render`,
`layer_render` не импортирует ни одного из них; `dataset_gen` никогда не импортирует `line_sim` (цикл). Границы — в
`.sentrux/rules.toml` (Task 1.3), проверка — CLI `sentrux check .`, не MCP.

| Файл | Что | Задача |
|---|---|---|
| `background.py` | стек фона: `solid` + `tile` (RGB/RGBA, прокрутка с лентой), альфа-«over» снизу вверх | 1.1 |
| `crop.py` | ОДНА функция квадратного выреза + сторона по радиусу + ресайз к входу модели | 2.1 |
| `compose.py` | `composite`, `rotate_expand`, `crop_to_alpha`, `fit_longest_side`, `cast_contact_shadow` (переезд) | 3.1 |
| `layers.py` | `LayerSpec`, `LayerAugment`, `AUGMENT_FIELDS`, `canvas_size`, чистая `compose_layers()` (переезд) | 3.2 |
| `effects.py` | `EFFECTS: dict[str, fn]`, `EffectSpec`, `apply_effects(frame, specs, rng)`; канонический список из `AugmentConfig` | 3.3 |
| `sources.py` | источники спрайта слоя: `image`, `class`, `solid`, `glyph`, `cutout` — функции → RGBA | 5.1–5.3 |

Старые места импорта **остаются реэкспортом** — ни один потребитель не правится ради переезда. Имена полей слоя
(`offset_px`, `augment`, `color_rgb`, …) не меняются: на них стоит веб-редактор `Plugins/sim/pult_web/plugin.py:1126-1183`.
Реестра плагинов эффектов, Protocol «на будущее» нет: новый эффект = функция + строка в `EFFECTS`.

**Порядок сцены (один и тот же в симе и в генераторе):** стек фона (снизу вверх) → объекты (каждый — стек своих слоёв,
эффекты «материала» слоя из sub-rng слоя) → эффекты камеры/сцены на весь кадр → вырез → вход модели.

**Контракт rng (нарушение = красные золотые эталоны):** порядок розыгрышей `ObjectFactory.make` и `rng.spawn` на слой не
меняются; пустой список эффектов = ноль розыгрышей; эффекты сцены в симе — отдельный поток `default_rng([seed, 1])`;
ключ конфига отсутствует = кадр байт в байт прежний.

## Out of scope

- Собственные torch-аугментации `ml_train` (`config.py:60-64`) — работают на тензорах в DataLoader и угол не пересчитывают
  (запрет в `TrainConfig._check_cross`); сводить их с `effects.py` — отдельный вопрос после замера пользы.
- Свести две модели размера (px/мм сима против `object_size_frac` датасета): у них разные задачи. Генератор 2.2 идёт через
  px/мм — значит обучение получает реальный масштаб.
- Эффекты на слоях фона, процедурные фоны, анимация освещения во времени — когда попросят.
- Ветка `_background_only_frame` `scene_source` — остаётся сплошной заливкой.
- Вырез **некруглых** объектов по детектору: центр/радиус в конвейере даёт `circle_detector`, это свойство детектора, не
  механизма. Механизм готов: вырез генератора повторяет регистр `center_crop` (`size_mode: radius | fixed`), радиус
  генератора — по альфа-bbox объекта (описанная окружность). Некруглый продукт = `size_mode: fixed` в пресете; свой
  детектор (прямоугольник/поворот) — отдельный план, когда появится продукт.
- Источники спрайта без потребителя сегодня: процедурные фигуры, градиенты, шумовые текстуры, 3D — функция в `sources.py`, когда понадобится.
- Дефекты в обучающих данных (letters-retrain: «диски будут без дефектов»; генератор ставит `defect_probability: 0`).

## Решения владельца (2026-10-01)

- **О-1 → ДА, общая формула.** `holdout_eval` переводится на формулу конвейера (`2r·1.0 + 2·14`, pad) отдельным коммитом
  после Фазы 2; старое и новое число — рядом в отчёте, базу отложенной выборки перемерить один раз.
- **О-2 → только живьём.** Эффекты сцены из пульта (4.4) не пишутся в `pipeline.yaml`; запись — отдельной задачей, когда набор устоится.
- **О-3 → новые пиксели допустимы.** Пересобранные через общий источник каталоги (5.2) НЕ обязаны быть побайтно равны
  прежним; геометрия — по замеру (высота глифа 0.486·D, штрих 0.081·D для текущего продукта, см. letters-retrain).
  Следствие, принятое владельцем: старые модели (`mobilenet_v3_large_20260616_050828`) и прошлые замеры на старых
  каталогах точно не воспроизводятся. Старые каталоги не удалять — переименовать с суффиксом версии.

## Риски

- **Производительность кадра** (1.1, 4.1, кадр 1440×1080) — в приёмке замер медианы до/после.
- **rng-дрейф** при переезде (3.2) и при новых эффектах (4.1, 4.2) — ловят золотые эталоны выше; их нельзя
  «перезаписать под новый код» — красный эталон = находка.
- **Каталог фонов `dataset_gen` читает `IMREAD_COLOR`** (`core/catalog.py:245`): RGBA-плитка там потеряет альфу.
  Генератор 2.2 берёт фон из стека 1.1.
- **Угол метки** = угол объекта + угол слоя, названного в пресете; ошибка молча испортит обучение — 2.2 сверяет маски числом.
