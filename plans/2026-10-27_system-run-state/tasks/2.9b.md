## Ключ для «модель не загружена» — решение для 1.0: (1) по степени узла

| Форма | Цена | Риск |
|---|---|---|
| (1) `severity: {out_of_spec: check_function}` у узла `ml_inference` | 0 строк сверх 2.9; 3 строки YAML | ключ действует на ВСЕ `out_of_spec` узла: будущая вторая причина `out_of_spec` плагина тоже заблокирует START (отказ в безопасную сторону); копия куска YAML на узел камеры (`camera_device` 2.2c, «камера останавливается») заблокирует START там |
| (2) по префиксу текста | ~+10 строк разбора и проверки; текст причины становится API | правка текста в плагине МОЛЧА снимает блок (отказ в опасную сторону) |
| (3) необязательный `code` у причины | контракт: `_canonical_items`, `READINESS_REASON_KEYS` («лишних нет»), проверка монитора PM, плагин; ~25 строк в 4–5 файлах трёх модулей + ревью контракта | срок 1.0 не выдерживает |

Выбор (1): единственная `out_of_spec` плагина сегодня — эта причина, ошибка формы ведёт к блоку, а не к пропуску. Правило «на узле с ≥ 2 причинами `out_of_spec` форма (1) негодна» — в ADR-PM-061 (2.9, DESIGN п.9); страховка — пин-тест (DESIGN п.4). Цель `check_function`, не `failure` (решение лида): `failure` в плагине занят отказом ассетов; блок START и `fault` в работе одинаковы для обеих степеней (`run_state.py:44`, `schema.py:128`). Цена: пока 2.7 (S3a) не в main, PM дописывает «recog не готов» (`run_state.py:95-96`) — косметика.

Сим `letter_robot_sim` без ключа (стендовые не трогаем, решение лида). Цена: сим расходится с боем и не гоняет блокировку; её проверяет стенд п.5 на копии сима с ключом.
