## DESIGN

**Q2.** `_run_apply` пишет `self._run_ready = ready` на `tick` (как раньше) И на `settled`/`ack`, когда событие РЕАЛЬНО сменило состояние: `new is not prev` (условия `code is None` не нужно: отказы `settled`/`ack` состояние не меняют). Запись на `start` НЕ добавляется: принятый START всегда идёт с `ready=True`, а в `ready` входят только `tick`/`settled`/`ack`, которые уже пишут (запись на `start` — эквивалентный мутант). Условие `new is not prev` обязательно (REDS 8): `settled` — no-op с `code=None` в `ready`/`not_ready`/`running`/`fault`; без условия `settled(ready=False)` из `running` (перекрытие двух `topology.apply`) оставил бы `_run_ready=False`, и один сбойный такт дал бы `fault`. Отказанная команда `_run_ready` не трогает. Устаревший `tick` (m2) по-прежнему не применяется совсем.
Предусловие воспроизведения (литерал): такт без `beat` -> `_run_ready is False`; затем `_run_apply("apply")`, `beat`, `_settle_run_state()` -> `_run_ready is True`; потом один сбойный такт -> состояние не `fault`.

**Q3.** `_evaluate_or_fail` получает параметр `admission: bool = False` и пробрасывает его в `_evaluate_run_readiness` ТОЛЬКО ключом (`admission=admission`): подмены в соседних тестах принимают только keyword. `_cmd_system_run_start` и `_cmd_system_run_ack` зовут `_evaluate_or_fail(admission=True)`. Сбой даёт `ready=False` + причину `failure` «оценка готовности не удалась» + ERROR в лог с ТИПОМ исключения (текста исключения нет ни в логе, ни в ответе). Дальше обычный путь машины:
- START из `ready` -> отказ `not_ready` (смена состояния): `{"success": False, "state": "not_ready", "error": "not_ready", "reasons": [одна причина failure]}`;
- START из `not_ready`/`booting`: отказ без смены состояния — в ответе причины последнего такта, не причина сбоя (граница C10: причины оценки отказанной команды в статус не попадают);
- `ack` из `fault` с завершённой остановкой -> `not_ready`, `success=True`, `error=None` (штатный исход таблицы `transition`; отказ с неизменным `fault` потребовал бы четвёртого кода отказа и правки таблицы, а при постоянном сбое держал бы `fault` навсегда); следующий такт оценит заново; `last_fault.acknowledged_at` проставлен, причина сбоя — в `reasons` статуса.

**A6.** `_evaluation_failed` не бросает: чтение срока молчания обёрнуто; при исключении берётся умолчание срока `_READINESS_STALE_FACTOR * _DEFAULT_HEARTBEAT_INTERVAL_S` = 15.0 с (НЕ 5.0: 5.0 — интервал heartbeat; срок = 3 × интервал). Такт со сбоем `get_config` идёт обычным путём серии (`ready=None` до срока, `False` после).

Docstring у `_evaluate_or_fail`, `_cmd_system_run_start`, `_cmd_system_run_ack` обновить под «не бросает».
