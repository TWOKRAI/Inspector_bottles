DESIGN (decided by the lead — you type it, you do not derive it):
  1. `MLInferencePlugin.readiness(ctx)`: если `_asset_degraded` — `[("failure", self._asset_reason)]`, иначе `[]`. Чтение только полей, без `_engine_lock`, без IO (хук зовётся ~2 Гц из воркера снимка; под замком движка он замёрз бы вместе с загрузкой модели). После `_clear_asset_degraded()` причина пропадает сама. Формат возврата — как у `ProcessModulePlugin.readiness` (`plugins/base.py:1565`: пары `(severity, reason)`).
  2. `PluginOrchestrator`: плагин, пропущенный из-за `REQUIRES`, остаётся причиной: запись `(plugin.name, "REQUIRES не удовлетворены: <missing через '; '>")` в словарь пропущенных (`self._skipped_requires`), `readiness_snapshot` добавляет по ней причину `failure`, `node` по общему формату узла (как у причин плагина), `source` — как у причин плагина. Лог `log_error` остаётся. Запись живёт до `shutdown()`/следующего `configure_all`; повторный сбор не плодит дублей.
  3. Соответствие серьёзности (standards.md §9.2): ошибка конфигурации ресурса — `failure`. `out_of_spec`/`maintenance` в 1.6 не производятся.
  4. Рецепт с такой ошибкой при смене АКТИВИРУЕТСЯ (прежний отказ `recipe.activate` из C-55b.3 не существует); система после apply — `booting` → `not_ready` с причиной; START отказан. Решение В5 изменено этим пунктом (текст «старый остаётся» снят) — координатору на подтверждение владельцем.
