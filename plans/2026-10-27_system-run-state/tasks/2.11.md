## DESIGN

1. **Поле:** `paused_by: str` — имя первого плагина, который был в `PAUSED` и пропустил item без обработки. Смысл универсален: «кадр не прошёл всю цепочку из-за паузы run-state»; GUI и буквы не упоминаются.
2. **Bypass** (`plugin_runner.call_process`): разделить ветки. `enabled is False` -> как сейчас, без метки. Иначе `state == PAUSED` -> `outputs = items` (тот же список), каждому dict-item, кроме `is_marker`, `item.setdefault("paused_by", plugin.name)`. Обработанной ветки правка не касается.
3. **Перенос** — отдельная функция рядом с `_carry_system_fields`, вызывается там же (`paused_by` в `_CARRIED_SYSTEM_FIELDS` не кладём). 1:1 -> позиционный донор. Иначе -> выход без ключа получает значение **первого помеченного** входа (любого, не только `inputs[0]`). Выход — тот же объект, что вход -> ничего. Ключ плагин выставил сам -> не трогать.
4. **Липкость:** работающий плагин метку не снимает: кадр, который хоть где-то не обработан, остаётся «не обработан» до конца пути.
5. **GUI** (`_run_view_drops`): у display `running` при `run_gate is not False` item с непустой строкой `data["paused_by"]` -> `True` (не показан, плашка `WAIT` остаётся). Фильтр `capture_ts < mark` **удаляется** вместе с `_run["mark"]`: всё, что он ловил, ловит метка, а без метки он отбрасывал только честно обработанные кадры. `_fresh.clear()` при входе в `running` остаётся. Display `always` (превью) метку не смотрит.
6. **ADR-PM-066** в `process_module/DECISIONS.md` (065 занят 2.2e) + `python -m scripts.sync`. Докстринги `call_process` и `_carry_system_fields`.
