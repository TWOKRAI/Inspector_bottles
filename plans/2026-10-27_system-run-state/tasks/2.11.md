## DESIGN

1. **Поле:** `paused_by: str` — имя первого плагина, который был в `PAUSED` и пропустил item без обработки. Смысл универсален: «кадр не прошёл всю цепочку из-за паузы run-state»; GUI и буквы не упоминаются.
2. **Bypass** (`plugin_runner.call_process`): метку решает только `state == PAUSED`, `enabled` не смотрим. Причина: при `enabled=False` и `PAUSED` кадр не обработан и из-за паузы тоже; только `enabled=False` в `RUNNING` — выбор оператора, метки нет. `outputs = items` (тот же список), каждому dict-item, кроме `is_marker`, `item.setdefault("paused_by", plugin.name)`. Ветку `process()` правка не касается.
3. **Перенос** — отдельная функция рядом с `_carry_system_fields`, вызывается там же (`paused_by` в `_CARRIED_SYSTEM_FIELDS` не кладём). 1:1 -> позиционный донор; выход — тот же объект, что его вход, -> ничего. Не 1:1 -> **любой** выход без ключа (в том числе тот же объект, что один из входов) получает значение первого помеченного входа. Ключ уже стоит -> не трогать.
4. **Липкость:** работающий плагин метку не снимает: кадр, который хоть где-то не обработан, остаётся «не обработан» до конца пути.
5. **GUI** (`_run_view_drops`): у display `running` при `run_gate is not False` item с `data["paused_by"]` — `str` и не пустой -> `True` (не показан, `WAIT` остаётся). Проверка добавляется к фильтру `capture_ts < mark` 2.10, фильтр остаётся: он ловит обработанный кадр прошлого прогона после второго START (цена — несколько мс после START). Display `always` (превью) метку не смотрит.
6. **ADR-PM-066** в `process_module/DECISIONS.md` (065 занят 2.2e) + `python -m scripts.sync`. Докстринги `call_process` и `_carry_system_fields`.
