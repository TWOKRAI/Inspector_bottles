  1. `run_state.py`: все переходы design.md §3.2; `evaluate(expected: list[str], leaves: dict, alive: dict, now: float,
     stale_s: float) -> tuple[bool, list[dict]]` — причины design.md §3.3: нет листа (поле `readiness` в heartbeat отсутствует) или `readiness.at` (время расчёта снимка наблюдателем 1.2 v3) старше `stale_s` — **судить по `at`, а не по времени heartbeat** (мёртвый поток-снимок при живом heartbeat иначе выглядит готовым; `amendments.md` §6) →
     `failure` `source: liveness` «нет отчёта о готовности»; не жив → `failure` «процесс не жив»; иначе причины листа; лист свежий, `ready: false`, и среди его причин нет `failure` → добавить
     `failure` `source: report` «<процесс> не готов». Первый элемент результата `evaluate` (`ready`) = среди итоговых
     причин нет `failure` и нет `check_function` (К3: `check_function` блокирует START и в `running` равен потере
     готовности).
  2. Источник данных — память монитора: `_on_heartbeat_received` (`monitor/process_monitor.py:254-287`) сохраняет
     `msg["readiness"]` в `self._readiness[sender]` (новый dict на каждый heartbeat), `updated_at` = `readiness.at` (запасной — `_last_heartbeat[sender]` для процесса без снимка);
     PM публикует `processes.<n>.readiness` через `_state_op` (для GUI; no-op без state-plane). Гейт от state-plane не
     зависит. PM: `expected` = имена процессов текущей применённой топологии (процесс с ключом `run_required: false`
     исключается; умолчание `true`; GUI-процесс без `ProcessHeartbeat` отмечается так); `stale_s = 3 × heartbeat_interval`. Оценка на такте
     монитора PM и в `system.run.start`. Публикация `system.run.reasons`, `start_allowed`, `last_fault` (design.md §4).
  3. Boot/apply → `booting`; после барьера → `ready`/`not_ready` по `evaluate`. `running` + не готов → `fault`, снять
     `run_event` (без шагов `pre_stop`); `last_fault` = причины. `fault` липкий с этой задачи: готовность вернулась —
     состояние `fault`; выход — только `system.shutdown` (Task 1.7 добавит `system.run.ack`, В4). Признак
     `fault_stop_done` заводит Task 1.4. Замок держателя: тик монитора и команды пишут состояние через него.
  4. Барьер `_wait_processes_ready` и его тесты (design.md §2) не менять.
