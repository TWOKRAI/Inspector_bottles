DESIGN (decided by the lead — you type it, you do not derive it; форма флага — вариант Б, если cto по К7 не выбрал А):
  1. Флаг — поле внутри уже существующего `restart_policy` процесса: `run_auto_restart: bool = False`
     (`process_manager_module/core/restart_policy.py`). Поле доходит до `_process_configs[name]["restart_policy"]` как
     сырой dict без фильтра ключей (`process_monitor.py:1115`; domain `Process.restart_policy: dict[str, Any]`), новой
     проводки через рецепт нет. Монитор подменяет глобальную политику любым непустым dict процесса, а умолчание
     `RestartPolicy.enabled = False`: флаг без `enabled: true` значит «супервизор не поднимет процесс». PM читает флаг
     из сырого dict `_process_configs[name]["restart_policy"]`; флаг без `enabled: true` считается снятым, на boot —
     WARNING «run_auto_restart без enabled: true». Форма в рецепте: `{enabled: true, run_auto_restart: true}`. Вариант А (отдельное поле процесса) стоит четыре места —
     `topology/blueprint.py:133,:287`, `process_module/configs/process_launch_config.py:67,:178,:226`,
     `multiprocess_prototype/domain/entities/process.py:102` (`extra="forbid"`, страж AU-2 round-trip) — и Layer
     framework + prototype/domain; при выборе А FILES — эти файлы + тесты, RED +1 на цепочку «YAML рецепта → domain
     Process → proc_dict → `_process_configs[name]`».
  2. `run_state.evaluate(expected, leaves, alive, now, stale_s, *, running: bool = False,
     auto_restart: frozenset[str] = frozenset(), down_since: dict[str, float] | None = None, grace_s: float = 30.0,
     given_up: frozenset[str] = frozenset())`: только при `running=True` процесс из `auto_restart` без свежего листа
     или не жив, у которого `now - down_since.get(name, now) < grace_s` (нет записи в `down_since` — окно началось
     сейчас) и которого нет в `given_up` → причина `out_of_spec` «перезапуск <процесс>», `source: liveness`; `ready`
     остаётся истинным. При `running=False` (`ready`, `not_ready`, `booting`) флаг не действует: мёртвый процесс —
     `failure` «процесс не жив», START запрещён.
  3. `down_since` хранит PM (по тику монитора, под замком держателя); `given_up` = процессы, у которых
     `ProcessMonitor.get_supervision_snapshot()[name]["status"] == "failed"` (`process_monitor.py:1727-1746`). Правок
     `process_monitor.py` нет — только чтение публичного снимка.
  4. Окно истекло без готовности → причина `failure` «<процесс>: перезапуск не завершён за <grace_s> с»; процесс в
     `given_up` → `failure` «<процесс>: супервизор отказался от перезапуска» → `fault` (Task 1.3) → квитирование (Task 1.7). Процесс без флага — без изменений: падение в `running` → `fault`.
  5. Ребёнок после рестарта наследует взведённый `run_event` (design.md §3.4) — новой проводки нет (проверить, что
     рестарт идёт через ту же `create_process`, что и первый спавн, — RED на настоящем spawn).
  6. Окно `run_restart_grace_s` — ключ конфига PM (умолчание 30.0).
