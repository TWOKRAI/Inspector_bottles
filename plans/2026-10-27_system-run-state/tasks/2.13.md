## Факты (`main` `6aa7d0dad`)

- Режим DRAW есть только у `RobotDriver` (`mode`, `robot_driver.py:167`). У `RobotDriverV2` ключа `mode` нет; рецепты букв 1.0 (`delta_v2`) в DRAW не переходят.
- Флаг идущего рисования `_draw_busy` ставится до переключения режима и снимается в `finally` (`_execute_draw`, `robot_driver.py:384-415`). Режим можно увести из `draw` посреди рисования (jog, `set_mode`, смена инструмента); флаг при этом остаётся.
- Прошивка в DRAW (`mode == 1`) не вызывает `handle_vfd` (`robot/universal3/cvt_universal_full.lua:845`, `:925`); в manual, return, toolchange и cvt вызывает (`:973`, `:1002`, `:1029`, `:1051`). Записанная в DRAW команда лежит в mailbox до конца рисования. Версия на роботе не сверена.
- Во время DRAW драйвер ПЧ пропускает только фоновый опрос; `run` и `set_freq` пишет. Других путей записи в ПЧ мимо `VfdDriver.call` ревьюер не нашёл.
- Вкладка ПЧ ждёт `carrier.mode` и `protocol_meta.cmd_freq` (`vfd/controller.py:234-250`); `DeviceManager.describe` их не отдаёт. Диапазон частоты, который проверяет клиент: `entry.params.freq_min_hz` / `freq_max_hz` (умолчания 0 / 50, `Services/vfd_comm/core/config.py:27-28`).
- `VfdPresenter._request` отдаёт колбэку сырой конверт роутера (`vfd/presenter.py:112-120`); `controller._on_run` / `_on_set_freq` ответ не читают.
- Строку статуса вкладки переписывает push статуса (`_apply_vfd_status`); при `poll_interval_s: 0.5` — каждые 0,5 с.
- `VfdWidget.set_controls_enabled(False)` гасит и «Стоп» (`vfd/widget.py:144-148`).

## DESIGN

1. `RobotDriver.drawing` — свойство только для чтения, возвращает флаг идущего рисования.
2. `vfd_driver.py`, замок: носитель (`transport.type == "bridge"`, найден) и (`mode == "draw"` **или** `drawing` истинно). Режим читается при каждой команде. `busy` (движение, доставка задания) не блокирует.
3. Под замком `run` и `set_freq` возвращают `{"status": "error", "message": <постоянный текст со словом «DRAW», без значения частоты>, "error": <тот же текст>}` (`CommandManager` пишет в лог `reason` / `error`). В транспорт ПЧ ничего не пишется, счётчики `tx_ok` / `tx_err` не меняются, память последней частоты не меняется.
4. Под замком `stop` пишется как обычно и отвечает `{"status": "ok", "deferred": True, "message": <«... стоп может исполниться только после рисования ...»>}` — в DRAW прошивка исполнит его после рисования. Без замка ответ `stop` прежний. `reset_fault`, `get_status` без изменений.
5. Вкладка ПЧ получает метку отказа: `widget.set_refusal(text)`, атрибут `_lbl_refusal`. Push статуса её не трогает. Очищается при следующей команде и при смене устройства.
6. `controller._on_run`, `_on_set_freq`, `_on_stop` читают ответ через `devices_common.reply.unwrap_reply`. Отказ: `success is False` в конверте или в развёрнутом ответе, либо есть `status` и он не `ok` -> в метку `message`, без него «ПЧ: команда отклонена». `deferred` истинно -> в метку `message`. `{}` (нет связи с отправителем) — не отказ. Ответ по устройству, которое уже не выбрано, метку не меняет.
7. Диапазон частоты: каждая граница отдельно — `protocol_meta.cmd_freq`, иначе `entry.params.freq_min_hz` / `freq_max_hz`, иначе 0 / 50.
8. `set_controls_enabled` не трогает «Стоп»: он доступен всегда.

`describe` поле `carrier` не получает: это снимок на момент выбора устройства, кнопка осталась бы выключенной после конца рисования. В живой системе «Пуск» во время рисования остаётся нажимаемым, замок стоит в драйвере.

- «Стоп» во время рисования не останавливает ленту до конца рисования: так устроена прошивка. Проверяется только запись в транспорт.
- Окно между проверкой замка и записью: пуск, принятый до начала задания рисования, прошивка исполняет как обычно.
- `pause_all` смотрит только `status` и отчитается `ok` за отложенный «Стоп»; плагин калибровки так же напишет «Лента остановлена».
- Пока задание рисования ждёт свободы робота (`drawing` уже истинно, режим ещё `cvt`), замок отказывает, а `stop` исполняется сразу, хотя текст говорит «может исполниться только после рисования».
- Прошивка на самом роботе не сверялась; ПЧ во время программы `draw` у v2 не проверялся.
