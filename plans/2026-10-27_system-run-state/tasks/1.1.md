     состояние, код отказа; `event` — `start|stop|ack|fault|apply|shutdown|settled|tick`; `settled` — подъём/применение топологии
     закончен (`booting` → `ready`/`not_ready` по `ready`); `tick` — очередная оценка готовности (`ready` ↔ `not_ready`
     по `ready`; в `running` потеря готовности → `fault`, в `stopping`, `fault`, `booting`, `shutting_down` — no-op); итог
     STOP (`stopping` → `ready`/`not_ready`) — событие `settled`. Недопустимое событие в состоянии — возврат

     `stop_done` — «аварийная остановка завершена», читает только `ack` в `fault`). В этой задаче живут только `ready ↔ running` (+ отказ
     `already_running`); остальные — Tasks 1.3, 1.4, 1.5, 1.7.

     держателя состояния (тик монитора пишет в него же, Task 1.3). Состояние после boot
     = `ready` (готовность — барьер как сейчас; честная — Task 1.3). Публикация `system.run.state/since` через
