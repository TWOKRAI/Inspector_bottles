## DESIGN (лид; developer печатает, не выводит)

**П.1. Чистая модель (без Qt).** `widgets/chrome/run_control.py`: функция `build_view(snapshot: dict, busy: bool) -> RunView` (frozen dataclass), где `snapshot` — словарь листьев `{state, reasons, start_allowed, ack_allowed, last_fault}` (`since` не используется и в модель не входит), любые ключи могут отсутствовать. Поля `RunView`: `state_text`, `level` (`neutral|ok|warn|danger`), `start_enabled`, `start_tooltip`, `stop_enabled`, `ack_visible`, `ack_enabled`, `detail_text`, `indicators_text`, `fault_text`.
 - Имена состояний (литералы): `booting` «Поднимается», `not_ready` «Не готов», `ready` «Готов», `running` «Работает», `stopping` «Останавливается», `fault` «Авария», `shutting_down` «Завершение». Нет листа `state` или значение вне таблицы: ранний возврат — «Нет данных», `level=neutral`, все кнопки неактивны, `ack_visible=False`, остальные тексты пустые.
 - `level`: ready/running → `ok`; booting/stopping/shutting_down → `neutral`; not_ready → `warn`; fault → `danger`.
 - `start_enabled = bool(start_allowed) and state == "ready" and not busy` (уточнено по ревью кода 2026-11-16: PM публикует `state` раньше `start_allowed`, без проверки `state` в окне между дельтами ЗАПУСТИТЬ и ОСТАНОВИТЬ были активны одновременно) (отсутствие листа = False). `stop_enabled = state == "running" and not busy`. `ack_visible = state == "fault"`; `ack_enabled = ack_visible and bool(ack_allowed) and not busy`.
 - Неактивная ЗАПУСТИТЬ: `detail_text` = reason первой записи с `severity == "failure"`, иначе первой с `check_function`; если блокирующих нет — пусто (в `ready` причин нет). `start_tooltip` = все блокирующие причины построчно `node: reason` (failure раньше check_function; порядок внутри — как в списке). Блокирующие = `failure`, `check_function` (как `READINESS_BLOCKING_SEVERITIES`).
 - В `fault` правило ЗАПУСТИТЬ не действует (перекрыто): пока `ack_allowed` ложно — `detail_text = "идёт остановка"` (даже при `reasons` с `failure`); иначе первая причина из `last_fault.reasons`, при `last_fault` `None`/без причин — `""`.
 - `indicators_text` (В8): причины `out_of_spec` → «Вне допуска: r1; r2», `maintenance` → «Обслуживание: r1» (две части через « · »), только при `state == "running"`; цвет аварии не используют (`level` от них не зависит).
 - `fault_text`: при `last_fault` не `None`: «Последняя авария ЧЧ:ММ:СС — <первая причина>» + (« — квитирована ЧЧ:ММ:СС» если `acknowledged_at`, иначе « — не квитирована»); время — локальное `strftime("%H:%M:%S")` от `at`. Строка остаётся, пока лист не станет `None` (PM сбрасывает при успешном START).
 - Ввод нетипичен (reasons не список, запись не dict, нет ключей) — не бросает; пропускаются негодные записи.

## ACCEPTANCE (живая, окно машины, числами)

GUI + backend с `run_gate: true` (после 2.1 коммит B; до него — рецепт с гейтом через `BackendHarness`/ручной манифест): (1) после boot ЗАПУСТИТЬ неактивна до `ready`, в подсказке/деталях причина; (2) `ready` -> клик -> «Работает» ≤ 2 с; (3) ОСТАНОВИТЬ -> «Останавливается» -> «Готов»; (4) GUI, запущенный при уже `ready` PM, показывает активную ЗАПУСТИТЬ ≤ 5 с; (6) GUI, запущенный в `fault`: «Авария» и `RunFaultLabel` заполнена ≤ 5 с (единственный живой замер затравки: `set_commands` вызывается на `app.py` до цикла Qt — если ответ `system.run.status` теряется (`no_receive_pump`), затравка промахивается; решает приёмка, повтор затравки не закладывается заранее); (5) принудительная авария (`failure` в `running`) -> «Авария», «Квитировать» неактивна «идёт остановка», затем активна; клик -> «Не готов»/«Готов». Скриншоты — qt-mcp (`qt-mcp` на этой машине недоступен — тогда `backend_ctl` `state_get system.run.*` + скриншот владельца).
