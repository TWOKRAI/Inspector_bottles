## DESIGN (решено лидом; стадия 0 проверила)

1. **Источник правды — `system.yaml`.** `SystemConfig.run_gate: StrictBool = False` (отказ на `1`, `"yes"`, `"true"`, `"on"`, `2`, `"maybe"`, `[]`, `None`; Pydantic-ошибка несёт `input_value` — для флага не секрет). `SystemBuilder.build()` кладёт `sys_config.run_gate` в `orchestrator_config["run_gate"]`. Нет ключа — `False` (вердикт cto К1).
2. **Harness по умолчанию гейт НЕ включает.** `build_headless_launcher(recipe, with_base, log_dir, run_gate: bool | None = None)`: после `load_system_config(CONFIG_PATH)` (`harness.py:109`) `if run_gate is not None: sys_config.run_gate = run_gate` (приём `log_dir`, `harness.py:110-114`; `validate_assignment` помечает поле заданным). `BackendHarness(run_gate: bool | None = False)` — по умолчанию переопределяет манифест на `False`; `True` — включает; `None` — как в манифесте. При `launcher_factory` (`harness.py:411-417`) `build_headless_launcher` не зовётся: `run_gate=True` вместе с factory — `ValueError`; `False` (умолчание) — не действует, factory сам отвечает за гейт.
3. **`BackendHarness.start_run(timeout=30.0)`:** алгоритм один — опрос `system.run.status` до `start_allowed`, затем START; ответ `error == "not_ready"` — повтор опроса и START (запас от окна), всё в пределах `timeout`; вердикт — только по итоговому `state == "running"`; ответ самого START не судится, `already_running` не ошибка. Не наступило — `AssertionError` с литералами состояния и узлов-причин. Без гейта работает так же (START из `ready` допустим).
4. **Драйвер:** `run_start/run_stop/run_ack/run_status` — тонкие обёртки `self.system_command({"cmd": "system.run.<x>"}, timeout=...)`; возвращают конверт `process.command.response` как есть (разворот `result` — на вызывающем, через `_leaf_result`, `backend_ctl/protocol.py`). MCP: четыре `ToolSpec` по образцу `process_restart_verified` (`mcp_tools.py:831-854`); `run_status` — READ; `run_start`, `run_stop`, `run_ack` — WRITE.
5. **Стенды «как в бою»** (`stand_gate`, `capacity_bench`): пара флагов `--run-gate/--no-run-gate` (умолчание вкл). У `stand_gate` ключ метрики `first_frame_after_ready_s` (`run.py:378`, читает `analyze.py:310`, лежит в закоммиченных `reports/stand/2026-10-03_first-run/*.json`) ОСТАЁТСЯ как есть; новая точка отсчёта (от `start_run`, а не от boot) записывается в отчёт стенда, `analyze.py` и старые JSON не трогаем. Числа с гейтом и без него НЕСРАВНИМЫ. У `capacity_bench` такой метрики нет — для него критерий «гейт включён, замер идёт после `start_run`», метрики прежние.
6. **Пульт:** `run_gated: false` у `ControlPanelPlugin` во всех трёх рецептах (пульт должен работать в «готов»: кнопки робота — не работа линии).
