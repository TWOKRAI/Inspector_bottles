# Task R3c — ложные «разрыв revision» в StateProxy: вариант (в) (ADR-SS-015)

Основание: решение CTO в ревью 2026-11-20 (`docs/reports/2026-11-20_cto-review-1.0.md`, §3): «(в) сейчас, (а) после 1.0; протокол до β не менять»; запись `docs/claude/OPEN_QUESTIONS.md` 2026-11-20 «StateProxy: ложные разрыв revision…». Ветка — своя от main `dc56f14df`. Версия v2: правки стадии 0 (reviewer Sonnet, CHANGES REQUESTED 1 из 2, 9 пунктов — применены).

## Факт

`StateProxy._advance_revision_and_maybe_resync` (`multiprocess_framework/modules/state_store_module/proxy/state_proxy.py`, ~839-905) на `first_revision > _last_revision + 1` пишет WARNING «разрыв revision (ожидалось …) — запускаю resync» и шлёт `state.get_subtree` (ресинк). `revision` — счётчик всего дерева, пакет подписчика — min/max ревизий попавших дельт, поэтому узкая подписка при чужих записях видит «разрыв» ~4 раза/с без потери данных (стенд 20.11: 106–111 строк за 25 с до и после П3; DEBUG-счёт: 88 ресинков, 0 неудач). Шум WARNING принимают за потерю пакетов.

**Ограничение варианта (в), проверено пробами ревьюера на настоящем `StateStoreManager`+`StateProxy`:** клиент не может различить по исходу ресинка «потеря пакета» и штатные причины: (B) запись в подписанный путь между последним flush диспетчера и снимком на сервере (дельта в полёте), (E) собственная запись `proxy.set` под своим паттерном при `exclude_self=True` (по умолчанию; кэш `set()` не обновляет), (C) NaN-лист (`nan != nan`). Все три дают «снимок изменил кэш». Поэтому разделение «ложный/настоящий» точное только в одну сторону: `clean` — точно ничего не потеряно; `diverged` — потеря ЛИБО штатное расхождение. Это записывается в ADR, в текст WARNING и фиксируется тестами-характеризациями (REDS 8), а не абзацем.

## DESIGN (протокол и `state.changed` НЕ меняются; поведение кэша и ресинка НЕ меняется)

1. **Строка обнаружения** «разрыв revision … запускаю resync» — WARNING → DEBUG, отложенной (`lambda:` по docstring `_log_debug`, правило Ф1.4: путь ~4 раза/с). Каждое обнаружение считается в `gap_detected_count`.
2. **Определение «снимок изменил кэш»** (сравнение значений ДО и ПОСЛЕ применения снимка к кэшу, только по путям, которые снимок вправе писать, — защищённые пути окна (`is_protected`) НЕ считаются): путь ДОБАВЛЕН, путь УДАЛЁН (стёрт как устаревший), значение ОТЛИЧАЕТСЯ. Равенство: NaN равен NaN; `__eq__`, вернувший не-bool или бросивший исключение, считается «отличается». `_apply_resync_snapshot` возвращает список изменённых путей (сейчас `None`; вызовов вне `state_proxy.py` и тестов модуля нет).
3. **Что считается.** Счётчики классификации считают ИСХОДЫ ресинков, ИНИЦИИРОВАННЫХ разрывом (а не все ресинки и не все обнаружения). Таблица:

| Событие | Счётчик |
|---|---|
| разрыв → ресинк ушёл → ответ `ok`, снимок применён, изменённых путей 0 | `gap_clean_count` +1 |
| то же, изменённых ≥ 1 | `gap_diverged_count` +1 |
| ответ `status != ok`, таймаут, отправка не удалась (колбэк синхронно из `request_async`), `overflow` (снимок не применён), `value` не dict, `shutdown` посреди полёта (`_resync_patterns` обнулён) | `gap_unclassified_count` +1 |
| разрыв, но ресинк не стартовал (нет роутера, пустые `patterns`) | только `gap_detected_count` |
| разрыв во время идущего ресинка (совмещение, `_resync_again_pending`) | `gap_detected_count` +1; классифицируется ОДИН раз — исходом ДОГОНЯЮЩЕГО ресинка; разрыв-инициатор — исходом первого ответа; классификация первого — ДО вызова догоняющего `self._resync(patterns)` |
| прямой `_resync` не от разрыва (`RemoteStateProxy.on_reconnected`, `remote_state_proxy.py:243`) | счётчики +0 |

   Обе точки исхода: `_on_resync_response` И `_resync_blocking_fallback` (путь `IRouter` без `request_async` — публичный контракт, им бегут `test_watch_from_revision`/`test_state_proxy`; там нет защитника и совмещения). Происхождение ресинка («от разрыва») запоминается там, где `_resync` взводит `_resync_inflight_id` (одна присвоительная строка в `_resync` разрешена; форма — на усмотрение исполнителя, но колбэк, вызванный СИНХРОННО из `request_async` при сбое отправки, обязан застать флаг уже взведённым — тот же порядок, что для `_resync_inflight_id`).
4. **Публичные счётчики** на `StateProxy`, по образцу `confirmed_pattern_count` (~184): `gap_detected_count`, `gap_diverged_count`, `gap_clean_count`, `gap_unclassified_count` (int, только чтение — property без setter); метрики `state_proxy.gap_detected` / `gap_diverged` / `gap_clean` / `gap_unclassified` через существующий `_record_metric`.
5. **Логирование `diverged`** (решение лида в рамках варианта (в) CTO «ограничить частоту и вести счётчик»; решение по финальному уровню — за CTO/владельцем после стендового замера): WARNING, ТРОТТЛЕННЫЙ — не чаще одного раза в `_GAP_WARN_INTERVAL_S = 30.0` на экземпляр (часы — через атрибут, подменяемый тестом), в сообщении число накопленных с прошлой строки `diverged`, число путей последнего снимка и до 5 имён путей; значения НЕ печатаются; текст НЕ утверждает потерю: «снимок после разрыва revision изменил N путей (потеря пакета, дельты в полёте или собственные записи — не различаются)» и содержит слово «разрыв». Для `clean` — только DEBUG. Существующие WARNING «resync не удался» (~1023, ~1072) и про переполнение (~1085) остаются как есть.
6. **Документация:** ADR-SS-015 в `state_store_module/DECISIONS.md` — приписка «пересмотрено 2026-11-21: вариант (в)» (что изменилось; ограничение из «Факта»; (а) водяной знак — после 1.0) и строка индекса ADR (`DECISIONS.md` ~1019, `✅ Готово (пересмотрено 2026-07-11)` → дописать); `STATUS.md` (~101); `README.md` (~126, счётчики). После правок DECISIONS — `python -m scripts.sync`, затем `python scripts/validate.py`.
7. Подозрение из OPEN_QUESTIONS (пакет с `revision <= S` снимка отбрасывается без callbacks) воспроизвелось в пробе B (поздний пакет rev 4 отброшен, callbacks 0) — НЕ чинить; строкой в отчёт.

## REDS (настоящий `StateProxy`; без шпионов на имя метода; лог — захватывающий логгер через `proxy.register_manager("logger", cap)` (`_Stand` логгер не принимает; `_make_mock_logger` из `test_state_proxy.py` DEBUG выбрасывает — не годится; двойник обязан разворачивать `lambda`), метрики — через `register_manager("stats", cap)`; таймаут: `proxy._SYNC_REQUEST_TIMEOUT = 0.25` и `stand.spin(...)`, переполнение: `_RESYNC_DIRTY_MAX = 2`, образцы — `test_resync_whose_answer_never_arrives…`, `test_snapshot_is_skipped_entirely…`)

Шаг 0 (до тестов): заглушки трёх свойств классификации + `gap_detected_count`, возвращающие 0 — тогда красные 3–5 краснеют как `0 != 1`, а не `AttributeError`. Каждый из REDS 1–5 прогоняется на ОБОИХ стендах: fallback (`_RelayRouter`/`MockRouter` без `request_async`) и async (`_Stand`).
1. Дыра по ревизии, снимок равен кэшу → `gap_clean_count == 1`, `gap_diverged_count == gap_unclassified_count == 0`, `gap_detected_count == 1`; в логе ДО чтения счётчика: НЕТ WARNING со словом «разрыв», есть DEBUG обнаружения. (Поведенчески красен на базе: там есть WARNING «разрыв revision (ожидалось…)».)
2. Снимок изменил кэш тремя способами, по отдельному тесту: (а) значение отличается, (б) путь ДОБАВЛЕН (потерянный create), (в) путь УДАЛЁН на сервере (форма `test_gap_resync_removes_stale_deleted_path`) → `gap_diverged_count == 1`; WARNING ровно один (две строки WARNING — обнаружение и diverged — красный), называет число путей; кэш исправлен.
3. Ответ `status != ok`; таймаут; `overflow`; `value` не dict; `request_async` бросает (колбэк синхронно) → `gap_unclassified_count == 1`, остальные классификации 0.
4. Совмещение: второй разрыв во время идущего ресинка. Литерал формы `test_second_gap_during_the_window_does_not_start_a_parallel_resync`: первый ответ `{"foo":{"bar":2}}` rev 5 (`foo.bar` защищён) → `clean` +1; ответ догоняющего `{"foo":{"bar":3}}` rev 9 → `clean` +1; итого `clean == 2`, `diverged == 0`, `unclassified == 0`, `gap_detected_count == 2`; параллельного ресинка нет.
5. Путь, изменённый ДЕЛЬТОЙ в окне ресинка (защищён) и совпадающий с кэшем всё остальное → `gap_clean_count == 1`, остальные 0 (а не `unclassified`; снимок отличается от кэша ТОЛЬКО по защищённому пути; якорь «ресинк применён»: `_resync_completed_count == 1`). Добавленный путь здесь использовать нельзя — он сам делает разрыв `diverged`.
6. Не от разрыва / не стартовал: прямой `proxy._resync(patterns)` → все четыре счётчика +0; разрыв при `router is None` и при пустых `patterns` (образец `test_gap_triggers_resync_no_router_is_safe`) → `gap_detected_count == 1`, три классификации 0, исключения нет.
7. Контроли поведения (зелёные до и после): ресинк запускается на каждом разрыве как раньше; `_last_revision` продвигается как раньше; число запросов `state.get_subtree` то же.
8. Характеризации ограничения (фиксируют, а не оправдывают): (B) запись в подписанный путь между flush и снимком → `gap_diverged_count == 1` (поздний пакет rev ниже снимка отброшен, callbacks 0 — подозрение п.7); (E) собственная запись `proxy.set("foo.own", 7)` под своим паттерном при `exclude_self=True` → `gap_diverged_count == 1`; (C) равный NaN-лист → `gap_clean_count == 1`.
9. Счётчики — только чтение: присвоение → `AttributeError` (все четыре). Метрики `state_proxy.gap_*` приходят в захваченный stats (мутант «метрику не писать» краснеет).
10. Троттлинг: три `diverged` подряд в пределах 30 с (часы подменены) → один WARNING (накопленное = 1), четвёртый после 30 с → второй WARNING с накопленным 3; `gap_diverged_count == 4`.
11. `GuiStateProxy` (`_Stand(gui=True)`, образец гейта 8 в `test_resync_offthread_hazards.py`): один случай классификации (`clean`).

Break-injection (предсказания лида ДО прогона; патчи — на копии/вне коммита):
(а) вернуть WARNING на строку обнаружения → красны {1, 2} (в 2 «ровно один WARNING» увидит два), {5} и {3, 4}, если они проверяют тишину лога; (б) всё как `clean` → {2 (а–в), 8(B,E)}, плюс {3}, если мутант затрагивает и неудачные исходы; (в) не считать `unclassified` при неудаче → {3}; (г) двойной счёт совмещённого → {4}; (д) убрать `not is_protected(path)` в расчёте изменённых → {5}; (е) не классифицировать на fallback-точке → красны REDS 1–3, 5 на fallback-стенде; (ж) классифицировать прямой `_resync` → {6}; (з) property с setter → {9}; (и) не писать метрики → {9}; (к) без троттлинга → {10}; (л) классификация ПОСЛЕ догоняющего `_resync` (порядок) → {4}.
