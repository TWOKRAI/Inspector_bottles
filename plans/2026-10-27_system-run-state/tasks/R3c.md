# Task R3c — ложные «разрыв revision» в StateProxy: вариант (в) (ADR-SS-015)

Основание: решение CTO в ревью 2026-11-20 (`docs/reports/2026-11-20_cto-review-1.0.md`, §3): «(в) сейчас, (а) после 1.0; протокол до β не менять»; запись `docs/claude/OPEN_QUESTIONS.md` 2026-11-20 «StateProxy: ложные разрыв revision…». Ветка — своя от main `dc56f14df`, не от `fix/run-state-p3-node-read`.

## Факт

`StateProxy._advance_revision_and_maybe_resync` (`multiprocess_framework/modules/state_store_module/proxy/state_proxy.py`, ~839-905) на `first_revision > _last_revision + 1` пишет WARNING «разрыв revision (ожидалось …) — запускаю resync» и шлёт `state.get_subtree` (ресинк). `revision` — счётчик всего дерева, пакет подписчика — min/max ревизий попавших дельт, поэтому узкая подписка при чужих записях видит «разрыв» ~4 раза/с без потери данных (стенд 20.11: 106–111 строк за 25 с до и после П3; DEBUG-счёт: 88 ресинков, 0 неудач). Шум WARNING принимают за потерю пакетов.

## DESIGN (протокол и `state.changed` НЕ меняются; поведение кэша и ресинка НЕ меняется)

1. Строка «разрыв revision … запускаю resync» — с WARNING на DEBUG.
2. Ложные и настоящие разрывы считаются РАЗДЕЛЬНО. Определение (клиент не знает причину разрыва, судит по исходу ресинка): разрыв — «с расхождением» (`diverged`), если применённый снимок ресинка ИЗМЕНИЛ хотя бы один путь кэша (значение или удаление; защищённые пути окна не считаются — они снимком не пишутся); иначе «без расхождения» (`clean`). Ресинк не удался, переполнил журнал (`overflow`) или снимок не применён — разрыв остаётся `unclassified`, не `clean` и не `diverged`.
3. Публичные счётчики на `StateProxy`, по образцу `confirmed_pattern_count` (`state_proxy.py` ~184): `gap_diverged_count`, `gap_clean_count`, `gap_unclassified_count` (int, только чтение); метрики `state_proxy.gap_diverged` / `gap_clean` / `gap_unclassified` через существующий `_record_metric`. Один разрыв = ровно один из трёх счётчиков (после завершения ресинка); совмещённый ресинк (`_resync_coalesced_count`, «догоняющий заход») счёт не удваивает — каждый обнаруженный разрыв классифицируется один раз по исходу того ресинка, что его покрыл.
4. WARNING остаётся ТОЛЬКО для «с расхождением» (текст: сколько путей изменил снимок, не больше 5 примеров путей) — это настоящий сигнал; для «без расхождения» — DEBUG.
5. Документация: ADR-SS-015 в `state_store_module/DECISIONS.md` — приписка «пересмотрено 2026-11-21: вариант (в)» (что изменилось, что осталось: (а) водяной знак — после 1.0); `STATUS.md` строка про ложные resync (~101) и `README.md` (счётчики). После правок DECISIONS — `python -m scripts.sync`, затем `python scripts/validate.py`.
6. Подозрение из OPEN_QUESTIONS (пакет с `revision <= S` снимка отбрасывается без callbacks) — НЕ чинить; только если по ходу тест-харнесс покажет его воспроизведение — записать в отчёт.

## REDS (настоящий `StateProxy` с тестовым роутером модуля; без шпионов на имя метода)

1. Пакет с дырой по ревизии, ресинк отвечает снимком, равным кэшу → `gap_clean_count == 1`, остальные 0; в логе НЕТ WARNING с «разрыв», есть DEBUG.
2. Пакет с дырой, снимок отличается по одному пути от кэша (пропущенная запись) → `gap_diverged_count == 1`, кэш исправлен, WARNING ровно один и называет число изменённых путей.
3. Ресинк не удался (ответ `status != ok` / таймаут) → `gap_unclassified_count == 1`; `overflow` → тоже `unclassified`.
4. Два разрыва подряд, второй совмещён с идущим ресинком → сумма трёх счётчиков равна числу ОБНАРУЖЕННЫХ разрывов, оба классифицированы после завершения, повторный «догоняющий» ресинк не даёт лишней единицы.
5. Путь, изменённый ДЕЛЬТОЙ в окне ресинка (защищён), не делает разрыв `diverged`.
6. Поведение без изменений (контроли, зелёные и до правки): ресинк запускается на каждом разрыве как раньше; `_last_revision` продвигается как раньше; число `state.get_subtree` запросов то же.
7. Счётчики доступны только чтением (присвоение — `AttributeError`).

Break-injection (лид предскажет до прогона): (а) вернуть WARNING на DEBUG-строку → красен 1; (б) классифицировать всё как `clean` → красен 2; (в) не считать `unclassified` при неудаче → красен 3; (г) считать разрыв в совмещённом заходе дважды → красен 4; (д) не исключать защищённые пути → красен 5.

## REPORT

Числа: красные до кода / зелёные после; радиус: весь `state_store_module/tests` (класс по `machine_gate`) и `Plugins`/`frontend`-тесты, что ссылаются на текст «разрыв revision» (`git grep`); пустой раздел «что осталось открытым / ненадёжно» (в т.ч. оценка «изменил кэш» ≠ «потерян пакет»: снимок может быть новее кэша из-за дельт в полёте).
