## DESIGN, п.1–4: признак окна, старт, канал, источник процента

DESIGN (decided by the lead — v3; основания — код и замеры 2026-11-26, Windows 10, main `.venv`):
  1. **Есть ли окно — точный признак, одна точка.** Окно даёт процесс `gui` с классом `multiprocess_prototype.frontend.process.GuiProcess`
     в собранной топологии; это правило `window_anyway` (`backend/launch.py:257-259`). Патч презентации процессов не добавляет (`launch.py:323-345`),
     его включает только env `INSPECTOR_PRESENTATION` (`frontend/run.py:80`; вход владельца — `scripts/run_sim_all.ps1:84`), headless-резолвер его снимает
     (`main.py:59-66`, `launch.py:568-581`). Имя входа не годится: `frontend/run.py dualcam_synth` окна не даёт (замер: признак `False`).
     Новая чистая функция `presentation_window_expected(topology) -> bool` в `launch.py` и свойство `SystemBuilder.presentation_window_expected`;
     `announce_presentation_absent` берёт `window_anyway` из неё (одно правило). Признак готов через 0,88–1,10 с от старта интерпретатора
     (замер: `load_manifest` 0,58–0,73 с + `from_manifest` 0,06–0,10 с). Нет окна — процесса заставки нет вовсе.
  2. **Старт.** `main.py::_prototype_launcher_factory(..., splash: bool = False)`: `SystemBuilder.from_manifest(...)` ->
     `start_splash(builder.presentation_window_expected)` -> трекер лончера `ProgressTracker([("recipe", 50), ("built", 50)])`, `advance("recipe")` ->
     `.build()` -> `finish()`; листы уходят `SplashLink.report(leaf)` с `id` `launch`. `main()` передаёт `splash=splash_enabled(os.environ)` через `partial`
     (как `headless`, `main.py:184-189`); умолчание `False`: тесты, зовущие фабрику напрямую, процессов не порождают. `build_launcher` не меняется.
     Процесс: `Popen([sys.executable, "-m", "multiprocess_prototype.splash.window", "--title", <имя манифеста>], cwd=PROJECT_ROOT, stdin=PIPE)`
     (`multiprocess_prototype/__init__.py` — 1 строка). Окно — PySide6 + stdlib + `splash.protocol`, **без импорта фреймворка**: импорт
     `process_module.progress` в свежем процессе стоит 0,77–1,26 с (1113 модулей); заставка без него — 0,19–0,32 с до первого оборота цикла с окном.
  3. **Канал — UDP 127.0.0.1; сокет принадлежит заставке, порт — в env.** Лончер биндит `127.0.0.1:0` и отдаёт сокет ребёнку (Windows: `sock.share(pid)`
     с длиной-префиксом в stdin; POSIX: `pass_fds` + `--fd`), свою копию закрывает, пишет `os.environ["INSPECTOR_SPLASH_PORT"]` ДО `launcher.run()`:
     PM и GUI наследуют env при spawn. Сокет не закрывается между bind и приёмом — гонки за порт нет (замер: датаграммы родителя и внука дошли).
     Посылка — JSON `{"id", "percent", "label", "done"}` (лист 1.3b + `id`, `label` ≤ 200 знаков). `sendto` в мёртвый порт исключения не даёт
     (замер: 3 из 3, 81–109 мкс) — всё равно в `try`; приложение ничего не ждёт.
  4. **Одна модель процента, один концентратор — стор.** Узлы пишут прогресс только своим API в `system.progress.<id>` (`ProgressTracker`,
     `process_module/progress.py:42-86`); backend_ctl видит то же, что заставка. В сторе PM — middleware `ProgressMirror`: `after_set` идёт до рассылки
     дельт (`state_store_manager.py:208-212`), целый лист `system.progress.<id>` (dict, `id` без точек) -> датаграмма. Ставит его прототипный PM:
     `ProcessManagerProcessApp._setup_state_store` = `super()` + `install_if_enabled(...)` (`orchestrator.py:34`; хук `app_module/orchestrator.py:381-427`,
     там же `.use(ThrottleMiddleware)`). **`process_manager_process.py` не трогаем**: лист `boot` (`:1594-1600`) приходит сам.
     Вне стора — только лист `launch`: стора до PM нет (`amendments.md` §5, решение 4). GUI пишет `system.progress.gui` через `StateProxy.set`
     (fire-and-forget, `state_proxy.py:251-268`), шаги `GUI_STEPS`: `qt` 10, `plugins` 40, `state` 20, `window` 30.

## DESIGN, п.5–8: процент заставки, жизненный цикл, выключатель, LoadingWindow

  5. **Процент заставки — доли фаз, не время.** `SplashScale`: веса `SPLASH_WEIGHTS` — `launch` 10, `boot` 50, `gui` 40; доля фазы = `percent/100` её листа;
     итог = round(Σ вес × доля), монотонный — правило `ProgressTracker` (тест сверяет оба); копия, а не импорт — из-за цены импорта (п.2).
     Неизвестный `id` шкалу не двигает, его подпись видна второй строкой («любой узел виден»). Смысл: `boot` 50 % = все процессы запущены,
     `boot` 100 % = барьер готовности пройден, `gui` 100 % = первое окно GUI. Подпись — заголовок этапа (`launch` «Подготовка рецепта»,
     `boot` «Запуск процессов», `gui` «Загрузка интерфейса») + `label` листа; в углу — секунды с показа (признак жизни, когда шкала стоит).
  6. **Жизненный цикл.** Закрытие — `app.quit()`, код 0; в stderr ровно две строки: `[splash] shown` и `[splash] closed reason=<r> after <с> s percent=<p>`.
     Причины `r`: `gui_done` — лист `gui` с `done: true`; `parent_gone` — EOF stdin (лончер умер любым способом; при перезапуске venv заставка ещё
     и в Job Object, `run.py:225-266`); `timeout` — `SPLASH_TIMEOUT_S = 60.0` с показа (замер: окно на 12,8–14,7 с, выброс 30,2 с); `sigint` — Ctrl+C
     (свой обработчик SIGINT; опрос сокета QTimer 50 мс даёт интерпретатору шанс). Окно `Qt.SplashScreen | FramelessWindowHint`,
     **без** `WindowStaysOnTopHint`, с `WA_ShowWithoutActivating`.
     Модальные диалоги: перед `StartupBlockingDialog.exec()` (`app.py:692-697`, `:707-708`) и `LoginDialog.exec()` (`app.py:757-758`) GUI зовёт
     `done("ожидание пользователя")` — первое окно GUI появилось, заставка уходит и не возвращается; иначе `done()` сразу после `window.show()` (`app.py:1039`).
     Рестарт UI (`process.py:294-301`) и рестарт процесса GUI пишут лист `gui` заново (новый трекер) — заставка не возвращается: её запускает только
     лончер, один раз за процесс (модульный держатель `SplashLink`, он же держит stdin открытым). Второй экземпляр — свой сокет и env, общих имён нет.
     Падение GUI до окна — заставка до `timeout` или `parent_gone` (принятая цена, см. TRAPS).
  7. **Выключатель:** `INSPECTOR_SPLASH=0` — нет процесса, нет env-порта, PM без зеркала (ноль цены). Иначе включена, в том числе при
     `INSPECTOR_GUI_UNATTENDED=1` (кликать в ней нечего); `QT_QPA_PLATFORM=offscreen` наследуется — заставка тоже offscreen.
  8. **`LoadingWindow` не размораживаем** (остаётся FROZEN, принцип 3): он во framework, импорт тянет цепочку пакетов (п.2) и `AppIdentity`;
     заставке нужен отдельный лёгкий процесс. Пункты 1–6 FILES v2 сняты. Отклонено: ранний скрытый запуск до признака (выигрыш 0,2–0,3 с ценой
     ветки отмены); TCP (отказ соединения на Windows ~1–2 с); именованный канал (`WaitNamedPipe` до 1 с); порт «bind-close-передать» (гонка за порт).
