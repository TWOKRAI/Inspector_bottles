  3. **Канал — UDP 127.0.0.1; порт биндит сама заставка и пишет строкой в stdout.** Первые строки `window.main` (stdlib, ДО импорта PySide6):
     `bind(("127.0.0.1", 0))`, `os.write(1, b"<порт>\n")`. Лончер читает её daemon-потоком через `os.read(fd, 64)` до `\n` или EOF.
     `publish_port` ждёт порт не дольше `SPLASH_PORT_WAIT_S = 0.3` с **от Popen**, затем пишет `environ["INSPECTOR_SPLASH_PORT"]` ДО `launcher.run()` —
     PM и GUI наследуют env при spawn. Нет порта к сроку — `close()`, env не пишется, одна строка stderr `[run] заставка: порт не пришёл — без заставки`.
     **Почему не передача сокета:** `.venv\Scripts\python.exe` — трамплин uv, `Popen.pid` ≠ PID интерпретатора (замер 7 из 7), `share(pid)` попадает
     в гонку (стадия 0: задержка ≥ 0,01 с -> WinError 10038). Замер схемы со строкой через трамплин, n=7: порт через 48,6–70,1 мс после Popen;
     датаграмма доходит до настоящего процесса; EOF stdin доходит; код 0 доходит. `build()` идёт 3,6–8,3 с (замер n=3) ≫ 70 мс: ожидания на деле нет.
     Не нужны `share`, `pass_fds`, POSIX-ветка, `sys._base_executable`. Посылка — JSON `{"id", "percent", "label", "done"}` (лист 1.3b + `id`, `label` ≤ 200);
     `sendto` в мёртвый порт исключения не даёт (3 из 3, 81–109 мкс) — всё равно в `try`.
     `report()` до прихода порта хранит последний лист и шлёт его, когда поток получил порт (общий замок `SplashLink`); очереди нет.
  4. **Одна модель процента, один концентратор — стор.** Узлы пишут прогресс только своим API в `system.progress.<id>` (`ProgressTracker`,

     дельт (`state_store_manager.py:208-212`), целый лист `system.progress.<id>` (dict, `id` без точек) -> датаграмма. Ставит его прототипный PM:
     `ProcessManagerProcessApp._setup_state_store` = `super()` + `install_if_enabled(getattr(self, "_state_store_manager", None))` (`orchestrator.py:34`;
     хук `app_module/orchestrator.py:381-427`). `_setup_state_store` идёт внутри `try` у `initialize()` PM — поэтому `install_if_enabled` не бросает никогда.
     **`process_manager_process.py` не трогаем**: лист `boot` (`:1594-1600`) приходит сам. Вне стора — только лист `launch` (стора до PM нет,
     `amendments.md` §5, решение 4). GUI пишет `system.progress.gui` через `StateProxy.set` (fire-and-forget, `state_proxy.py:251-268`).

## DESIGN, п.5–8: процент заставки, жизненный цикл, выключатель, LoadingWindow

  5. **Процент заставки — доли фаз, не время.** `SplashScale`: веса `SPLASH_WEIGHTS` — `launch` 10, `boot` 50, `gui` 40; доля фазы = `percent/100` её листа;
     итог = round(Σ вес × доля), монотонный — правило `ProgressTracker` (тест сверяет оба); копия, а не импорт — из-за цены импорта (п.2).
     Неизвестный `id` шкалу не двигает, его подпись видна второй строкой. Смысл: `launch` 5 % = рецепт прочитан, 10 % = система собрана;
     `boot` 50 % = все процессы запущены, 100 % = барьер готовности пройден; `gui` 100 % = первое окно GUI. Подпись — заголовок этапа
     (`launch` «Подготовка рецепта», `boot` «Запуск процессов», `gui` «Загрузка интерфейса») + `label` листа; в углу — секунды с показа.
  6. **Жизненный цикл.** `SplashController` владеет причиной закрытия: `request_close(reason)` только ставит флаг под замком (Qt не трогает);
     `poll()` (QTimer 50 мс, Qt-поток) возвращает первую из: запрошенная причина; `gui_done` (дренаж сокета дал `is_close_signal`); `timeout`
     (`time.monotonic()` от создания контроллера ≥ `timeout_s`); иначе `None`. Контроллер сам делает `sock.setblocking(False)`.
     Поток lifeline (`os.read(0, 1)` до `b""`) зовёт только `request_close("parent_gone")`; обработчик SIGINT — только `request_close("sigint")`.
     Непустой `poll()` -> `app.quit()`, код 0; в stderr ровно две строки: `[splash] shown` и `[splash] closed reason=<r> after <с> s percent=<p>`.
     `timeout_s` = `SPLASH_TIMEOUT_S = 60.0` (замер: окно на 12,8–14,7 с, выброс 30,2 с). При перезапуске venv заставка ещё и в Job Object (`run.py:225-266`).
     Окно `Qt.SplashScreen | FramelessWindowHint`, **без** `WindowStaysOnTopHint`, с `WA_ShowWithoutActivating`.
     Шаги GUI (`GUI_STEPS`): `qt` 10 после `app.py:205`, `plugins` 40 после блока `except` `:302-305`, `state` 20 после вызова `:450-458`, `window` 30 перед `:1039`.
     `done("ожидание пользователя")` — перед `StartupBlockingDialog.exec()` (`:692-697`, `:707-708`) и `LoginDialog.exec()` (`:757-758`): первое окно GUI
     появилось, заставка уходит и не возвращается; иначе `done()` сразу после `window.show()` (`:1039`). Рестарт UI (`process.py:294-301`) и рестарт процесса
     GUI пишут лист `gui` заново (новый трекер) — заставка не возвращается: её запускает только лончер, один раз (модульный держатель `SplashLink`, он же
     держит stdin открытым). Второй экземпляр — свой порт и env. Падение GUI до окна — заставка до `timeout` или `parent_gone` (принятая цена).
  7. **Выключатель:** `INSPECTOR_SPLASH=0` — нет процесса, нет env-порта, PM без зеркала (ноль цены). Иначе включена, в том числе при
     `INSPECTOR_GUI_UNATTENDED=1`; `QT_QPA_PLATFORM=offscreen` наследуется — заставка тоже offscreen.
  8. **`LoadingWindow` не размораживаем** (остаётся FROZEN, принцип 3): он во framework, импорт тянет цепочку пакетов (п.2) и `AppIdentity`.
     Отклонено: передача сокета (п.3); ранний скрытый запуск до признака (выигрыш 0,2–0,3 с ценой ветки отмены); TCP (отказ соединения на Windows
     ~1–2 с); именованный канал (`WaitNamedPipe` до 1 с); порт «bind-close-передать» (гонка за порт).
