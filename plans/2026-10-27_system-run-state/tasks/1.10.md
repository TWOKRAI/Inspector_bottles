## Источник

Свежее ревью Opus 2026-11-15, F3/С3 (`reports/phase1.review-opus-fresh.md`): `run_event` — `multiprocessing.Event`; каждый `is_set/set/clear` берёт межпроцессный замок. `_run_apply` трогает его под `_run_lock`; дети читают флаг с частотой ~90 обращений/с на ребёнка. Воспроизведение (ребёнок держит внутренний замок, SIGKILL): `system.run.start`, `system.run.status`, такт монитора висят дольше 3 с. Принцип владельца 5: сбой одного процесса не валит соседей.

## DESIGN

Единственный писатель флага — PM; читатели — дети (`reconcile_run_event`, `SourceProducer`, `process_module`), все читают только `is_set()`. Значит замок не нужен.

`RunFlag` (core/run_flag.py): один байт в разделяемой памяти — `multiprocessing.RawValue(ctypes.c_bool, initial)`.
- `is_set() -> bool`, `set() -> None`, `clear() -> None`; те же имена и смысл, что у `Event` (подмена одной строкой, потребители не меняются).
- `wait()` НЕ реализуется (блокирующих потребителей в репозитории нет — проверено `git grep`); контракт «только опрос» пишется в docstring.
- Передаётся ребёнку тем же путём, что `Event` (аргумент `Process(...)` при spawn); отдельного `__reduce__` нет.
- Запись байта без замка: один писатель, читатели видят старое или новое значение, оба допустимы. Формально Python барьера не даёт; безопасно, потому что одиночный байт атомарен на x86-64/arm64 и флаг не публикует зависимых данных (в ADR записать явно). Инвариант ADR-PMM-034 сохраняется: флаг уходит ребёнку только наследованием при spawn, не через bundle custom, очередь или Manager (вне spawn `pickle` падает громко: `TypeError cannot pickle 'mmap.mmap'`, проверено стадией 0).

Почему не байт в `shared_resources_module`: добавляет слой (реестр, имя, жизненный цикл) без выигрыша; рядом уже живёт `RawArray` (`exit_report_slot`) тем же путём.

Публичный класс: docstring `Purpose / Public API / Stability`, `__all__`, DbC `Pre/Post` (в `Pre`: «один писатель — PM»), контрактный тест `tests/test_run_flag_contract.py`.
PM: `self._run_event = RunFlag()` вместо `_MpEvent()` (имя атрибута сохраняется: на него завязаны раннер и дети). Обращения PM под `_run_lock` остаются, но замка ОС больше не берут.

## REDS (tester, слепой; ожидания — литералы; запуск: `pytest multiprocess_framework/modules/process_manager_module/tests/test_run_flag.py -q` из `multiprocess_framework/modules`)

1. Начальное значение: `RunFlag().is_set() is False`; `RunFlag(True).is_set() is True`.
2. `set()` → `True`; `clear()` → `False`; повторный `set()`/`clear()` идемпотентен.
3. Видимость родитель → ребёнок (spawn): `multiprocessing.get_context("spawn")` явно; цель процесса — функция верхнего уровня модуля; флаг передан аргументом `Process`; после `set()` родителя ребёнок видит `True` не позже 2 с, после `clear()` — `False`; результат ребёнок отдаёт по каналу с дедлайном. Обратного направления (запись ребёнка) нет: единственный писатель — PM.
4. Смерть ребёнка в горячем цикле: ребёнок в цикле `while True: flag.is_set()` и сигналит «в цикле» (второй `RawValue` или маркер-файл); задержка до kill считается ОТ сигнала, список задержек литералом (например 0, 1, 3, 7, 15 мс и т.д. — не менее 30 запусков); убийство `Process.kill()`; затем `set()`, `is_set()`, `clear()` в родителе, выполняемые в daemon-потоке с join-дедлайном, укладываются в 1 с. Ожидание дедлайна — тест красный, не зависание pytest. Контроль с `multiprocessing.Event` в том же файле, `pytest.skip("не воспроизвелось")`, если зависание не поймано.
5. Контракт «только опрос»: `not hasattr(RunFlag(), "wait")`.
6. PM-wiring (`test_run_flag_pm_wiring.py`, пишет developer): `type(pm._run_event) is RunFlag`; `run_gate: false` — флаг взведён сразу; `run_gate: true` — снят до `system.run.start`; START взводит, STOP снимает; тот же объект уходит в `ProcessRegistry(run_event=...)`.
7. Сквозной с настоящими объектами: `RunFlag` через `ProcessRegistry.create_and_register` → kwargs `Process` → ребёнок; ребёнок видит `True` после START и `False` после STOP (оба фронта), по образцу `test_run_event_wiring.py::test_spawned_child_sees_run_event_both_directions`, но с `RunFlag`.
8. Контрактный `test_run_flag_contract.py`: Pre/Post из docstring (идемпотентность, типы возврата `bool`/`None`).

Break-injection (предсказания лида — до прогона): (а) в `RunFlag` заменить `RawValue` на `multiprocessing.Event` → краснеет тест 4 (и только он из REDS 1–3, 5); (б) откат строки создания в PM на `_MpEvent()` → краснеют 6 и 7; (в) добавить `wait` → краснеет 5.
