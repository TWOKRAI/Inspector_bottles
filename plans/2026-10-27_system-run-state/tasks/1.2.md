  1. `plugins/base.py`, рядом с `pause/resume` (`:1540-1551`): `def readiness(self, ctx) -> list[dict]: return []`.
     Docstring-контракт: элемент `{"severity": "failure|check_function|out_of_spec|maintenance", "reason": str}` (`reason` — короткий текст
     БЕЗ значений входа: путь, ключ конфига, данные — в `log_*`); быстро, без IO, без замков; не бросает. «Плагин отчитывается устойчивым
     состоянием; переподключение в процессе — `out_of_spec`, не `failure`, пока не истёк его собственный срок» (дребезг — обязанность плагина,
     вердикт cto К4). Хуки `pause/resume` — в docstring: «зовутся наблюдателем `run_event` из отдельного потока, параллельно `process()`/
     `produce()` (как `request_stop`, C-60); идемпотентны; исключение не роняет остальные плагины; `produce()` может начаться РАНЬШЕ
     `resume()` и закончиться позже `pause()` (источник сам режется `run_event` в `SourceProducer`)» (Н11).
  2. Состояние процесса считает **отдельный поток-снимок**, не heartbeat и не поток сверки (Н2: `_send_heartbeat` и `_publish_health_to_tree` в одном
     `try`, `process_heartbeat.py:257-262`; Д1: один поток на снимок и хуки заморозил бы паузу всех плагинов из-за зависшего `readiness()` одного).
     `PluginOrchestrator.readiness_snapshot() -> dict` (в `plugin_orchestrator.py`; оркестратор владеет списком плагинов): для каждого плагина
     (а) `readiness(ctx)` под собственным `try`: исключение → причина `failure` «readiness() упал: <ТипИсключения>» (**без текста исключения**, Н7;
     текст и traceback — `log_error`); возврат не-list / элемент не-dict / `severity` вне словаря / `reason` не `str` → `failure` «readiness() вернул
     неверную форму»; `reason` ≤ 200 символов, причин на процесс ≤ 32 (лишние отбрасываются, в конец — одна `out_of_spec` «причин больше 32»);
     (б) плагин вне `{RUNNING, PAUSED}` (`IDLE` после упавшего `configure`, `READY` после упавшего `start`) → `failure` «плагин не поднят (<состояние>)»
     (Н4, design.md §3.3); (в) плагин, у которого последний вызов `pause()/resume()` бросил, → `failure` «pause() упал: <Тип>» / «resume() упал: <Тип>»;
     причина снимается, когда состояние плагина совпало с целью наблюдателя **или цель сменилась** (Д4: иначе `pause()` упал при уже взведённом событии —
     плагин `RUNNING` = цель, перехода нет, причина висела бы вечно). `node = "<процесс>.<плагин>"`, `source = "readiness"`.
     Снимок: `{"ready": bool, "reasons": [...], "paused": bool, "at": float}`; темп расчёта — ≤ 2 Гц (`readiness()` N плагинов 20 раз в секунду — лишняя
     цена; поток-снимок спит 0,5 с). `ready` = нет `failure` и нет `check_function` (вердикт cto К3: блокирует START и в `running` равен потере готовности;
     `maintenance` и `out_of_spec` не блокируют) **и** процесс объявил готовность. `at` — время расчёта (Task 1.3 судит «молчание» по `at`, а не по
     времени heartbeat: мёртвый поток-снимок при живом heartbeat иначе выглядит готовым).
  3. «Объявил готовность» (Н3, Д3) — **защёлка**: поток-снимок один раз видит `_current_process_status ∈ {running, paused}` (`running` ставится
     `process_module.py:1405-1406` прямо перед `_announce_ready`, `:1407`; `paused` — `worker.pause_all`, `builtin_commands.py:314`) и дальше держит
     `announced = True` навсегда: команда `process.pause`/`worker.pause_all` (PM паузит ей процесс) не должна превращаться в «потерю готовности».
     Процесс без оркестратора (`_orchestrator is None`): `reasons = []`, `ready` = `announced`, `paused` = применённая цель наблюдателя.
     Сигнатура (уточнение по вопросам слепого tester, 2026-11-13): `PluginOrchestrator.readiness_snapshot(announced: bool | None = None) -> dict`;
     `announced is None` → оркестратор сам читает `self._services._current_process_status in ("running", "paused")`, поток-снимок процесса передаёт
     значение защёлки явно. Элемент причины — ровно ключи `node, severity, reason, source` (лишних нет). Текст причины п.2(б) — литерал
     `плагин не поднят (<state.value>)`, например `плагин не поднят (idle)`.
  4. Публикация — полем heartbeat-сообщения: `heartbeat_msg["readiness"] = <последний снимок>` (`heartbeat/process_heartbeat.py:362-378`,

     `ProcessModule._init_application_threads` (`process_module.py:1033-1043`) **вне ветки** `if self._orchestrator is not None:` (Д2: `boot()` стоит
     внутри неё, а процесс без плагинов тоже должен публиковать снимок), после неё: (1) `run_watch` — сверка с темпом 0,05 с (тот же такт, что у

  6. Сверка **по уровню, не по фронту** (`run_watch`): на каждом опросе цель (`run_event` снято → «пауза», взведено → «работа») сверяется с состоянием
     плагинов и недостающее применяется: «пауза» → `_do_pause` каждому `RUNNING`, для которого `_should_pause(plugin)`; «работа» → `_do_resume` каждому
     `PAUSED`. `_should_pause(plugin)` — **одна функция** оркестратора для сверки и для паузы в boot (Д5): ложь для источника с `run_gated: false`

     (названы и тестируются): мигание `clear()→set()` быстрее опроса — чистый эффект нулевой, хуки не зовутся (осознанно); событие, изменившееся, пока хук
     блокирован, — следующий опрос сходится; упавший хук повторяется не чаще раза в 1 с на плагин (лог — один раз на серию). `paused` = цель «пауза»
     применена **и** ни один плагин, к которому применимо `_should_pause`, не в `RUNNING`; плагин в `IDLE` после упавшего `configure` не держит
     `paused: false`. До Task 1.9 `paused` — состояние ярлыков: плагин в `PAUSED`, воркеры идут.
  7. Первая пауза в boot (К5): при снятом событии **и** `_run_watch_enabled()` — `_do_pause` каждому плагину с `_should_pause` сразу после `_do_start`
     фазы start `plugin_orchestrator.boot()` (`:182-203`), до старта воркеров; причина — устройство не должно успеть отдать кадр до START. Без наблюдателя,
     который её снимет, плагины остаются `RUNNING`. **Правка фильтра источников** (`generic_process.py:185`, Н1): `plugin.state != RUNNING` →
     `plugin.state not in (RUNNING, PAUSED)`, иначе источник в `PAUSED` отбрасывается («рабочий поток ему НЕ создаётся») и после START кадров не будет;
     комментарий H-2 (`:151-163`) — слово «PAUSED». `SourceProducer` и `PluginRunner.call_produce` состояния плагина не смотрят (`plugin_runner.py:178-186`):
     после `set()` `produce()` источника в `PAUSED` идёт до `resume()` — принято (Н11), тест Т21.
  8. Остановка и shutdown (Д6): `request_stop()` оркестратора **первым действием** ставит флаг `_stopping` без замка (контракт C-60: хук не ждёт,
     `base.py:1569`); `run_watch` проверяет флаг под замком сверки перед каждым хуком; `shutdown()` берёт замок сверки с таймаутом **2 с**, по таймауту
     — `log_error` и идёт дальше (+≤ 2 с к закрытию, не 5). Гонку «медленный хук присвоил `PAUSED` поверх `STOPPED`» закрывает `base.py` (Д6, файл
     в FILES): `_do_pause/_do_resume` присваивают `self.state` после хука только если оно всё ещё прежнее (`RUNNING`/`PAUSED`), иначе не трогают.
