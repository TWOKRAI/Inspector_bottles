## Факты

- Настоящий ответ (`RouterManager.reply_to_request`, `router_manager.py:1304-1313`):
  `{"type","command","sender","targets","queue_type","request_id","success","result"}`.
- `services/vfd/presenter.py:122` и `services/devices_common/presenter.py:165` — две копии `_extract_top`: разворачивают, только
  если ключи ответа входят в `{result, status, request_id, command}`. Настоящий конверт под это не подходит.
- `services/robot/presenter.py:229` `_unwrap` настоящий конверт разворачивает (правило: `result` — dict и нет ключа `status`,
  либо прежнее условие).

## DESIGN

Одна функция `unwrap_reply(response) -> dict` в `services/devices_common/reply.py`; `vfd`, `devices_common` и `robot` зовут её,
три копии убраны. Правило — то, что уже работает у робота. Поведение робота не меняется.

## REDS (слепой tester)

- A1 настоящий конверт, `result` = ответ `device_describe` -> получатель видит поля `result`, а не конверт (ПЧ и common).
- A2 вкладка ПЧ: конверт с `carrier.mode = draw` -> пуск недоступен; предел частоты из ответа применён.
- A3 ответ без конверта проходит без изменений. A4 `{"result": {...}}` и `{"result": {...}, "status": ...}` разворачиваются.
- A5 конверт отказа (`success: False`, `result: None`) -> получатель видит `success is False`, исключения нет.
- A6 не dict (`None`, строка) -> `{}`.

## Раунд 2 — по ревью (reviewer `abf228d8f16976c73`, APPROVED с находками), стадия 2: developer

Правка конверта впервые делает кнопку «Изменить» сохраняющей, поэтому потери формы закрываются здесь же.

- **R1** `devices_common/device_form.py`: при редактировании и неизменном типе транспорта ключи, которых форма не показывает
  (`timeout_sec` и любые другие), сохраняются; значения из полей формы перекрывают. Смена типа транспорта — только поля нового типа.
- **R2** там же: `tcp` без `unit_id` при редактировании получает то же умолчание, что новая форма (`robot` — 2, иначе 1);
  `rtu` загружает свои `serial` и `baudrate`; `bridge`, чьего носителя нет в списке роботов, не подменяется первым из списка.
- **R3** `device_upsert` / `device_remove` разворачивают ответ; `_after_hub` предупреждает и при `status` не `ok`, и при
  `success is False` (конверт отказа с `result: None`).
- **R4** тест: вкладка робота получает поля `result` из настоящего конверта (краснеет на старом правиле «только подмножество ключей»).
- **R5** строка `reply.py` в `devices_common/README.md`.

Предсказания инъекций раунда 2: убрать слияние транспорта -> тест R1; умолчание `unit_id` = 1 -> тест R2 (robot); убрать загрузку
