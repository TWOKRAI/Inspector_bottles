**Решения (черновик; стадия 0 их принимает или меняет):**

1. **Контракт:** лист `system.progress.<id>` = `{"percent": int 0..100, "label": str, "stage": str, "done": bool, "updated_at": float}`; `id` — открытый набор (`boot`, `recipe_load`, …). 2. **Принцип 4 (меньше слоёв):** никакого `ProgressReporter` с IO. Один чистый файл `state_store_module/progress.py` (≤ ~40 строк): константы путей + `ProgressTracker(steps=[(имя, вес), …])`; `advance(step, fraction=1.0) -> dict` возвращает лист и держит процент **монотонным** (назад не мигает; новый прогон того же `id` — новый трекер, стартует с 0). ## 9. Task 1.4 — порядок `shutdown` и событие `run_event` (находка слепого tester, 2026-11-13)

Слепой tester 1.4 заметил: `_run_apply("shutdown")` при `run_gate: true` сразу снимает `run_event` (`new is not running`), а DESIGN п.5 требует «сначала п.1–3 (один проход `pre_stop`), потом стоп». ## 10. Task 1.2c — внеочередной heartbeat при смене `paused` (находка стенда 1.2/1.9/1.3, 2026-11-13)

Стенд (`reports/1.2-1.3.stand.md`): снимок считается каждые 0,5 с, но в PM (и в лист `processes.<n>.readiness`) попадает только с обычным heartbeat (`heartbeat_interval` 5 с): `paused` в листе отстаёт на 3–5 с (start +2,97 с, stop +4,79 с), шаг `at` ≈ 5,03 с, а не 0,5 с; кадры при этом идут и встают за 0,13 с. Для 1.4 это значит: STOP ждёт `paused` до интервала heartbeat, приёмка «`ready` ≤ шаг + 2 с» невыполнима, продуктовый эффект — задержка кнопки «стоп» до 5 с. Решение лида (framework, fix forward): **внеочередной heartbeat при смене `paused` в снимке** (антидребезг, не чаще ~2 в секунду; сбой отправки не роняет воркер снимка). Новый механизм → слепой tester (`rs-1.2c-tester`) → developer sonnet → hazard-тесты → матрица → стенд; файлы: `process_module/heartbeat/process_heartbeat.py`, `core/process_module.py` (воркер снимка). `stale_s` (3 × интервал) и окно `fault` 16 с не меняются (замер D1: 15,27 с, запас 0,7 с — впритык, пересмотреть в 2.5, если интервал heartbeat вырастет). Лист `readiness` в сторе не «стареет» сам (последний снимок остаётся при замороженном процессе): потребители (GUI, Task 2.3) судят о свежести по `readiness.at`, не по наличию листа — в README/2.3.
