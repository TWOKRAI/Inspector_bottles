## Что отбросила метка `paused_by` (наблюдение должно было иметь что отбрасывать)

Считаются только отброшенные при state GUI `running`. «Только метка» = `capture_ts >= mark`, то есть фильтр 2.10 этот кадр пропустил бы.

| фаза | прогонов | отброшено по `paused_by` | из них только меткой | из них полный сырой |
|---|---|---|---|---|
| START, серия п.1 | 10 | `recog` 1, `mask` 1 (прогон #4, `color_convert`) | **0** | 0 |
| START, остальные | 54 | `recog` 2, `mask` 1 | `recog` 1 (прогон fault #2, `center_crop`, кадр 481×800, `capture_ts − mark` = +0,001 с) | 0 |
| STOP | 61 | `mask` 1 | **1** | **1** (`mask`) |
| `fault` | 3 | `mask` 3 | **3** | **2** (`mask`) |

- **На START метка полный сырой кадр не отбрасывала ни разу.** Помеченные полные кадры были сняты до `mark` (−0,017…−0,028 с), их отбросил бы и фильтр 2.10. Кадров с подписью дефекта 2.10 (полный кадр, `capture_ts − mark` = +0,01…+0,03 с) за 64 START не пришло. Поэтому «0 из 10» по п.1 не доказывает, что дефект START закрыт меткой: окно гонки на этом прогоне не открылось.
- Что метка работает на живом пути, показывают STOP (1 случай) и `fault` (2 случая): полный сырой кадр пришёл при GUI в `running` и не показан. Плюс один частичный кадр на `recog` после START.
- Метка доходит до GUI: в обоих окнах `ready` по 10 с все отброшенные кадры `recog` / `mask` несут `paused_by = color_convert` (254 + 247 и 251 + 230).
- `drop why=mark` (фильтр 2.10, без метки): 49 кадров, все `mask`.
- Метка, застрявшая в `running` (TRAP про сбой `resume`), не наблюдалась: `mask` ожил в 64 из 64, на `recog` помеченные кадры после входа в `running` — единичные (выше).
