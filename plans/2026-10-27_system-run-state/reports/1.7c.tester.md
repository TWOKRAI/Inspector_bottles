Режим red (BRIEF-OVERRIDE); отчёт передан сообщением агента, файл записан лидом. Дерево tester (по ошибке лида) создано как `.claude/.claude/worktrees/rs-1.7c-tester` — убрать `git worktree remove`.

Файлы: `process_module/tests/test_heartbeat_pid.py` (1), `process_manager_module/tests/test_run_state_restarting.py` (2 функции, 10 прогонов), `test_run_restart_incarnation.py` (9 функций, 11 прогонов; настоящие `ProcessManagerProcess` + `ProcessMonitor`, решение супервизора настоящее). До реализации: 15 красных по существу (нет `pid` в heartbeat; `ack` → `ready` и START → `running` при запланированном рестарте; поздний лист старого pid освежает; `recovered` по оживлению старого; `running` без флага остаётся `running`; с флагом — нет причины; `TypeError` на `restarting` — допустим), 7 охранных зелёных (старые вызовы `evaluate`; лист принимается вне рестарта, без pid и с pid реестра; два теста «снятие по heartbeat нового pid» — страхуют путь восстановления).

Допущения: `pid` — верхний уровень heartbeat; текст причины в `reason` (в `evaluate` точный «cam: перезапускается супервизором»); после решения супервизора нужен ещё один такт PM; «исполнение рестарта» — настоящий диспатч + ручная подмена процесса реестра на новое воплощение (pid 41002; старый 41001); `recovered` считается по вызовам `monitor._emit_supervisor_event`; тесты привязаны к приватным именам монитора (как соседние).

Открыто (tester): окно «`process.restart` отправлен, но реестр ещё держит старый pid»; пересечение `restarting` и `auto_restart` в `evaluate` при `running=True`; heartbeat без `pid` в состоянии «перезапускается»; нет сквозного теста со spawn и настоящим pid; ack-тест мягок к `ack_allowed`.

## Решения лида (2026-11-13)
1. Новое воплощение = heartbeat с `pid == pid реестра` И `pid != pid, записанный в момент решения` (старый pid). Пока реестр ещё держит старый pid — heartbeat старого воплощения не снимает «перезапускается».
2. Heartbeat без `pid` в состоянии «перезапускается» состояние НЕ снимает (строго); вне перезапуска без `pid` принимается (совместимость).
3. `restarting` ∧ `auto_restart` при `running=True` в `evaluate`: процесс с флагом — окно 1.8 от момента решения (`out_of_spec` «перезапуск <процесс>»), без флага — `failure` «перезапускается супервизором»; hazard-тест автора.
4. Сквозной тест с настоящим spawn и pid — hazard-тест автора (daemon-поток + дедлайн), стенд — после.
