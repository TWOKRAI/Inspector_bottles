## 2. Три открытых места — решение по каждому

### (а) `_evaluation_failed` пишет в ERROR `{type}: {exc}` (`:1545`) — не блокер, оставить на 3.7 (A2)
Воспроизведено (`scratchpad/rev/repro.py`, E1a): оценка бросает `ValueError("bad restart_policy {'password': 'hunter2', 'host': '10.0.0.5'}")`:
- такт -> `ERROR: оценка готовности не удалась: ValueError: bad restart_policy {'password': 'hunter2', 'host': '10.0.0.5'}` (текст целиком);
- START -> `ERROR: readiness: оценка готовности не удалась (ValueError)` (только тип).
Опасность: текст исключения берётся из того, что бросил вызываемый код. Входы оценки — имена процессов, листы готовности детей (`normalize_leaf` -> dict), ключи конфига PM (`heartbeat_*`, `run_restart_grace_s`, `restart_policy`). Секретов штатно нет, но исключение, повторяющее вход (pydantic `input_value=`, `ValueError(f"...{value}")`), уйдёт в файл/консоль/`log_tail` как есть. Объём ограничен: одна строка на серию, не на такт (E1b: 5 циклов «сбой/ок» -> 4 строки ERROR); частый дребезг даёт до одной строки в ~1 с. Код `:1545` в дифф не входит (fix-B4), DESIGN обещает «без текста» только для пути START/`ack`. Лид в стадии 0 уже назвал разнобой «не блокер» (A2, 3.7). Обратная сторона: тип без текста и без трассы плохо диагностируется — решение (тип + усечённый текст на DEBUG / `exc_info` на DEBUG) — за 3.7.

### (б) `_run_stale_s` глотает `Exception` молча (`:1216`) — достаточна НЕ полностью; minor
Довод разработчика «такт логирует сбой серии один раз» верен только для пути `_evaluation_failed`. Правка стоит в `_run_stale_s`, и она же работает на пути УСПЕХА (`_evaluate_run_readiness:1284`, `_admission_stale_s:1263`): там сбой чтения конфига не даёт ни серии, ни лога. Воспроизведено (E2): `get_config` бросает `RuntimeError` только на `heartbeat_interval*`, оценка здорова, один такт -> `state ready`, `_log_error` и `_log_warning` пусты, причин нет, `stale_s == 15.0`. Поломка конфига на этих ключах невидима навсегда (срок молча 15 с вместо настроенного, например 3 с у интервала 1.0).
Маскировка дефекта конфига: значения-дефекты (`ValueError`/`TypeError`) молчали и раньше. Расширение до `Exception` оправдано реальным входом: `float(10**400)` -> `OverflowError`, он НЕ входит в `(TypeError, ValueError)` (проверено); на ветке `update_config("heartbeat_interval", 10**400)` -> `stale_s == 15.0`, такт `ready`, ошибок нет. Рекомендация (одна-две строки): лог WARNING один раз на эпизод (флаг рядом с `_eval_fail_since`) или оставить охрану только в `_evaluation_failed`, как буквально сказано в DESIGN A6 («чтение срока молчания обёрнуто» в `_evaluation_failed`). Правило проекта «log errors, never swallow» этой правкой нарушено для не-`ValueError`.
