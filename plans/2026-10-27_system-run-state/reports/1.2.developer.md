## Что я оставил открытым / ненадёжным

- Полный каталог `process_module/tests` не гонялся (OSError 28 на этой macOS, по брифу). Радиус — выше. Тесты вне радиуса, считающие воркеры процесса (`create_worker` на фейковом `worker_manager` через `ProcessModule._init_application_threads`), могут увидеть два новых воркера (`run_watch`, `readiness_snapshot`); в прогнанных файлах таких нет, но поиск был по `workers_status/heartbeat_msg/get_all_workers_status`, а не по всем способам. Нужен прогон лида.
- Приёмка «`paused == true` <= 1 с при `heartbeat_interval = 0,2`» целиком (с настоящим `ProcessHeartbeat` на настоящем процессе) не измерена: у тестового процесса интервал heartbeat не задать без правки конфига. Измерено по частям: `test_paused_flag_follows_event_within_budget` — снимок меняет `paused` <= 0,8 с (3 прогона зелёные, обычно 0,3-0,6 с), плюс слепой тест публикации доказывает, что каждый такт heartbeat несёт последний снимок. Сумма 0,05 + 0,5 + 0,2 = 0,75 с по DESIGN, запас мал; на загруженной машине тест с границей 0,8 с может мигать.
- Первый расчёт снимка стартует до `RUNNING` (воркер создаётся в `initialize`); если `readiness()` блокирует именно этот первый вызов, снимок опубликуется со старым `announced = False` и исправится на следующем такте (+0,5 с). Это видно в тесте T6; на свойства DESIGN не влияет.
- `_should_pause` зовёт `config_of` (копия dict) на каждом опросе для источника `run_gated: false` при снятом событии — 20 раз в секунду на такой плагин; цена мала, но не нулевая (в DESIGN п.2 цена опроса названа осознанной).
- Тайм-зависимые тесты: троттлинг T9 ждёт реальные 1,1 с, T5 — реальные ~2 с (таймаут замка); при очень медленной машине T19 (`<= 5` отсчётов `at` за 2,2 с) стоит у границы только снизу (`>= 2`).
- Слепые тесты и мои зелёные с первого прогона (18 из 18 в watcher-файле) доказаны только моими инъекциями A-D, F; остальное — на инъекциях лида.
