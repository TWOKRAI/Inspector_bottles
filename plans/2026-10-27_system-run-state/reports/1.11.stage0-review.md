### 2. Q3: `ack` из `fault` при сбое оценки -> `not_ready` — корректный исход
Аргументы по `transition` (`run_state.py:234`):
- Строка `fault` + `ack` + `stop_done` возвращает `_r(ready), None` для любого `ready`: `not_ready` — штатный принятый исход `ack` (тест `test_run_ack.py::test_ack_in_fault_with_failure_goes_not_ready`). Сбой оценки по смыслу — `ready=False` + причина `failure`, тот же класс входа, что молчащий лист.
- Отказ с неизменным `fault` требует нового кода: у `ack` отказов три — `fault_stopping`, `no_fault`, `shutting_down`; четвёртый — правка таблицы design.md §3.2 и всех потребителей кода отказа.
- Тупик: из `fault` выход только `ack`. При постоянно сломанной оценке отказ оставил бы `fault` навсегда; `not_ready` выходит по такту, как только оценка снова проходит (`not_ready` + `tick` -> `_r(ready)`).
- Безопасная сторона: из `not_ready` START отказан (`not_ready` + `start` -> `not_ready`), работа на непроверенной готовности не начнётся. Цена: авария «погашена» при сломанной оценке — но `last_fault` остаётся с `acknowledged_at`, а в статусе причина «оценка готовности не удалась» (прогон RED 2).
- Оговорка: `last_fault` помечается квитированным без проверки здоровья — то же происходит при любом `ack` -> `not_ready`.
