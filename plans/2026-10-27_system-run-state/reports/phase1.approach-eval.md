# Ф1 run-state — оценка подхода «без стадии 0, одно ревью Opus в конце» (черновик, лид, 2026-11-13)

Решение владельца 2026-11-13: стадия 0 пропущена у 1.9, 1.3, 1.3b, 1.4, 1.7, 1.5, 1.6, 1.8, стадия 5 по каждой — одно ревью Opus (с воспроизведением) на объединённый diff Ф1. Сравнение — с 1.1 и 1.2, где стадия 0 и ревью по задаче шли по обычной цепочке (24 и 16 замечаний стадии 0, из них 10 и 16 реальные major).

## Что собираем (заполняется по ходу, закрывается после ревью Opus)

1. Токены по ролям: слепые tester, developer (реализация + hazard + доработки), матрицы, стенды, лид. Источник — `usage` уведомлений агентов; сверять с оценкой плана (~0,4–0,6M на задачу).
2. Дефекты по механизму, который их нашёл: слепой tester / hazard-тесты автора / матрица инъекций / стенд / ревью Opus. Главный вопрос: что нашло ревью Opus в конце, чего не нашли первые четыре, и что бы нашла стадия 0.
3. Переделки: сколько раз правили уже закоммиченное (1.2 — три раунда; 1.2c, 1.7b — новые задачи из стенда).
4. Время: календарное от начала Ф1 до ревью; сколько ожидали (простои агентов, окна машины).
5. Риск, названный владельцу: «дефекты стадии 0 всплывут пакетом в конце и дороже по переделке» — подтвердилось или нет по числу и цене правок после ревью.
