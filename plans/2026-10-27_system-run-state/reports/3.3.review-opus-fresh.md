## Соответствие задаче (по пунктам брифа)
1. Push при смене подписи `(paused, ready, frozenset((node, severity) блокирующих))` — process_heartbeat.py:77-97, 397-448. Слепой критерий 1 (≤ 1,5 с при интервале 30 с) зелёный. Boot-push есть (J3 убит слепым 3). Подпись пишется только при `send_message(...) is not False` (:501-503); ключ серии `_UNDELIVERED` (:18, :442-446). Цена замка описана в ADR-PMM-048 «Известная цена» и совпадает с кодом (send под замком, :425-448, :450-453).
2. Потоки: одна точка записи `_last_sent_sig` — `_send_heartbeat_locked` под `_send_lock` (оба вызывающих держат замок). `_sig_error_type` трогает только поток снимка. Повторного входа нет: `send_message` не зовёт обратно heartbeat. Сбой отправки не теряет смену (J2 убит). Стоп — см. сценарий выше и `test_stop_during_slow_push_does_not_hang_the_process` (зелёный).
3. Регулярный heartbeat: формат тот же построитель (ключи push == ключи регулярного, слепой 8 зелёный), каденция (`test_regular_heartbeat_cadence_unchanged`, сетка, H6) зелёная. Подпись наружу не уходит — Dict at Boundary не задет.

## Находки (по убыванию важности; все minor)

1. [process_heartbeat.py:493-503] [quality] — Проблема: при сбое расчёта подписи в регулярном пути копия снимка УХОДИТ в PM, а `_last_sent_sig` остаётся прежней. Вход: ушло `ready=True`; затем снимок `reasons=[{"node": ["x"], "severity": "failure"}]`, регулярный heartbeat; затем снимок снова `ready=True`. Вывод: `sent readiness.ready: [True, False]`, `last_sent_sig unchanged: True (False, True, frozenset())`, `push after recovery: False` — PM держит `ready=False` до следующего регулярного (до `heartbeat_interval`). Плюс лог врёт: `heartbeat: снимок готовности не прочитан: TypeError`, хотя снимок прочитан и отправлен. Из боевого оркестратора недостижимо (node — строка `f"{process}.{plugin}"`, plugin_orchestrator.py:362). Исправление: при сбое подписи в `_send_heartbeat_locked` писать в `_last_sent_sig` метку «ушло неподписанное» (отдельный объект-сентинел, не `None`), чтобы следующий здоровый снимок ушёл push-ем; текст лога — «подпись ушедшего снимка не посчитана». Hazard на этот вход (H7 сейчас проверяет только «регулярный ушёл»).

2. [tests/test_heartbeat_paused_push.py:269-288] [quality] — Проблема: автор правил слепой тест 1.2c; файла нет в FILES задачи (tasks/3.3.md строка 6), а project-rules §5 разрешает это только решением лида. Новая проверка без числовой границы: «нет двух подряд одинаковых `(paused, ready)`» пропустит любое число чередующихся сообщений. Вход: старый литерал на HEAD -> `assert 2 <= 1` (правка нужна по сути). Исправление: лид фиксирует решение строкой в tasks/3.3.md (FILES + причина); в тест — литералы `len(sigs) <= 2` и `sigs[-1] == (False, True)`.

3. [process_heartbeat.py:458-460, ADR-PMM-048 п. 3] [quality] — Проблема: текст говорит «реальный `send_to_process` глотает исключения и возвращает `False`», а push зовёт `send_message` -> `communication.send_message` (process_module.py:1339-1343). Что именно возвращает/бросает `communication.send_message` при недоставке — в тексте не доказано. Поведение безопасно в обоих случаях (есть ветка исключения и ветка `False`). Исправление: назвать в тексте фактическую цепочку `send_message` и её контракт (или ссылку на тест, где реальный транспорт вернул `False`).
