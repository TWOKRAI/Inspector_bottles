## Замечания

### MAJOR-1 (воспроизведено) — `severity` не встроенного типа уходит через границу процесса

Место: `generic/plugin_orchestrator.py:505`. В причину копируется объект `item["severity"]`, который вернул плагин. Проверка `item.get("severity") in _SEVERITIES` пропускает `StrEnum` (это подкласс `str`, сравнение по `==`). `reason` срезом `[:200]` становится обычным `str`, а `severity` остаётся объектом плагина. `copy.deepcopy` в heartbeat (`heartbeat/process_heartbeat.py:387`) сохраняет класс.

Воспроизведение: файл `/private/tmp/claude-501/-Users-twokrai-Project-code-Inspector-bottles/e147e7a0-a862-486f-a6b6-acca4c94b237/scratchpad/repro_severity_enum.py`. Плагин возвращает `[{"severity": Sev.FAILURE, "reason": "camera down"}]`, где `Sev(StrEnum)`:
```
snapshot severity type: __main__ Sev
pickle references __main__.Sev: True
receiver unpickle rc: 1 | ["AttributeError: Can't get attribute 'Sev' on <module '__main__' ...>"]
```
Следствия. Если класса у получателя нет, heartbeat не распаковывается. Сообщение теряется на каждом такте, а это liveness: PM видит UNRESPONSIVE и перезапускает процесс. Если класс у получателя есть, PM импортирует модуль плагина (тяжёлые импорты, побочные эффекты). В обоих случаях нарушен Dict at Boundary. Собственный `try` heartbeat этот путь не закрывает: `send_message` (`:391`) стоит вне него, а `mp.Queue` упаковывает сообщение асинхронно в потоке-питателе.

Что поправить: в `_plugin_reasons` нормализовать значения к встроенным типам, например `severity = _SEVERITIES[_SEVERITIES.index(item["severity"])]` и `reason = str(item["reason"])`. Нужен hazard-тест: `StrEnum`-severity, затем `type(r["severity"]) is str` и pickle-раунд в чистом интерпретаторе (`-I`).

### MAJOR-2 (приёмка; лид решает) — ACCEPTANCE не проверен одним тестом от начала до конца

ACCEPTANCE требует: «юнит с настоящими объектами (`ProcessHeartbeat`, настоящая очередь, `heartbeat_interval = 0.2`): поле `readiness` приходит каждый такт, `paused == true` ≤ 1 с после `clear()`, `false` ≤ 1 с после `set()`».
Фактическое покрытие состоит из двух частей:
- `test_readiness_publish.py` — настоящий heartbeat и настоящая очередь, но снимок статический, положен вручную. Тест доказывает только транзит поля;
- `tests/test_readiness_hazards.py:445` `test_paused_flag_follows_event_within_budget` — время меряется по атрибуту `_readiness_snapshot`, сообщение из очереди не читается. Граница 0,8 с, а бюджет DESIGN 0,05 + 0,5 + 0,2 = 0,75 с, поэтому запас мал и тест может мигать.

Цепочку «воркер снимка → heartbeat → очередь → `paused`» с замером времени не держит ни один тест. Разработчик это признал (`reports/1.2.developer.md`, «открытое»). Возможный путь (advisory, не проверял): положить `"heartbeat_interval": 0.2` на верхний уровень `cfg` бандла, потому что `ProcessHeartbeat.start` читает `get_config("heartbeat_interval")`, и подменить `proc.send_message` очередью.
