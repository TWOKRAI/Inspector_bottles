# Плашка по режиму экрана и «триггер без кадра» (П6, владелец 2026-11-26)

Решение для задач W2-c2b, W2-t1, W2-t2, W2-c3 (поправка), W2-t3 (заморожена до железа). Числа строк — `integ` `8215a0c78`.

## Слова владельца

1. Плашку настраивают для каждого экрана в рецепте.
2. Камера по триггеру: плашка, если триггер был, а кадр не пришёл.
3. Источника триггера на линии сегодня нет («пока никак; заложи, тестить будем не скоро»). Механизм доказывается на синтетике сейчас. Настоящий источник подключается позже без переделки плашки: событие `Line0` камеры, контроллер или робот сообщением роутера.

Три режима экрана: держать последний кадр (умолчание, как сегодня); тишина N с; триггер без кадра за срок. Следующий кадр снимает плашку. Длинный текст переносится. Текст — гибкий шаблон, как в W2-c2.

## Что сегодня несёт «триггер был» (прочитано в коде)

- Живого сигнала нет. Есть только `RawFrame.trigger_index` (`Services/camera_device/interface.py:86-96`). MVS берёт его из `nTriggerIndex` (`Services/hikvision_camera/driver.py:447`). Его видно только с ПРИШЕДШИМ кадром. Разрывы `_on_frame` считает в `trigger_lost` (`plugin_base.py:505-508`) задним числом, на следующем кадре. Триггер без единого кадра после него не виден никак. Без chunk `nTriggerIndex = 0` даёт `None` (W1-a, не проверено на приборе).
- События прибора `EventSelector` (`Line0RisingEdge`, `FrameTriggerWait`) и счётчик `Counter0` есть на приборе (`docs/reviews/2026-11-26_stand-camera-packet-size.md:60-62`). Код их не читает. Вне записи прибора (`testing/recordings/*.json`) `git grep -n "Line0RisingEdge\|FrameTriggerWait\|Counter0" -- Services` пуст. У порта один канал событий — `drain_link_events` (`interface.py:323`), только обрыв связи. Его читает поток-владелец (`session.py:969,1044`).
- Программный триггер: `cmd_trigger_software` (`plugin_base.py:1133-1146`). Плагин знает, что отправил импульс.

## Где искать «триггер без кадра» — в бэкенде, в плагине камеры

Причины:
1. Это сигнал для других. Владелец: инспектор шлёт сигналы, ПЛК решает про ленту. Плагин публикует блок `frame_watch` в дереве, метрику и WARNING. На них подпишется переводчик ПЛК (в конце), карточки и плашка.
2. Только плагин видит оба события до прореживания GUI. Насос показывает не чаще `fps_limit`, ящик вытесняет кадры (`superseded`). Кадр, вытесненный в GUI, — всё равно кадр. В GUI счёт был бы ложным.
3. Бэкенд работает без GUI (принцип 6). Проверка в GUI молчала бы при закрытом окне.
4. Слоёв не прибавляется: чистый помощник `Services/camera_device/frame_watch.py`, вызовы из плагина. Вынос в framework — у третьего потребителя (как Р1/Р-W2-3).

GUI только рисует: экран в режиме `trigger` ставит плашку по `frame_watch.open_miss` своего источника.

## Контракт

Поля плагина камеры (регистры `registers_base.py`, умолчания — поведение без изменений):
- `frame_watch: Literal["off", "software", "message"] = "off"`:
  - `software` — импульсом считается каждый удачный `trigger_software`;
  - `message` — команда `trigger_seen {}` от любого процесса через роутер (контроллер, робот, на синтетике — backend_ctl).
  - Значение `device` (событие прибора) добавит W2-t3. Расширение `Literal` старые рецепты не ломает.
- `frame_watch_deadline_ms: int = 500`, пределы 1..10000.

Блок дерева `processes.<p>.state.plugins.<n>.frame_watch` (в том же `merge`, что `link`, `plugin_base.py:702-716`):
- `{"source": str, "deadline_ms": int, "triggers": int, "misses": int, "open_miss": bool, "last_miss_ts": float | None}`;
- `last_miss_ts` — `time.time()` (GUI на той же машине считает возраст);
- `open_miss` — `True` от первого просроченного импульса до следующего кадра;
- метрика `trigger_missed` (накопительная) — рядом с `trigger_lost`, `plugin_base.py:627`;
- лог: WARNING один на эпизод `"триггер без кадра: срок <deadline> мс"`, INFO при закрытии `"кадр после пропуска триггера, пропущено <k>"`.

Правило помощника `FrameWatch(deadline_s)`:
- `on_trigger(now)` — импульс в очередь;
- `on_frame(now)` — кадр гасит самый старый ждущий импульс (FIFO, кадр на импульс). Кадр без ждущего импульса не считается. Кадр закрывает `open_miss`;
- `poll(now) -> int` — каждый ждущий старше срока = пропуск, снят с очереди, `open_miss = True`. Возвращает число новых пропусков;
- `snapshot() -> dict` — `triggers`, `misses`, `open_miss`, `last_miss_mono`.
- Не потокобезопасен. Плагин зовёт все методы под своим `self._lock`: кадр уже под ним, `plugin_base.py:505`. Часы передаются аргументом.

Ключи экрана (`DisplayDefinition`, top-level `displays` рецепта; `extra="forbid"` остаётся):
- `plate_mode: "hold" | "silence" | "trigger" = "hold"`;
- `plate_after_s: int = 2` (1..600; только для `silence`);
- `plate_text: str = ""`;
- `plate_source: str = ""`.
- Умолчания `minimize` в рецепт не пишет (`adapters/recipe_canonical.py:96-116`), старые рецепты не меняются. Вопрос схемы домена, поднятый к CTO, решён: поля идут в `DisplayDefinition` (W2-c2b). CTO может наложить вето на стадии 0.

Статус плашки по приоритету: `link.state == "lost"` -> «нет связи, N с»; режим `trigger` и `open_miss` -> «триггер без кадра, N с» (N от `last_miss_ts`); режим `silence` -> «нет кадров, N с».

## Порядок

1. W2-c2b — режимы `hold`/`silence`, N на экран, перенос строки, поля схемы; ветка `dev/w2-c2` поверх `20899db90`.
2. Параллельно с W2-c2b — W2-t1 (помощник и поля), затем W2-t2 (плагин).
3. W2-c3 — после W2-c2b; режим `trigger` в GUI берёт имена блока из этого контракта, код W2-t2 для тестов не нужен (дельты подаёт тест).
4. W2-t3 — ЗАМОРОЖЕНА до прибора: источник `device`.

## Синтетика (П4, решение 5)

Пропуск на фейке:
- камера `frame_watch: message`, кабель вынут `fake_cable {"plugged": false}` (W2-q);
- `send_command("cam_3", "trigger_seen", {})` -> через срок `open_miss true`, плашка `trigger` на экране;
- кабель вставлен (`reconnect true`) -> кадр -> плашка снята.

Без кабеля: фейк в свободном потоке гасит импульс ближайшим кадром. Это проверка «импульс с кадром не даёт пропуска».

## Что не проверено

- Приходят ли события `Line0RisingEdge` при `EventNotification On` на MV-CS020-10GC.
- Растёт ли `nTriggerIndex` без chunk.
- Задержка события относительно кадра (срок 500 мс — выбор лида, не замер).
