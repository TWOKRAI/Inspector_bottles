  2. `DeviceSession.__init__`: именованные `reconnect: bool = False`, `link_silence_s: float = 0.0`, `reconnect_interval_s: float = 2.0`; читаются один раз. Состояние `lost` — в список докстринга `session.py:9-10`; `_FAILED` сеанса (`session.py:53`) не меняется (стоп во время `lost` даёт финальное `closed`).
  3. `_grab_loop` возвращает `Literal["stopped", "failed", "lost"]`. `last_frame = last_probe = time.monotonic()` на входе; кадр -> `last_frame = now`, `self._link = "up"`. `_poll_box` сообщает, исполнил ли он команду (флаг `self._box_ran`); исполнил -> `last_frame = last_probe = time.monotonic()` (перезахват по живой правке — не тишина). После каждого возврата `get_frame`: (а) `isinstance(self._port, LinkEventSource)` и `"disconnected" in self._port.drain_link_events()` -> причина `"событие прибора disconnected"`, `"lost"`. (б) `link_silence_s > 0` и `now - last_frame >= link_silence_s`: `mode` = `Step.value` шага поля `trigger_mode` в `self._run` (шага нет -> `None`). `mode` не `None` и не `"On"` (свободный поток) -> `"lost"` сразу, причина `f"тишина {s:.1f} с при trigger_mode={mode}"`, проба не спрашивается (решение лида: на стенде прибор мог отвечать при мёртвом потоке). `mode == "On"` или `None` -> проба, если `now - last_probe >= link_silence_s`: `last_probe = now`; план пуст -> `self._link = "silent"`; иначе `self._port_call("probe", self._port.get_param, self._run[0].binding)`; `PortError` вида `network|closed|timeout|not_found|busy` -> `"lost"`, причина `f"тишина {s:.1f} с, проба: {describe_error(exc)}"`; другой вид (`access`, `range`, `other`) или значение -> прибор ответил, `self._link = "idle"`. (в) три `PortError` подряд: `reconnect` -> `self._last_error = describe_error(exc)`, `"failed"` БЕЗ `_fail`; иначе прежний `_fail("error", exc)`, `"failed"`. (г) Исход `"lost"` (а, б) всегда пишет причину в `self._last_error`. Без `reconnect` (РЕШЕНИЕ ЛИДА по ревью): одна ERROR `session: связь с прибором потеряна (<причина>); переподключение выключено`, `self._cas(("grabbing",), "error")`, `self._link = "lost"`, повторов нет; готовность — прежняя «ошибка камеры», без «переподключение». Иначе рецепт с `trigger_managed true` + `Off` молча держал бы мёртвый поток.
  4. `_owner_main` — цикл попыток. Общее на весь цикл: один ящик команд (`_close_box(box)` только в финальном `finally`), один сторож (`_start_watchdog` один раз), `ever_grabbed = False`. Каждая попытка с нуля: `hold = self._hold = _Hold()`, `self._regrab_failed = False`, `self._profile.reset()`, новый `ProfileRunner` после `open`. Шаги попытки: `acquire` -> стоп? -> `_resolve_ident` + `open` -> стоп? -> `run = self._run` под `self._lock` -> `apply_plan(run)` -> стоп? -> вычитать и отбросить `drain_link_events()` (DEBUG с числом) -> `start_grabbing` -> п.6. Перезахват по живой правке (`_regrab`, `session.py:741`) тоже вычитывает и отбрасывает события перед своим `start_grabbing`. «Стоп?» = `stop_evt()` -> выход. Первая попытка ведёт `cmd` как сейчас (`_commit`, `_enter_grabbing`); `cmd.cancelled` (истёк срок `start`) -> выход без повторов, как сейчас. Повторы `cmd` не читают; вход в `grabbing` на повторе — `_set_loop_state("grabbing")`.
  5. Отказ попытки (`PortError` или иное исключение на шагах п.4) или исход `"lost"`/`"failed"`: без `reconnect` — поведение прежнее. С `reconnect`: (а) отказ ПЕРВОЙ попытки (прибор ещё не брался): прежний `_fail(_failed_state(exc, opening=not hold.opened), exc)` ровно один раз (не-`PortError` -> `error`), затем `self._reconnecting = True` ДО `cmd.finish(False)` (вызывающий `start()` видит `reconnecting`). В (а) и (б) под ОДНИМ захватом `self._lock`: запись состояния (правила `_set_loop_state`), `self._reconnecting = True`, слияние `self._pending` в план (`self._run = self._replace_in_run(...)`), очистка `_pending` (поставленный `_drain` найдёт пустой пакет и выйдет, `session.py:716-717`). Не-`PortError` (например `OSError` из ctypes): первый — `logger.exception` (со стеком), дальше — тем же дросселем 60 с (решение лида). (г) уборка `_cleanup(hold.grabbing, False, hold.opened, hold.acquired)`; ожидание `reconnect_interval_s` срезами `cycle_stop.wait(0.1)` с проверкой `stop_evt()` после каждого среза; затем `self._attempts += 1`.
