## Зачем

Приёмка F1 подтвердила: правки ремедиации на своих путях работают (Б-1/Б-2 закрыты live, темп действует, TTL жив, документация опорная — 123/129 утверждений совпали с кодом). Но братья тех же дефектов живут на соседних путях, и ровно они держат оси 3 и 5 ниже порога: хвост самого оркестратора и GUI остались ERROR-only, у второго стора нет vacuum, у слоя L3 есть дверь без валидации, контракт судит имена, но не типы. Список адресный, объём — дни. **Вход в план телеметрии уже открыт** — этот план идёт до или параллельно ей и не содержит её задач (stats-разъём C1 остаётся первой фазой телеметрии, решение Р-2в предшественника).

## Правила исполнения (наследуются от предшественника)

- Каждый коммит: `Refs: plans/observability-f1-hardening.md` + `Why:` + `Layer:`.
- **Break-injection на каждое заявленное свойство**, красные предсказываются ДО прогона; откат — восстановлением файла.
- **«Красный без фикса»** до починки.
- Три роли авторства тестов; независимый `tester` — там, где контракт наблюдаем снаружи; пропуск объявлять вслух.
- Каждое свойство сдаётся ненулевым live-фактом с числами; live-прогоны одиночные (порт 8765), логи в `logs_live/<дата>_<задача>/`.
- Ни «невозможно», ни «гарантировано» без воспроизведения рядом.

# Фаза A — пороги F1 (оси 3 и 5)

### Task A1 — level в «своём хвосте» оркестратора
**Уровень:** Middle+ (Sonnet) · **Исполнитель:** developer · **Основание:** Н-1 (major).
**Что подтверждено:** `observability_broker.py:283-293` — `_own_tail` зовёт `subscribe_self(subscriber)` одним аргументом; `subscribe_observability_tail(subscriber, level=None)` → `None` → дефолт `"ERROR"` (`process_module.py:1081`). Live: `orchestrator.min_level="ERROR"` при `tail_level="INFO"`, 0 событий ПМ при 22 строках стора за окно. Переподписка (replay) уровень из намерения несёт правильно — дефект один.
**Шаги:** передать level из намерения в `_own_tail` (та же запись durable-подписки, из которой его берёт `_fan_out`); тест брокера «свой хвост несёт уровень намерения» + «смена уровня переподпиской доезжает и до своего хвоста».
**Приёмка:**
- [ ] Live: `watch_like_gui(tail_level="INFO")` → в ответе `orchestrator.min_level == "INFO"`; за окно ≥60 с в `plane=logs` есть события `process=ProcessManager` с `severity=info` — число в отчёте (база для сравнения: стор ПМ ~22 строки/200 с).
- [ ] Тест красный без фикса.
**Инъекции:** (и-1) вернуть одноаргументный вызов `fn(subscriber)`; (и-2) брать уровень не из намерения, а константой.

### Task A2 — GUI-подписка называет уровень **(развилка Р-2)**

**Инъекции:** (и-3) убрать ключ из конверта → красный юнит.
**Вне скоупа:** ручка уровня в UI (отдельная задача, если Р-2 ≠ (в)).

### Task A3 — telemetry-содержимое L3 под валидатор значений
**Уровень:** Middle+ (Sonnet) · **Исполнитель:** developer · **Основание:** Н-4 (major) — класс B2 на соседней плоскости.

**Инъекции:** (и-4а/б) снять проверку на каждой из двух дорог по отдельности — частичная инъекция обязана дать ровно свой красный.

### Task A4 — типы на границе контрактов **(развилка Р-3)**
**Уровень:** Senior (Opus) · **Исполнитель:** teamlead · **Основание:** Н-5 (medium) — major-16 закрыт по именам, не по типам.
**Что подтверждено:** live `introspect.observability {"resolve": true}` → «Dispatch failed: 'bool' object is not iterable» + запись в plane=errors. Контракт объявляет `Union[str, List[str]]`, мидлварь в warn-режиме передаёт сырые args хендлеру.

**Приёмка:**
- [ ] Live: `resolve=true` → `success=false` + адрес поля и ожидаемый тип (не TypeError диспатча).
- [ ] Валидные формы (`str`, `list[str]`) работают — пара ОТКАЗ/ПРИЁМ.
- [ ] Оракул дополнен осью «хендлер читает провалидированное, не сырое» — красный на текущем коде до фикса.
**Инъекции:** (и-5) вернуть передачу сырых args; (и-6) снять адресность отказа (голый false).
