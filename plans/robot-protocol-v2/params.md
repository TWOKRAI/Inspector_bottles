# Словарь параметров робота v2

- **Часть контракта** [protocol-spec.md](protocol-spec.md) (вынесена по размеру; нумерация разделов сохранена — §11).
- **Источник истины:** `Services/robot_comm/protocols/delta_v2.yaml` → секция `params:`; расхождение с этим файлом — дефект YAML.

## 11. Параметры

### 11.1 Правила

- Значения — сырые целые u16/s16; YAML хранит для каждого `label`, `unit`, `scale`, `signed`, `min`, `max`, `default`, `group`, `apply`, `info`. GUI строит форму из этих метаданных.
- `PARAM_SET`: неизвестный id → `E_BAD_PARAM`; вне min..max → `E_RANGE`, значение не меняется; принятое значение сразу пишется в зеркало `0x3000 + id` (сохраняемая область, RL 12-2 ⚑; запасной вариант — `0x1300 + id`), затем пересчитывается `PMIR_CRC`.
- Прошивка проверяет только диапазон каждого параметра. Связи между параметрами (`R_MIN < R_MAX`, `ZONE_MIN < ZONE_MAX`) проверяет ПК до отправки. Если на роботе всё же окажется противоречивая пара, проверка зоны отклоняет цели — это безопасная сторона.
- Id стабильны навсегда (тест-снимок); группы идут блоками по 16, свободные id — для расширения.
- Хранение в двух местах: ПК — источник истины; робот — последние применённые значения в сохраняемом зеркале. После выключения питания робот стартует с них, а не со значений, зашитых в прошивку (§11.4).
- Сырое значение слова — от −32767 до 32767 (RL 12-2); −32768 не используется.

### 11.2 Классы применения (`apply`)

| Класс | `PARAM_SET` во время команды | Когда действует |
|---|---|---|
| `live` | разрешён (обрабатывается в ближайшей точке опроса) | с ближайшей точки опроса |
| `idle` | NAK `E_BUSY` | со следующей команды |
| `reinit` | NAK `E_BUSY` | после `PARAM_APPLY`: прошивка переинициализирует подсистему (CVT — `CVT_Initialization`, порт ПЧ — `SCM_FreePort`). До этого `TLM_CFG_PENDING = 1`, а зависящие команды (`CVT_JOB`) получают NAK `E_CFG_PENDING` |

⚠️ Допустима ли переинициализация CVT и порта на ходу программы, выясняется на GATE-1. Если нет — класс `reinit` меняет смысл на «после перезапуска программы на роботе» (перезаливка всё равно не нужна), `PARAM_APPLY` отвечает NAK, GUI показывает «перезапустите программу робота».

### 11.4 Синхронизация с ПК

1. Хранилище значений — ПК (`data/robot/<device_id>/params.yaml`, plan.md §4.3), источник истины. Робот держит
   рабочую копию в сохраняемом зеркале вместе с `P_CONFIG_EPOCH`.
2. **Старт программы на роботе:** если `PMIR_MAGIC`, `PMIR_CRC` и `PMIR_DICT` (отпечаток словаря этой сборки)
   сходятся — параметры и метка берутся из зеркала, каждый слот дополнительно проверяется на диапазон; иначе —
   значения по умолчанию, метка 0, зеркало переписывается ими. Отпечаток ловит новую сборку прошивки с
   добавленным параметром: без него старое зеркало приняло бы для нового параметра 0.
3. **Последовательность подключения:** probe `TLM_PROTO_VER` (только чтение) → чтение телеметрии → если
   `TLM_CFG_EPOCH` ≠ метке в хранилище ПК **или** `PMIR_DICT` ≠ отпечатку словаря ПК: отправка всех параметров `PARAM_SET` → `PARAM_APPLY`, если
   `TLM_CFG_PENDING = 1` → сверка зеркала с ожидаемым → запись новой метки `P_CONFIG_EPOCH` **последней**.
   Совпала метка — ничего не отправляется: робот уже на значениях ПК.
4. **Робот сбросил параметры** (испорчено зеркало, новая прошивка, другой ПК записал своё) — метка разойдётся,
   драйвер увидит это при очередном чтении телеметрии и повторит шаг 3. Значения не теряются молча.
5. Правка из GUI: `PARAM_SET` → ACK → драйвер сохраняет значение и новую метку в хранилище ПК. NAK → значение
   не сохраняется, GUI показывает текст errno.
6. ⚑ Если проба не подтвердит сохранение `0x3000..` через выключение питания, зеркало живёт в `0x1300 + id`,
   шаг 2 всегда берёт значения по умолчанию, а шаг 3 отправляет всё после каждого старта программы.
