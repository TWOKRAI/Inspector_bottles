## 0. Преамбула каждого брифа (агенту дословно)

1. **Git.** Работать в `feat/robot-protocol-v2`; писатели — каждый в своём worktree
   (`.claude/worktrees/team-<task>`), не больше трёх одновременно. Перед стартом сверить SHA базы с HEAD ветки;
   расхождение — стоп и доклад. **Не коммитить и не пушить**, если бриф этого прямо не разрешает.
2. **Коммиты** (если разрешены): Conventional Commits + `Why:`, `Layer:`, `Refs: plans/robot-protocol-v2/plan.md`.
3. **Тесты.** pytest из корня; `python scripts/validate.py` перед сдачей. GUI — только `QT_QPA_PLATFORM=offscreen`.
   Минимум один тест на боевых значениях параметров. Тест, который может зависнуть, вызывает код в
   daemon-потоке с дедлайном.
4. **v1 неприкосновенен:** `Services/robot_comm/core/{registers,client}.py`, `server/sim_core.py`,
   `Services/device_hub/drivers/robot_driver.py`, `robot/main_actual.lua`, `robot/universal3/*`, v1-тесты. Все
   v1-тесты зелёные после каждой задачи.
5. **Контракт первичен.** Адреса, id, опкоды, errno, коды причин — только из YAML через кодоген. Рукописный адрес
   вне `delta_v2.yaml` — брак.
6. **Язык.** Комментарии, докстроки, README — по-русски; идентификаторы — английские.
7. **Поиск.** «Где используется X» — `mcp__qex__search_code` после `get_indexing_status` (возраст индекса — в
   промпте числом), затем Grep. Числа — только грепом.
8. **Эскалация** (`project-rules` §7): вопрос — на уровень выше, не в догадку. Отчёт заканчивается разделом
   «что я оставил открытым и что в моей работе ненадёжно».

**Создать:** `Services/robot_comm/protocols/delta_v2.yaml`.
**Сделать:**
- `registers:` — в схеме существующего загрузчика (`Services/modbus/core/protocol_file.py:load_protocol`,

### T2.0 — Геометрия SCARA (developer, Layer: services)

`Services/robot_comm/programs/geometry.py` (Qt-free, без состояния): точка в зоне (кольцо, Z, RZ, сектор
`atan2`, ограждение) с кодом причины; отрезок LINE (расстояние до оси аналитически + сектор выборкой 5 мм);

**Приёмка (tester):** каждая причина на боевых границах; отрезок с допустимыми концами через мёртвую зону и через
недоступный сектор — отклонён; СК из трёх точек → база → СК — тождество.
**Известный предел (ревью 2026-09-27):** сектор у отрезка проверяется выборкой ≤ 5 мм — запретный клин с хордой
< 5 мм на `r_min` проскакивает (пример: сектор ±179°, `(-100,1.75)→(-100,-18.25)` → 0). На дефолтах (±165°, r_min 100)
хорда 53.6 мм, пропусков нет. Точное решение — пересечение с двумя граничными лучами аналитически; сделать в T3.3,
если зона будет настраиваться уже ±175°.

### T2.1 — sim v2: mailbox, параметры, безопасность (developer, Layer: services)

`Services/robot_comm/server/sim_core_v2.py`, `tests/test_sim_v2_core.py`. `RobotSimCoreV2(regs)` по образцу
интерфейса v1 (`tick()`, `attach()`), все адреса — из `protocol_v2`. Mailbox: флаг → разбор → проверки
(опкод, argc, `busy`) → ответ с `RES_SEQ` последним; повтор seq — повтор ответа. Опкоды: PING, CLEAR_ERR,
SERVO, DO_SET, PARAM_SET/GET/APPLY (классы применения, `E_CFG_PENDING`, зеркало + CRC, метка). Плоскость
безопасности: `STOP_REQ` по «значение изменилось», при старте текущее считается обработанным; `HB_PC`,
`JOG_LEASE` — каркас (действия — T2.2/T2.3).
**Приёмка (tester):** ACK/NAK на каждый опкод задачи; вне min..max → `E_RANGE`, значение не изменилось;
`live` проходит во время длинной команды, `idle` — `E_BUSY`; `reinit` → `CFG_PENDING` до `PARAM_APPLY`;
«перезапуск» sim с валидным зеркалом сохраняет значения и метку, с испорченным CRC — значения по умолчанию и
метка 0; повтор seq идемпотентен; повтор значения `STOP_REQ` не срабатывает второй раз.

### T2.2 — sim v2: движение (developer, Layer: services)

> **Заметки ревью T2.1** (`sim_core_v2.py`): `busy = ACTIVITY != IDLE` не отличает FAULT — обработчикам нужно третье
> состояние (§5: в FAULT SERVO/PARAM_SET принимаются, CLEAR_ERR → IDLE); `_handle_stop` пишет `STOP_ACK` сразу на
> любом уровне — отложенному SOFT нужен слот «ожидает»; PTP_MOVE — заглушка `PTP_PLACEHOLDER_TICKS`, заменить.

Поза интерполируется к цели со скоростью от `P_SPD_L × %` (минимум три тика на ход 100 мм). PTP, HOME,
JOG_STEP, JOG_CONT (едет, пока растёт `JOG_LEASE`; стоп по поводку, зоне, `STOP_REQ`). Зона SCARA: кольцо,
Z, RZ, ограждение; отрезок LINE не ближе `P_WS_R_MIN` к оси; причины в rval. Стоп SOFT/HARD/HALT; `E_ABORTED`
событием; `E_NO_SERVO`.
**Приёмка (tester):** поза меняется монотонно ≥ 3 тиков; каждая причина `E_RANGE` на боевых границах;
отрезок через мёртвую зону отклонён при допустимых концах; JOG_CONT встаёт через `P_JOG_LEASE_MS` без поводка;
каждый уровень стопа; HALT выключает серво и шлёт стоп ПЧ.

### T2.K — Модель робота (developer, Layer: services)

**Решение владельца 2026-09-27:** робот должен быть сменным — сейчас SCARA Delta Electronics (серия DRS),
в будущем 6-осевой или дельта («паук»). Сосредоточиться на SCARA. Кинематика SCARA — закрытой формулой без
новых зависимостей; `roboticstoolbox-python` (замер 2026-09-27: 1.4.4 работает на numpy 2.5.3, IK SCARA
0.25 мс, Puma560 решается; тянет scipy + spatialmath) — отдельной группой зависимостей, когда появится
6-осевой; дельта — формулы Клавеля за тем же интерфейсом. Поза протокола остаётся X/Y/Z/RZ: RX/RY добавляются
вместе с прошивкой 6-осевого (новый `PROTO_VER`), не заранее.

Три слоя замены: **контроллер/протокол** — поле `protocol` записи устройства (уже есть); **кинематика и зона** —
`RobotModel` (эта задача); **поза протокола** — расширение YAML вместе с новым роботом.

`Services/robot_comm/kinematics.py` (lite-модуль, Qt-free, без состояния модуля):
- `RobotModel` (Protocol): `kind`, `axes` (оси позы протокола), `joint_names`, `fk(joints) → pose`,
  `ik(pose, hand) → joints | None`, `chain_points(joints) → [(x, y, z), …]` (точки звеньев для отрисовки
  любым видом), `check_point(ws, pose) → reason`, `check_segment(ws, p0, p1) → reason`.
- `ScaraModel(l1, l2)`: J1, J2 — вращение, J3 — Z, J4 — вращение инструмента; `RZ = J1 + J2 + J4`;
  `hand` — как `P_HAND` (0 правая / 1 левая), правая ⇔ `J2 ≥ 0` ⚑ GATE-1 (знак сверить на железе);
  вне досягаемости (`|l1−l2| ≤ r ≤ l1+l2` нарушено) → `None`. Зона — делегирует `programs/geometry.py`
  (она зеркалит проверку прошивки, И6 — вторая «правда о досягаемости» не заводится). Длины звеньев —
  не параметры прошивки (контроллер считает кинематику сам), а свойство модели на ПК; по умолчанию
  заглушка 325 + 275 = 600 мм = `P_WS_R_MAX` по умолчанию, ⚑ модель с шильдика (plan §9 вопрос 1).
- `make_model(spec: dict) → RobotModel` (Dict at Boundary: `{"type": "scara", "l1": …, "l2": …}`),
  неизвестный тип → `ValueError` со списком известных.
- `RobotSimCoreV2(regs, *, model=None)`: по умолчанию `ScaraModel()`; проверки зоны — через модель;
  `joints()` — суставы текущей позы (IK позы из `TLM_*` с `TLM_HAND`) для окна-вида.
**Приёмка (tester):** `fk(ik(p, h)) == p` (±1e-6) для обеих рук на сетке точек зоны; руки дают разные
решения с противоположным знаком J2; точка дальше `l1+l2` и ближе `|l1−l2|` → `None`; `chain_points`
начинается в (0, 0, ·) и кончается в XY позы; `make_model` с чужим типом → `ValueError`; sim с моделью по
умолчанию — все тесты T2.1/T2.2 зелёные без правок; sim с подставной моделью, запрещающей всё, отвечает
`E_RANGE` на любой ход (проверка идёт через модель, а не мимо неё).

### T2.J — JOINT по суставам (developer, Layer: services)

**Находка живого снимка T2.V (2026-09-27):** ход JOINT `(-250, 350) → (-450, -150)` в sim идёт прямой в декартовых
координатах сквозь запретный сектор J1 (±165°). Настоящий робот так не поедет: J1 ограничен и повернёт длинным путём
через 0°. Упрощение T2.2 («JOINT интерполируется в декартовых») было безвредно без вида и без модели; теперь оно
показывает оператору путь, которого у робота нет, — а владелец просил, чтобы после железа ничего не переделывать.
`_progress_move` для JOINT/HOME: суставы от `model.ik(старт, TLM_HAND)` до `model.ik(цель, P_HAND)` линейно
(J1 в `(-180, 180]`, поэтому ±180° не пересекается), поза тика = `model.fk(суставы)`; длительность хода — как
сейчас (декартова длина / скорость), чтобы тайминги T2.2 не поплыли. `ik` = `None` у старта или цели (зона шире
досягаемости модели) → прежняя декартова интерполяция с `ponytail:`-пометкой. LINE и JOG не меняются.
**Приёмка (tester):** на этом ходе каждая поза тика проходит `check_point` (не заходит в сектор и мёртвую зону);
последняя поза = цель ±0.1; число тиков хода = T2.2 ±1; все тесты T2.1/T2.2/T2.K/T2.V зелёные; подставная модель
с `ik → None` даёт декартов путь.
