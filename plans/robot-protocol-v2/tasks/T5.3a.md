DESIGN (решено; не выводить заново):
  1. `RobotDriverV2.__init__(..., spawn: Callable[..., IHandle] | None = None)` — вызывается как `self._spawn(target, name=<имя>)`, `target(event)`. Тип `IHandle` — из `multiprocess_framework.modules.base_manager.interfaces`.
  2. `spawn is None` (тесты T5.1/T3.7, автономный драйвер): драйвер лениво открывает свой корень `open_scope(f"rv2-{entry.id}", budget_s=_PROGRAM_JOIN_S + _LEASE_JOIN_S)` при первом `spawn` и закрывает его в конце `disconnect()`; следующий `spawn` открывает новый. Импорт — `from multiprocess_framework.modules.base_manager import open_scope` (не `core.lifetime`: G6 R7).
  3. Поводок: `_JogRun.thread` → `_JogRun.handle: IHandle | None`; имя `f"lease-{run.seq}"` (seq растёт — имя не повторяется, пока старый поток выходит). `target = lambda ev: self._lease_loop(run, ev)`. В цикле: `run.released` → выход без стопа (стоп шлёт release); `ev.is_set()` без release (область закрывается) → путь истёкшего окна Д3 (`_stop_jog(run)`) → выход. Ожидание периода — `run.wake.wait(period)`; release по-прежнему будит `run.wake`.
  4. Исполнитель: имя `f"prog-{n}"`, `n` — счётчик экземпляра. Живость — флаги, не объекты потоков: `run.active` (снимается в `finally` поводка, как сейчас) и новый `_prog_alive` (ставится под `_flags_lock` вместе с `_busy` до `spawn`, снимается в `finally` `_program_loop`). `_activity_alive()` читает только флаги. `spawn` бросил (`ScopeClosedError`, `ValueError`) → флаги откатить под замком, ответ `{"status": "error", "message": "область потоков хаба закрыта"}` (постоянный текст `TEXT_SCOPE_CLOSED`).
  5. Ожидание выхода: `jog_release` и `disconnect` — `run.handle.close(_LEASE_JOIN_S)` вместо `_join(thread, ...)`; исполнитель в `disconnect` — стоп SOFT, затем `handle.close(_PROGRAM_JOIN_S)`. `CloseReport.survivors` не пуст → `_record_err()` + `logger.warning` с путём потока; не бросать. Поток не закрывает свою же запись (путь окна Д3 — без `close`).
  6. V1: `disconnect()` читает `self._jog` и помечает его `released/stop_requested` под `with self._jog_tx_lock: with self._flags_lock:` (JOG_CONT в полёте дописывает `self._jog` до входа), затем ОТПУСКАЕТ `_jog_tx_lock` и только потом `handle.close` и `_stop_jog(run)` (иначе поток поводка на пути Д3 ждёт этот замок до срока).
  7. `_launch`: при `self._jog_stopping` → `dict(_BUSY_JOG)` (окно T3.7). `_program_loop`: итоговая публикация `.program` — ДО снятия `_busy` (в `finally`: публикация, затем флаги).
  8. В файле не остаётся ни одного вызова `threading.Thread(`/`Timer(`; `import threading` остаётся для `Lock`/`Event`.
  9. `DeviceManager.__init__(store, publish_cb=None, *, spawn=None)`; фабрика `robot` передаёт `spawn=self._spawn` в `RobotDriverV2`; v1 — без изменений.
  10. `DeviceHubPlugin.configure`: `self._scope = open_scope("device_hub", budget_s=_SCOPE_BUDGET_S)` (`_SCOPE_BUDGET_S = 7.0` — поводок 1.0 + исполнитель 5.0 + запас 1.0), `DeviceManager(store=..., publish_cb=..., spawn=self._scope.spawn)`. `shutdown`: удалить воркеры → `self._manager.shutdown()` → `report = self._scope.close()`; выжившие или ошибки → `ctx.log_warning` с путями и `ctx.health.report_error(..., context="device_hub.scope")`. `DeviceManager.attach_scope` НЕ используется (шаблон закрыл бы область до `_on_shutdown` — до стопа робота).
  11. `scripts/lifecycle_guards/tables.py`: удалить запись `("R1", "Services/device_hub/drivers/robot_driver_v2.py")` целиком, больше ничего.
