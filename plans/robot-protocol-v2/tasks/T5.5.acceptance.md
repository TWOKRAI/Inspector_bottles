# T5.5 — приёмка для слепого тестера (ред. 2)

## Вход

Поверхность вызова: хаб — `DeviceHubPlugin`, команды `robot_draw_polyline {device_id, points: [{x_mm, y_mm, pen}], z?}`,
`robot_enqueue_job {device_id, x_mm, y_mm, z_mm?, e_capture?, place_x?, place_y?, place_z?, place_rz?}`,
счётчики драйвера — `plugin._manager.get_driver(<id>).snapshot()` (поля `jobs_done`, `queue_len`); состояние программы — публикация `devices.state.<id>.program`
(`{name, state, done, total, error}`); sim v2 — `Services/robot_comm/tests/e2e_rig_v2.py` (`E2eRig`, `bounded`, `pulse`).
Плагины — `Plugins.io.robot_draw.plugin.RobotDrawPlugin`, `Plugins.io.robot_io.plugin.RobotIoPlugin`; их транспорт в хаб —
атрибут `_client` с методом `request(command, data, timeout=...) -> dict`. Образец сборки хаба с v2-роботом на sim —
помощники `_plugin`, `_add_v2`, `_cmd`, `_shutdown` в `Plugins/hub/device_hub/tests/test_robot_v2_commands_acceptance.py`.

Как устроен стенд (это не реализация, а свойства помощников, без которых случаи не исполнимы):
- **Тик драйвера сам не идёт.** В хабе на `make_ctx` менеджер воркеров — подделка, воркеры не запускаются
  (`Plugins/hub/device_hub/tests/conftest.py:23-35`, `FakeWorkerManager`). Тик драйвера (пульс робота, исполнение
  заданий) тест крутит сам: `drv = plugin._manager.get_driver("r1")`, `with pulse(drv.tick, 0.05): ...` — образец
  `Plugins/hub/device_hub/tests/test_robot_park_all_plugin_acceptance.py:217`. Нужен для `done` программы (B1, B2, B4)
  и для `jobs_done` (B5).
- **Привязка плагинов к роботу:** `device_id` плагина — из `ctx.config` при `configure`; задать `{"device_id": "r1"}` —
  тот же id, что у `_add_v2`. Ключ задания `RobotIoPlugin` во входном item — `robot_job` (умолчание реестра плагина);
  ключ точек `RobotDrawPlugin` — `draw_points`.
- **Цикл форвардера плагина бесконечный** (`_forwarder_loop(stop_event, pause_event)`): запускать в daemon-потоке с двумя
  `threading.Event`, ждать счётчик с дедлайном, затем `stop.set()` и `join`. `_client` подменять ПОСЛЕ `start`.
  Образец: `Plugins/io/robot_draw/tests/test_robot_draw_plugin.py:33-43` (сборка плагина, подмена `_client`) и `:81-98`
  (поток форвардера); для `robot_io` — то же в `Plugins/io/robot_io/tests/test_robot_io_plugin.py:69-85, 195-221`.
- **Как читать `.program`:** хаб публикует в `ctx.state_proxy` (в `make_ctx` это `MagicMock`); путь
  `devices.state.r1.program` уходит вызовом `ctx.state_proxy.merge(path, dict)`. Публикации — в
  `ctx.state_proxy.merge.call_args_list` (или `mock_calls`): брать вызовы с `args[0] == "devices.state.r1.program"`,
  последний — текущее состояние. «`.program` не появляется» = ни одного такого вызова.
- **Поза sim:** `rig.pose_wire()` → `(x, y, z, rz)` уже в мм / градусах (регистры `TLM_*` / 10). Дом sim по умолчанию —
  `(300.0, -210.0, -40.0, -100.0)`; sim стартует в доме. История позы по тикам — `rig.core.ticks()` (поле `pose`).
- **Высоты пера** (умолчания записи робота без `params`, паритет v1): перо на листе — Z = −50.0 мм, над листом — −40.0 мм.
- **Точки зоны:** (0, 0) — вне зоны sim; квадрат (300, 0)–(320, 20) мм — внутри (проверено компиляцией на параметрах стенда).

Случаи (значения — литералы, каждый вызов с дедлайном):
- B1. Сквозной рисунок из плагина: `RobotDrawPlugin` (настоящий) с `_client`, который передаёт `request(...)` в команду
  хаба в том же процессе; плагин взведён `cmd_send`, `process([{draw_points: <квадрат 20×20 мм внутри зоны, начало pen=0>}])`,
  форвардер в потоке (см. выше) → в хаб ушла `robot_draw_polyline`; при идущем тике `.program` робота v2:
  `name == "draw"`, `state == "done"`, `done == total > 0`; счётчик плагина `jobs_sent == 1`.
- B2. Два штриха (две буквы, между ними точка `pen=0`) → программа доходит до `done`; (а) поза sim в конце — дом
  `(300.0, -210.0, -40.0, -100.0)` ±0.1 (мм; RZ — градусы); (б) перо уходит с листа между буквами: по `rig.core.ticks()`
  между первым и последним тиком с Z ≤ −49.9 есть тик с Z ≥ −40.5.
- B3. Точка вне зоны (0, 0) → ответ команды `status: error`, текст содержит «вне зоны»; `.program` не появляется;
  `jobs_dropped` плагина +1.
- B4. Пустой список точек / `pen = 2` → `status: error` с одинаковым текстом без значений; текст НЕ содержит
  «Неизвестная операция». В том же тесте валидный вызов (квадрат B1) → `status: ok`; дождаться `done` до выхода.
- B5. Подача: `RobotIoPlugin` (настоящий) с тем же мостом `_client`; задание в `robot_job`
  `{pick_x_mm, pick_y_mm, place_x_mm, place_y_mm}` внутри зоны → в хаб уходит `robot_enqueue_job`; при идущем тике через
  дедлайн `snapshot()["jobs_done"]` драйвера вырос на 1, `queue_len == 0` (sim дал DONE).
- B6. v1 не задет: на роботе v1 (фейк-транспорт conftest хаба) `robot_draw_polyline` → `status: ok` (как на `main`).

Можно читать: этот раздел; `e2e_rig_v2.py`; тесты-образцы хаба (помощники, `conftest.py`,
`test_robot_park_all_plugin_acceptance.py`); тесты плагинов `Plugins/io/robot_draw/tests/test_robot_draw_plugin.py` и
`Plugins/io/robot_io/tests/test_robot_io_plugin.py` — только как образец сборки. Запрещено: остальной `T5.5.md`, любой
другой файл `Plugins/io/robot_draw/*` и `Plugins/io/robot_io/*` (в том числе `plugin.py`), `robot_driver_v2/*`,
`spi.py`, тесты автора `test_robot_v2_draw.py`.

Ожидаемо до кода: B1, B2 красные (команда отвечает «Неизвестная операция робота: 'draw_polyline'», `.program` нет);
B3 красный (текст без «вне зоны»); B4 красный (валидный вызов не `ok`, текст — «Неизвестная операция»); B5–B6
зелёные — не дефект теста, а факт «подача уже на v2».
