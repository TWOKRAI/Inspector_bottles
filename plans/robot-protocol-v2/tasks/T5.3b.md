**Б1. Форма кода (треб. 1, 2, 4).** Только добавления в `Services/robot_comm/store.py`:

```python
import weakref  # новая строка импорта

#: Шов теста (REDS 9, часть 3): фабрика замка документа. ``_doc_lock`` читает это имя модуля
#: при каждом вызове, поэтому подмена ``Services.robot_comm.store._new_lock`` действует без правки файла.
_new_lock = threading.Lock
```

`RobotDataStore.__init__` — меняется одна строка:

```python
        self._locks: weakref.WeakValueDictionary[tuple[str, str], threading.Lock] = weakref.WeakValueDictionary()
        self._locks_guard = threading.Lock()  # без изменений
```

`_doc_lock` (`store.py:154-161`) целиком:

```python
    def _doc_lock(self, device_id: str, rel: str) -> threading.Lock:
        """Замок документа; ключ по ``casefold``: на Windows ``Prog.yaml`` и ``prog.yaml`` — один файл.

        Invariant: в ``_locks`` только документы с операцией в полёте; без операций — пусто.
        Вызывающий держит возвращённую сильную ссылку до конца операции: ``with self._doc_lock(...):``.
        """
        key = (device_id, rel.casefold())
        with self._locks_guard:
            lock = self._locks.get(key)
            if lock is None:
                lock = _new_lock()
                self._locks[key] = lock
            return lock
```

Правила:
- Поиск, создание и вставка — одна секция `_locks_guard`. `_new_lock()` вызывается только здесь и только внутри неё.
- `_new_lock` — глобальное имя модуля в момент вызова. Нельзя: `self._new_lock = ...` в `__init__`, `def _doc_lock(..., factory=_new_lock)`, `from threading import Lock as _new_lock` в теле функции, `threading.Lock()` вместо `_new_lock()`.
- Вызывающий — только `with self._doc_lock(dev, rel):` одним выражением (как `store.py:200, 215`). Нельзя: хранить замок в поле, звать `acquire()` и `release()` в разных выражениях, `weakref.ref(...)`-обёртки вокруг результата.
- Нельзя итерировать `_locks` (`for`, `items()`, `len()` в рабочем коде): итерация `WeakValueDictionary` копит отложенные удаления (`_pending_removals`). `len(store._locks)` — только в тестах.
- `delete_program` (DESIGN 1): `with self._doc_lock(dev, rel):` вокруг «байты → `current_rev` → сравнение с `base_rev` → `_remove_file`» — тот же замок и та же секция, что сравнение и замена в `_write` (`store.py:215-220`). Отказ `RevisionConflict` бросается внутри `with`: замок отпускается выходом из блока.

инъекция: `self._locks` — обычный `dict` → REDS 4 (b-I3).
инъекция: поиск и вставка вне `_locks_guard` → REDS 9, часть 3 (b-I7).
инъекция: `_doc_lock` всегда создаёт новый замок и перезаписывает запись → REDS 9, часть 1 (b-I8).
инъекция: `threading.Lock()` вместо `_new_lock()` в `_doc_lock` → REDS 9, часть 3: подмена шва не действует (b-I11).
инъекция: `delete_program` без замка → REDS 3 (b-I2).

**Б2. Почему нет двух замков на ключ и вытеснения удерживаемого замка (треб. 1).** Опора — факты CPython 3.12.12, проверены пробой (Б8, П1–П4):
- `threading.Lock` поддерживает слабые ссылки (П1).
- Замок не входит в циклы ссылок: он освобождается подсчётом ссылок в момент, когда снята последняя сильная ссылка; `gc` для этого не нужен (П2: запись ушла при `gc.disable()`). Значит, `gc.collect()` удерживаемый замок не вытесняет (П3: 3 × `gc.collect()`; внутри `with get('k'):` без локального имени — та же запись, `locked: True`).
- Колбэк умершей записи `WeakValueDictionary` удаляет ключ через `_weakref._remove_dead_weakref(d, key)` — только если по ключу всё ещё лежит мёртвая ссылка (`Lib/weakref.py`, функция `remove` в `__init__`). Новый живой замок под тем же ключом запоздалый колбэк не трогает (П4).
Вывод. Замок, который держит хотя бы одна операция, жив, поэтому `get` под `_locks_guard` его находит и второй не создаётся. Если `get` вернул `None`, ни одна операция этот ключ не держит (иначе замок был бы жив), и новый замок создаётся под тем же `_locks_guard`, под которым его ищет любой другой поток: создатель ровно один. Окно «найти — вставить» закрыто только тем, что обе операции стоят в одной секции `_locks_guard`; это и ломает b-I7. Инвариант «в `_locks` только документы с операцией в полёте» следует из П2: последняя ссылка уходит с выходом из `with`, и запись исчезает сразу.

**Б3. Рост `_locks` (треб. 3).** Проба П5 — настоящий `RobotDataStore` в `tempfile`, 5000 вызовов `read_program("r1", f"p{i}")` (файлов нет), `tracemalloc` до и после, `gc.collect()` перед замером:

Точная форма обёртки и потоков — Решение Б6.
