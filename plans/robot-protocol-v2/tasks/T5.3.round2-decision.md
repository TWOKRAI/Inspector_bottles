# T5.3a+b — анализ и решение после ревью (круг правок 2)

Дата: 2026-10-18. Ветка `feat/robot-v2-t53`, код `cc2281490..f76f7be99`.
Источники: ревью Opus `docs/reviews/2026-10-18_T5.3ab-opus-review.md` (раунды 1, 1b, 1c), вердикт CTO (Fable), ответы владельца 2026-10-18.

## 1. Что было не так

| № | проблема | замер (вход → выход) | кто воспроизвёл |
|---|---|---|---|
| П1 | у потоков робота три владельца: область плагина, свой корень драйвера `rv2-<id>`, финализатор GC | — (чтение: единственный продуктовый конструктор `manager.py:143` передаёт `spawn`, свой корень нужен только тестам) | ревью, CTO |
| П2 | гонка `start_program` и `disconnect` в автономном режиме снова открывает корень | после `disconnect()` корень `rv2-rv2 (open)`, ответ `ok` | ревью, CTO |
| П3 | финализатор прячет забытый `disconnect` от сторожа G3 | с финализатором G3 = 0, без него G3 = 2 (`rv2-rv2 (abandoned)` ×2) | ревью |
| П4 | при молчащем эхе стоп уходит повторно, каждый повтор ждёт эхо 2 с | 1 робот в jog: остановка 6,00 с, стопы в 0,0 / 2,0 / 4,0 с | ревью, CTO |
| П5 | стоп роботам идёт по очереди: молчащий робот задерживает соседа | 2 робота, молчит r1: r2 получает стоп через 2,0 с; оба молчат: 12,00 с (PM добивает через 5,0 с) | CTO |
| П6 | `robot_data.py`: `overrides` не проверяются при наличии файла; `save_params` пишет неполную карту | `P_NOPE` проходит; в файле один ключ | ревью |

Причина П4: флаг `stop_sent` ставится после эха, а не после записи (`robot_driver_v2.py:981-983`), поэтому `manager.py:106` и `disconnect` (`:475`) пишут стоп снова.
Причина П5: фаза 1 (`manager.py:95-102`) зовёт блокирующий `client.stop` по роботам в цикле.

Что стало лучше базы и остаётся: потоки в области плагина (снято исключение R1), остановка при исправной связи 2,55 с из 3,0, закрыты окна гонок запуска программы, граница `store.py` / `robot_data.py`, замки хранилища без гонок.

## 2. Решение

Общее для всего хаба устройств (роботы, камеры плана `2026-10-18_camera-device-service`, задачи настоящего робота T4.x).

| что | владелец | правило |
|---|---|---|
| потоки | область плагина `device_hub` | `spawn` обязателен для драйвера с потоками; драйвер не открывает корень и не создаёт `Thread`; `_robot_factory` без `spawn` — `RuntimeError` при создании (только `delta_v2`, драйверы v1 не трогаем) |
| защёлка стопа | драйвер, на каждого робота | помнит сильнейший **записанный** уровень и «последняя запись упала»; повтор только после неудачной записи, один раз, пока не вышел срок |
| рассылка стопа | менеджер | всем роботам **параллельно** потоками из `spawn` (`device_hub/stop-<id>-<k>`), ожидание по общему сроку |
| срок и фазы | плагин | один абсолютный срок `now + 3,0 − 0,5` с: фаза 1 запись стопа всем → потоки → `scope.close(deadline)` → фаза 4 без записи: одна проверка эха, закрытие сокетов, сохранение |
| эхо стопа | — | только диагностика: нет эха → `last_error` и health «стоп не подтверждён роботом»; остановку процесса не держит |
| робот при мёртвой связи | сторож робота `P_WDG_TIMEOUT_MS` | хаб не принимает конфиг `delta_v2` со сторожем 0 (решение владельца; правило — в бриф T5.3c) |
| стоп оператора `robot_stop` | — | идёт всегда, защёлка его не касается |

Клиент `robot_comm` — правка вперёд: `issue_stop(level) -> value` (только запись) и `await_stop_echo(value, level, *, deadline)`; `stop()` = оба, без изменений для операций оператора.

Гарантия (формулировка для ADR и брифа): **ПК пишет стоп каждому досягаемому роботу до срока; недосягаемого останавливает его сторож (если он не 0); остановка роботов и закрытие области укладываются в срок.** `remove_worker` фреймворка (до 5,0 с на поток) в срок не входит — сказано явно.

### Почему так

- Один владелец потоков — решение владельца 2026-10-03 (`project_universal_lifecycle_decision.md`) и принцип «меньше слоёв». Автономный режим родился в этой ветке (48215a023) и в main не был, поэтому FREEZE его не защищает; запустить драйвер отдельно по-прежнему можно: открыть область и передать её `spawn`. Гонка П2 уходит вместе с режимом, а не закрывается сторожем. Финализатор уходит: страж — детектор, не уборщик.
- Повтор после **успешной** записи — баг: ответ Modbus FC6 значит «регистр принят», второй раз не доставляет «сильнее», а съедает срок. Повтор после **упавшей** записи полезен — его оставляем.
- Параллельная рассылка — принцип «сбой одного не валит соседей»: молчащий r1 не задерживает стоп r2. На полуоткрытой связи каждая запись блокируется до `timeout_sec` = 1,0 с, по очереди это N секунд.
- Эхо не держит остановку: выход исполнителя программы уже значит, что робот принял стоп; ждать эхо от мёртвого робота бессмысленно, его останавливает сторож.

### Чем решение отличается от исходных позиций

- Ревьюер предлагал закрыть П2 двумя строками и вынести обязательный `spawn` в ADR после T5.3c/d. CTO: сторож чинит путь, которого не должно быть; ревьюер в раунде 1c согласился.
- Лид предлагал «никогда не повторять стоп». CTO мягче: повтор после упавшей записи остаётся.

## 4. Объём круга 2

1. Потоки: удалить `_spawn_own`, `_own_scope`, `_own_finalizer`, `_close_own_scope`, ветку в `disconnect`; `spawn` keyword-only без умолчания для `delta_v2`; фикстура `driver_scope`; REDS 5 по новому тексту.
2. Стоп: `issue_stop` / `await_stop_echo`; защёлка в драйвере; параллельная рассылка в менеджере; один срок от плагина. Замечания ревьюера: `_jog_tx_lock` брать с таймаутом остатка срока, не взял — писать стоп без замка (В1); второй `request_stop_all` после `scope.close` не должен падать на `ScopeClosedError` (В3); имя потока с номером.
3. Прочее: `try/finally: scope.close` в `plugin.shutdown` и лог вместо `pass` (`plugin.py:264-284`); докстрока `_JogRun`; `overrides` проверять всегда; полная карта в `save_params`; `except` сузить до `(ValidationError, ValueError, TypeError)`; тесты плагина перенести в `Plugins/hub/device_hub/tests`.
4. ADR-DH-009 в `Services/device_hub/DECISIONS.md` + `python -m scripts.sync`; бриф T5.3a (REDS 5, таблица К1, «Риски»); страница «как было и как стало» с замеренными числами (18 правок из раунда 1b).

Точки врезок журнала T5.6 (полоса Р) не меняются: конец `__init__` и `self._transport`, строка после `build_transport` в `connect()`, литерал `_OPS`, таблица `commands` плагина.

Новые тесты-сторожа (каждый красный под своей инъекцией): 1 робот молчит → ровно 1 запись стопа, ≤ 3,0 с; 2 робота, r1 молчит → запись r2 ≤ 0,1 с после r1; запись упала → ровно 1 повтор; нет эха → `last_error`; `robot_stop` оператора после защёлки пишет; запуск программы против фазы 1 → без выживших и корней; сторож 0 → отказ конфига.

- Новый дизайн не реализован; его числа на двух роботах не замерены.
- Полуоткрытая связь не воспроизведена (нужен настоящий Delta, T4.0); её границы выведены из `timeout_sec`, не замерены.
