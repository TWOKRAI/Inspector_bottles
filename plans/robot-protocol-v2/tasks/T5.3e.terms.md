# T5.3e — термины стопа: IEC 60204-1 и PackML (лид, 2026-10-27)

По просьбе владельца (через координатора) спека говорит языком стандартов. Привязка — по поведению кода, не по
названию уровня (`Services/robot_comm/server/sim_core_v2.py:12-13, :778`, `protocol_v2.py` `STOP_LEVEL`).

**Источники (сверил координатор 2026-10-27):** IEC 60204-1 Ed. 6.0 2016 + AMD1:2021 (консолидированная 6.1) — https://webstore.iec.ch/publication/71256; **определения категорий 0/1/2 — по вторичному источнику (machinerysafety101.com), текст IEC не открывали.** PackML — OPC 30050 v1.01 (2020), https://reference.opcfoundation.org/PackML/docs/. Остальное (web-researcher 2026-10-27; страницы iso.org / isa.org дали 403 — **по вторичным источникам, не первоисточник**): ISO 13849-1:2023 (ed. 4); IEC 62061:2021 + поправки (страница webstore.iec.ch/en/publication/112847 противоречит сама себе: AMD1:2024 + AMD2:2026 против «AMD1:2026»); ISO 13850:2015; ISO 10218-1:2025 (ed. 3); PackML State Model 2015 (OPC 30050 §6.3.5), ISA-TR88.00.02-2022. Текст п. 9.2.2 IEC 60204-1 и требования ISO 10218-1 к protective / emergency stop первоисточником не подтверждены.

| наше | что делает | IEC 60204-1 Ed. 6.1 (п. 9.2.2) |
|---|---|---|
| SOFT | ход доезжает до цели, затем стоп; питание приводов есть | кат. 2 — управляемая остановка, питание остаётся |
| HARD = «Остановить принудительно» (В-3) | активная команда обрывается сразу; серво ON | кат. 2 (быстрая) — питание остаётся; **не кат. 0** |
| HALT | обрыв + серво OFF + стоп ПЧ | ближе всего к кат. 0, но программно — не гарантия |
| park = «Остановить» | конец текущего хода/задания → домой → серво OFF | кат. 1 по результату — управляемая остановка, затем снятие питания |

- **Программный стоп — НЕ аварийный.** Аварийная остановка (e-stop) — аппаратная функция безопасности (ISO 13850,
  ISO 13849-1 / IEC 62061; издания не сверены), её не заменяют ни HALT, ни park, ни стоп `process.stop`. В текстах GUI и
  README слово «аварийный» для этих команд не используется; «аварийный стоп выключения» в этой спеке = стоп `process.stop`
  (CTO D3), т.е. программный стоп процесса, не e-stop.
- **Кат. 0 в программе нет.** Снятие питания приводов «немедленно» — аппаратное (STO / контактор); HALT ближе всего, но
  без функции безопасности. Если владельцу нужна кат. 0 для «Остановить принудительно» — это HALT вместо HARD (В-3) и
  отдельный вопрос; сейчас решение В-3 = HARD (серво ON, рука держит позицию).
- **PackML (OPC 30050 v1.01) — соответствие состояний, не реализация:** `devices.state.<id>.park.state`
  `parking` ≈ Stopping, `done` ≈ Stopped; `failed` (дом не достигнут, В-2) ≈ Aborted — в PackML выход из Aborted только Clear → Clearing → Stopped (вторичный источник), у нас — явное действие оператора; «серво ON»
  после park (В-4) ≈ Reset → Idle. «Остановить принудительно» ≈ команда Abort → Aborting → Aborted.
