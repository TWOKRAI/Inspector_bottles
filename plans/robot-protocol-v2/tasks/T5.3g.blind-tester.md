Отдельный файл, чтобы тестер не открывал DESIGN и инъекции из `tasks/T5.3g.md` (этот файл — единственный вход тестера кроме перечисленных ниже путей кода). Автор: teamlead, 2026-10-21, HEAD `d31bfbf63`.

## Приёмка (задана лидом, дословно)

A1. Простой робот, транспорт уже подключён, request_stop в любой точке connect (точка W1, точка W4, внутри probe/sync — WW): ровно 1 STOP_REQ уровня SOFT за выключение; connect() → False; после него is_connected False; is_shutdown True. Ни в каком порядке драйвер не «готов» после выключения.
A2. W4: после connect stopping True; jog_hold и запуск программы → TEXT_STOPPING; флаг stop_unconfirmed (запись без эха) переживает connect, флаг и текст согласованы.
A3. request_stop до подключения транспорта (connect ещё строит или подключает транспорт): записи нет, «стоп не подтверждён» не ставится (правило 2026-10-19: неподключённый простой — без SOFT); connect() → False.
A4. Регресс: request_stop после завершённого connect → 1 SOFT (как сейчас); обычный disconnect → connect без выключения по-прежнему снимает stopping/уровень/защёлку («ручное Подключить»).
A5. Задание/программа/jog посреди connect — пути и уровни как сейчас (HARD для задания и программы), без новых записей.
A6. Правка только через переходы RobotState (state.py); новых замков нет; порядок _param_lock → замок состояния сохранён; 7 красных пробы зелёные; Services/device_hub/tests и Services/robot_comm/tests зелёные.

Уточнения границ (предложение teamlead, поведение снаружи):
- «Транспорт подключён» для A1/A3: сам `connect` уже подключил (или застал подключённым у готового робота) транспорт. Стоп, пришедший, пока `connect` ещё подключает транспорт (внутри `transport.connect()`), — случай A3.
- `request_stop`, пришедший после того, как `connect()` уже вернул True, — случай A4.
- `request_stop` у готового робота ДО вызова `connect()` — не A1: 1 SOFT, `connect()` → False, `is_connected` остаётся True до `disconnect` (как в A4).
- A2 «флаг и текст согласованы»: пока `stop_unconfirmed` True, `stop_unconfirmed_text` — причина этой пометки.

Что дать тестеру:

- публичный API драйвера: `connect()`, `disconnect()`, `request_stop(deadline)`, `is_connected`,
  `stop_unconfirmed`, `stop_unconfirmed_text`, `state.view().stopping`, `state.is_shutdown()`,
  `call("jog_hold", {"dir": 1, "spd": 20})`, `call("enqueue_job", …)`;
- запуск программы — `drv.start_program(program, points, name=...)` (`programs.py:36`), программа из
  `Services.robot_comm.programs` (`Move`, `Point`, `Program`), пример — `test_robot_driver_v2.py:298-340`.
  Не `call("program_run", …)`: у `_fake_driver` нет хранилища, и ответ будет `TEXT_NO_STORE` раньше проверки
  останова (`programs.py:130-132`);
- срок `request_stop`: бюджет записи `_fake_driver` — 2 с (`timeout_sec 1.0 × (retries 1 + 1)`, `stop.py:99-102`).
  Срок меньше бюджета даёт `TEXT_NO_ECHO_WINDOW` вместо `TEXT_STOP_UNCONFIRMED`. Либо срок `> 2,5 с`, либо свой
  `DeviceEntry` с `transport={..., "timeout_sec": 0.05, "retries": 0}` и срок 0,5 с;
- обвязку с фейками: `Services/device_hub/tests/test_robot_driver_v2.py:464-582` (`_FakeTransport`, `_FakeClient`,
  `_fake_driver`, `_blocking_wait`); тексты — `Services/device_hub/drivers/robot_driver_v2/texts.py`
  (`TEXT_STOPPING`, `TEXT_STOP_UNCONFIRMED`, `_NOT_CONNECTED`).

Точки, доступные без DESIGN: пауза Event-ом внутри фейкового `client.probe`, `client.sync_params`,
`transport.connect` (сначала `is_connected = True`, как настоящий транспорт перед возвратом, затем пауза),
`transport.read_registers` (чтение TLM в действиях при подключении), с проверкой, что
вызов идёт из потока `connect`. Каждый блокирующий вызов — в daemon-потоке с дедлайном `join`. Проверка
отсутствия (0 записей) — только вместе с проверкой достижимости окна. Ожидаемые значения — литералы.

Поведение снаружи (имена тестов обязательны, на них ссылаются инъекции):
- `test_a1_stop_inside_probe_one_soft` / `test_a1_stop_inside_sync_one_soft` /
  `test_a1_stop_inside_on_connect_read_one_soft`. Простой робот с подключённым транспортом, `request_stop` внутри
  точки. Ровно 1 запись стопа уровня 1 (SOFT), `connect()` → False, после него `is_connected` False,
  `is_shutdown()` True.
- `test_a1_stop_before_connect_on_ready_robot`. Робот готов, `request_stop`, затем `connect()`: 1 SOFT,
  `connect()` → False. `is_connected` не проверять (остаётся True, см. уточнение).
- `test_a2_ready_robot_stop_inside_probe_keeps_stopping`. Робот готов, эхо стопа не приходит, `request_stop`
  внутри `probe` повторного `connect`. `connect()` → False, после него `is_connected` False, `view().stopping` True, `jog_hold` и `start_program` отвечают
  `TEXT_STOPPING`, `stop_unconfirmed` True, `stop_unconfirmed_text == TEXT_STOP_UNCONFIRMED`.
- `test_a3_stop_inside_transport_connect_no_write`. Транспорт не подключён, `request_stop` внутри
  `transport.connect()`: 0 записей стопа, `stop_unconfirmed` False, `connect()` → False.
- `test_a4_stop_after_connect_one_soft`. `connect()` → True, затем `request_stop`: 1 SOFT.
- `test_a4_disconnect_then_connect_clears_stopping`. `connect`, `disconnect` (без `request_stop`), `connect` →
  True. `view().stopping` False, `jog_hold` не отвечает `TEXT_STOPPING`.
- `test_a5_connect_during_job_no_new_writes`. Задание в полёте (`_blocking_wait`), `connect()` → True без `probe`.
  Затем `request_stop`: ровно 1 запись уровня 2 (HARD), SOFT нет.
