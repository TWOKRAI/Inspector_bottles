## Приёмка (слепой тестер; только публичное поведение)

Обвязка — как в пробе: настоящий `DeviceHubPlugin` (`make_ctx`), драйвер v2 на фейках (фабрика менеджера).
Счётчики — на фейке: STOP_REQ по уровням, SERVO, DO, `probe`, JOG_CONT. Статусы — канал `ctx.state_proxy.set` с
путём `devices.state.<id>.conn` (плагин и `publish_cb` менеджера), повторы подряд схлопнуты. Паузы — только в
потоке супервизора или тика; блокирующие вызовы — daemon-поток с join-дедлайном.
- A1. Команда посреди `connect` — `{"status": "ok", ...}` за 1,0 с, пока `connect` стоит.
- A2. После подъёма связи (`probe`; `sync_params`; перед SERVO; перед DO): после команды SERVO 0, DO 0;
  `connect()` False; SOFT ровно 1; в конце транспорт закрыт.
- A3. До подъёма связи (внутри `transport.connect()`): `probe` 0, SERVO 0, STOP_REQ 0, `connect()` False.
- A4. Долгая синхронизация 2,0 с и ожидание TLM после неподтверждённого SERVO: от команды до входа в `disconnect`
  драйвера < 0,5 с; SOFT 1.
- A5. Робот до этого не был подключён (воркера тика нет). Статусы прерванного `connect`: ровно `connecting`,
  `disconnecting`, `disconnected` (нет `connected`, нет `error`). Парная: `connect` без команды — `connecting`,
  `connected`. `desired_connected` False до конца очереди.
- A6. «Подключить» → команда → «Подключить»: `connect()` `[False, True]`; SERVO только после `disconnect`; SOFT 1;
  в конце подключён, `desired_connected` True.
- A7. Тик переподключает (связь упала), команда в `probe` тика: SERVO 0, тик не подключил, SOFT 1, закрыт.
- A8. Первый `connect` после старта, команда до того, как супервизор взял `connect` (драйвер ещё не создан):
  `probe` 0, SERVO 0, STOP_REQ 0.
- A9. Ручной `connect` ждёт замок за переподключающимся тиком, затем команда: после команды `probe` 0, SERVO 0;
  SOFT 1.
- A10. Робот подключён, команда, очередь ещё не разобрана: `jog_hold` → `{"status": "error", "message":
  "идёт отключение робота"}`, JOG_CONT 0; `jog_step` → тот же текст, кадров jog 0. Парная: без команды
  `jog_hold` → JOG_CONT 1.
- A11. То же окно: `enqueue_job` → `status` error, `message` «идёт отключение робота». Парная: без команды —
  `{"status": "ok", "queue_len": 1}`.
- A13. В6: робот подключён, в очереди 1 задание и 1 возврат; команда, очередь супервизора разобрана: задание и
  возврат роботу не отправлены; статус `last_error` и журнал (WARNING) содержат «при отключении сняты задания: 1,
  возвраты: 1»; после «Подключить» новое задание даёт `queue_len` 1. Парная: без команды задание тиком исполняется
  (фейк видит одно задание).
- A14. В5: то же окно: запуск программы → error «идёт отключение робота», программа до робота не дошла;
  `return_job` → error, тот же текст. Парная: без команды программа запускается, `return_job` → `{"status": "ok",
  "return_queue_len": 1}`.
- A15. Окно супервизора после `connect` против команды (правка лида 2026-10-25: публикация статуса идёт ПОСЛЕ
  замка, ввода-вывода под замком нет): супервизор завершил `connect` и стоит перед публикацией статуса `connected`;
  команда в этот момент возвращается `{"status": "ok", ...}` за 1,0 с (публикацию не ждёт); сразу после возврата
  команды `desired_connected` False; супервизор отпущен — опубликовал свой `connected` и разобрал очередь:
  `desired_connected` по-прежнему False, последний статус — `disconnected`, SOFT 1.
- A12. Регресс: команда на подключённом простом роботе — SOFT 1, `disconnect` за 1,0 с; затем «Подключить» →
  `connect()` True, `jog_hold` снова доходит.

Критерий стенда (симулятор, задержка 300 мс, живая связь; мёртвая связь исключена — там обмен в полёте до 2,0 с и
бюджет SOFT 2,0 с, `stop.py:106-109`): «Отключить» посреди ручного `connect` (в `probe`, в `sync_params`, до SERVO)
→ в журнале обмена после команды нет SERVO и DO_SET, кроме О1; STOP_REQ SOFT ровно 1, если связь поднята (0 — до
`connect ok` транспорта); статусы — `connecting`, `disconnecting`, `disconnected` (робот до этого не был подключён,
воркера тика нет; иначе — О12); от команды до `disconnected` —
не больше 5,0 с (сейчас 90–114 с). Ожидаемо ≤ 2 с: обмен в полёте ≈ 0,3 с + интервал супервизора + SOFT ≈ 0,3 с.
