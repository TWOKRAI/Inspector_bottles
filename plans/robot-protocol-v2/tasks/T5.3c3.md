DESIGN (решено):
  1. Текст health без окна эха (условие CTO; решение лида 2026-10-19). Окно: `_check_stop_echo` (`robot_driver_v2.py:687-717`) читает эхо, пока `time.monotonic() < deadline - _write_budget_s()` (`:703-705`; `_write_budget_s = timeout_sec * (retries + 1)`, `:644-647`, умолчания 1,0 и 1); срок плагина 2,5 с (`plugin.py:50-51, 274`) → окно ≈ 0,5 с, а при `timeout_sec >= 1,25` и `retries 1` его нет, и каждый остановленный робот получает ложное «стоп не подтверждён роботом» (`:713-717`; плагин — `:54, 302-313`). Три исхода: (1) запись прошла, окно есть, эхо не пришло или чтение упало — «стоп не подтверждён роботом»; (2) запись прошла (`value is not None`), окна нет (`time.monotonic() >= read_until` до первого чтения) — **«эхо не читалось (нет окна)»** (`TEXT_NO_ECHO_WINDOW`, константа драйвера рядом с `TEXT_STOP_UNCONFIRMED`, `:128`); (3) запись не прошла (`value is None`, попытка была) — «стоп не подтверждён роботом». Текст уходит в `last_error` (`_publish_error`, `:717`), в строку лога (`:716` пишет выбранный текст) и в health. Для health — свойство драйвера `stop_unconfirmed_text -> str | None` рядом со `stop_unconfirmed` (`:589-593`; bool не менять — на нём тесты T5.3a+b); поле `_stop_unconfirmed_text` ставится в том же блоке `with self._flags_lock`, что `_stop_unconfirmed = True` (`:713-714`): иначе плагин между двумя чтениями увидит `True` без текста. `_report_unconfirmed_stops` берёт `RuntimeError(getattr(driver, "stop_unconfirmed_text", None) or TEXT_STOP_UNCONFIRMED)`, `context="device_hub.stop_echo"` и `device_id` прежние; литерала нового текста в плагине нет.
     **Время жизни поля (решение лида 2026-10-19; стадия 0 р.3 п. 1).** `_stop_unconfirmed` и новое поле ставит ТОЛЬКО `_check_stop_echo`, а он зовётся ТОЛЬКО из `request_stop` (`:584`), который сначала ставит `_shutdown = True` (`:571`); `_shutdown` не снимается нигде (`:325`), `connect()` для такого драйвера выходит на `:445-446` раньше сброса `:453`. Значит сброс на `:453` для этого пути недостижим (по чтению; ни `_stop_unconfirmed`, ни новое поле не обнуляются никогда), драйвер после `request_stop` одноразовый. **Новый сброс НЕ пишется**, строка `:453` не правится (мёртвый сброс `_stop_unconfirmed` — не наш дефект, в отчёт строкой). Единственная правка вне функций — объявление поля в `__init__`.
  2. Отдельный `disconnect()` простого робота — только запись, без ожидания эха. Ветка простого подключённого робота в `_request_stop` (`robot_driver_v2.py:765-787`) после записи SOFT ждёт эхо до `soft_echo_timeout_s` = 2,0 с (`:779-782`) на потоке supervisor (`plugin.py:384-393`); замер ревью раунда 2d — 2,016 с при молчащем эхе, а на р.3 стадии 0 — 1,997 с, 1 запись, `last_error` не появляется (probe2). Правка: убрать `await_stop_echo` из этой ветки (`:779-787`), оставить `_write_stop(SOFT)` с защёлкой (`:765-777`); отказ записи — как сейчас (`_record_err` + лог); эхо простого не читается, `last_error` не публикуется. Правило владельца сохраняется: подключённый простой робот при выключении получает ровно одну запись SOFT, не подключённый — ни одной, вторую гасит защёлка (поколение открывает первый запрос выключения, `:525-530`). Ветки jog / программа / задание отдельного `disconnect()` остаются с эхом (`:745-764`).
