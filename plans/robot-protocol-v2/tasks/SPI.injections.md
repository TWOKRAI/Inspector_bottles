# SPI хаба — свойства для инъекций и стенд, ред. 2

Бриф — `tasks/SPI.md`; номера А* — `tasks/SPI.acceptance.md`. Tester этот файл не читает. Каждое свойство откатывается
отдельно; прогнозы пишет лид.

## Свойства

1. Набор имён команд = 72 (А1, А2).
2. Маршрут `needs_link=False` → `driver.call` без проверки связи (А6).
3. Маршрут данных → `manager.robot_data` без драйвера (А7).
4. Проверка вида в сгенерированной команде (А5).
5. Отказ без `device_id` при синхронном вызове (А4).
6. Каждая команда зовёт свою операцию с аргументами без `device_id` (А19).
7. `OP_SPECS == _OPS` у каждого драйвера (сторож автора `test_spi_contract.py`).
8. Одно имя из двух источников при неравных `OpSpec` → `ValueError` (А10 б, в).
9. `executor` + `immediate` → `ValueError` (А10 г).
10. Множество `immediate` (А12).
11. Описания в каталоге (А3).
12. `disconnect_pending is True`, не истинность (А14).
13. `request_disconnect` под `_workers_lock` до постановки в очередь (А14, `test_c29_*`).
14. `request_disconnect` в `try`, постановка `disconnect` всегда (А25).
15. Чтения `stop_unconfirmed*` и отбор `stop_aware` внутри `try` на драйвер (А24).
16. Поток стопа только у `stop_aware` (А15); `stop_aware == hasattr(cls, "request_stop")` (А16).
17. Нет `driver._client` в прод-коде хаба (сторож, часть (в)); нет `getattr`/`hasattr` по драйверу (AST,
    `test_spi_contract.py`, получатель — потоком данных; инъекция: `getattr(d, "last_io", None)` с переименованной
    переменной `d` — красный).
18. `RegisterTransportUnavailable` → постоянный текст (А13).
19. `install_op_commands` — copy-on-write, родитель не мутирует (А9).
20. Описание и `executor` кладутся при регистрации, `start()` их не заменяет (А18, А17).
21. Каскад моста: публикация только при `set_degraded() -> True`; умолчание не зовёт `disconnect()` (А20).
22. Умолчания базы — атрибуты класса (А21).
23. Запасной путь хука без исполнителя (А23); белый список опций (А26); «имя занято» без повтора (А27).
24. Пустые `command_options` → вызов `register_command(имя, метод)` как до правки (А26).
25. Полнота оракула защёлки: AST-множество сбросов == литерал 7, строки покрывают публичные методы (SPI.a).
26. `connect_begin("go")` сбрасывает защёлку (строка `connect_begin_go`).
27. Счётчики `_safe_call` под замком (тест автора, детерминированный: регистр-заглушка, чей сеттер уступает поток между
    чтением и записью, или проверка `_counters_lock.locked()` в момент записи; откат замка — красный без повторов).
28. Каскад моста: `try` на зависимого, отказ одного не лишает деградации второго (А20).
29. Отчёт `request_disconnect` в health — вне `_workers_lock` (тест автора: заглушка health проверяет, что замок свободен;
    А25).
30. Хук: при отказе исполнителя второго WARNING нет (А23).

## Стенд

v2, сценарии S0–S3 стенда C-29 (`tasks/C-29.stand.md`): «Отключить» в четырёх фазах подключения. Не хуже C-29: SERVO+DO
после команды 0; SOFT ровно 1 при поднятой связи (0 до связи); до `disconnected` ≤ 1,23 с на каждом сценарии (C-29:
0,75–1,23 с; порог 5,0 с). Плюс: `robot_point_list` (по IPC, через исполнитель после d2), `robot_stop` (подключён) и
`vfd_get_status` — ответы той же формы, что на main; `robot_point_list` без `device_id` → `key_missing`.
Урок C-29: `count.py` считает обмен S0 только до начала S1 (граница — первая строка S1 в `sim.log`). Стенд — в окне
координатора: после SPI.c1, после SPI.d3 и после SPI.g (затвор переподключения).
