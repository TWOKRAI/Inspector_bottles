DESIGN (decided by the lead — you type it, you do not derive it):
  1. Публичный API (модуля ещё нет — тесты красные на импорте, это ожидаемо). `from Services.robot_comm.core.client_v2 import RobotClientV2, ClientV2Config, CmdResult, StopResult`; ошибки — `from Services.robot_comm.errors import WrongFirmware, RobotNak, RobotCommandError, RobotAborted, RobotTimeout, RobotNotConnectedError`.
     - `RobotClientV2(transport, config, *, rng=None)`; `transport` — подключённый `ModbusDevice` (вызывающий зовёт `connect()` до `probe()`); `config = ClientV2Config.from_dict({...})` (поля: `poll_interval_s`, `longest_gap_s`, `res_timeout_s`, `done_timeout_s`, `stop_echo_timeout_s`, `soft_echo_timeout_s`; `res_timeout_s` и `soft_echo_timeout_s` не меньше `longest_gap_s`).
     - `probe()` — только чтения; не та прошивка → `WrongFirmware`.
     - `cmd(op: str, args: list[int]) -> CmdResult(seq, rvals)`; `op` — имя из `protocol_v2.OP`; NAK → `RobotNak` с полями `errno`, `reason`, `text`, `index`, `rvals`.
     - `wait_done(seq)` — для seq последнего `CmdResult` опкода с итогом DONE (`PTP_MOVE`, `HOME`, `JOG_STEP`, `JOG_CONT`, `CVT_JOB`, `SC_RUN`); успех → возврат; ошибка команды → `RobotCommandError` (стоп → подкласс `RobotAborted`).
     - `stop(level)` — `level` 1 SOFT / 2 HARD / 3 HALT; возврат `StopResult.ACKED` или `StopResult.SUPERSEDED`.
     - `sync_params(values: dict[str, int], epoch: int) -> SyncReport(sent, applied, epoch)`; `values` — сырые значения ВСЕХ имён `params_v2.PARAM_ID`, кроме `P_CONFIG_EPOCH`; `epoch ≥ 1`.
  2. Стенд: настоящий `SimRobotServer(core=RobotSimCoreV2(), port=<свободный>, on_write=<журнал>)` (`Services/robot_comm/server/sim_robot.py:207`) и настоящий `ModbusDevice` с `ModbusConfig(host="127.0.0.1", port=<свободный>, unit_id=ROBOT_UNIT_ID)`. Свободный порт — копия `_free_port()` из `Services/robot_comm/tests/test_sim_e2e.py:21` (копировать, не импортировать); порты `{5021, 8765, 8766, 8091, 8092}` запрещены — ассертом в хелпере.
  3. «Ноль записей» = в журнале `on_write` нет вызовов с `fc ∈ {6, 16}` (`on_write` зовётся и на чтения с `values=None`, `sim_robot.py:175-177`).
  4. «Пустое пространство»: `SimRobotServer(core=RobotSimCore())` с ядром v1 (по 0x1040 ноль) — либо `core.regs[REG["TLM_PROTO_VER"]] = 0` до старта сервера. Возьмите оба варианта (параметризация).
  5. Длинная команда: из дома (300.0, −210.0, −40.0, −100.0) `PTP_MOVE` LINE в (300.0, −150.0, −40.0, −100.0), `spd_pct = 1` — около 4 с (расчёт, не замер; аргументы — s16 ×0.1 по `protocol-spec.md` §5).
  6. Каждый блокирующий вызов — в daemon-потоке с дедлайном join. Ожидаемые значения — литералы из `protocol-spec.md` / `params.md`, не из кода под тестом. Каждый тест в докстринге называет, что он НЕ доказывает.

ACCEPTANCE (tester) — ровно эти шесть, по одному или нескольким тестам на строку:
  1. probe на пустом пространстве → `WrongFirmware` без единой записи (п.3, п.4).
  2. ACK: `cmd("PING", [])` → `CmdResult`; значение возврата — литерал из `protocol-spec.md` §5.
  3. NAK с текстом: `PTP_MOVE` к дому с `spd_pct = 101` → `RobotNak`, `errno` — литерал `E_RANGE` из §6, `text` — непустая строка без `None`.
  4. `wait_done` успех (короткий `PTP_MOVE` → возврат) и ошибка (длинный ход + `stop(2)` из другого потока → `RobotAborted`).
  5. синхронизация: совпала метка (после первой синхронизации тот же `epoch`) → ни одной записи (п.3); разошлась (новый `epoch`) → отправлены все параметры, и ПОСЛЕДНЯЯ запись mailbox — `PARAM_SET` с id `P_CONFIG_EPOCH` и новым значением (по журналу `on_write`).
  6. стоп проходит, пока mailbox занят длинной командой: поток A в `wait_done` хода из п.5; поток B `stop(2)` возвращается не позже 0.5 с с `StopResult.ACKED`; A получает `RobotAborted`.
