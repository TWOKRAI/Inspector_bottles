# T5.3e.1 — приёмка `robot_park` (А1–А18): форма `.park`, стенд модульных тестов, литералы

Файл для слепого тестера T5.3e.3 ([`T5.3e.3.md`](T5.3e.3.md)) и автора T5.3e.1. DESIGN — в
[`T5.3e.1.md`](T5.3e.1.md), тестеру его читать нельзя. Ред. 4 (2026-10-27, закрытие стадии 0 р.1).

## Goal

`robot_park {device_id}` → ответ `{"status": "ok", "accepted": True, "seq": k, "timeout_s": t}` сразу → драйвер в
своём тике доводит робота: конец текущей команды или цикла, домой, серво OFF → `devices.state.<id>.park` получает
итог. Отказы — во время park и после него, до «серво ON».

## Форма значения `.park`

`{"seq": int, "state": "parking"|"done"|"failed", "step": "activity"|"idle"|"home"|"servo", "home":
"moved"|"already"|None, "servo": False|None, "dropped": {"jobs": int, "returns": int}|None, "reason": str|None,
"elapsed_s": float|None}`. Путь появляется с первым принятым park. Терминальные — `done` и `failed`; после терминала
значений с тем же `seq` больше нет. `parking` пишется при смене `step`, не каждый тик. «Итог» — последнее значение с
`seq` ответа.

## Стенд модульных тестов

- Драйвер — `RobotDriverV2(entry, clock=fake_clock.clock, sleep=fake_clock.sleep, publish=rec, spawn=...)` над
  настоящим `E2eRig` (`Services/robot_comm/tests/e2e_rig_v2.py`); образец сборки — `_driver`, `driver_scope`
  (`test_robot_driver_v2.py`).
- `FakeClock` — `Services/device_hub/tests/conftest.py:47-62` (фикстура `fake_clock`).
- Рекордер публикаций — свой, в файле теста (образец `_Rec`, `test_robot_driver_v2.py:63-68`; `Rec`,
  `test_robot_v2_ops_acceptance.py:157-200`). У `E2eRig` рекордера нет — это не повод останавливаться.
- Тик — `drv.tick()` вручную, период не нужен. Ход сима и поток поводка идут реальным временем: ждать их через
  `bounded(...)` (`e2e_rig_v2.py`). Окно удержания jog (0,2 с) считается по часам драйвера: двигать его
  `fake_clock.t += ...`, не `sleep`.
- **Что чем наблюдать** (Opus r2-M1):
  - записи `STOP_REQ` — журнал обмена драйвера: `drv.call("exchange_log_get", {"since_seq": k, "limit": 2000})`,
    строки `W STOP_REQ = <n>` (повтор склеен полем `n`), уровень — `n & 3` (1 SOFT, 2 HARD); образец `_StopWatcher`
    (`test_robot_v2_ops_acceptance.py:112-153`);
  - серво сима — `rig.read("TLM_SERVO")` (1 ON, 0 OFF);
  - команды сима (`op=PARAM_SET`, `op=JOG_CONT`) — `rig.core.events()` (образец `Hub.count`,
    `test_robot_v2_ops_acceptance.py:170-176`); `rig.restart()` заменяет `rig.core` (`e2e_rig_v2.py:474`) — брать заново;
  - строки лога «jog остановлен поводком» — `caplog` с логгера `mpf.Services.device_hub.drivers.base` (образец
    `test_robot_v2_lease_log.py:8`).
  - `RecordingCore` записей `STOP_REQ`, значений `SERVO` и чтений `PROBE` не содержит — по нему их не считать.
- **Команды** `robot_<op>` в модульных тестах — `drv.call("<op>", args)` (образец `_call`, `test_robot_driver_v2.py`);
  А13 — через `DeviceManager`.
- **Подготовка сцен** (Sonnet r2 m-4):
  - программа пользователя ≥ 3 ходов — публичный `drv.start_program(program, points, name=...)`;
  - А5 `robot_program_run` — драйвер с `store=` и сохранённой программой (иначе ответ — «хранилище…» / «программа не
    найдена», не текст park); образец хранилища — `test_robot_driver_v2.py`;
  - задание в полёте (А9, А12) держит поток тика в `wait_done`: `tick()` гнать в своём потоке, ждать через `bounded`.
- Robot id — любой; на стенде — `robot_main`.

## Литералы А1–А18

- **А1. Робот вне дома, простой.**
  - Ответ ровно `{"status": "ok", "accepted": True, "seq": 1, "timeout_s": 30.0}`.
  - После 1-го `tick()`: последнее значение `.park` — `{"seq": 1, "state": "parking", "step": "home", ...}`;
    `bounded` до `.program.name == "park_home"`.
  - `bounded` до `.program.state == "done"`, затем 1-й `tick()` → итог `done`, `home == "moved"`, `servo is False`.
  - Рекордер на публикации `.program` `done` для `park_home` читает `rig.read("TLM_SERVO") == [1]`; после итога —
    `[0]`.
  - Строк `W STOP_REQ` в журнале обмена за park — 0.
- **А2. Робот дома.** А1 до `done`, затем `robot_servo {on: true}`, второй `robot_park`: итог `done`, `home ==
  "already"` после 1-го `tick()`, `.program` не менялся.
- **А3. Jog держится.** Держатель шлёт `jog_hold` каждые 0,1 с (реальное время), после ответа park — ещё ≥ 3 посылки.
  - Ответ park ≤ 1,0 с.
  - Ровно 1 строка `W STOP_REQ = n` с `n & 3 == 1` в журнале обмена до 1-го `tick()`.
  - После ответа `fake_clock.t += 0.3`, ждать реально 0,5 с: строк «jog остановлен поводком» — 0.
  - Все `jog_hold` после ответа: `status == "error"`, `message` — «идёт основная остановка робота» или «робот
    остановлен: включите серво».
- **А4. Программа пользователя (≥ 3 хода) идёт.** В рекордере `.program` `{name: <пользователя>, state: "aborted"}`
  раньше `{name: "park_home", state: "running"}`; итог `done`, `home == "moved"`.
- **А5. После `done`:** `robot_program_run`, `robot_jog_step`, `robot_enqueue_job`, `robot_jog_hold` → `message ==
  "робот остановлен: включите серво"`; `robot_servo {on: true}` → `ok`, затем `robot_jog_step` → `ok`.
- **А6. `request_stop()` во время хода домой** (свой поток, `deadline = monotonic() + 2.5`).
  - К возврату: итог `failed`, `step == "home"`, `reason == "драйвер робота останавливается"`.
  - Рекордер на публикации `failed` читает журнал обмена: строк `W STOP_REQ = n` с `n & 3 == 2` — ≥ 1.
  - `rig.read("TLM_SERVO") == [1]`.
- **А7. `timeout_s: 1.0`, ход домой длиннее.** `fake_clock.t += 1.1`, `tick()` → итог `failed`, `reason == "срок
  вышел"`; `.program` `park_home` затем приходит в `done` без новых строк `W STOP_REQ`; следующий `robot_jog_step` → `ok`.
- **А8. Обрыв связи во время хода домой** — `rig.restart()` (`e2e_rig_v2.py:464`).
  - Итог `failed`, `reason == "связь с роботом потеряна"` — не позже 2-го `tick()` после обрыва.
  - Затем `bounded` до выхода потока программы дома (`.program.state` не `running`; срок — `done_timeout_s`), после —
    `fake_clock.t += 2.1` перед каждым `tick()`: `drv.is_connected is True` за ≤ 3 `tick()` (Sonnet r2 m-5).
- **А9. Держится jog, в очереди 2 задания.** Итог `dropped == {"jobs": 2, "returns": 0}`; `jobs_sent` не вырос.
- **А10.** `timeout_s` 0,5; 61; `True`; `"30"` → `message == "неверные аргументы команды робота"`, `.park` не появился.
- **А11.** Второй `robot_park` во время хода → `message == "идёт основная остановка робота"`; итог первого — `seq == 1`.
- **А12. Стоп оператора на шаге `activity`** (park ждёт задание).
  - а) `robot_stop {level: "HARD"}` → следующий `tick()` → итог `failed`, `reason == "прервано стопом оператора"`;
    `.program` `park_home` не появился.
  - б) то же для `robot_stop {level: "SOFT"}` и `robot_abort {mode: 1}`.
- **А13. Робот не подключён** — через `DeviceManager` (образец `tests/test_manager.py`): отказ, текст содержит «не
  подключено», `.park` не появился.
- **А14. `disconnect()` во время хода** → к возврату итог `failed`, `reason == "идёт отключение робота"`.
- **А15. Возврат снят тиком, `park_begin` пришёл до его запуска.** Шов: обёртка публичного `drv.start_return`
  (сначала `drv.call("park", {})`, затем оригинал). Возврат остаётся в очереди (не `returns_failed`), затем итог
  `dropped.returns == 1`.
- **А16. `connect()` вручную во время park, связь жива** — после ответа park, до 1-го `tick()`: `drv.connect() is
  True`, событий `op=PARAM_SET` в `rig.core.events()` после вызова — 0; затем 1-й `tick()` → `.park` `parking`, `step ==
  "home"`.
- **А17. `robot_param_set` во время park** → `message == "идёт основная остановка робота"`, событий `op=PARAM_SET` после вызова — 0.
- **А18. Реконнект после `done`.** `rig.restart()`, `fake_clock.t += 2.1` перед каждым `tick()` до `drv.is_connected
  is True`: `rig.read("TLM_SERVO") == [0]`; `robot_jog_step` → «робот остановлен: включите серво».
