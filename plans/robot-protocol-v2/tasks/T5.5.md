DESIGN (decided by the lead — you type it, you do not derive it):
  1. `Services/device_hub/drivers/robot_driver_v2/programs.py`, класс `ProgramMixin`: метод `_op_draw_polyline(self, args: dict) -> dict`
     рядом с `_op_program_run` (`:147`), и модульная функция `_draw_strokes(points: list[dict]) -> list[list[tuple[float, float]]]`.
     - Штрихи: первая точка начинает штрих при любом `pen`; каждая точка `pen=0` начинает новый штрих; точка `pen=1`
       добавляется в текущий. Других правил нет (дедупликацию соседних равных XY делает генератор).
  2. Разбор аргументов (до любого обращения к роботу): `points` — непустой `list`; каждая точка — `dict` с `x_mm`, `y_mm` —
     конечные числа (`numbers.Real`, не `bool`), `pen` — 0 или 1 (нет ключа — 1, как v1); `z` — нет / `None` / конечное число.
     Любое нарушение → `{"status": "error", "message": TEXT_BAD_DRAW_ARGS}` — постоянный текст без входных значений (R8,
     как `TEXT_BAD_JOB_ARGS`).
  3. Потолок: `len(points) > int(entry.params.get("draw_max_points", 5000))` → `{"status": "error", "message":
     TEXT_DRAW_TOO_MANY}`. Причина — команда синхронная, на потоке приёма; 5000 точек ≈ 60 мс по замеру.
  4. Высоты и скорости — из `self.entry.params` теми же ключами и умолчаниями, что v1 (`robot_driver.py:112-122`):
     `pen_down_mm` −50.0, `pen_up_mm` −40.0, `lift_mm` 10.0, `draw_speed_pct` 30, `draw_travel_pct` 100, `draw_accel` 25000.
     Есть `z` → `pen_down = z`, `pen_up = z + lift_mm` (как v1). Генератор зовётся так:
     `draw(strokes, frame=None, hand=home.hand, rz=home.rz, pen_down=…, pen_up=…, lift_mm=lift_mm,
     draw_speed_pct=…, travel_speed_pct=…, accel=draw_accel, name="draw", home=home)`, где `home = self._home_point()`.
     `frame=None` — координаты базы, как у v1. `home=home` — рисунок кончается домом (паритет с RETURN/TOOLCHANGE v2,
     `tasks-2.md:92-93`; перо уходит с листа).
  5. Ошибка генератора (`GeneratorError`, `ValueError`) → `{"status": "error", "message": str(exc)}` (как `start_return`,
     `:75-78`). Иначе — `return self._launch(gp.program, gp.points, None, name="draw", kind="program")`; ответ `_launch`
     как есть (`{"status": "ok", "name": "draw", "total": N}` или отказ допуска / компиляции). Своей очереди рисунков нет:
     второй рисунок, пока идёт программа, получает отказ допуска `_launch` (у v1 — очередь; разница — в README, T5.5d).
  6. `robot_driver_v2/ops.py`: `OPS["draw_polyline"] = ProgramMixin._op_draw_polyline` ПОСЛЕ строки `OPS["park"]` (`:295`);
     комментарий у `park` — «… порядок `ROBOT_V2_OPS`» без слова «последней». `texts.py`: `TEXT_BAD_DRAW_ARGS =
     "неверные точки рисунка"`, `TEXT_DRAW_TOO_MANY = "слишком много точек в рисунке"`, оба — в `__all__` (`:40-…`).
  7. `Services/device_hub/spi.py`: описание `draw_polyline` (`:304-308`) выносится в модульный объект `_DRAW_POLYLINE`
     (поля — ДОСЛОВНО нынешние: `description`, `args_schema=("points", "z?")`, без `executor`, без `immediate`); в
     `ROBOT_V1_OPS` он стоит на прежнем месте, в `ROBOT_V2_OPS` — последним (после `park`). Докстрока модуля `:8` —
     `ROBOT_V2_OPS` (19); комментарий «18 ключей» (`:175`) → 19. Число команд хаба — прежнее (74).
  8. Не трогать: `Plugins/io/robot_draw/*`, `Plugins/io/robot_io/*`, `_launch`, `admit_launch`, `jobs.py`, остальные
     `draw_*` v1 (`draw_circle`, `draw_square`, `draw_set_*`, `draw_abort` — на v2 остаются «неизвестной операцией», О2).
