# T5.3h — слепой тестер: SOFT при обычном «Отключить» посреди `connect`, приёмка снаружи

Единственный вход тестера кроме перечисленных ниже путей кода. Автор: teamlead, 2026-10-21, база main `4b1a44050`.

## Приёмка

Решение владельца 2026-10-21: простой робот (нет задания, программы и jog), которому обычный `disconnect()` пришёл
посреди `connect` после подъёма связи, считается подключённым и получает ровно один стоп уровня SOFT. До подъёма
связи — записи нет (правило 2026-10-19: неподключённый простой робот стопа не получает).

- «Связь поднята»: `connect` уже подключил транспорт (или застал его подключённым у готового робота). `disconnect`,
  пришедший, пока `connect` ещё подключает транспорт (внутри `transport.connect()`) или закрывает старый сокет, —
  до подъёма связи.
- `disconnect`, пришедший после того, как `connect()` вернул True, — обычный случай: 1 SOFT.

## Задание тестера

Роль: tester (Sonnet), до кода исполнителя. Новый файл: `Services/device_hub/tests/test_robot_v2_t53h_blind.py`.

Публичный API драйвера: `connect()`, `disconnect()`, `request_stop(deadline)`, `is_connected`,
`state.view().stopping`, `call("jog_hold", {"dir": 1, "spd": 20})`. Обвязка с фейками:
`Services/device_hub/tests/test_robot_driver_v2.py:464-582` (`_FakeTransport`, `_FakeClient`, `_fake_driver`).
Точки паузы без DESIGN: Event внутри фейкового `client.probe`, `client.sync_params`, `transport.connect` (сначала
`is_connected = True`, как настоящий транспорт перед возвратом, затем пауза), `transport.disconnect` (закрытие
старого сокета), `transport.read_registers` (чтение TLM в действиях при подключении) — с проверкой, что вызов идёт из
потока `connect`. Каждый блокирующий вызов — в daemon-потоке с дедлайном `join`; первый тест файла — дедлайн 1 с.
Проверка «0 записей» — только вместе с проверкой достижимости окна. Ожидаемые значения — литералы. Уровень SOFT
протокола v2 — 1.

Поведение снаружи (имена обязательны, на них ссылаются инъекции):
- `test_b1_disconnect_inside_probe_one_soft` / `test_b1_disconnect_inside_sync_one_soft` /
  `test_b1_disconnect_inside_on_connect_read_one_soft`. Робот не готов, транспорт подключён; `disconnect()` внутри
  точки. Ровно 1 запись стопа уровня 1; `connect()` → False; после него `is_connected` False.
- `test_b2_ready_robot_disconnect_inside_probe_one_soft`. Робот подключён (`connect()` → True), затем повторный
  `connect()`; `disconnect()` внутри `probe` повторного. Ровно 1 запись уровня 1 за `disconnect`; `connect()` → False.
- `test_b3_disconnect_inside_transport_connect_no_write` / `test_b3_disconnect_while_closing_stale_socket_no_write`.
  0 записей стопа; `connect()` → False.
- `test_b4_disconnect_after_connect_one_soft`. `connect()` → True, затем `disconnect()`: 1 запись уровня 1.
- `test_b4_disconnect_then_connect_clears_stopping`. `connect`, `disconnect` посреди повторного `connect` (точка
  `probe`), затем `connect()` → True: `view().stopping` False, `jog_hold` не отвечает «драйвер робота
  останавливается».
