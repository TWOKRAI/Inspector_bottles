## API `RobotState` (решения teamlead Q6, Q9, Q10; стадия 0)

Внутреннее API драйвера, не SPI хаба: код вне пакета `robot_driver_v2` и вне тестов переходы не зовёт (сторож f3). Конструктор: `RobotState(*, clock: Callable[[], float], queue_maxlen: int)`. Accessor: `RobotDriverV2.state` (только чтение). Снимок: `view() -> RobotStateView` (замороженный dataclass, снят под замком; присваивание поля → `dataclasses.FrozenInstanceError`).

Поля (27): `program_active` (= `_busy` + `_prog_alive`), `prog_handle`, `job_active`, `jog` (`_JogRun | None`), `jog_starting`, `jog_stopping`, `last_hold`, `syncing`, `stopping`, `shutdown`, `stop_level`, `latch_level`, `latch_failed`, `latch_value`, `latch_attempts`, `echo_checked`, `stop_unconfirmed`, `stop_unconfirmed_text`, `own_stops`, `job_queue`, `return_queue`, `returns_done`, `returns_failed` (23) + `_JogRun`: `active`, `released`, `stop_requested`, `stop_sent` (4). Вне состояния: `_values`, `_epoch` (владелец `_param_lock`: писатели :1229, :1232, :1276, :1279, :1916; читатели без замка :519-528, :1022, :1088, :1331, :1343), `_ready`, `run.handle` (под `_jog_tx_lock` :1476), `jobs_*`, `_last_*`.

`RobotStateView` (23 поля): те же имена; `prog_handle` → `has_prog_handle: bool`; `jog: JogView | None` (`seq`, `active`, `released`, `stop_requested`, `stop_sent`, `has_handle`); очереди и `own_stops` — кортежи.
