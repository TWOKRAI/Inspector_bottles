DESIGN (decided by the lead — you type it, you do not derive it):
  1. Граница: ядро — только модель (части A, B). Хостинг, тик и Modbus TCP — плагин `SimRobotHostPlugin` с ключом `protocol: v1|v2`. По умолчанию v1; иное значение — отказ наблюдается на старте тем же путём, что `job_ms` (`_fail`, `state="error"`, процесс жив), но текст ошибки БЕЗ входного значения: «protocol: допустимо v1|v2». Путь v1 не меняется ни на строку поведения; все прежние тесты `Plugins/sim/robot_host/tests` и `Services/robot_comm/tests` зелёные без правок.
  2. `SimRobotServer` (`Services/robot_comm/server/sim_robot.py`) получает ключ конструктора `external_threads: bool = False`. При `True` `start()` собственных потоков не заводит; открыты два метода: `tick_once(dt)` (тик ядра, потолок `_MAX_TICK_DT_S`) и `serve_until(stop_event, ready)` (блокирующий asyncio-слушатель: сторожевая корутина опрашивает `stop_event` и зовёт `shutdown()`, после ожидания bind выставляет `ready`; сбой bind — исключение наружу). Блок регистров слушателя = `len(self.core.regs)` (для v2 это `REG_SPACE_SIZE_V2` = 0x3083, иначе FC3 по 0x3080 (PMIR) отвечает `ILLEGAL_ADDRESS`, а `attach` v2 молча растит список pymodbus); для v1 — прежний `REG_SPACE_SIZE`, поведение не меняется. Два `threading.Thread(` в `sim_robot.py` остаются только в пути `external_threads=False`.
  3. Воркеры v2 заводятся одним местом `_start_v2_workers(ctx)`: `ctx.worker_manager.create_worker(name, fn, ThreadConfig(execution_mode=ExecutionMode.LOOP), auto_start=True)`. `sim_robot_ticker`: шаг `TICK_INTERVAL_S`, `dt` по `perf_counter`, `pause_event` игнорирует (мир линии не должен вставать от паузы воркеров). `sim_robot_listener`: `server.serve_until(stop_event, ready)`. `_start_v2_workers` ждёт `ready` не дольше 5.0 с; сбой или таймаут → `_fail`, `state="error"` (с `create_worker(auto_start=True)` сбой bind иначе дал бы `WorkerStatus.ERROR` при `state="running"`). Повторный `start` после `shutdown` — через `start_worker` на существующее имя (`create_worker` на занятое имя возвращает False). Из `ctx` — только публичный API (`worker_manager`, `state_proxy`, `publish_metric`, `log_*`, `health`): задачи Ж 1.2–1.3 переделывают корень процесса и `WorkerManager`, кто вливается вторым, ребейзится. Под будущий `owner=` (Ж 1.3) правка одна — в `_start_v2_workers`.
  4. Ядро для v2: `RobotSimCoreV2(belt=..., on_event=journal.on_event, on_job_done=self._on_job_done)`; публичные имена ядра (`belt`, `belt_mm_s`, `encoder`, `command_vfd`) покрывают всё, что плагин читает у `RobotSimCore`. `_on_job_done` заменяет `t` события на `time.monotonic()` перед пересылкой `scene.job_done` (в ядре монотонных часов нет). Ветвление v1/v2 — в `_start_server` один раз; остальные методы работают с `self._server.core` через общие имена. `shutdown()` для v2 не трогает `core.vfd_fault_code`/`server.delay_ms` (их у v2 нет смысла), `sim_robot.status` получает ключ `protocol`.
  5. Команды: `belt.*` и `sim_robot.journal*` работают на v2 теми же ответами; `fault.*` — по О3.
