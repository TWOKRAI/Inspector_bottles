- probe(). Расписание держит вызывающий (драйвер, T3.2).
- seq mailbox. Старт `rng.randint(1, 65535)`. Каждая выдача, включая первую, берётся из одного чтения шага (2) по 0x1010..0x105F (как probe (1)). Пропускаются 0 и текущие `RES_SEQ`, `TLM_DONE_SEQ`, `TLM_ERR_SEQ`, по кругу 65535 → 1. Первая выдача — сам старт, если он не попал в этот набор; дальше +1 от последнего выданного (protocol-spec §3.1; §4 п.4 — повтор seq отдаёт прежний RES без исполнения).
- cmd(op, args) -> CmdResult(seq, rvals). `op` — имя из `OP`; `len(args) ≠ OP_SPEC[op]["argc"]` → `ValueError` без записи; аргумент вне `CONSTANTS["W_MIN"]`..65535 → `ValueError` без записи, иначе кодируется `& 0xFFFF`. Порядок под `_mailbox_lock` (сериализует `cmd()` целиком): (1) если прежний seq «в полёте» — досмотреть его `RES_SEQ` не дольше `res_timeout_s`; дождались или нет — метка снимается; не дождались → `RobotTimeout("response")` без записи (следующий `cmd()` пишет сразу; перезапись слота безопасна по §4 п.4); (2) одно чтение 0x1010..0x105F — база `ERR_EVT`, `DONE_SEQ` и поколение стопа в одном слоте (последний `done_seq`-seq); выдача seq; (3) одна `transport.transaction([("wm", CMD_SEQ, [seq, opcode, argc, *args]), ("w", CMD_FLAG, 1)])`; (4) поллинг `RES_SEQ == seq` до `res_timeout_s`; не дождались → метка «в полёте», `RobotTimeout("response", seq)`; README: после `RobotTimeout("response")` — `stop()`; (5) RES-блок одним чтением. NAK → `RobotNak`: `reason` = rval0 при `RES_RVALC ≥ 1` для `E_RANGE`, rval1 при `RES_RVALC ≥ 2` для `E_SC_RECORD`, иначе `None`; `index` = rval0 у `E_SC_RECORD`; `rvals` — первые `RES_RVALC`; `text` = `ERR_TEXT.get(errno, "неизвестная ошибка")` и `": " + REASON_TEXT[reason]` только при `reason in REASON_TEXT`. Значения RVAL сверх `RES_RVALC` не читаются как данные (`sim_core_v2.py:1422-1423`).
- Стоп и команда «в полёте» (О5). Счётчик поколений растёт после записи FC6 `STOP_REQ`, в `finally` (ошибка транспорта тоже считается), под `_stop_lock`; поле `last_halt_gen` — поколение последнего HALT. Сверка поколения к ACK — под `_stop_lock`. Только для опкодов с `OP_SPEC[op]["result"] == "done_seq"`: `cmd()` сравнивает поколение шага (2) с поколением к ACK; сменилось — одна запись FC6 стопа уровня HALT, если в окне был HALT, иначе HARD (решение владельца: `max(уровни в окне, HARD)`), под `_stop_lock` без ожидания эха, наружу всегда `RobotAborted` (команда принята после стопа, sim `sim_core_v2.py:735-739`). Мгновенные опкоды (`result: instant` — `SERVO`, `DO_SET`, `PARAM_APPLY`, …) возвращают свой результат.
- wait_done(seq). Только для seq последнего `CmdResult` опкода `done_seq` этого клиента; иначе `ValueError`. `_mailbox_lock` не берёт. Поллинг TLM-блока одним чтением от базы шага (2): `TLM_DONE_SEQ == seq` → успех; `ERR_EVT` изменился и `TLM_ERR_SEQ == seq` → `RobotCommandError` (`E_ABORTED` → `RobotAborted`); `ERR_EVT` изменился, `DONE_SEQ ≠ seq`, `ERR_SEQ ≠ seq` и `TLM_ACTIVITY ∈ {0, 5}` (простой или авария) → `RobotCommandError(errno=None, text="событие обрыва перекрыто")`; дольше `done_timeout_s` → `RobotTimeout("done", seq)`. Асинхронные события (`ERR_EVT` изменился, `ERR_SEQ` не наш) — `poll_errors() -> list[ErrorEvent]`, `ErrorEvent(evt, seq, errno, text, missed)`; курсор — `ERR_EVT` из probe; при изменении — одно событие из TLM (хранится только последнее), `missed = Δ − 1`; события своих команд тоже возвращаются; курсор не зависит от базы `wait_done`.
- stop(level) -> StopResult. `level ∉ {1, 2, 3}` → `ValueError` без записи. Под коротким `_stop_lock` только «выдать `stop_seq` + одна запись FC6 в `STOP_REQ`»; `stop_seq` — следующий после `TLM_STOP_ACK // 4` из probe, 1..16383 по кругу; значение `stop_seq * 4 + level`. Замок снят до ожидания эха. Конец ожидания: `TLM_STOP_ACK == значение` → `StopResult.ACKED`; seq эха новее нашего по кругу (окно в полкруга, 8191) → `StopResult.SUPERSEDED`; дольше таймаута уровня (SOFT — `soft_echo_timeout_s`, иначе `stop_echo_timeout_s`) → `RobotTimeout("stop_echo")`. `_mailbox_lock` не берёт.
- sync_params(values: Mapping[str, int], epoch: int) -> SyncReport(sent, applied, epoch) по params.md §11.4 п.3. Значения сырые (§11.1); обязательны все имена словаря `PARAM_ID`, кроме `P_CONFIG_EPOCH`; отсутствующее, лишнее или неизвестное имя, ключ `P_CONFIG_EPOCH`, `epoch == 0` (О1) → `ValueError` без записи. Читает `TLM_CFG_EPOCH` и `PMIR_DICT`; оба совпали (`epoch` и `params_v2.DICT_FINGERPRINT`) → ни одной записи, `SyncReport(0, False, epoch)`. Иначе `PARAM_SET` каждого значения через `cmd()`; NAK → `RobotNak` наружу, метка не пишется; `PARAM_APPLY`, если `TLM_CFG_PENDING == 1`; сверка `PMIR` с ожидаемым (`& 0xFFFF`, чтения ≤ `CONSTANTS["READ_MAX"]`), расхождение → `RobotSyncError`, метка не пишется; `PARAM_SET P_CONFIG_EPOCH = epoch` **последней** записью. Хранилище `params.yaml` клиент не читает и не пишет.
- Константы и адреса — только из `core/protocol_v2.py` и `core/params_v2.py` (сгенерированы, не править).
