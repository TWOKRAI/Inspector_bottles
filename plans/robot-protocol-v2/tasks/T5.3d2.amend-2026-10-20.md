## Факты проб (вход → наблюдение)

1. `state.get {"path": "devices.state.r1.conn"}` → лист `{"status": "ok", "request_id": "", "value": {"conn": "connected", "ts": N}}`
   — словарь, не строка; до первой публикации — `success: false`, `"Путь не существует: 'devices.state.r1.conn'"`.
   `devices.state.r1.program` — словарь `{"name", "state", "done", "total", "error"}`; путь появляется с первым `program_run`.
2. Журнал обмена: содержательный файл только `<log_dir>/devices/robot_exchange.log` (в каталогах других процессов
   файл есть, 0 байт). Строки `STOP_REQ`, записанные на `plugin.shutdown`, на диске к возврату `process.stop` — 21/21.
3. Получив `process.stop`, процесс `devices` перестаёт обслуживать команды («Stop signal received» в
   `devices/messages.log`); плагин закрывается через 150–190 мс («All workers stopped»). `robot_jog_hold`, отправленный
   после этого, отвечает `timeout`.
4. Поэтому окно удержания (`_HOLD_WINDOW_S = 0.2`) может истечь ДО `request_stop`: поводок пишет свой SOFT, затем
   выключение пишет SOFT стоящему роботу. Держатель жив до отправки `process.stop`: r1 = 2 в 9 из 16; держатель шлёт и
   во время `process.stop`: 5 из 16; держатель замолк за 0,6 с до стопа: 4 из 4. Простой r2 — 1 во всех 41 прогоне;
   уровень SOFT везде. Буквальный шаг 5 (один `jog_hold`): 5/5 по 1, но `JOG_CONT → STOP_REQ` 0,146–0,205 с против
   окна 0,2 с — гонка, тест мигал бы.

## Решение лида 2026-10-20 (владелец передал выбор лиду)

Стоп поводка — конец jog (защита: удержание пропало), не стоп выключения. Выключение пишет ровно один стоп каждому
подключённому роботу, стоящему — SOFT (решение владельца 2026-10-19, п. 1). Две записи у робота, чей jog закрыл поводок
до `request_stop`, — норма. Продукт пути стопа НЕ меняется: «пропуск» стопа выключения после поводка вносит в путь стопа
условие, которое может пропустить нужный стоп. Причина стопа поводка становится видна в логе (DESIGN ниже).
Корень — зазор «процесс не берёт команды → закрытие плагина» ~170 мс — в T5.3e (штатное выключение пересматривает
порядок остановки). Отвергнуто: окно удержания из конфига (правка конкурентности драйвера; зазор зависит от нагрузки,
окно его не закрывает).

## Решения владельца 2026-10-20 (вопросы передачи `docs/handoffs/2026-10-20_task-T5.3cd-lead.md`)

## DESIGN (developer)

D-L1. `robot_driver_v2.py`, `_lease_loop`: при `stop` под `_flags_lock` запомнить причину; после успешного
`self._stop_jog(run)` — одна строка `logger.info` с id робота и причиной. Тексты (литералы, для теста):
- окно истекло: `f"робот {self.entry.id!r}: jog остановлен поводком: окно удержания истекло"`
- область закрывается (`ev`): `f"робот {self.entry.id!r}: jog остановлен поводком: область закрывается"`
Если `run.released` или исключение — строки нет (прежнее поведение). Логика остановки, замки, порядок — без изменений.
Строка пишется ПОСЛЕ записи стопа, не держа `_flags_lock` и `_jog_tx_lock`.
