## Риски и ограничения

- О1-а — второй корень области в процессе `devices`; пока плагин закрывает его в `shutdown`, G3 чист. Если процесс гасится без `shutdown` плагина, корень `abandoned` — тот же риск, что у любого корня. Если `configure()` бросил, фреймворк всё равно зовёт `shutdown()` (Ф10): плагин закрывает корень в `configure` сам (T5.3a DESIGN 10).
- Команды хаба идут по одной (Ф8, file:line в таблице фактов), поэтому блокирующий обработчик задерживает все следующие, включая `robot_stop`: `jog_release` (до 1.0 с), `param_set` (две транзакции и fsync), `disconnect`. Решение владельца О9: обработчик каждой `robot_*` возвращается ≤ 1,0 с, в потоке `spawn` уходит только программа (захват точки — синхронно, О9-а); приёмка T5.3d — `robot_stop` во время `robot_jog_release` отвечает ≤ 1,5 с от постановки в очередь команд. **О9 гарантируется только при исправной связи (О9-б):** при мёртвой связи `robot_jog_release` ждёт до `_LEASE_JOIN_S` 1.0 с плюс эхо SOFT до `soft_echo_timeout_s` 2.0 с (`client_v2.py:170`), `robot_jog_hold` — ACK `JOG_CONT` до `res_timeout_s` 2.0 с (`client_v2.py:167`); срок не гарантирован, как и окно 3,0 с у О8. Оговорка Ф8: вложенный `receive()` в том же потоке может обработать чужую команду внутри обработчика.
- Длительность shutdown против срока остановки процесса `devices` (Ф9): graceful 5.0 с → `terminate` → 1.0 с → `kill` → 1.0 с; shutdown плагинов идёт в сегменте `work` = 3.0 с. Бюджет 7.0 с из ред. 2 в окно не входил; формула «N × (1.0 + 5.0) с на N роботов плюс область» входит ещё хуже. По О8: стоп-сигнал всем драйверам сразу, затем одно закрытие корня `device_hub` с `budget_s=2.5`; приёмка — два робота в движении, `plugin.shutdown` ≤ 3,0 с, `survivors == []` (T5.3a REDS 8).
- Остановка плагина по К1 (T5.3a, решение teamlead, принято лидом 2026-10-18): стоп всем драйверам сразу (задание и программа — HARD, jog — SOFT; О10), затем воркеры, одно закрытие корня `budget_s=2.5`, затем `manager.shutdown()`. Оценка с выжившим потоком ≈ 2,9 с — запас 0,1 с до окна 3,0 с; сроки не измерены, проверяет REDS 8 и стенд. При мёртвой связи окно 3,0 с не гарантировано: эхо HARD ждётся до 1,0 с на робота, по очереди.
- Имена потоков в общей области `device_hub` не должны совпадать между роботами и при пересоздании устройства: имя `f"{entry.id}-lease-{k}"` / `f"{entry.id}-prog-{k}"`, `k` — один на модуль `itertools.count(1)` (T5.3a DESIGN 3–4, REDS 6).
