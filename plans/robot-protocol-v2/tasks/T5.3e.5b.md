### DESIGN, часть 1 — менеджер (решено — набрать, не выводить)

**Ловушка, из-за которой C-60 потерял штатный `ProcessModulePlugin.shutdown`:** правка, заменяющая соседа, молча его
роняет. Здесь — ВСТАВКА методов; `DeviceHubPlugin.shutdown` (`plugin.py:276-315`) делает всё то же по пунктам (в), в том
же порядке. Сторож — полный радиус `Plugins/hub/device_hub/tests` + `Services/device_hub/tests` и REDS 9
(`test_shutdown_without_hook_latches_supervisor`).

1. **Поля** в `DeviceManager.__init__` рядом с `_stop_deadline` (`manager.py:96`): `self._stop_handles: list[IHandle] |
   None = None` (потоки стопа, запущенные `begin` и ещё не дождавшиеся), `self._stop_served: list[DeviceDriver] = []`
   (сами объекты драйверов, которым стоп уже ушёл; членство — `any(d is drv for d in ...)`, не по id: `remove` +
   `upsert` того же id в окне создают новый объект, `manager.py:427, 704`, р.2 M5), `self._stop_begin_lock =
   threading.Lock()` (R5: всё тело `begin` — под ним; контракт хука повтора с разных потоков не исключает, `base.py:1579`).
2. **Разделить без изменения смысла** тело `:150-183` на два приватных: `_stop_start(self, drivers, deadline) ->
   list[IHandle]` (`:150-175`: отбор `stop_aware`, `spawn` или по очереди без `spawn`, inline при отказе `spawn`) и
   `_stop_wait(self, handles, deadline)` (`:176-183`: `handle.close` до `deadline`, тексты лога прежние). Прежний
   `request_stop_all` без `begin` = срок `:142-148` + `_stop_wait(_stop_start(все), deadline)` — поведение байт в байт.
3. **`request_stop_all_begin(self, deadline: float) -> None`** — докстрока с `Pre:` (срок абсолютный по `monotonic`) и
   `Post:` (возврат без ожидания потоков; не бросает; повтор — без действия; при отказе `spawn` стоп этому роботу идёт
   в вызывающем потоке — fail-closed, тогда возврат до срока, R7). Тело под `_stop_begin_lock`: `_stop_handles is not
   None` → выход; под `_registry_lock` — защёлка `_stop_deadline` (как `:147-148`) и снимок драйверов;
   `handles = _stop_start(снимок, deadline)`; **в конце** под `_registry_lock` — `self._stop_served = list(снимок)`,
   `self._stop_handles = handles` (без `spawn` — `[]`). Ставить в конце, не заранее: упал `begin` → поле `None` →
   `shutdown` идёт прежним путём (R5).
4. **`request_stop_all(deadline=None)`**: срок — как `:142-148`. Под `_registry_lock` забрать `handles =
   self._stop_handles`; `None` → прежний путь (п.2) целиком. Иначе `self._stop_handles = []`; драйверы снимка, которых нет в
   `_stop_served` (появились после хука, R6), — **сначала запустить** `new = _stop_start(новые, deadline)` и добавить
   их в `_stop_served` (р.2 M6: зависший сосед не задерживает запись позднему роботу), **затем** `_stop_wait(handles +
   new, deadline)`.
   Вызов из `_on_shutdown` (`:194`, фаза 4) после хука: ждать нечего, новых нет — нового запроса нет.
