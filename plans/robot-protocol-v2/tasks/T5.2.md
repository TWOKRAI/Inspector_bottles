DESIGN (решено; не выводить заново):
  1. Публичный API (`__all__`; докстрока модуля `Purpose:` / `Public API:` / `Stability: lite` / `Test seam:`):
     `DOCS = ("params", "points", "frames", "calibration")`;
     `@dataclass(frozen=True) class StoredDoc: body: dict | None; rev: str | None`;
     `class RobotDataStore(root: str | os.PathLike[str])` с методами
     `read(device_id, doc) -> StoredDoc`, `write(device_id, doc, body, *, base_rev) -> str`,
     `read_program(device_id, name) -> StoredDoc`, `write_program(device_id, name, body, *, base_rev) -> str`,
     `list_programs(device_id) -> list[str]`; функция `compute_rev(raw: bytes) -> str`.
     `base_rev` — keyword-only БЕЗ умолчания (как обязательный ключ `base_rev` у `recipe.save`).
     В докстроке КАЖДОГО публичного метода — `Pre:` / `Post:` (форма — `Services/robot_comm/core/client_v2.py:345`): условия отказа, что на диске после успеха и после отказа.
  2. `root` — каталог `data/robot` целиком; конструктор только запоминает путь (`Path(root)`), env не читает, ничего не создаёт. Где лежит `root` в бою (`INSPECTOR_DATA_DIR`, корень проекта) — T5.3.
     Пути: `root/<device_id>/<doc>.yaml`; `root/<device_id>/programs/<name>.yaml`.
  3. Ревизия — `sha256(байты файла).hexdigest()`, считается от ТЕКУЩИХ байтов на диске в момент вызова, кэша ревизии в памяти нет. Клиент только сравнивает на равенство (непрозрачная строка). Нет файла → `rev is None`, `body is None`.
     `write`: под замком документа прочитать байты → `current_rev` → `base_rev != current_rev` → `RevisionConflict(current_rev)`, диск не тронут. `base_rev is None` = создание (файла быть не должно); строка при отсутствующем файле — тоже конфликт. Успех → вернуть `compute_rev(новых байтов)`.
     Почему не счётчик: счётчик живёт в теле файла, ручная правка без счётчика затёрлась бы молча; хэш ловит любую правку мимо хранилища.
  4. Документ — YAML-mapping верхнего уровня. Запись: `yaml.safe_dump(body, sort_keys=False, allow_unicode=True).encode("utf-8")` ДО взятия замка; `body` не `dict` или не сериализуется (`yaml.YAMLError`) → `StoreDocumentInvalid(rev=None)`, диск не тронут. Чтение: `yaml.safe_load(bytes)`; не разбирается или не mapping (в том числе пустой файл) → `StoreDocumentInvalid(rev=<rev этих байтов>)`: по этой ревизии вызывающий может сознательно перезаписать. Схемы содержимого (формат `params.yaml`, точки, программы) хранилище НЕ знает и не проверяет.
  5. Атомарная запись (`_atomic_write(path, data)`, под замком документа): `path.parent.mkdir(parents=True, exist_ok=True)` → `tempfile.mkstemp(dir=path.parent, prefix=f".{path.name}.", suffix=".tmp")` → запись, `flush`, `os.fsync`, закрыть файл (выйти из `with os.fdopen`) → `_replace_file(tmp, str(path))` с повтором (п.6). Любое исключение до конца замены: `os.unlink(tmp)` (ошибка `unlink` — в лог, не наружу), исходное исключение — наружу без обёртки (`OSError` не оборачивается, как транспортные ошибки в `errors.py`).

## Бриф: DESIGN п.6–8 (шов, временные файлы, потоки)

  6. **Шов теста (часть контракта):** модульная функция `def _replace_file(src: str, dst: str) -> None: os.replace(src, dst)`. Хранилище зовёт её ТОЛЬКО по имени модуля в момент вызова (не `from os import replace`, не поле экземпляра, не умолчание аргумента) — тестер подменяет `monkeypatch.setattr(store_mod, "_replace_file", fake)`. Повтор — снаружи шва: каждая попытка — новый вызов `_replace_file` по имени модуля. `PermissionError` (Windows: цель открыта чужим процессом — антивирус, редактор; WinError 5/32) → паузы `_REPLACE_PAUSES = (0.05, 0.1, 0.2, 0.4, 0.8)` (сумма 1.55 с, образец `scripts/atlas/codemap.py:44,166-180`), затем последняя попытка без перехвата → `PermissionError` наружу, старый файл цел, tmp удалён. Прочие `OSError` не повторяются.
  7. Застрявшие временные файлы (обрыв процесса между `mkstemp` и заменой) хранилище НЕ чистит: чтение открывает только точные имена, `list_programs` перечисляет только `*.yaml`, прошедшие проверку имени (п.9), — застрявший `.<файл>.<случайное>.tmp` не виден ни одному методу.
  8. Потоки (гарантия T5.2 — ОДИН экземпляр `RobotDataStore` в одном процессе, любое число потоков): замок на документ `threading.Lock` в словаре экземпляра по ключу `(device_id, rel.casefold())`, где `rel` — путь документа относительно `<root>/<device_id>` (`params.yaml`, `programs/<name>.yaml`); словарь под `_locks_guard` (как `recipe/service.py:108-110`). Почему casefold: на нечувствительной к регистру ФС (Windows) `programs/Prog.yaml` и `programs/prog.yaml` — один файл; с двумя разными замками два одновременных создания (`base_rev=None`) оба прочитали бы «файла нет» и оба записали бы — молчаливое затирание. Сравнение ревизии и замена — под одним замком: из двух `write` с одним `base_rev` успешен ровно один. `read`/`read_program` тоже берут замок документа: на Windows `os.replace` падает `PermissionError`, пока свой поток держит цель открытой на чтение; следствие — `read` может ждать до ~1.6 с, пока запись повторяет замену (п.6), записать в докстроку и README. `list_programs` без замка. Два экземпляра на один `root` или два процесса — НЕ гарантируется (В2), записать в докстроку. Глобального состояния нет (И8): замки, `root` — поля экземпляра; модульные константы — только неизменяемые. Потоков хранилище не создаёт (G6 R1), строк в `ALLOWLIST` не добавлять.
