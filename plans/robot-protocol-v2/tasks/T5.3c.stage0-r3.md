## Решения по вопросам лида

**Q1 — подкласс `RobotWatchdogDisabled(RobotDataInvalid)` оставить.**
Владелец (§3 `T5.3.round2-decision.md`): «отказ в продукте (ошибка проверки конфига)». Подкласс и есть ошибка проверки конфига: все `except RobotDataInvalid` ловят его без правок. Текст обязан назвать причину: 0 — единственное значение, которое таблица протокола принимает (`min 0`, probe1), а продукт отвергает. Общий текст «не прошли проверку» отправит оператора искать выход за границы, которого нет. Простой `RobotDataInvalid` со своим текстом потребовал бы менять его конструктор — публичный контракт T5.3b; это больше правки, а не меньше. Новый слой не появляется: один класс, ни одного нового обработчика. Условие: в T5.3c нет ветки `except RobotWatchdogDisabled`; если в `errors.py` есть `__all__`, класс вносится туда.

**Q2 — в файлах под git чинить нечего.**
`git grep robot_params` вне тестов и документов: один носитель — `multiprocess_prototype/recipes/letter_robot_sim.yaml:84`, `P_ZONE_MAX: 6000` — целое, в `0..32767`. Тест уровня плагина `test_robot_v2_scope.py:548` — `{"P_SPD_J": 4}`, целое в `1..100`. Тесты драйвера (`test_robot_driver_v2*.py`) создают драйвер без `param_source` и не затронуты. `50.0`, `True`, `"50"` нигде нет. Не проверено: реестры вне git (`data/devices.yaml` стенда и машин заказчика).

**Q3 — DESIGN 9–10 вынести в отдельную подзадачу; teamlead не нужен.**
Причины: предел формы 10 REDS (п. 8); другой механизм и файл; свой уровень Senior+ и Opus-ревью. Состав: DESIGN 9–10, REDS 18–19; FILES — `robot_driver_v2.py` (с п. 1), `plugin.py` только `_report_unconfirmed_stops`, `test_t53c_stop_acceptance.py`. Исполнитель — developer (Sonnet): дизайн у лида построчный, дифф около 25 строк. Ревью — Opus с воспроизведением (счёт `STOP_REQ`, время `disconnect`). Порядок — режим A, последовательно с остальной T5.3c: `plugin.py` общий. Если лид оставляет одну задачу: уровень всей задачи Senior+ и запись об отказе от предела REDS с причиной.
