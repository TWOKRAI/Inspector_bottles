DESIGN (решено):
  1. `RobotDriverV2.__init__(..., store: RobotDataStore | None = None)`; фабрика передаёт `robot_store`. Третий замок `_param_lock` — только вокруг `param_set`/`param_apply` и синхронизации; не берётся под `_jog_tx_lock` и наоборот; `_flags_lock` — внутри него.
  2. `_syncing` (под `_flags_lock`): `connect`-синхронизация и `_resync_maybe` ставят его в ОДНОЙ секции с проверкой «нет `_busy`, `_jog_starting`, `_jog_stopping`, живого jog, `_job_active`»; снимают в `finally`. `jog_hold`, `jog_step`, `_launch`, `param_set`, `param_apply` при `_syncing` → `{"status": "error", "message": "идёт синхронизация параметров"}`.
  3. Операции (текст — постоянный, без входных значений; NAK робота → `{"status": "error", "message": exc.text}`; нет связи → `_NOT_CONNECTED`):
     `stop {level}` — `level ∈ STOP_LEVEL` иначе `"неизвестный уровень стопа"`; шлётся всегда, без проверки занятости; ответ `{"status": "ok", "level"}`.
     `servo {on: bool}`, `do_set {ch: 1..16, on: bool}` (иначе `"канал DO вне 1..16"`) — при программе, jog, задании → ответы занятости T5.1/T3.7; ACK → ok.
     `jog_step {dx, dy, dz=0, drz=0, spd 1..100}` — `done_seq`: отказ при программе/jog/задании/синхронизации; `_coord` для смещений; ответ `{"status": "ok", "seq"}` после ACK, без ожидания DONE.
     `point_capture {name, base_rev}` — поза из TLM (`x_mm…rz_deg`, `hand`) → `Point(frame=None)` → вставка в `points.yaml` через `robot_data`; ответ `{"point", "rev"}`.
     `param_set {name, value, base_rev}` — имя ∈ `PARAM_ID` и ≠ `P_CONFIG_EPOCH` (иначе `"неизвестный параметр"`); `raw = to_raw(name, value)` в `min..max` (иначе `"значение вне диапазона"`, робот не тронут); под `_param_lock`: ревизия `params.yaml` ≠ `base_rev` → отказ T5.3c-формы, робот не тронут; `client.param_set(name, raw)` → NAK → отказ, файл не тронут; ACK → `epoch' = epoch % 65535 + 1` → `client.param_set("P_CONFIG_EPOCH", epoch')` → `save_params(..., base_rev)` → `self._values`, `self._epoch` под `_flags_lock` → публикация `devices.state.<id>.params` = `{"epoch", "rev", "values": {имя: {"raw", "value"}}}`; ответ `{"status": "ok", "name", "raw", "value", "epoch", "rev"}`. Запись файла упала после ACK → ответ-ошибка, `self._epoch` НЕ меняется: следующий тик увидит расхождение меток и вернёт роботу значения файла (§11.4 п.4).
     `param_apply` — `client.param_apply()` → ok.
     `program_run {name}` — программа, точки, СК из хранилища → `start_program(..., name=name)`; нет программы → `"программа не найдена"`; `CompileError` → `str(exc)`.
     `program_abort` — программа идёт → `stop(SOFT)`, `{"status": "ok", "stopped": true}`; нет → `{"status": "ok", "stopped": false}` без записи `STOP_REQ`.
