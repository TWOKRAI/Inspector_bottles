## Расхождения

1. **A-2: №1(а) выжил.** Тест `test_outcomes_per_robot[two_done]` сверяет только поле `result`, а мутант ставит `done`
   без ожидания. Мутант всё равно убит: его ловят №1(б) и 15 других тестов. Нового теста не нужно. Можно сверять в (а)
   весь `R` литералом.
2. **A-16c.** В прогнозе одна строка A-16 и один тест №1(б). №1(б) бросает только из `call`, поэтому ветку исключения
   `park_wait` ловит лишь хазард автора `test_wait_exception_is_error_and_neighbour_finishes`. Защита есть. В таблицу
   прогноза стоит добавить этот тест строкой A-16c.
3. **A-17b: красный сверх прогноза.** Без `_safe_call` исключение менеджера уходит из `cmd_robot_park_all` наружу.
   Его ловит хазард автора `test_command_exception_is_error_reply`, которого нет в REDS 5a2. Прогноз «красного нет»
   верен только для варианта без `isinstance` (A-17a).
4. **A-17a выжил** (принято в прогнозе). Настоящий `CommandManager` отдаёт словарь, поэтому проверка без `isinstance`
   проходит так же. Убить его может тест, где менеджер команд — `MagicMock`: команда должна отказать «нет исполнителя»
   и не звать `robot_park_all`. Такой тест достаточен как защита от заглушек. Предлагаю, не писал.
5. **Красные сверх прогноза в A-1, A-15** объяснимы. В A-1 без `executor` регистрация идёт без исполнителя, и каждый
   вызов отказывает «нет исполнителя». В A-15 подмена менеджера в тестах автора требует аргумент `should_stop`, и
   вызов без него падает `TypeError`. Это свойство подмены, а не второй сторож поведения: из пяти красных A-15
   поведение проверяют АВП №3 и СЛП `after_hook…`.
