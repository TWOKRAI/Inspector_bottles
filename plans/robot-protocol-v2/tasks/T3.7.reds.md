# T3.7 — красные тестера, тесты автора, инъекции

Часть брифа `tasks/T3.7.md` (ред. 2), вынесена по размеру (прецедент — `T3.5b.guard.md`). Тестер читает разделы «Стенд и правила» и «REDS»; раздел «Инъекции» — только лид и reviewer.

## Стенд и правила

- Sim — настоящий: `E2eRig` из `Services.robot_comm.tests.e2e_rig_v2` (`free_port()`, `rig.jobs()`, `rig.events()`, `rig.read`, `rig.restart`, `rig.core`). Драйвер — `RobotDriverV2(entry)` на `rig.port`; тик — `pulse(_tick_fn(drv), 0.1)`, как в `test_robot_driver_v2_acceptance.py`, кроме REDS 10 (ручной тик).
- Лента rig едет с первого тика: `belt_mm_s` 101.1, `P_BELT_DIR` 1 (+Y), энкодер растёт ~700 имп за 100 тиков. Литералы энкодера — только от `E0 = rig.read("TLM_ENC", 2)` (младшее слово первым), не абсолютные. Нужна неподвижная лента — `rig.core.command_vfd(run=False)` до драйвера.
- Точка забора: `r = hypot(x, y)` в 200..450 мм и `y <= −150` (кольцо по умолчанию 120..500 мм; за 5 с лента сдвигает точку на +505 мм по Y — проверить своей точкой). Литералы — из `params.md` / protocol-spec §5-6, не из кода. Каждое блокирующее действие — под дедлайном.
- Красные сегодня: операции нет → `status == "error"`.

## REDS (`Services/device_hub/tests/test_robot_driver_v2_jobs_acceptance.py`)

1. `::test_enqueue_job_runs_cvt_job_on_v2` — `enqueue_job {x_mm: 300.0, y_mm: −250.0}` → `{"status": "ok", "queue_len": 1}`; за ≤ 15 с `rig.jobs()` — 1 событие, `x_mm == 300.0`, `y_mm == −250.0`; в событиях `op=CVT_JOB` и `DONE … op=CVT_JOB`; snapshot: `jobs_sent == 1`, `jobs_done == 1`, `jobs_failed == 0`, `queue_len == 0`.
2. `::test_place_rz_is_pick_rz_plus_turn` — укладка (450.0, −300.0, −90.0, доворот 30.0) → после DONE `TLM_RZ` (s16) == −700; задание без `place_*` → `TLM_X` 4500, `TLM_Y` −3000, `TLM_RZ` −1000.
3. `::test_e_capture_given_and_read_now` — `e_capture = E0 + 345` → `rig.jobs()[0]["ecap"] == E0 + 345`; без `e_capture` → `ecap` в [энкодер до вызова, энкодер после вызова].
4. `::test_pick_lead_mm_shifts_ecap_and_wraps_u32` — `params={"pick_lead_mm": 14.447}` (100 имп при `P_BELT_FACTOR` 14447): `e_capture = E0 + 345` → `ecap == E0 + 245`; `e_capture = 50` → сразу после события `CMD … op=CVT_JOB` этого задания `rig.read("CMD_SEQ", 5)[3:5] == [0xFFCE, 0xFFFF]` (−50 по модулю 2^32), ответ `ok`, исхода задания не ждать (ход по такому `ecap` — промах, это не предмет теста).
5. `::test_return_jobs_queue_and_run_as_programs` — два `return_job` подряд (`{350.0, −150.0, −90.0}`, `{300.0, −150.0, −90.0}`) → оба `ok`, `return_queue_len` 1 и 2; за ≤ 30 с `devices.state.<id>.program` `state == "done"` дважды, ни одного «робот занят программой»; `returns_done == 2`, `returns_failed == 0`, `return_queued == 0`.
6. `::test_job_in_flight_refuses_jog_and_program` — обёртка над `ModbusDevice`: `transaction(ops)` с записью `CMD_SEQ`, где второе слово == `OP["CVT_JOB"]` → взвести `entered`, ждать `release` (≤ 5 с), передать дальше; отдельно утвердить `entered.wait(5)`. В окне: `jog_hold {dir: 1, spd: 20}` в daemon-потоке, join 1.0 с → вернулся и равен `{"status": "error", "message": "робот выполняет задание"}`; `start_return(...)` → тот же литерал; в событиях нет `op=JOG_CONT`, `op=SC_RUN`. После `release` — DONE, `jog_hold` снова `ok`.
7. `::test_job_waits_for_jog_and_program` — jog держится (подтверждения 0.05 с) + `enqueue_job` → 0.6 с: нет `op=CVT_JOB`, `queue_len == 1`; `jog_release` → DONE ≤ 15 с. С программой (`start_return`, ход ≥ 1 с): `CVT_JOB` только после `.program` `done`.
8. `::test_heartbeat_continues_during_job` — `robot_params: {"P_WDG_TIMEOUT_MS": 600}`, задание с ходом ≥ 1 с → нет `E_WDG_TIMEOUT`, `jobs_done == 1`.
9. `::test_zone_trip_fails_job_and_queue_goes_on` — `x_mm: 0.0, y_mm: −50.0` (r 50 < 120) → `jobs_failed == 1`, `jobs_done == 0`, `last_error` == «Объект вышел из рабочей зоны ленты» (§6, errno 12); следующее допустимое → `jobs_done == 1`.
10. `::test_link_loss_during_job_then_reconnect` — без `pulse`: `drv.tick()` в daemon-потоке; после события `CMD … op=CVT_JOB` → `rig.restart(keep_regs=False)` → поток тика завершился ≤ 10 с; СРАЗУ после (до следующего тика) `drv.is_connected is False` и `jobs_failed == 1`; затем `pulse` — за ≤ 10 с `is_connected`, новое задание `jobs_done == 1`.

## Тесты автора (`test_robot_driver_v2.py`, после GREEN)

`stop_event` в `wait_done` → `stop(HARD)` + `jobs_failed`; `disconnect` при `_job_active` шлёт `HARD`; NAK `E_BUSY` → задание в начале очереди, `jobs_failed` прежний; бит0 при `z_mm` 0 / не 0; `job_queue_maxlen=2` — старейшее вытеснено (паритет H-1); `get_telemetry.queue_len`; `connect()` при `_job_active` — без `probe`/`sync_params`; недопустимые аргументы (`"abc"`, `nan`, `3300.0`) → ответ без входного значения, очередь не тронута; `ValueError` из `cvt_job` → без `_link_lost`; `_BUSY_*` из `_launch` → возврат в начало очереди; `P_BELT_FACTOR` ≠ 14447 (закрывает I13); программа возврата с отказом → `returns_failed` (закрывает I14); барьер на `wm` `JOG_CONT` при `_jog_starting` (закрывает I11a); на sim: `jog_hold {dir: 5, spd: 50}`, подтверждения каждые 0.05 с, дождаться `DONE … op=JOG_CONT` (край зоны, робот свободен), подтверждения не прекращать, `enqueue_job` → за 0.6 с нет `op=CVT_JOB`, `queue_len == 1`; после `jog_release` → `DONE … op=CVT_JOB` (закрывает I11b). Хотя бы один — на sim.
