- **Запрещено читать:** `T5.3e.6.md`, `robot/controller.py` ниже публичных имён (`RobotWidgetController`, `set_device`,

- **Правила:** ожидаемые значения — литералы; проверять видимое (текст `_lbl_status`, подпись телеметрии, доступность

- **Снимок статуса** (форма хаба): `{"quality": "good", "ts": <time.time()>, "stats": {...}, "queue_len": 0, "telemetry":
  {"x_mm": ..., "y_mm": ..., "z_mm": ..., "rz_deg": ..., "servo": True}, "free": ..., "encoder": ...}`.

## Критерии

- **A1.** Устройство `robot_main`. Два `merge` статуса подряд: `x_mm` 300.0, затем 310.0 (прочее то же, `ts` свежий) →
  подпись телеметрии содержит `X=310.0`.
- **A2.** Первый `merge` со `free: False`, второй — тот же снимок, но `free: True` (меняется только `free` и `ts`) →
  переключатель режима доступен, подпись телеметрии хранит `X=` первого снимка.
- **A3.** После `set_device("robot_2")` `merge` статуса `robot_main` с другим `x_mm` подпись телеметрии не меняет.
- **A4.** После `set_device("robot_2")` каждый паттерн, который `GuiStateBindings` передал в `ensure_subscription` для
  `robot_main`, передан и в `release_subscription`.
- **A5.** Статус сейчас — «Нет связи с hub…» (пуши прекратились дольше 3 с; время можно сдвинуть monkeypatch `time.time`
  модуля контроллера). Свежий `merge`: (а) итог «Остановить» до этого был «Робот дома, серво выключено.» → снова он;
  (б) итога не было → «Связь с роботом активна.».
- **A6.** Связь есть (был пуш). Клик по кнопке «Послать тест-job» (`widget.py:125`; не «Ехать» — это jog) пишет свой
  текст; следующий `merge` статуса этот текст не меняет.
- **A7.** «Остановить» → ответ `{"status": "ok", "accepted": True, "seq": 1, "timeout_s": 1}`, листьев `.park` нет →
  через 3,5 с после ответа статус ещё «Основная остановка принята: домой, затем серво OFF…»; не позже 4,6 с —
  «Основная остановка: итог не получен за 4 с. Проверьте робота.» Тот же сценарий с `"timeout_s": 1.5`: через 4,0 с
  текста срока нет; не позже 5,1 с — «Основная остановка: итог не получен за 5 с. Проверьте робота.»
- **A8.** Как A7, но до срока приходят листья `.park` `seq 1`, `state done`, `home moved` → через 4,6 с статус
  «Робот дома, серво выключено.».
- **A9.** Как A7, срок сработал; затем листья `.park` `seq 1`, `state failed`, `reason "срок вышел"` → «Основная
  остановка не выполнена: срок вышел.».
- **A10.** Как A7, но через 1 с после ответа `set_device("robot_2")` → через 4,6 с текста «итог не получен» нет.
- **A11.** Как A7; через 1 с второе «Остановить» получает отказ `{"status": "error", "message": "основная остановка уже
  идёт"}` → не позже 4,6 с от первого ответа статус «Основная остановка: итог не получен за 4 с. Проверьте робота.»
- **A12. Тёплый кэш.** До создания контроллера в стор и read-model уже ушли два снимка `robot_main` (`x_mm` 300.0, затем
  310.0, `free: True`). `set_device("robot_main")` → статус «Связь с роботом активна.», подпись телеметрии с `X=310.0`.
  Затем `merge` снимка, где изменился только `y_mm` → `X=310.0` на месте, переключатель режима доступен.
- **A13.** Как A7, но через 1 с после ответа `unbind()` контроллера → через 4,6 с текста «итог не получен» нет, исключений
  в слотах Qt нет.
