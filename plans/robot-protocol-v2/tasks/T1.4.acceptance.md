# T1.4 — приёмка для слепого тестера

## Вход

Контракт, против которого пишется `Services/robot_comm/tests/test_aparam_ranges_acceptance.py` (тесты падают до кода — это ожидаемо):
- `Services/robot_comm/protocols/delta_v2.yaml`: новый ключ `scenario.aparam` — имя действия (все из `scenario.actions`,
  кроме `NONE`) → `{min, max}` или `{param: <имя P_*>}`; у `ACCEL` — `{param: P_ACC_L}`.
- `Services.robot_comm.codegen.generate(root) -> dict[Path, str]` (тексты `core/protocol_v2.py`, `core/params_v2.py`; на диск
  не пишет; `root` — каталог, где лежит `Services/robot_comm/protocols/delta_v2.yaml`); `codegen.lua_block(root) -> str`.
- В сгенерированном `core/protocol_v2.py` — `ACT_RANGE: dict[str, tuple[int, int]]`: имя действия → `(lo, hi)` включительно,
  без `NONE`; `ACCEL` = `(min, max)` параметра `P_ACC_L`. Модуль без импортов — текст можно `exec` в пустом словаре.
- В Lua-блоке — таблица `ARNG`: ключ — код действия (как в `ACT`), значение — `{lo = …, hi = …}`.
- Потребители читают `Services.robot_comm.core.protocol_v2.ACT_RANGE` в момент проверки (подмена строки через
  `monkeypatch.setitem` действует сразу): `programs.Action(act=…, value=…)` (вне диапазона — `pydantic.ValidationError`);
  sim v2 — запись сценария вне диапазона → NAK `E_SC_RECORD [индекс, R_APARAM]`; `SC_RUN` стартовое `spd_pct`/`accel`
  (0 — «не задано», иначе в диапазоне действия) и `accur` (0 — «не задано», иначе диапазон ACCUR + 1) → NAK `E_RANGE [R_APARAM]`;
  `DO_SET` — канал в диапазоне `DO_ON`, иначе NAK `E_RANGE`.
Случаи (ожидаемые значения — литералы):
- A1. Настоящий YAML: `ACT_RANGE == {"DO_ON": (1, 16), "DO_OFF": (1, 16), "DELAY_MS": (0, 65535), "SPEED_PCT": (1, 100), "ACCEL": (100, 50000), "ACCUR": (0, 1)}`.
- A2. tmp-копия YAML, `SPEED_PCT.max: 50` и у `P_ACC_L` `min: 200, max: 40000` → `generate(tmp)` даёт `ACT_RANGE["SPEED_PCT"] == (1, 50)`,
  `ACT_RANGE["ACCEL"] == (200, 40000)`; остальные строки — как в A1.
- A3. Подмена `ACT_RANGE["SPEED_PCT"] = (1, 50)` → `Action(act="SPEED_PCT", value=51)` — ошибка, `value=50` — принят.
- A4. Та же подмена → sim v2: запись сценария с действием SPEED_PCT 51 → NAK `E_SC_RECORD`, rval1 = `R_APARAM`; 50 → ACK;
  `SC_RUN` с `spd_pct=51` → NAK `E_RANGE`, rval0 = `R_APARAM`. Подмена `DO_ON = (1, 8)` → `DO_SET` канал 9 → NAK `E_RANGE`, 8 → ACK.
- A5. `lua_block` настоящего YAML: в блоке есть `ARNG`; при наличии `lupa` — `ARNG[4].hi == 100`, `ARNG[5].lo == 100`,
  `ARNG[1].hi == 16`; без `lupa` — текстовая проверка, что `ARNG` стоит в блоке и `[5]` несёт `100` и `50000` (skip запрещён).
Тестеру можно читать: этот раздел; `codegen.py` — только докстроку модуля; `tests/e2e_rig_v2.py` и помощники
`tests/test_sim_v2_scenario.py` / `tests/test_sim_v2_core.py` (как строить sim и писать записи). Запрещено: остальной
`T1.4.md`, `programs/program.py`, `server/sim_core_v2.py`, тело `codegen.py`, тесты автора T1.4.
