# C-29 — проба: «Отключить» посреди ручного `connect` робота v2 (прогнозы до запуска)

Автор: teamlead полосы Р2 (лид inspector-bottles-d0), 2026-10-25. База: main `fcc1033b9`, ветка `fix/robot-v2-c29`.
Код продукта не меняется. Файл пробы: `Services/device_hub/tests/test_c29_probe.py`.

## Посылки лида — проверены чтением (main `fcc1033b9`)

1. Верно. `cmd_device_disconnect` (`plugin.py:873-886`) пишет False только в словарь плагина
   `self._desired_connected[dev_id]` под `_workers_lock` и ставит `("disconnect", dev_id)` в очередь. На драйвер
   `driver.desired_connected = False` пишет супервизор, взяв элемент из очереди (`plugin.py:447-451`). Крючка
   «`connect` видит отмену» в драйвере нет: шаги `connect` смотрят только `_stopping` / `_shutdown` состояния.
2. Верно. После `manager.connect` супервизор безусловно ставит `driver.desired_connected = True` и зовёт
   `reset_reconnect()` (`plugin.py:434-445`), даже если «Отключить» пришло, пока шёл `connect`.
3. Верно. `connect_end` (`state.py:323-327`) снимает `_connecting` и `_connect_linked` на любом выходе. Если
   `connect` прерван раньше, чем `disconnect` из очереди дойдёт до D2, снимок D2
   `(_stopping and _stop_linked) or (_connecting and _connect_linked and link_up())` даёт False при
   `_stopping` False — 0 SOFT, хотя связь была поднята. Снимок должен родиться в момент «Отключить», не в D2.
4. Сверх посылок: очередь супервизора одна на все устройства (ADR-DH-006). «Отключить» робота B ждёт и долгий
   `connect` робота A. Флаг драйвера от команды снимает и это ожидание для тика, но не для очереди.
