## Общие правила L1–L3 (автотест и стенд)

- **Готовность (C-57).** Ждать двух условий, дедлайн 20 с, шаг 0,05 с:
  - `state.get devices.state.robot_main.conn` → `value.conn == "connected"`; `t_conn = time.time()` в этот момент;
  - `state.get devices.state.robot_main.status` → `value.ts > t_conn` (`ts` — `time.time()` процесса `devices`,
    `drivers/base.py:214`; машина одна).
  - Ответы «Путь не существует», `No handler for key`, `timeout` — ждать дальше; число попыток — в отчёт.
  - `introspect.*` в сценариях park не звать.
- **Итог park.** Опрос `state.get devices.state.robot_main.park` до `value.seq == <seq ответа>` и `value.state in
  {"done", "failed"}`, дедлайн 40 с, шаг 0,05 с. По ответу команды итог не судить.
- **Счёт:** `d1` — записи `STOP_REQ` от начала сценария до конца прогона; `L1` / `A1` / `E1` — строки «робот
  'robot_main': jog остановлен поводком: окно удержания истекло» / «… поводком после начала остановки» / «…
  поводком: область закрывается» в логах бэкенда; SOFT — `значение & 3 == 1`.
- **L1.** Держатель шлёт `robot_jog_hold` каждые ≤ 0,1 с до возврата `process.stop`. Через 0,3 с после `moving is
  True` — `robot_park`; ждать итог; затем `process.stop`. PASS:
  - ответ ≤ 1,0 с, `accepted is True`;
  - итог `done`, `home == "moved"`, ≤ 30 с от ответа;
  - `jog_hold` после ответа ≥ 3, из них `ok` — 0;
  - `L1 == 0`, `A1 == 0`, `E1 == 0`;
  - `d1 == 2` (SOFT release и SOFT выключения простому роботу);
  - последняя запись `& 3 == 1`.
- **L2.** Первый park — **без jog** (робот вне дома, простой) до `done`; `robot_servo {on: true}`; второй `robot_park`.
  PASS: итог второго — `home == "already"` за ≤ 1,5 с от ответа; после `process.stop` `d1 == 1` (только SOFT
  выключения; park без jog и программы `STOP_REQ` не пишет); `L1 == 0`.
- **L3.** Идёт программа пользователя ≥ 3 хода, `robot_park`. PASS:
  - `.program` с `name` пользователя и `state == "aborted"` наблюдается раньше первого `.program` с `name == "park_home"`;
  - итог `done`, `home == "moved"`; `L1 == 0`, `A1 == 0`.
- **Повторы:** каждый сценарий — 3 прогона подряд, нужно 3/3.
- **В отчёт:** время ответа; `elapsed_s`; число тиков до итога (`elapsed_s / 0,5`); `d1`, `L1`, `A1`, `E1`; время от
  итога до `process.stop` и время самого `process.stop`; health `device_hub.stop_echo` после выключения (есть / нет);
  строки «поводок jog прерван».

**Правки копии:**
- **Пути (ловушка README).** `SPI.stand/README.md` называет worktree `…/.claude/worktrees/robot-v2-spi` — в копии везде
  `…/.claude/worktrees/robot-v2-t53e`. `run_stand.py` берёт worktree от своего места (`WORKTREE = HERE.parents[3]`,
  `:34`) — оставить; проверка «import из worktree» (`:637-638`) — оставить. `DEFAULT_STAND_ROOT` (`:37-39`) ведёт в
  scratchpad чужой сессии — заменить на `Path(tempfile.gettempdir()) / "t53e-stand"` (вне git), `--stand-root` оставить.
- **Сим.** Для сценариев park — `delay 0` с самого начала (полный `connect` при 300 мс идёт минуты). `sim_v2.py` — без правок.
- **Ключ `--scenario P1|P2|P3`** — один сценарий park на прогон: каждому нужен свой `process.stop` в конце. Прогон: старт
  → группа D → `device_connect` → готовность → сценарий (`mark P<n>` в журнал сима) → `system_shutdown` → `count.py`.
  `--repeats N` (умолчание 3) повторяет прогон целиком, каждый в своём `run-<время>/`.
- **P1 = L1.** Поток держателя в оркестраторе: `robot_jog_hold {device_id, dir, spd}` каждые 0,1 с до возврата
  `system_shutdown`; каждый ответ — строка `jog.jsonl` (`t`, `status`, `message`). `moving` — из `.status` телеметрии.
- **P2 = L2.** Перед park точка вне дома: `robot_jog_step` или `robot_point_save` + программа из одного хода (имена и
  аргументы — по `docs/contracts/CAPABILITIES.md`).
- **P3 = L3.** Точки и программа ≥ 3 ходов — через команды хранилища (`robot_point_save`, сохранение программы —
  имя сверить по `CAPABILITIES.md`), затем `robot_program_run`. Опрос `state.get devices.state.robot_main.program`
  каждые 25 мс → `program.jsonl` (поле `aborted` пользователя держится до запуска дома, ≥ 1 тика 0,5 с).
- **Итог и счёт** — новые файлы прогона: `park.jsonl` (опрос `.park`), `jog.jsonl`, `program.jsonl`. `d1` — `soft_sim`-
  подобный счёт `W STOP_REQ` в `sim.log` от `MARK P<n>` до конца, все уровни, плюс `& 3` последней записи. `L1`/`A1`/`E1`
  — счёт строк по `logs/**`, как `finish` (`run_stand.py:589`).
- **`count.py`:** таблица `P` с порогами из «Общих правил» — литералы в коде (`1.0`, `30.0`, `1.5`, `== 2`, `== 1`,
  `== 0`, `>= 3`); строка на критерий `PASS` / `FAIL` с фактом; итог `STAND: PASS` и код выхода 0 — только если все
  критерии PASS. По каталогу из `--repeats` — `3/3` или `k/3`.
- **Регрессия SPI.stand.** Каждый прогон — группа D (до связи). Отдельный прогон `--regress` (1 раз): S0, S1 и G — с
  прежними порогами `count.py` (≤ 1,23 с, SOFT 1/1, G — 1 SOFT). S2 и S3 не гоняются: они проверяют `sync_params`,
  который park не меняет, а S3 идёт до ~2,5 мин (`SPI.stand/README.md`, «Время»). Нужны — `--only S2,S3`.
- **README копии:** назначение (park L1–L3), команды, пороги, время прогона, что ненадёжно; раздел про `device_io`
