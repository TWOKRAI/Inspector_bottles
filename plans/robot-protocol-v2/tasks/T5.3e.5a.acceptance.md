## Поверхность вызова

- Менеджер: `DeviceManager.robot_park_all(args: dict, *, should_stop: Callable[[], bool] = lambda: False) -> dict`
  (`Services/device_hub/manager.py`). «Стоп процесса» на этом уровне = `should_stop()` становится истинным **и**
  драйвер робота получает `request_stop()`.
- Драйвер v2: `RobotDriverV2.park_wait(seq, timeout_s) -> dict | None`, `park_current_seq() -> int`; park оператора —
  `drv.call("park", {...})`. Значение `park_wait`: `None` (нет итога к сроку) или `{"seq": int, "state": "done" |
  "failed", "step": str, "home": "moved" | "already" | None, "servo": False | None, "dropped": {"jobs": int, "returns":
  int}, "reason": str | None, "elapsed_s": float | None}`. Стенд — `E2eRig` из `Services/robot_comm/tests/e2e_rig_v2.py`
  (импорт как в `Services/device_hub/tests/test_robot_v2_park_tick.py:37`), `FakeClock` — `Services/device_hub/tests/conftest.py:47`.
- Плагин: команда `robot_park_all` (`Plugins/hub/device_hub/plugin.py`), хук — `plugin.request_stop(ctx)`. Строки
  приёмки про исполнитель и хук — только на плагине с настоящим `CommandManager`: `Rig(tmp_path, monkeypatch,
  executors={"device_io": {}})` (без `executors` — для «нет исполнителя») и `RouterPath` из
  `Plugins/hub/device_hub/tests/test_spi_commands_acceptance.py` (классы импортировать; `make_rig` там — фикстура
  модуля, свою написать над `Rig`). `PluginTestBench` для них не годится: его менеджер команд — `MagicMock`.
- Порядок отказов команды: нет исполнителя → «идёт остановка хаба» → `timeout_s`.
- Блокирующие вызовы — daemon-поток + `join` с дедлайном.

## ACCEPTANCE 5a

- Команда `robot_park_all` зарегистрирована на исполнителе `device_io` для всех ключей; без исполнителя в процессе —
  `{"status": "error", "message": "robot_park_all: нет исполнителя device_io"}`, роботы не тронуты.
- Все роботы v2 дома: `{"status": "ok", "timeout_s": 30.0, "robots": {<id>: {"result": "done", "seq": k, "home":
  "moved" | "already", "elapsed_s": ...}}}`.
- `timeout_s` 0,5 / 33 / `true` / `"30"` → `{"status": "error", "message": "timeout_s: число от 1 до 32"}`, у роботов
  нет нового `seq` park.
- Робот без итога: при `timeout_s 1.0` ответ ≤ 2,9 с, `result "timeout"`, `status "error"`, `message` =
  `"основная остановка не выполнена: <id>"` (несколько id — по возрастанию, через `", "`).
- Робот v1 (подключён или нет) → `skipped/not_v2`; робот v2 без связи → `skipped/not_connected`; оба не тронуты;
  `status "ok"`.
- Идущий park оператора: ответ несёт его `seq`, `"joined": true`.
- Стоп процесса во время ожидания (нет идущей отправки, связь жива: стоп записан ≤ 0,5 с): ответ ≤ 1,0 с от момента,
  когда `should_stop()` стал истинным и драйвер получил `request_stop()` (опора: реакция ≤ 0,2 с + 0,5 с на итог +
  запас 0,3 с), `result
  "failed"`, `reason "драйвер робота останавливается"`. Стоп записан позже → `result "timeout"`, `status` тот же.
- Стоп процесса до отправки очередному роботу: ему и следующим `skipped/stopping`, `status "error"`.
- После хука плагина (вызов команды напрямую) — `{"status": "error", "message": "идёт остановка хаба"}`. Через
  настоящий роутер после закрытия приёма исполнителем ответ — отказ исполнителя `system_stopping`.
- Повтор `robot_park_all` после `done` → `home "already"`, `status "ok"`.
- **Стенд v2 (`T5.3e.stand/`, окно `stand`, новые сценарии P4, P5, `--repeats 3`):**
  - P4: `robot_jog_step dx=80` → `robot_park_all {}` → ответ `ok`, `robot_main` `done/moved` ≤ 3,0 с от отправки
    (опора — P1 0,687–0,714 с, `reports/T5.3e.stand.md:22`); второй `robot_park_all` → `already` ≤ 2,0 с (P2
    0,446–0,498 с); `d1` и `L1 == 0` — по правилам P2.
  - P5: `robot_jog_step dx=80` → `robot_park_all {}` в потоке → через 0,2 с `system_shutdown` → `.park` `robot_main`
    `failed`, `reason "драйвер робота останавливается"` ≤ 1,5 с от `system_shutdown`; в `logs/**` нет строки
    исполнителя «не остановлен к сроку» для `device_io`; `L1 == A1 == E1 == 0`. Ответ команды записать, если пришёл.
    Ход кончился раньше `system_shutdown` — событие `precondition_failed`, прогон не в счёт.
