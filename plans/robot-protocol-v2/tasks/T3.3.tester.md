DESIGN (decided by the lead — you type it, you do not derive it):
  1. Публичный API (импорт только `from Services.robot_comm.programs import ...`; модуля пока нет — импорт делать внутри фикстуры или хелпера, чтобы каждый тест собирался и краснел отдельно, а не падала сборка файла):
     - Все конструкторы — только именованные аргументы (Pydantic). Импорт — в хелпере `_api()`, который вызывается в теле теста (или фикстура `scope="module"`); function-фикстуры вместе с `@given` запрещены (hypothesis `FailedHealthCheck`).
     - `Point(name=..., x=..., y=..., z=..., rz=..., hand=0|1, frame=None|str)` — мм и °; `frame=None` — база.
     - `FrameDef(name: str, origin, on_x, in_plane)` — три точки в базе (тройки float): начало, точка на оси X, точка в плоскости XY. Методы `to_base(x, y, z, rz) -> (x, y, z, rz)` и `from_base(...)`. Ось Z СК смотрит вверх; RZ в базе = RZ в СК + угол оси X СК в базе.
     - Шаги: `Move(point: str, kind: str)` — `kind` ∈ `"LINE"`, `"LINE_PASS"`, `"JOINT"`; `Action(act: str, value: int)` — `act` ∈ `"DO_ON"`, `"DO_OFF"` (value — канал 1..16), `"DELAY_MS"` (мс 0..65535), `"SPEED_PCT"` (1..100), `"ACCEL"` (мм/с², 100..50000), `"ACCUR"` (0/1).
     - `Program(name: str, steps: tuple[...])`.
     - `compile_program(program, points: dict[str, Point], frames: dict[str, FrameDef], params: dict[str, float]) -> Scenario`; отказ — исключение `CompileError` с атрибутами `step` (индекс шага программы) и `reason` (int).
     - `Scenario.records` — кортеж записей с полями `x, y, z, rz, kind, action, aparam` (`kind` и `action` — те же строки-имена; `action == "NONE"` — без действия); `Scenario.step_of[i]` — индекс шага, породившего запись i. `Scenario.to_dict()` / `Scenario.from_dict(d)`.
  2. Поведение (protocol-spec §7): `Move` даёт ровно одну запись с координатами точки в базе. `Action` исполняется после прихода в точку: сливается в предыдущую запись, если у неё нет действия (`"NONE"`) и она не `"LINE_PASS"`; иначе — отдельная запись с теми же координатами, `kind == "LINE"`. Внутри одного `Move` порядок проверок: неизвестная точка или СК (0) → последний `Move` LINE_PASS (6) → точка (4) → рука (7) → отрезок (5). Коды причин (protocol-spec, строка «Коды причины»): 4 — точка вне зоны, 5 — отрезок LINE через мёртвую зону у оси J1, 6 — последняя точка LINE_PASS. Пишите их литералами, `REASON` не импортировать.
  3. Параметры — литералы в тесте (мм, °): `P_WS_R_MIN=100`, `P_WS_R_MAX=600`, `P_WS_Z_MIN=-150`, `P_WS_Z_MAX=0`, `P_WS_RZ_MIN=-360`, `P_WS_RZ_MAX=360`, `P_WS_ANG_MIN=-165`, `P_WS_ANG_MAX=165`, `P_WS_BOX_EN=0`, `P_WS_X_MIN=-600`, `P_WS_X_MAX=600`, `P_WS_Y_MIN=-600`, `P_WS_Y_MAX=600`, `P_HAND=1`. Все точки генераторов — с `hand=1`.
  4. Оракулы — свои, по тексту protocol-spec §7.3, не из кода под тестом: зона точки (кольцо, Z, RZ, сектор `atan2`, бокс) и расстояние от (0, 0) до XY-отрезка — аналитически. Для круга «туда-обратно» — плоские СК с известным поворотом: `origin = O`, `on_x = O + L·(cos θ, sin θ, 0)`, `in_plane = O + L·(−sin θ, cos θ, 0)`; θ ∈ [−179, 179]; ожидаемая точка в базе = `O + R(θ)·p`, RZ = `rz + θ` (локальный rz подбирается так, чтобы |rz + θ| ≤ 350).
  5. Свойства (одно свойство — один тест; `@settings(max_examples=200, deadline=None, derandomize=True)`):
     a. `test_roundtrip_planar_frames_within_005` — программа из `Move` по точкам в плоских СК (и в базе); записи берутся после `Scenario.from_dict(scenario.to_dict())`; для каждого `Move`-шага k его запись (единственная с `step_of == k`) совпадает с оракулом п.4 в базе, а обратный пересчёт оракулом даёт исходные x, y, z, rz точки — каждая координата ±0.05.
     b. `test_frame_to_base_from_base_identity` — случайная невырожденная СК (в том числе наклонная: |on_x − origin| ≥ 10; расстояние от in_plane до прямой origin→on_x ≥ 10; координаты в ±2000) и случайная точка: `from_base(to_base(p)) == p` и `to_base(from_base(q)) == q` с допуском 1e-6.
     c. `test_no_record_outside_zone` — точки из широкого бокса (часть в зоне, часть вне): если `compile_program` прошёл — каждая запись в зоне по оракулу; если какая-то точка программы вне зоны — `CompileError`.
     d. `test_in_zone_program_compiles` — пара к c (проверка достижимости): точки строго внутри (r 110..590, угол −160..160, z −140..−10), только `JOINT`: компиляция успешна, записей = числу `Move`.
     e. `test_out_of_zone_rejected_at_first_offending_step` — только `JOINT`, одна или несколько точек вне зоны: `reason == 4`, `step` = индекс первого `Move` с точкой вне зоны.
     f. `test_no_line_segment_through_dead_zone` — если компиляция прошла, для каждой пары соседних записей, где вторая LINE или LINE_PASS, расстояние от (0, 0) до XY-отрезка ≥ 100 по оракулу.
     g. `test_dead_zone_line_rejected_joint_allowed` — литералы: точки (200, 100, −50, 0) и (−50, −150, −50, 0) в базе (обе в зоне; прямая между ними проходит в 70.7 мм от оси): `Move JOINT, Move LINE` → `CompileError`, `reason == 5`, `step == 1`; `Move JOINT, Move JOINT` → успех.
     h. `test_index_map_bijective_on_moves` — случайные программы из `Move` и `Action` (первый шаг — `Move`, последний `Move` — не LINE_PASS): для каждого `Move`-шага ровно одна запись с этим `step_of`; `step_of` не убывает; каждая запись, у которой шаг — не `Move`, имеет `kind == "LINE"` и `action != "NONE"`; `len(records)` = число `Move` + число таких записей; последовательность `(action, aparam)` записей с `action != "NONE"` == последовательность `(act, value)` шагов `Action` (ни одно действие не потеряно); `Action` сразу после записи с `"NONE"` и `kind != "LINE_PASS"` новой записи не даёт; у каждой записи `"LINE_PASS"` `action == "NONE"`; `Action` сразу после записи `"LINE_PASS"` даёт новую запись `"LINE"` с теми же координатами.
     i. `test_last_record_never_pass` — любая успешно скомпилированная программа: последняя запись не LINE_PASS; программа, у которой последний `Move` — LINE_PASS (с 0, 1 и 2 действиями после него — три случая) → `CompileError`, `reason == 6`, `step` = индекс этого `Move`.
  6. Валидность по построению (a, h, успешная ветка i): точки в базе — из зоны d, rz −350..350; у соседних записей, где вторая LINE/LINE_PASS, r ≥ 110 и разница углов ≤ 20° (до оси ≥ 110·cos 10° ≈ 108.3); в генераторе h встречаются все три `kind`; такие тесты требуют успех компиляции, без `assume` и без перехвата `CompileError`.
