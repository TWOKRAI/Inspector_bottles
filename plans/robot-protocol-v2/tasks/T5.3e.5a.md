### DESIGN, часть 1 — форма ответа (решено — набрать, не выводить)

`{"status": "ok" | "error", "timeout_s": t, "elapsed_s": x, "robots": {<id>: R}}`; при `"error"` ещё `"message":
"основная остановка не выполнена: <id>, <id>"` (id по возрастанию). `"ok"` ⇔ у каждого `R` либо `result == "done"`,
либо `result == "skipped"` с `reason in {"not_connected", "not_v2"}`; роботов нет — `"ok"`, `robots: {}`. `R`:
- `{"result": "done", "seq": k, "home": "moved" | "already", "elapsed_s": e}`;
- `{"result": "failed", "seq": k, "step": s, "reason": r}`;
- `{"result": "timeout", "seq": k}` — терминала нет к сроку ожидания (park робота идёт дальше по своему сроку);
- `{"result": "skipped", "reason": "not_v2" | "not_connected" | "stopping" | "no_time"}` — робот не тронут;
  `stopping` — хук пришёл до его отправки, `no_time` — срок вышел до его отправки;
- `{"result": "refused", "message": m}` — `robot_park` отказал (кроме «park уже идёт»);
- `{"result": "error", "message": f"{type(exc).__name__}: {exc}"}` — исключение вызова.
Park, уже идущий (отказ «идёт основная остановка робота» = `TEXT_PARKING`), — присоединение: ждём текущий `seq`, в
`R` ещё `"joined": true`. Присоединённый park живёт по своему сроку (до 60 с, `texts.py:177`); хаб ждёт только свой
срок → `timeout` верен (S m1.3).
Отказы всей команды (роботы не тронуты): `timeout_s` не число, `bool`, вне `[1.0, 32.0]` → `{"status": "error",
"message": "timeout_s: число от 1 до 32"}`; хаб уже останавливается → `{"status": "error", "message": "идёт остановка
хаба"}`; команда без исполнителя (п.6) → `{"status": "error", "message": "robot_park_all: нет исполнителя device_io"}`.

### DESIGN, часть 2 — 5a1, Services

1. **`park.py` — итог для ждущих.** В `__init__` (`:75`): `self._done = threading.Condition(self._mlock)`,
   `self._terminals: dict[int, dict] = {}`. В `_finish_locked` (`:307-332`) после сборки `value` и **до**
   `self._publish(value)`: `self._terminals[seq] = dict(value)`; больше 8 записей — удалить наименьший ключ;
   `self._done.notify_all()`. Причины: до публикации — сбой `publish` не отнимает итог (при сбое `_on_error` зовёт
   `_finish_locked`, `park_end` проигрывает — без этой записи итог потерян, O «проверено»); 8 — ждущий живёт ≤ 33,5 с,
   8 терминалов одного робота за это время — 8 принятых команд park, на деле 1–2; переполнение даёт `timeout`,
   безопасная сторона. Все вызовы `_finish_locked` — под `_mlock` (сверено O: `:113, :125, :143, :161, :181, :250,
   :258, :273, :344`). Новый `wait_terminal(self, seq: int, timeout_s: float) -> dict | None`: `with self._done:
   self._done.wait_for(lambda: seq in self._terminals, timeout=max(0.0, timeout_s))`, копия или `None`. Время —
   реальное, не `self._clock`. Докстрока модуля `Public API` (`:9`) — дополнить.
2. **`driver.py`** рядом с `call` (`:645`): `park_current_seq(self) -> int` → `self._state.park_view().seq`;
   `park_wait(self, seq: int, timeout_s: float) -> dict | None` → `self._park.wait_terminal(seq, timeout_s)`. Тик,
   `call`, `_op_park` (`ops.py:136-167`) не меняются.
3. **`manager.py` — `robot_park_all(self, args: dict, *, should_stop: Callable[[], bool] = lambda: False) -> dict`.**
   Литералы: `_PARK_ALL_DEFAULT_S = 30.0`, `_PARK_ALL_MIN_S = 1.0`, `_PARK_ALL_MAX_S = 32.0`, `_PARK_ALL_GRACE_S = 1.5`
   (тик 0,5 с + длительность: срок park замечает первый тик после него), `_PARK_ALL_STOP_GRACE_S = 0.5` (ответ ≤ 1,0 с
   после хука, чтобы не съесть окно join исполнителя W ≈ 3 с; на медленной связи запись стопа до 2,0 с,
   `stop.py:113-116`, — тогда `timeout` вместо `failed`, `status` тот же — принято, O m2 / S m6),
   `_PARK_ALL_SLICE_S = 0.2` (задержка реакции на `should_stop`: 0,2 + 0,5 < 1,0). Импорт — прямой:
   `from Services.device_hub.drivers.robot_driver_v2.texts import TEXT_PARKING` (слой тот же, `kinds.py:27` уже тянет
   драйверы; `sentrux check .` в Gate; запасного пути нет, S m3). Тип драйвера для проверки типов — `cast` к
   `RobotDriverV2` под `TYPE_CHECKING`.
   - `t0 = time.monotonic()`; `should_stop()` → отказ «идёт остановка хаба». `t = args.get("timeout_s", 30.0)`;
     `isinstance(t, bool) or not isinstance(t, (int, float)) or not (1.0 <= t <= 32.0)` → отказ. Прочие ключи — игнор.
     `deadline = t0 + t + 1.5`.
   - **Признак v2 — из записи реестра** (O M1 / S m3; образец `robot_data`, `manager.py:543`): обход
     `snapshot_registry()` с `entry.kind == "robot"` по возрастанию `entry.id` (порядок отправки и `message`
     детерминированы). `entry.protocol != "delta_v2"` → `skipped/not_v2` (до проверки связи); `drv =
     self.get_driver(id)`; `drv is None or not drv.is_connected` → `skipped/not_connected`. **Ни `getattr`, ни `hasattr`
     к драйверу** — сторож `test_spi_contract.py:649-653`.
   - **Отправка (S m2 / O M2):** перед каждым роботом — `should_stop()` → этому и следующим `skipped/stopping`,
     `deadline = min(deadline, now + 0.5)`, к ожиданию; `now >= deadline` → этому и следующим `skipped/no_time`.
     Иначе `r = drv.call("park", {"timeout_s": float(t)})` на **том же** `drv` (O m3: `self.call` берёт драйвер заново,
     `manager.py:510-528`; `device_upsert` между ними увёл бы `seq` к другому автомату), в `try` (исключение → `error`);
     `r.get("accepted") is True` → ждать `r["seq"]`; `r.get("message") == TEXT_PARKING` → `seq =
     drv.park_current_seq()`, ждать, `joined`; прочий отказ → `refused` с `r.get("message")`.
   - **Ожидание (S m1 / O m1):** пока есть ждущие и `now < deadline` — для каждого ждущего: сначала `should_stop()`
     (стал истинным → `deadline = min(deadline, now + 0.5)`), затем `v = drv.park_wait(seq, min(0.2, deadline - now))`;
     `v` есть → `R` (`done` → `done/seq/home/elapsed_s`, `failed` → `failed/seq/step/reason`). После цикла —
     **завершающий проход** `drv.park_wait(seq, 0.0)` по всем оставшимся; без итога → `timeout`.
   - `_registry_lock` во время отправки и ожидания не держать. Не бросает.
4. **Не менять:** шаги `ParkMachine`, `RobotState`, `spi.py` (операции драйвера нет), `request_stop_all*`.
