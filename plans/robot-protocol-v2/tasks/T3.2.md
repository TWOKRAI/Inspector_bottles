  1. Кодировщик — новый модуль `Services/robot_comm/programs/wire.py`, чистые функции, без транспорта:

     - `encode_scenario(scenario, *, params, round_step) -> tuple[tuple[int, ...], ...]` — на запись 6 слов по
       §7.1: X, Y, Z, RZ = `round_half_away(quantize(v, round_step) * WIRE_SCALE)` (знаковые, `W_MIN..W_MAX`),
       OP = `KIND[kind] + 256 * ACT[action]`, APARAM как есть;

  2. `ClientV2Config.round_step: float` — по умолчанию шаг провода (0.1). Валидатор: `round_step` ≥ шага провода и кратен
     ему (`abs(round_step * WIRE_SCALE - round(round_step * WIRE_SCALE)) <= 1e-9`), иначе `ValueError`, в тексте —
     `round_step`, значение и шаг провода. 0.05 и 0.15 — ошибка; 0.1, 0.2, 0.5 — допустимы.
  3. Обёртки — методы `RobotClientV2`, по одной на опкод `OP`, аргументы в порядке `OP_SPEC`; таблица класса

  4. `upload(records, offset)`: проверка до записи (`ValueError`): каждая запись — `SC_STRIDE` слов, `0 <= offset`,

     `SC_BASE + offset * SC_STRIDE`, по порядку, тем же путём записи, что `cmd()` (ошибка транспорта — `_stale` и
     наружу). `_mailbox_lock` не берёт. `SC_BASE`, `SC_STRIDE`, `SC_CAP`, `WRITE_CHUNK` читаются из `CONSTANTS` в
     момент вызова — без копий в модуле или экземпляре (на этом стоит тест порчи адреса).
  5. `wait_done(seq, *, on_poll=None)`: семантика T3.1 не меняется; после каждого чтения блока TLM (32 слова с
