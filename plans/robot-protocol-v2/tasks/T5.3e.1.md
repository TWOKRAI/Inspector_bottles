### D2. `state.py` (`RobotState`, 1a)

Поля: `_parking`, `_parked`, `_park_seq` (0), `_park_cancel` (`str | None`), `_program_kind` (`str | None`),
`_park_home_outcome` (`str | None`). Докстрока класса: 28 → 34 поля. **`view()` и `RobotStateView` не меняются** (23
поля, сторож `test_robot_v2_state_acceptance.py:553`, Opus m1): поля park видны только через `park_view()`.
Каждый переход — одна секция замка состояния, замок листовой, ввода-вывода нет.

- `park_begin() -> ParkBegin` (dataclass: `refusal`, `seq`, `run`, `prog_soft`). Отказы по порядку: `_shutdown` или
  `_stopping` → `TEXT_STOPPING`; `_disconnect_requests` → `TEXT_DISCONNECTING`; `_parking` → `TEXT_PARKING`;
  `_syncing` → `TEXT_SYNCING`. Допуск: `_parking = True`, `_park_seq += 1`, `_park_cancel = None`,
  `_park_home_outcome = None`; `_parked` не трогается. В той же секции, если `_holding_locked()`, — пометки release
  (тело `jog_release_begin`, `state.py:720-732`: `released`, `stop_requested`, `wake.set()`, `_jog_stopping = True`),
  `run` → вызывающему; поводок выходит по `"released"` (`state.py:742-743`). `prog_soft = _program_active and
  _program_kind == "program"` (В-1).
- `jog_started(run)` (`state.py:694-702`) возвращает `self._stopping or self._parking` (Opus M2, Sonnet m-3). Окно:
  `jog_hold_admit` поставил `_jog_starting`, JOG_CONT в полёте, пришёл `park_begin` (держащегося jog ещё нет, пометок
  нет). Возврат «стоп» ведёт `jog.py` путём H-B (`jog.py:72-86`): `jog_aborted_by_stop`, свой SOFT этого seq, поток
  поводка не запускается, ответ `jog_hold` — `TEXT_STOPPING`. `jog.py` не меняется; докстроку `jog_started` дополнить.
- `park_end(seq, ok) -> tuple[bool, int, int]` — сравнить-и-поставить: не `_parking` или `_park_seq != seq` →
  `(False, 0, 0)`. Иначе `_parking = False`; **`if ok: _parked = True`** (при `ok == False` `_parked` не трогается,
  Opus m3); очереди заданий и возвратов снять → `(True, jobs, returns)`.
- `park_cancel(reason)`: при `_parking` и `_park_cancel is None` — запомнить причину.
- `park_view() -> ParkView` (frozen dataclass): `parking`, `parked`, `seq` (`_park_seq`), `cancel`, `shutdown`,
  `disconnecting` (`_disconnect_requests > 0`), `job_active`, `program_active`, `program_kind`, `jog_busy`
  (`_jog_starting or _jog_stopping or (run is not None and run.active)`), `home_outcome`.
- `servo_on_done()`: `_parked = False`. **`_connect_reset_locked` не трогает ни `_parked`, ни `_parking`** (Opus m5):
  авто-реконнект после park не снимает запрет движения.
- Отказы `_PARKING` / `_PARKED` — сразу после проверки `_disconnect_requests` (порядок C-29): `jog_hold_check`,
  `jog_hold_admit`, `admit_launch` (вид не `"park"`), `take_next_action` (молча `(None, None)`), `disconnect_refusal`
  (её зовут `enqueue_job`, `return_job`, `jog_step`). Только `_PARKING`: `motion_refusal` (servo, DO), `connect_begin`
  (`"busy"`, Opus N1 ред. 2), `param_refusal` → `TEXT_PARKING` (Opus m4: `P_HOME_*` не меняется посреди park).
  `begin_sync()` при `_parking` → False.
  - Проверка в `jog_hold_check` — только ранний отказ без `_jog_tx_lock`; гарантию даёт `jog_hold_admit` (Opus M3:
    после `park_begin` `_holding_locked()` ложно, admit отказывает тем же текстом). Отдельной инъекции у неё нет.
- `_activity_alive_locked` (`state.py:252`) `_parking` НЕ учитывает (Opus N1 ред. 2). Это не изменение, а запрет.
- `admit_launch(connected, *, kind="program", park_seq=None)`: при допуске `_program_kind = kind`. При `kind ==
  "park"` проверки `_parking` / `_parked` пропускает, но после `_disconnect_requests` отказывает `_PARKING`, если не

### D5. `park.py` (новый, 1a) — `ParkMachine`, единственный писатель `.park`

- Класс драйвер не импортирует. Конструктор: `state`, `clock`, `publish(dict)`, `home_point()`, `launch_home(seq) ->
  dict`, `servo_off() -> bool`, `heartbeat()`, `record_err()`, `log_id`. Свой замок **`_mlock`** (имя `_lock` совпало бы с
  `log._lock` в `test_exchange_log.py:706-707` и сломало `_SEAMS`, Opus M7). Порядок: `_mlock` → замок состояния. Под
  `_mlock` — переход и одна публикация; `launch_home`, `servo_off`, `heartbeat` — вне `_mlock`.
- Поля: `_active` (False), `_seq` (0), `_t0`, `_deadline`, `_step`, `_launched`, `_home`, `_last_pub`.
- **Жизненный цикл (Opus M1, Sonnet M-2, m-9).** Холостое состояние — `_active is False`.
  - `accept(seq, timeout_s)`: под `_mlock` — `v = state.park_view()`; не (`v.parking and v.seq == seq`) → выход (park
    уже закрыт `abort` / `fail`). Иначе сброс всех полей: `_active = True`, `_seq = seq`, `_t0 = clock()`, `_deadline =
    _t0 + timeout_s`, `_step = "activity"`, `_launched = False`, `_home = None`, `_last_pub = None`; публикация
    `parking` / `activity`.
  - `guard(connected)` и `step(...)` первым делом под `_mlock`: `not _active` → выход; `v = park_view()`; не
    (`v.parking and v.seq == _seq`) → `_active = False`, выход (устаревший шаг, без записи).
  - Перед и после каждого вызова вне `_mlock` автомат запоминает `seq = _seq` и после возврата сверяет `_active and
    _seq == seq`; не совпало → выход без публикации (Opus M1 п. 4). Непрерывная публикация только под `_mlock` и при
    `_active`.
  - `fail(seq, reason)` — `_finish(seq, False, reason)` (исключение `_op_park` до `accept`).
  - `abort(reason)` (из `request_stop`, `disconnect`, `_link_lost`): `v = park_view()`; `v.parking` →
    `_finish(v.seq, False, reason)`. Закрывает и park, ещё не принятый автоматом.
  - `_finish(seq, ok, reason)`: под `_mlock` — `won, jobs, returns = state.park_end(seq, ok)`; не выиграл → выход без
    записи. Выиграл → при `_seq == seq` `_active = False`; терминальная публикация (`elapsed_s` от `_t0`, если `_seq ==
    seq`, иначе `None`; `step` — текущий или `"activity"`), одна `logger.info` (`done`) или `logger.warning` (`failed`);
    `dropped` не пуст → ещё `logger.warning(TEXT_PARK_DROPPED)`.
- **Причины** (`_reason(v, connected)`, одна функция для `guard` и начала `step`, Opus m2), первая сработавшая:
  `v.shutdown` → **замереть**: выход без записи и без шага, терминал ставит `abort(TEXT_STOPPING)` из `request_stop`
  после записи стопа (Sonnet m-1); `v.disconnecting` → `TEXT_DISCONNECTING`; `v.cancel`; не `connected` →
  `TEXT_PARK_LINK`; `clock() > _deadline` → `TEXT_PARK_TIMEOUT`. Причина есть → `_finish(_seq, False, reason)`.
- `guard(connected)` — тик, первой строкой. `step(telemetry, free)` — после разбора TLM и `poll_errors`, до
  `_dispatch`. Без циклов ожидания и `sleep`: идёт до первого ожидания и выходит.
  - `activity`: ждать, пока `v.job_active`, `v.jog_busy` или `v.program_active`. Программы видов `"return"`,
    `"toolchange"` доезжают сами.
  - `idle`: ждать `free`.
  - `home`: поза в допуске `home_point()` → `_home = "already"`, шаг `servo`. Иначе `r = launch_home(seq)` вне
    `_mlock`; `r["message"] in _PARK_RETRY` → повтор следующим тиком; прочий отказ → `_finish(seq, False,
    r["message"])`; запуск прошёл → `_launched = True`, ждать `not v.program_active`. Исход `v.home_outcome`: `done` и
    поза в допуске → `_home = "moved"`; `done` без позы → `TEXT_PARK_NOT_HOME`; `aborted` → `TEXT_PARK_HOME_ABORTED`;
    `failed` или `None` → `TEXT_PARK_HOME_FAILED`.
  - `servo`: `heartbeat()`, `ok = servo_off()`, `heartbeat()` вне `_mlock`. `ok is False` (выключение) → выход, итог
    ставит `abort`. Иначе `_finish(seq, True, None)`. Устаревший `servo_off` (seq закрыт `abort` и начат новый) даёт
    ≤ 1 запись `SERVO 0` в безопасную сторону; новый seq тогда находит робота дома (`already`).
  - Исключение в `guard` или `step` → `record_err()`, `logger.warning`, `_finish(seq, False, f"{type}: {exc}")`.
- Срок шага `home` вышел → `failed`, программа дома доезжает сама, серво остаётся ON. SOFT не пишется: SOFT посреди
  хода `run_chunks` превращает в `RobotAborted` (`client_v2.py:1110-1124`), робот всё равно доезжает.

## Ловушки

- Замок `RobotState` не реентерабельный: `connected()` зовётся под ним (как `admit_launch`).
- `_op_jog_release` зовёт `_close_thread` — замков не держать.
- Порядок замков: `_mlock` → замок состояния; `_jog_tx_lock` под `_mlock` не брать; `servo_off` / `launch_home` вне `_mlock`.
- `FakeClock.sleep` двигает время без паузы: `_await_tlm` при `connect` (`driver.py:413-423`) крутится без ожидания; на
  `E2eRig` серво уже ON — проходит. Ход сима и поток поводка идут реальным временем: ждать `bounded(...)` из
  `e2e_rig_v2.py`, а окно поводка двигать `fake_clock.t += ...`.
- `.park` и `.program` публикуются `merge` — в сторе дельты по листьям; тесту на рекордере `publish` это не мешает.
