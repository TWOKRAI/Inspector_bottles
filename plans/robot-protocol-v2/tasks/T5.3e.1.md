## DESIGN (решено лидом — набрать, не выводить)

Шаги «конца текущей команды / цикла» — `T5.3e.analysis.md` §В2 (таблица). Ниже — где и как они исполняются при В2.

### D1. `texts.py`

Тексты: `TEXT_PARKING = "идёт основная остановка робота"`, `TEXT_PARKED = "робот остановлен: включите
серво"`, `TEXT_PARK_TIMEOUT = "срок вышел"`, `TEXT_PARK_LINK = "связь с роботом потеряна"`,
`TEXT_PARK_CANCELLED = "прервано стопом оператора"`, `TEXT_PARK_HOME_ABORTED = "ход домой прерван"`,
`TEXT_PARK_HOME_FAILED = "ход домой не выполнен"`, `TEXT_PARK_NOT_HOME = "после хода робот не дома"`,
`TEXT_PARK_DROPPED = "основная остановка: сняты задания: {jobs}, возвраты: {returns}"`. Словари `_PARKING`,
`_PARKED` добавить в `_BUSY_REPLIES` (`texts.py:139`): возврат, снятый тиком до `park_begin`, вернётся в очередь, а не
пропадёт (Opus m3). Числа: `_PARK_TIMEOUT_DEFAULT_S = 30.0`, `_PARK_TIMEOUT_MIN_S = 1.0`, `_PARK_TIMEOUT_MAX_S = 60.0`,
`_HOME_TOL_MM = 0.5`, `_HOME_TOL_DEG = 0.5`. Все — в `__all__`.

### D2. `state.py` (`RobotState`)

Поля: `_parking`, `_parked`, `_park_seq` (0), `_park_cancel` (`str | None`),
`_program_kind` (`str | None`), `_park_home_outcome` (`str | None`). Переходы, каждый — одна секция замка состояния:
- `park_begin() -> ParkBegin` (dataclass: `refusal`, `seq`, `run`, `prog_soft`). Отказы по порядку: `_shutdown` или
  `_stopping` → `TEXT_STOPPING`; счётчик «Отключить» → `TEXT_DISCONNECTING`; `_parking` → `TEXT_PARKING`; `_syncing` →
  `TEXT_SYNCING`. Допуск: `_parking = True`, `_park_seq += 1`, `_park_cancel = None`, `_park_home_outcome = None`. В ТОЙ
  ЖЕ секции, если есть свой держащийся jog, — пометки release (тело `jog_release_begin`, `state.py:720-732`:
  `released`, `stop_requested`, `wake.set()`, `_jog_stopping = True`), `run` → вызывающему. Так поводок выходит по
  `"released"` (`state.py:739-741`) без своего SOFT (ревью: Opus M1, Sonnet М18). `prog_soft = _program_active and
  _program_kind == "program"` (решение В-1: программа возврата и смены инструмента доезжает).
- `park_end(seq, ok) -> tuple[bool, int, int]` — сравнить-и-поставить: не `_parking` или `_park_seq != seq` → `(False,
  0, 0)`. Иначе `_parking = False`, `_parked = ok`, очереди заданий и возвратов снять → `(True, jobs, returns)`.
- `park_cancel(reason)`: при `_parking` и `_park_cancel is None` — запомнить причину.
- `park_view() -> ParkView` (dataclass, только чтение): `parking`, `seq`, `cancel`, `shutdown`, `disconnecting`,
  `job_active`, `program_active`, `program_kind`, `jog_busy` (`_jog_starting or _jog_stopping or run.active`, Sonnet М6),
  `home_outcome`.
- `servo_on_done()`: `_parked = False`. `_connect_reset_locked` снимает `_parked` и не трогает `_parking`.
- Отказы `_PARKING` / `_PARKED` ставятся сразу после проверки `_disconnect_requests` (порядок C-29). Точки:
  `jog_hold_check`, `jog_hold_admit`, `admit_launch`, `take_next_action` (молча None), `disconnect_refusal` (её зовут
  `enqueue_job`, `return_job`, `jog_step`). Только `_PARKING` — в `motion_refusal` (servo, DO) и в `connect_begin`
  (отказ «busy», Opus N1). `begin_sync()` при `_parking` → False: ресинхронизация не перепишет `P_HOME_*` посреди park
  (Opus m2).
- `_activity_alive_locked` (`state.py:252`) `_parking` НЕ учитывает: иначе без связи park и реконнект ждут друг друга
  (Opus N1, Sonnet Н2).
- `admit_launch(connected, *, kind="program", park_seq=None)`: ставит `_program_kind = kind`. При `kind == "park"`
  проверки `_parking` / `_parked` пропускает, но отказывает `_PARKING`, если не (`_parking` и `_park_seq == park_seq`
  и `_park_cancel is None` и не `_shutdown`). Это закрывает окно «park прерван → дом всё же запущен» (Opus M5).
  Прочие вызовы — с умолчанием (`programs.py:45`, тесты `test_robot_v2_ops.py:304`,
  `test_robot_v2_state_acceptance.py:120` не меняются, Sonnet М8).
- `program_finished(kind, done, outcome=None)`: при `kind == "park"` пишет `_park_home_outcome = outcome`
  (`"done" | "aborted" | "failed"`). Счётчики возвратов — как раньше (Opus M3, Sonnet М3).
- Замок листовой, ввода-вывода под ним нет. Счёт полей в докстроке класса обновить.

### D3. `programs.py`

`_launch(..., kind, park_seq=None)` передаёт `kind`, `park_seq` в `admit_launch`.
`_program_loop` в `finally` зовёт `program_finished(kind, state["state"] == "done", state["state"])`. Новый
`start_park_home(seq) -> dict`: `Program(name="park_home", steps=[Move(point="home", kind="JOINT")])`, точки `{"home":
self._home_point()}`, затем `_launch(..., kind="park", park_seq=seq)`. Конструктор `Program` / `Move` сверить с
`Services/robot_comm/programs/program.py`. `start_toolchange` (`programs.py:71-77`) запускает с `kind="toolchange"`
(сейчас идёт видом `"program"` через `start_program`) — иначе смена инструмента получила бы SOFT вопреки В-1.

### D4. `ops.py` — команда, поток команды

- `_op_park(args)`: `timeout_s` — из аргумента, иначе `entry.params["park_timeout_s"]`, иначе 30,0. Вне `1.0 <= t <=
  60.0` → `{"status": "error", "message": "неверные аргументы команды робота"}`, робот не тронут.
- Затем `park_begin()`; отказ возвращается как есть. После допуска — `self._park.accept(seq, t)`. В `.park` команда
  НЕ пишет: писатель один — автомат (D5).
- Есть `run` → тело `_op_jog_release` после `jog_release_begin`: `_close_thread(handle, _LEASE_JOIN_S)` вне замков, затем
  `_stop_jog(run)` и в `finally` — `jog_release_done()`.
- `prog_soft` → `self._write_stop(STOP_LEVEL["SOFT"])` (тело `program_abort`, В-1).
- Исключение в release или SOFT → `self._park.abort(f"{type(exc).__name__}: {exc}")`, ответ — ошибка.
- Ответ: `{"status": "ok", "accepted": True, "seq": seq, "timeout_s": t}`.
- `_operator_stop` после удачной записи зовёт `park_cancel(TEXT_PARK_CANCELLED)` (М5 Opus). `_op_servo` при `on: true`
  после удачной записи зовёт `servo_on_done()`. Строка `OPS["park"] = OpsMixin._op_park` — в блоке T5.3d.

### D5. `park.py` (новый) — `ParkMachine`, единственный писатель `.park`

- Отдельный класс, драйвер не импортирует. Конструктор: `state`, `clock`, `publish(dict)`, `home_point()`,
  `launch_home(seq) -> dict`, `servo_off()`, `heartbeat()`, `record_err()`, `log_id`. Свой замок `_lock`; порядок замков —
  `ParkMachine._lock` → замок состояния. Под `_lock` — только переход и одна публикация (без ввода-вывода робота).
- Поля: `_seq`, `_t0`, `_deadline`, `_step`, `_home`, `_launched`, `_last_pub` (последнее `(state, step)`).
- Форма значения: `{"seq": int, "state": "parking"|"done"|"failed", "step": "activity"|"idle"|"home"|"servo",
  "home": "moved"|"already"|None, "servo": False|None, "dropped": {"jobs": int, "returns": int}|None,
  "reason": str|None, "elapsed_s": float|None}`. Путь появляется с первым park; значения `idle` нет. Терминальные —
  `done` и `failed`. `parking` пишется при смене `(state, step)`, не каждый тик.
- `accept(seq, timeout_s)` — только запоминает: `_seq`, `_t0 = clock()`, `_deadline`, `_step = "activity"`.
- `guard(connected)` — тик, первой строкой, до раннего выхода. Причина — первая сработавшая, в этом порядке (Sonnet
  М9): `shutdown` → `TEXT_STOPPING`; `disconnecting` → `TEXT_DISCONNECTING`; `cancel`; не `connected` →
  `TEXT_PARK_LINK`; `clock() > _deadline` → `TEXT_PARK_TIMEOUT`. Причина есть → `_finish(False, reason)`.
- `step(telemetry, free)` — тик, после разбора TLM, до `_dispatch`. Без циклов ожидания и `sleep`: автомат идёт до
  первого ожидания и выходит (Opus N4, Sonnet Н3).
  - `activity`: ждать, пока `job_active`, `jog_busy` или `program_active`. Программы видов `"return"`, `"toolchange"` и `"park"`
    доезжают сами (Opus M4).
  - `idle`: ждать `free`.
  - `home`: поза в допуске `_home_point()` → `home = "already"`, шаг `servo`.
  - Иначе `launch_home(seq)`. Отказ занятости (`_BUSY_*`, `TEXT_SYNCING`) — повтор на следующем тике (Sonnet М6). Прочий
    отказ → `_finish(False, message)`. Запуск прошёл → `_launched`, ждать `not program_active`. Исход
    `home_outcome`: `done` и поза в допуске → `home = "moved"`; `done` без позы → `TEXT_PARK_NOT_HOME`; `aborted` →
    `TEXT_PARK_HOME_ABORTED`; `failed` → `TEXT_PARK_HOME_FAILED`.
  - `servo`: `heartbeat()`, `servo_off()`, `heartbeat()` (Sonnet Н5), затем `_finish(True, None)`.
  - Исключение в шаге → `_finish(False, f"{type}: {exc}")`, `record_err()`, `logger.warning` (Sonnet Н7).
- `abort(reason)` — из `request_stop`, `disconnect`, сбоя команды: `_finish(False, reason)`.
- `_finish(ok, reason)`: под `_lock` — `state.park_end(_seq, ok)`. Проиграл сравнение → выход без записи. Выиграл →
  терминальная публикация, одна `logger.info` (`done`) или `logger.warning` (`failed`). `dropped` не пуст → ещё
  `logger.warning(TEXT_PARK_DROPPED)`.
- Срок шага `home` вышел → `failed`, программа дома доезжает сама, серво остаётся ON. SOFT не пишется: SOFT посреди
  хода ждёт прибытия, для программы из одного хода он ничего не меняет.

## ACCEPTANCE (литералы; модульно — вызовами `drv.tick()` при `FakeClock`, без реального периода)

Robot id в модульных тестах — любой, на стенде — `robot_main`. «Итог» — последнее значение `.park` с `seq` ответа.
- А1. Робот вне дома, простой.
  - Ответ ровно `{"status": "ok", "accepted": True, "seq": 1, "timeout_s": 30.0}`.
  - 1-й `tick()` → `.park` `{"seq": 1, "state": "parking", "step": "home", ...}`, `.program.name == "park_home"`.
  - 1-й `tick()` после `.program.state == "done"` → итог `state == "done"`, `home == "moved"`, `servo is False`.
  - Запись `SERVO 0` в журнале обмена позже публикации `.program` `done` для `park_home` (Opus M6). Серво сима ON, пока
    `.program.state == "running"`.
  - Записей `STOP_REQ` за park — 0.
- А2. Робот дома — сначала А1 до `done`, затем `robot_servo {on: true}`, потом второй `robot_park`: итог `done`,
  `home == "already"` после 1-го `tick()`, `.program` не менялся.
- А3. Jog держится (держатель `jog_hold` каждые 0,1 с, после ответа park ≥ 3 посылок).
  - Ответ park приходит ≤ 0,5 с.
  - Ровно 1 запись `STOP_REQ` SOFT до 1-го `tick()`.
  - Строк «jog остановлен поводком» — 0 при паузе 0,3 с перед 1-м `tick()`.
  - Все `jog_hold` после ответа: `status == "error"`, `message` — «идёт основная остановка робота» или «робот остановлен:
    включите серво».
- А4. Программа пользователя (≥ 3 хода) идёт.
  - В записи публикаций `.program` (рекордер `publish` рига) `{name: <пользователя>, state: "aborted"}` идёт раньше
    `{name: "park_home", state: "running"}`.
  - Итог `done`, `home == "moved"`.
- А5. После `done`:
  - `robot_program_run`, `robot_jog_step`, `robot_enqueue_job`, `robot_jog_hold` отвечают
    `message == "робот остановлен: включите серво"`;
  - `robot_servo {on: true}` → `ok`, затем `robot_jog_step` → `ok`.
- А6. `request_stop()` во время хода домой (вызов в своём потоке, `deadline = monotonic() + 2.5`).
  - К возврату `request_stop`: итог `failed`, `step == "home"`, `reason == "драйвер робота останавливается"`.
  - `STOP_REQ` HARD записан раньше этой публикации.
  - Серво сима ON.
- А7. `timeout_s: 1.0`, ход домой длиннее.
  - `FakeClock` +1,1 с, `tick()` → итог `failed`, `reason == "срок вышел"`.
  - `.program` `park_home` затем приходит в `done` без новых `STOP_REQ`.
  - Следующий `robot_jog_step` (после `done` программы) → `ok`.
- А8. Связь оборвана во время хода.
  - Следующий `tick()` → итог `failed`, `reason == "связь с роботом потеряна"`.
  - После восстановления транспорта `conn == "connected"` за ≤ 3 `tick()`.
- А9. Подготовка: держится jog, в очереди 2 задания.
  - Итог `dropped == {"jobs": 2, "returns": 0}`.
  - `jobs_sent` не вырос.

## Ловушки

- Замок `RobotState` не реентерабельный: `connected()` зовётся под ним (как `admit_launch`).
- `_op_jog_release` зовёт `_close_thread` — замков не держать.
- Порядок замков: `ParkMachine._lock` → замок состояния. `_jog_tx_lock` под `ParkMachine._lock` не брать.
- Под `ParkMachine._lock` не вызывать ни `servo_off`, ни `launch_home`.
- После `_shutdown` возможна ≤ 1 запись серво: проверка → `request_stop_begin` → `servo(False)` (остаточный риск, Opus m7).
- У `E2eRig` нет `FakeClock` или рекордера публикаций — стоп, вопрос лиду. Не обходить реальным временем.
