DESIGN (решено):
  1. Плагин: в `configure` — один `RobotDataStore(_resolve_registry_path(self._reg.registry_path).parent / "robot")` на процесс (не новое поле конфига: каталог `data/robot` рядом с `devices.yaml`); `DeviceManager(store=..., publish_cb=..., spawn=..., robot_store=self._robot_store)`.
  2. `DeviceManager.__init__(..., robot_store: RobotDataStore | None = None)`. Фабрика `robot` для `delta_v2` при `robot_store is not None` передаёт `param_source=make_param_source(robot_store, entry.id, overrides=entry.params.get("robot_params"), epoch_default=int(entry.params.get("config_epoch", 1)))`; без хранилища — как сейчас.
  3. `DeviceManager.robot_data(dev_id, op, args) -> dict` — путь О4 мимо `call`: устройство есть (иначе текст `DeviceNotFoundError`), `kind == "robot"` и `protocol == "delta_v2"` (иначе `"данные робота — только для протокола delta_v2"`), хранилище задано (иначе `"хранилище данных робота не задано"`); операции — модуль `Services/device_hub/robot_data_ops.py`: таблица `op -> fn(store, device_id, args) -> dict`. Ошибки → ответ: `RevisionConflict` → `{"status": "error", "message": str(exc), "current_rev": exc.current_rev}`; `InvalidStoreKey`, `RobotDataInvalid`, `StoreDocumentInvalid`, `pydantic.ValidationError`, `KeyError` аргумента → `{"status": "error", "message": <постоянный текст>}`; `OSError` — наружу в `_safe_call` плагина.
  4. Офлайн-операции (ключ `base_rev` обязателен у записей — О6; ответы — `rev`):
     `param_get_all` → `{"params": {имя: {"raw": int, "value": float}}, "epoch", "rev"}`;
     `point_list` → `{"points": [dict по имени], "rev"}`; `point_save {point, base_rev}` (вставка или замена по имени); `point_delete {name, base_rev}` (нет → `"точка не найдена"`);
     `frame_list` → `{"frames": [...], "rev"}`; `frame_teach {name, origin, on_x, in_plane, base_rev}` — имена точек → `FrameDef(origin=(x, y, z) точки, ...)` → вставка или замена в `frames.yaml` (О7); нет точки → `"точка не найдена"`; вырожденные → `"точки СК вырождены"`;
     `program_list` → `{"programs": [...]}`; `program_get {name}` → `{"program": dict | None, "rev"}`; `program_save {program, base_rev}`; `program_delete {name, base_rev}`.
  5. Плагин — 22 новых имени, каждое — однострочник (Р7): офлайн — `self._robot_data(data, "<op>")` (помощник по образцу `_kind_call`); движение — `self._kind_call(data, "robot", "<op>")`: `robot_param_set`→`param_set`, `robot_param_apply`→`param_apply`, `robot_stop`→`stop`, `robot_servo`→`servo`, `robot_do_set`→`do_set`, `robot_jog_step`→`jog_step`, `robot_jog_hold`→`jog_hold`, `robot_jog_release`→`jog_release`, `robot_point_capture`→`point_capture`, `robot_program_run`→`program_run`, `robot_program_abort`→`program_abort`. До T5.3d драйвер отвечает на них «Неизвестная операция робота» — это ожидаемо. Старые 27 имён — без изменений (О2).
  6. Каталог: словарь `_ROBOT_V2_DESCRIPTIONS: dict[str, str]` — 22 описания, каждое начинается с `"Робот v2: "` и называет ключи аргументов (`"Робот v2: стоп {device_id, level: SOFT|HARD|HALT}"`). В `start()` для каждого имени — `ctx.command_manager.update_command_metadata(name, {"description": text})` (метода нет или вернул `False` → `ctx.log_warning`, не падать).
  7. Д2 (О3): `DeviceManager.write_registers` — первой проверкой: `entry.protocol == "delta_v2"` → `{"status": "error", "message": "запись регистров робота v2 — только командами robot_*"}`. `read_register` не меняется.
