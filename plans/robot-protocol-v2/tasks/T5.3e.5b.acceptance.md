# T5.3e.5b — приёмка для слепого тестера (C-60.b: стоп хаба в хуке `request_stop`)

Тестеру дают только этот файл. Читать запрещено: `T5.3e.5.md`, `T5.3e.5b.md`, `T5.3e.5a.md`, `T5.3e.analysis.md`,
`T5.3e.1*.md`, прод-файлы `Plugins/hub/device_hub/plugin.py`, `Services/device_hub/manager.py`, тесты авторов
(`test_hub_request_stop_hook.py`). Файл тестера — `Plugins/hub/device_hub/tests/test_c60b_hook_acceptance.py`.

## Поверхность вызова

- Плагин: `DeviceHubPlugin()` (`Plugins/hub/device_hub/plugin.py`); контекст — `make_ctx(...)` и `FakeWorkerManager`
  из `Plugins/hub/device_hub/tests/conftest.py`; `plugin.configure(ctx)`, `plugin.start(ctx)`.
- Хук стопа процесса — метод `plugin.request_stop(ctx)` (зовётся прямо, без фреймворка); закрытие — `plugin.shutdown(ctx)`.
- Подключение — `plugin.cmd_device_connect({"device_id": id})`; разбор очереди супервизора — `plugin._process_conn_queue()`,
  воркеры устройств — `plugin._ensure_device_workers()` (так делают соседние тесты каталога).
- Поддельный робот с остановкой: объект с `stop_aware = True`, `request_stop(deadline)`, `connect()` (счёт
  подключений), `is_connected`, `stop_unconfirmed`, `stop_unconfirmed_text`, `disconnect()`; кладётся в менеджер так же,
  как в `test_lifecycle_regressions.py:83-88`.
- Замок воркеров плагина — `plugin._workers_lock` (так его берёт `test_spi_hazards.py:59`); держащий его поток
  отпускает замок до `cmd_device_connect` (команда берёт тот же замок).
- Область потоков — `plugin._scope`, взять **до** `shutdown`; после `shutdown` `scope.spawn(fn, name="x")` бросает
  `ScopeClosedError` (`multiprocess_framework.modules.base_manager.interfaces`).
- «0 подач на исполнитель»: после `start` — `ctx.command_manager.reset_mock()`; за время хука
  `ctx.command_manager.mock_calls == []` (`configure` уже оставил там вызовы регистрации).
- Воркер устройства — имя `f"dev_{id}"` в `ctx.worker_manager.workers` (там же всегда лежит `device_supervisor`).
- Блокирующие вызовы — daemon-поток + `join` с дедлайном.

## ACCEPTANCE 5b

- Хук возвращается ≤ 0,2 с, даже если стоп робота висит и даже если другой поток держит замок воркеров плагина.
- Стоп робота из хука исполняется не на потоке хука; хук не ставит операций на исполнитель процесса (0 подач).
- Робот получает стоп-запрос ровно 1 раз за закрытие: хук → `shutdown`; два хука подряд; два хука из разных потоков
  одновременно; `shutdown` без хука.
- Срок стоп-запроса — момент хука + 2,5 с (±0,1 с), а не момент `shutdown`.
- После хука «Подключить» не подключает устройство. Без хука — то же во время `shutdown`.
- `shutdown` после хука: удаляет воркер `dev_<id>` каждого устройства, закрывает область потоков (новый поток области —
  `ScopeClosedError`), отключает драйверы, сообщает в health `device_hub.stop_echo` о неподтверждённом стопе — как без
  хука; робот, бывший до хука, получает стоп ровно 1 раз за всё закрытие; робот, добавленный после хука, — тоже 1 раз.
- `shutdown` возвращается только после конца стоп-запросов, запущенных хуком (или после срока).
- Хук после `shutdown` и на плагине без `configure` — без действия и без исключения.
- В журнале плагина хук пишет `DeviceHubPlugin: request_stop`.
- Живьём (стенд `T5.3e.stand/`, P1–P3 и `--regress`): прежние пороги `T5.3e.stand/README.md:63-72` PASS; в логах
  `devices` строка `DeviceHubPlugin: request_stop` раньше строки `DeviceHubPlugin: shutdown`.
