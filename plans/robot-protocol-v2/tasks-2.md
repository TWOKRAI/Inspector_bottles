## Ф4 — Прошивка (один `teamlead` в своём worktree, Layer: mixed)

Настольная книга — [firmware-architecture.md](firmware-architecture.md). Отступление — только с письменным
обоснованием в отчёте. Старт — после GATE-1 и T0.3: подмножество языка, часы, точки, транспорт к ПЧ берутся
из отчёта пробы.

### T4.0 — Стенд сухого прогона (developer, Layer: tests)

Вынести заглушки DRAS из `robot/pc_platform_probe/dry_run.py` в `robot/v2/harness/fake_dras.py` (проба
импортирует оттуда — одна заглушка на двоих), расширить под v2 (`ReadPoint`, `TimerRead`, `RSmaster*` по
отчёту, локальные точки). `lupa` — в группу зависимостей `firmware` (`pyproject.toml`); без неё тесты
пропускаются. Контрактный набор `Services/robot_comm/tests/contract_v2/` гоняется **против `sim_core_v2` и
против собранного `main_v2.lua`** через общий транспорт.
Здесь же, **до кода прошивки** — `tester` пишет `contract_v2/test_findings.py` (12 находок, см. T4.6): тесты
красные против пустой прошивки — спецификация для T4.1–T4.4.
**Приёмка:** тесты пробы зелёные после выноса; контрактный набор и тесты находок против sim зелёные, против
пустой прошивки красные с понятной причиной.

### T4.1–T4.4 — Секции прошивки (teamlead)

Четыре задачи по порядку, каждая — отдельная задача протокола (инъекции ведущего + синхронный `reviewer` после
каждой), исполнитель может быть тем же teamlead последовательно: **T4.1** `00, 20, 25, 40, 45, 50` + сборка →
**T4.2** `60` (OPS, ответ) → **T4.3** `70, 71, 73, 74` (`move`, `run_long`, исполнители) → **T4.4** `30, 80, 90, 99`
+ полный luacheck.
Жёстко: телеметрия и ПЧ обслуживаются при любой активности; между LINE_PASS-точками Modbus не трогается; `pt_set`
пишет все четыре оси с `"RZ"`; состояние инструмента в прошивке не хранится; ни одного `a and f() or b` с
возможным `nil` в середине; комментарии — про инвариант, не про историю.
**Приёмка T4.4:** `build_fw --check` = 0; `luacheck` 0 предупреждений; контрактный набор против прошивки
зелёный; таблица «находка → функция» (firmware-architecture §8) в отчёте.

### T4.5 — README прошивки (tech-writer, Layer: docs)

`robot/v2/README.md`: карта секций; сборка и заливка в DRAStudio; версия прошивки контроллера; переключение

### T4.6 — Контракт-тесты находок (tester, пишутся в T4.0 до кода; Layer: tests)

`contract_v2/test_findings.py`: 12 тестов `test_finding_01_override_leak` … `test_finding_12_watchdog_clock`,

цитата находки.

**REVIEW-4** (в дополнение к ревью каждой T4.x): `reviewer` синхронно по прошивке целиком (корректность Motion ↔ Mirror, пути выхода и эпилог,

## Ф5 — Бэкенд (без GUI)

### T5.1 — `RobotDriverV2` (teamlead, Layer: services)

`Services/device_hub/drivers/robot_driver_v2.py`; фабрика хаба выбирает класс по протоколу записи устройства
(`delta_v2` → v2, прочее → v1; `manager.py:107-112`). Файл v1-драйвера не трогается. Подключение: probe,
синхронизация параметров, действия при подключении из конфигурации устройства (DO эжектора, серво).
Тик: `HB_PC`, телеметрия → `devices.state.<id>.status` (**поля ответа `robot_get_telemetry` v1 сохраняются** —
на них стоит калибровка камеры), события ошибок → `devices.state.<id>.last_error` с русским текстом.
Исполнитель программ (куски, прогресс → `devices.state.<id>.program`), поводок jog (тикает, пока от GUI
приходят подтверждения удержания не реже 100 мс).
**Приёмка (tester):** против sim v2: два робота в одном хабе не делят состояние; телеметрия v2 даёт тот же набор
полей, что v1; потеря подтверждений удержания → робот встаёт за `P_JOG_LEASE_MS`; перезапуск sim с другой
меткой → повторная отправка параметров.

### T5.2 — `RobotDataStore` (developer, Layer: services)

`Services/robot_comm/store.py`: `data/robot/<device_id>/{params.yaml, points.yaml, frames.yaml,
programs/<имя>.yaml, calibration.yaml}`; запись с оптимистичной ревизией (как `recipe.*` gui-service 1b.1:
чужая ревизия → отказ, а не затирание); атомарная запись файла (временный файл + переименование).
**Приёмка (tester):** два писателя с одной ревизией — второй получает отказ; обрыв посреди записи не портит
файл; два `device_id` не видят данных друг друга.

### T5.3 — Команды хаба (developer, Layer: plugins)

`Plugins/hub/device_hub/plugin.py`, команды с ответом (`device_id` в каждой):
`robot_param_set/get_all/apply`, `robot_stop{level}`, `robot_servo`, `robot_do_set`,
`robot_jog_step`, `robot_jog_hold{dir, spd}` (старт/подтверждение удержания), `robot_jog_release`,
`robot_point_capture/list/save/delete`, `robot_frame_teach/list`, `robot_program_list/get/save/delete/run/abort`,
`robot_calib_*` (T5.4). Имена, которые зовут плагины (`robot_enqueue_job`, `robot_draw_polyline`), сохраняются.
Каждая команда описана в каталоге команд (адрес `devices/robot_*` для Пульта и `backend_ctl`).
**Приёмка (tester):** каждая команда против sim v2: успех и отказ с текстом; `robot_program_run` → прогресс в
состоянии; `backend_ctl send_command` двигает sim.

### T5.4 — Калибровка, бэкенд (developer, Layer: services)

`Services/robot_comm/calibration/`: лента (две отметки объекта + энкодер → `P_BELT_FACTOR`, `P_BELT_DIR`,
`PARAM_APPLY`), пользовательская СК по трём точкам, точки инструментов. Камера ↔ робот — существующий
`Plugins/calibration/camera_robot` без изменений (проверить, что работает с v2-драйвером).
**Приёмка (tester):** лента: известный ход → коэффициент с ошибкой < 0.5 %; СК из трёх точек с шумом 0.1 мм
восстанавливает поворот ±0.1°.

### T5.5 — Плагины (developer, Layer: plugins)

`robot_draw` → генератор `draw` + `robot_program_run`; `robot_io` (подача CVT) → `CVT_JOB`. Интерфейсы плагинов
не меняются.
**Приёмка (tester):** существующие тесты плагинов зелёные без правок; рисунок из `robot_draw` на устройстве v2
доходит до sim как программа (прогресс в состоянии); задание подачи на v2 даёт DONE в sim. **REVIEW-5** → `cto`: приёмка Ф5 = приложение против sim v2 без GUI (параметры, программа,
калибровка ленты, стоп) через `backend_ctl`.

## Ф6 — Пакет GUI `robot.*` (Layer: services, подпакет `gui/`)

Условие: `gui-constructor` Task 1.0 (правило `Services/<x>/gui/`) и 1.5 (контекст виджета, `WidgetSpec`).
Виджет видит только контекст: команда с ответом, glob-подписка на `devices.state.<id>.*`. Каждый виджет
параметризован `device_id`.

### T6.0 — Движок форм (teamlead, Layer: framework)

Если `frontend-constructor` T3.6 к старту не сделан: промоушен движка форм из `multiprocess_prototype/frontend/forms/`
во фреймворк по списку T3.6 — пакет робота второй потребитель. **Отдельный PR** с `Refs: plans/frontend-constructor/plan.md`
(слой framework, не под Refs робота), по согласованию с владельцем того плана; прототип переводится на
промоутнутый движок той же задачей.

### T6.1 — `robot.status` + `robot.params` (developer)

Статус: активность, поза, серво, ошибки с текстом, ПЧ, СТОП / ВЫКЛ серво. Параметры: форма из `RobotParamsV2`
по группам; запись → `robot_param_set`; NAK — подсветка поля и текст; «применить» для `reinit`.
**Приёмка (tester, offscreen):** форма показывает все группы YAML; значение за границей не отправляется; NAK
подсвечивает поле; новый параметр в YAML появляется в форме без правки кода виджета.

### T6.2 — `robot.jog` (developer)

Непрерывный jog: нажатие — `robot_jog_hold`, удержание — подтверждения каждые 100 мс, отпускание —
`robot_jog_release`; потеря фокуса окна = отпускание. Шаги 0.1/1/10 мм. «Запомнить точку» → `robot_point_capture`.
**Приёмка (tester):** заморозка цикла событий Qt → подтверждения прекращаются → sim встаёт.

### T6.3 — `robot.programs` (developer) и T6.4 — `robot.calibration` (developer)

Программы: библиотека точек и программ, редактор шагов (таблица), запуск / стоп / прогресс по кускам,
импорт рисунка для генератора. Калибровка: мастера T5.4 шагами с подсказками.
**Приёмка (tester, offscreen):** программа из редактора сохраняется командой бэкенда (не файлом) и исполняется на
sim с прогрессом; конфликт ревизии показывается оператору, а не затирает чужую правку; мастер ленты проводит по
шагам и отправляет коэффициент; ни один виджет не открывает файлов данных робота (И10).

### T6.5 — Пульт и прототип (developer)

Набор ручек Пульта «Робот» (скорость, стоп, серво, запуск программы) по адресам `devices/robot_*`;
в раскладке прототипа — пакет для устройств v2, старая вкладка `tabs/services/robot/` — только для v1.
Ревизия вызовов `draw_*` прототипа (свежий grep перед стартом: оценки расходятся — 33 места вызова против 62
вхождений имени): при v1 — как есть, при v2 — не показываются. **REVIEW-6** → `cto`.
