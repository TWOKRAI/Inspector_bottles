# robot-protocol-v2 — что изменилось в редакции 2 (2026-09-27)

Часть [plan.md](plan.md), вынесена по размеру.

## Было → стало

| Было | Стало | Почему |
|---|---|---|
| STOP — опкод mailbox | регистр `STOP_REQ` с seq, без очистки | стоп при занятом mailbox; нет гонки очистки |
| Зона — прямоугольник | кольцо SCARA + отрезки LINE + ограждение | реальная геометрия; прямая может пройти через мёртвую зону |
| Сценарий stride 8, 96 записей за GATE-1 | stride 6, 55 записей, пинг-понг `offset` | длинные программы кусками; буфер в проверенном пространстве |
| Watchdog выключен до Ф7, часы неизвестны | включён по умолчанию на `TimerRead` | лентой управляет только робот; часы есть в мануале |
| ~20 параметров, хранение только на ПК | ~70, классы применения, `PARAM_APPLY`, зеркало в сохраняемой области | Ц1 |
| Проба потолка адресов (скрипт на 6 адресов) | проба платформы: 35 тестов, сухой прогон, 2 ревью | один визит должен снять всё |
| lupa-харнесс — stretch | сухой прогон прошивки — часть Ф4 | техника доказана пробой |
| Дуальный v1/v2 в каждой операции драйвера | два класса, выбор по `protocol` устройства | v1 действительно заморожен |
| GUI — вкладка прототипа | пакет `robot.*` + ручки Пульта | решение 09-26 |
| Данные в `devices.yaml` | `data/robot/<id>/`, ревизия при записи | не зависит от О-7; несколько роботов |
| Сценарии RETURN/TOOLCHANGE | программы точек, СК, калибровка | Ц3, Ц4 |
| — | несколько роботов, непрерывный jog, быстрый стоп, `E_VFD_LINK` | Ц5, удобство обучения |
