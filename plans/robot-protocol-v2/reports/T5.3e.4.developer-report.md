## Отклонения от DESIGN (малые, по причине)

1. Отказ park сделан липким (`_park_text = message`), иначе следующий пуш `.status` (<1 с) стирает «идёт отключение робота». DESIGN про отказ молчит.
2. Пустой `reason` при `failed` -> «Основная остановка не выполнена.» (без висящего «: .»). Непустой — ровно по DESIGN.
3. `_on_park` обнуляет `_park_seq` (не только `_park_text`): иначе итог прошлого запуска, лежащий в виде, показался бы как итог нового до прихода ответа. Закрыто hazard-тестом.
4. Ответы park/force_stop несут `device_id` в замыкании; ответ для уже сменённого устройства отбрасывается.
5. `_on_park_push` сверяет путь с `devices.state.<текущий id>.park` (чужой путь — игнор). Причина: `bind_fanout` не отвязывается (см. ниже), старые подписки живут после `set_device`.
6. `force_stop`: не-`ok` ответ показывает `message` (или «Принудительная остановка не выполнена.»); в DESIGN только ветка `ok`.
7. Тексты «запрос отправлен…» в момент клика НЕ добавлял (DESIGN их не содержит).
8. Текст «Робот остановлен (HARD).» НЕ липкий (по DESIGN `_park_text` только для park): следующий пуш `.status` его перепишет.
