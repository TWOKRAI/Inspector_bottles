## Замечания
- [major/context] Набор v2-хоста проверяет воркеры только на фейке `ThreadWorkerManager` (`Plugins/sim/robot_host/tests/v2_driver.py:75`). Это нарушает правило project-rules §9: «A fake-harness suite needs one test that wires the real objects». Сам набор это признаёт: `test_v2_host.py:129` («что настоящий `WorkerManager` (не наш фейк) их запустит» — не доказано), то же в `STATUS.md`. Контракт фейка расходится с настоящим в двух местах, от которых зависит `_start_v2_workers`:
  - `is_worker_running`: у фейка это `thread.is_alive()`, у настоящего — статус реестра `RUNNING` (`worker_manager.py:300-302`);
  - `start_worker` на живом потоке: фейк возвращает `False`, настоящий возвращает `True` и поток не заводит (`worker_lifecycle.py:97-100`).
  Это урок `feedback_a_faithful_fake_still_lacks_the_protocol.md`. Мой прогон на настоящем менеджере (scratch `real_wm.py`: `WorkerManager("robot")` в `services.worker_manager`, `protocol: v2`, 30 циклов start → TCP connect → `sim_robot.status` → shutdown) дал `cycles 30 bad []`, `restart_count {'sim_robot_ticker': 29, 'sim_robot_listener': 29}`. Сегодня путь работает, но регрессию здесь ни один тест не поймает.
  Исправить: добавить в `test_v2_host.py` тест с настоящим `WorkerManager`, ≥3 цикла start/shutdown на одном порту. Каждый цикл проверяет три вещи: соединение принято, `TLM_HB_ROBOT` растёт (тикер жив, а не только слушатель), порт свободен после shutdown. Прогноз под инъекцией «не звать `start_worker`, когда `create_worker` вернул `False`»: тест красный на 2-м цикле. После теста поправить строку в `STATUS.md` про «проверено только на фейке».
- [minor/design] Сторожевой таймер в FAULT расходится с текстом протокола §9.4 («ACTIVITY → IDLE»), а решения нет ни в ADR, ни в тесте. Вход: `inject_motion_fault()`, `HB_PC=1`, 10 тиков, затем 3.2 с без HB. Выход (scratch `core_probe.py`): `WDG_STATE 2 ACTIVITY 5 ERRNO 10 ERR_EVT 2`. ACTIVITY остаётся FAULT, а `TLM_ERRNO_LAST` с причины FAULT переписан на `E_WDG_TIMEOUT`. В `test_sim_v2_cvt_wdg_vfd.py` `inject_motion_fault` есть только в докстрингах (строки 29 и 407), ветку `fault=fault` в `sim_core_v2.py:801-802` не проверяет ни один тест. Само поведение разумное: сторож не должен снимать FAULT.
  Исправить: строка в `Services/robot_comm/DECISIONS.md` (дополнение к ADR-RC-016: «в FAULT сторож даёт событие, ACTIVITY остаётся 5») и тест с литералами `ACTIVITY == 5`, `ERRNO_LAST == 10`.
- [minor/fact] Открытый пункт в `Plugins/sim/robot_host/STATUS.md` устарел. Пункт: «`tests/test_v2_letter_straight.py` шлёт `CVT_JOB` с `flags=0` … Правка теста — за тестером/лидом». Факт: `git grep -n "flags" -- Plugins/sim/robot_host/tests/test_v2_letter_straight.py` → `:85: 2,  # flags бит1: укладка из place_* … правка лида`. Исправить: убрать пункт или записать, что он закрыт правкой лида.
- [nit/design] Совещательно. `_start_v2_workers` (`plugin.py:444-446`) не проверяет результат `start_worker` и ждёт только bind слушателя. Работает ли тикер, не проверяется. У настоящего менеджера есть окно: статус `STOPPED` уже выставлен в `finally` обёртки (`worker_lifecycle.py:247-250`), а поток ещё жив. `start_worker` в это окно вернёт `True` без нового потока (`:97-100`). Тогда старт «успешен», слушатель на месте, а тикера нет: mailbox молчит. За 30 циклов окно не попалось (между shutdown и start проходят миллисекунды, а окно — микросекунды), поэтому воспроизведения нет. Исправить по желанию: после запуска дождаться `is_worker_running(_V2_TICKER_WORKER)` или первого роста `TLM_HB_ROBOT`, иначе `RuntimeError` по той же дороге `_fail`.
