### 1. [tests, major] `test_robot_v2_park_tick.py:298` нестабилен на HEAD после слияния
- **Вход -> результат.** Три файла park одним процессом, чистый HEAD, 3 прогона: третий —
  `test_park_tick.py:298: AssertionError: assert True is False`
  (`FAILED ...::test_guard_runs_before_early_exit_on_link_loss`). Тот же красный — в прогоне с J1, хотя J1 путь
  `kind == "park"` не трогает. Один тест отдельно — 8 из 8 зелёных. Итог: 2 красных из 5 прогонов набора.
- **Механизм (по чтению, трассы нет).** После `rig.restart()` поток программы `park_home` может первым увидеть обрыв:
  `programs.py:134` -> `link_lost`, `programs.py:144` -> `program_finished("park", ..., "link")`. Транспорт
  переподключается сам, тик читает TLM, и `step` закрывает park веткой `park.py:252-253` (`outcome == "link"` ->
  «связь с роботом потеряна»). `is_connected` при этом True. Строка `:297` (`failed`, «связь с роботом потеряна»)
  верна в обоих путях; строка `:298` требует только путь `guard`. Код ведёт себя по замыслу А8: тест требует исхода
  гонки.
- **Следствия.** (а) Гейт слияния краснеет без причины в коде. (б) Когда побеждает `step`, тест не проверяет порядок
  «`guard` до раннего выхода тика» (его сторож для P-I6). Вывод вердикта инъекций «не флак: 8 из 8» снят на
  `50df420f4` при другой нагрузке машины.
- **Исправить.** Разложить на два детерминированных плеча: (1) сторож `guard` — обрыв, когда потока программы нет
  (park ждёт на шаге `activity` / `idle`: держится jog, или `free == False`); тогда закрыть park может только `guard`, и
  `is_connected is False` можно проверять; (2) плечо `step`/«link» уже покрыто
  `test_home_program_transport_error_gives_link_reason`. Просто удалить `:298` нельзя: P-I6 тогда теряет сторожа.
  После правки повторить P-I6 и прогнать набор не меньше 5 раз.

  состояния, а `is_connected` замков не берёт. Обратного порядка не нашёл; взаимной блокировки по чтению нет.
- **CAS `.park`.** `park_end` сверяет `_parking` и `seq` (`state.py`); `_finish_locked` — с запомненным `seq`;
  `_still_mine_locked` после каждого вызова вне `_mlock`. Чтение `v.seq` в `abort` вне `_mlock` безопасно: новый
  `park_begin` после `request_stop_begin` / `_request_stop` отказывает (`_stopping`), а проигравший CAS не пишет.

  `is_shutdown()`; терминал ставит только `abort(stop=True)` после записи стопа. Сторожа: P-I7, P-I22, P-I25.
