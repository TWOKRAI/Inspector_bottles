## 2. Новые дефекты

### N1 — [T5.3e.5a.md:82-85, 121, 167] [tests] major — REDS №7 не ловит A-10 (нет завершающего прохода)

**Механизм:** внутренний цикл (п.3, «для каждого ждущего: … `park_wait(seq, min(0.2, deadline - now))`») проходит
всех ждущих до конца прохода. Если срез одного робота перешёл через срок, у следующих по порядку остаток
отрицательный → `wait_terminal` делает `max(0.0, …)` (п.1) → `wait_for(timeout=0)` проверяет предикат. Итог робота,
стоящего **позже** в порядке `entry.id`, всегда виден в его срезе или в этой нулевой проверке после срока.
Завершающий проход нужен только роботу, стоящему **раньше**: его итог пришёл, пока шёл срез соседа после него.
**Вход → вывод (по чтению):** REDS №7 — «`A` без итога, `B` пишет `done` за 0,05 с до срока». Порядок `A`, `B`.
Мутант A-10 (без завершающего прохода): `B` проверяется после `A` → `B: done` → тест зелёный. Прогноз A-10 → №7
не сбудется.
**Исправить:** поменять роли: итог пишет первый по порядку (`A`), второй (`B`) — без итога. Срок итога — не по
часам (фаза срезов плывёт), а из поддельного `B.park_wait`: при вызове с `timeout_s < 0.2` (последний срез до срока)
он сначала записывает итог `A`, потом ждёт. Ожидание: `A: done`; мутант A-10 → `A: timeout`.
