## Замечания
- [minor/fact] `Plugins/sim/robot_host/README.md:42` не описывает новое ожидание тикера. Там сказано: «Старт ждёт bind слушателя не дольше 5 с; сбой или таймаут → `_fail`». Код после bind ждёт ещё и тикер, до `_V2_TICKER_TIMEOUT_S = 5.0` с (`plugin.py:461-466`), с отдельной причиной отказа. Докстринг `_start_v2_workers` (`plugin.py:430-440`) тоже говорит только про bind. Вход: настоящий `WorkerManager`, поток тикера задержан после останова (scratch `window.py ticker`). Выход: `start#2 (immediate) state=error in 5.05 s`, `reason: sim_robot_host: тикер v2 не запустился за 5.0 с`. Худший старт теперь около 10 с, а не 5. Это нарушает правило (6): README соответствует коду. Исправить: одна строка в README и докстринге — «затем ждёт живого тикера не дольше 5 с; иначе `_fail` с причиной „тикер v2 не запустился“».
- [nit/design] Ожидание тикера пассивное: окно «STOPPED, но поток жив» оно превращает в громкий отказ, но само не восстанавливается. Вход: `WorkerLifecycle._worker_wrapper` задерживает поток на 0.3 с после выставления STOPPED, сразу после shutdown — повторный start. Выход (`window.py`): `ticker` → `state=error in 5.05 s`; `both` → `state=error in 5.00 s` («нет bind за 5.0 с»). Старт через 0.5 с после этого → `state=running in 0.03 s`. Поток кончился через 0.3 с, но цикл ждёт ещё 4.7 с и `start_worker` повторно не зовёт. На практике окно — микросекунды, моё 0.3 с искусственное, поэтому только nit. Исправить по желанию: в обоих циклах ожидания (`plugin.py:450`, `:462`) звать `workers.start_worker(name)`, пока воркер не `RUNNING`. Для настоящего менеджера это идемпотентно (`worker_lifecycle.py:97-100`); фейк на живом потоке вернёт `False` без побочных эффектов.
