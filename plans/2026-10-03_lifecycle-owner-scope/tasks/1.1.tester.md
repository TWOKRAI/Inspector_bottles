DESIGN (decided by the lead — you type it, you do not derive it):
  1. Модуль `multiprocess_framework.modules.process_manager_module.core.stop_budget`: функция `stop_budget(shutdown_timeout) -> dict[str, float]`, ключи строго в порядке `work_s`, `infra_s`, `pm_graceful_s`, `pm_total_s`, `outer_s`. Литералы: `stop_budget(5.0)` → `work_s` 3.0, `infra_s` 1.0, `pm_graceful_s` 5.0, `pm_total_s` 7.0, `outer_s` 8.5; `stop_budget(1.0)` → 0.6, 0.2, 1.0, 3.0, 4.5 (сравнение `pytest.approx`); `None`, `0`, `0.0` → как для 5.0. NaN, `inf`, `-inf`, отрицательное → `ValueError`; `True` и строка → `TypeError`; текст ошибки не содержит само значение. Константы модуля: `STOP_POLL_S` 0.05, `TERMINATE_GRACE_S` 1.0, `KILL_CONFIRM_S` 1.0, `PM_TEARDOWN_MARGIN_S` 1.5, `DEFAULT_SHUTDOWN_TIMEOUT_S` 5.0, `KILL_RESERVE_S` 2.0, `SHUTDOWN_TIMEOUT_KEY` равна строке `shutdown_timeout`.
  2. Модуль `...process_manager_module.core.child_process_stop`: класс `ChildProcessStop(processes, stop_events, *, on_confirmed_dead=None, logger=None, terminate_grace_s=TERMINATE_GRACE_S, kill_confirm_s=KILL_CONFIRM_S, poll_s=STOP_POLL_S)`. `processes` — отображение имя → объект с `is_alive()`, `terminate()`, `kill()` (ваши дублёры; запись момента каждого вызова `time.monotonic()`); `stop_events` — имя → объект с `set()` (дублёр с записью вызовов). `on_confirmed_dead(name, process)` — колбэк метки.
  3. `request_stop()` зовёт `set()` события каждого ЖИВОГО процесса; не блокирует; повтор безвреден. `join_until(deadline) -> bool` — `deadline` абсолютный `time.monotonic()`; опрашивает ВСЕХ живых за один проход через `poll_s`; каждого умершего один раз передаёт в `on_confirmed_dead` в момент, когда смерть увидена; возвращает `True`, когда живых нет (пустая группа — `True`), на сроке `False`, не бросает; срок в прошлом — один проход. До вызова `kill()` `join_until` не шлёт никаких сигналов (`terminate`, `kill`).
  4. `kill()` НЕ блокирует: каждому живому — `terminate()` сразу; запоминает начало; возвращается немедленно (без ожидания `terminate_grace_s`); повторный вызов ничего не делает. После `kill()` `join_until` один раз шлёт настоящий `kill()` каждому ещё живому на первом проходе, где `time.monotonic() >= min(начало + terminate_grace_s, deadline - kill_confirm_s)`. Исключения из `terminate`, `kill`, `on_confirmed_dead` не прерывают цикл и не вылетают наружу.
  5. `survivors() -> tuple[str, ...]` — один проход наблюдения (метит новых умерших через `on_confirmed_dead`) и имена без подтверждённой смерти ПОСЛЕ этого прохода, в порядке `processes`. `close()` — метит подтверждённо мёртвых, кому метка ещё не ставилась; выжившим не ставит; идемпотентно. Метка на имя — не более одной за жизнь объекта, всеми путями вместе.
  6. Реестр: `ProcessRegistry(..., child_stop_budget: dict | None = None)`; при заданном словаре каждый ребёнок, созданный `create_and_register`, получает в своём конфиге ключ `stop_budget` с копией словаря; ключ, заданный в конфиге процесса явно, сильнее. Наблюдать без запуска процесса: `proc = registry.create_and_register("R", "os.getpid", {}, "normal")`, затем `proc._args[3]["config"]` (bundle — четвёртый позиционный аргумент `Process`; образец построения реестра — `tests/test_process_registry.py`). Без `child_stop_budget` ключа в конфиге нет.
  7. Тесты окон и меток строятся на дублёрах и маленьком `poll_s` (например 0.01) и `terminate_grace_s` (например 0.3); сравнения времени — с допуском не меньше 0.1 с (дискретность `time.monotonic()` на Windows 15,6 мс). Тест, который может зависнуть, гоняет вызов в daemon-потоке с `join` по сроку.
