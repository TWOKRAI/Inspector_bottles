## Решения (DESIGN)

DESIGN (decided by the lead — you type it, you do not derive it):
  Module contract: public-api-change.
  - `process_module`: `IProcessModule` получает `close_root`, `attach_stop_budget`.
  - `chain_module`: `WorkerPoolExecutor.shutdown(wait)` уходит, появляется `shutdown_nowait()`.
  - `base_manager`: impl-only (атрибут `_ON_SHUTDOWN_WAIT_S`, формула срока).
  1. Кодмод 23 классов. В каждой строке инвентаря `def shutdown(self) -> bool:` → `def _on_shutdown(self) -> bool:`.
     - Тело и свои флаги идемпотентности (`WorkerPoolExecutor._shutdown` и др.) не трогать; super не добавлять (кроме п.2).
     - Не менять вызовы `self.shutdown()` из других методов (`frontend_manager.py:219`, `router_manager.py:2099`, `process_manager_process.py:3344`) — они идут через шаблон.
     - Не менять `.shutdown()` подчинённых менеджеров (`self._event_manager.shutdown()`, `self.dispatcher.shutdown()`, `self._worker_manager.shutdown()`, `self.channel_dispatcher.shutdown()` и т. п.).
     - Слово «shutdown» в комментариях менять не обязательно, кроме строк п.2.
  2. Частные случаи:
     - `LoggerManager` (:51): `def _on_shutdown`; :66 → `result = super()._on_shutdown()`; докстринг :61 → «ПОСЛЕ ``super()._on_shutdown()``». Тело :67-80 без изменений.
     - `LoggerCore` (:483), `RouterManager` (:491): только имя, без super.
     - `WorkerPoolExecutor` (:259), Р2 (а), имя — решение лида В-5:
       - тело :266-277 дословно → `def _shutdown_pool(self, *, wait: bool) -> bool`;
       - `def _on_shutdown(self) -> bool: return self._shutdown_pool(wait=True)`;
       - новый публичный `def shutdown_nowait(self) -> bool: return self._shutdown_pool(wait=False)`.
       Поведение `shutdown_nowait()` (ответ из кода, не выбор):
       - через шаблон «раз за жизнь» НЕ идёт: это прямой вызов тела; запись жизни (`_bm_life`) не меняется, область не закрывается;
       - один раз его делает собственный флаг `_shutdown` под `self._lock` (:266-269): повторный `shutdown_nowait()` → `True` без работы;
       - следующий `shutdown()` после `shutdown_nowait()` — ПЕРВЫЙ вызов шаблона: закрывает область (если привязана), зовёт `_on_shutdown()` → `_shutdown_pool(wait=True)` → флаг уже стоит → `return True` (:267-268); итог `True`, кэш шаблона — `True`;
       - `shutdown_nowait()` после `shutdown()` → `True` по флагу.
       Докстринг `shutdown_nowait`: «Отменить невзятые задачи и остановить воркеры, не дожидаясь хвоста. Не шаблон: область не закрывает; последующий `shutdown()` вернёт `True`».
       В докстрингах :17, :45, :184, :228: `shutdown(wait=True)` → `shutdown()`, `shutdown(wait=False)` → `shutdown_nowait()`.
     - `ProcessModule` (:341): только имя. Тело то же: `close_root()`; исключение → `_uninstall_process_hooks()` + `_log_error`; `None` → `True`; иначе `not report.errors`. Повторный `shutdown()` отдаёт кэш шаблона, `close_root()` второй раз не зовёт.
     - `ProcessModule._open_root` (:370-389), решение В-7 — единственный источник. Сразу после `work_b, infra_b = self._root_budget(budget)` (:375) добавить строку `self._ON_SHUTDOWN_WAIT_S = work_b + infra_b` — это тот же `budget_s`, с которым открывается корень (:376-380, `kill_reserve_s=0.0`).
       - Член для `ProcessModule` — `work_s + infra_s`; для PM — через свой `_root_budget` (`process_manager_process.py:3528-3530`) `pm_total_s + infra_s`.
       - `attach_stop_budget` (:362-364) не меняется, только хранит словарь.
       - PM-файл не трогать; статического 8.0 на классе нет.
       - До открытия корня действует атрибут класса 5.0.
     - `WorkerManager` (:61), `StateStoreManager` (:134): только имя (FREEZE).
  3. Срок второго вызова (решение лида; член атрибута — по В-1):
     `BaseManager` получает атрибут класса `_ON_SHUTDOWN_WAIT_S: float = 5.0`.
