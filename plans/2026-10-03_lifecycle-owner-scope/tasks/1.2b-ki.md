# Task 1.2b-ki — BaseException в scope.close() не отменяет _on_shutdown() (бриф)

Основание: строка 1.2b-ki в `tasks/1.2b.md:37`; решение владельца 2026-10-13 («как считаешь лучше»): чинить после 1.2b-2, до 1.2b-3. Открыто с ревью кода 1.2b-1, вердикт (b); долг записан в `base_manager/DECISIONS.md:199`.

Сегодня (`base_manager/core/base_manager.py:159-177`): `scope.close()` обёрнут в `except Exception`; `KeyboardInterrupt`/`SystemExit` из него пролетают мимо вызова `_on_shutdown()` — внешний `finally` лишь кэширует `False` и взводит «готово». Тело подкласса не зовётся ни разу за жизнь объекта.

Отдельного тестера нет (решение владельца 2026-10-13): опасность порядка, hazard-тест автора. Стадия 0 (ревью спека) не проводится — правка ~10 строк в одном методе, решения ниже заданы лидом.

## DESIGN (задано лидом — набрать, не выводить)

1. `BaseException` (не `Exception`) из `scope.close()` перехватывается; пишется строка `shutdown <manager_name>: scope.close прерван: <ExcType>: <текст>` через `self._shutdown_log`; исключение запоминается.
2. Затем `_on_shutdown()` зовётся как обычно, ровно один раз: его `Exception` → строка `_on_shutdown упал: …` (как сейчас), результат не используется.
3. После `_on_shutdown()` запомненное исключение пробрасывается наверх (`raise`, исходный traceback). Кэш — `False` (останов прерван, область могла не закрыться), независимо от того, что вернул `_on_shutdown()`. Ждущие получают `False` сразу (поведение inj-21 сохраняется).
4. Если `_on_shutdown()` сам бросает `BaseException` на этом пути — наверх уходит его исключение (цепочка Python: `__context__` = исходное). Кэш — `False`.
5. Ветка `Exception` из `scope.close()` не меняется (строка `scope.close упал`, `_on_shutdown` зовётся, результат — его).
6. Ветка `BaseException` в самом `_on_shutdown()` (без сбоя close) не меняется (`test_base_exception_in_on_shutdown_propagates_and_caches_false`).
7. ADR-BM-009 (`base_manager/DECISIONS.md:199`): пункт о долге заменить строкой о решении (1.2b-ki, правила 1–4); `python -m scripts.sync`; STATUS `base_manager` — одна строка.

## Гарантии для инъекций (предсказания пишет лид до прогона)

- K-1. `BaseException` в `scope.close()` → `_on_shutdown()` вызван ровно 1 раз, после `scope.close()` (порядок `["close", "on_shutdown"]`).
- K-2. То же исключение (тот же объект) выходит из `shutdown()`.
- K-3. Кэш `False`, даже если `_on_shutdown()` вернул `True`; второй вызов — `False` сразу (< 1,0 с), `_on_shutdown` больше не зовётся.
- K-4. Строка `scope.close прерван: KeyboardInterrupt: …` ровно одна.
- K-5. `_on_shutdown` бросает `RuntimeError` на этом пути → наверх уходит `KeyboardInterrupt` (не `RuntimeError`), строка `_on_shutdown упал: RuntimeError: …` есть.
