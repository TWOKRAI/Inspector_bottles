# Task 0.2 — acceptance и инъекции

Спек — [`task-0.2.md`](task-0.2.md). Этот файл — его продолжение: приёмка (вход слепого тестера) и план инъекций
ведущего. Вынесен по размеру (doc-size-guard 32 КБ).

Времена — с допуском сетки Windows (`time.monotonic` 15.6 мс): верхние границы ниже уже включают допуск.
Каждый вызов, который может зависнуть, — в daemon-потоке с `join(timeout)`; зависание = провал с текстом.
Выход `spawn`-потока ждать опросом `threading.enumerate()` по имени (`"root/w"`) со сроком, а не событием из `target`:
самоотцепление идёт после возврата `target`.

**Сверка с DESIGN §3 «G1: сценарии a–h, E2–E5»** (раскладка из материалов дискуссии 2026-10-03, ревью спека р1 З10):
(a)–(f) — здесь; (g) исключение подписчика — Task 0.3; (h) и E2 — Qt, Task 0.4; E1 тайминг барьера, E3 pickle,
E4 kill, E5 сторож корней — здесь (разделы «Барьер», «Прочее», «Сроки», «`unclosed_roots()`»).

## Дверь и форма
- [ ] `from multiprocess_framework.modules.base_manager import open_scope, unclosed_roots` работает; оба в
      `__all__`; `"Scope" not in __all__`, `"Handle" not in __all__`, `hasattr(base_manager, "Scope") is False`.
- [ ] `inspect.signature(open_scope)` — `(path, *, budget_s, kill_reserve_s=0.0, reporter=None)`.
- [ ] Структурно (не `isinstance`: `IScope`/`IHandle` в 0.1 без `runtime_checkable`, ревью р1 Б1): у
      `open_scope("t", budget_s=1.0)` есть все члены `path`, `closed`, `parent`, `own`, `child`, `barrier`,
      `spawn`, `cancel`, `close`, `live`; у ручки `own`/`spawn` — `path`, `kind`, `close`. `interfaces.py` в части
      протоколов не меняется.
- [ ] `budget_s=float("nan")`, `-1.0`, `float("inf")` → `ValueError`; `budget_s=True` → `TypeError` — у
      `open_scope`, `child`, `close`.
- [ ] `close(budget_s=1.0, deadline=time.monotonic()+1)` → `ValueError`, ни один ресурс не освобождён.
- [ ] `root.parent is None`; `child.parent is root`; `root.closed is False` до `close`; вызываемое фазы 2 видит
      `root.closed is True`.

## Записи
- [ ] `own(SomeClass, name="x")` → `TypeError`, текст содержит `SomeClass`; запись не создана (`live() == []`).
- [ ] `own(42, name="x")` → `TypeError`, текст содержит `int`.
- [ ] Имя `""`, `"a/b"`, `"x (self)"` → `ValueError`; повтор имени живой записи → `ValueError`; после
      `handle.close()` то же имя принимается.
- [ ] `handle.path == "root/x"`; `kind` по умолчанию `"resource"`; `child` → `"scope"`; `spawn` → `"thread"`.
- [ ] Поток `spawn(target, name="w")` в области `"root"` имеет `threading.current_thread().name == "root/w"` и
      `daemon is True`; `target` получает `threading.Event`, которое взводится фазой 1.
- [ ] Поток вышел из `target` штатно → записи нет в `live()`, имя `"w"` принимается снова, `handle.close()` → отчёт
      `ok`.
- [ ] `target` бросил `ValueError("x")`, ручку не закрывали → пара `("root/w", "ValueError: x")` в `errors`
      ближайшего `close` области. Ручку закрыли раньше области → пара в отчёте `handle.close()`, а в отчёте
      `close` области её нет.
- [ ] `child("c")` без аргументов под `open_scope(budget_s=0.2, kill_reserve_s=0.3)`: застрявший `Stoppable` в `c`,
      умирающий через 0.05 с после `kill()` → в `killed` отчёта корня (бюджет и резерв унаследованы).

## Фазы и порядок
- [ ] Три вызываемых `a`, `b`, `c` → вызваны в порядке `c, b, a`.
- [ ] Два `Stoppable` в одном сегменте: оба `request_stop` записаны в журнал раньше первого `join_until`.
- [ ] `Stoppable` с `close()`: после успешного `join_until` `close()` вызван ровно один раз; у выжившего — ни разу.
- [ ] Вызываемое бросает `RuntimeError("boom")` → в `errors` пара `("root/x", "RuntimeError: boom")`; записи,
      зарегистрированные раньше, освобождены.

## G1 (a)–(f)
- [ ] (a) `gc.collect()` до `gc.disable()`. Презентер подписан bound method в список издателя, отписка — `own` в
      области. После `close()` и `del презентер` слабая ссылка на презентер мертва без `gc.collect()`. Мусор
      считается только по типам самого теста (`gc.DEBUG_SAVEALL` + фильтр `gc.garbage` по классам теста) — ноль.
- [ ] (b) Поток игнорирует стоп 3 с, бюджет 1.0, резерв 0.0: `close()` возвращается за ≤ 1.2 с;
      `"root/w" in report.survivors`; `live()` содержит `{"path": "root/w", "kind": "thread", "state": "survivor"}`.
- [ ] (c) `own(cb, …)` после `close()` → `cb` вызван до броска, `ScopeClosedError`; то же для `own` из
      вызываемого фазы 2 этой области (закрывающаяся); `spawn` во время `close` → `ScopeClosedError`, `target` не
      вызван.
- [ ] (d) Тестовый издатель обходит снимок подписчиков и пропускает неактивных; подписчик B зовёт `scope.close()`,
      область владеет отпиской C → C не получает текущую рассылку. Вызываемое фазы 2 зовёт `scope.close()` той же
      области (бюджет области 1.0) → внутренний вызов возвращается за ≤ 0.1 с с `complete=False`; внешний отчёт
      `complete=True` (внутренний в него не сливается).
- [ ] (e) Корень `budget_s=1.0`; первый `close` идёт ≥ 0.3 с (ресурс выходит через 0.3 с после `request_stop`);
      второй `close()` из чужого потока стартует через 0.05 с → возвращается после первого, `r2 is r1`. Второй
      `close(budget_s=0.05)` из чужого потока → `complete=False`.
- [ ] (f) `spawn`-поток зовёт `close()` своей области → возврат без дедлока за ≤ бюджет + 0.2 с;
      `"root/w (self)" in report.survivors`; `"root/w" not in report.killed`. То же для `spawn`-потока
      дочерней области, закрывающего корень.
- [ ] (f2) Поток `M` закрывает корень (бюджет 1.0); поток `spawn` ребёнка `c` в ответ зовёт `root.close()` → его
      вызов возвращается за ≤ 0.1 с с `complete=False`; `close` у `M` — ≤ 0.2 с.

## Сроки (Q3)
- [ ] Корень `budget_s=1.0`, ребёнок `budget_s=0.2` с застрявшим ресурсом (без `kill`) → фаза 2 ребёнка кончается
      за ≤ 0.35 с от начала (не 1.0).
- [ ] Корень `budget_s=0.3`, ребёнок `budget_s=2.0` с застрявшим ресурсом → `close()` корня ≤ 0.45 с.
- [ ] Два застрявших `Stoppable` с `kill()` (умирают через **0.3 с** после `kill`) в одном сегменте, бюджет 0.3,
      резерв 0.5 → оба в `killed`; `elapsed_s ≤ 0.3 + 0.5 + 0.1`.
- [ ] Два сегмента, в каждом застрявший `Stoppable`, чей `kill()` не убивает; бюджет 0.2, резерв 0.3 →
      `elapsed_s ≤ 0.2 + 0.3 + 0.1`; оба в `survivors`.
- [ ] Следствие общего `K`: два сегмента; верхний — неубиваемый застрявший (бюджет 0.2, резерв 0.3); нижний —
      `Stoppable`, останавливающийся через 0.01 с после `request_stop` → нижний в `survivors` (очередь дошла после
      `D`, одна проверка без ожидания).
- [ ] `kill_reserve_s=0.0`, ресурс умирает через 0.05 с после `kill` → `kill()` вызван, запись в `survivors`, не
      в `killed`. Тот же ресурс при резерве 0.3 → в `killed`.
- [ ] `own` из вызываемого фазы 2 закрывающейся области (бюджет 0.3, резерв 0.0) упрямого `Stoppable` без `kill` →
      `ScopeClosedError`; путь его записи в `survivors` отчёта внешнего `close`; reporter вызван 1 раз; внешний
      `elapsed_s ≤ 0.3 + 0.1`.
- [ ] `IHandle.close()` без аргумента берёт бюджет и резерв области: застрявший `Stoppable`, умирающий через 0.05 с
      после `kill()`, в области `budget_s=0.2, kill_reserve_s=0.3` → в `killed`, `elapsed_s ≤ 0.6`.

## Барьер и `cancel`
- [ ] Нижний сегмент — сток, дренирующий при `request_stop` (закрыть вход → дописать очередь → выйти); `barrier()`;
      верхний сегмент — вызываемое, пишущее в сток финальную строку, и поток, пишущий N = 200 строк. После
      `close()` сток получил 201 из 201.
- [ ] Журнал вызовов: `request_stop` записи нижнего сегмента позже последнего события фазы 2/3 верхнего.
- [ ] Вложенный барьер (вариант A, ревью р1 Б2): у ребёнка `c` записи `x | barrier | y`; `root.close()` → в журнале
      `request_stop(x)` позже фазы 2 записи `y`. То же при прямом `c.close()`.
- [ ] `cancel()` при двух сегментах: `request_stop` получили только записи верхнего сегмента (и верхние сегменты
      его дочерних областей, рекурсивно); возврат ≤ 50 мс при застрявших ресурсах; повторный `cancel()` не зовёт
      `request_stop` снова; `own` после `cancel()` работает; `live()` верхних записей — `"stopping"`.

## Handle
- [ ] `handle.close()` дважды → ресурс освобождён один раз; `r2 is r1`; записи нет в `live()`.
- [ ] После `handle.close()` (при `gc.disable()`) удалённый владельцем ресурс собирается refcount'ом: `Handle` его
      не держит.
- [ ] Досрочный `child.close()`: ребёнок отцеплен от родителя (нет в `live()` родителя), reporter вызван один раз.

## Reporter
- [ ] `close()` корня с ребёнком и тремя записями → reporter вызван ровно 1 раз, аргумент `is` возвращённый отчёт.
- [ ] Досрочный `handle.close()` → reporter вызван 1 раз с отчётом `ok`.
- [ ] Reporter бросает → `close()` возвращает отчёт без исключения; в `logging` одна запись уровня ≥ WARNING.
- [ ] Отчёт корня содержит пути выживших из поддерева (`"root/c/w"`).

## `unclosed_roots()`
- [ ] Живой незакрытый корень `p1` → `{"path": p1, "state": "open"} in unclosed_roots()`; ключи каждого словаря
      ровно `{"path", "state"}`.
- [ ] Корень `p2` создан, ссылка удалена без `close`, `gc.collect()` → `{"path": p2, "state": "abandoned"}` в
      списке; слабая ссылка на корень мертва.
- [ ] Закрытый корень `p3` — ни живым, ни после `del` + `gc.collect()` в списке нет. Дочерняя область в списке
      не появляется никогда. Пути в тестах уникальны (`uuid`), проверка — через `in`.
