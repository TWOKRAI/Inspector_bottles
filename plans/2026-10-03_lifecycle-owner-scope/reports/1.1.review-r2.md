## Замечания
- [minor/design] Приведение `timeout` в DESIGN 7 превращает `inf` («ждать без срока») в `0.0`, то есть в немедленный terminate. Модель `sim2.py` на настоящем `open_scope`: процесс уходит по событию через 0,3 с, `timeout=float('inf')` → `signals=[('terminate', 0.0)]`, `killed=('pm/stop/children',)`. Graceful-выхода нет. Старый `_stop_many` дождался бы выхода по событию.
  Правило к тому же расходится с DESIGN 8: у `spawner.stop` `inf` заменяется умолчанием с предупреждением.
  Не сказано, что делать с `bool`, `None` и строкой. «Как есть» пропустит `True` в `open_scope`, а `_seconds` (`lifetime.py:51`) бросит `TypeError` — вопреки «новых исключений на пути стопа нет».
  Исправить: `≤ 0` → `0.0` (прежняя семантика); NaN и `inf` → `DEFAULT_SHUTDOWN_TIMEOUT_S` с предупреждением, как в DESIGN 8; нечисловое и `bool` — явно туда же.
- [minor/form] Фраза про `survivors()` в DESIGN 5 читается двояко. Сначала: «делает один проход наблюдения (метит … каждого умершего)». Затем: «свежий `is_alive()` для результата не используется: процесс, умерший после последнего прохода, остаётся выжившим и без метки». Проход и есть свежий `is_alive()`. Если «последний проход» — последний проход `join_until`, фраза противоречит имени теста из REDS `test_late_death_after_deadline_is_marked`.
  Моя модель по первому прочтению (S7: X умирает через 20 мс после срока области) → `result={'X': True}`, `mark_at=2.547`, то есть `True ⇒ метка` держится. По второму прочтению → `False` без метки, и тест тестера краснеет на верном коде.
  Исправить: «результат — по набору подтверждённых ПОСЛЕ прохода самого `survivors()`; без метки остаётся только умерший позже этого прохода». Реестр зовёт `survivors()` один раз, лог и результат строит из одного кортежа.
- [minor/form] Свойство «настоящий kill не раньше `terminate_grace_s`» (инъекция, строка 25; REDS `test_escalation_waits_terminate_grace`) при новой границе верно только при сроке `deadline ≥ начало + terminate_grace_s + kill_confirm_s`. Модель D1: `kill(); join_until(now + 1.5)` → kill на 0,516 с, это граница `deadline − kill_confirm_s`. Модель D2: `join_until(now + 3.0)` → kill на 1,016 с. Тестер пишет вслепую; при сроке 1,5 с его тест будет красным на верном коде.
  Исправить: строка в TRAPS — «тест окна terminate→kill: срок `join_until` не меньше начало + 2,0 с; при меньшем сроке kill по границе `deadline − kill_confirm_s` верен».
- [nit/fact] Причина в DESIGN 8 «так PM читает 0 как 5,0» к `stop(timeout=X)` не относится. `X` до PM не доходит: он меняет только join спавнера (`spawner.py:177-197`). Graceful PM берёт из конфига, записанного при запуске (`spawner.py:105-106`). Само решение (`X ≤ 0` → умолчание) безвредно. Исправить в тексте для ADR: «`X ≤ 0` как бюджет бессмыслен; умолчание держит внешний бюджет ≥ внутреннего для конфига PM по умолчанию».
- [nit/form] В сигнатуре конструктора (DESIGN 3) нет `kill_confirm_s`; он добавлен только в DESIGN 5 («конструктор получает ещё»). Исправить: дописать параметр в DESIGN 3.
- [nit/dryrun] Инъекцию «имя без события получает `set()`» (строка 38) написать нельзя: у такого имени нет объекта события. Возможно, имелось в виду «мёртвый получает `set()`» или «имя без события получает `terminate` в `request_stop`». Исправить: назвать одну.
- [nit/context] Docstring `tables.py:3-6` («скопировано один в один из `0.5a.allowlist.tsv`… ничего не выведено и не добавлено») после 1.1 станет ложным: 4 записи удалены, 14 причин переписаны. Исправить: строкой в том же файле (он уже в FILES) — «правлено в 1.1».
