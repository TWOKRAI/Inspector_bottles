## 3. Конкурентность (зонд ревьюера, код коммита без правок)

Скрипт в scratchpad. Область-подделка: `close()` бросает `KeyboardInterrupt`/`SystemExit`. Настоящая `Scope`: `open_scope(...).child("mgr")` и вызываемая запись, которая бросает `KeyboardInterrupt`.

```
WAITER: second alive while body runs = True | first_err = KeyboardInterrupt('close-stop') | second = False | second returned after release: 0.000 s | second before hook end = False
REENTRANT: done = True | outer error = SystemExit('close-exit') | inner = False | inner_dt = 0.0000 s
REAL SCOPE: done = True | error = KeyboardInterrupt('real-close-stop') | on_shutdown calls = 1 | child.closed = True | second = False dt2 = 0.0000
REAL SCOPE: subtree-thread shutdown() = False dt = 0.0000 s
REAL SCOPE: lines = ['shutdown rv_real: scope.close прерван: KeyboardInterrupt: real-close-stop']
```

Итог: ждущий из другого потока ждёт, пока тело работает, и получает `False` сразу после конца первого вызова. Реентрантный вызов из тела — `False` за 0,0000 с. Поток поддерева настоящей области — `False` за 0,0000 с. Состояние «идёт» и поток первого вызова остаются согласованы, пока тело работает внутри обработчика.

## Что осталось открытым / ненадёжным

- **Настоящая `Scope` после `KeyboardInterrupt` в вызываемой записи** (вне FILES; поведение `lifetime.py` существовало до этой задачи). Зонд: `child.closed = True`; поток `spawn`, который игнорирует стоп 1,0 с, жив после прерванного `close()`; `root.close()` за 0,000 с даёт `survivors = ()`, `errors = ()`, а поток всё ещё жив. Поток не виден ни в отчёте, ни в G3/G4. На пути 1.2b-ki тело подкласса работает при живом потоке области. ADR допускает это словами «область могла не закрыться», но выжившего никто не учитывает. Предлагаю лиду записать это в `docs/claude/OPEN_QUESTIONS.md` или открыть отдельную задачу; решение — выше этой задачи.
