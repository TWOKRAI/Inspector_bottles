# 1.2b-1 — вердикт CTO: хранение области менеджера (cto `a02acbb13114fb2ea`, 2026-10-12)

Эскалация ревью кода р.1 п.3. Дерево `lifecycle-impl-1.2b` не менялось; симуляции — scratchpad `cto/` (`repro.py`, `opt_a.py`, `opt_c.py`, `pickle_c.py`). Текст перенесён лидом.

**Вердикт: C** — запись жизни в `__dict__` менеджера (сильная ссылка на область), без модульного `WeakKeyDictionary`; pickle — `_ManagerLife.__reduce__ → (_ManagerLife, ())`.

## Причина

Цикл «глобал `_lives` → значение → область → `_parent` → замыкание `_attr_call` (захватывает `self`) → `ProcessModule` → менеджер-ключ» есть у КАЖДОГО менеджера корня уже сегодня: Р7 (б) делает ключ вечным, пока корень не закрыт, G3 слеп — дефект механизма; B лишь документирует (против fix forward). A рвёт цикл, но меняет контракт: в пути через корень область уходит из менеджера ДО его `shutdown()`, `_on_shutdown` видит `None`, G-11b тестера краснеет, корень без другого владельца умирает сразу. C убирает глобальный якорь: цикл менеджер ↔ область — обычный мусор gc, G3 видит брошенный корень, G-11b держится, уходят модульный лок и зависимость от `__hash__/__eq__`; три чужих `__getstate__` (`observable_mixin.py:917`, SRM `:471`, `events/core/manager.py:271`) — `__dict__.copy()` минус список, неизвестный ключ проходит.

## Что делает исполнитель (`base_manager/core/base_manager.py`)

1. `_ManagerLife.__reduce__(self): return (type(self), ())`.
2. `_life_of(manager, create)`: `manager.__dict__.get("_bm_life")`; создание — `manager.__dict__.setdefault("_bm_life", _ManagerLife())` (атомарно под GIL; работает и для `cls.__new__`). Имя `_bm_life` (`Services/code_reader/core/sdk_reader.py:81` уже держит `self._life`).
3. `attach_scope`: под `life.lock` проверка и запись; `scope` — `life.scope` или `None`. Удалить `_lives`, `_lives_lock`, `import weakref`.
4. ADR-BM-009: Р7 (б) → (в), отвергнутое (б) с причиной; убрать «Отложенное» про `__hash__/__eq__`. Тест 32 классов на weakref/hash больше не контракт — решает лид. `interfaces.py` не меняется.

# Второе решение CTO — пути наблюдаемости (2026-10-12)

## 1. Шаблон пишет обе строки только через вид `FallbackLogger(__name__)` — APPROVE

| случай (`_on_shutdown` бросает) | как закоммичено (`1635c7b2a`) | только вид |

| A: миксин без логгера | writer +0, stderr нет — потеряна | stderr (+ буфер, сливается в писатель при подъёме) |
| W: миксин, логгер подключён | +1 | +1 |

## 2. Дрейф (две дороги к одному писателю) — дефект, отдельная задача — APPROVE с поправками

- (1) Падение на вид при «слота нет / `None`» — в `_log_checked`/`_log_*`, не в общем `_call_manager_result` (у слотов `error`/`stats` вида нет).
- (1c) «Менеджер закрыт» — чинить в писателе: `log()` после `LoggerManager.shutdown()` → lastResort stderr в одном месте (`logger_manager.py:51-72`).
- (2) `ProcessModule._log_*` → `bool` из `super()`.
- (3) Шаблон → `report_error(exc, context="shutdown")` через хук `BaseManager._report_shutdown_failure(exc)` (по умолчанию вид; `ObservableMixin` переопределяет), только для строки с исключением; строго ПОСЛЕ (1)+(2).
- (4) ADR в `logger_module/DECISIONS.md` «одна дорога к писателю».
- Дом: `plans/observability-closure/phase-4-scale-and-form.md`, новая задача рядом с Task 4.13 (хозяин шва `_log_checked`). В очереди владельца `14b610faf` плана нет — слот решает владелец (`docs/claude/OPEN_QUESTIONS.md`).

## 3. Уточнения к карте

- «вид +2 не разобран» — разобрано: ранний буфер 1 запись + вызов → +2, дальше +1. Слив, не двойная запись.
- «буфер сливается в файл при подъёме» — в писатель при первой записи вида после подъёма.
- Порог уровня (b2) запуском не проверен ни ревьюером, ни CTO (проба сломана: `TypeError: LoggerCore.is_enabled_for() missing 'level'`).
- Плоскость ошибок — второй экземпляр `LoggerCore` другого стора; против правила «один писатель» владельцу назвать прямо.

## Что осталось открытым / ненадёжным

- Порог уровня и слив буфера в файл — не проверены запуском.
- `report_error` в останове: окно голоса подавит второй одинаковый отказ (факт останется) — вопрос владельцу при (3).
- (1c) — по коду, прототипа нет. Боевой конфиг не поднимался.
