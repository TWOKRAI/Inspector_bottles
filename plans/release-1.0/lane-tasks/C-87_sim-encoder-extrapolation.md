# C-87 — сим рисует диск непрерывно: досчёт энкодера между пачками

Заведено 2026-11-11 лидом приёмки α по решению владельца («как лучше и правильно, без костылей»). Владелец кода — полоса сима (`Plugins/sim/scene_source`, `Plugins/sim/robot_host`, `apps/line_sim`; точную полосу сверить по `plans/queue/ORDER.md`). Лид приёмки код не пишет. Диагноз — `amendments.md` запись 20.

## Проблема (воспроизведено по журналам, механизм — по коду)
`scene_source` рисует диск по ПОСЛЕДНЕМУ пришедшему значению энкодера без экстраполяции (`plugin.py:32-38, 1060-1071`). Значение приходит пачками раз в 0,12 с (`delta_dispatcher.py:35, 278`; публикует `robot_host/plugin.py:707`). Диск стоит ≈ 3 кадра и прыгает на 16,5…24,7 px вместо 6,6 px за кадр. У живой камеры лента движется непрерывно, так что сим врёт про физику. Следствие: съём по `line_filter zone_edge` приходит на 0…3,75 кадра позже входа, окно §2.8 (`py` −344,0…−342,0) выполняется у 10 из 41 заданий.

## DESIGN
- В `_read_world_encoder` вернуть `value + mm_s·(now − t)`, пересчитанное в единицы энкодера. Поля `mm_s` и `t` уже есть в дельте `sim.belt.encoder`. **Единицы:** `mm_s` — мм/с, `value` — единицы энкодера; коэффициент брать из модели ленты (`core`/конфиг), не подставлять мм/с напрямую. Показать в ADR, откуда коэффициент.
- Часы: `t` пишется `time.monotonic()` в процессе `robot_host`, читается в `scene_source` — другой процесс. Проверить и записать в ADR: `monotonic` общий для процессов одной машины на macOS, Linux, Windows; для разных машин не годится.
- Границы досчёта: (1) возраст дельты больше `stale_ms` — не продолжать экстраполяцию дальше `stale_ms`, оставить предупреждение; (2) `mm_s = 0` и пауза ленты — позиция не движется; (3) реверс и скачок энкодера назад, новая дельта с меньшим `value` — позиция берётся из дельты, без «доезда» вперёд; (4) отрицательный возраст (`now < t`) — 0.
- Определение: монотонность позиции между двумя соседними кадрами при постоянной скорости; шаг между кадрами = `mm_s·Δt_кадров`, а не «ноль, ноль, прыжок».
- Записать **ADR** (локальный `DECISIONS.md` модуля): решение «не экстраполяция» (`plugin.py:32-38`) отменяется, причина — запись 20.
- НЕ менять: рассылку состояния фреймворка (`delta_dispatcher.py`, принятая цена, `state_store_module/DECISIONS.md:727-731`), окна §2.8, `line_filter`, `pixel_to_robot`.

## REDS (до кода; слепой `tester` пишет по этим критериям, не читая `plugin.py`)
1. Дельта `value=1000, mm_s=20, t=T`; чтение в `T+0,06` возвращает значение со сдвигом, равным 0,06·20 мм в единицах энкодера; в `T+0,12` — 0,12·20 мм. Числа выписать литералами, не считать кодом проверяемого.
2. Чтения в `T+0,00 / 0,04 / 0,08 / 0,12` дают монотонно растущие значения с равным шагом (а не три одинаковых и прыжок).
3. Возраст `> stale_ms`: сдвиг не больше `mm_s·stale_ms` и есть предупреждение.
4. `mm_s = 0`: значение равно `value` при любом возрасте.
5. Приход новой дельты с меньшим `value`: чтение равно новому `value` плюс досчёт от его `t`, назад не «доезжает» к старой траектории.
6. `now < t`: сдвиг 0.
7. Одна проверка с настоящими объектами: `robot_host` публикует, `scene_source` читает через реальный `state_proxy`, без двойников; кадры камеры за 1 с — шаг положения диска между соседними кадрами в пределах ±1 px от среднего (литерал порога — в тесте).

## Break-injection (предсказания записать ДО прогона)
Убрать досчёт → RED 1, 2, 7. Убрать ограничение по `stale_ms` → RED 3. Убрать обработку `mm_s = 0` — при коэффициенте 0 тест 4 зелёный сам; тогда в брифе сказать, что гарантия держится умножением и отдельной инъекции не требует (написать это явно, не молчать). Вернуть `value` из «старой» дельты после новой → RED 5.
