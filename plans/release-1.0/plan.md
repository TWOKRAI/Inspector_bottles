## Контекст

Решения 23 и 24 (`plans/queue/decisions.md:34-35`): оператор вводит слово, диски с буквами едут по одному; подходящую
букву робот v2 берёт, доворачивает и кладёт в ячейку слова; неподходящая уезжает. Брака нет. План даёт проверяемое
определение «1.0 готово»: веха α (сим, журнал) и веха β (железо). **Механизмов этот план не владеет**: его задачи —
сверка, прогон, вердикт. Для α он заказывает два механизма у чужих владельцев — line-sim «диски по списку {буква, угол}»
(находка 1) и word-layout «запись пропуска + перевзвод на новый физический диск» (находки 2, 3); строки очереди под них
запрошены у координатора. Без line-sim — α по запасному пути (`design.md` §2.9). Спецификация — [`design.md`](design.md).
Сверено с `main` = `45e40ca7e`.

## Ответы на вопросы очереди

**line-sim (ORDER #4).** Нет: сим не подаёт диски с заданной буквой и углом. `render` зовётся без `class_index`
(`Services/line_sim/core/factory.py:55`), хотя `layer_render` его принимает (`Services/layer_render/factory.py:116-135`,
`6348d35e2`); угол — всегда `uniform(angle_range_deg)` (`:189-193`); команд выбора диска нет (`Plugins/sim/scene_source/plugin.py:175-186`);
`preset.commit` фиксирует угол всем сразу и пишет отслеживаемый файл (`:693-712`). Нужна одна задача line-sim (находка 1);
решение 17 это допускает — только то, что нужно 1.0. Запасной путь — порядок по `seed` (`design.md` §2.9).

**robot-calibration F4/F5 (ORDER #30).** F4 поглощена, для 1.0 не нужна: `reject → image_to_robot` в 1.0 заменяет цепочка
`pixel_to_robot` (`Plugins/processing/pixel_to_robot/plugin.py:126-160`) → съём `word_layout` (`word_layout/plugin.py:167-202`)
→ `robot_io` (`Plugins/io/robot_io/plugin.py:164-184`); отбраковки нет (решение 24); флаг калибровки — регистр `loaded`
(`pixel_to_robot/plugin.py:86-96`); телеметрия в state — `devices.state.<id>.status` (`Plugins/hub/device_hub/plugin.py:519-520`).
F5 — 2.0, подтверждаю: камера одна (решение 24), линейный режим рецепта файл калибровки не читает (`pixel_to_robot/plugin.py:89-96`).
