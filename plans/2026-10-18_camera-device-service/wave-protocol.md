# Протокол волн — camera-device-service (пилот режима волн)

Часть плана [`plan.md`](plan.md). Решение владельца 2026-10-18 — **только для этого плана**: отступление от
`.claude/CLAUDE.md` «Task launch convention» (ревью после каждой задачи, стадия 0 Opus). Причина — скорость и стоимость;
W1 — пилот, по его метрикам владелец решает, оставлять ли режим. `.claude/CLAUDE.md` не меняется.

## Цикл одной волны

1. Лидер пишет прогнозы break-injection для механизмов волны в `tasks/<id>.md` (до запуска).
2. Стадия 0 (Sonnet) — синхронно, по одной на задачу из списка 9; блокер -> правка текста задачи, затем Opus сразу после задачи.
3. Слепой тестер (Sonnet) — для механизмных задач, в worktree на коммите до кода; RED передаётся исполнителю.
4. Исполнители (Sonnet) — не больше 3 одновременно, только пары с непересекающимися `Files:`.
5. Инъекции (Haiku) — только механизмы: поток-владелец (2.1), проверка чтением и run/rest (2.2), subscribe-цепочка (2.4), FieldMeta `apply`/`enabled_if` (1.1).
6. Opus-ревью сразу — 2.1, 2.2, 2.4, 4.2a.
7. Ревью волны (Opus, один агент) — общий diff волны; раунд 2 — тот же agentId.
8. Коммиты лидера (по задаче; К4' — один коммит); прогон `medium` по затронутым каталогам тестов.
9. Граница волны: `/clear` + handoff `docs/handoffs/<дата>_camera-wave<N>.md` с таблицей agentId, SHA, метриками волны.

## Эскалация

Лестница: Sonnet-исполнитель -> (Sonnet стадия 0) -> Opus (лидер / ревьюер волны) -> `cto` (Fable) -> владелец.
Вопрос идёт на уровень выше, не вбок и не догадкой. Формат:

```
ESCALATION -> <роль>
Question: <один вопрос, на который отвечают решением>
Tried: <что пробовали, с наблюдаемым выводом>
Blocked on: <какое решение или факт нужен>
Files: <пути>
```

- Лимит — 2 итерации на любой цикл (2 раунда ревью или 2 неудачные попытки правки); на 3-й — уровень выше.
- Если Opus (лидер или ревьюер) не закрыл задачу или спор за 2 итерации — на 3-й зовётся `cto`: лидер шлёт одно сообщение в формате эскалации с фиксированным SHA.
- Лимит ходов Sonnet (~30): обрыв без отчёта — дозвать тем же agentId; это не провал итерации. Два обрыва подряд на одной задаче — разбить задачу и эскалировать к Opus.

## Метрики пилота (пишет лидер в handoff каждой волны и в `amendments.md` после W1)

| Метрика | Как считать |
|---|---|
| токены на волну | сумма `total_tokens` агентов волны (`agent_report.py`), отдельно Opus / Sonnet / Haiku |
| дефекты ревью волны | число находок ревьюера волны с воспроизведением |
| дефекты, всплывшие позже | найденные в следующих волнах или на стенде в коде этой волны |
| переделки | число повторных запусков исполнителя по задаче |
| вызовы `cto` | сколько раз и причина |
| обрывы Sonnet | сколько дозывов по agentId |
