# Task 2.1 — прогнозы break-injection (лид, 2026-11-15, ДО прогона)

Механизм — «поток-владелец». Прогнозы написаны по именам тестов и тексту ACCEPTANCE; результаты самопроверки исполнителя (4 инъекции) лид к моменту записи уже видел — поэтому I5–I8 добавлены новыми и независимы от них. Тесты: `test_session_lifecycle.py` (слепой, 10) = T-имена, `test_session_lifecycle_hazards.py` (автор, 10) = H-имена. Откат — `cp` с копии, не `git checkout`; прогон по одной инъекции.

| # | Инъекция | Прогноз: красные тесты (минимум; «+» — возможны ещё) |
|---|---|---|
| I1 | `open` (и `acquire`/`enum_devices`) вызывается в потоке вызывающего `start()` | `test_один_поток_владелец` (+ журнал-литералы по потоку, + hazards) |
| I2 | `close` вызывается прямо из `stop()` (поток вызывающего) вместо владельца | `test_один_поток_владелец` (+ `test_журнал_старт_стоп`, `test_стоп_из_on_frame`) |
| I3 | `stop()` держит замок состояния на `join` владельца | `test_старт_во_время_stopping` (числовая граница < 0,1 с) (+ `test_старт_прерван_стопом`) |
| I4 | сторож без флага «уже сообщено» | `test_сторож_один_раз` (и только он) |
| I5 | после `open` не проверяется `cancelled`/`stop` (откат не выполняется) | `test_дедлайн_старта`, `test_старт_прерван_стопом` |
| I6 | счётчик ошибок кадра не сбрасывается на `None` | `test_три_ошибки_подряд` (сценарий C «err, none, err, none, err») и только он |
| I7 | `stop()` из потока владельца (из `on_frame`) делает `join` владельца | `test_стоп_из_on_frame` (зависание, daemon-дедлайн 2 с) |

Правило сверки: «ровно» там, где написано «и только он»; в остальных строках прогноз — нижняя граница, лишние красные — наблюдение, не провал прогноза. Исполнитель патчит свои файлы, лид читает таблицу «наблюдалось vs прогноз».

## Результат прогона (исполнитель, `docs/reviews/2026-11-15_task-2.1-injections.md`)

Совпало 7 из 8. Откат `cp`, diff чист после каждой. Лишние красные в I1, I2, I3 — наблюдения (прогноз — нижняя граница).
- I4, I5, I6 — «ровно» совпало. I7: красный `test_стоп_из_on_frame` в обоих вариантах; литеральный `join` из потока владельца даёт `RuntimeError: cannot join current thread`, которое `on_frame` теста ловит — настоящее зависание воспроизводит вариант «ожидание `while is_alive()`» (17 с).
- **I8 — расхождение (недооценка покрытия, ошибка прогноза лида):** `test_старт_пока_владелец_жив` зовёт `start()` из `on_state` в потоке владельца, поэтому отказ идёт по проверке «вызов из потока владельца», а не по флагу `_held`; ветку `_held` ловит только hazard автора из другого потока (`test_старт_при_живом_владельце_в_error_из_другого_потока`). «И только он» нарушено: прогноз надо было писать после чтения тела теста, а не по имени.
