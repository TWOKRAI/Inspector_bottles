DESIGN (decided by the lead — you type it, you do not derive it):
  **Интерфейс** (из 2.1): `DeviceSession(..., run=Sequence[Step], rest=Sequence[Step])`, `Step(field, binding, value, skip, parent)` из 1.6 — планы приходят готовыми (их строит плагин через `build_plan`); тесты 2.2 собирают `Step` руками. Состояние — свойства сеанса (копии под замком): `params: dict[str, scalar]`, `params_status: dict[str, {"verified": bool, "rc": str | None}]`, `param_errors: dict[str, str]`, `errors: int` (общий счётчик 2.1).
  **Где код:** логика профилей — `profiles.py` (≈ 120 строк: `apply_step`, `apply_plan`, `within_tolerance`, ветки rest); `session.py` +≤ 30 строк (вызовы в точках `_apply_run()` / `_apply_rest()` из 2.1). Один примитив `apply_step(step) -> None` (запись узла + чтение + классификация) и `apply_plan(steps)` для любого списка шагов — его же зовёт `apply(fields)` из 2.4.
  **Запись и чтение.** Run: между `open` и `start_grabbing`, шаги по порядку плана; `skip` -> шаг не пишется, INFO `skip=<причина>`. После КАЖДОГО `set_param` (в том числе упавшего) при capability `read_back` зовётся `get_param`; исходные значения не читаются. `inc` узла берётся один раз перед первым `set_param` узла: при `"node_describe"` в `port.capabilities` — `port.describe_param(binding).inc`, иначе `None` (`Binding` не расширяется; `describe_param` значение не читает и «чтением исходных» не считается).
  **Допуск (Р6, уточнение лида 2026-11-15, амендмент 3)** — ветвление по `Binding.vtype`, не по `isinstance`: `float` — `|r−t| ≤ max(inc or 0, 1e-3·|t|, eps_abs)` (`eps_abs=1e-6` по умолчанию в `Binding`, ревью B2); `int` — `|r−t| < max(inc or 1, 1)` (при `inc=1` — точное равенство; относительный член не применяется; при `inc>1` устройство округляет вниз — промах меньше шага принимается); `enum`, `bool`, `string` и прочие — `r == t`, enum сравнивается как имя элемента (драйвер отдаёт из `get_param` имя, не число); чтение `1` при цели `"On"` — не подтвердилось.
  **Классификация результата записи:** (rc = `exc.kind` или `None` без исключения; код SDK — только в лог `code=0x…`) — ok + чтение в допуске -> `verified True`; ok + вне допуска -> `param_errors[поле] = "не подтвердилось чтением"`; исключение + чтение = цель (H5) -> `verified True`, `rc`, WARNING `значение на месте`; исключение + чтение ≠ цели -> `param_errors[поле] = "<kind>"`; чтение бросило -> `param_errors[поле] = "чтение не удалось: <kind>"`, `verified False`; без `read_back` и запись упала -> `param_errors[поле] = "<kind>"`; без `read_back` и запись прошла -> `params[поле] = цель`, `params_status[поле] = {"verified": False, "rc": None}`. `params[поле]` — скаляр (прочитанное; без `read_back` — цель; Р6), статус — в `params_status`. Отказ узла не прерывает план. Потомок отказавшего родителя (`Step.parent` лежит в `param_errors` этого прогона) не пишется: INFO `skip=пропущен: родитель не записан`, в `param_errors` не добавляется. Текст ошибок значений рецепта не содержит (Р6); значение допустимо только в INFO/WARNING-строке `apply …`, не в `param_errors`/`last_error`/ERROR.
  **Жизненный цикл состояния:** `params`, `params_status`, `param_errors` сбрасываются в начале run каждого `start()`; rest дописывает; `errors` не сбрасывается и растёт на 1 за каждый узел, попавший в `param_errors`.
  **Rest** (capability `restart_regrab`): выполняет владелец после выхода из цикла кадров; при `restart_regrab` — после `stop_grabbing` и до `close`; иначе (ветка H1) — `stop_grabbing, close, open, rest, close`. Отказ rest растит `errors`, `close` — всегда после удавшегося `open`; упал `open` ветки reopen -> `close` не зовётся, `errors += 1`. Состояние `error` (3 ошибки кадра) — rest не выполняется. `stop(timeout)` ждёт не дольше `timeout` (2.1), rest доделывает владелец, `state == "closed"` — после `close`. Отказ узла run не мешает `start_grabbing`, `start()` -> `True`.
  **Наблюдаемость:** `on_timing("apply", секунды)` по полю (СЕКУНДЫ; `ctx.record_timing` подключает 2.3b, `apply_ms` у 2.3b убран). Логгер сеанса — `camera_device.session`.
  **Фейк:** опция `read_offset: dict[str, float]` — ключ `Binding.key`; чтение = записанное + смещение для числовых узлов; не меняет внутреннее значение. Для теста допуска без шага узла — `from_recording("Services/camera_device/testing/recordings/mvs_MV-CS020-10GC.json")` (`ExposureTime` `inc=None`, `type float`); узел `ExposureTime` у `make_port()` имеет `inc=1.0` (`fake_port.py:91`).
