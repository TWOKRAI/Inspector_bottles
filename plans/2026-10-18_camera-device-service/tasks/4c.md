# Task 4c: ключ `run_locked_commands: [release_device, take_device]` у узла камеры (этап 2 задачи 2.7d)

- **Level:** Middle (рецепт + тесты; механизм — готовый, в `main`) · **Assignee:** `developer` (sonnet) по точному DESIGN; слепой tester до кода
- **Priority:** P1 (к визиту ≈ 2026-11-22) · **Wave:** вне W4 (W4 не начата, слово владельца «не сейчас») · **Stage0:** reviewer (sonnet) на этом тексте
- **Goal:** в `running` команды `release_device` и `take_device` узла камеры отказывают конвертом `{"success": False, "result": {"status": "error", "error": "running", "message": "сначала ОСТАНОВИТЬ"}}`; вне `running` проходят. Ключ лежит в рецепте, плагин камеры не меняется.
- **Решение владельца (2026-11-20, через координатора `fb`):** список = `release_device`, `take_device`. НЕ блокируются: `apply_params`, `read_params`, `get_status`, `list_devices`, `describe_params`, `reset_stats`, `trigger_software` (живая правка 2.4 остаётся).
- **Gate:** `Services/camera_device/tests` (medium) + `multiprocess_prototype/recipes/tests` (medium); `infra:validate`. · **Dependencies:** 2.7d этап 1 (в `main`: `run_active`, `run_locked_commands` в `plugins/base.py`), 2.3c/2.3d (в `main`). · **Layer:** prototype (рецепт) + Services (тест). · **Module contract:** none

## Факты (проверены чтением HEAD `ad3dc7b72`)

- Ф1. Механизм (2.7d этап 1) в `main`: `git grep run_locked_commands` -> `plugins/base.py`, `plugin_orchestrator.py`, тесты `process_module/tests/test_run_locked_commands.py`. Ключ читается из `ctx.config` плагина ОДИН раз при `_auto_register_commands`; ключ на уровне узла молча игнорируется (2.7d Ф6). Плоская форма в элементе `plugins` и вложенный `config:` дают один `ctx.config` (`_extract_plugin_config`).
- Ф2. Рецептов с `CameraDevicePlugin` ровно один: `multiprocess_prototype/recipes/camera_device_demo.yaml` (`plugin_class: Services.camera_device.plugin_base.CameraDevicePlugin`, `plugin_name: camera_device`, плоские ключи, `auto_start: true`). Рецепты `hikvision_*`, `camera_robot_calibration`, `dataset_circle_capture` ссылаются на СТАРЫЙ `Services.hikvision_camera.plugin.plugin.HikvisionCameraPlugin` (команд `release_device`/`take_device` у него нет: `git grep` по `Services/hikvision_camera/plugin` -> 0 строк) — ключ туда не кладётся (даст ERROR «нет таких команд»); он уйдёт вместе с 4.3 (W4, `plugin_class` меняет 4.2a).
- Ф3. `start(ctx)` при `auto_start` и `shutdown(ctx)` зовут `self.cmd_take_device({})` / `self.cmd_release_device({})` ПРЯМЫМ вызовом метода (`plugin_base.py` около `:349`, `:354`), обёртка охраны стоит на зарегистрированном обработчике — прямой вызов её минует. Значит рестарт ребёнка супервизором в `running` (флаг взведён) открывает камеру по `auto_start`, а graceful shutdown закрывает её при взведённом флаге. Это текущее поведение; задача его не меняет, но тест его фиксирует.
- Ф4. Отказ через relay GUI не виден оператору (2.7d, Out of scope), `apply_params` не блокируется — вопрос открыт и записан в `docs/claude/OPEN_QUESTIONS.md` (запись лида Ф 2026-11-20); задача его не решает.

## REDS (литералы; слепой tester 1–5, автор 6)

Вызов — только `cm.handle_command({"command": …, "data": {}})`. Тест, который может зависнуть, гонит вызов в daemon-потоке с join-дедлайном.
1. Флаг СНЯТ, камера открыта (`get_status.state == "grabbing"`): `release_device` -> успех (`get_status.state == "closed"`); `take_device` -> успех (`"grabbing"`).
2. Флаг ВЗВЕДЁН, камера открыта: `release_device` -> `{"status": "error", "error": "running", "message": "сначала ОСТАНОВИТЬ"}`, `get_status.state` остался `"grabbing"`; флаг взведён, камера закрыта: `take_device` -> тот же отказ, `state` остался `"closed"`.
3. Флаг ВЗВЕДЁН, камера открыта: `get_status`, `read_params`, `describe_params`, `reset_stats`, `list_devices`, `apply_params` (`{"params": {"exposure_time": 5000.0}}` или иное допустимое поле фейка) — все исполняются (ответ без `error == "running"`).
4. Без ключа `run_locked_commands` (контроль) при взведённом флаге `release_device` исполняется.
5. Ключ, кроме `release_device`/`take_device`, не лишнего: `reset_stats` при взведённом флаге -> счётчик `frames` обнулён (исполнена).
6. (автор, hazard) Флаг ВЗВЕДЁН: `plugin.start(ctx)` при `auto_start: true` открывает камеру (`state == "grabbing"`), `plugin.shutdown(ctx)` закрывает её (`"closed"`) — прямые вызовы охрану минуют (Ф3). (автор, рецепт) тест п.3 DESIGN.
