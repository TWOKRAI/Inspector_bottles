## Как определена 1.0 и где определение размыто

- Решение 28 (`plans/queue/decisions.md:39`): «Цель 1.0 — инспекция на двух камерах и двух считывателях … заменяет цель решений
  23 и 24. Лентой управляет ПЛК, инспектор отдаёт сигналы и сообщения; работа по ПЛК — в самом конце. Порядок по камерам — П4».
- П4 (`plans/2026-11-25_multicam-observability/plan.md:313-326`) — порядок 1-9 и «в самом конце — связь с ПЛК».
- **Размыто:**
  1. Приёмки 1.0 нет: ни длительности, ни частоты кадров, ни что значит «инспекция» для считывателя (коды? брак?). У решения 23
     приёмка была («старт с одного рецепта … сбой одного устройства не валит соседей»), у 28 — нет.
  2. П4 не говорит, входят ли пункты 5-9 в 1.0 — только порядок. Ниже я считаю их 1.0, потому что П4 назван «порядком к цели 1.0»
     (`plan.md:315`). Это моё чтение.
  3. ПЛК: «в самом конце» — конец 1.0 или после 1.0? Не сказано.
  4. Робот: решение 28 «заменяет цель 23 и 24», где робот был сутью 1.0. Очередь `ORDER.md` по-прежнему зовёт робота 1.0
     (строки 2, 7-13, 24-26; шапка — «строки 1–27 — 1.0 … решения 23, 24»), строки 29 и 35 зовут ID3013 «2.0» (решение 24), а
     строка 0 прямо просит решение владельца о цели 1.0. Это противоречие — не моё решение.

**Критерии 1.0 — моё предложение (не решение владельца):** рецепт на 2 MVS + 2 ID3013 стартует одной командой; каждый источник
показывает адрес и связь; обрыв любого из четырёх виден в дереве, журнале и на экране за ≤ 5 с и не трогает соседей (fps ±2 %);
с `reconnect: true` источник возвращается сам; правка поля оператором подтверждена прибором или видна как отказ; приёмка на
железе через MCP (строка 0 `ORDER.md`: «правильно, надёжно и легко разбирается»).
