DESIGN (decided by the lead — you type it, you do not derive it):
  1. `freshness.py`: `FRESH_KEY = "_fresh"`; `stamp(seq, src_ts, incarnation, tick_sec) -> dict` ровно с четырьмя ключами
     `seq`, `src_ts`, `incarnation`, `tick_sec`. Значения — как переданы, без проверки и округления.
     `stamp(3, 100.0, "a", 5.0) == {"seq": 3, "src_ts": 100.0, "incarnation": "a", "tick_sec": 5.0}`.
     `src_ts` — `time.time()` писателя. Писатель кладёт метку в `data` последней (это делает 0.9).
     Причина: `time.time` сравним между процессами, `time.monotonic` — нет (у каждого свой ноль, как у `Delta.timestamp`);
     метка идёт после значений, которые заверяет (порядок ключей `data` — порядок дельт, `tree_store.py:305`).
  2. Форма записи. Писатель шлёт одно слияние на корень процесса: `proxy.merge("processes.<name>", {"state": {...},
     "workers": {...}, "_fresh": S})` (`process_heartbeat.py:1590`). Метка — на корне записи: `processes.<name>._fresh`;
     значения — `processes.<name>.state.fps`, `processes.<name>.workers.<w>.effective_hz`. Читатель получает поддерево
     процесса (`subtree` = `processes.<name>`) и ключ: имя листа или путь через точку от `subtree` (`"state.fps"`,
     `"workers.w.effective_hz"`). Метка — всегда `subtree["_fresh"]`.
     Причина: контракт обязан моделировать запись, которую писатель производит; иначе после 0.9 и 0.10b каждая живая
     метрика дала бы `no_data`, а контракт остался бы зелёным.
  3. `classify(subtree, now, alive_incarnation) -> Literal["no_data", "fresh", "stale", "writer_gone"]`. Всюду определена,
     исключений не бросает (исключение в потоке приёма уронило бы весь снимок). Правила — строго по порядку:
       (1) `subtree` не `dict` → `no_data`.
       (2) `subtree.get("_fresh")` не `dict` → `no_data`.
       (3) в метке нет любого из `seq`, `src_ts`, `incarnation`, `tick_sec` → `no_data`.
       (4) `src_ts`, `tick_sec` или `now` не число (`int`/`float`), либо `bool`, `nan`, `inf` → `no_data`;
           `tick_sec <= 0` → `no_data`.
       (5) `alive_incarnation is not None` и `alive_incarnation != incarnation` → `writer_gone`.
       (6) `now - src_ts > 2 * tick_sec` → `stale`. Граница строго `>`: ровно два такта — ещё `fresh`.
       (7) иначе `fresh`. Отрицательный возраст (часы писателя впереди) тоже `fresh`.
     `now` — число читателя; негодный `now` даёт `no_data`.
     Причины: негодная метка — `no_data`, не `stale` (мусор не доказывает ни свежесть, ни её отсутствие); `writer_gone`
     раньше `stale` (ответ «ушёл» полезнее «давно не писал»); два такта — один пропуск шум планировщика, два — потеря
     такта; «задан» — `is not None` (ложное значение остаётся значением, как ноль).
  4. `read_value(subtree, key, now, alive_incarnation) -> {"class", "value", "age_s"}`, всюду определена:
       (1) `classify(...) == "no_data"` → `{"class": "no_data", "value": None, "age_s": None}`;
       (2) `key` не строка; нет сегмента пути; посреди пути не `dict`; значение `None` → тот же ответ;
       (3) иначе `{"class": <класс>, "value": <значение>, "age_s": now - src_ts}`. Без округления.
     `age_s` — одна формула для `fresh`, `stale`, `writer_gone`; отрицательный возраст отдаётся как есть.
     Четыре ответа D1 — разные пары: нет данных (`no_data`, `None`); ноль (`fresh`, `0`); устарело (`stale`, последнее
     значение); писатель ушёл (`writer_gone`, последнее значение).
     Причины: ноль — значение (`if not value` слил бы `fps: 0` с «нет данных»); `None` — отсутствие (0.8 публикует `None`
     для снятой метрики); `age_s` у `no_data` — `None`, не `0` (ноль читался бы «только что»); знак возраста не прячем —
     он показывает перекос часов (1.6).
  5. Экспорт из `__init__.py`: `FRESH_KEY`, `stamp`, `classify`, `read_value`. Чистые функции над `dict`; `now` передаёт читатель.
