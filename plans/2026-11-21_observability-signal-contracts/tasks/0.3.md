DESIGN (decided by the lead — you type it, you do not derive it):
  1. `verdict.py`: `judge(pre, ack, post, target, *, readable=True) -> dict`. Ответ: `verdict` ∈ {`confirmed`,
     `vacuous`, `failed`, `unverifiable`}, `vacuous: bool`, `success: bool`, `pre`, `post`, `ack`, `unverifiable: list`.
     Правила: `readable=False` → `unverifiable`; ack — отказ (`success is False` или статус `error`) → `failed`;
     `post != target` → `failed`; `pre == target` → `vacuous`; иначе `confirmed`. `vacuous = (pre == target)` при любом
     вердикте. `success = verdict in {"confirmed", "vacuous"}`.
  2. Форма следует `config_reload_verified` (`verdict` + `unverifiable`): слова `confirmed`, `failed`, `unverifiable`
     уже живут там; `vacuous` — новое. Срез 2 (Task 2.6) переносит суд на хост, форма не меняется.
  3. Контракт-тест (tester, слепо, подставной драйвер): для каждого инструмента с проверкой — хост отвергает запись
     (`{"success": False, "error": "No handler for register_update"}`), а значение уже равно целевому. Ответ не
     `success`. Инструменты: `set_register_verified`, `register_restore`, `config_reload_verified`,
     `process_restart_verified` (список — `rg` по `backend_ctl/mcp_tools.py` 2026-11-21).
     Тесты на каждый инструмент: `test_rejected_write_not_success` и `test_accepted_write_from_other_value_success`
     (пара; образ до ≠ цель, запись принята → `success`) — 8 тестов.
