     `outcome_of(result) -> Outcome`. Правила: статус `error` → `failed`; `dropped` или `refused` → `refused`; всё прочее —
     `success`, `skipped` (`log_channel.py:1167`), `dict` без `status`, `None`, не-`dict` — → `accepted`.
     `channel_accepted(result)` становится `outcome_of(result) == "accepted"` — поведение бит в бит прежнее.
  2. `channel_routing_manager.py` рядом с `LOSS_COUNTER_KEYS` (:47): `count_outcome(counters, hop, outcome)` — одна
     функция, которая по таблице `LOSS_KEY_BY_HOP` увеличивает ключ потерь. Таблица: `channel` → refused
     `channel_refused_records`, failed `channel_write_errors`; `tap` → refused `tap_refused_records` (новый ключ),
     failed `tap_write_errors`; `bridge` → оба `lost_responses`. Звено не вправе улучшить исход нижнего звена.
