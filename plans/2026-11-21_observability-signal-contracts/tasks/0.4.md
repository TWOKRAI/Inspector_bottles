DESIGN (decided by the lead — you type it, you do not derive it; у каждого шага причина в одну строку):
  1. Общий миксин `_ErrorCapture` (рядом с `_SafeRotatingFileHandler`, выше него): `__init__` зовёт `super().__init__(*args, **kwargs)`
     и ставит `self._last_error = None`; `handleError(record)` сохраняет в `self._last_error` СТРОКУ, не исключение, и в stderr
     не печатает. Для `OSError` строка `"<Класс>: errno <n> <strerror>"` (пример: `"OSError: errno 28 No space left on device"`),
     для остальных исключений и для `OSError` без `errno` (`OSError("msg")`) — только имя класса; если `sys.exc_info()` пуст (вызов вне `except`) — строка `"UnknownError"`, не `None`
     (иначе ошибка маскируется под успех). Миксин — временная конструкция до Task 3.5: пометить комментарием
     «до Task 3.5 (свой писатель заменит)».
     Причина: stdlib зовёт `handleError` из `emit` и печатает «Logging error» в stderr — иначе причина отказа теряется, а строка без
     входного значения не утекает в ответ и в счётчик.
  2. Миксин применить к ТРЁМ классам хэндлера, не к одному: `_SafeRotatingFileHandler(_ErrorCapture, RotatingFileHandler)`;
     к `logging.FileHandler` (ветка `rotate: false` в `FileChannel.__init__`) — тонкий подкласс с миксином; к `logging.StreamHandler`
     (`ConsoleChannel.__init__`) — тонкий подкласс с миксином. Миксин в MRO первым (его `handleError` должен перекрыть stdlib).
     Причина: консоль и `rotate: false` иначе слепы, а контракт-тест (`_scenario_file_channel_enospc`) патчит `stream` у всех 4 каналов.
  3. `FileChannel.write`, внутри замыкания `_emit`: перед `self.handler.emit(log_record)` — `self.handler._last_error = None`;
     после `emit` — `err = getattr(self.handler, "_last_error", None)`. `err` не пуст -> вернуть
     `{"status": "error", "channel": self.name, "error": err}`; пуст -> прежний `{"status": "success", ...}`.
     Читать через `getattr(..., None)` — защитно (подмена хэндлера в тестах или чужой хэндлер без атрибута не должны давать ложный
     отказ через `except Exception` замыкания); отдельной инъекции на это нет.
     Причина: хэндлер общий для каналов одного файла, атрибут общий — сброс и чтение обязаны идти вокруг одной записи.
  4. То же в `ConsoleChannel.write` (`_emit`) — тот же контракт исхода для консольного приёмника.
     Причина: консоль — один из 4 каналов сценария r1; без неё счётчик покажет 2 из 4.
  5. Сброс и чтение — ВНУТРИ `_emit`: он уже исполняется под локом `_guarded_write` (`self._write_lock`: у файла с ротацией это
     `sink_lock` общего ротатора, у консоли и `rotate: false` — частный лок канала). Новых локов не брать; `handler.acquire()`
     ЗАПРЕЩЁН. Причина: ADR-LOG-009 — stdlib берёт `Handler.lock` без предела в `close()`/`flush()`, общий захват делает залипший
     сток вечным; `sink_lock` общий на путь, поэтому два канала одного файла друг друга не перекроют.
  6. Ключ ответа — `"error"`, не `"reason"`. Причина: так в остальных ответах `_guarded_write` и в `test_sink_overload_ladder.py`
     (`result["error"]`): единообразие; менеджер этот ключ не читает, он смотрит только `status`.
  Полный свой писатель (одно форматирование, ротация по байтам) — Task 3.5; здесь только видимость ошибки.
  Счётчик: ответ `{"status": "error"}` менеджер кладёт в `channel_refused_records` (`_write_record_to_channels`,
  ADR-CRM-019, решение 0.1). `channel_write_errors` считает только исключение канала (ADR-CRM-011); `write` его не бросает —
  поэтому ключ `channel_refused_records`, а не `channel_write_errors`.
  Не менять: ADR-LOG-008 (запись синхронная), путь пола ошибок (`errors_to_floor`, `errors_floor.jsonl`), имена счётчиков,
  лесенку `_guarded_write`.
