## Как выключается `_offline_home_isolation` (живой режим — по коду, не прогонялся: окна нет)

1. `request.config.getoption("--backend-live")` истинно (флаг или env `BACKEND_CTL_LIVE`, `conftest.py:135–138`) →
   фикстура возвращается, `HOME` настоящий — условие лида.
2. **Добавил второе условие** (сверх брифа): тест берёт `headless_backend` (`"headless_backend" in request.fixturenames`)
   → тоже без подмены. Причина: `pytest_collection_modifyitems` пускает живые тесты и при `-m harness_smoke` без
   `--backend-live` (`conftest.py:165`); session-бэкенд стартует с настоящим `HOME`, а драйвер теста с подменённым
   `HOME` при переподключении искал бы файл токена во временном каталоге. Условие 2 только сужает подмену; снять —
   одна строка.
3. Порядок: session-фикстура инстанцируется раньше function-фикстур теста, а `monkeypatch` прошлого теста откатан —
   `headless_backend` всегда стартует с настоящим `HOME`.
4. `test_token_client.py` / `test_token_handshake.py` держат `usefixtures("tmp_home")` и в живом прогоне: изолированы
   всегда (`headless_backend` не берут).

## Проверки брифа

- (а) `wait_until_ready` (`system_launcher.py:520`) возвращает True после завершения `initialize()` ПМ;
  `setup_backend_ctl_channel` синхронно внутри `initialize()` (`process_manager_process.py:506`), файл пишется до
  возврата из setup → харнесс подключается при записанном файле. Ретрай в `harness.py` не нужен (по чтению, живьём
  не проверено). Остаточное окно: файл записан, holder ещё пуст (две строки Python) — клиент в это окно получит
  `TokenRejected`; харнесс ловит только `OSError` (`harness.py:483`), `BackendUnavailable` — `RuntimeError`. Залипший
  файл + подключение до перезаписи (между `start()` и `write_token`) → тоже `TokenRejected`; до `wait_until_ready`
  харнесс не подключается, поэтому окно недостижимо из харнесса.
- (б) `scripts/stand_gate/run.py:349,366` и `scripts/capacity_bench/run_case.py:73,81` — через `BackendHarness`.
- (в) `harness.py:414` ставит `BACKEND_CTL=1` в `os.environ`; дочерний бэкенд наследует окружение, включая `HOME` →
  токен пишется под `HOME` процесса харнесса. Для `--backend-live`: `headless_backend` (`conftest.py:176`) — настоящий
  `HOME`; тест с `tmp_home` и живой session-фикстурой разойдутся по путям токена (поэтому `tmp_home` не autouse).
- (г) `SocketClient(` в тестах без провайдера: `frontend_module/tests/test_remote_*`, `router_module/tests/test_socket_client*`
  поднимают свой `SocketChannel` без authenticator — 0.12b их не задевает (через `setup_backend_ctl_channel` не идут).
  Под риском — живые: `backend_ctl/tests/test_frame_bridge_live.py:79` (`SocketClient` к порту живого ПМ без провайдера,
  после 0.12b получит `auth_required`; живой — в окне лида, не прогонял); `Services/robot_comm/tests/test_t38_line_view_acceptance.py:300`
  передаёт `token_provider=file_token_provider(...)` — не под риском.
- (д) Windows `os.replace` по файлу, открытому клиентом на чтение → возможна `PermissionError` → endpoint не поднимется
  (`return None` + ERROR). Не воспроизводилось (нет Windows): открыто.
