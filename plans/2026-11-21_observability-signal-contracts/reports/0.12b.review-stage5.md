### 2. [important] fail-closed-окно между `start()` и записью токена не закреплено тестом

`backend_ctl_endpoint.py:150–181`; `backend_ctl/tests/test_token_handshake.py` целиком. DESIGN 1 и ADR-PMM-052 п. 1
называют это свойство опорным («accept-цикл уже работает; пока holder пуст, authenticator возвращает `False`»).
Свойство **выполняется** (воспроизведено, `exp1.py` раздел A: `write_token` подменён блокирующей заглушкой, порт
слушает, файла нет):

```
raw {"cmd": "system.shutdown"}                  -> {"success": false, "error": "auth_required"}
raw command-shaped system.shutdown              -> {"success": false, "error": "auth_required"}
hello {"token": "aa"*32}                        -> {"success": false, "error": "auth_required"}
hello без токена                                -> {"success": false, "error": "auth_required"}
после отпускания: hello с настоящим токеном     -> {"type": "hello", "success": true}
```

Но все десять тестов вызывают `setup_backend_ctl_channel` до конца и бьют по серверу, когда holder уже полон: мутация
«authenticator принимает, пока holder пуст» (или «authenticator навешен после записи файла») оставила бы все десять
зелёными — по чтению; мутацию я не гонял (прогон инъекций — у лида, мой out-of-tree прогон отклонён классификатором,
повторять не стал). Юнит-тест `token_authenticator(callable → None) → False` (0.12) проверяет функцию, а не проводку
в endpoint.
Fix (внутри FILES): тест `test_window_before_token_write_is_closed`: подменить `socket_auth.write_token` заглушкой,
которая ставит `entered.set()` и ждёт `gate.wait(5)` до вызова настоящей; `setup_backend_ctl_channel` — в daemon-потоке;
после `entered.wait(5)` через `_exchange` отправить `{"cmd": "system.shutdown"}` и `{"type": "hello", "token": "aa"*32}`
→ оба `{"success": False, "error": "auth_required"}`; `gate.set()`, join потока, затем `hello` с токеном из файла →
`{"type": "hello", "success": True}`. Парная инъекция: authenticator возвращает `True` при пустом holder → красный.
