### Пустой файл и явный провайдер (серьёзность — nit, находка 5)

- Пустой файл токена → `read_token` даёт `None` → `hello` не шлётся → текст `token file not found: <путь>`, хотя файл есть. Атомарная запись `write_token` (`mkstemp` + `os.replace`) пустой файл не создаёт; он возможен только от ручного `touch`. Текст вводит в заблуждение, не ломает.
- Отказ при явном провайдере → текст называет путь ФАЙЛОВОГО провайдера, хотя токен дал явный. Драйвер явный провайдер нигде не задаёт (в коде — только тест сеттера), так что сейчас не достижимо вне теста.
- Новое, воспроизведено (`scratchpad/repro_eof_text.py`): хост закрыл сокет, прочитав `hello`, без ответа; файл токена на месте → `TokenRejected -> token rejected: /var/folders/…/ctl_63416.token | cause: SocketAuthError('socket_client: хост закрыл соединение до ответа на hello')`. Любой `SocketAuthError` (EOF, ответ длиннее 4096 байт, reset) выдаётся за «токен отклонён». Причина есть в `__cause__`, а не в тексте.

Механизм (по чтению `socket_client.py` и `transport.py:128–138`): метку ставит поток, чей `request` получил `auth_required` (`transport.py:137`), уже ПОСЛЕ возврата из `super().request`. Reader-поток тем временем читает EOF и будит остальных ожидающих (`_mark_conn_lost`). Поток-проигравший, чей запрос сервер сбросил без ответа, успевает прочитать `_token_missing` раньше победителя и поднимает общий `BackendUnavailable`; `system_shutdown` в этом потоке читает его как `pm_gone`.

Серьёзность — nit (низкая), по трём причинам:
1. Нужны одновременные ПЕРВЫЕ запросы на одном свежем драйвере без файла токена. MCP до этого не доходит: `self._driver` публикуется только после возврата фабрики (`mcp_driver_session.py:421`), пробы `_await_ready` идут последовательно в потоке-создателе под `_lifecycle_lock`, метку ставит проба 1 до того, как кто-то ещё увидит драйвер (чтение кода; MCP-параллель не гонял). `harness`, `stand_gate`, `alpha_sim`, `capacity_bench` — однопоточные клиенты.
2. Последствие — другой текст ошибки в уже сломанном состоянии (файла нет); следующий вызов получает верный текст. Команда в любом случае не дошла до PM.
3. Остаточный вред — одна ложная запись `pm_gone: True` в `system_shutdown` проигравшего потока; её читают только `alpha_sim.judge_shutdown` и текст инструмента MCP.

Нужна одна фраза в ADR «Известное» (см. д). Полное закрытие, если лид захочет: ставить метку в reader-потоке ДО пробуждения ожидающих — переопределить `_dispatch` в `_TransportMixin` (при `b"auth_required" in raw` разобрать строку и поставить `_token_missing = True`, затем `super()._dispatch(raw)`).
