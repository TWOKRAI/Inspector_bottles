## DESIGN (decided by the lead — you type it, you do not derive it)

  1. `recipes/save.py`: приватная `_editor_owned_topology(topology, doc) -> dict`. Если в `topology` нет ключа `processes` или он не список — вернуть `topology` как есть (ошибку, если она есть, даёт `Topology`, поведение прежнее).
     Иначе вернуть `{**topology, "processes": result}` (аргумент не мутируется), где:
     `protected_names` = `process_name` процессов топологии с truthy `protected`; `editor` = процессы топологии без truthy `protected` (не-mapping — непротектед);
     `file_procs` = mapping-элементы `doc["blueprint"]["processes"]` (не список -> пусто); файловый процесс «фундамента» = truthy `protected` ИЛИ `process_name` в `protected_names` (старый рецепт, где `devices` без флага);
     `result` = `editor`; затем каждый файловый процесс фундамента, по порядку файла, вставляется ЭТИМ элементом файла сразу ПОСЛЕ ближайшего более раннего процесса файла, чьё имя уже есть в `result`
     (иначе — в начало): якорь по предшественнику, не по индексу (вставка/удаление непротектед перед protected не двигает блок: замер позиционного правила +10/−16 и +25/−50).
     Следствия: protected редактора игнорируется (берётся версия файла); protected редактора, которых нет в файле, не пишутся; protected файла, которых нет в топологии, остаются.
  2. `save_editor_topology_to_recipe`: сразу после `doc is None` -> `RecipeNotFoundError`:
     `if expected_rev is not None and rev != expected_rev: raise RecipeConflict(slug, expected_rev, rev)` (импорт `from multiprocess_framework.modules.recipe import RecipeConflict`, как `display_catalog_recipe.py:27`).
     `rev` везде `compute_rev(байты)` (доказано запуском). Авторитетная сверка под локом остаётся.
  3. Вызов: после проверки «blueprint — mapping», до `topology_to_canonical`: `topology = _editor_owned_topology(topology, doc)`.
  4. Докстринги: `save_editor_topology_to_recipe` (правило, ранний `RecipeConflict`, порядок проверок), `_editor_owned_topology` (Pre/Post).
