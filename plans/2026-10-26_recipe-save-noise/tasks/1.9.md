## DESIGN (decided by the lead — you type it, you do not derive it)

  1. `RecipeDevicesStore.__init__(recipe_store, *, active_provider=None, session=None)`: `session` — duck с
     `base_rev_for(slug) -> str | None` и `rebase(slug, rev)` (`TopologySession`); `None` — поведение без базы (тесты, нет сессии).
     Докстринг модуля и класса (`:8`, `:29-31`) привести к `read_canonical` / `save_raw(…, expected_rev)` / `session`.
  2. `upsert` / `remove` (`recipe_devices.py:118,130`) — одна схема записи, общий приватный помощник:
     a. `doc, read_rev = store.read_canonical(slug)`; список — `doc.get("devices")` (только dict, как `_read_devices`);
        `doc is None` (файла нет) → пустой список, `read_rev = None`.
     b. `base = session.base_rev_for(slug) if session is not None else None`.
     c. `expected = base if base is not None else read_rev`.
     d. `new_rev = store.save_raw(slug, {"devices": devices}, expected_rev=expected)`.
     e. Только если `base is not None`: `session.rebase(slug, new_rev)`. Если база `None` (другой slug, база сброшена
        F6, сессии нет) — базу не трогать: rebase на `rev` своего чтения поглотил бы чужую правку (проба CTO H1b).
     f. `RecipeConflict` → `raise RecipeDevicesError("Рецепт изменён снаружи — перезагрузите его") from exc`; файл не
        тронут, `rebase` не зовётся. Вызывающие (`add_page.py:176-178`, `crud_actions.py:93-96,177-181`) уже показывают
        `RecipeDevicesError` пользователю — их не менять. `RecipeFormatError` в `upsert`/`remove` не перехватывать
        (прежнее поведение: `RecipeFormatError` выходил из `save_raw`; теперь — из `read_canonical` того же хелпера, тип тот же); прочие ошибки записи — прежнее поведение.
     `_read_devices` (чтение списка для UI, `:136`) переводится на `read_canonical`; `rev` чтения для UI не хранить —
     чтение не двигает базу (design.md §9.1: «в сторе базу не хранить»). `RecipeFormatError` при чтении списка
     (`list`/`get`, путь UI) → `logger.warning` (без содержимого файла) и `[]`: так `read_raw` отдавал `None` на битый файл,
     а `DeviceListPanel.refresh` (`device_list_panel.py:118`) зовёт `list()` из слота без `try`; тот же приём —
     `RecipeStoreFromManager.read`, `recipe_store.py:74`.
  3. Проводка: `robot/section.py:88`, `vfd/section.py:88` — `RecipeDevicesStore(recipes, session=getattr(self._runtime,
     "topology_session", None))`. Заглушку `_NullRecipeStore` (`section.py:21-31`, обе секции) привести к форме Protocol:
     `read_canonical` → `(None, None)`, `save_raw(..., *, expected_rev=None)`.
  4. Локальные фейки стора в тестах вкладки — `_FakeRecipeStore` (`test_recipe_devices.py:21-45`), `_DictRecipeStore`
     (`test_add_page.py:41`, `test_crud_actions.py:31`, `test_master_detail.py:27`): добавить `read_canonical` (тело +
     счётчик-`rev`), keyword `expected_rev` у `save_raw`, возврат нового `rev`; несовпадение — `RecipeConflict`.
     Тесты вкладки по смыслу не менять.
  5. `test_fakes_contract.py:79` — зеркало `_RecipeDevicesBackingStore`: `read_raw` заменить на
     `def read_canonical(self, slug: str) -> tuple[dict | None, str | None]: ...` (хелпер `read_raw` больше не зовёт) и
     `def save_raw(self, slug: str, data: dict, *, expected_rev: str | None) -> str: ...` — `expected_rev` БЕЗ умолчания
     (сверка `:218-224` учитывает только параметры без умолчания). Реестр `:124-126` не менять.
