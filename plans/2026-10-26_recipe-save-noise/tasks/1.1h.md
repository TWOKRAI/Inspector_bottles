DESIGN (decided by the lead — you type it, you do not derive it):
  1. Новый `recipe/file_lock.py` (lite-скаффолд в docstring: Purpose / Public API / Stability). Одна функция —
     контекстный менеджер `recipe_file_lock(path: str | Path, *, timeout: float = 5.0) -> Iterator[None]` и
     `class RecipeLockTimeout(TimeoutError)` (поля `path`, `timeout`; подкласс `OSError` → сервис отдаёт `io_error`).
  2. Lock-файл — рядом с рецептом: `path.with_name(path.name + ".lock")` (`letter_robot_sim.yaml.lock`). Уже в `.gitignore:150` (`*.yaml.lock`). Файл рецепта может не существовать (новый рецепт) — лок берётся всё равно.
  3. Механизм — stdlib, без зависимостей: открыть lock-файл `os.open(lock, O_RDWR | O_CREAT, 0o644)`; Windows —
     `msvcrt.locking(fd, LK_NBLCK, 1)` на байте 0 (`os.lseek(fd, 0, 0)` перед каждой попыткой и перед `LK_UNLCK`); POSIX —
     `fcntl.flock(fd, LOCK_EX | LOCK_NB)`. Обе ветки — неблокирующие попытки в цикле, шаг 0,01–0,05 с, до
     `time.monotonic() + timeout`; дедлайн → `RecipeLockTimeout`, fd закрыт. Блокирующие `LK_LOCK` / `LOCK_EX` без `LOCK_NB` запрещены. Освобождение: `LK_UNLCK` / `LOCK_UN`,
     затем `os.close`. Образец — `app_module/store.py:337-420` (`_FileLock`; не импортировать, его POSIX-ветка без дедлайна).
  4. Stale lock-файл: файл НЕ удаляется никогда — ОС снимает лок при смерти процесса-держателя; `unlink` — гонка по inode. Нереентерабелен: один процесс, два входа на один путь —
     ждёт сам себя до таймаута; вызывающие берут лок один раз на внешнем публичном методе.
  5. `service.py`: `save` (`:309-330`) и `delete` — внутри прежнего `with self._lock(name):` добавить
     `with recipe_file_lock(path):` вокруг «чтение байтов → сверка `base_rev` → запись/удаление». Потоковый лок
     остаётся (порядок: потоковый, затем файловый). Тело `save` не переписывать (Task 1.4).
  6. `__init__.py`: экспорт `recipe_file_lock`, `RecipeLockTimeout`.
  7. `service._atomic_write` (`service.py:382-396`; им же пишет `yaml_io._dump_atomic`, т.е. и путь `RecipeManager` —
     один повтор на всех, не копия): `os.replace` при `PermissionError` (WinError 5/32 — файл открыт читателем) —
     до 5 попыток с паузой 20 мс, затем исключение наружу (сервис → `io_error`); tmp убирается как сейчас.
