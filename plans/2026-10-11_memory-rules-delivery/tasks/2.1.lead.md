# Task 2.1 — лид: инъекции и живой стенд

Бриф исполнителя — `2.1.md`. Здесь работа лида. Прогноз красных пишется ДО запуска и называется ещё раз ПОСЛЕ.
Прогнозы пересчитаны по ревью `MODE: plan` р. 2 (замечание m1).

## Инъекции

Против тестов 1.1 и тестов автора. `_lessons.iter_lessons` уже сортирует по имени — поэтому инъекция порядка — обратный
порядок строк, а не «без сортировки».
- строки узла в обратном порядке → {0} (условие: в тесте 0 у одного модуля ≥ 2 урока — требование к 1.1);
- запись `\r\n` → {0, 1, 11, 12, 13, 14} при чтении каталога `read_bytes()` (текстовое чтение сводило бы CRLF к LF молча —
  скрытая нормализация вопреки контракту);
- канарейка не входит в ожидаемое (файл в каталоге становится orphan, `--write` её не пишет) → {0, 1, 11, 13, 14};
- `x/` → `x/*` вместо `x/**` → {0, 11} (если тест 11 сверяет элемент `paths` с формой `**`);
- тег вне `modules.yaml` роняет генератор → {8, 13};
- `>= 40` вместо `> 40` → {17}; узел пишется при `paths: []` → {6};
- узел `process_module` берёт уроки по префиксу id → {16};
- `--write` не удаляет лишние `*.md` → {6, 14} (если тест 6 идёт так: `--write`, мутация, `--write`);
- `budget` считается по строкам указателей, а не по полному тексту узлов → {18}; без теста 18 дыру ловит только сверка
  строки `total` с литералом приёмки 2.1 — записать в итог.

## Живой стенд

После `--write` в ветке: свежий worktree от коммита слоя; `python scripts/memory/rules.py --check` там → exit 0, строка
`total` в stderr равна литералу приёмки 2.1. Один `developer`-наблюдатель (промпт G0 из 0.1, шаги A и C на файле
