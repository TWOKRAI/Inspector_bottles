# Task 3.1 — замер на 10 парах: плечо A против плеча B, слепой судья, Gate 3

> **Поправка CTO 2026-10-11 — главнее текста ниже** ([`reports/2026-10-11_cto-verdict.md`](../reports/2026-10-11_cto-verdict.md)): **5 пар**, один прогон на плечо, второй пятёрки нет. Gate 3 по C3: стоп — B хуже A в ≥ 2 парах из 5; продолжать — «избежал − хуже» ≥ 2; медианный прирост ≤ 3k токенов. Считать знаки узлов, доставленные за сессию. Потолок всего плана — 3,5 млн.

- **Level:** Senior+ · **Assignee:** лид (стенд, запуски) + исполнители `developer` (Sonnet) + судья `general-purpose` (`model: opus`, без инструментов) <!-- lint-language: allow -->
- **Goal:** ответить числом, даёт ли доставка по пути пользу: оставить слой или удалить его одним коммитом.
- **Module contract:** n/a (замер; при провале — удаление слоя).
- **Chain:** лид (стенд по протоколу 0.2) → `developer` ×20 (A и B) → судья (вслепую, только ничьи) → лид (таблица, Gate 3) → владелец.

Основание: ревью р. 2, «Замер вместо раздела 8»; ревью `MODE: plan` р. 1, замечания 5–7, 11. Список и протокол —
`research/measure-pairs.md` (0.2), закоммичены до генератора. Пороги — предложения ревьюера; владелец утверждает их и
О4 строкой в `amendments.md` до первого запуска. Судья не `ai-judge`: тот выдаёт PASS/BLOCK, при неясности обязан BLOCK и
имеет Read/Bash — может найти файл соответствия плеч.

- **Files:**
  - `plans/2026-10-11_memory-rules-delivery/research/measure-results.md` — таблица прогонов и вердикт
  - `plans/2026-10-11_memory-rules-delivery/tasks/3.1.result.md` — итог (≤ 2 КБ)
  - при провале Gate 3, одним коммитом: удалить `.claude/rules/memory/`, `scripts/memory/rules.py`,
    `scripts/memory/tests/test_rules_acceptance.py`, шаг в `scripts/validate.py`, строку `.gitattributes`, шаг 2.4

- **Steps:**
  1. Предусловия: ответ шага 6 G0 («откуда грузятся правила у субагента в worktree») и проверка утечки из протокола 0.2 на
     одной паре (`search.py --root . --list` из каталога плеча, отфильтрованный по имени урока-ответа, → пусто).
  2. На каждую пару — два каталога-снимка родителя без истории (`git archive <родитель> | tar -x -C <пустой каталог>`,
     затем `git init` и один коммит; рядом с репо, имена без метки плеча: `m-<пара>-x`, `m-<пара>-y`). Общих ссылок с
     главным репо нет, поэтому `git log main` и `git show main:…` ответа не покажут. Срез памяти и копия
     `scripts/memory/` — по протоколу 0.2. A: `MEMORY.md` среза и `search.py --root .`. B: A плюс узлы, сгенерированные
     текущим `rules.py` из среза. Больше ничем плечи не отличаются (роль, модель, промпт, бюджет). Если G0 дал `none`
     или `main` — каждое плечо отдельной сессией с корнем в своём каталоге; абсолютные пути — в промпте. Если снимок
     невозможен — worktree, запрет в промпте любых ссылок кроме HEAD и поиск в транскрипте `main`, `--all`, `show `,
     `git log`; найдено → прогон недействителен.
  3. Исполнитель — `developer`, `model: sonnet`, `run_in_background: false`; промпт без слов «урок», «память», «правило»,
     поиск памяти — только `python scripts/memory/search.py --root . <слова>`; не коммитит и не пушит. Соответствие
     X/Y ↔ A/B — случайное, файл в scratchpad вне дерева, до раскрытия его никто не читает.
  4. После прогона лид снимает литерал проверки (тест или grep из 0.2), токены (`agent_report.py`) и знаки узлов,
     пришедших за сессию (накопление, не размер одного узла; ориентир — три модуля ~88 строк, 22 338 зн.; цепочка
     вложенных узлов — вся).
  5. Исход пары по литералу: «B хуже» = у B красный, у A зелёный; «B избежал» = наоборот. Ничьи (оба красные или оба
     зелёные) — судье: один вызов на все ничьи, дифы X/Y и задача прямо в тексте промпта, без путей к `docs/` и `.claude/`,
     промпт запрещает инструменты; ответ на пару — «X лучше / Y лучше / равно» с причиной. Перед раскрытием лид снимает `agent_report.py` судьи: вызовов инструментов должно быть 0, иначе вердикт недействителен и судью зовут заново. Потом лид раскрывает соответствие.
  6. Контрольная точка после 5 пар: таблица и цена — владельцу; остальные 5 — только по его слову (О4).
  7. Gate 3 по трём условиям (`plan.md`, «Метрики и стоп-условия»); провал — коммит удаления, затем 3.2.

- **Acceptance criteria:**
  - в `measure-results.md` 10 строк (или N по решению владельца): пара · литерал A · литерал B · исход · вердикт судьи
    (для ничьих) · токены A · токены B · знаков узлов за сессию B;
  - три числа Gate 3 литералами: чистая разница «B избежал» минус «B хуже» (порог ≥ 3), число «B хуже» (порог 0),
    медианный прирост токенов B − A (порог ≤ 5 000);
  - вердикт одной строкой: «слой остаётся» или «слой удалён, SHA <…>»; при удалении `python scripts/memory/rules.py --check`
    → файла нет, `python scripts/validate.py` без шага 9;
  - стоимость факт — сумма токенов запусков и судьи против оценки `plan.md` «Бюджет» (3,2–6,3 млн, гипотеза).

- **Out of scope:** перенастройка порогов после результата; выбор пар заново; правка генератора по ходу замера (любая
  правка — новый замер); второй прогон на плечо без решения владельца (О3); R5; правка плана Atlas.
