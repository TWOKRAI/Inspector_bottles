#### Устройство (решение лида, не жёсткий контракт)

- **Три маршрута, два адресата.** `preset.get`/`preset.commit` живут в `scene_source` (процесс `scene_process`,
  по умолчанию `camera`), а `preset.preview` — в отдельном плагине `layer_preview` процесса `layers`
  (вынесен туда в 1.2a: превью ~88 мс держало единственный поток команд сцены). Значит нужен **третий**
  `DeviceHubClient` рядом с `_client` и `_scene_client`; ключ конфига `layers_process`, дефолт `layers`.

  | Маршрут | Команда | Адресат |
  |---|---|---|
  | `GET /api/preset` | `preset.get` | `scene_process` |
  | `POST /api/preset/commit` | `preset.commit` | `scene_process` |
  | `POST /api/preset/preview` | `preset.preview` | `layers_process` |

  Маршруты — отдельной таблицей `_PRESET_ROUTES` **ниже** существующей `_SCENE_COMMAND_BY_PATH` (её завёл
  Task 5.3a, Task 6.1 дополняет), блок страницы — отдельной константой, а не вставкой внутрь `_PAGE_TEMPLATE`:
  так слияние с 6.1 остаётся механическим.

- **Находка 1 — потолок тела 4 КБ режет `commit`.** `_MAX_BODY_BYTES = 4096`, отказ 413 выносится **до**
  чтения тела. `preset.commit` шлёт пресет целиком: `letters_layered` — два слоя, уже сотни байт, пресет
  бутылки на пять слоёв с диапазонами выходит за 4 КБ. Потолок поднимается **на маршрут**, не глобально;
  для `/api/preset/commit` — 256 КБ, у прежних маршрутов 4096 остаётся (сверено с сессией 6.1: самое толстое
  тело `scene.*` — `{"interval_s": [lo, hi]}`). Отказ по-прежнему до чтения.

- **Находка 2 — `_dispatch` теряет код ошибки.** Сейчас любой `status == "error"` становится HTTP 504
  `{ok: false, error: message}`. Редактору это смертельно: `conflict` (кто-то правил файл) требует своего
  поведения и несёт `current_rev`, а 504 означал бы «бэкенд не ответил». Ответ команды отдаётся **как есть**,
  HTTP-код — по `code`: `invalid`/`bad_request` → 400, `conflict` → 409, `io_error` → 500, нет ответа от
  процесса → 504. Правка общая для обеих сторон: команды `scene.*` (Task 6.1) тоже типизированы (`invalid`),
  и 400 для них — правильный ответ. Маршруты `belt.*`/`sim_robot.*`, у которых `code` в ответе нет,
  ведут себя как раньше (504).

- **Находка 3 — таймаут 1.0 с меньше цены превью.** `timeout_s` один на всех клиентов, по умолчанию 1.0 с.
  README `layer_preview`: 8×160 px ≈ 88 мс, спрайты 1200 px — **до 1.3 с**. Таймаут задаётся на маршрут
  (`/api/preset/preview` — 5 с), общий дефолт не меняется.

- **Форма строится из отданного словаря, не из схемы.** `ScenePreset.to_dict()` — это `model_dump(mode="json")`,
  то есть все поля присутствуют, включая дефолтные; тип поля ввода выбирается по типу значения. Схему
  Pydantic страница не получает — добавлять её в ответ `preset.get` значит править `scene_source`, а он
  сейчас под 6.1. **Известный потолок:** `augment: null` и `color_rgb: null` не несут формы своих полей,
  поэтому включение аугментации на слое, где её не было, опирается на константу-скелет из пяти диапазонов
  в JS — новое поле `LayerAugment` в ней не появится само. Помечается `ponytail:`-комментарием; путь наверх —
  отдать `model_json_schema()` в `preset.get`, когда `scene_source` освободится.

- **Undo — в браузере, стек словарей.** Бэкенд про undo не знает; `commit` идёт с `base_rev`, полученным
  последним `get`/`commit`.

#### Сценарии паритета (пишутся здесь, гоняются потом против 1.2b)

Нумерация общая для обоих клиентов; тест Qt в 1.2b реализует те же номера своими средствами.

1. **П1 открыть** — клиент показывает столько строк слоёв, сколько в `preset.get`, в том же порядке, и `rev`.
2. **П2 правка** — `offset_px` слоя с `(0,0)` на `(15,0)` → `commit` уходит с этим значением и с `base_rev` из П1.
3. **П3 превью** — после правки запрошено превью; показанная картинка — та, что пришла в `png_b64`, своего
   рендера нет.
4. **П4 сохранение** — `commit` вернул новый `rev` → клиент показывает его и дальше шлёт как `base_rev`.
5. **П5 конфликт** — `commit` вернул `conflict` + `current_rev` → клиент говорит об этом и **не** теряет правку.
6. **П6 undo** — отмена возвращает прежнее значение в поля; на бэкенд при отмене ничего не уходит.
7. **П7 отказ** — `invalid` (диапазон `lo > hi`) показан текстом от бэкенда, файл не тронут.

#### Acceptance criteria (тестер, до кода; двойники процессов, как в `test_acceptance_5_3a.py`)

Литералы — в тестах, не из кода.

- [ ] H1: `GET /api/preset` → 200, тело **побитово** равно ответу двойника `preset.get`; команда ушла адресату
      `scene_process`, а не `robot`.
- [ ] H2: `POST /api/preset/commit` с телом 200 КБ доходит до двойника целиком (двойник видит ровно
      отправленный `preset`); тело больше потолка маршрута → 413 **без** вызова команды.
- [ ] H3: двойник отвечает `{status: error, code: conflict, current_rev: "…"}` → HTTP **409**, и `current_rev`
      есть в теле ответа страницы. Он же с `code: invalid` → **400**, с `io_error` → **500**.
- [ ] H4: прежние маршруты не задеты — `POST /api/run` с телом 5000 байт по-прежнему 413, а ошибка `belt.*`
      без `code` по-прежнему 504.
- [ ] H5: `POST /api/preset/preview` уходит клиенту процесса `layers` (не `camera` и не `robot`); двойник,
      отвечающий через 2 с, укладывается в таймаут маршрута — ответ 200, а не 504.
- [ ] H6: разметка страницы (`GET /`, разбор HTML, **не** через `page_offline.mjs`) несёт раздел редактора:
      контейнер списка слоёв, поле `rev`, кнопки «превью» и «сохранить». Причина отдельного теста — находка 1
      ревью 5.3a: харнесс создаёт элемент под любой `id`, поэтому удаление разметки тесты страницы не ловят.
- [ ] H7: настоящий `<script>` страницы через `page_offline.mjs` против живого сервера: правка `offset_px`
      → «сохранить» → двойник получил `preset.commit` с `base_rev` из первого `get` (сценарии П1–П2).
- [ ] H8: двойник `preset.commit` отвечает `conflict` → страница оставляет введённое значение в поле
      (сценарий П5); повторное «сохранить» уходит уже с `current_rev` как `base_rev`.

**Out of scope:** мышь на канве (1.3); Qt-вкладка (1.2b); любые правки `scene_source` и `layer_preview`;

#### Закреплено после слепого тестировщика (2026-09-28)

Тестировщик написал H1–H8 по контракту выше и упёрся в два места, которых контракт не давал буквально
(в отличие от образца 5.3a, где разметка закреплена литералами). Закрываются здесь, чтобы тесты и реализация
не разошлись в именах.

- **Ответ `preset.get` — шесть ключей, не три.** Факт кода (`scene_source/plugin.py`, `cmd_preset_get`):
  `{status, preset, rev, path, class_names, engine}`. Тестировщик угадал три из шести — его модель
  поправлена здесь, а не в тестах задним числом.
  **`engine: false` — отдельное поведение страницы, а не мелочь:** движок не собрался, `commit` файл
  запишет, но на ленте правка появится только после перезапуска. Страница обязана сказать это словами,
  иначе редактор молча врёт «сохранено и поехало». `rev: null` и `path: null` (плагин собран из каталога,
  а не из `.yaml`) — правка недоступна, «сохранить» заблокировано.
- **Имена в разметке — литералы, закрепляются здесь.** `id="presetRev"` (текущая ревизия),
  `id="presetLayers"` (контейнер списка слоёв), `id="presetEngineWarn"` (предупреждение про `engine: false`),
  `id="btnPresetPreview"`, `id="btnPresetSave"`, `id="btnPresetUndo"`, `id="presetPreviewImg"` (картинка
  превью). Поля слоя — `id="layer<i>_<имя поля>"`, например `layer0_offset_x`. H6 проверяет именно эти
  строки в HTML.
- **«Побитово» в H1 — про равенство после `json.loads`,** а не про байты: `_reply_json` сериализует словарь
  заново, порядок ключей сохранять никто не обещал. Прецедент — тесты 5.3a.
- **Дедлайн в тестах — только своим потоком, не маркером.** В этом окружении `@pytest.mark.timeout` —
  пустышка: `pytest-timeout` не установлен (`plugins: anyio, asyncio, cov, qt`, сверено 2026-09-28), маркер
  молча игнорируется. H5 и всё, что может заблокироваться, ставит вызов в daemon-поток с `join(deadline)`.
  Маркер в 20+ файлов репозитория — **находка за пределами 1.2h**, вынесена владельцу отдельно.
