# Design: механизм и единый формат коммитов

Контракт и порядок — [`plan.md`](plan.md). Числа и опыты — [разбор](../../docs/audits/2026-10-03_commit-mechanism.md).

## Решения владельца (2026-10-03)

| # | Решение | Почему |
|---|---|---|
| 1 | Единый формат у всех, включая слияния | `git log --first-parent main` — журнал изменений; 142 из 318 слияний — текст git по умолчанию |
| 2 | Хук `session-log` снять с pre-commit; журнал коммитит `/wrap-up` отдельным коммитом | единственный класс с потерей правок (10 случаев; воспроизведено с контролем); без хука журнал никто не стейджит |
| 3 | Длина subject — только предупреждение (после 72 и после 100), без отказа | длина ни разу не сорвала коммит; жёсткий лимит создал бы новый класс отказов |
| 4 | `Refs:` — любой существующий план (кроме `plans/queue/**` и `*.result*`) | 16 отказов «план ветки ≠ план коммита» |
| 5 | Помощник `scripts/commit.py` — отложен до замера (Task 3.2) | сначала убрать причины у источника; помощник — общий риск на три сессии |

Предыдущая редакция 1 и 4 (лимит 100 жёстко, помощник сразу) отменена владельцем в тот же день после разбора «лучше/хуже».

## Формат v2

```
<type>[(<scope>)][!]: <описание>
<пусто>
- тело (опционально)
<пусто>
Why: …            обязателен
Layer: a[, b]     обязателен; framework|services|plugins|prototype|docs|scripts|tests|infra|mixed
Refs: plans/…md   обязателен, если ветка разрешается в план; подходит любой существующий план
Risk|Reversible|Tested|Rejected: …   опционально
<пусто>
Co-Authored-By: … для агентов; хук не проверяет
```

- type: `feat fix refactor perf test docs chore build ci style revert merge`; у `merge` нет scope.
- scope: `[a-z0-9_./,-]+` (точка — чтобы проходил `task-5.5`).
- Длина subject: считается по символам (кириллица = 1); предупреждение после 72 и после 100, отказа нет.
- Слияние: `merge: <что вошло>`; синхронизация: `merge: main (<sha>) в <ветка> — <зачем>`.
  `git merge --no-ff <ветка> -F <файл>`; при `--no-commit` — подменить `.git/MERGE_MSG` до `git merge --continue`
  (хук видит итоговый текст — проверено в commitlab, git 2.50).
- Без проверки только `Revert "…"`, `fixup!`, `squash!`, `amend!`. Текст git по умолчанию (`Merge branch …`,
  `Merge remote-tracking branch …`) — предупреждение в фазе 2, отказ в фазе 3.
- Фолдинг: строка без `Key:` внутри абзаца трейлеров продолжает предыдущее значение (как git).

## Механизм после плана

- `commit-msg` — единственный валидатор, fail closed; код v2 одинаков в `scripts/validate_commit/` и в шаблоне сида
  `.claude/plugins/lang-python/templates/validate_commit/`; правка в каждую копию отдельно, без `cp`; тест сравнивает копии.
- `pre-commit` — ruff, ruff-format, whitespace, EOF, bandit; без `session-log`. Версия ruff в хуке = версии в `.venv`.
- Хук правки (`autoformat-python.sh` и аналог для `.md`) — чинит то, что чинится, и печатает остаток (E501) в stderr;
  fail open.
- Привычка агентов (Task 2.2): сообщение пишется файлом и передаётся `-F`; в коммит — явный список путей; без
  `| grep` после `git commit` (код выхода).

## Раскатка на три сессии

Хук `commit-msg` запускает валидатор своего worktree (`git rev-parse --show-toplevel`): ветка получает v2, только когда
вливает `main`. Поэтому фаза 2 — предупреждения: ни одна сессия не ломается на середине работы. До слияния каждой
задачи в `main` — SHA соседям (f4 transport, 5a plans-progress). Строгий режим (3.1) — только после явного согласия
обоих.

## Риски

| Риск | Мера |
|---|---|
| Сид при upgrade снова откатит валидатор или опустошит `commit-layers.txt` | сторожевые тесты в 2.1 |
| Журнал сессий беднеет без `session-log` | `/wrap-up` в конце сессии; `git log --stat` — полная история |
| Журнал висит незакоммиченным (хук делал `git add`, теперь никто) | решение владельца 2026-10-03: последний шаг `/wrap-up` — коммит `docs(sessions):` с одним явным путём |
| Строгий режим ломает слияние в чужой сессии | только после согласия; предупреждения неделю до этого |
| Дешёвых мер окажется мало | замер 3.2 по тем же классам; тогда помощник `commit.py` |
