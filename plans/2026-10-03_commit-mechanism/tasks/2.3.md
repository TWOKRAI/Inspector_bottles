## DESIGN (решено лидом — исполнитель печатает, не выводит)

  (a) **CLI.** `python scripts/commit_audit/classify.py --root <каталог projects> --since YYYY-MM-DD --until YYYY-MM-DD
      [--project-substr Inspector-vision-Inspector-bottles] [--json]`. Только stdlib. Даты — местные, по `timestamp`
      записи через `astimezone()`, `--until` включительно. Выход по умолчанию — таблица markdown, строки в порядке:
      `A1, A1-Edit/Write, A1-F401, A1-Bash, A1-undecided, A2, A3, C1, C2, C4, B1, B2, hidden`; колонки `class | commit |
      per100_commit | merge | per100_merge`; под таблицей — `commit_calls`, `merge_calls`, `both_calls`, `not_executed`,
      `any_failure`. `--json` — тот же набор ключами. per100 — округление до 2 знаков.
  (b) **Попытка** = один `tool_use` с `name == "Bash"` и его `tool_result` по `tool_use_id`; дедупликация по `tool_use.id`
      (первое вхождение). Знаменатель — ВЫЗОВЫ (один вызов с двумя `git commit` = 1). Распознавание команды:
      1. снять тела heredoc: заголовок `<<-?\s*(['"]?)([A-Za-z_]\w*)\1`, пропуск строк до строки, равной разделителю после
         `strip()`;
      2. заменить содержимое кавычек на `Q` автоматом состояний, многострочно, с `\` внутри `"…"` (построчный regex теряет
         попытку за многострочным `python -c "…"` — пункт 19 фикстуры);
      3. перенаправления `(\d?)>&(\d)` → `<n>>FD<m>`;
      4. regex:
         `SEG = (?:^|&&|\|\||[;|(\n{]|\bthen\b|\bdo\b|\belse\b|`|\$\()[ \t]*(?:[A-Za-z_]\w*=\S*[ \t]+)*`
         `GITOPTS = git(?:[ \t]+(?:-C[ \t]+\S+|-c[ \t]+\S+|--no-pager|--git-dir=\S+|--work-tree=\S+))*[ \t]+`
         `COMMIT = SEG GITOPTS commit(?![-\w])(?P<args>[^\n;&|]*)(?P<tail>[^\n;&]*)` — исключить `--dry-run` в args;
         `MERGE = SEG GITOPTS merge(?![-\w])(?P<args>[^\n;&|]*)(?P<tail>[^\n;&]*)` — исключить `--abort|--quit`.
  (c) **Каталог попытки:** последний `cd X` до первого `git … commit|merge`; относительный путь — от поля `cwd` записи;
      `$VAR` — из `VAR=` той же команды. В счёт, если путь (без регистра, `\`→`/`) содержит `inspector_vision/inspector_bottles`
      и не содержит `/temp/`, `/tmp`, `commitlab`.
  (d) **Не исполнено** (из знаменателя вон): результат начинается с
      `^(?:Error: )?(?:Permission to use Bash|The server-side auto mode classifier|PreToolUse:Bash hook error: (?!.*protect-branch))`.
  (e) **Исход:** срыв — есть метка класса из (f). Успех — `^\[[^\]\n]+? [0-9a-f]{7,40}\] ` (commit) или
      `^(?:Merge made by the '\S+' strategy\.|Fast-forward\s*$|Already up to date\.)`. Иначе — `unknown` (в `--json`).
  (f) **Сигнатуры** — только текст `tool_result` своей попытки, все с якорем `^` (MULTILINE). Блок хука — от строки статуса
      до следующей: `STATUS = ^(?P<label>\S.*?)\.{3,}(?:\([^)\n]*\))?(?P<st>Passed|Failed|Skipped)[ \t]*$`.

| Класс | Литерал |
|---|---|
| A1 | блок `label == "ruff format"`, `Failed` |
| A1-F401 | блок `label` ~ `^ruff(?: \(legacy alias\)| check)?$`, `Failed`, в теле `^- files were modified by this hook` или `^Found \d+ errors? \((\d+) fixed` с числом ≥ 1 |
| C1 | тот же блок ruff, `Failed`, в теле `^(?:\S+:\d+:\d+: )?E501 Line too long` |
| A2 | `label in {"trim trailing whitespace", "fix end of files"}`, `Failed` |
| A3 | `^\s*error: \S.*: patch does not apply\s*$` |
| B1 | ``^\s*- Branch has a plan \(.+\) but commit is missing matching `Refs:` trailer\.`` |
| B2 | `^\s*- Unknown type 'merge'\.` |
| C2 | `^(?:/usr/bin/)?bash: (?:-c: )?line \d+: (?:unexpected EOF while looking for matching|warning: here-document at line \d+ delimited by end-of-file)` |
| C4 | `^(?:error: could not read file '-'|fatal: could not read log file '.+': No such file or directory)\s*$` |

      Мультикласс разрешён (24 вызова в базе). `Rolling back fixes` без `patch does not apply` — НЕ A3.
  (g) **A1 по писателю** (только для попыток с A1; A1-F401 — отдельная ось, наслаивается):
      - состав коммита: пути `git add|rm` в том же вызове до коммита; нет — `git add` в предыдущих вызовах транскрипта после
        прошлой попытки; `.`, `-A`, `-u`, `commit -a` = «все»; каталог — префикс; для «всех» и каталогов — `.py`, записанные в
        транскрипте после прошлой попытки;
      - последний писатель `.py` до попытки: `Edit|Write|MultiEdit|NotebookEdit` с совпадающим концом `file_path` → `tool`;
        Bash с именем файла и записью (`>`, `cp|mv|install|tee|rsync`, `sed -i`, `git checkout|restore … файл`, python с
        `write_text(`/`.write(`) → `bash`; `git merge|cherry-pick|stash pop|apply|rebase|pull|reset --hard` → `bash`;
        `ruff format …` или прошлая попытка с A1 → `fmt`;
      - правило: есть `bash` → A1-Bash; все `tool` → A1-Edit/Write; иначе A1-undecided.
  (h) **hidden** — флаг у сегмента пайплайна команды: `2>/dev/null` или `&>/dev/null`; пайп при `2>FD1`/`|&` в `grep` без
      `-v`, в `tail`, в `head`. `grep -v…` — НЕ скрыто. `-q` — НЕ скрыто (прячет только `[ветка sha]`). hidden — отдельная
      строка, не исход: скрытая попытка с меткой считается и в своём классе.
  (i) **База.** После GREEN лид запускает скрипт на `--since 2026-09-02 --until 2026-10-03` и пишет таблицу в
      `amendments.md`; базой замера 3.2 становится она, а не каталог разбора. Расхождение с пересчётом investigator-а
      (числа в FACTS) — находка, объясняется до слияния.
