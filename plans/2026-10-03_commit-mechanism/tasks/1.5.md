# Task 1.5: autoformat-python.sh проверяет расширение до запуска Python

- **Level:** Middle · **Assignee:** developer · **Создана** 2026-10-04 по условию C3 приёмки фазы 1 (CTO), follow-up, не гейт.

FACTS:
  - `autoformat-python.sh` запускает встроенный Python (разбор входа) на КАЖДОЙ правке, затем отсекает не-`.py`.
    Замер CTO на `.md`: 0,30 / 0,33 / 0,30 с. Тот же класс цены, за который в 1.4 снят `check-imports` (0,25–0,29 с).
  - Путь из JSON надёжно достаёт только Python (экранирование, `\r` — Task 1.2). Дешёвая проверка возможна по сырому
    входу: если в нём нет подстроки `.py"` — выйти до Python.

DESIGN (ред. 2, 2026-10-05, лид; стадия 0 не проводится — задача solo-trivial: 1 файл, < 20 строк, без нового механизма):
  - Замер лида 2026-10-05 (3 прогона, payload Write `.md`): хук 348–356 мс; из них поиск интерпретатора в
    `_lib/python-bin.sh` (`python3 -c "import sys"`) ~70 мс, разбор входа встроенным Python ~200 мс, старт bash ~70 мс.
    Черновик ставил отсечку ПОСЛЕ чтения stdin, но поиск интерпретатора идёт раньше — сэкономил бы только половину.
  - Поэтому: первое действие хука после комментария-шапки — `INPUT="$(cat)"`, затем
    `case "$INPUT" in *'.py"'*) ;; *) exit 0 ;; esac`; поиск `python-bin.sh` и `PY` — после отсечки; разбор берёт
    `"$INPUT"` вместо повторного `cat`. Остальное не меняется.
  - Ложный проход (`.py"` где-то ещё во входе, например в `new_string`) безвреден: дальше полная проверка в Python.
    Ложного отсечения нет: путь `.py` в JSON всегда кончается на `.py"` (Python и так требует `endswith('.py')`,
    `.PY` хук не форматирует и сейчас).

FILES: `.claude/plugins/lang-python/hooks/autoformat-python.sh`; тесты — файлом тестера.

REDS (наблюдаемо — подменный интерпретатор через `CLAUDE_PYTHON_BIN`, который пишет строку в файл-счётчик и
  передаёт вызов настоящему Python):
  - Write `notes.md` → счётчик пуст (0 запусков Python), rc 0, stdout пуст. Сейчас красный.
  - Edit `notes.md`, в `new_string` есть `x.py"` → Python запускается (ложный проход), файл `.md` не меняется, rc 0.
  - Write `mod.py` в git-репо внутри проекта с неформатированным кодом → счётчик ≥ 1, файл отформатирован.
  - Все тесты `scripts/validate_commit/tests/test_edit_hooks_match_precommit.py` зелёные.

ACCEPTANCE: лид — время хука на `.md` ≤ 120 мс (3 прогона, тот же замер), на `.py` поведение прежнее.

OUT OF SCOPE: autofix-text.sh (ему Python нужен на каждом текстовом файле).
