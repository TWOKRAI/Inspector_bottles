## DESIGN (decided by the lead — you type it, you do not derive it)

1. **`autoformat-python.sh`**
   1. Поиск ruff: сначала `$CLAUDE_PROJECT_DIR/.venv/Scripts/ruff.exe`, затем `$CLAUDE_PROJECT_DIR/.venv/bin/ruff`,
      затем `command -v ruff`. Ветку `venv/` удалить.
   2. Порядок как в pre-commit: сначала `check --fix --unfixable F401` (F401 не чинить — причина в комментарии хука
      остаётся), затем `format`.
   3. После них — `ruff check FILE --output-format concise --quiet`, без fix. Если есть остаток, напечатать на stdout
      JSON `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"autoformat-python: <N> ruff
      issue(s) left in <file> — not auto-fixed, pre-commit will reject: <до 10 строк path:line:col CODE msg>"}}`.
   4. Код выхода всегда 0 (fail open). Падение ruff — тоже тишина и 0.
2. **Новый хук `.claude/plugins/core/hooks/autofix-text.sh`** (PostToolUse `Edit|Write`).
   1. Логика — в `.claude/plugins/core/hooks/autofix_text.py` (stdlib).
   2. Что чинит: файл из `tool_input.file_path`, кроме `*.py` (его ведёт ruff), путей `^robot/` и
      `^docs/claude/frozen/` (относительно корня репозитория) и бинарных файлов (есть байт NUL).
   3. Поведение байт в байт как у pre-commit-hooks v5.0.0:
      - trailing-whitespace: по строкам, eol сохраняется; в `.md` непустая строка, которая кончается двумя
        пробелами, сохраняет ровно два;
      - end-of-file-fixer: ровно один перевод строки в конце, пустой файл остаётся пустым, eol берётся из последней
        строки.
   4. Пишет файл, только если байты изменились. Молчит, exit 0 всегда.
   5. Регистрация: `.claude/plugins/core/.claude-plugin/plugin.json` (`${CLAUDE_PLUGIN_ROOT}/hooks/autofix-text.sh`)
      и `.claude/settings.json` (`bash "${CLAUDE_PROJECT_DIR}"/.claude/plugins/core/hooks/autofix-text.sh`, timeout 10)
      — в группу `Edit|Write` рядом с `doc-size-guard.sh`.
3. **`rev` ruff `v0.15.14`** в `.pre-commit-config.yaml` и в шаблоне сида — каждую копию отдельно.
