## FACTS (замеры 2026-10-03)

### Причина A1: хук мёртв на Windows

- **Дефект.** Хук правки на Windows ни разу не доходит до ruff:
  - разбор входа — `read -r TOOL_NAME FILE_PATH < <($PY -c "...print(...)")`;
  - Windows-Python печатает `\r\n`, поэтому `FILE_PATH` кончается на `\r`;
  - `[[ "$FILE_PATH" != *.py ]]` истинно → `exit 0`.
  - Дефект с `3dbb2985a` (2026-05-15).
  - Контроль ревьюера: тот же хук, но вывод python пропущен через `tr -d '\r'` → файл отформатирован.
- **Связь с A1.** Investigator: все 68 срывов A1 за 2026-09-02..10-03 — при мёртвом хуке.
  - Пары Edit→Edit: в 14 из 14 файл остался неформатированным.
  - Симуляция живого хука на 28 содержимых Write: 25 проходят pre-commit чисто, 3 падают на F401.
  - H3 (порядок проверок) — 0 из 28.
- **Чего живой хук не закроет:**
  - F401 — до 23 из 68 срывов с участием `ruff (legacy alias)`; хук F401 не чинит намеренно;
  - файлы, записанные через Bash/cp/sed/merge, — у 48 из 66 срывов есть такой staged `.py`.

### Ruff: версии, exclude, порядок, вывод

- **Версии.** Гипотеза разбора «версии 0.15.12 vs 0.15.14» опровергнута:
  - `format --check .` у обеих версий — 447 одинаковых файлов;
  - `check .` — одинаковый вывод.
- **Exclude.** ruff соблюдает `extend-exclude = [".claude/"]` для явно переданного файла только с `--force-exclude`.
  Хуки ruff-pre-commit вызывают его именно так.
- **Порядок.** pre-commit: `ruff --fix` (чинит F401), затем `ruff-format`. Хук: `format`, затем `check --fix`.
  Порядок обратный. На пограничной фикстуре (строка ровно 121 символ с `f"x"`) старый порядок оставляет файл, который
  ruff-format переписывает.
- **Канал к агенту.** Stderr при exit 0 агенту не показывается (документация хуков: «debug log only»). Канал — JSON
  `hookSpecificOutput.additionalContext` на stdout. Невалидный JSON при exit 0 уходит в debug log, то есть молча.
  Так уже работает `doc-size-guard.sh`.

### Пробелы и EOF (pre-commit-hooks v5.0.0)

## DESIGN (decided by the lead — you type it, you do not derive it)

### 1. `autoformat-python.sh`

0. **Разделение труда (решение лида, ред. 4).** Python разбирает вход, проверяет путь и собирает JSON. Поиск ruff и
   три вызова ruff — в bash.
1. **Вход.** Разбор JSON и все проверки — во встроенном Python, как в `doc-size-guard.sh`.
   - Проверки: инструмент Edit/Write, путь `*.py`, файл существует.
   - Корень и пропуски — то же правило, что в DESIGN 2.1: ближайший предок с `.git` внутри `CLAUDE_PROJECT_DIR`;
     `^robot/`, `^docs/claude/frozen/` относительно этого корня.
   - Код правила (~10 строк) ДУБЛИРУЕТСЯ здесь, а не импортируется из `core/hooks/autofix_text.py`: зависимость
     плагина `lang-python` от `core` хуже копии. В обоих местах — комментарий со ссылкой на двойника.
   - Python печатает на stdout только путь файла, если его надо обрабатывать; bash снимает `\r` при чтении.
     Никакого `read` двух полей.
   - `python-bin.sh` подключать в подшелле, чтобы его `exit 1` не давал «hook error».
2. **Поиск ruff:**
   1. `git -C "$CLAUDE_PROJECT_DIR" rev-parse --path-format=absolute --git-common-dir`. Если имя последнего каталога
      `.git`, корень — его родитель, там ищем `.venv/Scripts/ruff.exe`, затем `.venv/bin/ruff`. Иначе или при rc≠0
      шаг пропустить. Замер ревью: и главное дерево, и worktree приходят к `.venv` главного дерева.
   2. затем `$CLAUDE_PROJECT_DIR/.venv/...`;
   3. затем `command -v ruff`.
   - Ветку `venv/` удалить.
3. **Порядок как в pre-commit**, во всех вызовах `--force-exclude`:
   1. `ruff check FILE --fix --unfixable F401 --force-exclude`;
   2. `ruff format FILE --force-exclude`;
   3. `ruff check FILE --no-fix --force-exclude --output-format concise --quiet`.
4. **Остаток.** Только при rc==1 последнего вызова, остальные коды → тишина. N — число непустых строк stdout.
   - JSON собирать в Python через `json.dumps(..., ensure_ascii=True)`.
   - `additionalContext`: `autoformat-python: <N> ruff issue(s) left in <file> — not auto-fixed, pre-commit will reject:`
     + до 10 строк диагностики как есть. Строки не резать по `:` — в пути есть буква диска.
   - F401 тоже попадает в остаток. Это верно: pre-commit его вырежет и сорвёт коммит.
5. **Код выхода** всегда 0.

### 2. Новый хук `.claude/plugins/core/hooks/autofix-text.sh`

Логика — в `autofix_text.py` (stdlib).

1. **Цель.** Файл `tool_input.file_path` при Edit/Write. Пропуск, если:
   - `*.py` — его ведёт ruff. Остаток: хвостовые пробелы в многострочных не-docstring строках `.py` хук не тронет,
     pre-commit их заметит;
   - символическая ссылка;
   - больше 1 MiB;
   - вне репозитория;
   - путь (относительно корня репозитория) под `^robot/` или `^docs/claude/frozen/`;
   - двоичный файл.
   - Корень репозитория — ближайший предок с `.git` (каталог или файл). Он обязан лежать внутри
     `os.path.normcase(os.path.realpath(CLAUDE_PROJECT_DIR))`.
   - Двоичный — если в первых 1024 байтах есть байт вне `{7,8,9,10,11,12,13,27} ∪ 0x20–0x7E ∪ 0x80–0xFF`
     (`identify.is_text`). Правило одно для всех расширений.
   - Известный остаток: файл с текстовым расширением и управляющим байтом в первом KB (например, `.md` с NUL) хук
     пропустит, а pre-commit поправит при коммите.
2. **Алгоритм** — дословная копия `trailing_whitespace_fixer._process_line` и `end_of_file_fixer.fix_file` из
   pre-commit-hooks v5.0.0 (MIT, в комментарии путь и версия).
   - Работа только над байтами, без декодирования; строки делятся по `b'\n'`, как `readlines()`.
   - Пробельные — `bytes.rstrip()` без аргумента.
   - Markdown — `os.path.splitext(path.lower())[1] == '.md'`.
   - Порядок: TW, затем EOF.
3. **Запись.** Оба алгоритма идут в памяти:
   - `_process_line` — по строкам, разделённым только по `b'\n'` с сохранением разделителя, как `readlines()`
     (не `splitlines()`: он делит и по `\r`);
   - затем `fix_file(io.BytesIO(...))`.
   - Потом сравнение с исходными байтами и одна запись `open(path, 'wb')` — только если байты изменились и
     `st_mtime_ns` и размер равны значениям при чтении. Иначе пропуск.
   - `autofix-text.sh` — как `doc-size-guard.sh`: `python-bin.sh` в подшелле, вход идёт в Python через stdin,
     stdout пустой. Молчит, exit 0 всегда.
4. **Регистрация** — вторым элементом в тот же список `hooks`, что `doc-size-guard.sh`:
   - `.claude/plugins/core/.claude-plugin/plugin.json`: `${CLAUDE_PLUGIN_ROOT}/hooks/autofix-text.sh`;
   - `.claude/settings.json`: `bash "${CLAUDE_PROJECT_DIR}"/.claude/plugins/core/hooks/autofix-text.sh`, timeout 10.
   Так `plugin sync` даёт нулевой diff (композер `settings_compose/merge.py:_rewrite_hook_command`).

### Условия для всех REDS

  - cwd — временный репо.
- **Окружение:**
  - `CLAUDE_PROJECT_DIR` — временный репо;

- **Процессы.** Вывод — во временные файлы, `timeout=120`. Нет pre-commit → FAIL. Ожидаемые значения — литералы.
