## DESIGN (decided by the lead — you type it, you do not derive it)

1. **Режимы.** Режим хука — путь к файлу в argv (`validate_commit.py <file>`, так зовёт `.git/hooks/commit-msg`).
   Режим проверки — stdin (`validate_commit.py -`: `/dev:ship`, CI сида, тесты). Пишет на диск только режим хука.
2. **Где сообщение.** Файл читается байтами. Конец сообщения — перед строкой ножниц, дословно
   `# ------------------------ >8 ------------------------` (раскладка `git commit -v`), если она есть. Строки, начинающиеся с `#`, при поиске абзацев пропускаются и сохраняются побайтно
   на своих местах. Конец строки (LF или CRLF) берётся из файла и сохраняется. Файл, который не декодируется в UTF-8, —
   не трогается, поведение прежнее (OUT OF SCOPE).
3. **Определения.** Пустая строка — пустая или из одних пробельных символов (включая ``): для git это граница
   абзаца. Отступ — пробел или табуляция в начале строки.
   **Абзац трейлеров** — абзац, в котором первая строка — трейлер, и каждая строка — либо трейлер `TRAILER_RE`, ключ
   которого входит в `KNOWN_TRAILERS` без учёта регистра, либо строка с отступом сразу после трейлера или другой такой
   строки. Абзац тела вида `Note: см. ниже` или `See: http://x` — не абзац трейлеров (ключ не из списка).
   Причина: `git interpret-trailers` считает трейлером любой `Key: value`, после склейки git увидел бы абзац тела в блоке.
4. **Склейка.** Если последние два и больше абзацев сообщения — абзацы трейлеров (п. 3), разделённые только пустыми
   строками (п. 3, включая строки из одних пробелов), режим хука удаляет эти строки и больше ничего не меняет.
   Склейка пишется в файл, даже если отказ дан по другой причине (нет `Layer`): git при отказе оставляет
   COMMIT_EDITMSG/MERGE_MSG, повторная попытка начнёт со склеенного текста. Печать в stderr одной строки
   `fixed: trailers joined into one block`. Отказа за разрыв нет.
5. **Режим проверки** (stdin) на склеиваемый разрыв даёт предупреждение `trailers split - the commit-msg hook joins
   them`, не ошибку: `/dev:ship` не должен отклонять то, что хук примет.
6. **Не склеивается** (файл побайтно прежний; правило «trailers git does not see» — phase-3, при `STRICT` отказ):
   разрыв, где между абзацами трейлеров стоит строка без отступа не-трейлер (перенос значения без отступа), или
   абзац начинается с отступа. Причина не чинить перенос автоматически: с 10-04 таких 0 из 150 (правило гайда работает),
   а дописанный отступ меняет значение трейлера. Если 3.2 покажет их возврат — отдельная задача.
7. **`STRICT = True`** в обеих копиях. Отказ при `STRICT` — ровно эти вызовы `_phase3` (строки по HEAD `0a7297809`):
   - 993: текст слияния git по умолчанию;
   - 1075: `merge` без Why/Layer/Refs;
   - 1078: нет `Layer`;
   - 1080: `Layer` не из списка `.claude/commit-layers.txt`;
   - 1113: `Task:` не по грамматике 3.0;
   - 1121: трейлеры, которых git не видит, после неудачной склейки (п. 6).
8. **W-REFS-INVALID (строка 1151) — простое предупреждение, не phase-3.** Причина: оно срабатывает на план, который
   есть только в соседнем worktree, — это не нехватка данных (верхняя граница по истории с 09-01 — 143). Жёсткий отказ
   v1 «у обычного коммита нет Refs на план» не меняется.
9. Длина темы — предупреждение (решение владельца). Без env-флага: переключатель — константа `STRICT`.

Module contract: CLI `validate_commit.py <file>` теперь может переписать `<file>`. Post: файл перезаписан только при
  склейке; убраны только пустые строки между абзацами трейлеров; при ошибке записи исходный файл цел (запись через
  временный файл и замену), rc — как без склейки. `validate_commit.py -` ничего не пишет. Usage в docstring — обновить.
