# Task 3.1: один формат без лишних отказов — хук склеивает трейлеры сам, отказ только при нехватке данных

- **Level:** Middle · **Assignee:** developer → reviewer

TASK: 3.1 — склейка трейлеров и строгий режим для данных                 PLAN: plans/2026-10-03_commit-mechanism/plan.md
ROLE: developer → reviewer
CHAIN: lead -> reviewer (стадия 0) -> tester (только склейка, worktree до кода) -> developer -> lead (injections) -> reviewer

ПЕРЕСМОТРЕНО 2026-10-05 (решение владельца: «главное — один формат, эффективность и качество»).
Прежний текст (всё phase-3 из предупреждений в отказы) снят. Замер лида: валидатор на 150 коммитах `main` с 2026-10-04
дал phase-3 предупреждение в 77. Из них 74 — «trailers git does not see» (пустая строка перед `Co-Authored-By`, её
подсказывает шаблон attribution Claude Code), 3 — текст слияния git по умолчанию; нет `Layer` — 0, неверный `Task:` — 0.
Строгий режим как есть дал бы отказ каждому второму коммиту.

DESIGN (decided by the lead — you type it, you do not derive it):
  1. Склейка (новое). Валидатор в режиме хука `commit-msg` сам переписывает файл сообщения, если в конце сообщения
     два и больше абзацев подряд, и КАЖДАЯ строка в них — трейлер (`TRAILER_RE`) или продолжение значения с отступом.
     Пустые строки между такими абзацами удаляются; больше ничего в тексте не меняется (байты до первого абзаца
     трейлеров — как были, конец строк и кодировка — как были). Хук печатает одну строку `fixed: trailers joined
     into one block`. Отказа нет.
  2. Если хотя бы одна строка в этих абзацах не трейлер (например перенос значения без отступа) — файл не трогается,
     правило остаётся phase-3 (отказ при `STRICT`).
  3. Склейка — только в режиме хука (файл сообщения). Проверка готового текста (`--resolve-plan`, тесты, CI по
     истории) не пишет ничего.
  4. `STRICT = True` в обеих копиях. Отказ — только там, где не хватает данных и починить нечем: текст слияния git по
     умолчанию; `merge:` без Why/Layer/Refs; нет `Layer`; `Task:` не по грамматике 3.0; трейлеры разбиты так, что
     склейка неприменима (п. 2). Длина темы — предупреждение (решение владельца).
  5. Без env-флага. Переключатель — константа `STRICT`, как ввела 2.1.

FILES (complete list — nothing else; need another file -> stop and ask the lead):
  1. обе копии `validate_commit.py`
  2. тесты валидатора (склейка — файлом тестера)
  3. `.claude/COMMIT_GUIDE.md` — строка «пустую строку внутри блока трейлеров хук убирает сам»

REDS: уточняются на стадии 0.

ACCEPTANCE (литералы, не из кода):
  - Сообщение «тема / тело / `Why: a` `Layer: tooling` `Refs: plans/x.md` / пустая строка / `Co-Authored-By: N <e>`»
    после хука — тот же текст без этой одной пустой строки; `git interpret-trailers --parse` видит Why, Layer, Refs,
    Co-Authored-By; rc=0.
  - Блок, в котором строка `wrapped value without indent` стоит между двумя абзацами трейлеров, — файл побайтно
    прежний, rc=1.
  - Абзац тела, похожий на трейлер одной строкой (`Note: см. ниже`), но со строкой прозы в том же абзаце, не склеивается.
  - Слияние с текстом по умолчанию → «Not committing merge» (commitlab); обычный коммит без Layer → rc=1.
  - CRLF-сообщение остаётся CRLF после склейки.
