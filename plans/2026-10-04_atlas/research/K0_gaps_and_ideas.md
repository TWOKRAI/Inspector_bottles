## 3. Правила кода — «храповик», не переписывание разом

Правило обязательно для новых и изменённых файлов фреймворка; `atlas card` показывает долю соответствия модуля.
Переписывание всего кода разом — нет: дорого и конфликтует с соседними треками. Нужна ADR в
`multiprocess_framework/DECISIONS.md` — пишет лид, утверждает владелец.

| Правило | Что даёт | Проверка |
|---|---|---|
| П1. Реализация явно наследует свой интерфейс | реализации находятся точно; дрейф сигнатур ловит pyright без своего детектора | pyright `reportIncompatibleMethodOverride` (в режиме `basic` выключен — проверить и включить для фреймворка) |
| П2. Docstring публичного API — Google-стиль (Args / Returns / Raises) | `ref` выдаёт поля, а не одну фразу | ruff `D`, `convention = "google"`, только `interfaces.py` и имена из `__all__` |
| П3. `__all__` = публичный API | `ref` знает, что показывать | уже есть (сторож `__all__`) |
| П4. Файлы конфигурации пишутся одной функцией фреймворка (атомарная запись) | «кто пишет файл» = кто её вызывает (вопрос 9); исчезает класс дефектов 1.2 | ast-grep / AST: `open(…, "w")` на таких файлах вне функции — находка |

## 4. Готовые библиотеки вместо своего AST

| Библиотека | Что берёт на себя | В `.venv` |
|---|---|---|
| griffe (движок mkdocstrings) | публичный API модуля: сигнатуры, разбор docstring по полям, унаследованные члены, базы, реэкспорты | нет — новая dev-зависимость |
| grimp 3.15 (движок import-linter) | граф импортов с номерами строк — «кто использует» | есть |
| jedi 0.19 | точные ссылки и реализации по одному символу (для `card` одного модуля; на весь репо медленно) | есть |
| libcst 1.8 | автоматическая правка кода под правила (codemod) | есть |
| coverage 7.14 | dynamic contexts: какой тест исполняет какую строку | есть |

## 5. Новые идеи (1.6d, после вердикта K0)

- **А. Карта с прогона тестов.** `coverage` с dynamic contexts: честное «тестов N» (тесты, которые исполняют метод) и
  реальные вызывающие через `getattr`, реестр, плагины — их статика не видит в принципе. Цена — ночной прогон в CI.
- **Б. Каналы роутера в `card`.** Модули фреймворка связаны каналами чаще, чем импортами; граф импортов этого не
  видит. Разбор `FieldRouting` / `send_message` уже есть в команде `/channel-map`.
- Отложено раньше и остаётся отложенным: MCP-сервер Атласа, эмбеддинги.

## 6. Раскладка

- **1.6c** (до третьей задачи K0): `ref`/`card` на griffe + grimp (+ jedi для `card`), проверки П1–П4 как находки
  (код фреймворка под правила не правится), включение pyright-проверки, `pack` для задачи без коммитов, честный
  счёт тестов по статике; экзамен 8 из 10; холодный build не медленнее базы на 30 %.
- **ADR правил П1–П4** — лид, параллельно с брифом 1.6c.
- **1.6d** (после вердикта K0): идеи А и Б.
- Третья задача K0 мерит Атлас после 1.6c — в вердикте это сказано прямо.
- Экзамен не набрал 8 из 10 → Атлас как помощник брифа не работает; K0 закрывается отказом от расширения.
