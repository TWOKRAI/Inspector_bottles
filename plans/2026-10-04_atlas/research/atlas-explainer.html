Атлас проекта

Правда проекта — файлы в git. Доверие к модулю строится не на прочитанном коде, а на доказательствах, которые код пережил: тест на каждое публичное имя, инъекция, показавшая, что тест умеет краснеть, мутационный балл из CI. Атлас собирает эти доказательства с планов, коммитов и тестов в один реестр. Реестр он показывает двумя способами: страницей для владельца и карточкой для агента перед работой. Что выводится, не пишется руками. Что написано руками, имеет один дом. Старое помечено один раз и не переделывается.

CTO: принято с поправками качество в центре системы kill-проверка через 3 недели после ядра основа: main = 03952a020

Почему это станет лучше, а не просто больше

  • Контроль через доказательства, а не через чтение. Агент пишет код быстрее, чем его можно прочитать. Атлас показывает, что код пережил: тесты, инъекции, мутационный балл. Слабое место видно числом.
  • Генерируемое не стареет. Половина фактов, которые сегодня расходятся, выводится из кода и git. Когда их перестанут писать руками, расхождения исчезнут.
  • Система сжимается. Уходят три копии памяти, два COMMIT_GUIDE, три дома ADR, два парсера планов, мёртвые скрипты и таблицы из CLAUDE.md. Фаза принимается, только если удалила больше, чем добавила: в каждой приёмке есть ведомость удалений.
  • Есть способ проверить и остановиться. Через 3 недели после ядра. Если ни одно ревью не сослалось на находку Атласа, или мутационный гейт флапает больше 20 % прогонов, или строка доказанности не изменила ни одного решения — карточка и HTML снимаются. Остаются два гейта CI и генерируемые блоки.
Правила

Пять принципов

  1. Истина — файлы в git.Реестр производный, его не коммитит никто.
  2. Что выводится, руками не пишется.Что пишется руками, имеет один дом.
  3. Свежесть — число коммитов в зоне документа.Не отметка и не дата.
  4. На main пишет один.Лид в точке слияния. CI проверяет, но не пишет.
  5. Фаза принята, если удалила больше, чем добавила.Система должна сжиматься, а не расти.
  6. Старое помечается один раз и не переделывается.Отсечка legacy_before: <SHA слияния А1>: находки по старому только информационные, база-храповик пишется один раз. Строгие проверки — для нового.

Это подход «контроль через тесты, а не через чтение кода». В проекте он уже есть как культура: слепой тестер до кода, инъекция на каждое свойство, ревьюер запуском. Ваш вопрос

Ветки деревом по модулям?

Что показали числа

  • 72 % слияний задевают 2+ модулей, 43 % — 3+.
  • Задача плана в медиане трогает 5 модулей.
  • Влитая ветка живёт около часа, 91 % — меньше суток.
  • Долгая ветка feat/lifecycle-owner-scope отстала от main на 118 коммитов при 18 своих.

Что делаем вместо веток

  • atlas log <модуль> — лента изменений области по main, сгруппированная по задачам.
  • Карточка модуля: последние коммиты, открытые задачи, ветки, которые его сейчас трогают.
  • Область в заголовке коммита подставляется сама по путям.
  • Долгая ветка области — только исключение: один владелец, main вливается ежедневно, срок до 7 дней.

Дерево уже есть — это история коммитов в main. Не хватает вида по области, и его даст лента модуля без долгих веток и дрейфа.

Память: одна, сжатая, без потерь

  • Канон — docs/claude/memory в git. Локальная папка — кэш, наполняется скриптом.
  • Проход 1, скрипт без LLM: 160 одинаковых и 100 отличающихся только переводами строк сливаются сами. Остаётся 156 реально разных.
  • Проход 2, Sonnet в облаке: раскладывает 431 файл по видам и присылает PR с таблицей «файл → действие → причина».
  • Правило, которое должно сработать само, уходит в хук или project-rules. Урок с числами остаётся и привязывается к модулю. Состояние работ заменяется ссылкой на план.
  • Ничего не удаляется: всё уходит в _archive/ со ссылкой. MEMORY.md — до 8 КБ. Цена $25–35.

Handoff: короткий результат на задачу

  • Свободный handoff от каждого агента — нет. В handoffs уже 77 файлов, их читают несистемно.
  • Вместо него обязателен tasks/<id>.result.md до 2 КБ: сделано, осталось, не проверено, файлы, SHA, таблица инъекций, кому передано.
  • Один файл — один писатель, поэтому конфликтов нет.
  • Атлас показывает «осталось» и «не проверено» в пакете следующей задачи и в карточке модуля. Так следующий агент реально видит чужой результат.
  • Уроки роли по-прежнему пишутся в agent-memory, таблица agentId — в handoff лида.

Метрики: доказанность по модулю (имена с тестом, гарантии с инъекцией, мутационный балл); слияния, изменившие интерфейс без теста, → 0; дефекты, найденные живым стендом уже после ревью, → вниз; цена входа агента; мест на один факт; MEMORY.md ≤ 8 КБ.
