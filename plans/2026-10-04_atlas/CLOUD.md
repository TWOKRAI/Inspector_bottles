## Правило выбора места

Облако — где работа = исполнитель пишет код и гоняет тесты на Linux, а контекст передаётся файлом задачи.
Локально — где нужен лид (спека, инъекции, ревью, слияние, запись в `main`), Windows, живой стенд, qex/serena,
или где задача — короткий текст и запуск облачной сессии (установка окружения, чтение правил) дороже самой работы.

## Правила облачной сессии (дополняют `plan.md` → «Правила исполнения»)

1. Одна сессия = одна задача = одна ветка `atlas/<task>` (например `atlas/1.2`) от свежего `main`; сдача — PR в
   `main`. Коммит и push в `main`, `--force`, `--no-verify` — нет.
2. Порядок внутри задачи — конвенция проекта: тестер (до кода, свой коммит в ветке) → developer → отчёт. Инъекции,
   ревью и слияние делает лид локально по ветке PR.
3. Трейлеры `Why:`/`Layer:`/`Refs: plans/2026-10-04_atlas/plan.md`/`Task: atlas#<id>` одним блоком — их проверяет job
   `commits` на PR (git-хуков в облаке нет).
4. Файлы вне задачи не трогать. Особенно: `.github/**` (кроме 1.7/1.8), `plans/queue/ORDER.md`, `CLAUDE.md`,
   `.claude/**`, `docs/claude/memory/**`, чужие планы.
5. Итог — `plans/2026-10-04_atlas/tasks/<id>.result.md` в ветке PR: сделано / осталось / не проверено / SHA; цена
   сессии в $ и `subagent_tokens`. Урок для памяти — блоком `MEMORY LESSON <имя>.md` в итоге (2.4g Р5): файл кладёт лид.
6. Не больше трёх облачных сессий одновременно (правило плана о писателях); лид держит очередь слияний.

## Защита `main` от облака

- Облачная сессия технически может сделать push в `main`: прокси GitHub блокирует только force-push и теги
  (документация cloud, 2026-10-06). Запрет держится на правилах выше.
- Хук `protect-branch.sh` ловит только команду, которая **начинается** с `git commit` (regex `^\s*git\s+commit`):
  `git add x && git commit …` проходит на `main` (замер 2026-10-06: прямой вызов хука → rc 2, а коммиты лида вида
  `git add … && git commit` в `main` шли без блока). Push хук не проверяет вовсе. Хук — сид claude-kit; правка — в
  `OPEN_QUESTIONS.md`, не здесь.
- **Настоящая защита — ruleset GitHub на `main`** (репозиторий публичный — rulesets бесплатны): Settings → Rules →
  Rulesets → New branch ruleset → цель `main`; включить «Restrict deletions», «Block force pushes», «Require a pull
  request before merging»; в «Bypass list» — роль Repository admin (лид пушит слияния под владельцем). Облачная
  сессия ходит через GitHub App Claude — не admin, её прямой push в `main` будет отклонён. Делает владелец (UI).
