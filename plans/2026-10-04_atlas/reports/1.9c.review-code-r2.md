## Замечания
- [blocker/design] Блокер р.1 по pytest `@файл` закрыт не полностью. Новая проверка отсекает `@` только у позиционного аргумента. Значения `-k` и `-m` цикл пропускает (`i += 1`) без проверки. А pytest раскрывает `@файл` в ЛЮБОЙ позиции: `_pytest/config/argparsing.py:463` → `fromfile_prefix_chars="@"`, это раскрытие argparse до разбора. Проба без записи файлов (`probe_r2b.py`, `replay.run` во временном репозитории):
  `python -m pytest --collect-only -q -k @k1 tests/test_ok.py` (в `k1` строка `nomatch`) → `(5, 'no tests collected (1 deselected)')`: файл раскрыт;
  `… -k @nosuchfile …` → `(4, "error: [Errno 2] No such file or directory: 'nosuchfile'")`;
  `… -k @k3 …` (в `k3` строки `test_ok` и `--help`) → `(0, 'usage: __main__.py [options] …')`: опция вне allow-list применена.
  Через тот же путь проходят `--junitxml=`, `-p <модуль>`, `-c`, `-o`. Решение `replay._allowed` для `… -k @x t.py` → `ALLOW`.
  Исправить в `replay._pytest_ok`: до цикла `if any(a.startswith("@") for a in args): return False`. В `test_allow_list_option_spellings` добавить `python -m pytest --collect-only -q -k @args.txt tests/test_ok.py` и то же с `-m`. В матрицу — инъекция, которая возвращает текущую проверку (только позиционный `@`); ожидаемый красный — этот тест.
- [nit/design] Побочный эффект префиксного отказа git. Решения `_allowed`: `git log --follow -- src/a.py` → deny (имя — префикс `--follow-symlinks`), `git log --e` → deny, `git grep -e -Ox alpha` → deny (значение `-e`). Ошибки нет: такие строки уходят в «не сверено». Но `--follow` — обычная опция для факта «история файла». `--follow-symlinks` у git действует только вместе с `--batch*`, а `--batch*` уже запрещён.
  Исправить (по желанию): убрать `--follow-symlinks` из `_GIT_BAD_LONG`.
