## Замечания
- [major/design] С `--module` объект задачи теряется, а вместе с ним файл объекта, члены, тест, потребители и второе звено.
  Вход: `python -m scripts.atlas brief k0-framework-quality#1.2 --ref 24a229e66 --module config_module`. Это тот же модуль, который `pack` выбирает сам. Наблюдение: exit 0, stderr `brief: объект задачи не найден — задать --symbol`; `grep -c "ConfigFileWatcher\|через"` → 0. Без флага → 15.
  У задачи с коммитами то же: `brief k0-framework-quality#1.2 --ref 2d7e9d8f6` → тот же stderr.
  Причина: `brief.py:128-131` собирает `text_files` только из строк `pack`, которые кончаются на `— из текста задачи`. `pack --module` и `pack` задачи с коммитами таких строк не печатают. Резерв DESIGN 6 («символы файлов из текста задачи») тогда пуст. В строке плана путь стоит в обратных кавычках (`config_module/tools/watcher.py`), идентификатора там нет.
  Исправить: файлы «из текста» брать всегда из `views.pack(..., [])` без `--module` (вызов в процессе, вид кэширован) или из путей в обратных кавычках строки задачи (`text` уже разобран на `:150-152`). Тест: `brief alpha#1.1 --module m` → литерал `m/widget.py` у `файл объекта Widget`. Инъекция с прогнозом.
- [minor/fact] Строки кандидатов из первого `pack` не отфильтрованы по DESIGN 5 («`pack`: из текста»). Файлы самой задачи помечены «из прошлой задачи».
  Вход: `brief k0-framework-quality#1.2 --ref 2d7e9d8f6` → 12 строк `кандидат в FILES из прошлой задачи`. Из них 8 кончаются на `— 1.2`: это коммиты самой задачи 1.2, не прошлой. Каждый путь стоит дважды: из `pack k0-framework-quality#1.2` и из `pack … --module config_module`.
  Исправить: на `brief.py:127-131` из первого `pack` брать только строки `— из текста задачи`. Строки `— <id своей задачи>` не писать: в словаре DESIGN 4 нет для них «что». Если такое слово нужно, лид добавляет его в DESIGN.
- [minor/design] `--write` собирает весь блок и только потом проверяет путь файла задачи.
  Вход: `brief otel-export#0.1 --write --ref 24a229e66` (план `plans/otel-export.md`, без `/plan.md`). Наблюдение: exit 2. В stderr сначала `brief: объект задачи не найден — задать --symbol` (блок собран), потом `brief: нет плана otel-export с каталогом tasks/ …`. На холодной базе это полная сборка, около 30 с (замер developer), впустую.
  Исправить: в `__main__.py:137-139` при `args.write` звать `brief.task_file(root, args.task)` до `brief.brief(...)`.
- [minor/dryrun] У половины DESIGN 10 («пути модулей из команд блока — входы `--check`») нет красного.

- [nit/design] Правило «самый длинный элемент `split` по обратной кавычке» даёт в хвостах куски без смысла.

  Вариант: перед выбором самого длинного куска срезать по краям `,;:()` и брать только кусок не короче двух слов. Иначе строку не писать.

  Исправить: `.removeprefix("\ufeff")`.
- [nit/design] Если в файле смешанные концы строк, `--write` переводит их все в CRLF, и меняются строки вне блока.
  Вход (в процессе, scratch): `brief.write()` на `b"# Task 9.9\r\nTASK: 9.9\nROLE: developer\r\n\nDESIGN (decided by the lead):\n  1. a\n"` (2 CRLF, 4 LF) → CRLF 10, голых LF 0. DESIGN 9 обещает, что концы строк сохраняются.

- [nit/scope] `brief.py` — 281 строка против «≤ 260» в DESIGN 11. Вход: `wc -l scripts/atlas/brief.py` → `281`. Код уже ужат за счёт читаемости: `[x] * (условие)` вместо `if` (`:131`, `:276`), три `# fmt: skip`. Функция `brief()` занимает 106 строк, в ней три замыкания.

- Удалённый файл в pathspec `git diff`: не воспроизведён. Между `24a229e66` и HEAD вне `plans/` удалённых файлов нет (`git diff --name-only --diff-filter=D` → пусто). Что `git diff --name-only <sha> -- <путь>` печатает удалённый путь, я знаю из семантики git, не из прогона.
- Неоднозначный sha7: не воспроизведён. `resolve` снимает неоднозначность через `^{commit}`, а `git diff` на `brief.py:278` получает сырой sha7. Совещательно: передавать в `git diff` полный sha из `resolve`.
