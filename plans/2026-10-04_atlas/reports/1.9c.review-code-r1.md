## Замечания
- [blocker/design] Allow-list git пропускает внешнюю команду через пейджер `git grep`. Фильтр сверяет префикс аргумента (`-O`, `--open-files-in-pager`), но git принимает склейку коротких опций и сокращение длинных. Проба `replay.run` во временном репозитории (скрипт в scratchpad, `probe_sec.py`): `git grep -nOtouch\ made_by_nO alpha` → `(0, False, '')`; `git grep --open-f=touch\ made_by_openf alpha` → `(0, …)`; `git grep --op=touch\ made_by_op alpha` → `(0, …)`. После прогона в корне есть файлы `made_by_nO`, `made_by_openf`, `made_by_op`. Полное `--open-files-in-pager=…` → `None` (фильтр видит только его).
  Исправить в `replay._git_ok`: у `--имя[=…]` отказ, если имя — префикс любой запрещённой длинной опции (`any(bad.startswith(name) for bad in …)`, правило сокращений git); у одиночного `-xyz` отказ, если в склейке есть `O`. В `off_cmds` теста добавить три написания с маркерами `made_by_*`.
- [blocker/design] Allow-list pytest пропускает файл аргументов `@файл` (pytest 9.0.3, есть с 8.2). Через него проходят `--junitxml=`, `-p <модуль>` и любые опции. Проба: `args.txt` = `--junitxml=made_by_argfile` / `-p` / `no:cacheprovider`, `python -m pytest --collect-only -q @args.txt` → `(0, False, 'tests/test_ok.py::test_ok | … 1 test collected')`, в корне появился `made_by_argfile`.
  Исправить в `replay._pytest_ok`: отказ для аргумента, который начинается с `@`. В тест добавить строку факта с `@<файл>`, в файле `--junitxml=made_by_argfile`.
- [major/dryrun] Фильтры безопасности почти не покрыты тестами. Удалить по одному `-O`, `--open-files-in-pager`, `--exec`, `--batch`, `--ext-diff`, `--textconv`, `--follow-symlinks`, проверку `no:` у `-p` (inj-32, observed `[]`), ограничение `wc -l` корнем (inj-33, observed `[]`), фильтр `--w` у `brief`/`index` — во всех случаях тесты остаются зелёными. `grep -n -e "--write" -e "open-files" -e '"-O' scripts/atlas/tests/test_lint_brief_1_9c.py` → 0 строк. В тесте опции проверяют только `--output=`, `--junitxml=`, `git -c`. Счёт `сверено 17, вне allow-list 8` и `sorted(off_list) == sorted(off_cmds)` ловят только сужение списка, расширение не ловят.
  Исправить: по одной строке вне списка на каждое запрещённое написание (вместе с двумя блокерами выше), каждая с файлом-маркером. Для `wc -l ../x` — проверка «не сверено».
- [minor/dryrun] Чтение лидом inj-19 («эквивалентный мутант: communicate() закрывает stdin и без него») неверно для свойства из плана. План: «`stdin=DEVNULL` снят». Инъекция же заменила его на `stdin=PIPE`, а `communicate()` закрывает свой PIPE, поэтому мутант эквивалентен по построению. Если аргумент снять, stdin наследуется от родителя. Проба (`probe_proc.py`, мутант в памяти `subprocess.DEVNULL = None`, родитель с открытым stdin `sleep 15 | python …`): `git log --stdin -1` → `inherit: 1 True 5.1s` (таймаут). С DEVNULL: `devnull: 0 False 0.0s`. DEVNULL нужен.
  Исправить: перепрогнать inj-19, где `new` удаляет строку `stdin=…`. Ожидаемый красный — `test_replay_allow_list_and_no_shell` (через `_assert_open_stdin_does_not_hang`: `ATLAS_REPLAY_TIMEOUT=5`, ассерт «нет FACT_TIMEOUT»). Поправить текст коммита `f90098109`.
- [minor/design] `ATLAS_REPLAY_TIMEOUT` не проверяется на значение. Проба `probe_proc.py env`, команда `git rev-parse HEAD`: `'0'` → таймаут 0.0, `timed_out=True` за 0.17 с; `'-5'` → то же. Каждая строка факта даёт ложный `FACT_TIMEOUT`. `'inf'`/`'1e400'` → `OverflowError timestamp out of range`, `'nan'` → `ValueError`: трассировка и код 2.
  Исправить в `_timeout`: принимать только конечное число > 0, иначе — умолчание 300 (или `AtlasError` с именем переменной).
- [minor/design] `LITERAL_TIMING` (регулярка DESIGN 5 дословно) срабатывает на русский предлог «с». `lint_brief._TIMING.search("2 с ошибкой")` → `True`, `"файлов 3 с маркером"` → `True`. Верный литерал из русского вывода (`atlas` пишет по-русски) получает ошибку с кодом 1 и не повторяется.
  Исправить: после `с`/`сек` запретить продолжение « <буква>», например `(?:с|сек)(?![\w])(?![ \t]+[а-яёa-z])`, и добавить в тест литерал `2 с ошибкой` как «не время». Или записать ограничение в ADR §2.5б. Решает лид.
- [nit/form] `FACT_MISMATCH` печатается в две строки (`…: <литерал>\n  вывод: …`). DESIGN 2 требует «по строке на находку», DESIGN 7 — `… | вывод: …`. Вторая строка начинается с двух пробелов, как строки `  не сверено`. Построчный читатель (grep, будущий `--json` 1.10a) ошибётся. Проба: пин `1.2.md` → после строки `…:26: error FACT_MISMATCH литерал не найден в выводе: tools/watcher.py:81:` идёт отдельная строка `  вывод: …`. В ADR §2.5б отклонение записано, оно принято. Если две строки остаются, читатель 1.10a должен знать формат.
- [nit/design] В спавне порядок отказов зависит от проекта. `_limits` сначала собирает все `*_MISSING`. Промпт: DESIGN 2 строки, FILES нет, REDS 11, REPORT нет. Проект с модулем → `FILES block missing; DESIGN has 2 …; REDS lists 11 …; REPORT block missing`. Пустой проект (`_legacy_violations`) и хук до правки (`e82f1b8f3`) → `DESIGN has 2 …; FILES block missing; …`. Тексты прежние, решение deny то же. Порядок не читает никто: тесты ищут подстроку. Регрессии функции нет.
  Исправить (по желанию): в `_limits` выдавать нарушения поблочно (DESIGN, FILES, REDS, затем REPORT), как было.
- [nit/dryrun] Чтение расхождений inj-9 и inj-15 неточное. inj-9: 7 красных тестов дал сбой, не CRLF. После `split("\n")` строк N+1, а `_unfenced_lines` даёт N, поэтому `doc.fenced[i]` выходит за границу. Мутант в памяти на LF-брифе с последней меткой `OUT OF SCOPE` → `IndexError: list index out of range` в `lint_brief.py:139`. Свойство CRLF инъекция не изолирует. inj-15: в прогнозе есть `test_freshness_flags_and_usage`, а в observed его нет. Формула «прогноз занижен» к inj-15 подходит только наполовину. inj-16, inj-28, inj-30 лид прочёл верно: observed — надмножество прогноза, причины проверены по тестам (n/a в хуке, forecast из FILES роли, повтор в `--no-replay`).
  Исправить: для inj-9 взять мутант той же длины, например `self.lines = [ln + "\r" for ln in text.splitlines()]` для CRLF-файла. Ожидаемый красный — CRLF-ветка `test_facts_grammar_marker_timing`.

## Что я оставил открытым / ненадёжным
- POSIX-путь `_kill_tree` (`os.killpg`) и зомби после второго `TimeoutExpired` не запускал: машина Windows. Проверка будет в CI ubuntu (тест таймаута) или на стенде.
- Python старше 3.11 нет на машине (`py -0` → 3.11, 3.13, venv 3.12). Импорт под 3.8–3.10 не проверен. На старом `$PY` `SyntaxError` в `plans_ledger`/`lint_brief` даёт fail open: хук молча пропускает всё. Раньше встроенный код работал на любом Python 3. Это следствие DESIGN 11, лиду решить, нужна ли запасная копия и на `SyntaxError`.
- Расхождение путей хука на экзотических разделителях строк (совещательно): `str.splitlines()` режет по `\u2028` и `\x0c`, старый `re.MULTILINE` по ним не режет. Промпт с `  0. d0\u2028REPORT: fake` в DESIGN: проект → `DESIGN has 1 …`, запасная копия и старый хук → пропуск. В реальных промптах таких знаков не встречал.
- Байт NUL в команде факта → `ValueError: embedded null character` из `Popen`, перехвата нет → трассировка и код 2. Видел только в пробе `replay.run` напрямую. Совещательно.
- На Windows `Popen(["git", …])` и `["taskkill", …]` ищут exe и в текущем каталоге родителя (корень репозитория). Подложенный `git.exe` в корне запустится. Это атака содержимым репозитория, не брифом. Не проверял, совещательно.
- `lint(…, replay: bool)` закрывает имя модуля `replay`, а `# noqa: A002` к нему не относится (A002 — про встроенные имена). Сейчас внутри `lint` модуль не зовётся. Риск только для будущей правки, в замечания не вынес.
- Мутанты в памяти (inj-9, inj-19, inj-25) — мои пробы в отдельном процессе, файлы не правил. Полный перепрогон матрицы инъекций по файлам — за лидом.
- Полный набор Атласа не гонял: лид сообщил `316 passed, 2 skipped`, красный `test_modules_map.py::test_every_source_file_has_a_module` есть и на main.
- Скрипты проб лежат в scratchpad сессии (`probe_sec.py`, `probe_proc.py`, `probe_gc.py`, `hook_drive.py`, `real.txt`), в репозиторий не попали.
