## DESIGN (решения лида)

1. **Маркер `slow`** регистрируется в `pyproject.toml` → `[tool.pytest.ini_options].markers` строкой с причиной.
   Ставится декоратором `@pytest.mark.slow` **на функцию** — ровно на три теста из «Медленные тесты» (в каждом их
   файле остальные тесты быстрые; `pytestmark` модуля не годится).
2. **По умолчанию `slow` пропускается с причиной, а не вырезается** — приём `backend_ctl/tests/conftest.py`
   (живые `harness_smoke`): строка `N skipped` в отчёте видна, «не собрали» — нет. В `scripts/atlas/tests/conftest.py`:
   - `pytest_addoption`: флаг `--atlas-slow` (`store_true`, по умолчанию `bool(os.environ.get("ATLAS_SLOW"))`);
     помощь: «… алиас — env `ATLAS_SLOW` (любое непустое значение, `0` тоже включает)»;
   - `pytest_collection_modifyitems`: флаг включён → не вмешиваться; оператор дал непустой `-m` → не вмешиваться;
     иначе элементу, у которого **`item.get_closest_marker("slow") is not None`**, — `pytest.mark.skip` с причиной,
     где есть `ATLAS_SLOW=1` и `--atlas-slow`. Условие `"slow" in item.keywords` (как в backend_ctl) **запрещено**:
     keywords содержат id параметризации и имена родительских узлов (ревью р.1: тест с `parametrize(["fast","slow"])`
     без маркера → `skipped`).
   - docstring conftest: локальная команда `python -m pytest scripts/atlas/tests -q` (slow — skipped с причиной),
     полный набор — `ATLAS_SLOW=1`; `-m "not slow"` — **только вместе с путём** `scripts/atlas/tests` (из корня явный
     `-m` снимает и пропуск 44 живых тестов backend_ctl, ~10 мин); `--atlas-slow` распознаётся только в прогоне, где
     загружен этот conftest (`pytest backend_ctl/tests --atlas-slow` → «unrecognized arguments»), env — везде.
3. **Job `atlas` в `.github/workflows/ci.yml`** (триггеры — общие для файла: push в `main`, `pull_request`,
   расписание, кнопка):
   - `runs-on: ubuntu-latest`; `timeout-minutes: 45` (≈ 1,6× локального полного прогона 1651 с; время на ubuntu до
     A8 неизвестно);
   - `env: QT_QPA_PLATFORM: offscreen` и шаг «Установка системных Qt-зависимостей» (`libegl1 libgl1 libxkbcommon0
     libdbus-1-3`) — как у job `tests` (замер выше: тест импортирует `frontend_module`);
   - `actions/checkout@v4` с `fetch-depth: 0`: пиновым тестам нужны полный клон и разрешимые пины
     (`test_views_pinned.py:39-42`), шагу `check` — `origin/main`;
   - `astral-sh/setup-uv@v5` + `uv sync`, как у соседних job;
   - шаг 1: `uv run python -m pytest scripts/atlas/tests -q -p no:cacheprovider`, `ATLAS_SLOW: "1"` в `env` шага
     (в CI гоняется всё, включая `slow`); в `run` нет `-m` и `-k`;
   - шаг 2 — `check`, база зависит от события (`env: EVENT: ${{ github.event_name }}`,
     `BEFORE: ${{ github.event.before }}`; в `run` — `if [ "$EVENT" = push ]; then … --base "$BEFORE"; else …; fi`):
     - **push** (в `main`): `uv run python -m scripts.atlas check --base "$BEFORE"` — вершина `main` до push. С 1.6e
       в `main` попадают локальные слияния лида push'ем; без этого `check` на push сравнивал бы HEAD с самим собой
       (merge-base = HEAD) и не стерёг бы ничего (ревью р.2, «открыто»);
     - **иначе** (pull_request, расписание, кнопка): `uv run python -m scripts.atlas check` — **без `--base`**:
       `git merge-base <main-ref> HEAD`, как требует `scripts/atlas/DECISIONS.md:191` («в CI на синтетическом слиянии
       PR это `HEAD^1`. Не `main` и не `base.sha`»). На PR-checkout локального `main` нет → `_default_main_ref` даёт
       `origin/main`. `--base origin/main` давал бы ложный красный при повторе старого PR-прогона, когда `main` ушёл
       вперёд (`check.py:67` берёт вершину, не merge-base). Расписание: merge-base = HEAD, пустое сравнение.
     Строка `plan.md` 1.7a правится (`check --base origin/main` → `check`, на push — `--base` = до push);
   - шаг 3: `uv run python -m scripts.atlas index --check`.
   Шапку файла («Что гоняется») дополнить строкой про job `atlas`.
4. `plan.md`, строка 1.7a: «локально `-m "not slow"`» → «локально slow пропускаются с причиной (`ATLAS_SLOW=1` —
   полный набор)»; `check --base origin/main` → `check` (merge-base). Статус — при закрытии задачи.

## ACCEPTANCE

Объект A1–A4 — **синтетический** тест (свой временный файл с `@pytest.mark.slow` и без него), запускаемый подпроцессом
pytest (или `pytester`) так, чтобы действовали хуки `scripts/atlas/tests/conftest.py`; способ — на выбор tester.
Три настоящих медленных теста в приёмке **не исполняются**. Файл приёмки целиком ≤ 30 с. Для разбора вывода —
`-o addopts=""` или `-qq` (корневой `addopts = "-v --tb=short"` гасит `-q`). **Env подпроцесса задаётся явно:**
режимы «без env» запускаются с удалённым `ATLAS_SLOW` (копия `os.environ` без ключа или `monkeypatch.delenv`), режим
env ставит его сам — в CI весь шаг идёт с `ATLAS_SLOW=1`, и унаследованный env сделал бы A1 красным (ревью р.2:
родитель с `ATLAS_SLOW=1` → `2 passed` вместо `1 passed, 1 skipped`).

- [ ] A1. Тест с маркером `slow` в прогоне без флага и без env — `skipped`, причина содержит `ATLAS_SLOW=1`.
- [ ] A2. С `ATLAS_SLOW=1` или с `--atlas-slow` тот же тест исполняется (`passed`).
- [ ] A3. С явным `-m "not slow"` тест `deselected`, не `skipped`; с `-m slow` — исполняется (`passed`).
- [ ] A4. Тест без маркера `slow` во всех режимах A1–A3 исполняется (кроме `-m slow`, где он `deselected`); тест без

      `skipped`.
- [ ] A5. `python -m pytest scripts/atlas/tests -m slow --strict-markers --collect-only -qq` → exit 0 и ровно три
      node id — литералы списка «Медленные тесты» (маркер зарегистрирован и стоит ровно на трёх).
- [ ] A6. `ci.yml`: есть job `atlas`; его checkout с `fetch-depth: 0`; шаг pytest `scripts/atlas/tests` с
