**Решения лида (приняты при постановке задачи, имеют приоритет над столбцом «умолчание»):**

- `ref <module>`: по каждому интерфейсу — строка-заголовок (имя, первая фраза docstring класса, `interfaces.py:<строка>`, число тестов, путь к одному тесту-примеру из рёбер `tests`); по каждому публичному методу — две строки: сигнатура «имя(арг: тип = умолч., …) -> тип  :<строка>» и первая фраза docstring; третья строка «Pre: … / Post: …», если они есть. Нет docstring — «нет описания». Длинные типы — для чтения: `Union[A, B]` → `A | B`, `Optional[X]` → `X | None`, кавычки форвард-ссылок снять; смысл не менять.
- Источник сигнатур и описаний — AST `interfaces.py` в дереве ревизии сборки (`Tree.read` по sha), в момент вызова вида; схема SQLite не меняется (реестр хранит имена интерфейсов, `ref` дочитывает файлы той же ревизии — источник один, детерминизм по sha сохраняется). Причина: не плодить новый вид узла ради справочника.
- `index`: весь проект на одной странице — по каждому модулю `modules.yaml` одна строка «id — назначение» и до 5 главных интерфейсов (по числу методов). Не больше 200 строк. Назначение модуля и в `card`, и в `index` — первая ФРАЗА README (до точки), не первая строка; markdown-разметку убрать.
- Файл `docs/atlas/INDEX.md` — вывод `atlas index`, генерируется той же командой (`atlas index --write`), руками не правится (строка-шапка об этом в самом файле). Проверка свежести: тест в `scripts/atlas/tests`, который регенерирует индекс на HEAD и сравнивает с файлом — 0 строк разницы. Подключение проверки в CI — задача 1.7, не здесь.
- Скорость: тёплые `ref` и `index` ≤ 1 с. Холодная сборка не входит.
- Приёмка: `ref router_module` содержит строку метода `send` с типами и `interfaces.py:<строка>` (литерал в тесте) и «нет описания» хотя бы у одного метода из модуля, где оно отсутствует; `index` покрывает все строки `modules.yaml` и ≤ 200 строк.

Решения:

1. **Два вида, один новый файл.** `ref <module>` и `index` — подкоманды `python -m scripts.atlas`; весь код — `scripts/atlas/reference.py` (новый); фраза «назначение» — общая функция в `views.py` (её используют `card` и `index`, дубля нет); проводка — `scripts/atlas/__main__.py`. Ядро (`build.py`, `store.py`, `check.py`, `schema.py`, `tree.py`, `modules.py`), все адаптеры (включая `adapters/code.py`: узлы `interface` не меняются, `_BASE` не поднимается) и `scripts/atlas/views.py` кроме п. 4 не трогаются. Оба вида читают `data/atlas.sqlite` SQL-запросами по `build_id` после `build(con, root, ref, main_ref)` (ленивая сборка, как у `card`), соединение приходит из `main()`, `reference.py` не вызывает `store.connect`. Данные из git (`interfaces.py`, README, тестовые файлы) вид читает сам, байты, `decode("utf-8", "replace")`, `﻿` в начале срезается; чтение — через `Tree`/`scripts.atlas.adapters.code._read` (пакетный `cat-file`). Причина: схема SQLite не меняется (решение лида), `--json` на тёплой базе 17,8 МБ и ≈ 2 с против предела 1 с.
2. **Формат `ref <module>`** (строки в этом порядке; интерфейсы по возрастанию имени, `sorted` по строке; методы — в порядке исходного файла):
   ```
   Справочник модуля {id} — {путь interfaces.py}, интерфейсов {n}
   {Имя} — {фраза или «нет описания»} — interfaces.py:{N} — тестов {t}[, пример {путь теста}]
     {сигнатура}  :{N}
       {фраза или «нет описания»}
       Pre: … / Post: …
   ```
   Нет интерфейсов (в реестре нет узлов `interface` модуля) — единственная строка `Справочник модуля {id} — интерфейсов нет`, код 0. Интерфейс — узел `interface` модуля; **выбор по точному префиксу `{id}:`** (`substr`, не `LIKE`: `_` — подстановочный знак, модули `a_b` и `axb` не смешиваются). Файл — `path` узла (корневой `interfaces.py` модуля). Строка `{N}` — `lineno` оператора `class`/`def` (не декоратора). Виды определения имени из `__all__`: (а) `class` верхнего уровня — заголовок с фразой docstring класса и блок методов; (б) `def`/`async def` верхнего уровня — вместо имени в заголовке стоит сигнатура (формат п. 3), фраза — docstring функции, методов нет; (в) `from … import …` (в том числе `as`) — `{Имя} — реэкспорт из {откуда} — …`, где `откуда` = точки уровня + `module` (`.core.base`, `.`), строка — оператора `from`; (г) прочее (присваивание `Имя = …`, `import x as y`, имя только в `__all__`) — «нет описания», строка оператора присваивания/`import`, а если оператора нет — строка элемента в `__all__`. У (б)–(г) блока методов нет. Метод — публичный (имя без `_`) `def`/`async def` в теле класса; свойства и методы без docstring включаются; атрибуты класса не выводятся. Причина формата — решение лида; причина точного префикса — как у `card` (1.6).
3. **Сигнатура** (правила для тестера и developer; всё через `ast`, без импорта кода проекта): `{имя}({арги}) -> {тип}`; `async` метод — префикс `async `; свойство (`@property`) — без скобок `{имя} -> {тип}`; `self`/`cls` первым параметром не выводится (у `staticmethod` не отбрасывается); результат без аннотации — без ` -> …`. Аргумент: `имя`, с аннотацией `имя: тип`; значение по умолчанию — `имя: тип = значение` (пробелы вокруг `=`, если есть аннотация) и `имя=значение` (если аннотации нет); значение — `ast.unparse` (`'normal'`, `None`, `0.0`); `*имя`, `**имя` (с аннотацией `*keys: str`), одинокий `*` перед keyword-only, `/` после позиционно-только. Многострочная сигнатура — в одну строку, аргументы через `, `. Типы «для чтения» (смысл не менять): `Union[A, B]` → `A | B` (вложенные `Union`/`Optional` разворачиваются плоско), `Optional[X]` → `X | None`, строковая аннотация `"Msg"` → `Msg` (строка разбирается как выражение и упрощается так же; не разбирается — выводится без кавычек как есть); `Dict[str, Any]`, `List[...]`, `Callable[...]` остаются как написаны; `typing.Optional`/`typing.Union` не встречаются (замер) и не обязательны. Причина: решение лида; правила скобок и пробелов заданы здесь явно, чтобы вывод не зависел от версии `ast.unparse`.
4. **Первая фраза и назначение (общая для docstring, `card` и `index`).** Абзац — подряд идущие непустые строки (после `strip`), склеенные через пробел. Порядок операций (закреплён литералами Ф4): (1) абзац; (2) обрезка по **сырому** тексту — до первой точки, за которой пробел или конец абзаца (`\.(?:\s|$)`), точка снимается; точки без пробела после (`1.2`, `a.b`) не режут; нет такой точки — весь абзац; (3) снятие markdown: `**x**` → `x`, `` `x` `` → `x`, `[t](u)` → `t`; (4) усечение по длине уже **без** разметки. Точка внутри обратных кавычек режет по тем же правилам, что и вне их (шаг 2 раньше шага 3). Причина порядка: от него зависят 8 из 57 фраз README пина (замер ревью), `INDEX.md` их фиксирует. **docstring:** абзац — первый абзац `ast.get_docstring` (чистка отступов штатная); (тот же порядок операций) длиннее 120 знаков → первые 119 и `…`; пустой/отсутствующий docstring → `нет описания`. **README (`card`, `index`):** файл — первый элемент `docs:` строки модуля, оканчивающийся на `README.md`; абзац — первый после пропуска строк вне блоков из `` ``` `` (маркеры блока — строки, начинающиеся с `` ``` ``), пустых и начинающихся (после `strip`) с `#`, `---`, `|`, `>`, `<`, `!`, `-`, `*`, `[`; абзац кончается на пустой строке, строке-пропуске или маркере блока; длиннее 160 знаков → первые 159 и `…`; нет элемента, файла или абзаца → `нет README в docs: modules.yaml`. Это замена п. 4 DESIGN 1.6 (там «первая строка»): правило пропуска строк то же, меняются склейка абзаца, обрезка по точке и снятие разметки. Причина: решение лида («первая ФРАЗА, не первая строка»; сейчас `card` обрывает «…создаёт **один по дефолту**»); склейка абзаца — 15 из 57 README переносят фразу на следующую строку (замер).
5. **`Pre:`/`Post:`.** Строка docstring (после `strip`), начинающаяся с `Pre:` / `Post:`. Текст — остаток строки после маркера, а если он пуст — первая следующая непустая строка (если это маркер `Pre:`/`Post:` — текст пуст); у текста снимаются ведущие `- `/`* ` и markdown (п. 4), длиннее 100 знаков → 99 и `…`. Третья строка метода `    Pre: {текст} / Post: {текст}` печатается, если найден хоть один маркер с непустым текстом; найден один — без ` / ` и второго куска. Нет маркеров — строки нет. Причина: решение лида; в docstring проекта маркер почти всегда за строкой-заголовком со списком (10 методов из 567), одна строка с первым пунктом — компромисс «справочник, не копия».
6. **Тесты интерфейса.** Связанные файлы — пути узлов `test` с ребром `tests` на `module:{id}` (любой `via`). Слово интерфейса — `\b{имя}\b` в тексте файла (`decode("utf-8", "replace")`) — то же правило, что у `INTERFACE_WITHOUT_TEST` (`adapters/code.py`). `{t}` — число узлов `test` в файлах, где слово найдено; пример — наименьший по строке путь среди таких файлов; `t = 0` — `тестов 0` без примера. Все имена модуля ищутся одним регулярным выражением на файл (скорость, замер выше). Причина: связи интерфейс–тест в реестре нет (О3), правило совпадает с находкой — «тестов 0» ⇔ `INTERFACE_WITHOUT_TEST` (на пине 95 из 95).
7. **Формат `index`.**
   ```
   # Индекс проекта — собран командой `python -m scripts.atlas index --write`, руками не править
   {id} — {назначение}
     {Имя} ({n}), {Имя} ({n}), Имя, … ещё {k}
   ```
   Первая строка — шапка (дословно). Затем в порядке строк `modules.yaml` ревизии (не пересортировывать) — строка на модуль; назначение — п. 4. Вторая строка (два пробела) — только если у модуля есть узлы `interface`: до 5 главных интерфейсов через `, `, порядок — по убыванию числа публичных методов класса, затем по имени (ключ `(-n, имя)`); у класса печатается `Имя (n)` (в том числе `(0)`), у не-класса (реэкспорт, функция, присваивание — n неизвестно) — просто `Имя`, считается как 0; если интерфейсов больше 5 — в конце `, … ещё {k}`. Методы считаются как в п. 2 (публичные `def`/`async def` тела класса, свойства включаются). Нет модуля с README — `{id} — нет README в docs: modules.yaml`. Строк = 1 + число модулей + число модулей с интерфейсами (на пине 133, потолок 200 — замер, механизма усечения нет). Причина формата — решение лида; порядок файла — единственный стабильный порядок без сортировки по слоям.
8. **`index --write` и `docs/atlas/INDEX.md`.** `index --write` пишет в `docs/atlas/INDEX.md` от корня git-репозитория (не от cwd; каталоги создаются) байты `"\n".join(строки) + "\n"` в UTF-8, переводов строк `\r\n` нет; в stdout — одна строка `atlas index: docs/atlas/INDEX.md, {n} строк`, код 0; без `--write` stdout — строки индекса (`print("\n".join(lines))`). Файл вывод не зависит от `--main-ref`, от времени и от SHA ревизии (в выводе их нет). Тест свежести (RED 9): регенерирует индекс для HEAD checkout на свежей базе и сравнивает `splitlines()` с файлом `docs/atlas/INDEX.md` **ревизии HEAD** (`git show HEAD:…`) — списки равны. Сбой записи `index --write` (например, каталог на месте файла) уходит в прежний `atlas: internal error: …`, код 2 — принято, RED нет. Файл создаёт `developer` последним коммитом (`Layer: docs`). CI не подключается (1.7). Причина: решение лида; независимость от SHA — иначе файл устаревал бы с каждым коммитом.
9. **CLI.** `ref <module> [--ref R] [--main-ref M]`, `index [--ref R] [--main-ref M] [--write]`; `--main-ref` принимается до и после подкоманды (как у `build`). Формы: `ref`/`index` не сочетаются с `--json` (`--json ref m` → код 2, как сегодня «нужна ровно одна форма»); `--write` только у `index`. Печать — `print("\n".join(lines))`, код 0. Ошибки — `AtlasError` → stderr одна строка, код 2, **без значений из ввода**: неизвестный модуль — `atlas: module not found` (текст `card`). Других новых текстов `AtlasError` нет; исключения — прежние тексты ядра (`atlas: ref not found: <ref>`, `atlas: git … failed: …`). Строка текста формы `atlas: нужна ровно одна форма: …` в `__main__.py` дополняется именами `ref`, `index` (тесты проверяют только непустой stderr — `test_core_cli.py`). Причина: тот же контракт CLI, что у `card`/`pack`/`log`.
10. **Детерминизм.** Одни и те же `ref`, `main-ref`, дерево git дают один и тот же вывод побайтно: все сортировки заданы (имя интерфейса, путь теста, `(-n, имя)`); итерация по множеству без сортировки в выводе запрещена; времени и SHA в выводе нет. Неизвестные виды узлов и рёбер реестра пропускаются, не падают (ADR-ATL-001 §5). Причина: побайтная стабильность нужна `INDEX.md` (сравнение с регенерацией) и воспроизводимости брифов; урок 1.6 — порядок множества зависит от `PYTHONHASHSEED`.
11. **Скорость и границы.** Тёплые `ref` и `index` ≤ 1 с (ожидание 0,65 и 0,4 с — замер выше); холодная сборка не входит (О6). Файлы: `scripts/atlas/reference.py` (новый), `scripts/atlas/views.py`, `scripts/atlas/__main__.py`, `docs/atlas/INDEX.md` (новый). Бюджеты — О7. Подпроцессы — через `git`/`run_git`/`git_z`/`Tree.read`/`_read`; вывод git — байты. Причина: ядро и адаптеры не меняются (схема SQLite — решение лида), бюджет и скорость — О6, О7; параллельная 1.7 может править `__main__.py` (О8).
