## Решения лида (DESIGN)

Общее. Новые файлы — `scripts/atlas/codemap.py` (ревизия на диск, griffe, «кто использует») и `scripts/atlas/rules.py` (реализации интерфейсов, правила П1–П4: адаптер `RulesAdapter` и чистые функции для видов); правки — `reference.py`, `views.py`, `__main__.py`, `build.py` (один элемент в `ADAPTERS`). Ядро (`store.py`, `check.py`, `schema.py`, `tree.py`), прочие адаптеры (включая `adapters/code.py`: `INTERFACE_WITHOUT_TEST` и `_BASE` не меняются), `modules.py`, `index` и `docs/atlas/INDEX.md` — **не меняются** (`index --check` остаётся 0). Каждый новый `.py`: docstring с `Purpose:`, `Public API:`, `Stability: lite` и `__all__`. Без `LIKE`, итерации по `set` в вывод, `text=True` у subprocess (байты, `decode("utf-8","replace")`). Все сортировки полные. Ошибки: текст без значения ввода.

1. **Ревизия на диск.** `codemap.checkout(root, sha)` — `Tree(root, sha).materialize(*корни)` из `tree.py` (там же `-c core.autocrlf=false`, `git archive`, `tarfile.extractall(filter="data")`; `tree.py` не меняется), один раз на вызов вида; возвращает временный каталог. **Корни выгрузки** — верхние каталоги элементов `paths` всех строк `modules.yaml` ревизии, существующие в её дереве (в реальном репозитории `multiprocess_framework`, `Services`, `Plugins`, `multiprocess_prototype`, …; в фикстурах `m`, `b`, `u` в корне: `git archive` по несуществующему пути падает с кодом 128, поэтому только существующие). Замер выгрузки четырёх деревьев 0,23 с. Причина: griffe и grimp читают файлы с диска, а `--ref` — ревизия, не рабочее дерево; поэтому и при `--ref HEAD` всегда выгрузка (одно поведение). **grimp:** пакеты ищутся через `sys.path` — каталог выгрузки вставляется первым, `importlib.invalidate_caches()`, `cache_dir=None` (иначе `.grimp_cache` в cwd); каждый путь в результатах обязан лежать в каталоге выгрузки (иначе `--ref` молча читает рабочее дерево — внутренняя ошибка 2); Rust-предупреждение `skipping module with too many dots` подавляется на время `build_graph` (fd 2), в stderr вида его быть не должно.
2. **griffe — только классы интерфейсов и «Кода модуля».** `GriffeLoader(search_paths=[<выгрузка>/<родитель пакета модуля>], allow_inspection=False)`; пакет грузится по **имени каталога**, не по точечному пути (замер 3,2–4,2 с против 0,13 с). Правило баз общее: абсолютное имя базы `a.b.pkg.rest` разрешается так — найти строку `modules.yaml`, чей путь (`/`→`.`) является префиксом имени, загрузить её пакет из своего каталога поиска (по разу на пакет), взять `[rest]`; не нашлось — база не разрешена (в списке баз печатается, членов не даёт). Любое обращение к `is_module`/`final_target` у алиаса — под `is_alias`/`try` (замер: `AliasResolutionError`). Griffe парсит и `tests/` (на `process_module` 0,9–1,7 с): griffe получает копию каталога без `tests/` (или читает только нужные файлы по `Tree.files()` — выбор исполнителя, критерий — бюджет п. 13). Пакет не разбирается или база не разрешена → строка `  вид: не определён`, вид не падает и не молчит.
3. **Формат `ref <module>`.** Старые строки (шапка, заголовок интерфейса, методы с фразой и `Pre/Post`) — как в 1.6b, с изменениями ниже. После заголовка каждого интерфейса-**класса**:
   - строка вида (отступ 2): `  вид: ABC; базы: IBaseManager, ABC; абстрактных 16 (своих 7)` или `  вид: Protocol, runtime_checkable; базы: Protocol; абстрактных 1 (своих 1)`; вид: `Protocol` (+`, runtime_checkable` при декораторе), `ABC` (база `ABC`/`ABCMeta` или есть `abstractmethod`), иначе `класс` (`  вид: класс; базы: —; абстрактных 0 (своих 0)` — класс без баз и без абстрактных членов печатает те же поля). Базы — простые имена в порядке объявления (последний компонент точечного имени, без подписки); нет баз — `—`. «Абстрактных»: у ABC — публичные методы/свойства с меткой `abstractmethod`, у Protocol — все публичные члены и значимые dunder (п. 4) тела; считаются уникальные имена по своим и по разрешимым базам; «своих» — объявленные в теле класса;
   - члены (как раньше, но п. 4);
   - если унаследованных абстрактных > 0 — по строке на базу, давшую хотя бы одно имя, в порядке баз: `  унаследованные абстрактные от IBaseManager (9): attach_adapter, detach_adapter, …` (имена по возрастанию);
   - реализации: `  реализации (0): нет` либо `  реализации ({n}):` и строки `    {Имя} — явно|структурно|структурно (Qt) — {путь}:{строка}` по возрастанию `(Имя, путь)`, не более 8, затем `    … ещё {k}`.
   Заголовок интерфейса, не являющегося классом (функция, реэкспорт), строк вида/реализаций не получает. Модуль без интерфейсов: шапка `Справочник модуля {m} — интерфейсов 0` (вместо прежнего раннего выхода «интерфейсов нет»), затем «Код модуля» и «Кто использует». **`--symbol ИМЯ`:** первая строка `Справочник модуля {m} — символ {ИМЯ}`, затем только блок этого символа (интерфейс — как в полном выводе, вместе с видом и реализациями; символ кода — строка пути файла и блок п. 6, без заголовка раздела и счётчиков) и «Кто использует» только по нему.
4. **Значимые dunder:** `__init__`, `__call__`, `__enter__`, `__exit__`, `__aenter__`, `__aexit__`, `__iter__`, `__next__`, `__getitem__`, `__setitem__`, `__len__`, `__contains__` печатаются наравне с публичными методами (`self`/`cls` отбрасываются); прочие `_имена` — нет.
5. **Реализации (чистая функция `rules.implementations`, один код для адаптера и `ref`).** Причина «тот же модуль»: ADR-175 говорит о собственных реализациях, и чужие структурные совпадения — шум (замер до порога ≥ 2: 87 пар вместо 31). Кандидат — класс верхнего или вложенного уровня в нетестовом `.py` (путь не `…/tests/…`, не `test_*.py`, не `*_test.py`). **Явная:** среди предков класса (по именам баз через разрешение импортов файла, транзитивно по классам кандидатов) есть интерфейс. **Структурная:** кандидат **того же модуля Атласа**, не явная, у которого есть все абстрактные члены интерфейса (членами класса считаются `def`, свойства, присваивания в теле и `self.x =` в методах, плюс унаследованные от предков-кандидатов), число абстрактных членов ≥ 2. **Qt:** структурная, если среди предков класса (его баз и баз предков-кандидатов, как у явной) есть класс, импортированный из `PySide6`/`PyQt5`/`PyQt6` — пометка `структурно (Qt)` (метакласс Qt наследуется, ADR-175 п. П1). «Тот же модуль» — по строке `modules.yaml` (`paths`), а не по первому каталогу: число П1 отличается от замера 31/30 ожидаемо, разницу объясняет итог. Область явных — файлы модуля интерфейса плюс файлы-импортёры его модуля (grimp), в `build` — все нетестовые файлы `multiprocess_framework`. Интерфейс сам себе не реализация; класс интерфейса другого модуля (имя в его `__all__`) — тоже не реализация.
6. **Код модуля** (раздел после интерфейсов): `Код модуля (без tests/ и interfaces.py): файлов {F}, классов {C}, функций {N}`, затем по возрастанию пути файлы с публичными символами: строка пути, под ней класс `  {Имя}({базы}) — {фраза} — :{строка}` (без баз — `  {Имя} — …`) и функция `  {сигнатура} — {фраза} — :{строка}`, под классом методы на отступе 4 (`    {сигнатура}  :{строка}` и фраза на отступе 6 — как у интерфейсов, но с отступом на 2 больше), не более 12 методов на класс (`    … ещё {k}`), раздел не более 150 строк (`… ещё {k} строк, сузить: ref {module} --symbol ИМЯ`). Публичные символы: класс/функция верхнего уровня без `_`; в файле с `__all__` — только перечисленные (П3). Файлы, не входящие в модуль (`modules.yaml`, `paths`), не учитываются; вложенные `tests/` исключаются на любой глубине. `файлов {F}` — файлы хотя бы с одним публичным символом (литерал `config_module` — 10 из 16 нетестовых без `interfaces.py`: 6 из них `__init__.py` без собственных определений). В лимиты 150/120 входят строка заголовка раздела и строка «… ещё».
7. **«Кто использует»** (раздел в конце `ref`; чистая функция `codemap.usage`). Строка-ограничение дословно: `Кто использует (статика: импорты и вызовы по имени; getattr, реестры, patch по строке, методы объектов и каналы роутера не видны):`. Символы — имена интерфейсов и «Кода модуля» по возрастанию имени. Единое множество файлов для п. 7, 8 и `card` — потребители по этому пункту (рёбра `tests` реестра не используются). Для символа `S`, определённого в модуле `D`: цепочка реэкспорта — `D` и пакеты, чей `__init__.py` импортирует `S` из цепочки (до фиксированной точки); потребитель — любой `.py` четырёх деревьев (grimp сужает кандидатов, имена и строки — из AST файла), у которого `ImportFrom`, разрешённый (с относительными уровнями) в цепочку, содержит `S` (строка — `alias.lineno`, «импорт»), и каждый `Call`, чей вызываемый — локальное имя `S` (алиасы `as` учитываются; строка вызова, «вызов»). Файлы самого модуля — не «вне модуля»; тестовые файлы (по п. 5) — отдельная группа вне зависимости от модуля. Вывод символа: `{S} — вне модуля {n}, тестов {t}, файлов {f}`, где `n` — число строк «импорт»/«вызов» нетестовых файлов вне модуля, `f` — число различных таких файлов, `t` — число тестов (определение ниже) во всех тестовых файлах-потребителях (своего модуля и чужих); строки `  {путь}:{строка}  импорт|вызов` по `(путь, строка)`, не более 5 (`  … ещё {k}`); при тестовых потребителях — `  тесты:` и до 3 строк `    {путь}:{строка первого импорта (alias.lineno)}  импорт, тестов {k}` по пути (сверх трёх — `    … ещё {k}`; файл с импортом и 0 тестов печатается с `тестов 0`). Символ, у которого есть только тесты, печатается (`вне модуля 0, тестов t, файлов 0`); символ без каких-либо использований не печатается, итог — одна строка `без использований вне модуля: a, b, …` (не более 20 имён, затем `… ещё {k}`). Раздел не более 120 строк; при превышении последняя строка `… ещё {k} строк, сузить: ref {module} --symbol ИМЯ`. Тест — функция `test*` верхнего уровня или в классе `Test*`, у которой в теле встречается локальное имя `S` (`Name`, `Attribute.attr`, импорт-алиас); docstring и комментарии не считаются.
8. **Честный счёт тестов.** Число «тестов N» в заголовке интерфейса — по п. 7 (функции-тесты связанных с модулем файлов, использующие имя), «пример» — наименьший путь среди учтённых. 9. **Правила ADR-175 (адаптер `rules`, `_BASE = 1`, одна находка `warning` на нарушение, узел `module:<id>`).** Охват — слой строки `modules.yaml`: `framework` — находки и доля; `services`, `plugins` — только доля; остальные — «вне охвата». Нетестовые файлы модуля. Находки (`code`, `detail`, `source`): **`P1_IMPL_NOT_INHERITING`** — структурная (не Qt) реализация интерфейса того же модуля; detail `{Класс}>{Интерфейс}`; source `путь:строка` класса. **`P2_DOCSTRING`** — символ API без docstring либо со стилем `:param`/`:returns`/`:raises` или NumPy-подчёркиванием; detail `{Класс}.{метод}` / `{Имя}`; source `путь:строка`. **Набор символов П2 — один, чистой AST-функцией `rules.py` для адаптера и доли в `card`** (griffe для П2 не используется — иначе доля и находки разойдутся): классы и их публичные собственные методы (включая `@property`) корневого `interfaces.py`, затем классы (с публичными собственными методами) и функции, определённые в модуле и перечисленные в `__all__` корневого `__init__.py` (определение ищется по цепочке `from .x import` и в подпакетах; не найдено — символ пропускается); повтор по имени не считается дважды. **`P3_NO_ALL`** — `interfaces.py` или `__init__.py` любой глубины модуля (кроме `tests/`) с публичными именами, но без `__all__`, либо имя в `__all__`, которого нет в файле; detail — путь; source `путь:1`. Публичные имена: класс/функция верхнего уровня без `_` и алиасы импорта без `_` и без `*`; «верхний уровень» включает тела `try`/`if` верхнего уровня (иначе `tools/__init__.py:16–19` даст ложную находку). **`P4_DIRECT_WRITE`** — `open(…, "w"|"wb"|"x"…)`, `.write_text`, `.write_bytes` в функции, где нет вызова `.replace`/`.rename`/`.move`; detail `{путь}::{функция}` (`{Класс}.{метод}` для метода; для вложенной функции — внешняя верхняя; `<module>` для верхнего уровня), source `путь:строка записи`. Находка не содержит номера строки в `detail` (перенос кода не делает старое нарушение новым). Доля соответствия модуля (`card`): П1 — явных из явных + структурных; П2 — соответствующих из символов; П3 — файлов с `__all__` из `interfaces.py`/`__init__.py` с публичными именами; П4 — записей в функциях с атомарным вызовом из всех записей. Замер на `config_module` (оракул `reports/1.6c.baseline.d/rules_oracle.py.txt`): П1 1 из 2, **П2 46 из 48** (свойства включены; без docstring `ConfigManager.initialize`, `.shutdown`), П3 7 из 7 (6 вложенных `__init__.py` + `interfaces.py`), П4 0 из 0.
