# Task 2.4j — генерируемый индекс уроков по модулям (BY-MODULE)

**Level:** Middle (Sonnet) · **Assignee:** developer · **Refs:** вердикт CTO `plans/2026-10-11_memory-rules-delivery/reports/2026-10-11_cto-verdict.md` (C7), `tasks/2.4.md` строка 2.4j.
**Files:** `scripts/memory/search.py`, `scripts/memory/_lessons.py`, `scripts/validate.py`, `.gitattributes`, `docs/claude/memory/{BY-MODULE*.md,CRAFT*.md,MEMORY.md}`, `SKILL.md` ×2 (`.claude/skills/project-rules/`, `.claude/plugins/dev/skills/project-rules/`), `remember.md` ×2 (`.claude/commands/core/memory/`, `.claude/plugins/core/commands/memory/`), `scripts/memory/tests/`.
**Goal:** человек находит уроки по модулю и по механизму в маленьких сгенерированных файлах; свежесть держит `validate.py`; рукописный `CRAFT-by-module.md` удалён.

## Измерения (2026-10-11, 373 урока)

- 55 значений `module:` (54 урока с двумя и более), 30 `mechanism:`, уроков без обоих тегов — 0.
- Размер строки `- [stem](stem.md) — описание ≤ 80 симв.`: слой framework ≈ 42 КБ, tools ≈ 10 КБ, prototype ≈ 4,5 КБ, services ≈ 4 КБ, plugins ≈ 2 КБ; список по `mechanism:` только с именами ≈ 65 КБ.
- Вывод: лимит 32 КБ из вердикта CTO недостижим при «все уроки»; guard — 80 000 байт на файл (`MAX_FILE_BYTES`).

## Контракт

Код: `scripts/memory/search.py` (+ функции генерации там же или в новом `scripts/memory/by_module.py`); разбор уроков — только `_lessons.py`, второго парсера нет.

### CLI

- `search.py --by-module --write [--root DIR]` — пишет файлы индекса в `<root>/docs/claude/memory/`, stdout `wrote <N> files`, выход 0.
- `search.py --by-module --check [--root DIR]` — выход 0, если файлы на диске байт-в-байт равны сгенерированным и лишних `BY-MODULE*.md` нет; иначе выход 1 и по строке на файл: `stale: <имя>` / `missing: <имя>` / `extra: <имя>`.
- `--by-module` без `--write` и `--check`, либо `--write` вместе с `--check` — ошибка argparse, выход 2.
- Без `--by-module` поведение поиска не меняется (`--write`/`--check` без `--by-module` — выход 2).
- Корень по умолчанию в режиме `--by-module` — `_lessons.current_tree_root()` (как у `tags.py --check`), не main checkout; `--root` его переопределяет.
- Строки `--check` идут в stdout, по одной на файл, порядок по имени. `<N>` в `wrote <N> files` — число сгенерированных файлов.
- Любой генерируемый файл больше `MAX_FILE_BYTES = 80000` байт — в обоих режимах выход 2, строка в stderr `too big: <имя> <байт>`, ничего не пишется.

### Слой модуля

По значению `module:` v, `seg = v.split("/")[0]`: `services` → `services`; `plugins`, `plugins_shared` → `plugins`; `prototype` → `prototype`; `tools`, `scripts` → `tools`; всё остальное → `framework`. Урок без `module:` (и без frontmatter) — слой `other`.

### Файлы

- `BY-MODULE.md` — хаб: заголовок; строка «Сгенерировано: `python scripts/memory/search.py --by-module --write`; не править вручную»; таблица `| слой | файл | модулей | уроков |` (модулей — число разных значений `module:` слоя, у `other` — 0; уроков — число разных уроков слоя, урок с двумя `module:` одного слоя считается один раз) по слоям, в которых есть уроки (порядок: framework, services, plugins, prototype, tools, other); строка со ссылкой на `BY-MODULE-mechanism.md`.
- `BY-MODULE-<слой>.md` — по файлу на слой, где есть уроки. `##` на значение `module:` (отсортированы), заголовок `## <module> (<n>)`; под ним строки `- [<stem>](<имя файла>.md) — <описание>` по имени файла. Урок с двумя `module:` стоит под обоими. Слой `other`: единственный раздел `## (без module) (<n>)`.
- `BY-MODULE-mechanism.md` — `##` на значение `mechanism:` (отсортированы), заголовок `## <mechanism> (<n>)`, строки `- [<stem>](<имя файла>.md)` без описания; урок с несколькими `mechanism:` под каждым; уроки без `mechanism:` — раздел `## (без mechanism) (<n>)` в конце, если такие есть.
- Текст ссылки = имя файла без `.md`, дословно. Описание = `" ".join(description)` из frontmatter; длиннее 80 символов — первые 79 + `…`; пустое — строка без ` — `.
- Детерминизм: без дат и времени; переводы строк `\n`; UTF-8 без BOM; файл кончается одним `\n`.
- `--write` удаляет каждый `BY-MODULE*.md`, которого нет в наборе сгенерированных (после `--write` проверка `--check` всегда даёт 0).
- Переводы строк: в `.gitattributes` строка `docs/claude/memory/BY-MODULE*.md text eol=lf` (как у `docs/atlas/INDEX.md`): при `core.autocrlf=true` свежий checkout не должен давать `stale`.
- Какие уроки входят: ровно те, что даёт `_lessons.iter_lessons`; в него добавлено исключение для имён, начинающихся с `BY-MODULE` (как `CRAFT`) — сгенерированные файлы не считаются уроками ни в `search.py`, ни в `tags.py --check`.

### validate.py

Новая функция `check_memory_index()`, заголовок «9. Индекс уроков по модулям», вызов в `main()` после `check_memory_tags()`: `search.py --by-module --check --root BASE`; выход 0 → `[OK]`, иначе `[FAIL]` с хвостом stdout+stderr (≤ 20 строк) и запись в `errors`. Образец — `check_memory_tags`; при `validate.BASE` = tmp-копия печатает `[OK]`/`[FAIL]`, при `[FAIL]` в `errors` +1.

### Замена CRAFT-by-module

`docs/claude/memory/CRAFT-by-module.md` удалён (`git rm`); ссылки на него в `CRAFT.md`, `CRAFT-*.md`, `MEMORY.md` ведут на `BY-MODULE.md`; в обоих `SKILL.md` (строка с `CRAFT-{…,by-module}.md`) `by-module` из скобок убирается — индекс для человека, в карту агентов не входит; в обоих `remember.md` после записи урока — шаг `python scripts/memory/search.py --by-module --write` (иначе каждый `docs(memory):` красит `validate`); исторические записи (`docs/handoffs`, `docs/reviews`, `workspace/dev`, `plans`) не трогать. Сгенерированные файлы закоммичены.

## Acceptance criteria

- [ ] Три режима CLI и коды выхода — как выше.
- [ ] `--write`, затем `--check` на тех же данных → 0; правка одного байта любого `BY-MODULE*.md` → 1 и `stale: <имя>`; удаление файла → `missing:`; чужой `BY-MODULE-x.md` → `extra:`; правка `description:` существующего урока → `stale: BY-MODULE-<слой>.md`; правка тела урока → 0; первый урок нового слоя → `missing:`; `--check` и `--write` без записи вне `--root`.
- [ ] Два запуска `--write` дают байт-в-байт одно и то же.
- [ ] Урок с двумя `module:` виден в обоих разделах; с двумя `mechanism:` — в обоих разделах mechanism-файла.
- [ ] Слой по таблице: `plugins_shared` → plugins, `scripts/atlas` → tools, `frontend_module/widgets` и `process_module/generic` → framework, `framework_meta` → framework.
- [ ] Описание 80/81 символов: граница усечения; пустое описание.
- [ ] Сгенерированные файлы не попадают в `search.py --list` и в `tags.py --check`.
- [ ] Реальные данные: копия `docs/claude/memory` в tmp, `--write --root <tmp>` — каждый файл ≤ 80 000 байт; множество stem в файлах слоёв = множество stem из `search.py --list`; число строк-уроков в файлах слоёв = Σ по урокам max(1, число значений `module:`).
- [ ] Без `--root` в worktree `--write` пишет в дерево worktree, а не в main checkout.
- [ ] `check_memory_index()`: `[FAIL]` и +1 в `errors` на устаревшем индексе, `[OK]` на свежем.
- [ ] `.gitattributes` содержит правило eol=lf для `BY-MODULE*.md`.
- [ ] Оба `remember.md` (источник и зеркало, `diff -q` чист) содержат шаг `search.py --by-module --write` после записи урока; в обоих `SKILL.md` нет `by-module` в строке про CRAFT-файлы.
- [ ] `CRAFT-by-module.md` нет; ссылок на него в `docs/claude/memory/` нет.
