# Task 2.4j — генерируемый индекс уроков по модулям (BY-MODULE)

**Level:** Middle (Sonnet) · **Assignee:** developer · **Refs:** вердикт CTO `plans/2026-10-11_memory-rules-delivery/reports/2026-10-11_cto-verdict.md` (C7), `tasks/2.4.md` строка 2.4j.
**Goal:** человек находит уроки по модулю и по механизму в маленьких сгенерированных файлах; свежесть держит `validate.py`; рукописный `CRAFT-by-module.md` удалён.

## Измерения (2026-10-11, 373 урока)

- 55 значений `module:` (54 урока с двумя и более), 30 `mechanism:`, уроков без обоих тегов — 0.
- Размер строки `- [stem](stem.md) — описание ≤ 80 симв.`: слой framework ≈ 42 КБ, tools ≈ 10 КБ, prototype ≈ 4,5 КБ, services ≈ 4 КБ, plugins ≈ 2 КБ; список по `mechanism:` только с именами ≈ 65 КБ.
- Вывод: лимит 32 КБ из вердикта CTO недостижим при «все уроки»; guard — 80 000 байт на файл (`MAX_FILE_BYTES`).

## Контракт

Код: `scripts/memory/search.py` (+ функции генерации там же или в новом `scripts/memory/by_module.py`); разбор уроков — только `_lessons.py`, второго парсера нет.

### CLI

- `search.py --by-module --write [--root DIR]` — пишет файлы индекса в `<root>/docs/claude/memory/`, stdout `wrote <N> files`, выход 0.
- `search.py --by-module --check [--root DIR]` — выход 0, если файлы на диске байт-в-байт равны сгенерированным и лишних `BY-MODULE*.md` нет; иначе выход 1 и по строке на файл: `stale: <имя>` / `missing: <имя>` / `extra: <имя>`.
- `--by-module` без `--write` и `--check`, либо `--write` вместе с `--check` — ошибка argparse, выход 2.
- Без `--by-module` поведение поиска не меняется (`--write`/`--check` без `--by-module` — выход 2).
- Любой генерируемый файл больше `MAX_FILE_BYTES = 80000` байт — выход 2, строка в stderr `too big: <имя> <байт>`, ничего не пишется.

### Слой модуля

По значению `module:` v, `seg = v.split("/")[0]`: `services` → `services`; `plugins`, `plugins_shared` → `plugins`; `prototype` → `prototype`; `tools`, `scripts` → `tools`; всё остальное → `framework`. Урок без `module:` (и без frontmatter) — слой `other`.

### Файлы

- `BY-MODULE.md` — хаб: заголовок; строка «Сгенерировано: `python scripts/memory/search.py --by-module --write`; не править вручную»; таблица `| слой | файл | модулей | уроков |` по слоям, в которых есть уроки (порядок: framework, services, plugins, prototype, tools, other); строка со ссылкой на `BY-MODULE-mechanism.md`.
- `BY-MODULE-<слой>.md` — по файлу на слой, где есть уроки. `##` на значение `module:` (отсортированы), заголовок `## <module> (<n>)`; под ним строки `- [<stem>](<имя файла>.md) — <описание>` по имени файла. Урок с двумя `module:` стоит под обоими. Слой `other`: единственный раздел `## (без module)`.
- `BY-MODULE-mechanism.md` — `##` на значение `mechanism:` (отсортированы), заголовок `## <mechanism> (<n>)`, строки `- [<stem>](<имя файла>.md)` без описания; урок с несколькими `mechanism:` под каждым; уроки без `mechanism:` — раздел `## (без mechanism)` в конце, если такие есть.
- Текст ссылки = имя файла без `.md`, дословно. Описание = `" ".join(description)` из frontmatter; длиннее 80 символов — первые 79 + `…`; пустое — строка без ` — `.
- Детерминизм: без дат и времени; переводы строк `\n`; UTF-8 без BOM; файл кончается одним `\n`.
- `--write` удаляет `BY-MODULE-<слой>.md` слоёв, где уроков больше нет.
- Какие уроки входят: ровно те, что даёт `_lessons.iter_lessons`; в него добавлено исключение для имён, начинающихся с `BY-MODULE` (как `CRAFT`) — сгенерированные файлы не считаются уроками ни в `search.py`, ни в `tags.py --check`.

### validate.py

Новая проверка «9. Индекс уроков по модулям»: `search.py --by-module --check --root BASE`; выход 0 → `[OK]`, иначе `[FAIL]` с хвостом stdout+stderr (≤ 20 строк) и запись в `errors`. Образец — `check_memory_tags`.

### Замена CRAFT-by-module

`docs/claude/memory/CRAFT-by-module.md` удалён (`git rm`); ссылки на него в `CRAFT.md`, `CRAFT-*.md`, `MEMORY.md` ведут на `BY-MODULE.md`; исторические записи (`docs/handoffs`, `docs/reviews`, `workspace/dev`, `plans`) не трогать. Сгенерированные файлы закоммичены.

## Acceptance criteria

- [ ] Три режима CLI и коды выхода — как выше.
- [ ] `--write`, затем `--check` на тех же данных → 0; правка одного байта любого `BY-MODULE*.md` → 1 и `stale: <имя>`; удаление файла → `missing:`; чужой `BY-MODULE-x.md` → `extra:`; добавление или правка урока → `stale`.
- [ ] Два запуска `--write` дают байт-в-байт одно и то же.
- [ ] Урок с двумя `module:` виден в обоих разделах; с двумя `mechanism:` — в обоих разделах mechanism-файла.
- [ ] Слой по таблице (в том числе `plugins_shared`, `scripts/atlas`, `frontend_module/widgets` → framework).
- [ ] Описание 80/81 символов: граница усечения; пустое описание.
- [ ] Сгенерированные файлы не попадают в `search.py --list` и в `tags.py --check`.
- [ ] Реальные данные: `--write` на корне репозитория — каждый файл ≤ 80 000 байт, число строк-уроков в разделах слоёв ≥ числу уроков.
- [ ] `validate.py` падает на устаревшем индексе и зелёный на свежем.
- [ ] `CRAFT-by-module.md` нет; ссылок на него в `docs/claude/memory/` нет.
