  1. Контракт. `from scripts.atlas import review_form`: `review_form.parse(text: str) -> (review | None, list[str])`; у `review`
     поля `verdict` (`APPROVED` | `CHANGES REQUESTED`), `severities` — кортеж 4 чисел (blocker, major, minor, nit) из строки `Итог`,
     `classes` — кортеж 7 чисел (fact, dryrun, form, context, design, scope, process) из строки `Классы`, `findings` — кортеж пар
     (степень, класс) по пунктам `- [степень/класс]` файла в порядке строк. Нарушений нет — `(review, [])`; есть — `(None, [строки])`,
     и строка нарушения, привязанного к строке файла, содержит `строка N` (N с 1). Формат отчёта — ADR-ATL-004 §5
     (`scripts/atlas/DECISIONS.md`, раздел «5. Отчёт ревью») и шаблон `.claude/plugins/dev/templates/review-report.md`: читай оба.
  2. CLI. `from scripts.atlas.__main__ import main`; `main(["metrics", "<spec>", ...])` возвращает код, печатает таблицу в stdout
     (проверять через `capsys`). Репозиторий — git toplevel cwd (`monkeypatch.chdir`). Spec — `<slug>` (все задачи плана, у которых есть
     `tasks/<id>.md`, в натуральном порядке: `1.2` перед `1.10`; id — имя файла без `.md`, целиком похожее на номер задачи: `1.2.tester.md`,
     `1.2.result.md`, `1.2.injections.md`, `1.2.injections.json` — не задачи) или `<slug>#<id>`; `--base <spec>` повторяемый, значение одно
     (`--base a#1 --base b#1`); spec подряд, `--base` после них (`metrics c#1 --base a#1`); ни spec, ни `--base` → код 2; только `--base` → таблица. План — каталог
     `plans/<slug>/` или `plans/<YYYY-MM-DD>_<slug>/` с `plan.md`. Заголовок таблицы `| метрика | <колонки> |`; колонка — `<slug>#<id>`;
     при наличии `--base` колонки `--base` идут первыми с меткой `база <slug>#<id>`, остальные — `сейчас <slug>#<id>`. Пять строк
     с подписями ровно: `M1 доля фактов Атласа`, `M2 blocker+major р.1 по классам`, `M2 из них fact+dryrun+form`, `M3 раундов до APPROVED`,
     `M4 коммитов после DONE`; строки таблицы — `| <подпись> | <ячейка> | …`. После таблицы: при нарушениях — пустая строка и
     `нарушения формы (N):`, затем по строке `  <путь от корня>: <текст>`; одно и то же нарушение печатается один раз (один отчёт читают M2 и M3 — в блоке одна строка, `(1)`);
     всегда последняя строка `U1/U2: не считаются — журнала нет (Task 1.10b)`.
     Коды: 0 — всё посчитано; 1 — в какой-то ячейке `?`; 2 — нет плана, два плана с этим slug, неизвестная задача, нет spec, `--ref`.
  3. Ячейки. M1 — доля строк блока FACTS брифа `tasks/<id>.md` (между `<!-- atlas:facts <sha7> -->` и `<!-- /atlas:facts -->`), у которых
     команда (первый кусок в обратных кавычках после ` — `) начинается `python -m scripts.atlas `: `<p>% (<a>/<b>)`, p — половина вверх
     (1/8 → `13%`, 2/3 → `67%`, 0/2 → `0%`); строка блока — любая, что начинается `- ` (с отступом или без, и не по форме тоже);
     нет файла, нет блока или нет закрывающего маркера — `—`; брифы ролей (`<id>.tester.md`) не читаются.
     M2 — отчёт `reports/<id>.review-r1.md`, только степени blocker и major: `major dryrun 2, form 1, context 1, design 2`;
     `blocker design 1; major dryrun 2, form 1`; классы в порядке fact…process, нулевые пропущены; ни blocker, ни major — `0`; нет файла — `—`;
     файл с нарушениями — `?`. `M2 из них fact+dryrun+form` — число пунктов blocker+major этих трёх классов (минор и nit не в счёт), `—`/`?` как у M2.
     M3 — отчёты `reports/<id>.review-r<N>.md` (имя целиком: `1.1` не читает `1.10.review-r1.md`; `review-code-r<N>` не читается), N — число:
     наименьший N с `APPROVED` → `<N>`; ни одного → `нет (раундов <K>)`; отчётов нет → `—`; любой отчёт с нарушениями → `?`.
     M4 — строка `- Task <id>:` в `plan.md`, группа `[DONE …]`, в ней первый по позиции хеш двух видов: (а) в обратных
     кавычках — 7–40 символов `[0-9a-f]` любого состава (`88373724` из одних цифр годится); (б) голый токен — 7–40 символов `[0-9a-f]`, хотя бы одна
     цифра и одна буква, границы — не буква и не цифра («PR #1234567» и даты не хеши). Голый хеш в тестах — только полные 40 знаков (даты коммитов
     фикстура не закрепляет: короткий голый хеш из одних цифр случайно даст `— (DONE без хеша)`). Нет строки/группы → `—`; DONE без хеша → `— (DONE без хеша)`; хеш не коммит → `?` и нарушение с текстом `хеш DONE <h>`.
     Иначе `n` — число не-merge коммитов `<done>..HEAD` с трейлером `Task: <slug>#<id>` (строка трейлера целиком), `k` — из них не типа `docs`
     (тип — до `:` или `(`/`!` темы коммита): `<n> (не docs <k>) после <первые 7 знаков полного хеша DONE>`.
