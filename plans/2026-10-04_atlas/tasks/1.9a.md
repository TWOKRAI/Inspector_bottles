## DESIGN

1. Один парсер — новый `scripts/atlas/result_form.py` (stdlib, без импорта тяжёлых модулей Атласа):
   `REQUIRED = ("Сделано", "Осталось", "Не проверено", "Файлы", "SHA", "Инъекции", "Кому передано")`,
   `TAILS = ("Осталось", "Не проверено", "Для следующего брифа")`,
   `section(lines, title) -> tuple[str, list[str]] | None` — (маркер как в файле: `## T`, `**T:**` или `**T.**`; тело),
   `lint(text) -> list[str]`. `views.py` берёт тело из `section`; второго парсера нет, `lint` зовёт тот же `section`.
2. `section` принимает три формы: строка `## T` (после `rstrip`), абзац `**T.**` и абзац `**T:**` (строка после `strip`
   НАЧИНАЕТСЯ с маркера; маркер в середине строки — не раздел). Тело `## T` — до следующей строки `## `; тело абзаца —
   до пустой строки или строки на `**` (как сейчас). CRLF даёт тот же результат, что LF. Заголовок `## T` выигрывает
   у абзаца где бы ни стоял; среди абзацев — первый (ред. 3, ревью р.1 после кода: абзац `**Осталось:**` выше
   `## Осталось` прятал настоящий раздел и в `pack`, и в `lint`).
3. `pack` (хвосты): печатает разделы `TAILS` в этом порядке (`    <T>:` + строки тела с отступом 6, тело из одного «нет»
   опускается — как сейчас); строка `итог без разделов формы 0.7: <путь>` — только если ни один из `TAILS` не найден ни в
   одной форме (итог только с `## Для следующего брифа` — не «без разделов»).
4. `lint(text)` — по одной строке на каждый раздел `REQUIRED` с нарушением, в порядке `REQUIRED`, литералы:
   - нет ни в какой форме → `нет раздела «## <T>»`;
   - есть только абзацем → `раздел «<T>» абзацем «<маркер как в файле>», нужен «## <T>»`;
   - `## T` без непустых строк → `пустой раздел «## <T>»: пишут «нет»`;
   - `## Не проверено`, тело которого — одно «нет» (`нет` / `- нет`) → `«## Не проверено» не бывает «нет»`.
   Порядок разделов, дубли, ```-блоки — не проверяются (Out of scope).
5. CLI `atlas lint-result <file>`: печатает строки `lint` с префиксом двух пробелов и последнюю
   `lint-result: нарушений <N>`; exit 1 при N > 0, иначе 0. Нет файла / не читается → stderr `lint-result: нет файла <file>`,
   exit 2 (путь в сообщении — тот, что дал вызывающий: агенту нужно знать, какой из записанных файлов). Git и база не
   нужны: ветка — до определения корня репозитория (работает и вне git-репо). `--ref` с `lint-result` → exit 2 (как у
   `check`/`log`). Чтение — `utf-8-sig`. Строка «нужна ровно одна форма…» дополняется словом `lint-result`.
6. Находка `RESULT_FORM` (warning) — в `adapters/plans.py`, внутри `_load` по уже материализованному `plans/` (без
   `Tree.read` на каждый файл: 51 `git cat-file` — 2,6 с, р.1): для каждого файла `plans/**/tasks/*.result.md` с непустым
   `lint` → `Finding("RESULT_FORM", "warning", f"result:{slug}#{id}", detail, message, path)`; узел — по ADR-ATL-001
   (`result` = `<slug>#<id>`, slug — каталог плана над `tasks/` без префикса `YYYY-MM-DD_`, id — имя файла без
   `.result.md`); `detail` — имена нарушенных разделов через `,` без пробела в порядке `REQUIRED`
   (`Осталось,Файлы`); `message` — `Итог не по форме 0.7: ` + строки `lint` через `; `; `source` — путь от корня.
   Версия `PlansAdapter` = `2·2**48 + 12 hex sha256` от байт `plans_progress.py` И `result_form.py` (правка линта меняет
   ключ кэша сборки; `version >> 48 == 2`). `CommitsAdapter` находки `plans_for` не берёт (`commits.py:184`) — так и остаётся.
   Строка `RESULT_FORM` — в таблицу кодов `scripts/atlas/DECISIONS.md` (ADR-ATL-001 §3).
7. Хук `.claude/plugins/dev/hooks/lint-result.sh` — PostToolUse `Edit|Write`:
   - дешёвый `case` на `.result.md` до запуска Python;
   - путь — `tool_input.file_path` через `$(...)` (не `read < <(...)`: `\r` на Windows), обратные слэши → `/`; должен
     совпасть с `(^|/)plans/(.+/)?tasks/[^/]+\.result\.md$`;
   - корень — от пути самого хука (`$HOOK_DIR/../../../..`); интерпретатор — `python-bin.sh` в подоболочке, как
     `autofix-text.sh:17-19` (`exit 1` внутри не роняет хук), `$PY` без кавычек (`py -3`); `CLAUDE_PYTHON_BIN` уважается;
   - зовёт `python -m scripts.atlas lint-result <file>` с `cwd` = корень. Нарушение = exit 1 **и** последняя строка
     stdout `^lint-result: нарушений [1-9][0-9]*$`; иначе (сбой импорта, нет модуля — тоже exit 1) — exit 0 молча;
   - гонка с `autofix-text.sh`: при нарушении — пауза 0,3 с и второй прогон; сообщать, только если оба вывода равны;
   - сообщение — stderr: `lint-result: <file> не по форме 0.7 (.claude/plugins/dev/templates/task-result.md):` + вывод
     линта; exit 2 (Claude Code показывает stderr агенту). Любой сбой (нет Python, плохой JSON) — exit 0 (fail open).
   - Ручки в `_stack.md` нет (выключение — убрать строку из `settings.json`); подключение — ОТДЕЛЬНОЙ группой
     PostToolUse `Edit|Write` после существующих (позиция ≥ 2), timeout 10; `plugin.json` — нет (О4).
