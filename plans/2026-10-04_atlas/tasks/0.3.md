# Task 0.3 — `modules.yaml` v0: путь → модуль

**Level:** Middle+ (Sonnet). **Assignee:** tester (RED до кода) → developer.
**Goal:** у каждого исходника репозитория есть ровно один модуль; модуль знает слой, ярус и свои документы.
**Plan:** `plans/2026-10-04_atlas/plan.md`, Task 0.3. Потребители: 1.3a (адаптер modules), 1.3b (коммит → модуль), 1.6 (`atlas card`).
**Ред. 3** — по ревью стадии 0, два раунда (12 + 3 правки, reviewer 2026-10-04).

## DESIGN (решение лида)

1. Файл `modules.yaml` в корне репозитория. Формат:
   ```yaml
   version: 1
   other_allowed: [run.py, conftest.py, ".claude/", "docs/"]   # что законно остаётся без модуля
   modules:
     - id: process_module
       paths: ["multiprocess_framework/modules/process_module/"]
       layer: framework
       tier: core
       docs: ["multiprocess_framework/modules/process_module/README.md", "..."]
       parent: null
   ```
   - `paths` и `other_allowed`: элемент с `/` на конце — префикс каталога; без `/` — точный файл; пустая строка `""` запрещена. Один префикс стоит ровно в одной строке.
   - `layer` ∈ {framework, services, plugins, prototype, scripts, tools, docs, infra}. Это ось `modules.yaml`, с трейлером `Layer:` коммита не сверяется (в списке трейлера нет `tools`, sentrux зовёт прототип `application`).
   - `tier` ∈ {core, optional, frozen} — только у строки с `parent: null` и путём ровно `multiprocess_framework/modules/<m>/`; у остальных строк (в том числе подмодулей) `null`, ярус подмодуля выводится через `parent`.
   - `docs` — каждый из `README.md`, `STATUS.md`, `DECISIONS.md`, лежащий прямо в каталоге строки (каталог строки — элемент `paths` с `/` на конце; точные файлы каталога не задают), обязан быть в списке; других путей — только существующие файлы.
2. Резолвер `scripts/atlas/modules.py` (stdlib + PyYAML, без импорта кода проекта). Контракт:
   - `load_modules(path: str | Path = "modules.yaml") -> list[dict]`. Нет файла → `FileNotFoundError`. `version != 1`, нет обязательного ключа строки (`id`, `paths`, `layer`, `tier`, `docs`, `parent`) или пустая строка в `paths` → `ValueError`, в тексте ключ и индекс строки (без значения).
   - `resolve(rel_path: str, modules: list[dict]) -> str` — id строки с САМЫМ ДЛИННЫМ совпавшим элементом `paths` (точный файл — совпадение целиком, префикс — `startswith`); нет совпадения → `"other"`. Не бросает исключений. Разделитель `\` нормализуется к `/`. Результат не зависит от порядка строк в списке.
3. Имена id. Модуль framework — имя каталога (`process_module`). Остальные — литералами:
   - `services/<каталог>` (`services/sql`), `plugins/<каталог>` (`plugins/processing`), `prototype/<каталог>` (`prototype/frontend`);
   - семь корней: `tools/backend_ctl`, `prototype/apps`, `tools/tools`, `scripts`, `tools/utils`, `prototype/robot`, `docs/examples`;
   - служебные: `framework_meta`, `services_shared`, `plugins_shared`, `prototype_root`;
   - подмодуль — `<id родителя>/<путь от каталога родителя без завершающего />` (`process_module/generic`).
4. Состав:
   - каждый каталог `multiprocess_framework/modules/<m>/`, кроме `tests/`, — модуль, `tier` из таблицы §1 `multiprocess_framework/docs/MODULE_TIERS.md` (27 строк);
   - `framework_meta` (layer framework): `multiprocess_framework/*.py`, `multiprocess_framework/modules/*.py` (точными файлами), `multiprocess_framework/docs/`;
   - каждый `Services/<s>/` и `Plugins/<category>/` (кроме `tests/` и `_shared/`) — модуль слоя services / plugins; `Plugins/_shared/` и корневые `Plugins/*.py` — `plugins_shared`; корневые `Services/*.py` — `services_shared`;
   - каждый `multiprocess_prototype/<subpkg>/` (кроме `tests/`) — модуль слоя prototype; корневые файлы прототипа — `prototype_root`;
   - семь корней п.3: `backend_ctl/` → `tools/backend_ctl` (tools), `apps/` → `prototype/apps` (prototype), `tools/` → `tools/tools` (tools), `scripts/` → `scripts` (scripts), `Utils/` → `tools/utils` (tools), `robot/` → `prototype/robot` (prototype), `examples/` → `docs/examples` (docs);
   - каталог `tests/` модулем не бывает: `Services/tests/`, `Plugins/tests/`, `multiprocess_framework/modules/tests/` резолвятся по родителю или в `other` — тестовые файлы в покрытие не входят (п.6).
5. Подмодули (решение владельца 2026-10-04). Единицы — модули п.4, кроме четырёх служебных; каждый новый подмодуль тоже единица. Кандидат — непосредственный подкаталог единицы. Строка заводится, если в кандидате ≥ 15 нетестовых `.py`, а в единице ≥ 60; оба счёта — рекурсивно по всему поддереву. `parent` = ближайшая объемлющая строка. Исключений нет (`_examples` тоже считается). На `ce3920df2` правило даёт 14 строк: `frontend_module/{components, components/_examples, components/base, core, widgets, widgets/chrome, widgets/tabs}`, `process_module/generic`, `prototype/frontend/widgets{, /tabs, /tabs/pipeline, /tabs/services, /tabs/settings}`, `tools/backend_ctl/probes`. Оба названных владельцем каталога входят сами: `process_module/generic` и `prototype/frontend/widgets/tabs/pipeline` (владелец назвал его «frontend_module/widgets/pipeline»; в framework такого каталога нет).
6. «Нетестовый `.py`» = путь из `git ls-files '*.py'`, у которого ни один сегмент не равен `tests`, имя не начинается с `test_` и не равно `conftest.py`.

## REDS (tester пишет до кода; все красные на коммите этой редакции)

Общее для тестов 1–10: `len(modules) >= 70`, иначе тест красный (пустой yaml не проходит ничего).
1. `test_every_source_file_has_a_module` — каждый нетестовый `.py` резолвится не в `other`, кроме путей под `other_allowed`; `len(other_allowed) <= 10`; ни один элемент `other_allowed` не является корнем п.4 (`Services/`, `Plugins/`, `multiprocess_framework/`, `multiprocess_prototype/`, семь корней), не лежит внутри него и не содержит его.
2. `test_framework_tiers_match_module_tiers_md` — разбор таблицы §1 даёт ровно 27 строк; множество id строк с `parent: null` и путём ровно `multiprocess_framework/modules/<m>/` равно этому множеству; ярус совпадает построчно.
3. `test_no_dead_rows` — элемент с `/` — префикс хотя бы одного пути `git ls-files`; элемент без `/` равен пути из `git ls-files`.
4. `test_docs_exist_and_complete` — каждый путь из `docs` существует; каждый `README.md`/`STATUS.md`/`DECISIONS.md` прямо в каталоге строки (элемент `paths` с `/`) есть в её `docs`.
5. `test_ids_unique_and_parents_valid` — id уникальны; один элемент `paths` встречается ровно в одной строке; `parent` ссылается на существующий id; пути подмодуля лежат внутри путей родителя; каждый каталог-единица п.4 с ≥ 1 нетестовым `.py` — элемент `paths` ровно одной строки с `parent: null`; служебные строки держат из каталогов только `multiprocess_framework/docs/` и `Plugins/_shared/` (катч-олл `Services/` вместо 17 строк — красный).
6. `test_longest_prefix_wins` — на `modules` и на `list(reversed(modules))`: файл внутри `process_module/generic/` → `process_module/generic`; файл в корне `process_module/` → `process_module`; `README.md` корня репо → `other`.
7. `test_layer_and_tier_values` — layer из множества п.1; tier ∈ {core, optional, frozen} у строк п.1 «ровно `modules/<m>/`, parent null» и `null` у всех остальных.
8. `test_submodule_rule_holds` — тест сам вычисляет по `git ls-files` строки правила п.5 и требует строку для каждой; вычисленное множество содержит `process_module/generic` и `prototype/frontend/widgets/tabs/pipeline`; `parent` каждой строки равен литералу id ближайшей объемлющей строки.
9. `test_resolve_all_files_fast` — резолв всех путей `git ls-files` < 1 с (замер ревьюера: наивный резолвер 0.045 с).
10. `test_windows_separators` — `resolve("Services\\sql\\x.py") == "services/sql"` и `resolve("Services/sql/x.py") == "services/sql"`.
11. `test_load_errors` — нет файла → `FileNotFoundError`; `version: 2` → `ValueError`; строка без `layer` → `ValueError`, в тексте `layer` и индекс; `paths: [""]` → `ValueError`.
