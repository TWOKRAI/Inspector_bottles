- **Уроки 1.3a (обязательны):**
  - тесты правит только `tester`, никогда `developer`, даже по находке ревью; `developer` с красным тестом, который он

Решения:

1. **Узлы `commit`: `first-parent(<sha сборки>)` ∪ `<sha сборки> --not <вершина main-ref>` ∪ коммиты, названные хешем в
   строках DONE.** `id` — полный SHA, `path` и `status` — `null`, `time` — `%ct`. Причина: ADR §1 даёт первые два
   множества; третье нужно, потому что 154 из 266 хешей DONE (58 %) лежат вне first-parent, и без их узлов `done_by` ведёт
   в пустоту (в PR эти коммиты входят во второе множество, после слияния — выпадают). Узлы строятся **от sha сборки**, а не
   от вершины `main`: `check` строит `<ref>` старой ревизии (причина — решение 1 из 1.3a). Вершина main-ref — через
   `resolve`; не найден → `AtlasError("atlas: main ref not found")` (без значения, как `NOT_FOUND_MSG` в `check.py`).
   Неглубокий клон (`git rev-parse --is-shallow-repository` = `true`) →
   `AtlasError("atlas: shallow clone — commits need full history; run: git fetch --unshallow")`: на глубине 314 ложно
   «не найден» 155 хешей из 266. Все коммиты узлов обрабатываются одинаково (пп. 2–4).
2. **Трейлеры — regex по полному сообщению (`%B`), не `interpret-trailers`** (О2). Строки `^Refs:[ \t]*(\S.*?)[ \t]*$` и
   `^Task:…` с флагом многострочности; значение — один раз на коммит. `decode("utf-8", "replace")`. Рёбра:
   - `refs`: commit → `plan:<slug>`, `via` = `trailer:Refs`; только значения вида `plans/…​.md`; `slug` — первый сегмент
     после `plans/` (и после необязательного `_archive/`), без суффикса `.md`, без префикса `^\d{4}-\d{2}-\d{2}_`;
     одно ребро на пару (commit, plan); значения не под `plans/` (324 из 498) рёбер не дают;
   - `implements`: commit → `task:<значение>`, `via` = `trailer:Task`; значение — `<slug>#<id>` с непустыми частями
     (иначе пропуск); грамматику id адаптер не проверяет — это делает валидатор (0 нарушений из 21); несколько строк
     `Task:` — несколько рёбер, одинаковые — одно.
   - **`dst` может не существовать** (164 и 3 на эталоне) — ребро пишется всё равно: это материал для `REF_TO_MISSING`
     (О4), вне задачи.
3. **`touches`: commit → `module:<id>`, `via` = `path`; одно ребро на пару.** Пути коммита — дифф против первого родителя
   (`git log -m --first-parent --no-renames --name-only -z`): merge-коммит `main` даёт весь дифф влитой ветки, при
   переименовании учитываются оба пути (старый и новый модули), корневой коммит — все его файлы. Модуль —
   `resolve(path, modules_for(ctx.tree))` из `scripts/atlas/modules.py`; нет `modules.yaml` в дереве — все пути в `other`.
   **Путь вне модулей даёт ребро в `module:other` без узла `other`:** причина — число узлов `module` равно числу строк
   `modules.yaml` (приёмка 1.3a, 87), узел-«прочее» её ломает. Побочный эффект на запрос ядра `modules_without_contract_test` — О6. Новые строки `modules.yaml` не заводятся (решение 7 из
   1.3a закрыто числами): 189 из 370 коммитов за 30 дней трогают только `other` — это `docs/sessions`, `docs/claude`,
   `docs/handoffs`, `plans/*`, `.claude/*`, то есть процесс и документы, а не код модулей; их свяжет `covers` в 1.4, а
   карточке модуля (1.6) коммиты процесса не нужны. Пересмотр — когда потребитель назовёт, чем ему мешает `other`.
4. **`done_by` и находки — перенос из 1.3a.** Источник — задачи со статусом `done` из `plans_for` (п. 5); задачи с хешем в
   прочих статусах (21) игнорируются. Разрешение: **один** вызов `git cat-file --batch-check` по строкам `<хеш>^{commit}`
   на все разные хеши сборки (`^{commit}` снимает неоднозначность «коммит или blob/tree»: 10 пар коллизий на 7 знаках, одна
   с коммитом). Исход строки: `<полный SHA> commit …` — разрешён; `missing` или `ambiguous` — не разрешён (две ветки одним
   кодом: различимы текстом `message`, не `code`).
   - разрешён → узел `commit` (если ещё нет, п. 1) и ребро `done_by`: `task:<slug>#<id>` → `commit:<SHA>`, `via` =
     `plan-line`; **не предок** `<sha сборки>` (множество `git rev-list <sha>`, один вызов) → ещё и находка;
   - не разрешён → ребра и узла нет, находка;
   - `DONE_HASH_NOT_IN_MAIN`: `severity` `blocking`, `node` = `task:<slug>#<id>`, `detail` = хеш **как написан**,
     `source` = путь плана; `message` — по-русски, называет причину (не найден / неоднозначен / не предок);
   - `DONE_WITHOUT_COMMIT`: `done`, `ref` пустой, нет ребра `implements` на задачу (среди узлов `commit`); `info`,
     `detail` `""`, `source` — путь плана; на эталоне 310;
   - `COMMIT_WITHOUT_DONE`: есть ребро `implements` на существующий узел `task`, чей статус ≠ `done`; `info`, `detail`
     `""`, `source` = наименьший по порядку строк полный SHA среди таких коммитов; на эталоне 3. Ребро `implements` на
     несуществующую задачу находки не даёт (это `REF_TO_MISSING`).
   Уровни — как в ADR-ATL-002 §2: blocking только у `DONE_HASH_NOT_IN_MAIN`.
5. **Адаптеры `plans` и `commits` читают один разбор.** Публичная `plans_for(tree)` в `adapters/plans.py` (распаковка
   `plans/` + `plans_progress --json --root`) кэшируется `functools.lru_cache` по ключу (путь `PLANS_PROGRESS`, корень, ref
   дерева; ref — SHA, так зовёт `build`). Причина: второй запуск `plans_progress` — +0,55 с на сборку, `check` строит
   дважды; ядро (`schema.py`, `build.py`) под общий контекст не меняется. **Коллизия slug — находка, не exit 2** (вопрос а):
   сохраняется план по порядку (живой раньше архивного, затем по `path`), остальные отбрасываются целиком вместе с
   задачами, находка `PLAN_SLUG_COLLISION`: `blocking`, `node` = `plan:<slug>`, `detail` и `source` = путь отброшенного
   плана. Причина: `exit 2` ронял сборку и `check` для **всех** PR после слияния такого плана (принцип 5 плана: сбой
   одного не валит соседей); `plans_progress --check` на двух планах одного slug даёт exit 0 (замер: `x` и `2026-10-01_x`),
   на дубле id — exit 1 (`DUP_ID blocking`); находка `blocking` на новом диффе блокирует именно PR, который её внёс. **Дубль id задачи в плане остаётся `exit 2`**
   (`atlas: duplicate task id in one plan`): `plans_progress --check` блокирует его до атласа (exit 1, `DUP_ID`).
6. **`modules.yaml`: пустой, `null`, не строковый (int, date) или повторяющийся `id` → `AtlasError` (exit 2)** (вопрос б).
   Сейчас дубль и `null` в `INSERT` дают `IntegrityError` с traceback. Проверка — в `modules_for` (`adapters/modules.py`),
   не в `parse_modules`: ядро не растёт (606 > 600), `load_modules` и хуки коммита не меняются. Текст, как у
   `parse_modules`, с 0-based индексом и без значения: `modules.yaml: в строке <i> ключ 'id' пустой, не строка или
   повторяется` (`i` — индекс первой плохой строки). Заодно minor из итога 1.3a: `ValueError` самого YAML-конструктора
   (скаляр `id: 2026-13-45` → «month must be in 1..12») получает префикс — любой `ValueError`, текст которого не начинается
   с `modules.yaml:`, заменяется константой `_UNPARSEABLE` (`modules.yaml: файл не разобран как YAML в UTF-8`).
7. **`plans_progress`: таймаут и stderr** (вопрос в). `PLANS_TIMEOUT = 120` (с; запуск — 0,55 с, запас ×200) в
   `subprocess.run`; `TimeoutExpired` → `AtlasError("atlas: plans_progress --json timed out")`. На сбое (код ≠ 0 или не-JSON на
   stdout) stderr процесса **целиком, декодированный с `errors="replace"`, печатается в stderr atlas до строки ошибки**;
   при таймауте stderr не читается; тексты `AtlasError` не меняются (инвариант (iii): значения в текст ошибки
   не попадают, диагностика самого инструмента — отдельный поток). На успехе stderr (0 байт) не печатается.
8. **Ключ кэша включает содержимое `plans_progress.py`** (вопрос г): нужен. Причина: `check` строит `<ref>` старой
   ревизии и `HEAD` одним и тем же инструментом; закэшированный `<ref>` со старым разбором против нового `HEAD` даёт
   фантомные «новые» находки, а теперь на узлах `task` стоят blocking-находки; парсер менялся 16 раз за 30 дней.
   Без правки ядра: `PlansAdapter.version` и `CommitsAdapter.version` — свойства, возвращающие `int`: собственная
   константа адаптера (поднимается руками при смене его разбора) × 2⁴⁸ + первые 12 hex-знаков `sha256` байтов
   `PLANS_PROGRESS`; нет файла → вклад 0. `fingerprint()` берёт `f"{a.name}:{a.version}"` — менять его не нужно. У
   `ModulesAdapter` `version = 1`. Принятый предел 1.3a («смена парсера → поднять version руками») снят; в докстринге
   `adapters/plans.py` строка про него удаляется.
9. **Регистрация:** `ADAPTERS = (ModulesAdapter(), PlansAdapter(), CommitsAdapter())`; имена `modules`, `plans`,
   `commits`. Правки ядра — эта строка и `import` в `build.py` и фильтр узла модуля в `store.py` (О6): `wc -l scripts/atlas/*.py` ≤ 610.
   Весь новый код — `scripts/atlas/adapters/`.
10. **Ошибки — `AtlasError`, exit 2, без входных значений в тексте** (полный stderr = текст + `\n`):
    `atlas: main ref not found`; `atlas: shallow clone — commits need full history; run: git fetch --unshallow`;
    `atlas: plans_progress --json timed out`; прежние тексты 1.3a (`failed (exit <N>)`, `duplicate task id in one plan`,
    тексты `parse_modules`); новый текст п. 6. Текст «two plans share one slug» **удаляется** (п. 5).
