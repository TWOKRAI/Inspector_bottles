Решения:

1. **Находки считаются по пути и по значению, а не по `dst` ребра.** Причина: ADR-ATL-001 §3 определяет находку по
   существованию цели `Refs:` (пути), а ребро хранит лишь slug плана; путь `plans/<план>/tasks/9.md` у существующего
   плана даёт `dst` без висячести и всё равно ссылается на то, чего нет (623 из 667 «пропавших» пар — у планов, которые
   в сборке есть, но перенесены в архив). Ребро и находка строятся из одного разбора сообщения, `dst` не читается.
   Находка — одна на пару (коммит, `detail`): `code` ∈ {`REF_TO_MISSING`, `REF_MOVED`}, `node` = `commit:<полный SHA>`, `detail`
   = токен пути как найден (после `rstrip(".")`) или значение `Task:` как написано (`<slug>#<id>`), `source` = полный SHA
   коммита, `message` — по-русски по п. 6. Находки строятся для **всех** узлов `commit` сборки (first-parent, коммиты PR,
   цели DONE): 11 из 623 пар `REF_MOVED` лежат вне first-parent.
2. **Что проверяется.** `Refs:` — каждый токен `plans/[^\s,;)]+` значения (О7, п. 3), без проверки расширения: путь
   существует как `blob` или `tree` (причина: `Refs: plans/dirx/` называет существующую цель — каталог; расширение не
   проверяется, потому что цель — путь, а не обязательно `.md`: слаг плана выводится только из `.md`, находка — из любого
   пути); значения вне `plans/` не дают ни рёбер, ни находок (О1). `Task:` — значение с
   `#` и непустыми частями по обе стороны (то же условие, что у ребра `implements`); `nohash`, `#5`, `x#` пропускаются
   без находки. Одинаковые токены и значения в одном коммите — одна находка.
3. **О7: токены.** Значение строки `Refs:` разбирается `re.findall(r"plans/[^\s,;)]+")` (тот же шаблон, что
   `_REFS_TOKEN_RE` в `plans_progress.py:1683`) и к каждому токену применяется `.rstrip(".")` (как
   `plans_progress.py:1844`); по ребру `refs` (commit → `plan:<slug>`, `via` = `trailer:Refs`) на пару (коммит, slug),
   slug — правилом 1.3b (`plans/[_archive/]<сегмент>[/…].md`, без `.md`, без `^\d{4}-\d{2}-\d{2}_`). Причина: на пине 75
   рёбер `refs` с мусором в `dst` (`plan:otel-export.md, plans`) и 282 связи, которых парсер по значению не видел;
   `REF_TO_MISSING` на таких `dst` дал бы ложные находки. Рёбра значений вне `plans/` по-прежнему не пишутся.
4. **Существование пути — один вызов `git cat-file --batch-check`.** Строки stdin: `<sha сборки>:<токен>` для каждого
   разного токена (193) и `<sha коммита>:<токен>` для каждой пары (1882) — 2075 строк, 0,06–0,07 с. Строка с ответом
   `… missing` — пути нет; ответ `<oid> blob|tree <размер>` — есть. Решение: пути нет в сборке и нет в дереве коммита →
   `REF_TO_MISSING`; нет в сборке, есть в дереве коммита → `REF_MOVED`; есть в сборке → находки нет (какой бы ни был
   исход в дереве коммита). Причина: один вызов не зависит от числа коммитов (замер: `ls-tree` на коммит — 1,25–4,2 с против
   0,06 с); все пары в одном вызове — без второго шага «сначала сборка, потом коммит» (+0,04 с к двухшаговому, но без
   зависимости между шагами). Ответ сопоставляется со строкой по позиции (`zip`), как `_resolve_hashes`. Пути без деталей
   нормализации (`..`, `//`, `:`, `^{tree}`) git возвращает как `missing` (проверено, код 0) — отдельной обработки нет.
5. **`Task:`: план по slug и id задачи.** slug — часть до `#`, id — после. (а) slug нет среди планов сборки (узлы `plan`,
   живые и архивные, после отсева `PLAN_SLUG_COLLISION`) → проверка дерева коммита: `git ls-tree -z --name-only <sha> plans/
   plans/_archive/` (`-z`: имена не в кавычках); запись `<имя>` совпадает, если после `removesuffix(".md")` и снятия `^\d{4}-\d{2}-\d{2}_` равна
   slug: найдена → `REF_MOVED`, нет → `REF_TO_MISSING` (О3: `ls-tree` двух каталогов, 2 мс, только для коммитов с отсутствующим
   slug; на пине таких 0). (б) slug есть в сборке, а `<slug>#<id>` среди узлов `task` нет → `REF_TO_MISSING` **без**
   проверки дерева коммита (id ищется только в дереве сборки, тем же парсером `plans_progress`: узлы `task` строит адаптер
   `plans`, второго парсера нет). Причина (б): план-файл коммита мог содержать строку задачи, которую позже удалили, но
   «был ли id в коммите» потребовал бы разбора плана каждой ревизии — именно второй парсер; решение лида его исключает.
6. **Уровни, поля, тексты.** Адаптер выставляет `severity`: `REF_TO_MISSING` — `blocking`, `REF_MOVED` — `info`; гейт
   «новое в диффе / было» делает `check` (ADR-ATL-002 §2: `blocking` только у находки, которой нет на merge-base, на старом —
   `info`), ядро не меняется. Тексты `message` (дословно, `{…}` подставляется):
   - путь `Refs:`, нет нигде: `Refs: путь {токен} не найден ни в дереве сборки, ни в дереве коммита`;
   - путь `Refs:`, перенесён: `Refs: путь {токен} есть в дереве коммита, но не в дереве сборки (перенос или архив)`;
   - план `Task:`, нет нигде: `Task: план {slug} не найден ни в дереве сборки, ни в дереве коммита`;
   - план `Task:`, перенесён: `Task: план {slug} есть в дереве коммита, но не в дереве сборки (перенос или архив)`;
   - id `Task:`: `Task: в плане {slug} нет задачи {id}`.
7. **О8: две строки на хеш.** В том же вызове `cat-file` на каждый разный хеш DONE две строки: `<хеш>` и `<хеш>^{commit}`.
   Исход: строка `^{commit}` — `<40 hex> commit <размер>` → разрешён (даже если голая строка `ambiguous`: коммит и дерево с
   общим префиксом, как у `9ae6621`); иначе голая строка `ambiguous` → «неоднозначен»; иначе «не найден». Прежняя
   посылка (один запрос `<хеш>^{commit}` различает) неверна: git 2.43 отвечает `missing` и на несуществующий, и на
   неоднозначный (замер выше). Тексты причин в `message` `DONE_HASH_NOT_IN_MAIN` остаются прежними: `Хеш в строке DONE
   задачи {tid}: коммит {не найден | неоднозначен | не предок ревизии сборки}`; `detail` — хеш как написан. Тесты:
   RED 7 (оба кандидата — блобы), 8 (коммит и блоб, обязан разрешиться), 9 (тексты двух остальных причин, закрывает хвост
   «Не проверено» 1.3b).
8. **Версия адаптера:** `CommitsAdapter._BASE` 1 → 2 (разбор `Refs:` и набор находок изменились; правило из `adapters/plans.py`
   «поднимается руками при смене разбора адаптера»). Причина: отпечаток сборки включает `version`; без подъёма база
   `data/atlas.sqlite` на ревизии, собранной кодом 1.3b, отвечает старыми рёбрами `refs` и без находок. `PlansAdapter` не
   меняется (`_BASE` остаётся 1).
9. **Границы кода.** Весь код — `scripts/atlas/adapters/commits.py`; ядро (`build.py`, `store.py`, `check.py`, `schema.py`,
   `tree.py`, `__main__.py`, `modules.py`), `adapters/plans.py`, `adapters/modules.py` не трогаются. Бюджеты:
   `wc -l scripts/atlas/*.py` = 608 (≤ 610, прирост 0), `adapters/*.py` ≤ 390 (О6). Подпроцессы — через существующие
   `git`/`run_git`/`_stdout`; вывод — байты, `decode("utf-8", "replace")`, не `text=True`.
10. **Ошибки.** Новых текстов `AtlasError` нет: сбой `cat-file`/`ls-tree` идёт прежним `atlas: git <команда> failed: …` через
    `_stdout`; значения из коммитов (токены, slug) в тексты ошибок не попадают (инвариант (iii)); находка — не ошибка, exit 0.
