- **Правила 7–8 `CLOUD.md`:** слияние — только после проверки лида (лид сверяет итог и даёт тексты полей слияния,
  владелец сливает; тебе слияние не делать). Цена без потери качества: одна инъекция на каждое заявленное свойство
  плюс строки ожидаемых дыр; второй раунд ревью — только при `blocker`/`major`; работа вне задачи — нет, даже ради
  зелёного CI (чужой красный CI — строкой в итоге, а не правкой); трейлеры — каждый на своей строке; перед push
  `git log -1 --format='%(trailers:key=Layer,valueonly)'` → непусто.
- **Коммиты:** темы `test(atlas): 1.6 — …`, `feat(atlas): 1.6 — …`, `docs(plans): atlas 1.6 — …`. Трейлеры каждый на
  своей строке, одним блоком в конце, `Co-Authored-By` внутри блока, без пустой строки перед ним:
  `Why: <одна строка>` / `Layer: scripts` (бриф, прогноз, итог — `Layer: docs`) /
  `Refs: plans/2026-10-04_atlas/plan.md` / `Task: atlas#1.6`.
- **Ловушки окружения** (из 1.2, 1.3a, 1.3b, 1.5a): `pre_report_gate.py` (SubagentStop) требует в каждом новом `.py` строки
  `Purpose:`, `Public API:`, `Stability: lite` в докстринге модуля и `__all__` — и в тестах; выполнять, не обходить.
  CI не гоняет `scripts/atlas/tests` — доказательство только прогон сессии; числа — в итог. `validate-safe-command`
  блокирует весь вызов Bash по подстроке, даже внутри `echo`/heredoc, и `rm -rf` с абсолютным путём — текст с
  опасными подстроками писать файлом, каталоги в тестах и скриптах удалять через `shutil.rmtree`. Хук `lint-brief`
  пропускает не больше 6 путей в одном блоке FILES и не больше 10 строк-пунктов в REDS — блоки ниже в пределе;
  строка внутри блока, начинающаяся с трёх и более заглавных букв и двоеточия, считается началом нового блока —
  в текст REDS такие строки не добавлять. Тесты запускать `python -m pytest` из `.venv`. `/usr/bin/time` в облаке нет —
  время меряй `time` оболочки или `time.perf_counter()`. Тесты на пине (RED 7–9, RED 10) требуют полный клон.

Решения:

1. **Три вида, один новый файл.** `card <module>`, `pack <slug>#<id>`, `log <module>` — подкоманды `python -m scripts.atlas`;
   весь код видов — `scripts/atlas/views.py` (новый), проводка — `scripts/atlas/__main__.py`; `scripts/atlas/adapters/code.py`
   правится только п. 12; ядро (`build.py`, `store.py`, `check.py`, `schema.py`, `tree.py`, `modules.py`) и остальные адаптеры
   не трогаются. `card` и `pack` читают `data/atlas.sqlite` SQL-запросами по `build_id`, **не `--json`**; `log` реестра не
   читает и не строит (нужны `modules.yaml` ревизии `main-ref` и git). Причина: после 1.5a `--json` — 17,8 МБ и 1,50–1,96 с на
   тёплой базе при пределе вида 1 с; холодная сборка 4,4–4,8 с `log` не нужна. Соединение приходит из `main()`:
   `views` не вызывает `store.connect` (тесты подменяют `store.connect`). Ленивая сборка: `card` и `pack` зовут
   `build(con, root, ref, main_ref)` — ключ найден, адаптеры не зовутся (0,11–0,14 с), иначе холодная сборка. Данные из git, не
   лежащие в реестре (темы коммитов, файлы коммитов плана, README, итоги задач) вид читает сам: `git`/`Tree.read`, байты,
   `decode("utf-8", "replace")`, не `text=True`.
2. **Формат `card`** (строки в этом порядке, ничего лишнего; без склонений: «планов» всегда):
   ```
   Модуль {id} — {layer}, ярус {tier}
   Назначение: {текст}
   API ({n}): {имена}
   Открытые задачи ({p} планов, {t} задач):
     {slug} — {k}: {id}, {id}, …
     … ещё {r} планов
   Коммиты ({N} всего, последние {m}):
     {sha7} {YYYY-MM-DD} {тема}
   Находки ({f}):
     {severity} {code} {node} {detail или -}
     … ещё {r}
   ```
   `layer`, `tier` — из строки модуля в `modules.yaml` ревизии (`tier: null` → `—`). Нет открытых задач — одна строка
   `Открытые задачи: нет`. `API`: имена узлов `interface` модуля (id узла — `<модуль>:<Имя>`, префикс отрезается), по
   возрастанию, через `, `; больше 20 — первые 20 и `, … ещё {n-20}`; нет — `API (0): —`. Коммиты: узлы `commit` с ребром `touches`
   на модуль, по убыванию `time`, затем по возрастанию SHA, не больше 5; `{N}` — число всех таких коммитов, `{m}` — `min(5, N)`;
   дата — UTC из `time`; тема — первая строка сообщения (одним вызовом `git log --no-walk=unsorted --stdin --format=%s`),
   длиннее 90 знаков → первые 89 и `…`. Находки: находки сборки, у которых `node` равен `module:<id>` или начинается с
   `interface:<id>:` (**точное совпадение префикса, не `LIKE`**: `_` в id модуля — подстановочный знак; модули `a_b` и
   `axb` не должны смешиваться); порядок — `blocking`, `warning`, `info`, затем `code`, `node`, `detail`; не больше 10 строк,
   остальное `  … ещё {r}`. Строки доказанности нет. Причина: лимиты секций дают потолок 27 строк при плане ≤ 60 (замер: 18 у
   `router_module`, 28 — максимум по 87 модулям), строки доказанности — после K0 (урезанный путь, `amendments.md` п. 8).
3. **`card`: открытые задачи.** План связан с модулем, если есть коммит с ребром `touches` на модуль и (ребро `refs` на `plan:<slug>`
   **или** ребро `implements` на задачу плана — ребро `in_plan` от этой задачи). Открыта задача со статусом `pending`,
   `in_progress` или `blocked` (`deferred`, `superseded`, `done` — нет). Планы без открытых задач не выводятся и не считаются.
   Порядок планов — по убыванию числа **разных** связывающих коммитов (коммит с `refs` и `implements` на один план — один),
   затем `slug` по возрастанию; не больше 5 планов, остальное `  … ещё {r} планов`; в строке плана id задач в
   натуральном порядке (п. 10), не больше 6, остальное `, … ещё {k-6}`; `{k}` — все открытые задачи плана, `{p}` и `{t}` — по
   всем планам с открытыми задачами. Причина: связь на уровне плана — единственная, что даёт хоть что-то при нынешних данных
   (по прямой связи для `router_module` 0 задач, по плану 80 — О3); решение о шуме — лида.
4. **`card`: назначение.** README модуля — первый элемент `docs:` строки модуля, оканчивающийся на `README.md`, читается из
   дерева ревизии (`Tree.read`). Назначение — первая непустая строка README вне блоков из `` ``` `` (маркеры блока — строки,
   начинающиеся с `` ``` ``), не начинающаяся (после `strip`) с `#`, `---`, `|`, `>`, `<`, `!`, `-`, `*`, `[`; длиннее
   160 знаков → первые 159 и `…`. Нет элемента `README.md`, нет файла или нет такой строки → `нет README в docs: modules.yaml`.
   Причина: в `modules.yaml` описания модуля нет (О6); 57 из 87 модулей получают строку, остальным — честное «нет».
5. **Формат `pack` и модули задачи.** Вывод (строки в порядке):
   ```
   Задача {slug}#{id} — статус {status}, план {путь плана}
   Модули: {id}, {id} ({источник})
   Файлы-кандидаты в FILES ({n}):
     {путь} — {id}, {id}
   Хвосты прошлых задач плана ({k} задач):
     {slug}#{id} ({статус}):
       …
   ```
   `status` — статус узла `task` (`pending`, `done`, …), путь плана — `path` узла `plan`. Модули задачи `M` (id модулей; модуль
   `other` не считается): (а) `--module <id>` (повторяемый; id должен быть в `modules.yaml`) — ровно они, источник `--module`; иначе
   (б) модули путей коммитов самой задачи (п. 6), если их нет — источник `коммиты задачи`; иначе (в) модули **последней задачи плана
   с модулями** — задачи, у которой самый поздний (по `%ct`) коммит, затронувший путь модуля (при равенстве — большая по
   натуральному порядку id), источник `последняя задача плана с модулями — {id}`; иначе (г) `M` пусто, строка `Модули: — (у плана нет
   коммитов с модулями)`. Модули выводятся по возрастанию через `, `. Причина (в): у ещё не начатой задачи коммитов нет, а
   объединение модулей всего плана несёт модули давних задач (для плана `atlas`: 0.4 и 0.8 тронули 8 модулей, текущая работа — один,
   `scripts`); `--module` — рычаг лида, если вывод неверен.
6. **`pack`: кандидаты в FILES; коммиты — из git.** Коммиты плана: `git log <sha ревизии> --no-merges -E --grep '^Task: <slug>#'
   --format=%H%x00%ct%x00%B%x02` (потомки не нужны, только предки ревизии `--ref`); id задач коммита — значения его строк
   `Task: <slug>#<id>` (только этого плана; остальные игнорируются); коммит без таких строк после разбора не берётся. Файлы
   коммитов — одним вызовом `git log --no-walk=unsorted --stdin --no-renames --name-only -z` с `-m --first-parent`, как `_paths`
   адаптера `commits`. Кандидат — путь, который (1) лежит в модуле из `M` (по `modules.yaml` ревизии, правило самого
   длинного элемента: `scripts.atlas.modules.resolve`) и (2) **есть в дереве ревизии** (`Tree.files()`; удалённые файлы не
   кандидаты). Строка кандидата: `  {путь} — {id}, {id}`, где id — задачи плана, чьи коммиты тронули путь, в натуральном порядке;
   пути — по возрастанию. Лимита нет. Причина источника: рёбра `implements` реестра берут только first-parent и цели DONE —
   на пине 9 рёбер против 142 коммитов с `Task: atlas#…` (О1); без git приёмка «перечисляет FILES задачи 1.5a» не выполнима.
   Причина фильтров: модуль задачи — лидова граница работы (п. 5), путь без файла в дереве бесполезен кандидатом.
7. **`pack`: хвосты прошлых задач.** Задачи для хвостов — идентификаторы по **файлам** каталога `<каталог плана>/tasks/` в дереве
   ревизии: имя `<id>.md` или `<id>.result.md`, где `<id>` целиком совпадает с `TASK_ID_PATTERN` (флаг `re.ASCII`); файлы с
   другими именами (`readme.md`, `1.1.notes.md`, `notes.result.md`) пропускаются. Каталог плана — родитель `path` узла `plan`,
   если путь оканчивается на `/plan.md`; иначе (плоский план) вместо блока одна строка `Хвосты прошлых задач плана: у плана нет
   каталога tasks/`. Сама задача `pack` не входит. `{k}` в заголовке — число напечатанных блоков (задач с хоть одной частью). Фильтр модулей: задача входит, если множество модулей её коммитов (п. 6,
   без `other`) пусто **или** пересекается с `M`; `M` пусто (п. 5г) — входят все (причина: нельзя доказать непересечение —
   тихо терять хвост хуже лишней строки). Порядок блоков — натуральный по id. Заголовок блока:
   `  {slug}#{id} ({статус узла или —}):`; блок печатается, только если в нём есть хоть одна часть. Части, в порядке (указатель, `Осталось`, `Не проверено`, `Инъекции` — из `<id>.result.md`; `Открыто для лида` — из `<id>.md`):
   - **указатель:** `    итог без разделов формы 0.7: {путь файла}` — если `<id>.result.md` есть и ни раздел `Осталось`,
     ни раздел `Не проверено` не найден ни в одной из двух форм;
   - **`    Осталось:`** и **`    Не проверено:`** — раздел — строка ровно `## Осталось` / `## Не проверено` — до следующей строки на `## `, либо абзац
     `**Осталось.**` / `**Не проверено.**` (строка маркера без маркера + следующие непустые строки до пустой строки или строки,
     начинающейся с `**`, каждая после `strip`, через пробел — одна строка). Строки раздела — после `strip`, непустые, как в файле
     (с `- `), с отступом 6 пробелов; раздел, единственная непустая строка которого после снятия `- `/`* ` равна `нет`, пропускается;
   - **`    Инъекции, где предсказано ≠ наблюдалось ({n}):`** — строки таблицы, у которой заголовок: первая ячейка `инъекция`, вторая
     начинается с `предсказано`, третья — с `наблюдалось` (таблицы с другими заголовками игнорируются); строка берётся, если вторая
     и третья ячейки — целые числа (`^\d+$`) и **различаются**; текст `      {ячейка 1} — предсказано {p}, наблюдалось {o}`;
     таблицы с несколькими заголовками одного файла (1.3a) читаются все;
   - **`    Открыто для лида ({n}):`** — строки `| О<число> | вопрос | … |` раздела `## Открыто для лида…` файла `<id>.md`, только если
     статус задачи не `done` (узла нет — тоже показывается); текст `      О{n}: {вопрос}` (вторая ячейка после `strip`, как в
     файле). Строки с `NEEDS LEAD` вне этой таблицы не разбираются (упоминания в тексте брифа — инструкции, не пункты).
   Причина двух форм итога и указателя — О5; порядок и фильтры — п. 5; «не `done`» для брифов: пункты закрытой задачи решены при слиянии,
   а нерешённое остаётся в её `result.md` («Осталось»).
8. **`log <module> [-n N]`.** Модуль — строка `modules.yaml` ревизии `--main-ref`; записи — `git log --first-parent -n {N} <sha main-ref>
   -- {элементы paths} {исключения}` (`-n` по умолчанию 30, целое ≥ 1). Элемент `paths` с `/` на конце — каталог, без — точный файл (как
   в `modules.py`). Исключения: `:(exclude){элемент}` для каждого элемента другого модуля, который длиннее и лежит **внутри** каталога
   элемента этого модуля (правило «самый длинный побеждает», как у `touches`; вложенных модулей 14). `Task:` записи — собственные
   строки `Task: <slug>#<id>` сообщения **и**, если записи слияние (два родителя), строки `Task:` коммитов
   `git log <p1>..<p2> -- {те же пути и исключения}`. Группы: по значению `Task:`, запись попадает в каждую свою группу; записи без `Task:` —
   группа `(без Task)`. Порядок групп: по убыванию времени самой свежей записи группы, затем ключ в натуральном порядке (п. 10);
   `(без Task)` — последней. Порядок записей в группе — как у git. Вывод:
   ```
   Лог модуля {id} — first-parent {main-ref как задан}, записей {n}
   Task {slug}#{id} ({k}):
     {sha7} {YYYY-MM-DD} {тема}
   (без Task) ({k}):
     {sha7} {YYYY-MM-DD} {тема}
   ```
   `{n}` — число записей first-parent (≤ N); тема — первая строка, длиннее 90 → 89 знаков и `…`. Неизвестный модуль — п. 9. Реестр
   не строится (в `builds` строки нет). Причина боковой ветки слияния: собственный `Task:` у записей first-parent на пине — 0 из 80,
   слияния PR несут одно название PR (О4); причина `-- пути` в боковом поиске: иначе слияние несёт задачи всей ветки, а не тронувшие
   модуль. `--ref` `log` не знает (как `check`).
9. **CLI.** Подкоманды: `card <module> [--ref R] [--main-ref M]`, `pack <slug>#<id> [--ref R] [--main-ref M] [--module ID]…`,
   `log <module> [--main-ref M] [-n N]`; `--main-ref` принимается до и после подкоманды (как у `build`). Формы: `card`/`pack`/`log` не
   сочетаются с `--json` (`--json card m` → код 2, как сегодня «нужна ровно одна форма»); `log --ref …` → код 2, как `check --ref`.
   Печать — `print("\n".join(lines))` в stdout, код 0. Ошибки — `AtlasError` → stderr одна строка, код 2, **без значений из ввода**
   (инвариант (iii)): неизвестный модуль (`card`, `log`, `--module`) — `atlas: module not found`; `pack` с неизвестным планом или задачей без
   узла — `atlas: task not found`; аргумент не `<slug>#<id>` (нет `#`, пусто слева или справа, `<id>` не целиком по `TASK_ID_PATTERN`) —
   `atlas: task must be <slug>#<id>`; `-n` меньше 1 — `atlas: -n must be a positive integer`. Разбор `<slug>#<id>`: `partition("#")`
   по первому `#`, `<id>` проверяется `re.fullmatch(TASK_ID_PATTERN, id, re.ASCII)`, **шаблон — импорт**
   `from scripts.validate_commit.validate_commit import TASK_ID_PATTERN` (в `views.py` имя `TASK_ID_PATTERN` — тот же объект), копии
   строки нет; `<slug>` не проверяется грамматикой — существование плана проверяет реестр. Причина импорта: решение лида, согласовано

10. **Детерминизм и устойчивость.** Одни и те же `ref`, `main-ref`, дерево git дают один и тот же вывод побайтно: сортировки заданы
    (выше), времени сборки и текущего времени в выводе нет, даты — UTC. **Натуральный порядок id** — всюду, где «натуральный»:
