MEMORY LESSON feedback_set_sort_with_partial_key_depends_on_hash_seed.md:
```
---
name: feedback_set_sort_with_partial_key_depends_on_hash_seed
description: Сортировка множества по неполному ключу (natural sort, PYTHONHASHSEED) даёт разный вывод в разных процессах; два запуска подряд это не ловят / sorting a set by a partial key makes output depend on the hash seed
type: feedback
tags:
  role: [reviewer]
  module: [scripts]
  mechanism: [flaky-tests, probes]
---
`sorted(some_set, key=k)` is deterministic only when `k` is a total order. A "natural order" key that maps `1.2`, `1.02` and `01.2` to the same value leaves those items in set iteration order, and that order changes with PYTHONHASHSEED per process (atlas 1.6 `pack`: 7 distinct outputs over 8 seeds).
Why: two runs in one shell, or one pytest process, can still look byte-identical, so a "run twice and compare" check proves nothing here.
How to apply: when a view promises byte-for-byte determinism, run it in subprocesses under several PYTHONHASHSEED values with inputs that tie under the sort key, and make the key total by adding the raw string as the last element. A test of a tie rule proves something only if the expected item is not first in the source order (`max`/`sorted` keep the first of equal keys).
```
