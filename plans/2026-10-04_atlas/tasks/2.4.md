# Task 2.4 — контекст агентов по ролям: ядро + карта правил вместо «всё всем»

**Решение владельца 2026-10-04.** Главное — эффективность и качество исполнения агентов, экономия вторична. Агент получает ядро правил и ссылки на глубокие файлы; каждый берёт своё. MCP и навыки — по нужде роли. Каждое изменение проверяет Fable по тексту изменений («стало лучше, не хуже»), без контрольных прогонов.
**Основание.** `research/token_audit.md`: старт субагента 68–86k (n=441), до первой правки ещё +42…57k. Правила только для лида грузятся в каждого субагента (~14k); список навыков 12,7k; память роли + шаблон 9,6k.
**Возможности Claude Code** (сверено с https://code.claude.com/docs/en/sub-agents.md 2026-10-04): `omitClaudeMd: true` — субагент без CLAUDE.md (нужна v2.1.271+, сейчас 2.1.222, владелец обновит); `disallowedTools: mcp__<server>` — снимает сервер у роли; `skills:` — только предзагрузка, список не ограничивает; `disable-model-invocation: true` — убирает навык/команду из списка модели, слэш-команда остаётся; SessionStart `additionalContext` — только главная сессия; память роли — первые 200 строк / 25 КБ `MEMORY.md` + инструкции.

## Приёмка каждой подзадачи

- Таблица прослеживаемости: каждое правило «было где → стало где»; потерянных 0.
- Источник плагина и зеркало одинаковы (`diff -q`).
- Fable: вердикт по тексту изменения — лучше / не хуже / хуже, с пунктами; «хуже» = откат или правка до повторного вердикта.
- Замер после — по журналам обычной работы (парсер `research/baseline_scripts/m4.py` и скрипты аудита): старт роли и токены до первой правки, без специальных прогонов.
