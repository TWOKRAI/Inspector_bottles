## Контекст

Проект растёт на 2051 коммит за 60 дней (пик 204 в день), агенты работают параллельно. Знание о проекте разъехалось:
- 112 581 байт правил грузится в каждую сессию (оценка ~21k токенов: `.claude/CLAUDE.md` ~7.3k, `MEMORY.md` ~6.5k, корневой `CLAUDE.md` ~5.5k);
- 300 из 596 DONE-задач не связаны с коммитом;
- `git %(trailers)` видит `Refs:` в 0 из 200 коммитов, потому что `Co-Authored-By` отделён пустой строкой;
- у 18 из 57 модулей код новее документа больше чем на 30 дней;
- число модулей записано тремя разными значениями;
- памяти три копии, ADR три дома, парсеров планов два;
- матрицы инъекций (главное доказательство качества) лежат в 39 из 364 файлов `docs/reviews` и не индексируются.

Цель владельца — качество и надёжность агентной разработки: контроль агента через доказательства, которые код пережил,
а не через чтение кода. Документация — средство. Новизна системы — интеграция, не изобретение (готовой замены нет ни
одному компоненту, поиск 27 кандидатов — `research/CTO_VERDICT.md`, дополнение §2).

## Цели

- Один реестр (не в git), собираемый детерминированно из git, планов, модулей, документов, тестов и итогов задач.
  Два лица: `atlas card|pack|log` для агента, HTML для владельца.
- Цепь `commit → Task → plan → module → doc` выводится из трейлеров и путей, руками не набирается.
- Доказанность модуля видна числом: доля публичных имён с тестом, доля гарантий с инъекцией, мутационный балл из CI Linux.
- Гейты CI для нового кода: жёсткие с первого дня — `PRE_POST_MISSING` на изменённых интерфейсах, битая ссылка,
  `Refs`/`Task` на несуществующее, DONE-хеш не в `main`; `SURFACE_CHANGED_WITHOUT_TEST` — 2 недели предупреждение,
  перевод в блок решается в K1.1.
- Система сжимается: задачи 1.7, 2.5, 3.1 сдают ведомость удалений (что снято, файлов/строк).

## Принципы (из вердикта CTO)

1. Истина — файлы в git; реестр — производная, её не коммитит никто.
2. Что выводится — не пишется руками; что пишется руками — имеет один дом.
3. Свежесть — число содержательных коммитов в зоне документа (без массовых >30 файлов и `style`/format), не штамп и не дата.
4. На `main` пишет один — лид в точке слияния (`atlas sync --write`); CI проверяет, не пишет; облачные сессии — только PR.
5. Фаза принята, если удалила больше, чем добавила.
6. Старое помечается один раз: `legacy_before: <SHA слияния 1.7>`, база-храповик пишется один раз; засыпки нет.

## Out of scope

- Засыпка старого: 300 DONE без хеша, шапки архивных планов, старые коммиты (решение владельца 2026-10-04).
- Ветки на модуль (O2, O3: 72 % слияний задевают 2+ модулей, задача — медиана 5). Вид по области даёт `atlas log`.
- Рёбра документов в graphify пост-обработкой; `chunks.jsonl`/BM25; Backstage, Qdrant, Node/.NET-генераторы.
- Массовый тираж документов по 15–18 модулям; «Пульт владельца» (Фаза 6 дашборда) — до kill-проверки.
- Свободный хендофф каждого агента — вместо него `tasks/<id>.result.md`.
- Код валидатора коммитов и парсера планов — пишут их планы (commit-mechanism, plans-progress-dashboard); здесь — предусловия и проверка.

## Правила исполнения

- Правила проекта без исключений: тестер до кода — один раз на механизм, в worktree на коммите до реализации; инъекции
  лида на каждое заявленное свойство; синхронный reviewer после каждой задачи; CTO — на приёмке фазы.
  Для гейтов CI (1.7) инъекция = PR с нарушением; красный job CI — свидетельство.
- Облачная сессия: своя ветка `atlas/<task>`, только PR; запрещены `git push --force`, правка `.github/` без отдельного
  согласия владельца и любые коммиты в `main`. Трейлеры `Why/Layer/Refs/Task` одним блоком. Git-хуков в облаке нет —
  гейт там только CI, поэтому 0.2 (`validate_commit` на PR) — предусловие облачных фаз.
- Локально: 0.1–0.3, 0.5, 0.6, K1.1, 3.1, 5.1, `--baseline-init` и `sync --write` (пишет лид в `main`).
- Данные в одну сторону: `plans_progress` → `atlas`; `plans_progress` не читает `atlas --json`. Облачный PR, меняющий `.github/workflows/**` или `scripts/validate_commit/**`, — ручной разбор лидом до слияния (job из PR правит сам себя).
- Не больше трёх писателей одновременно; общий сводный файл пишет один (правило `sci-librarian`, knowledge-apps).
- Ядро `scripts/atlas/` ≤ ~600 строк до второго адаптера; `plans_progress` — адаптер через `--json`, не донор кода.
- Пять выходов (`card`, `pack`, `log`, HTML, `sync`) до kill-проверки допустимы только при ведомости удалений (правило «меньше слоёв»).
- Вызов `atlas pack` не держится на воле агента: после 1.6 `lint-brief` требует в брифе блок из `atlas pack` (иначе kill-условие №2 измеряет дисциплину, а не инструмент).
- Честная оценка (CTO): самое надёжное — базовая загрузка (память 0.4 + `CLAUDE.md` 2.4 ≈ 12–15k токенов на каждую сессию); карточка режет разведку, экономия входа 10–25 %; доказанность 6–12 недель показывает `n/a` у большинства модулей. Вероятность срабатывания kill — 40–50 %.

## Метрики и kill-критерий

Замер в Task 0.6 (база) → повтор в K1.1:
- доказанность по модулю: имена с тестом, гарантии с инъекцией, мутационный балл;
- слияния, изменившие публичную поверхность без теста → 0;
- дефекты, найденные живым стендом после ревью → тренд вниз;
- цена входа агента (токены до первой правки, ≥ 10 задач, медиана и разброс);
- доля задач, где агент вызвал `atlas card`/`pack` (из `agent-journal` и транскриптов);
- мест на один факт (D1–D10: сегодня 2–5, цель 1);
- повторные грабли: доля новых уроков памяти, у которых нашёлся похожий существующий (урок был, но не сработал); база — уроки за 60 дней до 0.4;
- `MEMORY.md` ≤ 8 КБ; корневые `CLAUDE.md` < 12 КБ каждый (сейчас 25,3 и 30,0 КБ).

**Kill (Task K1.1)** — останавливаемся на минимуме при любом из шести:
1. цена входа агента упала < 20 %;
2. `atlas card`/`pack` вызван в < 50 % задач;
3. из ≥ 8 ревью и вердиктов за 3 недели 0 цитируют находку `atlas`;
4. мутационный гейт: из ≥ 10 прогонов CI на одном SHA ≥ 3 с разным результатом;
5. строка доказанности не изменила ни одного решения лида (по журналу ревью);
6. доля повторных граблей не снизилась против базы 0.6 — доставка уроков агентам не работает (решение владельца 2026-10-04).

Минимум = два гейта CI + гейты связности + генерируемые блоки; карточка, HTML и сид снимаются.
Условие на каждую фазу: коммиты Атласа ≤ 25 % влитых за неделю (по `Refs:`).
