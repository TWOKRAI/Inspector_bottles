# Task 7.1: Вкладки, страница плана и переключатель — лаконичная страница без `<script`

TASK: 7.1 — вкладки сверху, страница плана по `#plan-<slug>`, переключатель планов   PLAN: plans/2026-10-02_plans-progress-dashboard/plan.md

CHAIN: reviewer(текст, ред. 3) -> tester(RED до кода, worktree) -> developer -> lead(инъекции, живой стенд в браузере) -> reviewer

DESIGN:
  - **Зачем.** Владелец (2026-10-05): страница красивая, удобная, информативная; по умолчанию лаконичная, вкладки и поля скрываются; переключение между планами; раскладка «вкладки сверху». CTO (вердикт «одно окно»): якорь `plan-<slug>` у каждой карточки, страница плана по `:target` без `<script`, якорь закреплён тестом — по нему Атлас 3.1 встроит страницу вкладкой «Планы» и даст ссылки (стык 7 в `ORDER.md`; контракт — фрагмент URL `#plan-<slug>`).
  - **Без JS.** Ни одного `<script`, ни одного атрибута, имя которого начинается с `on`, ни `javascript:`. Вкладки — радиокнопки в `nav.tabs` + правила вида `main:has(#tab-x:checked) > #sec`; каждое правило, которое **скрывает** секцию, само содержит `:has()` (браузер без `:has()` показывает все секции). Раскрытие закрытых `#waiting`/`#archive` на их вкладке — `::details-content`; в старом браузере — клик.
  - **Прежняя разметка не меняется, только добавки.** Порядок секций и их `id`; литералы `<details id="waiting">`, `<details id="archive">`, `<section id="queue">`; `#priority` выводится всегда, как сейчас (без строк «Снимка» — с заглушкой); `<details class="plan" …>` — прежние атрибуты, `id` у него **нет**, `<summary>` сразу после открывающего тега; чипы и их порядок; начало `<div class="body">`.
  - **Запреты для новых элементов:** нет `data-plan`, `data-ready`, `data-chip`; нет классов `meta`, `note`, `chip`, `badge`, `name`, `tally`, `cell`, `info`, `plan`; у новых `<details>`/`<section>` нет `id`; внутри `#who` и `#priority` новых `<p>`/`<li>` нет.
  - **Шапка.** `<header class="topbar">`: `h1`; три прежних `div.meta` без изменений текста и порядка (собрано · SHA; счётчики; `#ready`); переключатель «Планы ▾»; ссылка `<a class="back" href="#">← все планы</a>` (видна только на странице плана). Липкая — только `nav.tabs` (на 390 px шапка не съедает экран).
  - **Вкладки** — `<nav class="tabs">` в шапке, порядок в документе: `queue, waiting, unlisted, archive, who, overlaps, priority, lanes`. Разметка: `<input type="radio" name="tab" id="tab-<ключ>">` + `<label for="tab-<ключ>">Метка · N</label>`. Метки дословно: `Очередь`, `Ждут`, `Нет в ORDER`, `Архив`, `Кто где`, `⚠ Пересечения`, `Приоритеты`, `Полосы`. `checked` — только `tab-queue`. Есть всегда: `queue`, `waiting`, `archive`, `who`, `lanes`. `unlisted` — если есть планы вне ORDER; `overlaps` — при N > 0; `priority` — если в «Снимке» ≥ 1 строки (иначе вкладки нет, секция скрыта). N: планы (`queue`, `waiting`, `unlisted`, `archive` = §4.3 + `_archive/`), строки (`who` — активные + сироты, `priority` — строки «Снимка»), файлы (`overlaps`), полосы (`lanes`). Вкладка показывает свою секцию, прочие секции скрыты.
  - **Якорь карточки** — пустой `<span class="anchor" id="plan-<slug>"></span>` сразу после `</summary>`, до `<div class="body">`. Имя: `plan-` + имя плана, символы вне `[A-Za-z0-9_-]` → `-`. Имя занято карточкой выше на странице: у архивного плана — `plan-<slug>-archive`; если и оно занято, или план живой, — первый свободный из `plan-<slug>-2`, `-3`, … Живые карточки на странице всегда выше архивных, поэтому живой план с уникальным slug получает `plan-<slug>` без суффикса (инвариант для Атласа; то же — в README).
  - **Якорь в `--json`** (просьба Атласа, стык 7: правило slug в одном месте): ключ `anchor` в конце объекта плана. Якоря назначает одна функция в порядке карточек страницы (живые выше архивных) — её зовут и `to_html`, и выгрузка `--json`; Атлас правило не повторяет.
  - **Ссылка на страницу плана** в `<summary>` сразу после `span.name`: `<a class="plan-link" href="#<id якоря этой карточки>" title="страница плана">↗</a>`.
  - **Страница плана** (`details.plan:has(> .anchor:target)`): видна шапка без `nav.tabs` и одна эта карточка — раскрытая, во всю ширину, со списком задач; остальное скрыто (правило вида `main:has(.anchor:target) > :not(header, :has(:target))`). Пока URL указывает на карточку, вкладки не видны. Правила страницы плана перебивают правила вкладок (стоят ниже; `display` — через `!important`, рамка `#waiting`/`#archive` — отдельным правилом со специфичностью выше `details#archive`, ред. 5): иначе архивная карточка на странице плана останется в скрытом `#archive`.
  - **Переключатель** — `<details class="switcher"><summary>Планы ▾</summary>`; группы — `<div class="sw-group"><b>Название</b> <a href="#plan-…">имя</a> <small>…</small> …</div>`; текст `<small>` — как у `.tally` карточки без хвоста «(снято/отложено…, без статуса…)», у плана без задач `0 из 0` в порядке `Очередь`, `Ждут`, `Нет в ORDER`, `Архив`; пустой группы нет; по одной ссылке на каждую карточку страницы, в порядке карточек, `href` — `#` + `id` её якоря.
  - **Поля карточки свёрнуты.** `div.cells` виден; `<ul class="tasks">` — внутри `<details class="tasklist"><summary>Задачи · N</summary>`, N = число `<li>` в этом `ul.tasks`; у карточки без задач `details.tasklist` нет. На странице плана список раскрыт CSS-ом.
  - **Вид.** Весь CSS — в одной константе `CSS`, на странице один `<style>`; содержимое `<style>` ≤ 6 900 байт UTF-8. **только тёмная тема** (решение владельца 2026-10-05, ред. 4): тёмные значения CSS-переменных прямо в `:root` и `color-scheme: dark`, без `@media (prefers-color-scheme…)` и без светлой палитры; тесты 1.2 (`test_acceptance_progress.py:893–895`) и авторский про media-запрос переписываются на «страница тёмная всегда»; правило `.chip.ok{color:var(--done);border-color:var(--done)}` — дословно; нигде нет `http://`/`https://` (в т. ч. `xmlns` в data-URI), `@import`, внешних шрифтов. Карточки с рамкой и скруглением, прогресс в цвет акцента, вкладки — «таблетки» с выделенной активной, ширина ≤ 1100 px по центру.
