DESIGN:
  - Идея владельца 2026-10-04 («пульт»): владелец сам ставит, что брать следующим. Источник правды — блок в `ORDER.md`; страница (6.2) и `--next` (6.5) его только читают. Решение (в) — в очередь идут и планы, и задачи (замысел владельца; лид 2026-10-06, владелец: «продолжай»). Решения (а), (б), (г) этой задачи не касаются.
  - Блок — строки между `<!-- owner-queue:begin -->` и `<!-- owner-queue:end -->`. Маркер — строка целиком (пробелы по краям не в счёт); маркер внутри строки с другим текстом — не маркер. Ни одного маркера — блока нет: очередь пуста, находок нет. Ровно один begin и после него один end — блок есть. Любое другое сочетание — находка `OWNER_QUEUE_BLOCK` (число begin и end в тексте), очередь пуста.
  - Таблица — первая в блоке (строки, начинающиеся с `|`). Колонки ищутся по тексту шапки после `clean_md` и `casefold`: `#`, `план`, `задача`, `заметка`; обязательна только `план`. Нет таблицы или нет колонки `план` — `OWNER_QUEUE_BLOCK`, очередь пуста. Строка-разделитель (`|---|`) и строка из пустых ячеек — не пункты.
  - Пункт — строка данных, порядок — порядок строк. Ячейка `#` не читается (она для глаз): `n` = номер строки данных с 1.
    - План: имена из сырой ячейки тем же способом, что в «Снимке» (`snapshot_slugs`: ссылка `[..](путь)` или текст; только вид слага), поиск — `find_by_slug` (точное имя раньше имени с датой, живой раньше архивного). Ноль имён или больше одного — `OWNER_QUEUE_BAD`. Имя без плана — `OWNER_QUEUE_UNKNOWN`.
    - Задача: ячейка после `clean_md`, без начального `Task ` (без учёта регистра). Пусто, `—` или `-` — пункт-план. Иначе — id задачи: полное совпадение с `ID_PATTERN`, иначе `OWNER_QUEUE_BAD`. Задачи с таким id нет в найденном плане — `OWNER_QUEUE_UNKNOWN`. Повтор id в плане — берётся первая.
    - Закрыт: пункт-задача — статус задачи в `TASK_CLOSED`; пункт-план — `plan_closed(plan)`. Закрытый известный пункт — `OWNER_QUEUE_CLOSED` («уберите из очереди»).
    - Заметка — ячейка `заметка` через `clean_md`; нет колонки — `""`.
  - `--queue` — отдельный режим, как `--who`: печатает `{"items": [...]}` (`json.dumps(..., ensure_ascii=False, indent=2)`), exit 0. Пункт — ключи строго в порядке `n`, `kind` (`"plan"` / `"task"`), `plan` (имя найденного плана; не найден — текст ячейки через `clean_md`), `task` (id или `null`; у пункта-плана `null`), `note`, `known` (план найден, у пункта-задачи и задача найдена, строка без `OWNER_QUEUE_BAD`), `closed` (`false`, если `known` ложно). Контракт ключей — только дописывание в конец. Каждая строка данных — пункт, и битая тоже (`known: false`). Сочетание `--queue` с `--json`, `--html`, `--check`, `--sync-order` или `--who` — exit 2 и сообщение в stderr со словом `--queue`. Работает с `--root` и `--order`.
  - Находки `--check`: все четыре кода не блокируют (`info`, exit не меняют), `plan` = `ORDER.md`, `task_id` = `None`, текст называет номер пункта `n` и имя плана или задачи. В любой ветке и вне git (не через `order_block_findings`, она молчит вне `main`). Почему не блокируют: `--check --baseline` идёт в `validate.py` у всех сессий и в CI; опечатка владельца не должна валить чужие коммиты.
  - `--json`, `--html`, блок `progress:begin…end` и `--sync-order` не меняются: блок `owner-queue` им не виден.
