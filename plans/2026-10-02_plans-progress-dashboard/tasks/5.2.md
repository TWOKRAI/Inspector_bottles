  - Корни: `git -C <root> worktree list --porcelain`, если `rev-parse --show-toplevel` — тот же каталог, что `--root` (`os.path.samefile`). Иначе (нет git, нет `git init`, tmp внутри чужого репозитория) корней нет: `active: []`, `--who` пуст, exit 0. Ветка из porcelain: `branch refs/heads/X` → `X`, `detached` → `""`. Главное дерево — тоже корень.
  - Сигнал: строки `<worktree>/data/agent-journal.jsonl` корня (журналы вне списка не читать; нет журнала = «неизвестно»). Пропускать битый JSON и не-объект, `event == ""`, `ts` не строкой, не по `datetime.fromisoformat` или с поясом. `ts` — местное время. Свежая: `now - ts <= окно` (будущее тоже свежее). Корень без свежей строки в выдачу не попадает.
  - По свежим строкам: `sessions`, `agents` — число разных непустых `session_id`, `agent_id`; `last_signal` — наибольший `ts` строкой как в журнале.
  - Резолвер — функция от (ветка, worktree или None), первый успешный шаг, имя шага в `via`: (а) `plan_ref`: `git -C <wt> config --worktree --get plan.ref` (ненулевой код = не задан; 128 — нет `extensions.worktreeConfig`); без worktree шаг пропускается; (б) `refs`: самый новый коммит в `git -C <root> log --format=%B main..<ветка>` со строкой `Refs:` и токеном `plans/[^\s,;)]+`, первый такой токен; неизвестное имя → шаг не дал плана, к старым коммитам не идти; (в) `header`: строка `Ветка:`/`Branch:` в первых 30 строках главного файла плана (разметка `- **…:**` и обратные кавычки допустимы), первый токен вида `тип/имя`, хвост отброшен; сначала живые планы, архивные — если у живых нет; ветка у двух планов одного уровня → шаг не дал плана. Пустая ветка → (б) и (в) пропускаются. Порядок: явная привязка, затем след в коммитах, затем шапка трека.
  - Имя плана из пути: первый сегмент после `plans/` (после `_archive/` и `<квартал>/`, если есть), без `.md`: `plans/X/tasks/1.1.md` → `X`, `plans/Y.md` → `Y`. `plan.ref` — путь или голое имя. Сначала живой план, потом архивный. Неизвестное имя → шаг не дал плана.
  - `--json`: у каждого плана ключ `active` — ПОСЛЕДНИЙ (README: новые ключи в конце): список `{"branch", "worktree", "via", "sessions", "agents", "last_signal"}`; `worktree` — путь как в porcelain. Прочие ключи и их порядок не менять.
  - `--who`: на stdout только объект `{"active": [...], "orphans": [...]}`; в `active` те же записи плюс `"plan"`, в `orphans` корни без плана, без `plan` и `via`. Все списки по `worktree` по возрастанию. `--who` вместе с `--json`/`--html`/`--check`/`--sync-order` → exit 2. Потребитель — Task 5.3.
  - Точки впрыска: `--now ISO` (местное без пояса, иначе exit 2; по умолчанию сейчас), `--active-window` вида `\d+[mhd]` (по умолчанию `6h`, не измерено); иное → exit 2, в stderr сообщение без самого значения. `main..<ветка>` — литерал `main`: нет ветки `main` → (б) не дал плана.
  - Фикстура тестера — настоящий `git init -b main` с `git worktree add`, как в Task 5.5: шаги (а) и (б) без git не проверить. `--html` и `--check` задача не трогает.
