DESIGN:
  - Модель. `Plan` получает `after: list[str]`, `after_reason: str`, `waiting_on: list[str]`, `ready: bool`, `dep_unknown: list[str]`, `dep_cycle: list[str]`. `Task` получает `after: list[str]` и `ready: bool`; `Item` (:368) получает `after`. В `--json` новые ключи идут в конец объекта, старые ключи и их порядок не меняются.
  - Поле плана. Новая `find_after(text) -> tuple[list[str], list[str], str]` рядом с `find_header_status` (:337): то же окно (первые 30 строк), тот же вид строки (`После`/`After`, жирный, маркер списка, цитата). Значение режется по первому ` — ` или ` – `: слева список, справа причина. Элемент списка (делится по запятой) с `⛔` — условие (`waiting_on`), иначе имя плана: без обратных кавычек, префикса `plans/`, хвоста `/plan.md` и `.md`. Вызов — в `analyze_plan` сразу после `plan.header_status = …` (:633).
  - Связи задач. `TASK_AFTER_RE` ищет `(после N.M)`, `(после N.M, K.L)` и `(after …)` без учёта регистра; id — `ID_PATTERN`. Разбор в `_finish_item` (:383) даёт `Item.after`; `analyze_plan` переносит его в `Task` только в ветке пунктов списка (:664), у остальных задач `after=[]`.
  - Решение. Новая `resolve_deps(plans)` вызывается в `main` сразу после `apply_order` (:1315). План закрыт, если он в архиве, или `tier == "4.3"`, или `header_status` в `{done, superseded}`, или у него есть задачи и ни одной незакрытой (`unknown`, `pending`, `in_progress`, `blocked`). `ready` плана = не закрыт, нет `waiting_on`, и каждое имя из `after` найдено среди ВСЕХ планов (живых и архивных) и тот план закрыт. Имя, которого нет, держит (`ready: false`) и попадает в `dep_unknown`: опечатка не должна выглядеть закрытым планом. `ready` задачи = статус `pending` и каждый id из `after` есть в этом же плане и имеет статус `done`, `deferred` или `superseded`. Цикл (включая ссылку плана на себя) ищется обходом графа по планам и отдельно по задачам каждого плана; каждый участник цикла попадает в `dep_cycle`.
  - Находки. В `build_findings` (:833) добавить `DEP_UNKNOWN` (план: имя; задача: id, которого нет) и `DEP_CYCLE`; блокирующие только при `tier == "4.1"` (`in_41`), иначе информационные; архивные планы линт не смотрит. Ключ базы `plan:code`.
  - Не менять: разбор задач и статусов, старые ключи `--json`, `--html`, блок `progress:begin…end`, `plans_ledger.py`.

ACCEPTANCE:
  Все проверки идут через CLI: `python scripts/plans_progress/plans_progress.py --root <фикстура> --json` и `--check`; фикстура — каталог `plans/` с планами и при необходимости `plans/queue/ORDER.md` (таблицы §4.1 и §4.3 задают `tier`). Ожидания — литералы.
  P1. План без поля: `after: []`, `waiting_on: []`, `ready: true` (план не закрыт).
  P2. B: `- **После:** A`, A не закрыт → у B `after: ["A"]`, `ready: false`. A закрыт (все задачи DONE) → `ready: true`. A в `plans/_archive/2026-Q4/` → `ready: true`. A в §4.3 `ORDER.md` → `ready: true`. У A шапка `Статус: DONE` при незакрытых задачах → `ready: true`.
  P3. `- **После:** ⛔ железо` → `waiting_on: ["железо"]`, `after: []`, `ready: false`. Список `A, B` → `after: ["A","B"]`, `ready: true` только если оба закрыты. Причина после ` — ` не попадает в имя: `- **После:** A — ждёт API` → `after: ["A"]`, `after_reason: "ждёт API"`.
  P4. Имена с `plans/A/plan.md`, `A.md`, ``` `A` ``` → `after: ["A"]`. Английское `- **After:** A` читается так же. Поле глубже 30-й строки не читается.
  P5. Ссылка на несуществующий план → `DEP_UNKNOWN`, `ready: false`. Цикл A↔B → `DEP_CYCLE` у обоих, `ready: false` у обоих. Ссылка плана на себя → `DEP_CYCLE`.
  P6. Блокировка: для плана из §4.1 `DEP_UNKNOWN` и `DEP_CYCLE` блокирующие (`--check` exit 1, без базы); для плана вне §4.1 — информационные (exit 0). Строка находки содержит слово `blocking` или `info` как у остальных.
  P7. Задачи: `- Task 1.2: x [PENDING] (после 1.1)` при `1.1` в PENDING → у задачи `after: ["1.1"]`, `ready: false`; при `1.1` DONE → `ready: true`; при `1.1` DEFERRED → `ready: true`; `(after 1.1, 1.0)` → `after: ["1.1","1.0"]`, `ready` только если обе закрыты. Задача `DONE` → `ready: false`. Ссылка на отсутствующий id → `DEP_UNKNOWN` и `ready: false`. Цикл 1.1 ↔ 1.2 → `DEP_CYCLE`.
  P8. Старые ключи `--json` не изменились (`plan`, `path`, `archived`, `lane`, `tier`, `done`, `total`, `dropped`, `unknown`, `unmarked`, `header_status`, `tasks[].id/title/status/ref`).
