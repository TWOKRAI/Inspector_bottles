## Что осталось открытым

- Перекрёстная история (ревью раунда 2, minor): `git merge-base` без `--all` берёт одну базу из двух. Общий предок ушёл вперёд, обе сестринские ветки влили один и тот же новый `main` → правка предка снова даёт строку (воспроизведение reviewer `s10.py`, S1f). На живом дереве 0 случаев. Исправление ~5 строк + тест: `merge-base --all`, файл засчитывается, только если он есть в diff от каждой базы у обеих веток.
- Приёмка 14 закреплена только тестами автора, слепой набор тестера не расширялся.
- Запятая в имени ветки делает `data-branches` неоднозначным (`feat/a,b` + `feat/c&d` → три имени при чипе `веток: 2`); формат задан спеком, оговорки в README нет.
- Переименования: `--no-renames` (наследие 5.5) даёт предупреждение там, где `git merge` с поиском переименований сливает чисто; при корне на ветке, перенёсшей план в архив, строки нет. Граница спека.
- `--json` при корне на ветке платит за проход радара (+1 `merge-base`, +1…2 `diff`), хотя радар там не строится; вывод побайтно прежний.
