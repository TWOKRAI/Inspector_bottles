# Task 5.6: Радар пересечений — две актуальные ветки меняют один файл плана

TASK: 5.6 — Радар пересечений                 PLAN: plans/2026-10-02_plans-progress-dashboard/plan.md
ROLE: developer (Sonnet); tester до кода (слепой, worktree)
CHAIN: reviewer(текст, 2 раунда) -> tester(RED до кода, worktree) -> developer -> lead(инъекции) -> reviewer

DESIGN:
  - **Зачем.** Конфликт слияния рождается там, где две независимые ветки меняют один файл. Это видно из git без реестра занятости и без привязки ветки к плану. Радар только предупреждает, ничего не запрещает.
  - **Ветки и стек — как в 5.5, тем же кодом.** Актуальная ветка, окно `--branch-window`, стек (`_stack_parent`), тронутые пути (`touched` в `collect_branches`: diff от родителя ∩ diff от merge-base) — без изменений. Проход по веткам выносится из `collect_branches` в одну функцию, которой пользуются числа 5.5 и радар; сигнатура и вызовы git `collect_branches(root, plans, now, window)` прежние (тесты 5.5 считают их на границе ОС).
  - **Ветка `--root` участвует в радаре** (решение лида: страница, собранная в worktree, иначе не видит пересечений своей же ветки). Её `touched` считается, как у прочих: от родителя или merge-base; окно свежести к ней не применяется (как к кандидату в родители в 5.5). В числах 5.5 она по-прежнему не выводится. Это +1 `merge-base` и +1…2 `diff` за прогон против 5.5, когда корень взят на ветке, а не на `main` (свежей или устаревшей; в `--json` тоже — ред. 2: README поправить); незакоммиченные правки корня радар не видит (считается вершина) — фраза в README.
  - **Пересечение.** Файл `F` под `plans/` даёт пересечение, если:
    1. `F` относится к плану, найденному на диске `--root`: равен файлу однофайлового плана или лежит в каталоге плана (живого или архивного) — правило `_touches`. Служебные файлы (`plans/queue/…`, `plans/README.md`, `plans/QUEUE.md`) — не файлы плана.
    2. `F` есть в `touched` двух и более участвующих веток, и среди них есть независимая пара: вершина A не входит в `main..B`, вершина B не входит в `main..A`.
    3. **(ред. 2, ревью кода)** Если у независимой пары есть общие невлитые коммиты (`main..A` ∩ `main..B` не пусто), пара засчитывается за `F`, только когда `F` меняли обе ветки после их общей точки: `F` есть в `git diff --name-only -z --no-renames <merge-base A B> refs/heads/<X> -- plans/` и для A, и для B. Причина: правка общего предка, который перестал быть родителем в стеке (ушёл вперёд или выпал из окна), иначе засчитывается обеим дочерним — ложная строка (живой случай: `task-4.7.md`, `tests/t47d1-blind` и `tests/t47d4-blind`). `merge-base` пары и diff кэшируются; у пар без общих коммитов вызовов git не прибавляется. `merge-base` пары не получен — пара засчитывается по правилу 2 (радар лишь предупреждает). `touched` из 5.5 не меняется.
    Ветки стека друг с другом не пересекаются. Ветка, для которой `main..<ветка>` не получен (git не ответил, множество пусто), в радаре не участвует. Список веток строки — все участвующие ветки, тронувшие `F`, у которых есть независимая пара; по имени. Считаются ветки, не корни стеков (дочерняя и родитель — две ветки) — фраза в README.
  - **Страница.**
    - Секция только при N > 0, сразу после `#who`; порядок прочих секций прежний. Разметка (все значения через `_e`, файлы по пути):
      `<section id="overlaps"><h2>Пересечения · N</h2><ul><li data-path="<путь>" data-overlap-plan="<план>" data-branches="<a>,<b>">…</li></ul></section>`
      N — число файлов. Атрибут `data-plan` в строках не используется (по нему тесты находят карточки планов).
    - Чип у плана: `<span class="chip" data-chip="overlap" data-overlap="<N>">⚠ пересечение, веток: N</span>`, N — число разных веток по всем файлам этого плана. Место — после чипов `data-chip="branch"`, перед чипами `active` (они последние).
    - Нет пересечений, нет git, `--root` не верхний каталог, нет `refs/heads/main` — секции и чипов нет, exit 0.
  - **Режимы.** Только `--html`. `--json`, `--check`, `--who`, `--sync-order`, текстовый список — прежние (ключей в `--json` не добавляем: его читает Атлас 1.3a).
  - **Отвергнуто.** Пересечения по коду вне `plans/`; блокировка слияния; ключ в `--json`; счёт по корням стеков.
