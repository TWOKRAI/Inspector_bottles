# Task 5.6: Радар пересечений — две актуальные ветки меняют один файл плана

TASK: 5.6 — Радар пересечений                 PLAN: plans/2026-10-02_plans-progress-dashboard/plan.md
ROLE: developer (Sonnet); tester до кода
CHAIN: tester(RED до кода, worktree) -> developer -> lead(инъекции) -> reviewer

DESIGN:
  - Конфликты слияния рождаются там, где две независимые ветки меняют один файл. Это видно из git без реестра занятости и без привязки ветки к плану: `git diff --name-only <база>...<ветка>` по актуальным веткам.
  - Страница: секция «Пересечения» — файлы плана (`plans/…`), изменённые двумя и более независимыми актуальными ветками, с именами веток; чип «⚠ пересечение: N веток» у плана. Файл `docs/sessions/*.md` не считается (сливается по union, `.gitattributes`).
  - **Актуальная ветка** (решение владельца 2026-10-03: считаем только актуальные): у ветки есть коммиты, которых нет в `main` (`git rev-list --count main..<ветка>` > 0), и последний коммит не старше порога (стартово 3 суток, не измерено как оптимум). Замер 2026-10-03: из 71 ветки worktree коммиты сверх `main` у 31; последний коммит сегодня у 6, в последние двое суток у 19, трое суток у 26.
  - **Стек веток:** ветка B — дочерняя к A, если tip(A) — предок tip(B). Дочерние ветки делят коммиты с родителем, поэтому «`plan.md` тронут 8 ветками» (замер: трек transport — 8 веток, `layer-render` — 7) без учёта стека завышает пересечения. Считать по коммитам, уникальным для ветки: `main..A` для корня стека, `A..B` для дочерней.

FILES:
  `scripts/plans_progress/plans_progress.py`, `scripts/plans_progress/tests/`

ACCEPTANCE:
  фикстура: ветки `a` и `b` от одного `main`, обе меняют `plans/x/plan.md` → пересечение `[a, b]`; `b` — дочерняя к `a` (стек) → пересечения нет; `a` и `b` меняют разные файлы → нет; `docs/sessions/2026-10-03.md` в обеих → не считается; неактуальная ветка не участвует; нет git → секция пуста, exit 0.
