# Task 5.6: Радар пересечений — две актуальные ветки меняют один файл плана

TASK: 5.6 — Радар пересечений                 PLAN: plans/2026-10-02_plans-progress-dashboard/plan.md
ROLE: developer (Sonnet); tester до кода (слепой, worktree)
CHAIN: reviewer(текст) -> tester(RED до кода, worktree) -> developer -> lead(инъекции) -> reviewer

DESIGN:
  - **Зачем.** Конфликт слияния рождается там, где две независимые ветки меняют один файл. Это видно из git без реестра занятости и без привязки ветки к плану. Радар только предупреждает, ничего не запрещает.
  - **Ветки и стек — как в 5.5, тем же кодом.** Актуальная ветка, ветка `--root`, окно `--branch-window`, стек (`_stack_parent`), тронутые пути (`touched` в `collect_branches`: diff от родителя, отфильтрованный diff от merge-base) — без изменений. Проход по веткам выносится из `collect_branches` в одну функцию, которой пользуются и числа 5.5, и радар. Число вызовов git на прогон не растёт (тесты 5.5 считают вызовы на границе ОС — они остаются зелёными без правок).
  - **Пересечение.** Файл `F` под `plans/` даёт пересечение, если:
    1. `F` относится к плану: равен файлу однофайлового плана или лежит в каталоге плана (живого или архивного) — правило `_touches`. Служебные файлы (`plans/queue/…`, `plans/README.md`, `plans/QUEUE.md`) — не файлы плана, в счёт не идут.
    2. `F` есть в `touched` двух и более актуальных веток, и среди них есть пара, где ни одна не лежит в стеке другой: вершина A не входит в `main..B`, вершина B не входит в `main..A`.
    Ветки стека (родитель и дочерняя) друг с другом не пересекаются. Список веток пересечения — все актуальные ветки, тронувшие `F`, у которых есть независимая пара; по имени.
  - **Страница.**
    - Секция `<section id="overlaps">` «Пересечения · N» (N — число файлов): строка на файл — путь, план, ветки через запятую; файлы по пути. Секция есть, только если N > 0; стоит сразу после `#who`. Без пересечений, без git, `--root` не верхний каталог, нет `refs/heads/main` — секции нет, exit 0. Порядок прочих секций прежний (его закрепляют тесты 3.4).
    - Чип у плана: `<span class="chip" data-chip="overlap" data-overlap="<N>">⚠ пересечение: N веток</span>`, N — число разных веток по всем файлам этого плана. Место — после чипов веток (`data-chip="branch"`), перед чипами `active` (они последние). Все значения через `_e`.
  - **Режимы.** Только `--html`. `--json`, `--check`, `--who`, `--sync-order`, текстовый список — прежние (ключей в `--json` не добавляем: его читает Атлас 1.3a).
  - **Отвергнуто.** Пересечения по коду вне `plans/` (первая версия — только планы); блокировка слияния; ключ в `--json`.

ACCEPTANCE:
  Фикстура: `git init` в `--root`, `symbolic-ref HEAD refs/heads/main`, в `main` план-каталог `plans/2026-01-01_x/plan.md` (`## Порядок выполнения`, `- Task 1.1: a [PENDING]`) и однофайловый `plans/2026-01-01_y.md`; ветки создаются от `main`, коммиты свежие (или `--now`).
  1. `feat/a` и `feat/b` от одного `main`, обе меняют `plans/2026-01-01_x/plan.md` → секция `#overlaps` с одной строкой: путь `plans/2026-01-01_x/plan.md`, ветки `feat/a, feat/b`; у плана `2026-01-01_x` чип `⚠ пересечение: 2 веток`, `data-overlap="2"`.
  2. `feat/b` создана от `feat/a` (стек), обе меняют `plans/2026-01-01_x/plan.md` своими коммитами → секции нет, чипа нет.
  3. `feat/a` меняет `plans/2026-01-01_x/plan.md`, `feat/b` — `plans/2026-01-01_y.md` → секции нет.
  4. `feat/a` и `feat/b` меняют `plans/2026-01-01_x/tasks/1.1.md` и `plans/2026-01-01_x/plan.md` соответственно (разные файлы одного плана) → секции нет.
  5. Обе меняют `plans/queue/ORDER.md` (служебный) → секции нет. Обе меняют `docs/sessions/2026-10-03.md` → секции нет.
  6. Вершина `feat/b` старше окна (`--now`, 4 суток при окне 3d) → секции нет; с `--branch-window 5d` → строка есть.
  7. Три ветки: `feat/a`, `feat/c` (от `main`) и `feat/b` (от `feat/a`) — все три меняют `plans/2026-01-01_x/plan.md` своими коммитами → строка с ветками `feat/a, feat/b, feat/c`, чип `3 веток`.
  8. Нет git (`GIT_CEILING_DIRECTORIES`, каталог без `git init`), `--root` — подкаталог репозитория, нет ветки `main` → секции нет, exit 0.
  9. `--json` на фикстуре 1: список ключей каждого плана тот же, что на той же фикстуре без веток (`branches` — последний); ни одного нового ключа.
  10. Чип пересечения стоит после чипов `data-chip="branch"` и перед `data-chip="active"`.
  11. После прогона вершины веток и `git status --porcelain` фикстуры прежние.
