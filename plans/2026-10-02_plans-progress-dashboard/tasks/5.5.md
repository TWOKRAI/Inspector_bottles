# Task 5.5: Прогресс актуальных веток против `main`

TASK: 5.5 — Прогресс актуальных веток против `main`                 PLAN: plans/2026-10-02_plans-progress-dashboard/plan.md
ROLE: developer (Sonnet); tester до кода (слепой)
CHAIN: tester(RED до кода, worktree) -> developer -> lead(инъекции) -> reviewer

DESIGN:
  - **Актуальная ветка** (владелец, 2026-10-03): локальная `refs/heads/<B>`, не `main`; `git rev-list refs/heads/main..refs/heads/<B>` не пуст; вершина свежая: `%(committerdate:unix)` -> `datetime.fromtimestamp()` (местное), `now - t <= --branch-window`, будущее — свежее. `--branch-window` по умолчанию `3d`, формат `--active-window`; проверяется до выбора режима: неверное -> exit 2 в любом режиме, stderr без значения флага.
  - **Ветка `--root`** (взятая в корне) кандидат в родители, но в `branches` не выводится: её состояние уже на диске. Подпись «в main» — допущение (страницу строит лид).
  - **Стек:** кандидаты в родители — актуальные ветки и ветка `--root`. A — родитель B, если вершина A входит в `main..B`; при равных вершинах родитель — меньшее имя; из нескольких — с наибольшим `main..A`, при равенстве — меньшее имя.
  - **Тронутые планы:** `git diff --name-only -z --no-renames <от> refs/heads/<B> -- plans/`; `<от>` — вершина родителя, у корня стека — merge-base с `main`. Путь относится к плану, если равен файлу однофайлового плана или лежит в каталоге плана (живого или архивного).
  - **Числа ветки — слияние по задачам** (почему — `design.md`). Шаги:
    1. План разбирается `analyze_plan` дважды: на merge-base `main` и `B` (база) и на вершине `B`. Парсер не меняется.
    2. Ключ — id (повтор — первая запись); отсутствие задачи — тоже статус. Задача с диска: вершина = база → статус диска; иначе, если диск = база, → статус вершины (отсутствие — задача выпадает); иначе (изменили обе) → `done`, если он на вершине или на диске, иначе статус диска. Плана нет на базе → база пуста.
    3. Задачи вершины, которых нет ни в базе, ни на диске, добавляются.
    4. `done`/`total` — по тем же правилам, что у плана.
  - **Выгрузка:** `git archive --format=tar -o <tmp>/x.tar <коммит> -- <путь плана>` через `_git` (stdout пуст), распаковка `tarfile` с `filter="data"`. Плана нет на вершине (удалён, перенесён) — записи нет.
  - **`--json`:** ключ `branches` последним (после `active`): `[{"branch", "done", "total"}]`, ключи в этом порядке, `sorted()` по имени ветки. Запись — для каждой актуальной ветки, тронувшей план, даже при тех же числах. Нет git, `--root` не верхний каталог репозитория, нет `refs/heads/main` -> `[]`, exit 0.
  - **Закрепления «`active` последний»** (5 мест) перевести на хвост `"active", "branches"`. Места: `test_acceptance_active.py:922` и `:933`, `test_active_author.py:551`, `test_acceptance_deps.py:129`, `test_acceptance_priority.py:39-42` (`OLD_JSON_KEYS`). Остальное в них не трогать.
  - **Страница:** `<span class="chip" data-chip="branch" data-branch="<B>">в ветке <B>: N из M, в main: K</span>`; K — `done` на диске, все значения через `_e`. Чип ставится, только если `done` или `total` отличаются от диска; у закрытых и архивных тоже. Место: после прочих чипов, сразу перед чипами `active` (они закреплены последними); несколько — по имени ветки.
  - **Режимы:** ветки считаются только для `--json` и `--html`; `--who`, `--check`, `--sync-order` и текстовый список прежние. Git только через `_git`, `main` всегда как `refs/heads/main` (тег `main` ломает голое имя).
  - Замер, отвергнутое, связь с 5.6 — `design.md`, «Task 5.5».
