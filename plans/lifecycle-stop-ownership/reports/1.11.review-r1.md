## Major

**1. DESIGN — пропущен путь: бюджет области `children` и источник потолка PM.**
`process_manager_process.py:3700` — `work.child("children", budget_s=self._budget()["pm_graceful_s"], …)`: срок группы детей жёстко = S (`shutdown_timeout`). `_budget()` (3691) идёт от раннера (`process_runner.py:61-79, 407`, не в FILES). DESIGN называет только корень PM (`_root_budget`, 3687); без правки 3700 системный стоп режет A (окно 8) на S=5 — R4 не пройти. Менять: один помощник `G = max(S, max_stop_window_s)` в `_root_budget`, `_own_work:3700` и спавнере; дописать в DESIGN/FILES. Арифметика S=5, C=10: `children` budget=G=10, reserve 2 → 12 = `pm_total_s`; корень 12+`infra_s`1 = 13; спавнер 13,5 — запас 0,5, как сегодня; 13,5 = R5.

**2. DESIGN — не определено, кто знает окна по именам.**
Единственное узкое место — `_build_child_stop` (`process_registry.py:463`), его зовут `_stop_many` (491) и `_ChildrenGroupStop.request_stop` (584). Реестр не видит `_process_configs`; все четыре PM-места передают скаляр (1990, 3852–3855, 4411, 3875 через `stop_process`). Выбор должен быть в DESIGN. Рекомендация: реестр запоминает окно в `_create_process` (рядом с 203) и снимает в `remove_process`; потолок — в конструктор реестра, как `child_stop_budget`. Тогда одиночный, откат, пакет топологии, рестарт и системная группа получают окна без правки каждого места; `stop_many(names, timeout)` — `timeout` становится окном для имён без ключа; бюджет области = max окон группы. `deadlines` двусмысленно (длительности от `request_stop` или абсолютные `monotonic`?) — группа строится до `request_stop`, значит длительности; переименовать в `windows_s`.

**3. DESIGN ломает инвариант и контракт фаз.**
`child_process_stop.py:21-22`: «до `kill()` процессам не шлётся ни одного сигнала». DESIGN — `terminate` по своему окну внутри `join_until`, то есть до `kill()`. Scope держит фазу 3 у себя (`lifetime.py:627-654`); `process_registry.py:485-487` — порядок фаз живёт один раз, в Scope. Эскалация групповая (`_kill_started_at`, `_real_kill_sent`, `_kill_at`, `child_process_stop.py:219-224`): для имени с окном 5 в группе с max 8 нужны свои `terminate_at=w`, `kill_at=w+TERMINATE_GRACE_S`, подтверждение до `w+2 ≤ G+2`. `kill()` (197-217) повторно шлёт `terminate` уже терминированным и логирует групповое `waited` (8,0 вместо 5,0). Per-name `terminate` обязан идти ПОСЛЕ `_abort_requested()` (253-257), иначе прерванный системным стоп (`handed_over`, 1.9b D4) получит сигнал. Менять: описать per-name эскалацию и порядок «опрос → abort → сроки имён»; поправить инвариант в docstring и ADR; RED на abort и на имя, игнорирующее SIGTERM (п.7).

**4. DESIGN — потолок ниже `shutdown_timeout` не определён.**
S=5, C_cfg=3: если клампить все окна, окно без ключа станет 3, а бюджет ребёнка без ключа из S (`work_s+infra_s` = 0,8·5 = 4,0 > 3) — «ребёнок < PM» нарушена. Явно: `G = max(S, C_cfg)`, кламп только для окна с ключом; без ключа — S (системный) / `stop_process_timeout` (одиночный); WARNING при C_cfg < S — по желанию. Остальные комбинации держатся (ключ ниже → `w ≤ G`; выше → `w = C_cfg ≤ G`; нет → как сегодня).

**5. Невалидное значение ключа не описано.**
`stop_budget()` бросает на NaN/отрицательное/bool/строку (`stop_budget.py:61-69`), `0` → 5,0 (70); `_stop_timeout_s` (`process_registry.py:429`) трактует 0 как «сразу эскалация». `_create_process` ловит `except Exception` и возвращает `None` (311-317) — плохой `stop_window_s` молча не создаёт процесс. Менять: проверка один раз при регистрации; невалидное → ключ игнорируется + WARNING без значения; путь стопа не бросает (DESIGN 7 Task 1.1). То же для `max_stop_window_s`.

**6. Путь «рецепт → топология → конфиг» не проверен REDS.**
Ключ доживает до `_process_configs[name]`, только если назван в `ProcessConfig.as_generic_config` через `_pick(...)` (`topology/blueprint.py:322-380`; прецеденты молчаливой потери C-47 `executors`, G.4.b). `GenericProcessConfig` — `extra="allow"` (`generic_process_config.py:34`); `create_process` (3764) и `_topology_create` (4488) копируют dict целиком. DESIGN «добавляет поле» — конвенция проекта extras + `_pick`, а не типизированное поле (рычаг C6). Менять: уточнить DESIGN; R7 — рецепт с `extras.stop_window_s` → `build_configs()` → dict содержит ключ.

**7. REDS не покрывают заявленные пути и наблюдаемость.**
Нет RED на откат (1990), пакет топологии (4411), рестарт (3875), корень PM и спавнер при явном `stop(timeout)`; ни одна из четырёх инъекций их не краснит. R4: `terminated` наблюдать нечем — `_ChildrenGroupStop.result()` отдаёт `{имя: bool}` (`process_registry.py:613-626`), `outcomes()` пишет только `_stop_many` (507-511); либо `_ChildrenGroupStop.outcomes()` в DESIGN, либо проверять момент `terminate()`. R4 «~5 с» без полосы; инъекция «группа вместо имени» краснит R4 только при проверке момента смерти B (5,0–5,6); для R4 задать `max_stop_window_s ≥ 8`, иначе A обрезается до 5. R5: «читает при спавне» ломает юнит с подставным `_process` без `launch_orchestrator`; `_stop_graceful_s` читает `_orchestrator_config` в `stop()` (`spawner.py:172`) — читать в `stop()`, формула `stop_budget(max(graceful, C_cfg))["outer_s"]`; явный `stop(timeout)` меньше PM-бюджета и ключа нет — как прежде (Task 1.4 зелёные). Нет RED на добивание `kill` по имени (игнорирует `terminate`; на Windows `terminate` убивает сразу — нужен фейк-процесс).
