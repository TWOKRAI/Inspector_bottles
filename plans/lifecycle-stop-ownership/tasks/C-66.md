## DESIGN

**Форма: заявки владельцев вместо одной ячейки и флага.** Эффективный статус вычисляется из заявок; breaker — один из владельцев.

1. **`health/state.py`, `HealthState.__init__` `:215`:** убрать `_breaker_owns_degraded`; завести `self._claims: dict[str, tuple[HealthStatus, str | None]] = {}` (порядок вставки = порядок постановки). Константа модуля `_BREAKER_OWNER = "__breaker__"`.
2. **`set_status(self, status, reason=None, *, owner: str = "")`, `:404`:** под `self._lock`:
   - если `st == OK`: `self._claims.pop(owner, None)`;
   - если `st != OK` и у владельца уже лежит заявка с теми же `(st, rsn)`: **позицию не менять** (повтор идемпотентен; иначе две заявки на тике чередуют причину и шумят журналом и публикацией);
   - иначе: `self._claims.pop(owner, None)`, затем `self._claims[owner] = (st, rsn)` (новое значение становится самым поздним);
   - эффективный статус: если есть заявка `FAILED` — самая поздняя из них; иначе самая поздняя `DEGRADED`; иначе `OK`;
   - причина: причина выбранной заявки; при `OK` — `rsn` этого вызова (сохраняет прежний `ok("текст")`);
   - дальше прежний код: сравнение с `_status`/`_degraded_reason`, `changed`, `_updated_at`, `_dirty` (с учётом `_log_only`), `_safe_log` вне замка — **только при изменении эффективного значения**.
3. **`degraded`/`failed`/`ok`** получают `*, owner: str = ""` и передают его в `set_status`.
4. **`report_error` `:333-337`:** переход в `OPEN` → `self.set_status(HealthStatus.DEGRADED, reason, owner=_BREAKER_OWNER)`, без установки флага.
5. **`_clear_breaker_degraded` `:396-402`:** тело заменить на `self.set_status(HealthStatus.OK, None, owner=_BREAKER_OWNER)`. Имя метода и его вызовы из `record_success` `:376`, `poll` `:389` **остаются**.
6. **`HealthReporter` `:590-600`:** `set_status`/`degraded`/`failed`/`ok` передают `owner=self._source`. Сигнатуры прежние. `IHealthReporter` (`:115-146`) меняет только docstring `set_status`: статус `ok` снимает заявку этого плагина.
7. **Прямые вызовы `HealthState` без `owner`** (команда `health.report`, тесты) — анонимный владелец `""`, один на процесс; `health.report status=ok` снимает только заявку этой же команды. `builtin_commands.py` не меняется.
8. **`Services/ml_inference/plugin/plugin.py`:**
   - снять блок `:370-378` в `_publish_state` целиком (комментарий `# Обход C-66`, захват `_engine_lock`, повторная постановка);
   - в `_clear_asset_degraded` `:331`: заменить `if self._asset_degraded and self._ctx.health.status == "degraded":` на `if self._asset_degraded:`. Причина: при чужом `failed` проверка `== "degraded"` пропустит снятие, флаг сбросится, а заявка плагина останется навсегда (замер ревьюера; страж — `test_g10_…`).    - `Services/ml_inference/README.md`: снять абзац «Обход C-66 (временный)» `:99-104` целиком, оставить одну фразу «`_publish_state` замок движка не берёт» (координатор просил сохранить описание неблокирующего тика);

9. **Документы:**
   - `process_module/DECISIONS.md` — **ADR-PM-058**, форма как у ADR-PM-057 (`:4239`): заголовок `### ADR-PM-058 — Заявки владельцев деградации (<дата>, C-66)`, абзацы «Решение», «Не тронуто», «Отвергнуто», «Следствия и риски» (в том числе: при открытом breaker причина плагина наверх не выходит, оператор видит `breaker open…` до закрытия; заявка владельца заменяется целиком), затем `**Refs:**`. ## HAZARDS (что учесть в коде и ревью)

- **Смена смысла `ok()`:** `ctx.health.ok()` больше не «всё хорошо у процесса». Живой вызов один (`plugin.py:332`), и он ждёт именно этого.
- **Утечка заявки:** плагин, ушедший без `ok`, оставляет её до конца процесса; рестарт процесса создаёт новый `HealthState`. Выгрузку плагина из живого процесса не проверял. Строка в ADR.
- **Плагины с одним именем и `source=""`** делят заявку; анонимный владелец — один. Принятый предел (решение лида, текст в ADR): `_plugin_name` ставит оркестратор в boot, reporter кэшируется при первом обращении; уникальность имени в рецепте не проверяется.
- **Причина breaker поверх причины плагина:** оператор видит самую позднюю; `last_error` и `errors` не меняются.
- **`_safe_log` вне замка:** не вносить под `_lock` (`report_error` уже держит порядок: сначала факт, потом голос).
