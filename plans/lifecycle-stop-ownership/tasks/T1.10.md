# Task 1.10 — честный итог стопа: `outcome` рядом с `success`

> Вынесено из [`plans/lifecycle-stop-ownership.md`](../../lifecycle-stop-ownership.md) 2026-10-20 (размер плана). «Файлы полосы Ф» и «Открытые решения О1–О5» — в плане.

процесса); тестер — слепой (Sonnet) в worktree на коммите открытия; реализация — `developer` (Sonnet) по DESIGN

**Module contract:** public-api-change (новое поле ответа и `supervision.status`, аддитивно)
**CHAIN:** `reviewer`(стадия 0) → `tester`(RED) → `developer`(GREEN) → лид (инъекции, стенд) → `reviewer`
**Зависит от:** Task 1.9b (ответ строит исполнитель жизненного цикла; общие файлы). **Источник:** CTO §7 D3 (1); отчёт §4 — `success: True` и при
terminate (`process_registry.py:470-472`).
**Goal:** по ответу `process.stop`/`process.restart` и по `supervision.status` видно, как умер ребёнок; `success`
по-прежнему значит «смерть подтверждена».

**DESIGN:**
- `ChildProcessStop.outcomes() -> dict[str, str]`: на каждое имя группы — `exited` (смерть подтверждена до любого
  `terminate()`), `terminated` (после `terminate()`, до настоящего `kill()`), `killed` (после `kill()`), `survived`
  (не подтверждена). Источник — шаг эскалации в момент подтверждения, **не exitcode** (на Windows -15 бывает и у
  самоубийства через TerminateProcess).
- `ProcessRegistry.stop_outcome(name) -> str | None` — итог последнего стопа воплощения (заполняет `_stop_many`).
- PM: ответ `process.stop` и `process.restart` — `{"success", "process_name", "outcome"}`; `supervision.status` — поле
  `stop_outcome` на процесс (последний стоп; `None`, если не стопался). `success` = `outcome` ∈ {`exited`, `terminated`, `killed`} —
  как сегодня по смыслу. Стоп, прерванный системным стопом (1.9b D4), — **пятое значение `handed_over`** (решение CTO
  по О1, [план](../../lifecycle-stop-ownership.md)): `success: False`, `error: "system_stopping"`, ребёнка добивает
  `_ChildrenStop`. `survived` — только «пережил kill», не смешивать.
- Парсеры `backend_ctl` и GUI не меняются: поле аддитивное.

**Files:** `core/child_process_stop.py`, `core/process_registry.py`, `process/process_manager_process.py`,
`process_manager_module/{DECISIONS.md (дополнение к ADR-PMM-039; 038 занят — стадия 0 1.9b), README.md}`,
`process_manager_module/tests/`.

**REDS — слепой тестер (`test_stop_outcome_acceptance.py`):**
- R1 `test_outcome_exited_for_cooperative_child` — `{"success": True, "outcome": "exited"}`.
- R2 `test_outcome_terminated_for_child_ignoring_stop_event` — ребёнок не реагирует на стоп: `success: True`,
  `outcome: "terminated"`.
- R3 `test_outcome_killed_when_terminate_unconfirmed` — на уровне `ChildProcessStop` с поддельным процессом
  (`is_alive` ложь только после `kill()`): `killed`. Настоящим процессом на Windows недостижимо (TerminateProcess не
  игнорируется) — поэтому подделка; это не пропуск теста.
- R4 `test_outcome_survived_when_kill_unconfirmed` — подделка жива и после `kill()`: `success: False`, `survived`.
- R5 `test_supervision_status_carries_stop_outcome` — после R2: `stop_outcome == "terminated"`.
- R6 `test_restart_reply_carries_outcome_of_stop_phase` — `process.restart` ребёнка из R2: `outcome: "terminated"`.
- R7 `test_backend_ctl_restart_verified_parser_unchanged` — `process_restart_verified` проходит без правок (страж).
- R8 `test_outcome_handed_over_when_system_stop_interrupts` — системный стоп посреди одиночного стопа: ответ
  `{"success": False, "outcome": "handed_over", "error": "system_stopping"}`, не `survived`.

**Инъекции:** перестановка `exited`/`terminated` → R1, R2, R5, R6; итог по exitcode → R2 красный на Windows,
R1 зелёный; `outcome` не попадает в ответ рестарта → R6; `success` от `outcome == "exited"` → R2 (`success` ложно
`False`). Прогноз — до прогона.

**Acceptance:**
- [ ] R1–R8 зелёные; инъекции совпали.
- [ ] Стенд s3, 2 робота ×10 `process.stop devices`: `outcome: "exited"` 10 из 10 (прогноз); `slow` со стопом 6,0 с и
  окном 5,0 с ×3: `outcome: "terminated"`, `success: True`, ответ 5,0–5,3 с (прогноз).
- [ ] Ответ GUI и `backend_ctl` разбирается без правок парсеров (I3 Task 1.9b — их тесты зелёные).

**Out of scope:** `outcome` в сводке стопа (ADR-PMM-033) и в записи стора; код 76 (выжившие внутри ребёнка) —
остаётся статусом монитора, `outcome` о нём не говорит; правка GUI-отображения.
