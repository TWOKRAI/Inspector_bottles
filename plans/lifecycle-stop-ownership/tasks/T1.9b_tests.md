## REDS — слепой тестер (`process_manager_module/tests/test_lifecycle_fifo_acceptance.py`)

Обвязка: PM с конфигом `stop_process_timeout: 8.0`, `shutdown_timeout: 8.0`; медленный ребёнок — `stop_delay_s: 3.0`.
Медленный ребёнок — тестовый класс процесса в `tests/` (стоп ≥ 3,0 с в хуке остановки), вызов — настоящей командой в
очередь PM, каждый ждущий вызов — в daemon-потоке с дедлайном join. Ожидания — литералы. В окне измерения R5–R7 корень
PM **не закрывается** (ни раннер, ни `shutdown()`): `system.shutdown` только взводит события, снятие очереди и прерывание
стопа видны до закрытия корня (иначе область `executor_manager-scope` снимет очередь третьим путём — ревью р.2 п.6).
- R1 `test_supervision_status_answers_during_long_child_stop` — `process.stop slow` (стоп 3,0 с), на +1,0 с
  `supervision.status` прямой дверью с request_id: ответ ≤ 0,5 с. До: ≥ 2,0 с (ждёт конца стопа).
- R2 `test_relay_to_other_process_during_long_stop_delivered_fast` — на +1,0 с `process.relay` в другой процесс: тот
  получил внутреннее сообщение ≤ 0,5 с, ответ relay ≤ 0,5 с. До: ≥ 2,0 с.
- R3 `test_stop_reply_after_confirmed_death_direct_door` — ответ `process.stop` приходит не раньше, чем `is_alive()`
  ребёнка стал `False`; содержимое — `{"success": True, "process_name": "slow"}` (страж, зелёный и до).
- R4 `test_stop_via_process_command_door_deferred_same_content` — `process.command {cmd: process.stop}`:
  `process.command.response` с тем же результатом и `success: True`; пока он ждёт — `supervision.status` ≤ 0,5 с. До: ≥ 2,0 с.
- R5 `test_system_shutdown_during_stop_sets_events_immediately` — на +1,0 с `system.shutdown`: `system_stop_event`
  взведён ≤ 0,2 с после отправки. До: на +3,0…3,6 с.
- R6 `test_queued_lifecycle_ops_rejected_on_system_stop` — стоп `slow` + в очереди `process.restart other`; затем
  `system.shutdown`: ответ рестарта `{"success": False, "error": "system_stopping"}` ≤ 0,5 с, `instance_restarts`
  `other` не вырос. До: рестарт исполнится после стопа.
- R7 `test_system_stop_mid_single_stop_one_owner` — системный стоп посреди стопа в исполнителе `slow`: `slow` выходит с
  exitcode 0, в логе PM 0 строк `did not stop in`, 0 `terminating` и 0 `всё ещё жив после kill`, сводка стопа —
  `reported=true`; ответ `process.stop
  slow` приходит ≤ 0,5 с после отправки `system.shutdown`, `success: False` (D4). До: ответ на +3 с, `success: True`.
- R8 `test_relay_to_target_in_restart_reaches_new_incarnation` — `process.relay` в `slow` на +1,0 с после отправки
  `process.restart slow` (идёт стоп 3,0 с): новое воплощение получает сообщение, 1 из 1 (страж — и до зелёный; после —
  защищает от гонки investigator).
- R9 `test_lifecycle_commands_keep_arrival_order` — `process.stop slow`, сразу за ним `process.restart other`: ответ
  restart приходит после ответа stop, `instance_restarts` `other` = +1 (страж порядка класса L).
- R10 `test_supervision_status_alive_through_topology_apply_with_slow_stop` — `topology.apply`, убирающий `slow`:
  `supervision.status` во время него ≤ 0,5 с (I4 для топологии). До: ≥ 2,0 с.

Ожидаемо RED: R1, R2, R4, R5, R6, R7, R10; стражи (зелёные и до, и после): R3, R8, R9.

**Hazard-тесты автора (H1–H4, H6–H9, `test_lifecycle_fifo_hazards.py`; H5 ушёл в [1.9c](T1.9c.md)):**
- H1 — предусловие: в момент отправки `system.shutdown` у исполнителя активная операция (стоп `slow`, проверка —
  `_in_transition("slow")`); от ОТПРАВКИ до простоя исполнителя ≤ 0,2 с (D4). Без предусловия тест красный. Простой
  исполнителя — `KeyedExecutor.join_until(now)` после `request_stop` или ответ `process.stop`; не счётчик
  `_lifecycle_submit`.
- H2 ни один стоп из описи не ждёт на потоке `message_processor` (обёртка `stop_wait_idle` пишет имя потока; все
  команды класса L) — страж описи.
- H3 `_routing_lock` свободен, пока исполнитель ждёт ребёнка (захват с таймаутом 0,1 с с другого потока успешен).
- H4 исключение в обработчике команды класса L → ответ `success: False`, следующая операция исполняется, и
  `_in_transition(<цель>)` после ответа — `False`.
- H6 — **дымовой тест, не страж** (инъекции нет: вложенная подача в последовательный исполнитель исполняется на месте,
  `keyed_executor.py:196-205`): `recipe.activate` внутри исполнителя зовёт `_cmd_topology_apply` на месте, без дедлока
  (дедлайн 10 с).
- H7 `topology.apply` на исполнителе + 200 вызовов `wire.status` / `supervision.status` / `topology.get` с другого потока
  — 0 исключений `RuntimeError: dictionary changed size during iteration`, каждый ответ ≤ 0,5 с.
- H8 — предусловие как у H1; системный стоп посреди стопа `slow` в исполнителе: число созданных `ChildProcessStop`, в которых есть `slow`, — 1
  (обёртка `__init__` в тесте считает), пока операция не вернулась (ревью р.2 п.1). H8 закрывает корень PM:
  `pm.stop()` (= `cancel()`, фаза 1) на отдельном потоке, как раннер (`process_runner.py:192-196`); счёт объектов — до
  возврата операции и после `_start()`.
- H9 — системный стоп без операции в исполнителе, PM после `initialize()` (`stop_abort` поставлен), корень закрывается
  (`pm.stop()` на отдельном потоке, затем `close_root()`). Ребёнок со стопом 0,3 с выходит с exitcode 0,
  `_children_stop.result()` = `{"<имя>": True}`, 0 строк «ВЫЖИЛИ». Зависший ребёнок (без выхода) получает `terminating`,
  как сегодня (стадия 0 р.3 п.A).
