## Почему так + отвергнутое

- **Отдельный процесс-исполнитель («nginx» как процесс)** — отвергнут владельцем: исполнитель зовёт обработчики команд
  процесса и его объекты по ссылке; через границу процессов шёл бы только dict (Dict at Boundary) — `action` не перевезти.
- **Правка ядра `keyed_executor.py`** (публичный `stats()`, признак своего потока) — отвергнута решением владельца
  «1.9a без правок»: признак потока берётся из имён (D2), пробел интроспекции — явным списком `unavailable` (D6).
- **Новый модуль** — D1 (четыре контракт-теста и слой ради одного файла).
- **Позднее разрешение имени (при `handle_command`)** — отвергнуто: ошибка конфигурации всплыла бы на первой команде в
  бою, а не при регистрации; подмены имени нет (D2) — позднее связывание ничего не даёт.
- **Менеджер через `managers=` CM** — отвергнуто: словарь становится реестром наблюдателей миксина (D4).
- **Без записи в области (полагаться на `_WorkersStop`)** — отвергнуто: исполнитель остановится, но очередь получит отказ
  только в фазе 2 после всех `request_stop` записей `work` (Факт; R9, И6).
- **Владение зарегистрированными `Stoppable`** — отвергнуто: второй владелец рядом с регистрирующим (I1 1.9b).
- **Ключ `executors` наверх `proc_dict` (как `workers`)** — отвергнуто: путь `config` уже есть (`plugins`), лишняя ветка в
  `build()` и в `ProcessModule`.

## Hazard-тесты (автор)

**Hazard-тесты автора (H1–H6):** H1 `create` на потоке A параллельно `shutdown()` на B (×50): либо исполнитель создан и
остановлен, либо `RuntimeError`; после — 0 живых потоков `"_keyed-"`, дедлайн 2 с; H2 ответ операции исполнителя
доставлен через роутер до закрытия `transport` (флаг в подменённом `command_manager.shutdown` — `False` в момент `reply`);
H3 PM-образно: `request_stop()` + `join_until(now+1)` исполнителя напрямую, затем закрытие области → ≤ 0,05 с, `reply`
каждой операции ровно раз, исключений нет; H4 после `run()`-образного `worker_manager.start_all_workers()` потоков
`"_keyed-io-"` ровно `max_workers`; H5 `describe()` ×1000 параллельно с `create`/`register` → 0 `RuntimeError`; H6 `register`
под именем созданного исполнителя → `ValueError`, `get` отдаёт созданный.
