**Goal:** ребёнок, которому штатно нужно больше (или меньше) общего окна, получает своё окно на всех путях стопа;
вложенность «ребёнок < PM < спавнер» сохраняется по построению. **Не носитель возврата робота домой** — это команда
устройству до `process.stop` (полоса Р2, T5.3e, CTO D3 (3)); здесь только ссылка.

**DESIGN:**
- Ключ конфига процесса `stop_window_s: float | None` (сырой конфиг `_process_configs[name]`; типизированный
  `GenericProcessConfig` ключ отбрасывает — ADR-PMM-035 (г); шаг 0 сверяет путь рецепт → топология → конфиг и, если
  схема топологии режет ключ, добавляет поле там). Нет ключа — окно = `stop_process_timeout` (одиночный стоп) /
  `pm_graceful_s` (системный), как сегодня.
- Ключ конфига PM `max_stop_window_s` (по умолчанию = `shutdown_timeout`). Окно ребёнка больше потолка → потолок +
  один WARNING при регистрации (`topology.apply`, создание из конфига) с именем и обоими числами.
- `ChildProcessStop`: окно на имя (`deadlines: dict[str, float] | None`); `terminate` каждому — по своему окну, общий
  `join_until` группы — до максимума. Одиночный стоп — окно ребёнка.
- Словарь `stop_budget` ребёнку (`process_registry.py:172-173`, `setdefault`) — из его окна: `stop_budget(stop_window_s)`.
- Внешние сроки — из потолка: корень PM `pm_total_s + infra_s` от `max(shutdown_timeout, max_stop_window_s)`; спавнер
  — `outer_s` от того же числа (читает `max_stop_window_s` из конфига оркестратора при спавне). Арифметика ADR-PMM-031
  не меняется, меняется только аргумент.
