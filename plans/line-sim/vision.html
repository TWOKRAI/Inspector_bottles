line_sim · описание продукта · на согласование

Виртуальная линия

Отдельный сервис, который притворяется участком производственной линии: лента везёт объекты, датчик срабатывает, «камера» отдаёт кадры из нарисованной сцены, а инспектор и робот разговаривают с ним по Modbus — тем же протоколом, что с железом. Прототип не знает, что мир ненастоящий.

универсальный движок · первый пресет — буквы под реальный стенд SCARA · v1 — встроенная в прототип сборка · ред. 4 (все решения закрыты), 2026-08-13

01Сцена

Окно симулятора — это сцена: лента с фоном из фотографии реальной ленты (зациклена для правдоподобия), по ней едут объекты со скоростью виртуального ПЧ. Два пресета вида — сверху (диски с буквами — первый: этот проект живёт на реальном стенде со SCARA, симулятор будет с чем сверять) и сбоку (бутылки — следующий проект; слои — из наработок Create_bottles).

ЛЕНТАФон-луп и честная скорость

Фон — загружаемая картинка ленты, зацикленная. Скорость берётся из виртуального ПЧ по Modbus и крутит тот же энкодер, который читает робот, — константы трекинга общие с прошивкой. Инспектор может притормозить или остановить конвейер — как на железе.

ДАТЧИККак в боевом тракте — зрением

Уточнено кодом: в рецепте букв «объект пересёк линию» детектится зрением (line_filter по кадру), физического Modbus-датчика на железе нет. v1 честно повторяет это: line_filter срабатывает на синтетических кадрах. Modbus-фотоэлемент добавится, когда появится в боевом рецепте.

КАМЕРАРамка вместо объектива

Прямоугольник на сцене, который двигаешь и растягиваешь мышью. Содержимое рамки уходит кадрами в прототип — тот выбирает «sim-камеру» в рецепте как обычный источник. Настраивается как настоящая: fps, размер кадра, цвет/моно — та же поверхность настроек, что у боевых камер. Поверх кадра — фотометрия из dataset_gen: блик, смаз движения, тень, баланс белого, гамма.

ПУЛЬТВкладка, не окно

Вкладка в GUI прототипа по образцу tabs/pipeline (MVP: tab + presenter): скорость, поток объектов, доля дефектов, пауза, «выпусти брак». Там же sim-диалог — две колонки «принято от инспектора ↔ ответила линия». Картинки сцены — в штатные дисплеи (display_module, DisplaysTab / PreviewWindow), свои виджеты не пишем.

02Объект — группа слоёв, а не картинка

Движок универсальный: «объект» — это набор спрайтов-слоёв с правилами. Бутылка — тара, наполнение, этикетка, крышка, кольцо. Диск с буквой — диск и буква. Любой новый продукт — новый пресет из картинок, без правки движка.

Каждый слой в пресете помечен одним из режимов: статика — одинаковый у всех объектов; аугментация — варьируется в заданных пределах (уровень налива, сдвиг этикетки, оттенок); дефект — вариант-брак, включается вероятностью или по команде с пульта («выпусти брак сейчас» — и смотришь, поймает ли инспектор).

Главный выигрыш слоёв: симулятор собирал объект сам — значит, он знает правду. Каждому объекту прилагается паспорт: класс, угол, какие дефекты. Вердикты инспектора можно сверять с истиной автоматически и получать матрицу ошибок — «инспектор пропустил 2 недолива из 40» вместо «вроде работает».

Спрайты — в том числе из реальных фото. Закольцовка с прототипом: снял объект боевой камерой → вырезал в RGBA-эталон → положил в каталог пресета — лента ездит с настоящей фактурой (блики, износ), без вложений в фотореализм. Для дисков этот конвейер уже есть (dataset_gen/tools/cut_real_disks: детекция круга → вырез → приведение к вертикали). Каталог спрайтов общий с генератором датасетов — одна съёмка кормит и симулятор, и обучение.

03Петля целиком

В v1 процессы линии поднимаются в топологии прототипа той же механикой SystemLauncher → ProcessManager — ещё один процесс рецепта, как devices или gui. Автономное мини-приложение с собственным окном — отложено: фасад с разъёмами делает его сборкой «потом», а не переделкой. Точность мира — примерная, и это осознанно; ключевой измеряемый инвариант: один объект → одна команда роботу, а не «два задания на одну деталь».

Рецепт — один на два мира. Симулятор читает тот же YAML, что выбран в инспекторе: рецепт hikvision_letter_robot — на ленте буквы-диски; рецепт бутылок — бутылки. Сим-часть рецепта опциональна: без неё рецепт остаётся чисто боевым, с ней инспектор и линия гарантированно говорят об одном продукте. В рецепте при подмене меняются две вещи: источник кадров — «sim-камера», адреса устройств — на симулятор. Остальной прототип о подмене не знает.

04Один движок — две сборки

Ядро одно и не знает, куда воткнуто. v1 — сборка в прототипе: вкладка, штатные дисплеи, source-плагин. Автономное окно — отложено, но фасад с разъёмами держит его возможным: каждая способность выведена на свой разъём, сборки отличаются только адаптерами.

Принцип: сначала готовое — framework, Services, Plugins, прототип. Если нужное линии заперто внутри прототипа — оно выделяется в сервис/плагин для переиспользования (продолжение carve-out Phase 4–5), а не копируется. Стартовый набор уже в репозитории:

06Чем продукт НЕ является

  • Не 3D и не физика. Спрайты на плоскости; коллизии, освещение по лучам, падения — нет. Геометрию движения проверяет Virtual Robot в DRAStudio.
  • Не фотореализм. Задача — правдоподобная картинка для тракта детекции, а не рендер.
  • Не генератор датасетов. Это делает dataset_gen; линия его переиспользует, а не дублирует.
  • Не Rust. Композиция ROI ~1–2 Мп на 30 fps — рядовая задача OpenCV/NumPy; переписывать не из чего. Если когда-то упрёмся — узкое место одно (сборка кадра), его и ускорим точечно.

07Что решено — и что осталось

Решено владельцем (2026-08-13):

  • Первый пресет — буквы-диски (вид сверху): проект живёт на реальном стенде со SCARA, симулятор будет с чем сверять. Бутылки — следующий проект; движок универсален с первого дня.
  • v1 — встроенная в прототип сборка: вкладка управления по образцу tabs/pipeline, картинки — в штатные дисплеи, кадры — через source-плагин. Своё автономное окно — отложено, разъёмы фасада сохраняются.
  • Запуск — механикой фреймворка: процессы линии в топологии прототипа через SystemLauncher, не отдельный скрипт.
  • Точность мира — примерная, достаточно. Ключевой измеряемый инвариант v1: один объект → одна команда роботу (не «два задания на одну деталь»).
  • Функция правды — в v1 (одобрена).
  • Виртуальная камера настраивается: fps, размер, цвет — как настоящая.
  • Рецепты общие с инспектором: выбранный рецепт определяет и сцену.
  • Спрайты из реальных фото: боевая камера → вырезка RGBA → каталог пресета (для дисков конвейер готов).
  • Максимум переиспользования: сначала готовое из framework / Services / Plugins; нужное, но запертое в прототипе — выделяется в сервис/плагин, не копируется.
  • Робот — отдельным процессом (robot_comm как есть); общая с линией — только правда о ленте (один энкодер) через канал.
  • Сим-секция — в том же YAML, опциональная; боевые рецепты без неё валидация не трогает.
  • ПЧ и датчик — через Modbus-фасад там, где боевой тракт ходит по Modbus: проверяется тот же код, что поедет на железо.
