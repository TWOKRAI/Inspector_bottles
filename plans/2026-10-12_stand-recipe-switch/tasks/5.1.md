- **Статус:** [PENDING] (после 4.2 и device-tree-recipe Task B2) · **Level:** Senior · **Assignee:** teamlead (IPC из потока работы)
- **Goal:** устройства — часть транзакции смены, которую ведёт PM. Сегодня GUI шлёт `device_sync_set` ДО apply,
  fire-and-forget, без отката (`recipes/presenter.py:410-425`, карта «Устройства»). После задачи: работа смены после
  `applying` шлёт синхронизацию запросом с ожиданием ответа, ждёт подключения устройств рецепта до таймаута из конфига,
  кладёт итог в `system.switch.job.result`; при откате apply возвращает устройства прошлого рецепта.
  Порядок «носители раньше мостов» внутри `device_sync_set` — **device-tree-recipe B2 (R-10)**, здесь не правится.

- **Steps:**
  1. Запрос к `devices` — из потока работы (1.2), никогда с потока сообщений PM: там запрос даёт
     `RouterReentrantRequestError`. Таймаут ответа и ожидания подключения — ключи конфига PM, дефолты в ADR 4.1.
  2. Ожидание подключения — по `devices.state.<id>.conn` устройств рецепта: `connected` или `error`, иначе таймаут.
  3. Итог в `result.devices` = `{connected: [...], failed: [...], pending: [...]}`; не все `connected` → `degraded`
     (по 4.1 Q7). Откат apply → `device_sync_set` прошлого рецепта (origin прошлого).
- **Acceptance criteria:**
  - [ ] Подменённый `devices` отвечает за 0.2 с, оба устройства `connected` через 1 с: фаза `devices` закрыта,
        `result.devices.connected == ["robot_main", "vfd_belt"]` (сортировка), `degraded == []`.
  - [ ] `devices` не отвечает: через таймаут из конфига фаза закрыта, `degraded` содержит `"devices"`, смена не откатана.
  - [ ] Apply откатан: следующая команда к `devices` — синхронизация с origin прошлого рецепта и его списком.
  - [ ] Рецепт без `devices:` → хук даёт `None`, фаза пропущена (в истории фаз отмечена `skipped`).
  - [ ] Тест-ловушка: вызов запроса с потока сообщений PM поднимает исключение в тесте (страж стоит).
  - [ ] Break-injection: убрать ожидание ответа — тест 1 красный.
