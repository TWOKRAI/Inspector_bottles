## Решения лида (не пересматривать)

1. **Миграция реестра D1 — предупреждение, не копирование и не прежний путь.** Прежний путь (`parents[4]`) на машине владельца может держать настоящий `devices.yaml` (`/Users/twokrai/Project_code/data/devices.yaml`). После правки плагин читает путь внутри репозитория; если там файла нет, а на прежнем месте есть — один `WARNING` с обоими путями («перенесите вручную»). Автокопирование отвергнуто: оно размножило бы общий реестр по каждому worktree — тот самый дефект. Прежний путь как запасной отвергнут: он сохраняет дефект.
2. **D2 — область по корню checkout, не по cwd.** К имени файла добавляется короткий отпечаток каталога пакета `multiprocess_framework` (родитель пакета, `resolve()`); не `parents[N]` от файла, не `os.getcwd()` (cwd у детей и у скриптов разный). Дети наследуют путь через env (`system_launcher._prepare_pid_registry` кладёт его в `MULTIPROCESS_PID_FILE` / `INSPECTOR_PID_FILE`), поэтому единообразие имени между процессами обеспечено существующим механизмом.
3. **Реестр прежнего имени `<app>_system_pids.jsonl` (до D2) не убиваем.** В нём могут быть живые процессы соседнего checkout — убить их = воспроизвести дефект. Цена: хвосты аварийного запуска старой версии один раз остаются до ручной чистки. Записано в `DECISIONS.md`.
4. **Явная env-ручка `MULTIPROCESS_PID_FILE` / `INSPECTOR_PID_FILE` остаётся сильнее дефолта** (стенды соседей уже ставят её).
5. **Логи реапа называют жертв** (`pid` и имя процесса): в smoke осталось неизвестным, чьи два процесса убиты; счётчик без имён не диагностируется.
