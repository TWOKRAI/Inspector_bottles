# D1t — слепая приёмка пути реестра устройств

Только критерии. `D1.md` (DESIGN) тестеру не читать. Пишешь до кода, тесты ожидаемо красные там, где указано.

- **Файл:** `Plugins/hub/device_hub/tests/test_registry_root_acceptance.py` (новый).
- **Запрещено читать:** `plans/r2-env-isolation-defects/**`, `docs/reviews/**`, `docs/reports/2026-11-15_R2_lane.md`, ветку разработчика. Можно читать: `Plugins/hub/device_hub/plugin.py` (публичные имена и `_resolve_registry_path`, `DeviceHubPlugin.configure`), существующие тесты `test_device_hub_plugin.py` (как собран плагин на `make_ctx`), `DECISIONS.md`.
- **Правила:** ожидаемые значения — литералы; НИКОГДА не писать в настоящий `<репо>/data/` и не читать настоящие `devices.yaml` владельца. Корень репозитория в тестах — литерал `Path(<модуль plugin>.__file__).resolve().parents[3]` (в тесте, не из кода под тестом).
  Каждый тест снимает `INSPECTOR_DATA_DIR` (`monkeypatch.delenv(..., raising=False)`).
- **Наблюдаемое:** (а) значение `_resolve_registry_path(...)` (его уже импортируют существующие тесты); (б) вызовы `ctx.log_warning` (в `make_ctx` ctx — мок: `caplog` ничего не увидит; смотреть `ctx.log_warning.call_args_list`, пути в тексте — `str(Path)`).
  Для проверок предупреждения: плагин собирается через `configure`; «корень проекта» подменяется на `tmp_path` через `monkeypatch.setattr(<модуль plugin>, "_PROJECT_ROOT", tmp_path / "repo")` — иначе прежнее место совпало бы с настоящим файлом владельца.
  Реестр создаётся плагином при первом сохранении, не в `configure`: «реестр существует» в тестах = файл создан тестом заранее.

## Критерии

- **B1** (красный до кода). Без `INSPECTOR_DATA_DIR`: `_resolve_registry_path("data/devices.yaml") == Path(<модуль plugin>.__file__).resolve().parents[3] / "data" / "devices.yaml"`.
- **B2** (красный до кода). Тот же результат `.is_relative_to(<корень репозитория>)` — истина.
- **B3.** С `INSPECTOR_DATA_DIR=<tmp>/data`: `_resolve_registry_path("data/devices.yaml") == <tmp>/data/devices.yaml`.
- **B4.** Абсолютный путь возвращается как есть.
- **B5** (красный до кода). `_PROJECT_ROOT` = `<tmp>/repo`; прежнее место `<tmp>/data/devices.yaml` — файл есть, нового `<tmp>/repo/data/devices.yaml` нет; `configure` с `registry_path: data/devices.yaml` → ровно ОДИН вызов `ctx.log_warning`,
  текст которого содержит `str(<tmp>/repo/data/devices.yaml)`, `str(<tmp>/data/devices.yaml)` и слово «вручную»; прежний файл по содержимому и mtime не тронут; `<tmp>/repo/data/devices.yaml` не появился.
- **B6.** То же, но на прежнем месте только каталог `<tmp>/data/robot/` (файла реестра нет) → одно предупреждение.
- **B7.** Новый реестр существует (`<tmp>/repo/data/devices.yaml` создан тестом) → предупреждений нет. Задан `INSPECTOR_DATA_DIR` → нет. Абсолютный `registry_path` → нет. Прежнего места нет вовсе → нет.
- **B8.** Второй `configure` (после shutdown первого) при том, что первый создал реестр, → предупреждений нет.
- **B9.** Сбой проверки прежнего места (`OSError` при обращении к прежнему пути, подставленный через `monkeypatch`) не роняет `configure`: плагин доходит до READY.
