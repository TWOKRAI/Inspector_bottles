  Корень репозитория в тесте = `Path(<модуль плагина>.__file__).resolve().parents[3]` (литерал в тесте, не из кода под тестом).

## Критерии

- **B1.** Без `INSPECTOR_DATA_DIR`, при `registry_path: "data/devices.yaml"` (относительный) после запуска плагина реестр создан ВНУТРИ корня
  репозитория: `<корень>/data/devices.yaml`; каталог робота — `<корень>/data/robot`. (Подготовка: чтобы не писать в настоящий `data/` репозитория,
  тест подменяет корень проекта через `monkeypatch` на `tmp_path`-копию дерева ТОЛЬКО если иначе нельзя; предпочтительно проверять
  `resolved` через публичный эффект — путь, который плагин отдаёт в регистр/лог. Если без записи в репозиторий не обойтись — создать
  файлы в `<корень>/data/` и удалить в `finally`.)
- **B2.** Путь реестра НЕ лежит выше корня репозитория: ни один родитель `<корень>.parent` не фигурирует как каталог `data/devices.yaml`.
- **B3.** С `INSPECTOR_DATA_DIR=<tmp>/data` и `registry_path: "data/devices.yaml"` реестр — `<tmp>/data/devices.yaml`, каталог робота — `<tmp>/data/robot`.
- **B4.** Абсолютный `registry_path` — ровно он, каталог робота — рядом.
- **B5.** Предупреждение: `INSPECTOR_DATA_DIR` не задан, нового реестра нет, а по прежнему месту (`<корень>.parent>/data/devices.yaml`) файл есть →
  ровно ОДНА запись уровня WARNING, содержащая оба пути и слово «вручную»; прежний файл по содержимому и mtime не тронут; нового файла
  не появилось копией прежнего.
- **B6.** Новый реестр есть → предупреждений нет. Задан `INSPECTOR_DATA_DIR` → предупреждений нет.
- **B7.** Прежнего файла нет и нового нет → предупреждений нет (чистая установка), реестр создан внутри корня.
