- **Запрещено читать:** `plans/r2-env-isolation-defects/**`, `docs/reports/2026-11-15_R2_lane.md`, ветку разработчика. Можно читать: публичные функции

- **Правила:** ожидаемые значения — литералы; жертва — настоящий `subprocess` (`sleep`), не мок; второй checkout имитируется двумя РАЗНЫМИ копиями пакета
  `multiprocess_framework` в разных каталогах (импорт через `subprocess` с разным `PYTHONPATH`) — не подменой внутренних функций; temp изолирован
  как в существующих тестах; каждый тест снимает `MULTIPROCESS_PID_FILE` / `INSPECTOR_PID_FILE`, `MPF_APP_NAME` задаёт явно.

## Критерии

- **C1.** Два checkout одного приложения (`MPF_APP_NAME=AppOne`) → `pid_file_path()` двух разных каталогов пакета возвращает РАЗНЫЕ пути в одном temp; один и тот же каталог — один и тот же путь при повторном вызове
  (и из дочернего процесса с тем же `PYTHONPATH`).
- **C2.** Имя файла начинается с имени приложения (`AppOne`) и кончается `_system_pids.jsonl`.
- **C3.** Сосед выживает: процесс-жертва записан в реестре checkout A (`register_self` из дочернего процесса A); `reap_and_reset()` из checkout B → жертва ЖИВА, файл A не изменён.
- **C4.** Своё реапится: жертва записана в реестре checkout A; `reap_and_reset()` из A → жертва мертва (≤ 5 с), реестр A пуст, возврат ≥ 1.
- **C5.** Файл прежнего неразделённого имени `AppOne_system_pids.jsonl` в temp с записью живой жертвы: `reap_and_reset()` (любой checkout) → жертва ЖИВА, файл на месте и не пуст.
- **C6.** То же для приложения `inspector`: файл `inspector_system_pids.jsonl` с живой жертвой → после `reap_and_reset()` жертва жива, файл на месте.
- **C7.** Лог: убитый процесс называется в логе — строка содержит его pid (литерал из `Popen.pid`) и имя процесса (`sleep`); одна строка на жертву, плюс итоговый счётчик прежнего вида «убито N».
- **C8.** Явная ручка `MULTIPROCESS_PID_FILE=<файл>` по-прежнему сильнее дефолта; `INSPECTOR_PID_FILE` — слабее `MULTIPROCESS_PID_FILE`.
