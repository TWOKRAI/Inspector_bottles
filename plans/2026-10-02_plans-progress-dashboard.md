## Формат задачи (эталон)

**Раздел:** заголовок `#{2,6}` с необязательным номером (`3.`, `2)`), текст которого **начинается** с `Порядок выполнения` / `Execution order` или **равен** `Порядок` (регистр не важен); так `## Порядок и окна` (framework-architecture-rework) не раздел. Раздел кончается на следующем заголовке уровня ≤ уровня раздела. Раздел ищется только в `plan.md` плана.
**Пункт:** `- Task <id>: название [СТАТУС] (после <id>)`; допустим префикс `**` перед `Task`. Пункт тянется до следующего пункта, пустой строки или заголовка;
**строки-продолжения принадлежат пункту** (статус может стоять на продолжении: `line-sim/plan.md:486–487`).
**Статус:** сначала из текста пункта снимаются код-спаны (`` `…` ``): статус внутри обратных кавычек — цитата, не статус. Затем — первая группа `[...]` или `**[...]**`, содержащая слово набора; слово может стоять не первым (`[5.3a DONE 2026-09-23, …]`), но не примыкает к букве, `_` или `-` (`[DONE-ish]` → не статус). Группа идёт до парной `]` с учётом вложенности (`[DONE … [контракт](…)]`).
**Набор:** `PENDING`, `IN PROGRESS`, `DONE`, `BLOCKED`, `DEFERRED`, `SUPERSEDED`; старые `SKIPPED`/`CANCELLED` → `SUPERSEDED`.
**Хвост разрешён у любого статуса:** `[DONE 2026-10-02 — \`hash\`; числа]`, `[BLOCKED, частично]`, `[DEFERRED — после 4.1`. Дата вне скобок (`**[DONE] 2026-08-31**`) читается.
**Один маркер на пункт:** `- [x]` рядом с `[DONE]` — то же дублирование. `~~Task X.Y~~` и «СНЯТА» → `SUPERSEDED`. Пункт без слова набора → `?`.

**Id задачи:** `ID = [A-Z]{0,2}[0-9]+[a-z]?(?:\.[0-9]+[a-z]*)?(?:-[a-z0-9]+)*` — покрывает `1.3`, `1.3a`, `1b.2a`, `1b.2b-pre`, `1.3h-c-fix`, `T1`.
**Извлечение из строки:** `Task\s+(ID)(?=[\s:~*,;.]|$)` — хвостовая пунктуация и `~~` не входят в id. Id из таблиц карты (`T2.J2`, `T4.x`, `GATE-1`, `Ф7`) читаются только форматом таблицы.
**Зона разбора:** только пункты внутри раздела. `- **Task …` вне раздела — ссылки, не задачи (layer-render `plan.md:134,136`).
**Вложенность:** родитель без маркера (`- Task 1b.2: **РАЗДЕЛЕНА…**`) не считается задачей; дети с отступом считаются.

**Набор задач плана (N1, одно правило для дашборда и ledger):** если в разделе есть хотя бы один пункт `Task` — набор = **только эти пункты**. Заголовки `### Task` и файлы `phase-*`
дают тело и `STATUS_CONFLICT` для id из набора, но **новых id не добавляют** (старые `3.3`, `4.3`, `4.4` из прежней нарезки `layer-render` не попадают в набор). Раздела нет
или в нём нет пунктов → набор из заголовков `#{2,6} Task <id>`, затем из таблицы карты (`✓`), затем из `tasks/<id>.md`.
**Задача из заголовка** (плана без списка): статус — слово набора в `**Статус:**` её тела; иначе первая группа со словом набора в строке заголовка; иначе `DONE`, если все чекбоксы тела отмечены (как `is_task_closed` ledger); иначе `PENDING`. `?` бывает только у пункта списка.
**Таблица `✓`:** читаются файлы `tasks.md`, `tasks-*.md` и `plan.md`; задача — строка, первая ячейка которой `[✓ ]*T<цифры>(.<буквы-цифры>)?`, кроме суффикса `.x` и строк `GATE-*`/`Ф*`; `✓` = `DONE`, иначе `PENDING`.
**Приоритет двух статусов одной задачи:** пункт списка побеждает `**Статус:**`; расхождение — `STATUS_CONFLICT` (сейчас такие есть у `layer-render`: 1.1, 1.2, 1.3, 2.1, 5.3 — замер `developer`; ревью нашло четыре, 1.2 настоящий: `phase-1.md:93` PENDING против DONE в списке).
**Процент** = `DONE / (всего − DEFERRED − SUPERSEDED − ?)`; `?` — не done, не pending, не в знаменателе, но в линте. Рядом всегда `N из M`.

**Охват страницы и порядок:** все планы в `plans/` (кроме `QUEUE.md`, `README.md`, `queue/`, `_archive/`) + архив. Порядок на странице: строки `ORDER.md` §4.1 по порядку таблицы →
§4.2 → §4.3 (закрытые, не в архиве) → планы вне `ORDER.md` (полоса «—», по имени) → «Архив». Связь плана с `ORDER.md` — по имени файла (basename), не по ссылке:
после `close` ссылки устаревают.

## Интерфейс (чтобы тестер писал вслепую)

`python scripts/plans_progress.py [--root DIR] [--order PATH] [--json] [--html PATH] [--check] [--baseline PATH] [--sync-order]`

- `--root DIR` — каталог с `plans/` и `plans/_archive/` (фикстура без записи в репозиторий); по умолчанию корень репозитория.
- `--order PATH` — `ORDER.md`; по умолчанию `<root>/plans/queue/ORDER.md`; нет файла → полосы «—», не ошибка.
- `--json` → stdout, список: `{"plan": "<basename>", "path": "<rel>", "archived": bool, "lane": str|null, "tier": "4.1"|"4.2"|"4.3"|null, "done": int, "total": int, "dropped": int, "unknown": int, "tasks": [{"id","title","status","ref"}]}`.
  `total` — после вычета `dropped` (DEFERRED+SUPERSEDED) и `unknown`; `ref` — первый хеш в обратных кавычках из хвоста пункта или `null`.
- `--html PATH` — по умолчанию `data/plans_progress.html`. Разметка: `<details class="plan" data-plan="<basename>">`, внутри `<summary>` с названием и `<progress value max>`; ячейка на задачу — `<span class="cell" data-status="done|pending|in_progress|blocked|deferred|superseded|unknown">`; архив — `<details id="archive">`.
- `--check` — печатает находки; exit 1 при блокирующих, не вошедших в базу; иначе 0. `--baseline PATH` — файл строк `<план>:<КОД>` (для `UNKNOWN_STATUS` и `DUP_ID` — `<план>:<КОД>:<id>`, чтобы новая находка внутри уже известного плана не пряталась); находка из базы не блокирует (храповик: база только убывает).

| Находка | Блокирует | Когда |
|---|---|---|
| `NO_TASKS` | да, только для планов §4.1 | найдено 0 задач; для §4.2/§4.3/вне `ORDER.md` — информационная |
| `UNKNOWN_STATUS` | да, только для планов §4.1 | пункт `Task <id>` без слова набора; для остальных — информационная |
| `DUP_ID` | да | один id у **двух пунктов списка** одного плана; дубль заголовков между файлами — информационная `DUP_HEADING` |
| `NO_STATUS_MARK` | нет | задача из заголовка получила `PENDING` по умолчанию (нет `**Статус:**`, группы `[...]` в заголовке и чекбоксов): цифра может быть занижена. Замер 2026-10-02: `transport-single-policy` 0/31, `letters-retrain` 0/4, `frontend-constructor` 0/24. В `--json` — `unmarked`, на странице чип «⚠ N без отметки» |
| `STATUS_CONFLICT` | нет | пункт списка и `**Статус:**` расходятся |
| `NO_DATE_IN_NAME` | нет | `close` не примет (54 из 59 планов) |
| `ALL_DONE_NOT_ARCHIVED` | нет | в наборе нет `?` и `PENDING`/`IN PROGRESS`/`BLOCKED`, есть хотя бы один `DONE`; план не в архиве (допустимо `DONE` + `DEFERRED`) |

**Храповик вместо «чинить чужие планы».** Находки, которые сегодня блокируют (оценка ревьюера: 25 `NO_TASKS`, 27 `UNKNOWN_STATUS` — до правил продолжений, хвостов и «Задачи из заголовка»),
записываются в `plans/queue/progress-baseline.txt` при Task 1.1 (прототип teamlead: на §4.1 `NO_TASKS` — 1 план, `UNKNOWN_STATUS` — от 1 до 14 строк в зависимости от правила для заголовочных задач; после правила «Задача из заголовка» число падает, замер — в итоге 1.1); `validate.py` краснеет только на **новую** находку. Владельцы планов убирают строки из базы при касании.
Литерал приёмки: `--check --baseline plans/queue/progress-baseline.txt` на SHA сдачи Task 1.1 даёт exit 0; число строк базы и список — в итоге задачи.

## Решения по вопросам слепого тестера (лид, 2026-10-02)

Тестер (128 тестов, `red/plans-progress` `9f948a233`) вынес десять мест, где текст плана допускал две трактовки. Решено:

1. **Имя плана** в `--json` (`plan`), `data-plan` и ключе базы — basename **без** `.md` (`2026-10-02_x` для файла и каталога). Тесты нормализуют суффикс, реализация обязана его снимать.
2. **Статус в JSON** — каноническое слово набора в нижнем регистре с `_`: `done|pending|in_progress|blocked|deferred|superseded|unknown`.
3. **Строка находки в `--check`:** `<КОД> <план>[:<id>] <blocking|info> — <текст>`; информационные находки печатаются обязательно.
4. **`lane`** для плана, которого нет в таблицах `ORDER.md`, и для «—» — `null`.
5. **Источники набора задач** (резервная цепочка): первый непустой из «пункты раздела порядка» → «заголовки `#{2,6} Task`» → «таблица `✓`» → «`tasks/<id>.md`»; объединения нет. Остальные источники дают только тело и статус для id из набора.
6. **`- [x]` рядом с `[DONE]`** читается как один маркер (`done`), находки нет; `- [ ]` рядом с `[DONE]` — `STATUS_CONFLICT`.
7. **Незакрытая группа** `[DEFERRED — после 4.1` (без `]`, `line-sim/plan.md:619`) идёт до конца пункта и читается как статус.
8. **«Светлая и тёмная тема»** = `@media (prefers-color-scheme: dark)` в `<style>`.
9. **Причина отказа `close` для плана без даты:** проверка имени идёт **раньше** проверки «готов»; текст отказа не содержит `is not done`.
10. **Фикстуры c и d приёмки 1.0:** c — пункт с хвостом плюс заголовок с неотмеченным чекбоксом (пункт решает → `1/1`); d — пункт плюс заголовок с отмеченными чекбоксами.

Не покрыто тестером (закрывают teamlead и лид): `check_plan_gate` на `####`-задачах и id `1.3a`, сдвиг `contract_files_fingerprint`, зеркало источника и манифест, знаменатель `line-sim` на реальном снимке, `--sync-order`, Task 1.3, Фаза 2.

## Архив

`close` переносит план в `plans/_archive/<YYYY-Qn>/<имя>` через `git mv` (квартал — из даты в имени, не из даты закрытия). Одиночный файл переезжает целиком — задачи с маркерами остаются в нём;
каталожный план получает `SUMMARY.md`. Дашборд ищет план по имени в `plans/` и `plans/_archive/*/`, закрытые показывает в свёрнутой секции «Архив» с итоговым `N из M`.
Старые архивные планы (88 записей) в неизвестных форматах — строка без шкалы, без находки.
