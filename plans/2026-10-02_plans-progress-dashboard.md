## Цели

- Одна страница: заголовок плана, шкала `N из M · P%`, ячейка на задачу, раскрытие с задачами, следующим шагом и описанием.

## Формат задачи (эталон)

**Строка:** `- Task <id>: название [СТАТУС] (после <id>)` внутри раздела `## Порядок выполнения` (или `## Execution order`; заголовок `#{2,6}`).
**Статусы (закрытый набор):** `PENDING`, `IN PROGRESS`, `DONE`, `BLOCKED`, `DEFERRED`, `SUPERSEDED`; старые `SKIPPED`/`CANCELLED` читаются как `SUPERSEDED`.
У `DONE` допустим хвост: `[DONE 2026-10-02 — \`hash\`; числа приёмки]`; встречающийся `**[DONE] 2026-08-31**` (дата вне скобок) тоже читается.
**Один маркер на строку:** `- [x]` рядом с `[DONE]` — то же дублирование. `~~Task X.Y~~` и заголовок «СНЯТА» → `SUPERSEDED`.

**Id задачи:** `^[0-9]+[a-z]?\.[0-9]+[a-z]*(?:-[a-z0-9]+)*$` — покрывает `1.3`, `1.3a`, `1b.2a`, `1b.2b-pre`, `1.3h-c-fix`. Не-Task id из таблиц карты (`T2.J2`, `T4.x`, `GATE-1`, `Ф7`) читаются только форматом таблицы.
**Зона разбора:** только строки внутри раздела порядка. `- **Task …` вне раздела — ссылки, не задачи (layer-render `plan.md:134,136`).
**Вложенность:** родитель без маркера (`- Task 1b.2: **РАЗДЕЛЕНА…**`) не считается задачей; дети с отступом считаются.
**Приоритет двух статусов одной задачи:** строка списка в разделе порядка побеждает. `**Статус:**` в заголовке или теле задачи читается, только если у id нет строки списка;
расхождение — находка линта `STATUS_CONFLICT` (сейчас такие есть: 1.1, 1.3, 2.1, 5.3 у `layer-render` — `phase-*.md` отстали от списка).
**Процент** = `DONE / (всего − DEFERRED − SUPERSEDED − ?)`; `?` — строка, статус которой не понят: не done, не pending, не в знаменателе, но в линте. Рядом всегда `N из M`.

**Охват страницы:** все планы в `plans/` (кроме `QUEUE.md`, `README.md`, `queue/`, `_archive/`) + архив. `ORDER.md` §4 даёт только полосу, статус и «следующий шаг» по имени файла плана;
плана нет в `ORDER.md` → полоса «—». Поиск плана — по имени, не по ссылке: после `close` ссылки в `ORDER.md` устаревают.

## Интерфейс (чтобы тестер писал вслепую)

`python scripts/plans_progress.py [--root DIR] [--order PATH] [--json] [--html PATH] [--check] [--sync-order]`

- `--root DIR` — каталог, где ищутся `plans/` и `plans/_archive/` (фикстура без записи в репозиторий); по умолчанию корень репозитория.
- `--order PATH` — путь к `ORDER.md`; по умолчанию `<root>/plans/queue/ORDER.md`; нет файла → полосы «—», не ошибка.
- `--json` → stdout, список объектов: `{"plan": "<basename>", "path": "<rel>", "archived": bool, "lane": str|null, "done": int, "total": int, "dropped": int, "unknown": int, "tasks": [{"id","title","status","ref"}]}`; `total` — после вычета `dropped` и `unknown`.
- `--html PATH` — страница; по умолчанию `data/plans_progress.html`. Разметка: `<details class="plan" data-plan="<basename>">`, внутри `<summary>` с названием и `<progress value max>`; одна ячейка на задачу — `<span class="cell" data-status="done|pending|in_progress|blocked|deferred|superseded|unknown">`; секция архива — `<details id="archive">`.
- `--check` — печатает находки, exit 1 при блокирующих (см. таблицу), иначе 0.

| Находка | Блокирует | Когда |
|---|---|---|
| `NO_TASKS` | да | план из охвата, не `DEFERRED`-справочник, найдено 0 задач (исключения: `QUEUE.md`, `README.md`, `queue/`, `_archive/`) |
| `UNKNOWN_STATUS` | да | строка внутри раздела порядка с `Task <id>`, но без понятного статуса |
| `STATUS_CONFLICT` | нет | список и `**Статус:**` расходятся |
| `NO_DATE_IN_NAME` | нет | `close` не примет (54 из 59 планов) |
| `ALL_DONE_NOT_ARCHIVED` | нет | все задачи `DONE`, план не в архиве |
| `DUP_ID` | да | один id дважды в одном плане |

Литерал приёмки: на реальном дереве после Task 1.1 `--check` даёт exit 0 и N информационных находок; N фиксируется в итоге задачи. Если же там блокирующие находки — они чинятся в планах-владельцах, а не подавляются.

## Архив

`close` переносит план в `plans/_archive/<YYYY-Qn>/<имя>` через `git mv` (квартал — из даты в имени, не из даты закрытия). Одиночный файл переезжает целиком — задачи с маркерами остаются в нём;
каталожный план получает `SUMMARY.md`. Дашборд ищет план по имени в `plans/` и `plans/_archive/*/`, закрытые показывает в свёрнутой секции «Архив» с итоговым `N из M`.
Старые архивные планы (88 записей) в неизвестных форматах — строка без шкалы, без находки.
