**отстал от `main`**: `✓` у 5 задач, выполнено в `main` около 14 (`ORDER.md` §2 Р).

Обзор готовых решений (web-researcher, 2026-10-02): подходящего готового нет (Obsidian/org-mode требуют приложение, Backlog.md и Task Master

генерируется» — практика Log4brains, towncrier, git-cliff, `mdbook-goals`; в проекте так же работает `python -m scripts.sync`.

Решения владельца 2026-10-02: вывод — HTML-страница; формат — терпимый разбор + линт, планы массово не переписываем; отметка о выполнении
видна и в очереди, и в плане, без ручного дублирования.

## Архив (замечание владельца 2026-10-02: закрытые планы уходят в `_archive/`)

Проверено по `plans_ledger.py close` (стр. 1548–1650) и `plans/_archive/` (88 записей):

- `close` переносит план в `plans/_archive/<YYYY-Qn>/<имя>` через `git mv`. Одиночный файл переезжает целиком, **задачи с маркерами остаются в нём** —
  тот же парсер читает его по новому пути. Каталожный план дополнительно получает `SUMMARY.md`.
- **`close` требует имя `YYYY-MM-DD_…`** (иначе `ValueError`). Планы без даты в имени (`layer-render`, `gui-constructor`, `robot-protocol-v2`,
  `line-sim`…) закрыть нельзя, пока их не переименуют. Это находка линта (Task 1.1), а не повод переименовывать их сейчас.
- После переезда ссылки в `ORDER.md` устаревают (в `ORDER.md` §4 записано «ссылки чинить скриптом»). Дашборд не должен от этого ломаться.

Требования: план ищется по имени (basename) в `plans/` и `plans/_archive/*/`, а не по ссылке из `ORDER.md`; закрытые уходят в свёрнутую секцию
«Архив» с их итоговым `N из M`; старые архивные планы в неизвестных форматах не линтуются (показываются строкой без шкалы); план, у которого все
задачи `DONE`, но он ещё не в архиве, помечается «готов к архивации» (в ledger это находка `DONE_NOT_ARCHIVED`).

## Цели

- Одна страница: заголовок плана, шкала `N из M · P%`, ячейка на задачу, раскрытие с задачами, следующим шагом и описанием.
- Один эталон строки задачи с закрытым набором статусов; линт ловит строку, которую парсер не понял, и план с 0 задач.
- Отметка «сделано» пишется один раз (в плане); копия в очереди строится скриптом и сверяется в `validate.py`.

## Формат задачи (эталон, вход для Task 2.1)

`- Task X.Y: название [СТАТУС] (после N.M)` — статус из закрытого набора: `PENDING`, `IN PROGRESS`, `DONE`, `BLOCKED`, `DEFERRED`, `SUPERSEDED`.
У `DONE` допустим хвост после пробела: `[DONE 2026-10-02 — \`hash\`; числа приёмки]`. Один маркер на строку: `- [x]` рядом с `[DONE]` — то же дублирование.
Процент = `DONE / (всего − DEFERRED − SUPERSEDED)`; рядом всегда печатается `N из M`.

**Приёмка фазы 1 (вход для tester, без доступа к реализации):**
1. Каждый формат даёт верное `done/total` на своей фикстуре; ожидаемые числа — литералы в тесте.
2. `DEFERRED`/`SUPERSEDED` не в знаменателе; непонятый статус — `?`: не done и не pending, попадает в линт.
3. План с 0 найденных задач → `--check` возвращает ≠ 0 и называет план.
4. HTML: у каждого плана `<summary>` с названием и шкалой; число ячеек = число задач; нет внешних ресурсов.
5. Перестановка строк в таблице `ORDER.md` меняет порядок в HTML.
6. Архив: план из `plans/_archive/2026-Q4/` (фикстура) показывается в секции «Архив» с теми же `N из M`; ссылка на него из `ORDER.md` указывает на старый путь — страница не падает и не теряет план.
7. План без даты в имени → линт называет его и причину («`close` откажет»); архивный план в неизвестном формате → строка без шкалы, не ошибка линта.
8. Реальный прогон: у `layer-render` ровно 4 из 17 закрыты (1.1, 1.2, 1.3, 2.1 — `plan.md:84-89`), у `robot-protocol-v2` числа сходятся с `ORDER.md` §2 Р.
