# gui-service — доказательная база и связи

Часть плана [`plan.md`](plan.md). Здесь — то, на чём стоит контракт: проверенные по коду факты о

**Чего нет (новые механизмы, ровно четыре):**

| # | Разрыв | Где | Задача |
|---|---|---|---|
| G1 | **Паритет с встроенным GUI по fence-штампу.** Уточнено по `backend_ctl/AGENTS.md` («Чего драйвером проверить нельзя»): receive-мидлварь **дочернего** процесса на сокетном пути отрабатывает штатно — обхода нет; но `make_fence_stamp_middleware` висит только в дочерних `ProcessModule`, поэтому внешний отправитель не штампует `_fence`, и фильтр пропускает его «легаси-веткой» (`token.py:124-126`). Встроенный `GuiProcess` — дочерний, штампует; Пульт — нет. После рестарта бэкенда устаревшие команды Пульта не будут отсечены как stale | клиент: `RemoteCommandSender` штампует `_fence` из `capabilities` | 1.2 |
| G1b | **Хаб без судьи** — у ProcessManager receive-мидлвари нет **ни для кого** (`state.*`, `system_command`, `introspect.*`). Это не дефект сокета и не цель этого плана — существующее ограничение фреймворка (память `project_backend_ctl_socket_bypasses_mw`). Для Пульта по сети компенсируется токеном (2.2); «судья на хабе» — кандидат в полосу B, строка заведена в «Открытые вопросы». **Fence внешних клиентов** (2026-09-24, из Task 1.2): у детей нет PSR-записи Пульта (fail-open `token.py:134-136`), PM на relay перештамповывает `_fence` (`router_manager.py:544`) — отказ stale для Пульта возможен только здесь. Уточнение: receive-мидлварь у PM есть (`builtin_commands.py:3931`), её обходит сокетный канал (`router_manager.py:1509-1514`) | фреймворк | вне плана |
| G2 | Кадры не пересекают границу дерева штатно: SHM-ссылки уходят только процессу `gui` внутри дерева; по сети — ничего | мост + клиент | 1.3 (одна машина), 2.1 (сеть) |
| G3 | Сокет без аутентификации; README: «localhost dev-tool». Для `bind ≠ 127.0.0.1` — недопустимо | хост + клиент | 2.2 |
| G4 | Нет точки входа «GUI без дерева» и модели «N подключений» | Пульт | 1.4, 3.1 |
