### Task 0.1 — Сторожа четырёх дефектов (красные до ремонта)
**Level:** Middle+ · **Assignee:** tester (независимый, стадия 1)
**Goal:** Четыре теста с воспроизведениями из ревью S-8, красные на HEAD до ремонта.
**Files:** `multiprocess_framework/modules/process_module/tests/test_plugin_levels_defect_quartet_acceptance.py` (новый)
**Steps:**
1. Критерии тестеру (без указания причин и мест дефектов):
   Д1 — самозванец публикует в объявленное, но ещё не публиковавшееся имя владельца и уходит
   (`_do_shutdown`) → имени в дереве НЕТ ВОВСЕ (контроль-якорь: когда владелец публикует, лист
   есть с литералом);
   Д2 — гейт активен (`default_interval_sec` больше тика), владелец опубликовал на тике 1 →
   самозванец уходит → на тике 2 лист владельца ЖИВ (не `None`), контроль: без гейта тоже;
   Д3 — самозванец публикует ПОСЛЕ снятия владельца → снятие владельца всё равно доезжает
   (лист исчезает/становится `None` за ≤3 тика), контроль: без самозванца поведение то же;
   Д4 — плагин, чей `configure()` бросил, НЕ переходит в RUNNING и его `produce` не зовётся
   (якорь: сосед с целым configure переходит и зовётся).
2. Два тика минимум в Д2/Д3 (кванторные). Гейт в Д2 собирать честно — через `start()`-дорогу
   (боевая сборка `_build_telemetry_gate`, `process_heartbeat.py:97`); оговорки «собрать
   конструктором в обход» НЕТ — ревью S-8 записало, что гейтированная прод-дорога в приёмке не
   проверялась вовсе, и обходная сборка узаконила бы ту же дыру. Если стенд тестера `start()`-дорогу
   не достигает — это идёт в раздел «недостижимо на стенде», а Д2 закрывается авторским тестом
   по той же боевой дороге плюс живым съёмом в Task 0.2.
**Acceptance criteria:**
- [x] 7 тестов (4 сценария + 3 контроля), красные на HEAD: Д1, Д2', Д3 + находка про `SourceProducer`
- [x] в каждом — якорь существования; Д2/Д3 — ≥2 тика

**Что пошло не по плану (2026-08-19).** Первая редакция критерия Д2 была **недоспецифицирована**:
«ДРУГОЙ плагин, не владелец этого имени, завершается» тестер честно собрал как «чужой плагин
объявил и публиковал СВОЁ имя» — сценарий столкновения на одном имени не собирался вовсе, и тест
был зелёным. Дефект формулировки, не механизма. Уточнённый Д2' («самозванец публикует В ИМЯ
владельца, потом уходит; на тике, где гейт имя не пропускает, лист владельца жив») воспроизвёл
дефект с первого прогона. Тестер также раскрыл **нарушение изоляции** сам: `Read` не умеет
пропустить запрещённый докстринг внутри разрешённого файла — `plugins/base.py` прочитан целиком.
Урок записан в память тестера; в следующих фазах запрет на докстринги внутри читаемого файла
формулировать как «сигнатуры добывать через `inspect.signature`», иначе он неисполним.
**Тестеру запрещено:** `heartbeat/telemetry.py`, `heartbeat/process_heartbeat.py`,
`generic/plugin_orchestrator.py`, `plugins/base.py` (докстринги declare/publish),
`test_plugin_levels_hazards.py`, `test_plugin_levels_*acceptance.py`, `test_plugin_level_retraction_*.py`,
`DECISIONS.md`/`README.md` модуля, `plans/*`, `git diff/log/show`.
**Out of scope:** ремонт; правки существующих тестов.

### Task 0.2 — Ремонт четырёх дефектов
**Level:** Senior+ · **Assignee:** teamlead
**Goal:** Четыре точечные правки гранулярности и жизненного цикла; Task 0.1 зеленеет.
**Files:** `multiprocess_framework/modules/process_module/heartbeat/telemetry.py`,
`.../heartbeat/process_heartbeat.py`, `.../generic/plugin_orchestrator.py`
**Steps:**
1. `retract` (`telemetry.py:435-436`): откладывать снятие только для имён, где
   `metric_owners().get(name) == owner` (уходящий действительно владелец).
2. `publish` (`telemetry.py:364`): `_retracted.pop(name)` — только если публикатор владелец имени.
3. «Живое побеждает» (`process_heartbeat.py:806`): сверять с ДО-гейтовым владельческим снимком
   (публикации, отфильтрованные владением), а не с пост-гейтовым `state`.
4. Фаза 2 оркестратора (`plugin_orchestrator.py:183-185`): `_do_start` только для плагинов в
   состоянии READY; упавший на configure остаётся в списках ради shutdown (H-2 сохраняется),
   но не стартует.
5. Инъекции: род 1 — откат каждой из четырёх правок по отдельности (какие тесты гибнут —
   предсказать до прогона); род 2 — «снятие не откладывается никогда» и «фаза 2 стартует всех».
6. Обновить докстринг `retract` (диагональный случай «перехватчик уходит, владелец жив» —
   теперь рассмотрен) и ADR-PM-038 дополнением.
**Acceptance criteria:**

  №1 → 2 теста, №2 → 3, №3 → 1, №4а/№4б → по 1, род 2 «снятие не откладывается» → 24,
  «механизма нет вовсе» → 70, «гейт пропускает всё» → 11
- [x] живой съём ЧИСЛОМ: гейт закрыт → листа нет; открыт → `capture_fps 21.3`, `fps 21.4`,
  `frame_count 2021`; `stop_capture` → `capture_fps 0.0`; рестарт процесса (pid 17104 → 7384,

- [ ] **НЕДОСТИЖИМО НА СТЕНДЕ, критерий переписан:** «листья переходят в `None` за ≤3 тика» на

**Блокер итерации 1 (закрыт).** Правка №5, добавленная по находке сверх спеки, ушла шире находки:
фильтр `state == RUNNING` встал ДО разделения плагинов и срезал processing тоже. Для источника
неподнятость = «нечем производить», а для processing-плагина позиция в списке — штатная дорога
предохранителя (`SuspectTagStep` на его позицию + тег `inspection_status`). Воспроизведение:
с широким фильтром `_plugins = ['passthrough']`, тега нет вовсе; со списком оркестратора
`['critical_inspector', 'passthrough']`, проход 1 → `not_inspected`, проход 2 → `suspect`.
Полный гейт был при этом зелёным — дефект латентный (`error_critical_plugins` нигде не выставлен).
Урок записан: [[feedback_a_fix_on_a_finding_must_not_outgrow_it]].

(0.57 / 0.61 / 0.58 мкс при 3 / 50 / 500 объявленных против 1.14 / 4.52 / 33.35).
