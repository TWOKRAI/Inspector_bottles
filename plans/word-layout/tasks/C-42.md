# Task C-42: line_filter `zone_edge` — одно событие на один проход диска

- **Статус:** [OPEN 2026-10-26 — ветка `fix/line-filter-c42`] · **Level:** Middle+ · **Assignee:** developer <!-- lint-language: allow -->

TASK: C-42 — `zone_edge` не выдаёт второе событие на тот же диск при потере детекции внутри зоны и при старте плагина с занятой зоной   PLAN: plans/word-layout.md
ROLE: developer (красные тестера — до правки `plugin.py`)
CHAIN: lead (DESIGN) -> reviewer stage 0 -> tester -> developer -> injections -> reviewer

**Цель.** Режим `zone_edge` (`Plugins/filter/line_filter/plugin.py:124-150`) выдаёт событие на переходе
«зона пуста → в зоне есть точка». Защёлка `_zone_occupied` снимается после `rearm_frames` пустых кадров
(в рецептах робота `rearm_frames: 2`). Диск проходит зону 250 px примерно за 38 кадров (~6.6 px/кадр, оценка
из `plans/queue/defects.md` C-42, прогоном не проверена). Если детекция пропадает на 2 кадра внутри зоны,
защёлка снимается, и тот же диск даёт второе событие. После C-32 `word_layout` принимает его как новый
диск: робот едет за пустым местом, ячейка ложно занята, следующий настоящий такой же диск пропускается.
Второй путь к дублю — перезапуск процесса `line`, когда диск в зоне: состояние плагина теряется, первый
кадр — снова rising edge.

Module contract: **impl-only**. Порты, имена полей регистра и форма событий не меняются. Меняются
тексты `FieldMeta.info` у `max_match_distance`, `max_age`, `rearm_frames`, `mode` и поведение `zone_edge`.

## Решения владельца

- (2026-10-25, строка C-42 в `plans/queue/defects.md`) Чинить до 1.0.
- О1 (2026-10-26). Перезапуск `line`, когда зона занята: первый кадр **не** засчитывается. Триггер
  взводится, только когда плагин увидел пустую зону. Диск, вошедший в зону за время перезапуска,
  теряется — это допустимо: его ячейка остаётся свободной и примет следующий такой же диск. Дубль хуже.

## Решение (DESIGN)

Только режим `zone_edge`. Режимы `enter_zone` и `cross_line` не меняются.

1. **Память последнего места.** Новое состояние плагина `self._last_seen: tuple[int, tuple[float, float]] | None`
   — номер кадра и позиция, где плагин последний раз видел объект в зоне. На каждом кадре с непустым
   `in_zone` (и под защёлкой, и на rising edge) `_last_seen = (self._frame, p0)`, где `p0` — точка из
   `in_zone`, ближайшая к линии (тот же порядок, что у записи событий сейчас). Обновлять до решения о
   событиях этого кадра нельзя: сравнение в п. 2 идёт с прежним значением.
2. **Повторное появление — тот же объект.** На rising edge (зона была отпущена, в зоне есть точки)
   каждую точку `p` из `in_zone` (в порядке «ближе к линии — раньше») проверить:
   `_last_seen` есть, кадров без точки в зоне между `last_frame` и текущим кадром не больше `r.max_age`
   (`self._frame - last_frame - 1 <= r.max_age`, как `misses > max_age` у трекера, `tracker.py:97`) и
   `math.hypot(p - last_pos) <= r.max_match_distance` (как `d <= max_dist`, `tracker.py:70`) → это тот же объект: событие не выдаётся,
   одна строка `ctx.log_info` с позицией, расстоянием и числом кадров перерыва. Иначе — событие через
   `_record_pos(p)`, как сейчас. В обоих случаях `_zone_occupied = True`.
   Это та же ассоциация, что у трекера в других режимах (`tracker.py`: радиус `max_match_distance`,
   забывание после `max_age` кадров без совпадения). Новых регистров нет.
3. **Старт с занятой зоной (О1).** В `configure` — `self._zone_occupied = True`. Защёлку снимает то же
   правило: `rearm_frames` пустых кадров подряд. Отдельного правила для старта нет.
4. **Почему новый диск не теряется.** Новый диск входит с другого края зоны. Расстояние до места, где
   последний раз видели прежний диск: около `zone_width` (прежний вышел с другого края) или не меньше
   `zone_width / 2` (прежний пропал в середине и больше не появился). Условие корректной настройки:
   `max_match_distance` < `zone_width / 2` и > (смещение за кадр) × (самая длинная потеря детекции + 1).
   Записать его в `FieldMeta.info` у `max_match_distance` и в README плагина. Валидатор не добавлять.
5. **Рецепты робота.** В `multiprocess_prototype/recipes/letter_robot_sim.yaml` и
   `multiprocess_prototype/recipes/hikvision_letter_robot.yaml`, блок `config` у `line_filter`: добавить
   `max_match_distance: 60` (при ~6.6 px/кадр покрывает потерю до 8 кадров; 60 < 125 = `zone_width / 2`).
   `max_age` — по умолчанию (30). Других ключей рецептов не трогать.
6. **Тексты.** `FieldMeta.info`: `max_match_distance` — «радиус ассоциации; в zone_edge — радиус, в котором
   повторное появление после пустых кадров считается тем же объектом»; `max_age` — то же для zone_edge
   (окно памяти в кадрах); `rearm_frames` — добавить, что при старте защёлка закрыта; `mode` — без слова
   «БЕЗ трекинга» в смысле «без памяти позиции». README и STATUS плагина — абзац о zone_edge.

каждым сценарием — 2 пустых кадра (взвод по О1), если сценарий не про старт.
