## Протокол

0. Окно `heavy` — своё (`machine_gate.sh request/wait`), все запуски через `machine_gate.sh heavy inspector-bottles-55 …`.
1. S1 (запуск). Из корня worktree `lane-s-c5x`, в фоне, под гейтом: `Python313\python.exe multiprocess_prototype/run.py letter_robot_sim --headless`
   (env `BACKEND_CTL=1`). Ждать готовности (backend_ctl `get_status` / `system_overview`), записать PID лаунчера и дерево потомков
   (снимок процессов через Toolhelp32: pid, ppid, имя образа; корень — python313 лаунчера).
2. S2 (M1 на живом приложении). `taskkill /PID <лаунчер> /F` БЕЗ `/T`. Через 5 с — число живых потомков из снимка S1 (живость:
   `OpenProcess` + `GetExitCodeProcess == 259`, handle открыт, пока процесс жив) и `netstat -ano` по портам 8765/8766 (слушают ли).
   Проверка идёт, пока фоновая задача/сеанс агента жив (ловушка C-70: харнес добивает дерево после конца задачи).
3. S3 (запуск без убийства, M3). Второй запуск как S1; остановка `TaskStop` фоновой задачи (если у агента нет `TaskStop` — через `backend_ctl
   system_shutdown` и штатный код выхода 0 как T2 из C-70). Потомков после — 0.
4. S4 (штатный выход, п.3 DESIGN). Третий запуск; `system_shutdown` (graceful). → задача завершилась кодом выхода приложения (0) и живых
   потомков 0 (в т.ч. остатки job убиты закрытием handle).
5. Зачистка: после каждого сценария убедиться, что процессов цепочки нет (по PID из снимка), порты свободны.
