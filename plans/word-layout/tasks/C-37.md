**Цель.** В `letter_robot_sim.yaml` у `word_layout` `word_source: signal_2`, `target_word: ''`. Слово приходит двумя путями:
кнопка телефона (`phone.phone_camera.signal_2` → порт `word`, item `{"signal_2": <слово>, "data_type": "signal", …}`,
`Services/phone_gateway/plugin/plugin.py:355-367, 173-186`) и запись регистра (`register_update` →

регистра, конфиг не меняются; меняется только текст `FieldMeta.info` у `word_source`).

## Решение

DESIGN (решено лидом; стадия 0, раунд 1 — правки внесены):

### Состояние и приход слова

1. Состояние слова в плагине — два поля вместо `_latched_word`: `self._word: str` (действующее слово) и
   `self._word_src: str` (`"порт <word_source>"` или `"регистр"`). Новые поля учёта записей регистра:
   `self._reg_writes: int = 0` (число записей поля), `self._seen_writes: int`, `self._seen_reg_word: str`.
   В `configure` после `_init_register`: `_word = reg.target_word` и `_word_src = "регистр"`, если `target_word.strip()`,
   иначе `_word = ""`, `_word_src = ""`; `_seen_writes = 0`, `_seen_reg_word = reg.target_word`.
2. Приход записи регистра ловится признаками (а) и (в); (б) — путь, где работает только (в) (одна проверка в п. 3):
   - (а) подписка `ctx.registers.subscribe(self.name, "target_word", self._on_target_word_written)` в `configure`,
     только если `ctx.registers` не `None` и у него есть `subscribe`. Колбэк `def _on_target_word_written(self, _value)
     -> None` (`manager.py:260-261` зовёт `cb(value)`) — один оператор `self._reg_writes += 1`. Колбэк зовётся на
     каждый успешный `set_field_value`, в том числе тем же значением (О1, `manager.py:219-223`). Поток колбэка — поток
     команды CommandManager, не поток `process` (`pipeline_executor`): колбэк не трогает ассемблер, журнал и регистр.
     Подписанный менеджер хранить в `self._sub_rm`; повторный `configure` сначала отписывается от него.
   - (б) путь GUI `set_config` (`ProcessModulePlugin.cmd_set_config`, `base.py:1700-1727`) пишет `reg.apply_values`
     мимо наблюдателей — дефект framework **C-45**. Обхода в плагине НЕТ (владелец 2026-10-26, принцип 2): на этом пути
     приход виден только признаком (в) — по смене значения. Запись того же значения через `set_config` — после C-45.
   - (в) смена значения: `self._reg.target_word != self._seen_reg_word`. Нужна для регистра без менеджера
     (`ctx.registers is None`, тесты C-32 через `p._reg.update_field`) и для пути `set_config` (до C-45).
   Атрибуты `_subscribed = False`, `_sub_rm = None` — на уровне класса: оркестратор зовёт shutdown и плагину, у которого
   `configure` бросил (`plugin_orchestrator.py:163-172`).
   «То же слово» везде (п. 3, п. 4, `sig[0]` в `_ensure_assembler`) — по нормализации `" ".join(w.upper().split())`
   (как `geometry.parse_word`, `geometry.py:35`); `_word` хранится сырым. Иначе «мир» после «МИР» сбрасывает ячейки.
3. `_resolve_word(item)`, порядок внутри одного item: сначала регистр, потом порт.
   - Регистр: `writes = self._reg_writes`, затем `val = self._reg.target_word`. Если `writes != self._seen_writes`
     или `val != self._seen_reg_word` — приход: `_seen_writes = writes`, `_seen_reg_word = val`; если `val.strip()` —
     `_word = val`, `_word_src = "регистр"`; пустое (О2) — состояние слова не трогать.
   - Порт (только при непустом `word_source`): разбор значения как сейчас (`dict` → `word`/`value`); непустая строка —
     `_word = w`, `_word_src = f"порт {word_source}"`.
   - Вернуть `self._word`.
   `_resolve_word` остаётся первым оператором `_handle_item`, до раннего выхода по пустому слову (`plugin.py:143-145`):
   приход гасится на каждом item, в том числе без слова и без диска. `cmd_reset` приход не потребляет — он применится
   на следующем item.
   Запись регистра между чтением `writes` и `val` даёт на следующем item повторный приход того же значения; если между
   ними на порт пришло слово, регистр его перекроет (допустимая линеаризация: запись считается поздней).

### Журнал, сбросы, подписка

4. Журнал (`_ensure_assembler` + `_resolve_word`):
   - Смена слова (C-32, `plugin.py:361-366`): та же строка + источник **после** закрывающей кавычки нового слова:
     `f"WordLayoutPlugin: смена слова '{old_norm}' → '{new_norm}' (источник: {src}) — ячейки с нуля (было заполнено {old_filled}/{old_total})"`.
     Подстроки C-32 (`"смена слова 'ПЕРЕМИРИЕ' → 'МИР'"`, `"было заполнено 9/9"`) остаются.
   - Первая сборка (`old_sig is None`): новая строка `f"WordLayoutPlugin: слово '{new_norm}' (источник: {src})"`.
     Подстроки «смена слова» в ней нет (C-32 A6 зелёный).
   - То же слово пришло из другого источника (`_word` не изменился, `_word_src` изменился) — пересборки нет, ячейки
     сохраняются; одна строка `f"WordLayoutPlugin: источник слова → {src} (слово то же '{word}') — ячейки сохранены"`.
     Пишет `_resolve_word` в момент смены источника. То же слово из того же источника — строки нет.
   - `src` передаётся в `_ensure_assembler` аргументом (`_ensure_assembler(word, src)`); пересборка только по геометрии
     строк не пишет (C-32 A18).
5. Правила C-32 не меняются: смена слова = ячейки с нуля; `_taken_track` при смене слова, `cmd_reset` и возврате не
   сбрасывается. `cmd_reset` и `_maybe_return` не трогают `_word`/`_word_src`.
   Приход слова применяется ДО возврата (`_resolve_word`/`_ensure_assembler` раньше `_maybe_return`, `plugin.py:143-151`):
   сигнал возврата сразу после смены слова = «возвращать нечего», заданий возврата нет. Это следствие правила владельца
   2026-10-25 «смена слова = оператор убрал собранное».
6. Расширить существующий `shutdown(ctx)` (`plugin.py:483-487`, строку лога сохранить):
   `self._sub_rm.unsubscribe(self.name, "target_word", self._on_target_word_written)`, если `self._subscribed`; затем
   `_subscribed = False`, `_sub_rm = None`. Повторный `configure` того же экземпляра сначала снимает прежнюю подписку тем
   же вызовом (`subscribe` и сам дедуплицирует, `manager.py:159`).
7. Тексты: докстринг `_resolve_word`, комментарий латча в `configure` (`plugin.py:85-87`), `FieldMeta.info` у
   `word_source` в `registers.py:28-31` — «равноправно со «Слово»: действует последнее пришедшее; пусто = только «Слово»».
   README/STATUS плагина — правило и ограничения (ниже).
