- **Статус:** [IN PROGRESS 2026-10-26 — ветка `fix/word-layout-c37`, worktree `.claude/worktrees/lane-s-c37`; DESIGN v2 — одно хранилище слова] · **Level:** Middle+ · **Assignee:** developer <!-- lint-language: allow -->

TASK: C-37 — слово с порта больше не перекрывает регистр навсегда; регистр — единственное хранилище слова; в журнал пишется источник   PLAN: plans/word-layout.md
ROLE: developer (красные тестера — до правки `plugin.py`)
CHAIN: lead (DESIGN v2) -> reviewer stage 0 -> tester -> developer -> reviewer

**Цель.** В `letter_robot_sim.yaml` у `word_layout` `word_source: signal_2`, `target_word: ''`. Слово приходит двумя путями:
кнопка телефона (`phone.phone_camera.signal_2` → порт `word`, item `{"signal_2": <слово>, "data_type": "signal", …}`,
`Services/phone_gateway/plugin/plugin.py:355-367, 173-186`) и запись регистра (`register_update` →
`PluginOrchestrator._on_register_update` → `RegistersManager.set_field_value` → `apply_values`; путь GUI `set_config` →
`apply_values`; оба — на том же экземпляре регистра, что держит плагин). Сейчас `_resolve_word` (`plugin.py:226-241`)
латчит слово с порта в отдельное поле плагина, и оно перекрывает регистр навсегда. Module contract: **impl-only** (порты,
поля регистра, конфиг не меняются; меняются тексты `FieldMeta.info` у `target_word` и `word_source`).

## Решения владельца

- (2026-10-25, строка C-37 в `plans/queue/defects.md`) Действует самое свежее; в журнал — источник (порт/регистр).
- О1 (2026-10-26). Оператор снова пишет в регистр слово, которое стояло там до слова с телефона, — это приход.
- О2 (2026-10-26). Пустая запись регистра (`''`, пробелы) — не приход, как пустое слово с порта.
- О3 (2026-10-26). Без обходов дефекта framework C-45 (`set_config` мимо наблюдателей) — принцип 2.
- О4 (2026-10-26). **Одно хранилище слова — регистр `target_word`.** Слово с порта плагин записывает в этот же регистр;
  латча и подписки нет. Поле «Слово» в GUI показывает действующее слово. Без костылей, к архитектуре, которая
  масштабируется: у любого потребителя (GUI, пульт, backend_ctl, новый плагин) один источник правды.

## Решение

DESIGN v2 (решено лидом и владельцем, О4; v1 с латчем и подпиской отменён до реализации):

### Одно хранилище

1. Удалить `self._latched_word`. Новые поля плагина: `self._own_word: str` — значение `target_word`, которое плагин
   последним принял (записал сам с порта или принял от внешнего писателя); `self._word_src: str` — `"регистр"` или
   `f"порт {word_source}"`. В `configure` после `_init_register`: `_own_word = reg.target_word`;
   `_word_src = "регистр"`, если `target_word.strip()`, иначе `""`.
2. Запись слова — один хелпер `_write_word(w: str) -> bool`: `ok, err = self._reg.update_field("target_word", w)`;
   при отказе — `log_error` с текстом `err`, `_own_word` не меняется, вернуть `False`. Тот же экземпляр регистра читают
   GUI и backend_ctl (pull; push из процесса нет ни для одного поля — `set_send_callback` в `process_module` не
   вызывается, как и для `slots_filled`).
3. `_resolve_word(item)`, порядок внутри одного item — сначала регистр, потом порт:
   - Внешняя запись регистра: `val = self._reg.target_word`; если `val != self._own_word` — кто-то записал снаружи
     (`register_update`, `set_config`, `update_field` в тесте — любой путь, C-45 не нужен):
     - `val.strip()` непусто → `_own_word = val`, `_word_src = "регистр"`;
     - пусто (О2) → если `_own_word.strip()` — `_write_word(_own_word)` (вернуть действующее слово в регистр) и одна
       строка `f"WordLayoutPlugin: пустое слово в регистре не принято — действует '{norm(_own_word)}'"`.
   - Порт (только при непустом `word_source`): разбор значения как сейчас (`dict` → `word`/`value`); непустая строка `w`
     → `_write_word(w)`; при успехе `_own_word = w`, `_word_src = f"порт {word_source}"`.
   - Вернуть `self._own_word`.
   `_resolve_word` остаётся первым оператором `_handle_item`, до раннего выхода по пустому слову (`plugin.py:143-145`):
   внешняя запись принимается на каждом item, в том числе без слова и без диска.
4. «То же слово» — по нормализации `norm(w) = " ".join(w.upper().split())` (как `geometry.parse_word`, `geometry.py:35`):
   `sig[0]` в `_ensure_assembler` — `norm(word)`. В регистре хранится сырое значение последнего писателя.
   «мир» после «МИР» — приход, но не смена слова: пересборки нет, ячейки сохраняются.

### Журнал и сбросы

5. Журнал (`_ensure_assembler(word, src)` — `src` аргументом):
   - Смена слова (C-32, `plugin.py:361-366`): та же строка + источник после закрывающей кавычки нового слова:
     `f"WordLayoutPlugin: смена слова '{old_norm}' → '{new_norm}' (источник: {src}) — ячейки с нуля (было заполнено {old_filled}/{old_total})"`.
     Подстроки C-32 (`"смена слова 'ПЕРЕМИРИЕ' → 'МИР'"`, `"было заполнено 9/9"`) остаются.
   - Первая сборка (`old_sig is None`): `f"WordLayoutPlugin: слово '{new_norm}' (источник: {src})"` — без «смена слова»
     (C-32 A6 зелёный).
   - Пересборка только по геометрии строк не пишет (C-32 A18). Приход того же слова (по `norm`) строк не пишет.
6. Правила C-32 не меняются: смена слова = ячейки с нуля; `_taken_track` при смене слова, `cmd_reset` и возврате не
   сбрасывается. `cmd_reset` и `_maybe_return` регистр слова не трогают. Приход слова применяется ДО возврата
   (`plugin.py:143-151`): сигнал возврата сразу после смены слова = «возвращать нечего» (правило владельца 2026-10-25
   «смена слова = оператор убрал собранное»).
7. Тексты: докстринг `_resolve_word`; комментарий латча в `configure` (`plugin.py:85-87`) заменить на «одно хранилище»;
   `FieldMeta.info` в `registers.py`: у `target_word` — «целевое слово; пишут оператор и порт слова, действует последнее;
   пробел = разрыв между словами»; у `word_source` (`registers.py:28-31`) — «входной порт со словом: слово с порта
   записывается в «Слово»; пусто = только «Слово»». README/STATUS плагина — правило и ограничения.

### Ограничения

8. В README, не чинить:
   (а) порядок = порядок обработки в потоке `pipeline_executor`, не время прихода: слово с порта, стоящее в `chain_queue`
       на момент записи регистра, её перекроет; на одном item порт побеждает (п. 3);
   (б) гонка: внешняя запись, попавшая между проверкой п. 3 и `_write_word` порта того же item, перезаписывается словом
       порта без строки журнала (окно — несколько операторов в потоке pipeline);
   (в) перед сменой слова нажми «вернуть» — после смены возвращать нечего (п. 6);
   (г) пустой записью регистра слово не очистить (О2) — плагин возвращает действующее слово в регистр;
   (д) запись в регистр того же значения, что в нём уже стоит, — не событие (смены нет);
   (е) если GUI сохраняет регистры в рецепт, туда попадёт действующее слово, в том числе пришедшее с телефона.
