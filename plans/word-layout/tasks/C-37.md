# Task C-37: слово с порта и запись регистра `target_word` равноправны — действует последнее пришедшее

- **Статус:** [IN PROGRESS 2026-10-26 — ветка `fix/word-layout-c37`, worktree `.claude/worktrees/lane-s-c37`] · **Level:** Middle+ · **Assignee:** developer <!-- lint-language: allow -->

TASK: C-37 — слово с порта больше не перекрывает регистр навсегда; в журнал пишется источник слова   PLAN: plans/word-layout.md
ROLE: developer (красные тестера — до правки `plugin.py`)
CHAIN: lead (DESIGN) -> reviewer stage 0 -> tester -> developer -> reviewer

**Цель.** В `letter_robot_sim.yaml` у `word_layout` `word_source: signal_2`, `target_word: ''`. Слово приходит двумя путями:
кнопка телефона (`phone.phone_camera.signal_2` → порт `word`, item `{"signal_2": <слово>, "data_type": "signal", …}`,
`Services/phone_gateway/plugin/plugin.py:355-367, 173-186`) и запись регистра (`register_update` →
`PluginOrchestrator._on_register_update` → `RegistersManager.set_field_value` → `apply_values` на том же экземпляре
регистра, `plugin_orchestrator.py:422-450`, `registers_module/core/manager.py:190-240`; так пишут `set_register_verified`
стенда S6 α и пульт β8). Сейчас `_resolve_word` (`plugin.py:226-240`) латчит слово с порта, и оно перекрывает регистр
навсегда: после первого слова с телефона запись регистра игнорируется. Module contract: **impl-only** (порты, поля
регистра, конфиг не меняются; меняется только текст `FieldMeta.info` у `word_source`).

## Решения владельца (2026-10-26, лиду в чате)

- О1. Запись в регистр того же текста, что там уже стоял, — **приход** (перекрывает слово с порта).
- О2. Пустая запись регистра (`''`, пробелы) — **не приход**, как пустое слово с порта сейчас.
- (2026-10-25, строка C-37 в `plans/queue/defects.md`) Действует самое свежее; в журнал — источник (порт/регистр).

## Решение

DESIGN (решено лидом; стадия 0 может оспорить):
1. Состояние слова в плагине — два поля вместо `_latched_word`: `self._word: str` (действующее слово) и
   `self._word_src: str` (`"порт <word_source>"` или `"регистр"`). Новые поля учёта записей регистра:
   `self._reg_writes: int = 0` (число записей поля), `self._seen_writes: int`, `self._seen_reg_word: str`.
   В `configure` после `_init_register`: `_word = reg.target_word` и `_word_src = "регистр"`, если `target_word.strip()`,
   иначе `_word = ""`, `_word_src = ""`; `_seen_writes = 0`, `_seen_reg_word = reg.target_word`.
2. Приход записи регистра ловится двумя признаками (одна проверка, оба нужны):
   - (а) подписка `ctx.registers.subscribe(self.name, "target_word", self._on_target_word_written)` в `configure`,
     только если `ctx.registers` не `None` и у него есть `subscribe`. Колбэк — один оператор `self._reg_writes += 1`.
     Колбэк зовётся на каждый успешный `set_field_value`, в том числе тем же значением (О1). Поток колбэка — поток
     обработчика команды, не поток `process`: колбэк не трогает ассемблер, журнал и регистр.
   - (б) смена значения: `self._reg.target_word != self._seen_reg_word`. Нужна для регистра без менеджера
     (`ctx.registers is None`, тесты C-32 через `p._reg.update_field`): подписки там нет.
3. `_resolve_word(item)`, порядок внутри одного item: сначала регистр, потом порт.
   - Регистр: `writes = self._reg_writes`, затем `val = self._reg.target_word`. Если `writes != self._seen_writes`
     или `val != self._seen_reg_word` — приход: `_seen_writes = writes`, `_seen_reg_word = val`; если `val.strip()` —
     `_word = val`, `_word_src = "регистр"`; пустое (О2) — состояние слова не трогать.
   - Порт (только при непустом `word_source`): разбор значения как сейчас (`dict` → `word`/`value`); непустая строка —
     `_word = w`, `_word_src = f"порт {word_source}"`.
   - Вернуть `self._word`.
   Запись регистра между чтением `writes` и `val` даёт на следующем item повторный приход того же слова из того же
   источника — это no-op (п. 4).
4. Журнал (`_ensure_assembler` + `_resolve_word`):
   - Смена слова (C-32, `plugin.py:358-362`): та же строка + источник **после** закрывающей кавычки нового слова:
     `f"WordLayoutPlugin: смена слова '{old_norm}' → '{new_norm}' (источник: {src}) — ячейки с нуля (было заполнено {old_filled}/{old_total})"`.
     Подстроки C-32 (`"смена слова 'ПЕРЕМИРИЕ' → 'МИР'"`, `"было заполнено 9/9"`) остаются.
   - Первая сборка (`old_sig is None`): новая строка `f"WordLayoutPlugin: слово '{new_norm}' (источник: {src})"`.
     Подстроки «смена слова» в ней нет (C-32 A6 зелёный).
   - То же слово пришло из другого источника (`_word` не изменился, `_word_src` изменился) — пересборки нет, ячейки
     сохраняются; одна строка `f"WordLayoutPlugin: источник слова → {src} (слово то же '{word}') — ячейки сохранены"`.
     Пишет `_resolve_word` в момент смены источника. То же слово из того же источника — строки нет.
   - `src` передаётся в `_ensure_assembler` аргументом (`_ensure_assembler(word, src)`); пересборка только по геометрии
     строк не пишет (C-32 A18).
5. Правила C-32 не меняются: смена слова = ячейки с нуля; `_taken_track` при смене слова, `cmd_reset` и возврате не
   сбрасывается. `cmd_reset` и `_maybe_return` не трогают `_word`/`_word_src`.
6. `shutdown(ctx)` (новый, `base.py:1559` — no-op по умолчанию): `ctx.registers.unsubscribe(self.name, "target_word",
   self._on_target_word_written)`, если подписка была (флаг `self._subscribed`). Повторный `configure` того же экземпляра
   сначала снимает прежнюю подписку тем же вызовом — одна подписка на экземпляр.
7. Тексты: докстринг `_resolve_word`, комментарий латча в `configure` (`plugin.py:85-87`), `FieldMeta.info` у
   `word_source` в `registers.py:27-30` — «равноправно со «Слово»: действует последнее пришедшее; пусто = только «Слово»».
   README/STATUS плагина — правило и ограничения (ниже).
8. Ограничения (в README, не чинить): (а) регистр без менеджера (`ctx.registers is None`) не видит записи того же
   значения — только смену; (б) регистр и порт пришли «одновременно» — на одном item порт побеждает (порядок п. 3),
   истинное время записи регистра не хранится.
