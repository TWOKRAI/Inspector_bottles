## Общий DESIGN (решает лид; teamlead не выводит заново)

1. **Тип находки** (`plugins/manifest.py`): `@dataclass(frozen=True) class PreflightFinding: severity:
   Literal["error", "warning", "info"]; message: str; path: str | None = None`. Исключение
   `class PreflightFailed(RuntimeError)` с полем `findings: list[tuple[str, str, PreflightFinding]]`
   (процесс, плагин, находка); `str()` — по строке на находку `error`.
2. **Хук** (`plugins/base.py`, рядом с `register_schema`): `@classmethod def preflight(cls, config: dict[str, Any])
   -> list[PreflightFinding]: return []`. Контракт в docstring: вход — секция `config` плагина из рецепта (dict at
   boundary); без `ctx`, без экземпляра, без побочных эффектов; быстро (чтение каталога, без загрузки модели);
   не бросает — свои ошибки возвращает находкой `error`.
3. **Сборщик** (`plugins/manifest.py`): `collect_preflight(processes: Iterable[tuple[str, Mapping[str, Any]]])
   -> list[tuple[str, str, PreflightFinding]]`. Для каждого `proc_dict["config"]["plugins"][i]`: класс — через
   `PluginRegistry.get(plugin_name)`, затем по `class_path == plugin_class` (как `_find_plugin_entry`,
   `blueprint.py:1239`), затем импорт по точечному пути `plugin_class`. Класс не найден / не импортируется →
   находка `warning` «класс не найден — preflight пропущен» (ошибку импорта класса ловят другие стражи сборки,
   дублировать не нужно). Хук бросил исключение вопреки контракту → находка `error` с типом и текстом
   исключения (дефект плагина громкий).
4. **Вызов** (`system_launcher.py`): приватный `_run_preflight(processes)` первым действием `run()` и `start()`,
   до `_prepare_pid_registry` и любых побочных эффектов: лог каждой находки по уровню; есть `error` →
   `raise PreflightFailed(findings)`. Без `error` — запуск дальше.
5. **`ml_inference`** (C-55b.1 — только `error`; C-55b.2 — `warning`/`info`): `MLInferencePlugin.preflight(config)`:
   `models_dir = config.get("models_dir") or _DEFAULT_MODELS_DIR` (тот же резолв, что `configure`, `plugin.py:117`),
   `model = config.get("model") or ""`. Проверка — новый публичный метод реестра
   `ModelRegistry.diagnose(model_id: str) -> ModelDiagnosis` (`registry.py`; `ModelDiagnosis` — frozen dataclass
   `ok: bool, message: str, path: Path | None`), который применяет те же правила, что `scan()`
   (`_WEIGHT_SUFFIXES`, sidecar рядом, `_load_spec`) к одному id. Уровни:
   - `model` задан, весов `<id>.{суффиксы из _WEIGHT_SUFFIXES}` нет / sidecar нет / sidecar битый / каталога нет →
     **error**, `path` — недостающий файл или каталог;
   - `model` пуст → **warning** «модель не выбрана — pass-through до выбора в GUI» (`path` — каталог);
   - модель на месте → **info** «модель `<id>`: `<веса>`, backend `<backend>`».
