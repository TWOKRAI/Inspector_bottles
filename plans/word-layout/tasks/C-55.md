## Решение (DESIGN)

Всё в `multiprocess_prototype/run.py`.

1. **`git_common_dir(cwd: Path) -> Path | None`.** `subprocess.run(["git", "rev-parse", "--path-format=absolute",
   "--git-common-dir"], cwd=cwd, capture_output=True, text=True, timeout=5)`. Код 0 → `Path(stdout.strip())`.
   `OSError` (git нет), `subprocess.TimeoutExpired`, код ≠ 0 → `None`. Это не проглатывание: `None` значит
   «основная копия не определена», сообщение п. 5 называет это явно. Комментарий `# nosec B603 B607` с причиной
   (аргументы — литералы), как у `os.execv` на `run.py:58`.
2. **`main_copy_root(project_root: Path, *, common_dir_of=git_common_dir) -> Path | None`** — родитель общего
   каталога `.git`; `None`, если `common_dir_of` вернул `None`. В основной копии — сам `project_root`.
3. **`venv_python(venv_dir: Path) -> Path`** — замена `_venv_python()`: `Scripts/python.exe` при `os.name == "nt"`,
   иначе `bin/python`. Константу `PROJECT_VENV` оставить.
4. **`resolve_venv_python(project_root: Path, main_root: Path | None) -> tuple[Path | None, list[Path]]`** — чистая
   функция, без `git`. Кандидаты по порядку: `venv_python(project_root / ".venv")`; затем, если `main_root` не
   `None` и `main_root.resolve() != project_root.resolve()`, — `venv_python(main_root / ".venv")`. Возвращает
   первый существующий и список всех проверенных. Свой `.venv` (настоящий или junction) всегда выигрывает.
5. **`launch(*, project_root: Path = PROJECT_ROOT, common_dir_of=git_common_dir, execv=os.execv) -> int`.**
   Ключевые параметры — швы для тестов; `__main__` не меняется (`sys.exit(launch())`).
   1. `main_root = main_copy_root(project_root, common_dir_of=common_dir_of)`;
      `venv_py, tried = resolve_venv_python(project_root, main_root)`.
   2. `venv_py is None` → stderr: «[run] ОШИБКА: venv не найден» и все пути из `tried`; при `main_root is None` —
      строка «основная копия не определена: `git rev-parse --git-common-dir` не ответил». Подсказки `uv sync` нет.
      Возврат `1`.
   3. Интерпретатор другой (`_same_interpreter` без изменений) → `[run] переключаюсь на <venv_py>`; если venv
      не из `project_root` — дописать `(venv основной копии <main_root>)`. Затем
      `execv(str(venv_py), [str(venv_py), str(Path(__file__).resolve()), *sys.argv[1:]])`, как сейчас. После
      `execv` кода нет: настоящий `os.execv` не возвращается.
   4. Дальше — как сейчас (`run.py:60-75`).
6. **Докстринг модуля** (`run.py:2-13`): порядок поиска venv (свой → основной копии), код выхода 1. Пункт про
   `sys.path` оставить.

## Приёмка (для тестера; ожидаемые значения — литералы)

Харнес: `import multiprocess_prototype.run as run` (импорт без побочных эффектов). Корни — `tmp_path`.
«Python venv» — пустой файл `<dir>/.venv/Scripts/python.exe` при `os.name == "nt"`, иначе `<dir>/.venv/bin/python`
(литерал в тесте, не `run.venv_python`). Подмена `git` — лямбда `common_dir_of`. Подмена `execv` — функция,
которая бросает своё исключение с аргументами.

- **V1.** Есть `wt/.venv` и `main/.venv`; `resolve_venv_python(wt, main)` → python из `wt`; `tried` — 1 путь.
- **V2.** Нет `wt/.venv`, есть `main/.venv` → python из `main`; `tried == [<wt python>, <main python>]`.
- **V3.** Нет ни одного → `(None, [<wt python>, <main python>])`.
- **V4.** `main_root = None`, нет `wt/.venv` → `(None, [<wt python>])`; `main_root == wt` → `(None, [<wt python>])`,
  без дубля.
- **L1.** `launch(project_root=wt, common_dir_of=lambda _: main / ".git", execv=<бросает>)`, venv нигде нет → возврат
  `1`; stderr (`capsys`) содержит оба пути из V3, не содержит `uv sync`; `execv` не вызван.
- **L2.** То же, `main/.venv` python есть; `monkeypatch.setattr(sys, "argv", ["run.py", "letter_robot_sim",
  "--headless"])` → `execv` вызван с `str(<main python>)` и списком
  `[str(<main python>), str(Path(run.__file__).resolve()), "letter_robot_sim", "--headless"]`.

## REDS

До правки красные все 6: V1–V4, L1, L2. Сторожа разработчика (`_hazards.py`):
- повторный `launch` в тот же python не вызывает `execv` (нет зацикливания): `sys.executable` подменён на путь
  фейкового venv; приложение не стартует — до вызова подменить `multiprocess_prototype.main.main` заглушкой
  (`monkeypatch.setattr`; `launch` берёт имя из модуля в момент вызова), заглушка возвращает `0`;
- настоящий `git_common_dir(Path(run.__file__).parent)` → существующий каталог с именем `.git`;
- `git_common_dir(tmp_path)` вне репозитория → `None` без исключения.

**Инъекции (черновик предсказаний для лида):** И1 — поменять порядок кандидатов → V1, V2; И2 — не добавлять
кандидат основной копии → V2, V3, L2; И3 — не убирать дубль при `main_root == project_root` → V4; И4 — вернуть
`uv sync` в сообщение → L1; И5 — re-exec `run.py` основной копии вместо `Path(__file__)` → L2.
