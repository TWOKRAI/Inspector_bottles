## Решение (DESIGN)

Реализация — в `multiprocess_prototype/run.py`; `frontend/run.py` её вызывает.

1. **`git_common_dir(cwd: Path) -> Path | None`.** `subprocess.run(["git", "rev-parse", "--path-format=absolute",
   "--git-common-dir"], cwd=cwd, capture_output=True, text=True, timeout=5, env={**os.environ,
   "GIT_CEILING_DIRECTORIES": str(cwd.parent)})`. Вызов через атрибут модуля (`import subprocess`;
   `subprocess.run(...)`), чтобы тест мог подменить `run.subprocess.run`.
   - Код 0 и непустой `stdout.strip()` → `Path(stdout.strip())`; код 0 и пустой вывод → `None`.
   - `OSError` (git нет на PATH), `subprocess.TimeoutExpired`, код ≠ 0 (в том числе 128 «не репозиторий» и 129
     «неизвестная опция» на git < 2.31) → `None`. Это не проглатывание: `None` значит «основная копия не
     определена», сообщение п. 5 называет это явно.
   - **Почему потолок `GIT_CEILING_DIRECTORIES = cwd.parent`:** git ищет репозиторий вверх по дереву; на этой
     машине каталог `tmp` резолвится в репозиторий `C:/Users/INNOTECH/.git` (находка стадии 0). Потолок разрешает
     только сам `cwd` — корень дерева, где лежит `.git` (каталог у основной копии, файл у worktree).
   - **Почему `timeout=5`:** обычный ответ — десятки мс; таймаут — страховка от зависшего git (антивирус, сетевой
     диск), чтобы вход не висел молча. Пять секунд с запасом на холодный старт git на Windows.
   - **Почему `--path-format=absolute`:** без неё git отдаёт путь относительно cwd; абсолютный путь не зависит от
     того, откуда запущен скрипт.
   - Комментарий `# nosec B603 B607` с причиной (аргументы — литералы), как у `os.execv` на `run.py:58`.
2. **`main_copy_root(project_root: Path, *, common_dir_of=git_common_dir) -> Path | None`** — зовёт
   `common_dir_of(project_root)` **позиционно**; возвращает `.parent` пути **как его отдал git**, без `.resolve()`;
   `None`, если `common_dir_of` вернул `None`. Все сравнения путей в п. 4–5 — только через `.resolve()`.
3. **`venv_python(venv_dir: Path) -> Path`** — замена `_venv_python()`: `Scripts/python.exe` при `os.name == "nt"`,
   иначе `bin/python`. **`PROJECT_VENV` остаётся публичным именем** в обоих файлах (принцип владельца 3: публичный
   путь без вызывающего — контракт).
4. **`resolve_venv_python(project_root: Path, main_root: Path | None) -> tuple[Path | None, list[Path]]`** — чистая
   функция, без `git`. Кандидаты по порядку: `venv_python(project_root / ".venv")`; затем, если `main_root` не
   `None` и `main_root.resolve() != project_root.resolve()`, — `venv_python(main_root / ".venv")`. Возвращает
   первый существующий и список всех проверенных.
5. **`venv_guard(script: Path, *, project_root: Path = PROJECT_ROOT, common_dir_of=git_common_dir, execv=os.execv,
   tag: str = "[run]") -> int | None`** — единственная реализация guard'а.
   1. `own = venv_python(project_root / ".venv")`. Есть → `venv_py, tried, main_root = own, [own], None`;
      **git не вызывается**. Нет → `main_root = main_copy_root(project_root, common_dir_of=common_dir_of)`;
      `venv_py, tried = resolve_venv_python(project_root, main_root)`.
   2. `venv_py is None` → stderr: `<tag> ОШИБКА: venv не найден` и все пути из `tried`. Дальше:
      - `main_root is None` → строка «основная копия не определена: `git rev-parse --git-common-dir` не ответил»;
        подсказки `uv sync` нет (см. «Открыто», п. 1);
      - `main_root.resolve() == project_root.resolve()` (основная копия без `.venv`) → подсказка
        `Создай его: cd <project_root> && uv sync`, как сейчас;
      - иначе (связанный worktree) → строка «venv основной копии <main_root> тоже не найден»; подсказки `uv sync`
        нет.
      Возврат `1`.
   3. Интерпретатор другой (`_same_interpreter(Path(sys.executable), venv_py)`, функция без изменений) →
      `<tag> переключаюсь на <venv_py>`; если `venv_py` не из `project_root` — дописать
      `(venv основной копии <main_root>)`. Затем `execv(str(venv_py), [str(venv_py), str(script.resolve()),
      *sys.argv[1:]])`. После `execv` кода нет: настоящий `os.execv` не возвращается.
   4. Интерпретатор тот же → возврат `None` (продолжать запуск).
6. **`launch(*, project_root: Path = PROJECT_ROOT, common_dir_of=git_common_dir, execv=os.execv) -> int`** в `run.py`:
   1. `rc = venv_guard(Path(__file__), project_root=project_root, common_dir_of=common_dir_of, execv=execv,
      tag="[run]")`; `rc is not None` → `return rc`.
   2. `sys.path.insert(0, str(PROJECT_ROOT))`, если его там нет, — **модульная константа `PROJECT_ROOT`, не
      параметр `project_root`, намеренно**: в `sys.path` идёт корень дерева, чей код сейчас исполняется; параметр —
      шов для тестов, `tmp_path` в `sys.path` не нужен.
   3. Дальше — как сейчас (`run.py:64-75`).
7. **`frontend/run.py`:**
   - После `PROJECT_ROOT = PROTOTYPE_ROOT.parent` (`:40`) — минимальный бутстрап на уровне модуля:
     `if str(PROJECT_ROOT) not in sys.path: sys.path.insert(0, str(PROJECT_ROOT))` (при запуске скриптом
     `sys.path[0]` — каталог `frontend/`), затем `from multiprocess_prototype.run import git_common_dir, venv_guard`.
   - `_venv_python`, `_same_interpreter` (`:48-60`) — удалить: это приватные копии, решение владельца «одна
     реализация» (п. а). `PROJECT_VENV` и `PRESENTATION_PATH` остаются.
   - `launch(*, project_root: Path = PROJECT_ROOT, common_dir_of=git_common_dir, execv=os.execv) -> int`:
     `rc = venv_guard(Path(__file__), project_root=…, common_dir_of=…, execv=…, tag="[frontend/run]")`;
     `rc is not None` → `return rc`; дальше — как сейчас (`:82-98`: `sys.path`, `INSPECTOR_PRESENTATION`, `app_main`).
   - Докстринг `:28-29`: «venv-guard — 1-в-1 с …» → «venv-guard — общий: `multiprocess_prototype.run.venv_guard`
     (одна реализация, C-55a); бутстрап `sys.path` ниже нужен, чтобы импортировать его до re-exec».
8. **Докстринг `run.py`** (`:2-13`): порядок поиска venv (свой → основной копии, git — только если своего нет),
   подсказка `uv sync` только для основной копии, код выхода 1, `venv_guard` — общий для `frontend/run.py`.
