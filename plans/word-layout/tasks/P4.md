Правила судей:
- `judge_journal`/`judge_case`: посторонние строки пропускаются; строки диска сверяются по порядку с `expects`; лишняя/недостающая строка — FAIL `lines.count`; строка слова (`word_line`) — до первой строки диска, иначе FAIL `word_line`. `feed` не `None`: буква ≠ → reason `feed` у строки. **Ред. 3 (стенд 2026-11-10, коммит `ede55423e`):** угол подачи против угла сети отдельным FAIL больше не судится (допуск 0,5° был ужесточением вне `design.md`; сеть читает угол с шумом до 13°) — Δ угла выводится в `observed`, ошибку доворота держат окна `r` и `ARGS[9]` (±5° от угла списка); строки диска и подача выравниваются по буквам (`_align`). Угол подачи против угла списка (точный по R1) скриптом не проверяется — открыто. `regs.jobs_emitted` — PASS, если `regs["jobs_emitted"] − jobs_emitted_before == Case.jobs`; при PASS, но `regs["jobs_emitted"] ≠ Case.regs["jobs_emitted"]` в `observed` дописывается `(каскад от прошлого случая: литерал <n>)`. Остальные поля `regs` — равенство литералу.
- `judge_home`: PASS ⇔ `reply.result.status == "ok"`, `robots.robot_main.result == "done"`, `home ∈ {"moved","already"}`, `park_state` = `{"seq": <seq ответа>, "state": "done", …}`, в `texts` есть `W* CMD_OPCODE = 65 (SERVO)` и после неё `W* CMD_ARGS[0] = 0`, при `home == "moved"` до SERVO есть `W* CMD_OPCODE = 48 (SC_RUN)`, строк `STOP_REQ` нет.
