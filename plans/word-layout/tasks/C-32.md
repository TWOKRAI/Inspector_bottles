## Решение

DESIGN (решено лидом, не пересматривать):
1. Идентичность диска — `item["sidecar"]["track_id"]`. Его ставит `center_crop` (`center_crop/plugin.py:189`, id события
   `line_filter`: zone_edge — `_counted_total`, монотонный, `line_filter/plugin.py:113-121`; tracking — `track.id`). Item
   целиком едет по IPC (`pipeline_executor.py:497-525`; `pixel_to_robot`/`ml_inference` возвращают `{**item, …}`).
   Новый регистр и новое поле конфига не заводить.
2. Новый метод `_disk_id(item) -> object | None`: `sidecar` — dict → `sidecar.get("track_id")`, иначе `None`.
   В `_handle_item` перед `_should_take` вызвать `_disk_id(item)`. Передать результат в `_should_take(pred, tid)`.
3. `_should_take`, авто-режим, ветка `tid is not None` (сравнение `is not None`, не по истинности: id 0 — допустимый id).
   Новые поля в `configure`: `self._cur_track = None`, `self._taken_track = None`.
   - `tid != self._cur_track` → новый диск: `_cur_track = tid`, `_settle = 0`, `_cur_label = ""`.
   - `tid == self._taken_track` → `False` (этот диск уже взят: и когда задание выдано, и когда был пропуск).
   - `pred is None` → `_settle = 0`, `_cur_label = ""`, `False`. Новый диск этим не считается.
   - Смена буквы внутри одного `tid` → `_settle = 1`, но не перевзвод. Та же буква → `_settle += 1`.
   - `_settle >= max(1, settle_frames)` → `_taken_track = tid`, `_settle = 0`, `True`.
   Обновить докстринг `_should_take` и комментарий в `configure` (`:90-92`): два режима — по `sidecar.track_id` и по
   букве/паузе; `_armed` в id-ветке не читается.
4. Ветка `tid is None` — текущий код `:390-410` без изменений (непрерывный тракт без `center_crop`).
   Пауза без `tid` (item слова, пульта, `predictions: []`) не трогает `_taken_track`. Поэтому управляющий item между
   двумя item одного диска дубля не даёт.
5. `use_trigger` — без изменений (`:384-388`). `tid` там не читается.
6. `cmd_reset`, `_maybe_return`, `_ensure_assembler` поле `_taken_track` **не** сбрасывают. **Правило:** диск с тем же
   `track_id`, что у последнего взятого до сброса, после сброса не берётся. Тот же id = то же событие пересечения линии.
   Робот этот диск уже снял или пропустил, повторное задание ушло бы на пустую ленту. Следующий id берётся.
7. Журнал смены слова, в `_ensure_assembler` (`:322-354`): старое `word_norm` запомнить до пересборки. Если `self._sig`
   был не `None` и `sig[0]` отличается от прежнего `self._sig[0]` — **после** пересборки один `log_info` литералом:
   `f"WordLayoutPlugin: смена слова '{old_norm}' → '{self._reg.word_norm}' — ячейки с нуля (было заполнено {old_filled}/{old_total})"`.
   `old_filled`/`old_total` — `slots_filled`/`slots_total` до пересборки.
   Первая сборка (`_sig is None`) этой строки не пишет: слово из регистра уже в строке `configured` (`:103`).
   Пересборка только по геометрии (слово то же) строку не пишет: поведение `:338-349` не меняется.
   `old_sig = self._sig` берётся ДО присваивания `self._sig = sig` (`:338`); условие: `old_sig is not None and
   sig[0] != old_sig[0]`; `old_norm`, `old_filled`, `old_total` — тоже до пересборки.
8. README `:61-62`, STATUS `:11` — фраза: «новый диск = новый `sidecar.track_id`; без него — смена буквы/пауза.
   Ограничение: id zone_edge — счётчик процесса line; его рестарт без рестарта layout обнуляет id, и диск с id, равным
   последнему взятому до рестарта, отбрасывается (`reset_word` это не лечит).»
