# Task C-40: ml_inference распознаёт каждый кадр — `inference_every_n` и кэш повтора убрать

- **Статус:** [OPEN 2026-10-26 — ветка `fix/ml-inference-c40`, worktree `.claude/worktrees/lane-s-c40`] · **Level:** Middle · **Assignee:** developer <!-- lint-language: allow -->

TASK: C-40 — `ml_inference` распознаёт каждый входной кадр; регистр `inference_every_n` и кэш повтора предсказания удалены   PLAN: plans/word-layout.md
ROLE: developer (красные тестера — до правки `plugin.py`)
CHAIN: lead (DESIGN) -> reviewer stage 0 -> tester -> developer -> injections -> reviewer

**Цель.** При `inference_every_n > 1` плагин `ml_inference` (`Services/ml_inference/plugin/plugin.py:172-213`)
на кадрах между инференсами отдаёт прошлое предсказание. В тракте робота каждый кадр — новый диск
(`line_filter` → `center_crop` → `ml_inference` → `word_layout`): вход `inference_every_n=2`, диски
Р Р Е Е И И → диск 5 (физически «И») получает метку «Е» и ячейку буквы Е. Робот кладёт И в ячейку Е
(`plans/queue/defects.md`, строка C-40; воспроизвёл ревьюер C-32 на настоящих плагинах и заглушке модели).
Во всех рецептах с `ml_inference` сейчас стоит 1, в штатном тракте дефект недостижим. Ручка остаётся
ловушкой для следующего рецепта.

Module contract: **API change** — из регистра `MLInferenceRegisters` удаляется поле `inference_every_n`.
Имя схемы `MLInferenceRegistersV1`, порты, форма `predictions`, остальные поля и команды не меняются.

## Решения владельца

- (2026-10-25, строка C-40 в `plans/queue/defects.md`) У модуля нейросети такой ручки быть не должно:
  `inference_every_n` и кэш повтора убрать, каждый кадр на входе распознаётся. Отбор кадров, если понадобится,
  — отдельный модуль-фильтр на входе, ставится рецептом в pipeline. Это осознанное исключение из принципа
  FREEZE: владелец решил удалить ручку.
- `edge_detection.inference_every_n` — тот же вопрос, решение владельца отдельно. В C-40 не входит.

## Решение (DESIGN)

1. **Регистр.** В `Services/ml_inference/plugin/registers.py` удалить поле `inference_every_n` и заголовок
   раздела «Производительность» над ним. Имя схемы не менять: неизвестный ключ `SchemaBase` пропускает
   (pydantic `extra` по умолчанию `ignore`). `_init_register` (`multiprocess_framework/modules/process_module/plugins/base.py:1442`)
   берёт из `ctx.config` только поля регистра. Значит, старый рецепт или сохранённый конфиг с
   `inference_every_n` загружается без ошибки, ключ ничего не делает.
2. **Обработка кадра.** В `_process_item` инференс идёт на каждом кадре с `frame` при готовой модели:
   - удалить `every_n`, `self._frame_idx`, `run_now` и ветку `else` (пометка кэша);
   - удалить атрибуты `self._frame_idx`, `self._last_predictions` из `configure`;
   - путь ошибки инференса: строка `self._last_predictions = []` и комментарий про `inference_every_n>1` уходят.
     Поведение остаётся: `last_error`, лог, телеметрия `[]` (fail-safe `last_below_threshold=True`), выход
     `{**item, "predictions": []}`;
   - успешный путь: `preds` → телеметрия latency и `_update_last_pred_telemetry(preds)`, как сейчас.
     `_mark_below_threshold` остаётся: он ставит флаг порога на свежие предсказания.
   Порядок «порог из регистра читается при пометке» сохраняется: `cmd_set_threshold` между кадрами
   действует со следующего кадра.
3. **Смена модели.** В `_load_selected_model` удалить сброс кэша (`_last_predictions`, `_frame_idx`) и его
   комментарий. Сброс угловой телеметрии и `last_below_threshold=True` остаётся.
4. **Команда.** В `cmd_set_threshold` убрать `inference_every_n` из списка полей. Ключ в `data`, которого нет
   в списке, пропускается, как сейчас пропускается любой лишний ключ. Ответ `{"status": "ok"}`.
5. **Рецепты.** Удалить строку `inference_every_n: 1` у `ml_inference` в трёх рецептах (п. «Файлы»). У
   `edge_detection` (`phone_sketch.yaml:170`, `webcam_sketch.yaml:175`) ключ остаётся.
6. **Документация.** `Services/ml_inference/README.md:55-56` — пункт про кэш заменить одной фразой:
   «Каждый кадр на входе распознаётся; отбор кадров — отдельный фильтр в рецепте (C-40)». `STATUS.md` —
   строка о C-40. `Plugins/processing/word_layout/README.md:67-68` и докстринг `plugin.py:449-450` —
   предупреждение про `inference_every_n = 1` снять: ручки больше нет. Комментарий `_publish_state`
   (`plugin.py:343`) — без `inference_every_n`.

## Приёмка (для тестера; ожидаемые числа — литералы)

Харнес: плагин с подменённым backend, как `_make_plugin` в
`Services/ml_inference/tests/test_acceptance_always_label.py:59-99`. Хелпер скопировать в свой файл, не
импортировать: тот файл меняется в этой задаче. Backend-заглушка выбирает класс **по содержимому входа**:
кадр «Р», «Е», «И» — однотонный, яркость 40 / 120 / 200; заглушка отличает их по среднему входного тензора.
Порядок средних после препроцессинга тестер проверяет отдельным ассертом в своём файле. Заглушка, которая
отдаёт метки по номеру вызова, запрещена: она не отличает предсказание этого кадра от предсказания другого.
Уверенность топ-1 — 0.9, `confidence_threshold=0.5`, если в пункте не сказано иное. Модель метки — `["Р", "Е", "И"]`.

- **A1.** `"inference_every_n" not in MLInferenceRegisters.model_fields`.
- **A2.** Конфиг плагина содержит `"inference_every_n": 2` (старый рецепт). `configure` проходит без исключения.
  Шесть кадров Р Р Е Е И И, по одному на вызов `process` → топ-1 метки
  `["Р", "Р", "Е", "Е", "И", "И"]`, число вызовов `infer` у заглушки — 6.
- **A3.** То же, все шесть кадров одним вызовом `process(items)` → те же метки по порядку, вызовов `infer` — 6.
- **A4.** `cmd_set_threshold({"inference_every_n": 3, "confidence_threshold": 0.4})` → ответ `{"status": "ok"}`,
  `confidence_threshold` регистра `0.4`. Затем три кадра Е И Р → метки `["Е", "И", "Р"]`, вызовов `infer` — 3.
- **A5.** Кадр Р — инференс без ошибки; кадр Е — `infer` бросает исключение → `predictions == []`,
  регистр `last_below_threshold` — `True`; кадр И → топ-1 метка `"И"`.
- **A6.** Уверенность топ-1 — 0.45. Порог 0.4 → у кадра `below_threshold` `False`; `cmd_set_threshold`
  с порогом 0.5 → у следующего кадра `True`.
- **A7** (цепочка на настоящих объектах). `LineFilterPlugin` → `CenterCropPlugin` → `MLInferencePlugin`
  (заглушка по содержимому, в конфиге `"inference_every_n": 2`) → `WordLayoutPlugin`. Геометрия и слово —
  как в `Plugins/processing/word_layout/tests/test_disk_identity_chain.py` (физический проход поперёк линии,
  пустой старт). Диски Р Р Е Е И И, каждый — свой проход. Буквы в заданиях `word_layout` по порядку —
  `["Р", "Р", "Е", "Е", "И", "И"]`; номера ячеек тестер выписывает литералами из правил `word_layout/README.md`.
  Кадр, который `center_crop` отдаёт в `ml_inference`, должен нести яркость своего диска. Если для этого
  нужна подготовка кадра, тестер описывает её в докстринге теста.
