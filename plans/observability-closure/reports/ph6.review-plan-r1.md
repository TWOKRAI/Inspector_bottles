## Пробы ревьюера (запуском, `.venv` Python 3.12.12; скрипты были в scratchpad сессии)

- **P1.** Перехват `os.dup2` на трубу с читателем внутри процесса, запись в fd 2, затем `os._exit(76)` → `pipe lines=3 LAST=0`, 5 из 5 (последняя строка потеряна). `dup2` на файл с `O_APPEND` → `lines=4 LAST=1`, 5 из 5.
- **P2.** Ребёнок с непрочитанной stderr-трубой; писатель-daemon со `StreamHandler(sys.stderr)` и очередью, 20000 строк, обычный выход → `HUNG: no exit within 8 s after MAIN_DONE`, 3 из 3. Писатель через `os.write` в свой `os.dup(2)` → `rc: 0 exit_after_s: 1.05`, 3 из 3.
- **P3.** `faulthandler.dump_traceback(all_threads=True)` печатает `Thread 0x000061d4`, без имени потока.
- **P4.** `os.dup2(w, 2)` на Windows ловит `os.write`, MSVCRT `_write` и `GetStdHandle` (UCRT `_dup2` переставляет и `SetStdHandle`).

## Находки

1. **[blocker] 6.8 DESIGN** — труба + читатель в процессе теряют вывод в момент смерти (P1), ровно тот, что задача обязана сохранить (`process_runner.py:533-543`, traceback финализации, дамп faulthandler). Исправить: `dup2` fd 1/2 на файл `console.log` (`O_APPEND`), зеркало в консоль — поток по хвосту файла; либо читатель в родителе. Приёмка: «fd 2, затем `os._exit(76)` → строка в `console.log`, 5 из 5».
2. **[blocker] 6.1 DESIGN п.3, приёмка** — срок `close()` не спасает выход (P2): писатель внутри `sys.stderr` держит лок буфера, `logging.shutdown` и flush при финализации ждут вечно; `process_runner.py:541-542` встаёт так же. Строка «нет живого `console-writer-*`» невыполнима. Исправить: писатель пишет в свой `os.dup(2)`, его хэндлер не в `logging._handlerList`; приёмка «20000 строк в непрочитанную трубу → выход ≤ 3 с»; `process_runner.py:541-542` в Files («согласовать с Ж»).
3. **[blocker] 6.2 приёмка** — «имя потока `*_message_processor` в дампе» недостижимо при «только faulthandler» (P3). Исправить: шапка `ident → name` в hex-формате faulthandler перед дампом.
4. **[major] 6.1 DESIGN п.4** — синхронный stderr убран только у голоса консоли; `_warn_sink_stuck` (`log_channel.py:230-243`), ротация, ретеншен, `ChannelRoutingManager._fallback_log` (`:772-799`) идут `emergency_log` → lastResort → тот же stderr.
