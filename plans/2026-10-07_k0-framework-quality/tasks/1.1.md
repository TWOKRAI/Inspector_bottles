## DESIGN (решено лидом — исполнитель печатает, не выводит)

Охват. В трёх модулях находок `INTERFACE_WITHOUT_TEST` ровно **5** (`atlas card`, совпало с «тестов 0» в `atlas ref`): `IRouterManager`, `IProcessCommunication`, `IConfig`, `IConfigManager`, `IConfigObserver`. Задача берёт **все 5**; осталось — 0. Остальные интерфейсы трёх модулей (`IMessageChannel`, `IProcessModule`, `ISharedResources`, `ProcessStatsDict`) не трогаем («тестов N» в `ref` — упоминания слова, включая docstring, не покрытие).

1. **Один файл на интерфейс или пару.** Нужны 4 новых файла (ниже). Причина: независимость сбоев и читаемость; существующие файлы не правятся — соседний трек (О3).
2. **Что проверяет контрактный тест.** Контракт интерфейса = набор публичных членов (имена из `ref`) + вид (ABC или Protocol) + соответствие реализации. Не поведение реализации: оно уже покрыто тестами реализации.
3. **ABC-интерфейсы** (`IRouterManager`, `IConfig`, `IConfigManager`): `__abstractmethods__` равен литеральному множеству; создать экземпляр интерфейса нельзя (`TypeError`). Множества — литералы из этого брифа (раздел «Литералы»), не вычисляются из кода.
4. **Protocol-интерфейсы** (`IProcessCommunication`, `IConfigObserver`; оба `runtime_checkable`): заглушка с полным набором проходит `isinstance`, заглушка без любого одного члена — нет (цикл по каждому из 11 имён). Не читаем приватные атрибуты `typing`.
5. **Соответствие реализации.** `ProcessCommunication` и `ConfigManager` наследуют свои интерфейсы явно; `RouterManager` и `Config` — нет (структурное соответствие): тест проверяет, что у **экземпляра** есть каждое имя интерфейса и оно вызываемо (`manager_name` и `data` — значения, не вызываемые), а у `RouterManager` (только у него) для методов, имеющихся и там и там, сравниваются параметры связанного метода экземпляра (без `self`) с параметрами интерфейса по правилу: параметры интерфейса — **префикс** параметров реализации, лишние параметры реализации имеют значения по умолчанию. Расхождение — находка, не правка кода (О5). Известный дрейф закрепляется литералом: `{"get_channel": (["channel_name"], ["name"]), "unregister_channel": (["channel_name"], ["name"])}` (интерфейс, реализация); тест сравнивает со словарём расхождений целиком. Причина: тест, красный на текущем коде при запрете править фреймворк, невыполним, а закреплённый дрейф краснеет на любом новом расхождении и на починке. Сигнатуры `Config` не сравниваются (расхождений нет, проверка не нужна).
6. **`IConfig.data` — «копия»** (docstring `ref`): изменение возвращённого словаря не меняет конфиг. Единственная поведенческая проверка задачи: она закрепляет фразу интерфейса.
7. **Наблюдатель.** `IConfigObserver.__call__(key, old_value, new_value)` (`ref` его не показывает — приватное имя, пришлось читать исходник): функция с тремя параметрами проходит `isinstance`, `object()` — нет; сценарий-литерал: два наблюдателя, один подписан на ключ `"k"`, второй — по умолчанию (`"*"`); `set("k", 1)`, затем `set("k", 2)`; каждый наблюдатель пишет свои вызовы в список; последний вызов каждого равен `("k", 1, 2)`. Утверждения только после `set`, не внутри наблюдателя. Причина: `Config._notify` ловит исключение наблюдателя через `logger.exception` (assert внутри проглатывается), уведомляет только при `old_value != value` и обходит два цикла — по ключу и по `"*"`; два наблюдателя покрывают оба. Первое значение `old_value` не пинится.
8. **Ожидаемые значения — литералы.** Ни одно множество, имя или число не вычисляется из проверяемого кода. Сигнатуры сравниваются как списки имён параметров, взятых литералом из `ref`.
9. **Дыры известны заранее** (раздел «Инъекции»): `runtime_checkable` Protocol не проверяет сигнатуру `__call__`, `isinstance` на заглушке не проверяет типы.
