## DESIGN (решено лидом — исполнитель печатает, не выводит)

1. **Механизм-кандидат** (из чтения `tools/watcher.py:81–96` и замеров; тестер его **не знает** — блок A его не содержит). `_maybe_reload` — дебаунс по **переднему** фронту: первое событие читает файл, все события в течение `debounce_seconds` (умолчание обоих боевых watcher — 1,0 с) **отбрасываются**, повторной перезагрузки нет. Писатель на месте даёт два `modified`: truncate и write. Чтение по первому событию видит пустой или частичный файл; второе событие — с итогом — отбрасывается окном. Для YAML пустой файл читается как `{}` (`yaml_to_dict`: `or {}`), перезагрузка «проходит» без ошибки — потеря **молчаливая**. Это кандидат, не вывод: исполнитель подтверждает его воспроизведением, а не чтением.
2. **Писатели файлов под наблюдением.** `observability_config_path` (системный YAML) и спутник рецепта (`start_observability_watcher`, `app_module/orchestrator.py:166,223`; пути из конфига). Известные писатели: `write_companion` — tmp + `os.replace` (`observability_companion.py:100–143`); `recipe/service._atomic_write` — tmp + `fsync` + `os.replace`; `app_module/store.py:155–166` — то же; `DataConverter.save_to_file` — `open(path, "w")` + `f.write(content)` на месте (`converter.py:292–293`), вызывающих вне тестов нет (`git grep`: 0). Внешний писатель — человек в редакторе (на месте или подменой — зависит от редактора).
3. **Воспроизведение — первый шаг.** Файл `multiprocess_framework/modules/config_module/tests/test_watcher_final_write.py` (тестер, блок A). Каждый тест: свой каталог `tmp_path`; `ConfigFileWatcher(path, cfg, debounce_seconds=1.0)`; `start()`; пауза 0,4 с; **N = 10** запусков внутри теста; в каждом файл содержит `{"v": "old"}` (JSON) или `v: old` (YAML), писатель пишет итог `final`; ожидание до 2,0 с, пока `cfg.get("v") == "final"`; `stop()`. Тест падает, если хоть один запуск не дошёл до `final`; сообщение — `lost k/10`. Тело теста идёт в daemon-потоке с `join(120)`; поток жив после дедлайна — тест красный с текстом «завис». Утверждение только об итоге (`cfg.get`), не о числе перезагрузок. Писатели:
   - W1 `Path.write_text` на месте, JSON — страж;
   - W2 `DataConverter.save_to_file(dict, path)` на месте, JSON — страж;
   - W3 tmp + `os.replace`, YAML (как `write_companion`) — страж;
   - W4 `open(p, "w")`, `flush()`, пауза 0,05 с, запись `v: final\n`, YAML;
   - W5 YAML двумя кусками: `a: 1\n`, `flush()`, пауза 0,05 с, `v: final\n`;
   - W6 как W4, но JSON (`{"v": "final"}` после паузы) — вариант с записью в журнал ошибок.
4. **Разброс.** Запуск файла целиком — 5 раз подряд (`-p no:cacheprovider`), на каждый тест — пять чисел `lost k/10`. Итог пишет таблицу «тест × запуск → k». Один зелёный прогон гонки ничего не доказывает.
5. **Две ветки.**
   - **«Воспроизвелось»** (О1): коммит RED-тестов отдельно (`test(framework): k0 1.2 — RED …`), затем `developer`: в `_maybe_reload` событие, отброшенное окном, не пропадает — ставится **один** отложенный повтор `_reload` на момент `_last_reload + debounce`; повтор обновляет `_last_reload`; `stop()` отменяет ожидающий таймер. Публичный API `ConfigFileWatcher` (аргументы конструктора, `start`, `stop`, `is_running`) не меняется. Автор (не тестер) добавляет в `test_watcher.py` тесты-ловушки 7–8 и правит тест из О3. Затем инъекции, ревью.
   - **«Не воспроизвелось»**: все REDS 1–6 зелёные во всех 5 запусках → тесты остаются стражами, `watcher.py` не правится, в итоге строка «гипотеза опровергнута: 0 потерь из K прогонов (писатели W1–W6, 5 запусков × 10)»; стадии `developer` и инъекций нет, ревью — по тестам.
6. **Принцип.** Чинится `watcher.py` (fix forward, корневой `CLAUDE.md`, принцип 2). Тест не ослабляется и не снимается; красный тест из-за дефекта кода — починка, не пропуск.
7. **Литералы.** Старое `old`, итог `final`, ключ `v`, N = 10, дедлайн ожидания 2,0 с, `debounce_seconds=1.0`, пауза записи 0,05 с, пауза старта 0,4 с, `join(120)`, запусков 5. Ничего не вычисляется из проверяемого кода.
8. **Дыры известны заранее:** тесты не проверяют, что таймер именно daemon (процесс не зависает на выходе); не проверяют Windows (О4); нет теста на частичный файл, который парсится в **другой** валидный словарь с теми же ключами (W5 закрывает только добавление ключа).
