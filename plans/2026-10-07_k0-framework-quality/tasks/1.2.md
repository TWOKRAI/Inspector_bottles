## DESIGN (решено лидом — исполнитель печатает, не выводит)

1. **Механизм-кандидат** (из чтения `tools/watcher.py:82–99` и замеров; слепота тестера — **по коду** (worktree на коммите брифа, `watcher.py` запрещён), не по механизму: бриф целиком читаем, поэтому блок A разрешает читать из `1.2.md` только DESIGN 3, 4, 7 — это запрет прозой, а не самодостаточность). `_maybe_reload` — дебаунс по **переднему** фронту: первое событие читает файл, все события в течение `debounce_seconds` (умолчание обоих боевых watcher — 1,0 с) **отбрасываются**, повторной перезагрузки нет. Писатель на месте с паузой между truncate и write даёт два `modified` (замер ревью р.1, `events.py`: W4 — два события, через 0,001 и 0,051 с; `write_text` и `save_to_file` — одно, поэтому на Linux они стражи, а не воспроизведение; на Windows число событий иное — О4). Чтение по первому событию видит пустой или частичный файл; второе событие — с итогом — отбрасывается окном. Для YAML пустой файл читается как `{}` (`yaml_to_dict`: `or {}`), перезагрузка «проходит» без ошибки — потеря **молчаливая**. Это кандидат, не вывод: исполнитель подтверждает его воспроизведением, а не чтением.
2. **Писатели файлов под наблюдением.** `observability_config_path` (системный YAML) и спутник рецепта (`start_observability_watcher`, `app_module/orchestrator.py:166,223`; пути из конфига). Известные писатели: `write_companion` — tmp + `os.replace` (`observability_companion.py:100–143`); `recipe/service._atomic_write` — tmp + `fsync` + `os.replace`; `app_module/store.py:155–166` — tmp + `os.replace` (без `fsync`); `DataConverter.save_to_file` — `open(path, "w")` + `f.write(content)` на месте (`converter.py:292–293`), вызывающих вне тестов нет (`git grep`: 0). Внешний писатель — человек в редакторе (на месте или подменой — зависит от редактора).
3. **Воспроизведение — первый шаг.** Файл `multiprocess_framework/modules/config_module/tests/test_watcher_final_write.py` (тестер, блок A). Каждый тест делает **N = 10** запусков, и **каждый запуск независим: свой подкаталог `tmp_path`, новый файл с `old`, новый `Config`, новый `ConfigFileWatcher(path, cfg, debounce_seconds=1.0)`, `start()`, пауза 0,4 с, писатель, ожидание, `stop()` в `finally`; между запусками ничего не делится** (один watcher на десять запусков даёт красный страж из-за устройства теста — замер ревью р.1: W1 `lost 1/3`). Файл содержит `{"v": "old"}` (JSON) или `v: old` (YAML), писатель пишет итог `final`; ожидание до 2,0 с (окно дебаунса 1,0 с + запас 1,0 с; под нагрузкой запас может не хватить — ловушка в TRAPS), пока `cfg.get("v") == "final"`; `stop()`. Тест падает, если хоть один запуск не дошёл до `final`; сообщение — `lost k/10`. Тело теста идёт в daemon-потоке с `join(120)`; поток жив после дедлайна — тест красный с текстом «завис». Утверждение только об итоге (`cfg.get`), не о числе перезагрузок. Писатели:
   - W1 `Path.write_text` на месте, JSON — страж;
   - W2 `DataConverter.save_to_file(dict, path)` на месте, JSON — страж;
   - W3 tmp + `os.replace`, YAML (как `write_companion`) — страж;
   - W4 `open(p, "w")`, `flush()`, пауза 0,05 с, запись `v: final\n`, YAML;
   - W5 YAML двумя кусками: `a: 1\n`, `flush()`, пауза 0,05 с, `v: final\n`;
   - W6 как W4, но JSON (`{"v": "final"}` после паузы) — вариант с записью в журнал ошибок.
4. **Разброс.** Запуск файла целиком — 5 раз подряд, **каждый запуск отдельным вызовом** (`-p no:cacheprovider`), на каждый тест — пять чисел `lost k/10`. Итог пишет таблицу «тест × запуск → k». Один зелёный прогон гонки ничего не доказывает.
5. **Две ветки.**
   - **«Воспроизвелось»** (О1): коммит тестов тестера отдельно (`test(framework): k0 1.2 — воспроизведение потери итоговой записи watcher`), затем `developer`: в `_maybe_reload` событие, отброшенное окном, не пропадает — ставится **один** отложенный повтор `_reload` на момент `_last_reload + debounce`; повтор обновляет `_last_reload`. Конкурентность задана так: один `RLock` на поле таймера (не `Lock`: `_maybe_reload` держит его при вызове `_reload`); колбэк таймера снимает флаг «повтор ожидается» **до** чтения файла (иначе запись во время чтения теряется — модель ревью: `итог потерян даже при ожидании 3 с`); `_reload` идёт под замком (его зовут и поток таймера, и поток watchdog, а `on_reload` замка не имеет); `stop()` берёт таймер под замком, **отпускает замок**, затем отменяет и ждёт идущий колбэк (`join` с дедлайном 5 с): удержание замка на время `join` даёт перезагрузку уже после возврата `stop()` (модель ревью р.2: `stop_s=5.00` против `0.20`). Публичный API `ConfigFileWatcher` (аргументы конструктора, `start`, `stop`, `is_running`) и приватный атрибут `_on_reload` (его читают тесты `app_module`) не меняются.
