# sim-lateral-offset — диски на ленте сима лежат со смещением поперёк хода

- **Дата:** 2026-10-01 · **Ветка:** `feat/sim-lateral-offset` (от `main` a87a0cbe) · **Статус:** IN PROGRESS
- **Запрос владельца 2026-10-01:** «диски на конвейере могут по оси y лежать не по центру, а иногда со смещением…
  чтоб можно было задавать, но по дефолту 10–20 пикселей, а так можно вручную и больше».
- **Почему сейчас:** прогон прототипа на кадре сима (2026-10-01, кириллица А/К/Р/Х) дал 55.9 % по дискам —
  но все диски шли строго по центру `belt_y_px`. Реальная лента так не кладёт; числа были оптимистичны.

## Как сейчас (сверено по коду 2026-10-01)

- Кадр: `SceneCompositor.render` — `cy = belt_y_px - y_px` для КАЖДОГО объекта (`Services/line_sim/core/scene_compositor.py`).
- Истина для робота: `object_robot_xy` — `origin + BELT_U * off`, поперечного слагаемого нет (`Services/line_sim/core/matching.py:89-93`).
- `augment.offset_x/y_px` слоёв (`layered_object.py:168`) сдвигает СЛОЙ внутри спрайта, а не объект на ленте — это не оно.

## Контракт

| Что | Значение |
|---|---|
| Ключ конфига `scene_source` | `lateral_offset_px: [lo, hi]` — диапазон МОДУЛЯ смещения в пикселях кадра, `0 <= lo <= hi` |
| Знак | случайный, ±1 равновероятно (вверх/вниз по кадру) |
| Дефолт ядра/плагина (ключа нет) | `[0, 0]` — смещения нет, поведение **байт в байт** прежнее (кадр, rng-последовательность, паспорт-словарь без нового ключа не ломает `from_dict`) |
| Дефолт стенда (`apps/line_sim/pipeline.yaml`) | `[10, 20]` — то, что владелец назвал «по дефолту»; больше — правкой ключа |
| Кривой ключ (`lo<0`, `lo>hi`, не пара чисел, NaN/inf) | `ValueError` на старте плагина, текст называет ключ и значение |
| Паспорт | новое поле `lateral_px: float = 0.0` (знаковое, `+` = вниз по кадру); `to_dict`/`from_dict` с ним; старый словарь без ключа → `0.0` |
| Кадр | `cy = belt_y_px + lateral_px - y_px` |
| Истина | `object_robot_xy` += `(lateral_px / px_per_mm) * frame_down` — `frame_down` = единичный вектор «вниз по кадру» в системе робота |
| `frame_down` | поле `geometry` (`frame_down_ux`, `frame_down_uy`); на стенде `(-1, 0)` — из калибровки рецепта: верх ROI X=497.4, низ X=419.0, Y не меняется |
| `lateral_offset_px != [0,0]` без `frame_down` в `geometry` | `ValueError` на старте — иначе истина молча врёт про позицию |
| Публикация | `sim.objects` (паспорт `to_dict`) несёт `lateral_px` — замер сверяет его с кадром |

**Известное расхождение, НЕ чинится здесь:** сим изотропен (`px_per_mm` 8.163 по обеим осям), линейная калибровка
рецепта по вертикали — 78.4 мм / 481 px = 6.135 px/мм. Для 20 px это 2.45 мм (сим) против 3.26 мм (прототип) —
0.8 мм невязки `pick_error` при `match_radius_mm: 60`. Записать в README сима.

**Запас ROI:** ROI по высоте 481 px (297…778), центр 537.5, диск ≈300 px → полностью в ROI до ±90 px. Дефолт 20 —
с запасом; больше 90 — диск режется краем ROI, это владелец увидит сам (и это честный сценарий).
