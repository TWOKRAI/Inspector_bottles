## Контекст

Требование владельца 2026-10-20: крестик не убирает GUI сразу. Есть несохранённое — «Сохранить / Не сохранять /
Отмена»; затем окно «Остановка системы…» с ходом по каждому процессу; окно исчезает **последним**, когда весь бэкенд
остановился и сообщил об этом. `backend_ctl` останавливает систему принудительно — без диалогов и вопросов.
Принято владельцем по предложению лида: зависание → «Подождать ещё / Закрыть принудительно», второй крестик =
принудительно; стоп без диалогов пишет черновик восстановления + строку в лог, следующий запуск предлагает
восстановить; принудительный режим `backend_ctl` — короткий срок, остальных добить, честный итог по процессу;
подключаемый GUI (Пульт, `plans/2026-09-22_gui-service/phase-3-multi-backend.md:159`) спрашивает «Остановить систему /
Только отключиться».

Основание по архитектуре — вердикт CTO 2026-10-20 по L-9, D2–D4
(`docs/reports/2026-10-20_lifecycle-stop-ownership_L-9-residual_details.md` §7; сейчас в worktree `l9-residual`, коммит
`856bb2e0c`): ход стопа требует, чтобы PM оставался зрячим во время стопа детей (Task 1.9b плана
[`lifecycle-stop-ownership`](../lifecycle-stop-ownership.md)), честного итога (Task 1.10 там же) и **отдельной правки
корня PM** — сейчас `message_processor` PM закрывается раньше детей (ADR-PMM-036, LIFO); эта правка — Task 1.1 здесь.
Принцип 6: GUI только шлёт `system.shutdown` и показывает ход, процессы не останавливает.

## Цели (вехи)

1. **Ф1 — бэкенд отвечает во время стопа и знает порядок:** `backend_ctl` гасит систему принудительно с коротким сроком (Task 0.2, первой); PM отвечает на `supervision.status` всё окно стопа детей;
   ответ несёт фазу и `outcome` каждого процесса; GUI гаснет отдельной последней волной; `system.shutdown` имеет режимы
   `graceful`/`force` и точку `pre_stop` для «домой». Вертикальный срез 1.1 даёт сценарий «крестик → ход → окно
   последним» уже в первой задаче.
2. **Ф2 — UX:** окно хода со всеми ветками (зависание, второй крестик, внешний стоп, смерть бэкенда), один вопрос на все
   источники несохранённого, черновик и его восстановление; живая приёмка с числами.
3. **Ф3 — Пульт:** контракт для подключаемого GUI; код — в плане gui-service.
