DESIGN (decided by the lead — you type it, you do not derive it). Якоря — по `main` `c07fb7cb7`, пересчитать перед правкой:
  1. `CloseCoordinator(QObject)` в новом `frontend/shutdown/close_coordinator.py` (+ `__init__.py`); Qt-родитель — окно.
     Состояния `RUNNING → CONFIRMING → STOPPING → CLOSING`, свойство `state`. Все эффекты — внедряемые вызовы (иначе
     слепой тест не написать):
     `CloseCoordinator(window, *, confirm_discard: Callable[[], bool], send_shutdown: Callable[[], dict],
     poll_status: Callable[[float], dict], ignore_names: frozenset[str], ask_force_stop: Callable[[Callable[[bool], None]], Closable], force_stop: Callable[[], None],
     quit_app: Callable[[], None], on_shutdown_sent: Callable[[], None], unattended: bool = False,
     clock: Callable[[], float] = time.monotonic, poll_interval_ms: int = 250, no_answer_s: float = 2.0)`.
     `ask_force_stop(on_answer)` не блокирует: показывает вопрос и сразу возвращает ручку с `close()`; ответ оператора приходит
     вызовом `on_answer(True)` («Остановить») или `on_answer(False)` («Подождать»). Координатор закрывает ручку сам, если ответ PM
     пришёл раньше оператора (в тесте фейк хранит `on_answer` и считает вызовы `close()`). `request_runner: RequestRunner | None = None` —
     внедряемый раннер (по умолчанию общий пул `QThreadPool.globalInstance()`, `request_runner.py:85-90`); тесты идут на реальном
     пуле с блокирующим фейком `poll_status` на `threading.Event`, который teardown обязан освободить.
     `ignore_names` — имена, которые не ждём: собственное имя `gui` И имя ProcessManager (PM отдаёт в `supervision.status`
     запись о себе с `alive: True` — `process_manager_process.py:875-881`; без исключения окно ждало бы выхода PM = H2 снова).
     Методы: `request_close()` (крестик), `request_restart()` (рестарт UI), `backend_gone()` (`should_stop` при
     `RUNNING`/`CONFIRMING`), `commit_close()` (`→ CLOSING`, затем `quit_app()`). Отправка `system.shutdown` — один раз;
     после неё `on_shutdown_sent()` ставит `GuiProcess.shutdown_sent = True` (простой булев атрибут процесса, значение по умолчанию `False` на уровне класса `GuiProcess`: его читает
     `GuiProcess.run` после возврата `run_gui`, когда Qt-объектов уже может не быть).
  2. `request_close()`: состояние не `RUNNING` → ничего (второй крестик в `CONFIRMING`/`STOPPING`/`CLOSING` = `ignore()`
     без повторной отправки; принудительный режим — Task 2.1). Иначе `CONFIRMING`: `confirm_discard()`
     (= `window.confirm_discard_topology_changes`); «Отмена» → `RUNNING`, ничего не отправлено. Иначе `send_shutdown()`
     (= `process_manager_proxy.shutdown_system()`, :112), `on_shutdown_sent()`, `STOPPING`, показать прогресс. После возврата из `confirm_discard` состояние перепроверяется (`CONFIRMING`): если за время модального вопроса таймер
     безопасности перевёл в `CLOSING` (`on_safety_tick(True)`), `send_shutdown` не вызывается. Исключения: сбой `confirm_discard` → ERROR в лог, `RUNNING`;
     сбой `send_shutdown` (`process_manager_proxy.py:149-152` не перехватывает) → ERROR в лог, `commit_close()` БЕЗ
     `on_shutdown_sent` (сработает прежний путь `_request_system_shutdown`) — иначе состояние навсегда `CONFIRMING`.
  3. Прогресс: `QProgressDialog`, окно-модальный, показывается через `show()` (не `exec()`), без кнопки отмены
     (`setCancelButton(None)`), `setMinimumDuration(0)`, `setAutoClose(False)`, `setAutoReset(False)`, Esc/`reject`
     игнорируются. Заголовок «Остановка системы… k из N».
  4. Опрос: `QTimer` 250 мс → координатор сам отдаёт `poll_status(1.0)` в `RequestRunner.submit`; результат приходит сигналом в
     главный поток (тест ждёт `qtbot.waitUntil`). Реальный `poll_status` = `command_sender.request_system_command(…,
     timeout=1.0)` (параметр есть, `command_sender.py:253-257`; по умолчанию 30 с). Литерал ответа handler'а закреплён кодом
     `process_manager_process.py:896`: плоский `{"success": True, "epoch": …, "processes": {имя: {"alive": bool|None, "pid": …, …}}}`;
     dict `RequestRunner` не оборачивает (`request_runner.py:46`). Живая сверка формы — в приёмке heavy (Windows), не у teamlead
     на Darwin. Тестовые фейки отдают плоскую форму. В полёте не более одного запроса. Ответом считается только результат с
     `success is True`; `{"success": False, "error": "timeout"}` — не ответ. «Все процессы остановлены»: у всех детей,
     кроме имён из `ignore_names`, нет ни одной записи с `alive is True` → `commit_close()`. Ждём только `alive is True`: `alive: None` — запись вне реестра

     ответ без `success is True` или с пустым `processes` «все мертвы» не засчитывается (нужен минимум один успешный непустой ответ).
  5. Сторож тишины — одна формула, проверка на КАЖДОМ тике `QTimer` (не по приходу результата):
     `last = max(t_send, t_last_success, t_wait_click, t_force)`, где `t_send` — момент `send_shutdown()`, `t_last_success` —
     последний ответ с `success is True`, `t_wait_click` — момент, когда ОПЕРАТОР нажал «Подождать», `t_force` — момент
     «Остановить» (`clock` — monotonic). Когда `clock() - last >= no_answer_s`:
       а) вопрос ещё не показывался и `force_stop` не нажат → `ask_force_stop(on_answer)` с текстом: «Бэкенд не ответил на
          команду остановки за 2 с. Остановить систему принудительно? Шаги подготовки («домой») будут пропущены.» Кнопки
          «Остановить» (default) / «Подождать». Пока вопрос открыт, повторно не спрашиваем. unattended — вместо вопроса
          сразу «Остановить»;
       б) «Остановить» → `force_stop()` (= `set()` общего `system_stop_event` + WARNING), `t_force = clock()`, ожидание детей
          продолжается; «Подождать» → `t_wait_click = clock()`, вопрос можно задать снова после следующей тишины;
       в) `force_stop` уже нажат (PM мёртв или завис — механизма обнаружения смерти PM нет, сторож родителя на Windows
          отключён: `process_runner.py:166`) → `commit_close()` + WARNING (иначе модальный диалог без отмены не имеет
          выхода — регрессия против сегодняшнего «X закрывает окно»).
     Ответ PM пришёл, пока вопрос открыт → ручка вопроса закрывается, считается как «Подождать» БЕЗ сдвига `t_wait_click`
