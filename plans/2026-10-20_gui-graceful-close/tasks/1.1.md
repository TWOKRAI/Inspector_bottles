DESIGN (decided by the lead — you type it, you do not derive it). Якоря — по `main` `c07fb7cb7`, пересчитать перед правкой:
  1. `CloseCoordinator(QObject)` в новом `frontend/shutdown/close_coordinator.py` (+ `__init__.py`); Qt-родитель — окно.
     Состояния `RUNNING → CONFIRMING → STOPPING → CLOSING`, свойство `state`. Все эффекты — внедряемые вызовы (иначе
     слепой тест не написать):
     `CloseCoordinator(window, *, confirm_discard: Callable[[], bool], send_shutdown: Callable[[], dict],
     poll_status: Callable[[float], dict], ask_force_stop: Callable[[], bool], force_stop: Callable[[], None],
     quit_app: Callable[[], None], on_shutdown_sent: Callable[[], None], unattended: bool = False,
     clock: Callable[[], float] = time.monotonic, poll_interval_ms: int = 250, no_answer_s: float = 2.0)`.
     Методы: `request_close()` (крестик), `request_restart()` (рестарт UI), `backend_gone()` (`should_stop` при
     `RUNNING`/`CONFIRMING`), `commit_close()` (`→ CLOSING`, затем `quit_app()`). Отправка `system.shutdown` — один раз;
     после неё `on_shutdown_sent()` ставит `GuiProcess.shutdown_sent = True` (простой булев атрибут процесса: его читает
     `GuiProcess.run` после возврата `run_gui`, когда Qt-объектов уже может не быть).
  2. `request_close()`: состояние не `RUNNING` → ничего (второй крестик в `CONFIRMING`/`STOPPING`/`CLOSING` = `ignore()`
     без повторной отправки; принудительный режим — Task 2.1). Иначе `CONFIRMING`: `confirm_discard()`
     (= `window.confirm_discard_topology_changes`); «Отмена» → `RUNNING`, ничего не отправлено. Иначе `send_shutdown()`
     (= `process_manager_proxy.shutdown_system()`, :112), `on_shutdown_sent()`, `STOPPING`, показать прогресс.
  3. Прогресс: `QProgressDialog`, окно-модальный, показывается через `show()` (не `exec()`), без кнопки отмены
     (`setCancelButton(None)`), `setMinimumDuration(0)`, `setAutoClose(False)`, `setAutoReset(False)`, Esc/`reject`
     игнорируются. Заголовок «Остановка системы… k из N».
  4. Опрос: `QTimer` 250 мс → `poll_status(1.0)` — запрос `supervision.status` через `RequestRunner` +
     `command_sender.request_system_command` со сроком 1,0 с (по умолчанию команда ждёт 30 с — `command_sender.py`;
     если параметра срока нет, стоп и вопрос лиду). В полёте не более одного запроса. Ответом считается только результат с
     `success is True`; `{"success": False, "error": "timeout"}` — не ответ. «Все процессы остановлены»: у всех детей,
     кроме собственного имени процесса, `alive is False` → `commit_close()`.
  5. Нет ни одного ответа за `no_answer_s` (2,0 с, `clock` — monotonic, отсчёт от `send_shutdown()`) →
     `ask_force_stop()` с текстом: «Бэкенд не ответил на команду остановки за 2 с. Остановить систему принудительно?
     Шаги подготовки («домой») будут пропущены.» Кнопки «Остановить» (default) / «Подождать» (ещё 2,0 с от момента
     ответа). «Остановить» → `force_stop()` (= `set()` общего `system_stop_event` + WARNING) и ожидание детей
     продолжается до выхода или смерти PM; unattended — без вопроса «Остановить». Ответ пришёл, пока вопрос открыт —
     вопрос закрывается как «Подождать» без сброса счётчика, опрос идёт дальше. GUI общий `system_stop_event`
     НЕ взводит сам при `RUNNING → STOPPING` (то был бы запасной путь, противоречащий шагу 2) — только наблюдает его.
  6. `MainWindow.closeEvent` (`main_window.py:287`): состояние `CLOSING` → `_save_geometry()` + `super().closeEvent(event)`,
     БЕЗ `confirm_discard_topology_changes` (иначе второй вопрос: «Не сохранять» не снимает `dirty`, ревью п. 4);
     иначе `event.ignore()` + `coordinator.request_close()`.
  7. Рестарт UI (`app.py:958-968`, `_request_ui_restart`): `window.confirm_discard_topology_changes` вызывает
     `coordinator.request_restart()`: один вопрос, `process._restart_ui = True`, `commit_close()` — БЕЗ `system.shutdown`
     (бэкенд остаётся). Цикл `GuiProcess.run` (`process.py:316-323`) не меняется.
  8. Safety-таймер (`app.py:1245-1259`, интервал 1000 мс остаётся): `process.should_stop()` при `RUNNING`/`CONFIRMING` →
     `coordinator.backend_gone()` → `commit_close()` сразу, без вопросов (backend-driven teardown, комментарий
     :1250-1255 переписать); при `STOPPING` не прерывает ожидание детей — PM молчит → шаг 5. `app.quit()` из таймера
     напрямую запрещён: только `coordinator.commit_close()`.
  9. `GuiProcess._request_system_shutdown` (`process.py:342-360`): `shutdown_sent` уже `True` → событие не взводится
     (`TestRequestSystemShutdown`, `test_gui_process.py:626`, не удалять — сузить до пути без координатора).
  10. Журнал `gui` (INFO): «закрытие: подтверждено», «… system.shutdown отправлен», «… все процессы остановлены (N)»,
      «окно скрыто» (метка для зонда).
  11. Первым шагом teamlead выясняет чтением и пишет в отчёт: взводится ли `process.should_stop()` у `gui`, пока PM
      останавливает остальных детей (H2 из Task 0.1 говорит, что `gui` живёт до `terminate`). Если взводится в
      `STOPPING` — шаг 8 остаётся (в `STOPPING` не прерывает), расхождение — вопрос лиду до правки.
