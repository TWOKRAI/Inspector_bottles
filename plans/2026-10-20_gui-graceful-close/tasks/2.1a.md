       `set_elapsed(clock() − t_send)` на каждом тике.
     - **Опрос.** 250 мс, срок запроса 1,0 с (`_POLL_TIMEOUT_S`, :46; design.md A3), один в полёте — без изменений 1.1.
       Источник — `poll_status_async(timeout_s, on_result)` (шаг 6) вместо `poll_status` + `request_runner`.
     - **«Не отвечает» (решение владельца 2026-11-08, сужает решение 7).** Ребёнок завис, если `alive is True`,
       `stop_outcome` `null`, `stop_deadline_at` — число и `wall_clock() >= stop_deadline_at + HANG_GRACE_S`;
       `HANG_GRACE_S = 1.5` — константа модуля: `TERMINATE_GRACE_S` 1,0 (`stop_budget.py:48`; PM шлёт `kill()` через
       1,0 с после `terminate`, `child_process_stop.py:365-371`) + 0,5 (два опроса GUI). `stop_deadline_at` `null`
       (`last` до сигнала, вне стопа) — не завис. Есть зависшие → `show_hang(имена)` (имена по алфавиту); на следующем
       ответе без зависших → `hide_hang()`. Причина: при окне `g` PM терминирует ребёнка в тот же миг, когда истекает
       его окно (вариант А Task 1.3, ADR-PMM-043); вопрос на сроке окна недостижим или уже неправда, «Подождать ещё»
       ничего не продлевает на стороне PM — кнопки нет. Вопрос показывается, только когда и `kill()` не помог.
     - **«Закрыть принудительно»** (`force_close` вида, второй крестик, unattended) → `_force_close(who)`, один раз за
       закрытие: `send_force(0.5, on_result)` (шаг 6, `mode="force"`, `deadline_s=0.5` — design.md C) и отметка
       `t_force_sent`. Подтверждение = конверт `success is True` и `result.success` не `False`. Нет подтверждения:
       отказ, таймаут или `clock() >= t_force_sent + 1.0` без ответа → один раз `_do_force("PM не принял force")` (1.1,
       :356: общий `system_stop_event`, решение владельца 4) + WARNING «закрытие: PM не принял force — взводится общий
       system_stop_event». Закрытие: все дети `alive is False` (обычный путь) или `clock() >= t_force_sent + 3.0` →

       → `commit_close()`. Хвост 1.1 (2,0 с молчания после `force_stop`, :324-330) остаётся: закрывает тот, кто раньше.
       Принцип 6: GUI сам процессы не останавливает; единственное собственное действие — уже существующий запасной путь
       1.1 `_force_stop` (`app.py:1231-1241`, взвод общего события). Он не зависит от `process.shutdown_sent`
       (`app.py:1243-1244`, `process.py:357-364` блокирует только взвод при выходе) — правка `process.py` не нужна.
       Следствие: при `deadline_s = 0.5` PM терминирует и `gui` (ADR-PMM-043, `D ≤ 2,0`) — WARNING и геометрия могут
       не успеть; приёмка их не требует.
