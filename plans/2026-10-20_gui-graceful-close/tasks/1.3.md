  4. `ChildProcessStop` (`child_process_stop.py`, FILES 9): тело `join_until` выносится в публичный `poll(deadline) -> tuple[bool | None, float]` — ровно один проход
     (наблюдение, abort, `_name_escalate`, `_kill_at`, проверка срока) без ожидания: `(True, 0.0)` — ждать некого; `(False, 0.0)` — срок `deadline` вышел или abort;
     `(None, pause)` — продолжать, `pause` — до ближайшего события (≤ `poll_s`). `join_until` становится `while True: r, p = self.poll(deadline); if r is not None: return r; self._wait(max(0.0, p))` —
     поведение и порядок проверок прежние. Публичный `wait(pause)` — тот же `_wait` (idle реестра, сбой idle — сон). В `poll` из модуля `time` — только `monotonic`.
     Причина: группе с двумя сборками нужен один поток, который крутит обе; короткий `join_until(now + STOP_POLL_S)` для этого не годится — срок вызова
     зажимает `term_at = min(запрос + окно, deadline)` (:345) и `_kill_at = min(…, deadline − kill_confirm_s)` (:274), и `terminate`/`kill` уходят через ~50 мс.
