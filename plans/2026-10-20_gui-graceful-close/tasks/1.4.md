DESIGN (decided by the lead — you type it, you do not derive it):
  1. `_cmd_system_shutdown` (`process_manager_process.py:666`): аргументы `mode` (`graceful`|`force`, по умолчанию
     `graceful`), `deadline_s` (только `force`; 1,0; диапазон 0,1–5,0, иначе `{"error": …}`), `initiator` (по умолчанию
     `sender`). Ответ сразу: `{"success": True, "accepted": True, "mode": …, "phase": …}`. Повтор: `graceful` во время
     стопа → `{"success": True, "accepted": False, "reason": "already_stopping"}`; `force` во время `graceful` → эскалация.
  2. `graceful`, стопа нет: `phase = "pre_stop"`; шаги исполняет исполнитель Task 1.9 (его примитив отложенной работы) —
     НЕ `message_processor`. Шаг = запрос ребёнку через существующий `_send_child_command` с `timeout_s`; таймаут или
     ошибка → WARNING `pre_stop: шаг '<process>.<command>' — <причина>`, следующий шаг. После шагов — события как сейчас.
     Пустой список — события сразу (поведение сегодня, задержка 0).
  3. `force`: пропустить или прервать `pre_stop` (флаг отмены — между шагами и в ожидании ответа шага), взвести события,
     через `deadline_s` вызвать `kill()` текущих групп `main` и `last` (`core/child_process_stop.py:172` — terminate без
     ожидания, дальше эскалация как есть). Таймер владеется корнем PM (Scope `lifecycle-owner-scope`), не сырой
     `threading.Thread` (правило G6).
  4. FIFO Task 1.9 в фазе `pre_stop` отклоняет новые команды жизненного цикла с `reason: "system_stopping"` — это
     требование к 1.9 (`design.md` → «Соседи»); если 1.9 этого не даёт — ESCALATION -> cto.
  5. `pre_stop.py`: схема шага `{process: str, command: str, args: dict = {}, timeout_s: float, 0 < t <= 60}` и функция
     исполнения списка с флагом отмены. Источник — ключ `pre_stop` в конфиге процесса PM (манифест приложения);
     ошибка схемы — отказ старта PM с текстом «pre_stop[<i>]: <поле> — <причина>». Пустой по умолчанию.
  6. `backend_ctl/driver.py` (рядом с `system_command`, :669): `system_shutdown(mode="graceful", deadline_s=1.0,
     wait=True, wait_timeout=15.0) -> dict` — команда; при `wait` опрос `supervision_status` (:1042) каждые 100 мс, пока все
     дети `alive is False` или сокет закрыт; возврат `{"accepted": bool, "outcomes": {name: outcome}, "elapsed_s": float,
     "pm_gone": bool}`; `outcomes` — из последнего снимка до закрытия сокета.
  7. `backend_ctl/mcp_tools.py`: инструмент `system_shutdown(mode, deadline_s)`; класс безопасности — разрушающий (таблица
     классов `mcp_tools.py:1485` и далее; `supervision_status` там `SAFETY_READ`, :1489). `AGENTS.md` — строка инструмента.
  8. GUI не меняется: «без диалогов» даёт путь E Task 2.1/2.2, не `INSPECTOR_GUI_UNATTENDED`.
