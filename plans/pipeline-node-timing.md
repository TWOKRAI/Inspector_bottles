# pipeline-node-timing — время каждого узла цепочки в GUI и честные кирпичи обработки

**Составлено:** 2026-09-30, лид. **Полоса:** И (интерфейс) + плагины. **Ветка:** `feat/pipeline-node-timing` (от
`feat/qr-code-reader` после слияния 4.5 — нужен `plugin_ms`).

## Зачем (слова владельца, 2026-09-30)

«Нужно как-то сделать универсальным. Можно в самом GUI, когда создаётся цепочка процессов и эффектов, писать время
выполнения, чтобы понимать, что и как настройками улучшать. Там можно фильтр ставить, чтобы шум отсекать.»

Не чинить одну пару плагинов, а дать инструмент: собрал цепочку из кирпичей → видишь миллисекунды каждого узла
против бюджета кадра → меняешь настройки/состав → видишь эффект. Связь с целью по мощностям —
`.claude/memory/project_capacity_planning_goal.md` (шаг «наш код»: сначала лишняя работа, потом язык).

## Задачи

### Task T1 — Цепочка инспекции находит объекты; детектор берёт готовую маску
**Level:** Middle · **Assignee:** developer · **Layer:** plugins + prototype
**Goal:** закрыть PC-1/PC-2 универсально: любой детектор по маске использует маску из цепочки, а не пересчитывает её.
**Дизайн (решает лид при брифе, наброски):** `color_mask` пишет `mask` (1 канал) по своему порту и `frame` не
заменяет (опция вида маски на экране — через `mask_to_frame`, как в чистой цепочке); `blob_detector`: есть `mask`
в item → HSV не считает; рисует на копии кадра (переезжает сюда из 4.7 п. 3). Топологии `inspection_full/basic`.
**Acceptance:** кадр 1080p с 6 красными кругами через цепочку рецепта → 6 детекций (литерал); тест-сторож на каждую
эталонную топологию «цепочка находит объекты»; время цепочки — committed-бенчмарк (median по N прогонов,
`test_pnt_t1_chain_timing_within_budget_or_warns`), бюджет 5 мс **не блокирует** (решение владельца 2026-10-01:
число machine-dependent — ревью этой же задачи получило 6.33 мс median на другой машине против 4.6 мс у лида;
порог понижен до предупреждения `UserWarning`, видимого в выводе теста).
**Статус: ✅ слита 2026-09-30 `b611e7a7`.** 6/6 в `inspection_full` и `inspection_basic`; цепочка 1080p медиана
4.1–4.7 мс под нагрузкой CPU 79 % (было 9.5 мс при 0 детекций) — за счёт `draw_contours: false` в топологиях,
детекции рисует `render_overlay` (решение владельца: критерий 5 мс можно поднять, если сценарию нужно рисование
в детекторе). Попутно по ревью: песочница «Плагины» показывает первый `image/*`-выход и судит совместимость по
dtype обязательных входов, категории с побочными эффектами закрыты (36 → 25 совместимых, закрытые — пустышки);
отвергнутая маска — одно предупреждение. Ревью: reviewer ×2 + teamlead (APPROVE). Инъекции лида I1–I6, J1–J5:
две пустые проверки найдены и исправлены (`cc6c8c13`). Хвосты — PC-5, PC-6 в `queue/defects.md`.

### Task T2 — Время узла на графе цепочки
**Level:** Middle+ · **Assignee:** developer · **Layer:** prototype (GUI)
**Goal:** на каждом узле вкладки «Pipeline» — «8.4 мс» и цвет против бюджета кадра процесса (1/fps): зелёный < 50 %,
жёлтый < 100 %, красный ≥ 100 %; на контейнере процесса — сумма узлов и доля бюджета.
**Источник:** `plugin_ms` из опроса (`TelemetryViewModel`), бюджет — `effective_hz`/`target_interval_ms` источника.
Бейджи проводов (PC-4) — fps из `effective_hz` получателя, мс из `transport_ms`.
**Acceptance:** на живом стенде `inspection_full` узлы показывают числа, совпадающие с `introspect.telemetry`
(± одно обновление); смена параметра узла (напр. `resize` 0.5) меняет число за ≤ 3 с; без телеметрии — «—», не 0.

### Task T3 — Геометрия кадра после уменьшения и кропа
