# `logs_live/` — артефакты живых прогонов

Один каталог на все прогоны вместо россыпи `logs_live_*` в корне репозитория.
Заведён 2026-08-06, когда россыпь из двенадцати каталогов набрала **223 МБ** и
каждый раз всплывала в `git status`.

## Как класть сюда логи

Каталог логов задаётся переменной окружения — код читает `MULTIPROCESS_LOG_DIR`,
затем `INSPECTOR_LOG_DIR` ([`log_paths.py`](../multiprocess_framework/modules/logger_module/core/log_paths.py)).
Один прогон — один подкаталог:

```powershell
$env:INSPECTOR_LOG_DIR = "logs_live/2026-08-06_f8-1_before"
python multiprocess_prototype/run.py
```

Имя подкаталога — `<дата>_<задача>_<что за точка>`. Дата первой, потому что
прогоны сравнивают парами «до/после», и сортировка по имени должна ставить их
рядом. Прежние имена вида `logs_live_f71` этого не давали: по ним нельзя было
сказать ни когда прогон сделан, ни какая половина пары перед тобой.

## Что не коммитится

Всё содержимое каталога, кроме этого файла (`.gitignore`). Логи прогона —
расходный материал: числа из них переезжают в отчёт ревью или в план, а сами
файлы живут ровно до следующей уборки.

**Из этого следует правило:** если на прогон ссылается отчёт, ссылка обязана
нести **числа**, а не только путь. Путь переживёт уборку мёртвым — так уже
вышло с четырьмя отчётами в `docs/reviews/`, которые ссылались на удалённые
теперь каталоги. Числа в отчёте были, поэтому потери нет; но проверять это
задним числом дороже, чем написать сразу.

## Уборка

```powershell
Remove-Item -Recurse -Force logs_live/*  -Exclude README.md
```
