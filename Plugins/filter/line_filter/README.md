# line_filter — фильтр виртуальной линии

Категория: **filter** («Фильтр»). Классический фильтр технического зрения — virtual
tripwire / line-crossing. На вход — координаты объектов, на выходе — отмеченные
объекты (вход в зону / пересечение линии) + draw-params для рендера.

## Контракт

| Порт | Тип | Описание |
|------|-----|----------|
| **вход** `detections` | list[dict] | детекции с `center: [x, y]` (или `points: [[x,y]]`) |
| **выход** `overlay` | dict | семантика линии (`vlines`) + отмеченные точки — для `overlay_draw` |
| **выход** `filtered` | list[dict] | сработавшие объекты (`current` или `accumulated`) |

Выход помечается `data_type="overlay"` и наследует `seq_id` входа — для корреляции
кадр↔overlay в `JoinInspectorManager`. **Кадр через себя не пропускает.**

## Методы (защита от шума)

1. Знаковое расстояние точка→линия (`geometry.signed_distance`); линия «от края до
   края» разворачивается в `overlay_draw` (клиппинг по кадру).
2. Центроидный трекинг (`tracker.CentroidTracker`, SORT-lite) — стабильная идентичность.
3. Temporal confirmation (`min_hits`) + TTL (`max_age`) — отсев одиночных вспышек.
4. `enter_zone` + гистерезис (`hysteresis_margin`) — анти-дребезг границы зоны.
5. `cross_line` — пересечение (смена знака), направление наезд/выезд.
6. Дедуп по радиусу (`dedup_radius`) — «±N px = тот же объект».

## zone_edge: одно событие на проход диска

`zone_edge` — rising-edge по занятости зоны: событие на переходе «зона пуста → в зоне есть точка».
Защёлка снимается после `rearm_frames` пустых кадров подряд. Ассоциации центров между соседними
кадрами нет (на любой скорости ленты лишь бы `zone_width` ≥ смещения за кадр).

- **Память места пропажи (C-42).** Плагин помнит, где и в каком кадре последний раз видел объект
  в зоне (обновляется на каждом кадре с точкой в зоне). Если защёлка снялась (детекция пропала
  на ≥ `rearm_frames` кадров внутри зоны), а точка снова появилась не дальше `max_match_distance`
  от места пропажи и после не более чем `max_age` пустых кадров — это тот же диск: события нет
  (в журнал пишется одна строка). Иначе — новый диск, событие.
- **Старт с занятой зоной (решение владельца О1).** Защёлка при старте/рестарте плагина закрыта:
  первый кадр с занятой зоной не засчитывается, триггер взводится после `rearm_frames` пустых
  кадров подряд. Диск, вошедший в зону за время рестарта, теряется — его ячейка свободна для
  следующего такого же диска (дубль хуже потери). Дыра по построению: диск, уже засчитанный до рестарта,
  который детектор не видит первые `rearm_frames` кадров после рестарта, даёт ВТОРОЕ событие (второе задание).
- **Допущение:** в зоне один объект за раз; несколько точек рядом с местом пропажи дают одно
  «тот же объект» на все.
- **Условия настройки** (v — смещение диска за кадр, L — самая длинная потеря детекции в кадрах;
  валидатора нет — скорость ленты регистром не задана):
  - `max_match_distance` ≥ v × (L + 1);
  - память работает, только если `max_age` ≥ `rearm_frames`; потеря в L кадров — тот же объект при
    L ≤ `max_age` и v × (L + 1) ≤ `max_match_distance` (потерю короче `rearm_frames` держит одна защёлка);
  - `max_age` × v < `zone_width` − `max_match_distance` — иначе новый диск у входного края
    примут за пропавший прежний.

  Рецепты робота: `max_match_distance: 140`, `max_age: 2`. Основа — замер на стенде: линия 19.3–25.3 кадр/с
  (медиана 23.8), то есть v = 32.6–42.7 px/кадр (медиана 34.7); зона 250 px проходится за 6–8 кадров.
  Проверка на худшем v = 42.7: v × (L + 1) = 128 ≤ 140 при L = 2 — тот же диск при потере до 2 кадров
  (потерю в 1 кадр держит одна защёлка при `rearm_frames: 2`; `max_age: 2` ≥ `rearm_frames`);
  `max_age` × v = 85 < 250 − 140 = 110.

## Параметры

См. `registers.py`: `center_x/y`, `angle`, `zone_width`, `mode`, `dedup_radius`,
`min_hits`, `max_age`, `max_match_distance`, `rearm_frames`, `hysteresis_margin` (≥ `dedup_radius`),
`emit_mode`. Все редактируются в карточке ноды (live).
