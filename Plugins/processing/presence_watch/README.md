# presence_watch

Проходной индикатор: «нет изделия» и «слабое распознавание». Плагин не меняет поток items.
Пока система в `running`, он отдаёт причину `out_of_spec` в `system.run.reasons`. Это не авария:
START и STOP не блокируются. Тексты и ключи item задаёт рецепт, о конкретном продукте плагин не знает.

Stability: lite. Интерфейс — `ProcessModulePlugin`; входных и выходных портов, команд и state нет.

## Поля регистра

| поле | умолчание | смысл |
|---|---|---|
| `absent_after_s` | `10.0` | срок до «нет изделия», с (1…600) |
| `text_absent` | `нет изделия` | текст причины; `""` — причина выключена |
| `text_weak` | `слабое распознавание` | текст причины; `""` — причина выключена |
| `presence_keys` | `predictions,sidecar` | ключи изделия через запятую, путь «a.b»; изделие, если хоть один путь не `None` |
| `predictions_key` | `predictions` | путь к списку топ-K; топ — элемент `[0]` |
| `label_key` | `label` | ключ метки в топе; `""` — не проверять; метка `0` — метка |
| `below_threshold_key` | `below_threshold` | ключ «ниже порога» в топе; `""` — не проверять |
| `confidence_key` | `confidence` | ключ уверенности в топе; нет в топе — 1.0 |
| `min_confidence` | `0.0` | порог уверенности (0…1); `0` — не проверять |

Регистр читается на каждом вызове: живая правка действует сразу.

## Правила

- Причина одна. «Нет изделия» старше «слабого».
- Слабое: нет списка топ-K или он пуст; топ не dict; нет метки; флаг «ниже порога»; уверенность
  ниже порога или NaN; разбор item бросил исключение.
- Одного слабого изделия достаточно. Причина держится до уверенного изделия или до `absent_after_s`
  (после него — «нет изделия»).
- Пустой текст выключает свою причину. При выключенном `text_absent` устаревшее «слабое» после срока
  не показывается.
- «В работе» задают хуки: `start`/`resume` открывают срок заново и забывают прошлую работу,
  `pause` закрывает. Вне работы и у выключенного узла (`set_enabled`) причин нет.
- Логов на item нет. Ошибка разбора — одна строка ERROR на (место, тип исключения) на экземпляр,
  без значений item.

## Место и цена

- Плагин стоит последним в процессе `recog` (после `ml_inference`): индексы остальных плагинов и провода
  не меняются. Порт слова с телефона приходит не в `recog`.
- Без изделия до конца `recog` ничего не доходит, поэтому «нет изделия» — правило по сроку.
  Цена шага без изделия — 0, с изделием — около 1,3 мкс плюс разбор ключей.

## Без `run_gate`

При `run_gate: false` событие работы взведено всегда, и плагин считает себя в работе в любом состоянии
системы. Причина есть в листе узла всегда; GUI вне `running` её не показывает.

## Порог и `word_layout`

В рецептах букв `min_confidence` равен `config.min_confidence` плагина `word_layout` процесса `layout`.
Рецепты сторожит `tests/test_recipes_pin.py`. Живая правка только одного регистра расходит пороги молча.

Ключ `readiness` узлу не задавать: `severity: {out_of_spec: check_function}` сделает «нет изделия»
аварией.

## Ограничения конфигурации

- «Слабое» предполагает список топ-K, пустой список — слабое. Изделию без распознавания или детектору,
  где пусто означает «хорошо», ставить `text_weak: ""`.
- `predictions_key: ""` — всегда «слабое»; `presence_keys: ""` — всегда «нет изделия». Опечатка в ключе
  принимается молча.
- Негодное значение регистра в рецепте не поднимает плагин и останавливает START (осознанный
  fail-closed). Негодную живую правку регистр отклоняет.
- После повторного включения узла (`set_enabled`) причина может держаться до первого изделия.
- Изделие — любое значение, кроме отсутствующего и `None`: `[]`, `False`, `0`, `""` тоже изделие; ключом
  наличия ставить поле, которого без изделия нет.
