# Plugins/sim/layer_preview — превью пресета слоёв в своём процессе

Плагин процесса `layers` приложения `apps/line_sim` (редактор слоёв, Task 1.2a, ревью S1). Одна команда —
`preset.preview`: сетка объектов пресета по seed в PNG; `preset.layout`: слои объекта раздельно для канвы редактора; `preset.sprites`: список PNG-файлов для добавления слоя. Своих портов данных нет (side-effect, `category: control`).

## Зачем отдельный процесс

Превью объекта по-настоящему стоит ~88 мс (8 seed по 160 px, пресет `letters_layered` на Arial 300 px, замер
ревью 1.2a). Пока оно жило в `scene_source`, эти 88 мс держали единственный поток команд процесса `camera`, и
`scene.job_done` от робота ждал столько же. В своём процессе поток сцены свободен: задержка `job_done` при
непрерывном превью — медиана 0.004 мс (замер тимлида, два потока одного процесса — верхняя оценка). Правило
владельца 2026-09-27: собирать из процессов и роутера фреймворка, а не из своих потоков в плагине.

## Команда

`preset.preview {preset?: dict, seeds?: list[int], tile_px?: int}` →
`{status: ok, png_b64, tiles: [{seed, class_name, layer_params}]}`; ошибки — `{status: error, code: invalid |
bad_request, message}`.

- Без `preset` — рендерит файл пресета из своего `preset_path`; файл перечитывается, когда меняется его `rev`
  (`recipe.service.compute_rev`), поэтому `preset.commit` через `scene_source` виден без рестарта.
- `preset` клиента: `base_dir` принудительно = каталог файла пресета; каждый путь картинки после `resolve()` обязан
  лежать в корне репозитория или в каталоге файла пресета, иначе `invalid` с одним и тем же текстом (нет оракула
  существования файла) — `Services.line_sim.core.preview.confine_preset_paths`.
- Размер ответа (L-6, крупные ответы через pipe): 8×160 ≈ 79 КБ JSON (120 КБ с конвертом роутера), ~88 мс;
  16×113 — 100–137 КБ. Спрайты 1200 px — до 1.3 с на превью (держит только поток `layers`). Замеры ревью 1.2a it.2.
- Лимиты: 1..16 seed, `tile_px` 16..256 и бюджет `len(seeds) × tile_px² ≤ 8 × 160²` — иначе `bad_request`.
- Рендер — `Services.line_sim.core.preview.render_preview_grid` (кэш фабрики — одна запись на процесс).

`preset.layout {preset?: dict, seed?: int}` → `{status: ok, class_name, canvas_px: [w, h], layers: [{name, png_b64,
center_px: [x, y], size_px: [w, h], origin_px: [x, y]}]}` (Task 1.3h-a, канва редактора на `pult_web`); ошибки — те же `invalid` /
`bad_request`, та же ограда путей клиентского пресета.

- Каждый слой объекта ленты — отдельной RGBA-картинкой, уже после заливки, `scale` и поворота слоя (тот же
  `LayeredObject._transform`); **номинал**: `augment` не разыгрывается, угол объекта 0, defect-слои не рисуются.
- Слои — снизу вверх как у объекта ленты: у пресета с каталогом без слоя `class://` первым идёт авто-слой `base`
  (спрайт класса), он не редактируется — страница сопоставляет слои с пресетом по имени.
- `center_px` — центр слоя относительно центра объекта (Y вниз), `canvas_px` — размер объекта в номинале.
- `origin_px` — целый левый верхний угол слоя на канве `canvas_px`: ставить PNG слоя ровно сюда; лента округляет
  Python `round` (half-even), JS `Math.round`/`floor` расходятся — не пересчитывать из `center_px`.
- Класс для `seed` тот же, что у плитки `preset.preview` с этим seed (общий `np.random.default_rng(seed)` и
  общий розыгрыш `ObjectFactory._resolve_bottom_layers`); `force_defect_next()` раскладка не трогает.
- `seed` — целое ≥ 0 (не `bool`), по умолчанию 0; верхней границы нет.
- Цена (замер ревью it.2 2026-09-29, Windows, прогретый кэш, после отказа от `_compose`): `letters_layered.yaml`
  (диск + буква 300 px) — 1.5 мс, 11.7 КБ JSON; каталог `letter_catalog_rep` — 0.12 мс, 2.6 КБ. До правки было 22 мс.
- Цена на крупных слоях (слой 1200 px, повёрнутый на 30° + буква 300 px, прогретый кэш фабрики, Windows). Замер ревью 1.3h-a
  ДО правки: 611 мс (размытая картинка) / 720 мс (шум), JSON 1.71 / 6.51 МБ — канва считалась полным `_compose`. Свой замер на
  синтетическом круглом слое (одна и та же фикстура): до 468 / 505 мс, после (`layered_object.canvas_size`, без рендера)
  50 / 79 мс, JSON 2.09 / 6.51 МБ; остаток — PNG-кодирование и base64. Слой со смещением 20000 px (x30, канва 40420x630):
  1.5 с -> 10 мс. Числа ревью и свои получены на разных картинках — сравнивать только пары «до/после» внутри одного замера.

`preset.sprites {}` → `{status: ok, dir, files: [{path, sprite_source}], truncated, layer_template}` (Task 1.3h-c,
список файлов для «Добавить слой» на `pult_web`); ошибки — `{status: error, code: bad_request | io_error, message}`.

- Каталог — ключ конфига `sprites_dir` (по умолчанию `data/line_sim`; относительный — от корня репозитория,
  абсолютный принимается). `data/` в `.gitignore`: на свежем клоне каталога нет, и это `io_error`, а не пустой список.
- `files` — рекурсивно, суффикс `.png` без учёта регистра, только обычные файлы, порядок по `path`, не больше 500
  (усечение — после сортировки, `truncated: true`). `path` — от `sprites_dir`, прямые слэши (подпись в списке);
  `sprite_source` — от каталога файла пресета хоста (у пресета без файла — от корня репозитория), прямые слэши: это
  значение вписывается в слой как есть и грузится `preset.layout`. Считает одна функция — `sprite_entry(file,
  sprites_dir, base_dir)`; её же позовёт запись из браузера (Task 1.3h-d). `dir` — `sprites_dir` от корня репозитория
  (если внутри него), иначе абсолютный.
- Ограда — та же, что у `preset.layout` (корень репозитория + каталог файла пресета; `_allowed_roots`). Файл, чей
  `resolve()` уходит за неё (симлинк наружу) или у которого нет пути от каталога пресета (`relpath` между дисками
  Windows), в список не попадает. Симлинк-каталоги и junction не обходятся (петля `loop -> ..` не даёт дублей).
- Отказы: тело не dict / `sprites_dir` вне ограды → `bad_request` (ограда проверяется РАНЬШЕ существования);
  каталога нет, это не каталог или он не читается → `io_error`, путь в `message`.
- `layer_template` — `LayerSpec(name="_", mode="static", sprite_source="_").model_dump(mode="json")`: полный набор
  ключей слоя с дефолтами (форма слоя строится из ключей словаря; новое поле `LayerSpec` попадает в шаблон само).
- RGBA при перечислении **не** проверяется: не-RGBA картинку отвергнет следующий `preset.layout` (`invalid`).
- Цена: обход дерева полный (сортировка идёт до усечения), потолок 500 действует на ответ, а не на обход —
  каталог с десятками тысяч файлов будет медленным (не измерено).

## Конфиг (`pipeline.yaml`)

| Ключ | Обязателен | Что |
|---|---|---|
| `preset_path` | да | тот же, что у `scene_source` (держать равными): `.yaml` пресета слоёв или каталог классов; относительный — от корня репозитория (`Services.line_sim.resolve_repo_path`) |
| `defect_probability` | нет | то же перекрытие, что у `scene_source` (`Services.line_sim.load_scene_preset`) |
| `sprites_dir` | нет | каталог PNG для `preset.sprites`, по умолчанию `data/line_sim`; относительный — от корня репозитория; обязан лежать внутри ограды (корень репозитория или каталог файла пресета) |

## Границы

Не импортирует `Plugins.sim.scene_source` (закреплено тестом): общее правило загрузки пресета — в
`Services/line_sim/core/preset.py`. HTTP-маршрут для браузера — задача 1.2h (`pult_web`).
